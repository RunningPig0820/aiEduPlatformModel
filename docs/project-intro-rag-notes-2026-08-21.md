# 项目介绍 RAG 问答系统 — 讨论纪要

- 日期: 2026-08-21
- 状态: 讨论收敛，待转 OpenSpec proposal
- 目的: 面试用的**项目介绍 RAG 问答系统** —— 用 RAG 引擎驱动，给面试官讲清楚每个页面的设计逻辑（产品设计 / 为什么这么设计 / 数据流转 / 关注点）

---

## 一、定位

- **不是纯 RAG 项目**。产品 = 项目介绍问答，RAG = 证明能力的引擎。
- 覆盖 4 个有内容的模块（页面）:
  1. 知识图谱
  2. AI答疑
  3. 组织中心
  4. 学生知识点分析
- 语料 = 自己的方案 + 设计文档 + 代码注释（"反向整理"，不是全量倾倒）。

## 二、核心架构：双池

```
┌─ 索引层池(问题索引层): 每页 5~8 条预写 QA ────────────────┐
│   每条 = 问题 + 答案要点 + 引用源文档                       │
│   作用: 引导问题的检索目标, 答案可控                        │
└──────────────────────────────────────────────────────┘
┌─ 源文档池(证据层): OpenSpec / 语雀 / 代码注释 全文 ────────┐
│   作用: 自由问题的纯 RAG 检索 + 回答的证据引用              │
└──────────────────────────────────────────────────────┘
```

- **引导问题 → 索引层池**：小上下文（要点+少量引用），便宜、稳定。
- **自由问题 → 源文档池**：跨页纯检索，可答没准备过的问题。
- 预写答案 + **依然走向量检索**（"选哪条"这一步真实发生）。

## 三、完整链路

```
[离线]
文档收集(OpenSpec + 语雀产品文档 + 代码注释)
  → 反向整理成每页 QA(索引层)
  → 切分 + 标注 metadata(页面/问题类型/角色权限/源文档全文)
  → embedding(dashscope text-embedding-v3, 768维)
  → 写入 COS 向量桶(rag-index)
[在线]
query 理解(页面锚定 + 问题类型)
  → 权限门(前置校验当前页权限点)
  → 多路召回(向量 + BM25 关键词, 源文档池可加图谱)
  → 打分(相似度 × 问题类型匹配 × 页面锚定)
  → 范围门(检索置信度低于阈值 → 边界回答)
  → 生成(doubao, 强制带引用, 按页面分别标注)
  → 展示(答案 + 召回文档原文面板 + 预置流程图 + token 明细)
```

## 四、页面锚定（两种模式）

- **页面模式**：前端主动传 `page` → 页面概览卡 + 权限标签 + 引导问题 chips → 问答锁定在该页文档内。
- **全局模式**：跨页问题 / 前端没传 page → 权限门过滤可检索页 → 全局检索。

## 五、两道门

- **权限门（前置校验）**：进页面/会话时校验"当前页需要的权限点 vs 当前角色"。demo 默认学生账号 = 最高权限（演示中基本放行，机制可切换演示）。
- **范围门（检索后判定）**：**检索置信度 = 是否在覆盖范围内**。低于阈值 → 边界回答，不硬编：
  > "这个问题不在本次介绍范围，我目前覆盖了 知识图谱/AI答疑/组织中心/学生知识点分析，你可以问我其中任何一个页面的设计、数据流转或难点。"

## 六、引导问题（chips）

- UI 上的引导问题 = 索引层问题的**变体文案**（故意制造检索难度，让检索真实发生，避免"点按钮=预定答案"）。
- 例：UI 写"你们为什么拆成三段"，索引层是"为什么拆 decide/generate/question-understand"。
- 每页需**维护两套文案并配对**（UI 引导问题 + 索引层规范问题）。
- chips 也走**同一检索管道**（不是直连答案）。

## 七、token 成本

- **真算 usage**，流结束时更新。
  - 需改 `core/tutoring/ark_stream.py`：请求体加 `stream_options: {"include_usage": true}` + 解析时抓结尾 usage chunk（choices 为空、带顶层 usage）。
  - 需改 `core/tutoring/vector_store.py`：`embed()` 抓 `resp.usage.total_tokens`（embedding 单独记账）。
- 展示字段：每轮 `prompt/completion` + 会话累计 + ¥ 换算（doubao 单价）；embedding tokens 单列。
- **成本叙事**：doubao 聪明 + 引导问题走索引层小上下文 = 主力路径便宜；限制追问轮数防上下文膨胀；关键词兜底便宜路径。
- 面试可讲的坑：流式 usage 只在结尾返回 → "结束后更新"。

## 八、流程图（数据流转）

- 每页**预置一张 mermaid 图**，命中"数据流"类问题直接渲染（稳、快）。
- 未预置的问题 → 动态生成 mermaid 兜底（备选通道，演示不依赖）。

## 九、追问限制

- 每次会话（页面锁定期间）最多 **5 轮**问答，到上限提示"信息较多，请开启新一轮对话"。
- 目的：上下文不无限膨胀 = 成本可控 + 面试节奏可控。

## 十、异常与降级

### 10.1 基础设施降级矩阵

| 环节 | 故障 | 重试? | 降级到 | 最差兜底 |
|------|------|-------|--------|---------|
| query 理解 | embedding API 挂/超时 | 否(不幂等) | 关键词/规则匹配(jieba) | 提示"换个说法" |
| 检索(COS) | 查询失败/超时/索引不存在 | 是, 短超时重试1~2次 | 关键词检索兜底(源文档池内) | 边界话术 |
| 打分/范围门 | 全部低于阈值 | —(正常路径) | 边界回答 | 同上 |
| 生成(doubao) | 调用失败/限流 | 否(流已起, 重试=重复花钱) | 直接展示召回原文 | 引导问题→展示预写答案卡片 |
| 流式中断 | SSE 断开 | 否 | 保留已吐内容 + 提示中断 | 同上 |
| 展示 | mermaid 渲染失败 | 否 | 降级为文本/预置图片 | 纯文字答案 |

**核心设计点（独家优势）**：引导问题的**预写答案 = 天然兜底**。doubao 挂了，索引层答案要点直接渲染成卡片，不用 LLM 也能答。
> 面试话术："我的系统最坏情况也能给出预写答案，LLM 只是负责组织语言的加分项。"

### 10.2 重试策略

- **可重试**：COS 查询（幂等，指数退避，最多 2 次）。
- **不重试**：LLM 生成（流已开始，重试=烧钱+重复输出）；embedding（改走缓存/关键词）。
- **超时**：每步设内部超时。检索链 target < 2s，生成流 < 15s（借鉴图片分析 20s 超时经验），超时即降级。

### 10.3 行为异常（幻觉 / 答非所问 / 引用错）

| 异常 | 对策 |
|------|------|
| 幻觉(编出处) | 强制带引用：答案必须附召回文档，无引用不生成 |
| 答非所问 | prompt 强约束"只基于检索上下文回答" + 三段式回复模板(概览/要点/引用) |
| 引用错页 | 引用带页面标签，prompt 要求标注来源页；后校验引用页 ∈ 检索页集合 |
| 卡住/挂起 | 兜底超时 + 提示"重新生成" |

**核心防御原则**：**"检索不到就边界拒绝，模型没引用就不输出正文"**——同时堵死幻觉和跑题。

### 10.4 会话层异常

- 超过追问限制(5轮) → 提示开新会话（提示文案预写好）。
- 前端没传 page / 角色切换异常 → 默认全局模式 + 权限降级为"演示默认放行"。

## 十一、数字默认值（可改）

| 项 | 默认值 | 说明 |
|----|-------|------|
| 范围门阈值 | 索引层命中 > 0.75；源文档池 > 0.5 | 低于就边界拒绝 |
| top-K | 索引层 1~3；源文档池 3~5 | 索引层要精，源文档池要多一点 |
| token 展示字段 | 每轮 prompt/completion + 累计 + ¥换算；embedding 单列 | doubao 单价换算 |
| 评估集 | 每页 5 条 Q&A，共 20 条，算命中率 | 面试官问"怎么证明有效"亮数据 |
| 边界话术 | 预写 2~3 条固定文案 | "目前覆盖了 X/Y/Z，你可以问我…" |
| 追问上限 | 每会话 ≤ 5 轮 | 上下文不膨胀 |
