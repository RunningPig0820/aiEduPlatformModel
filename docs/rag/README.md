## 系统级开场引导（还没点页面，先讲 3 句）

| 引导问题 | 亮点 | 预期追问 |
|---------|------|---------|
| 介绍一下你的 RAG 项目 | 全链路（文档准备→嵌入→向量桶→多路召回→打分→生成→展示）+ 一句话差异化 | "具体每步怎么设计？" → 指向第 2、3 段 |
| 你的 RAG 和普通 RAG 有什么不同？ | 双池 / 范围门=检索置信度 / 预写答案兜底 / token 成本展示 | "双池怎么判断走哪个？" → doc_type 区分 |
| 你怎么证明它有效？ | 评测 agent：hit@3 + 答案质量分 + 版本对比 | "指标怎么算的？" → 纯函数可验证 |

## 系统级最危险的可能问题（全局防御）

| 可能问题 | 防御要点 |
|---------|---------|
| 这是预写答案吧？检索是假的？ | 引导问题用**变体文案**强制走检索；自由问题走**源文档池纯 RAG**；现场可让他随意问一个没准备的 |
| 评测集也是你自己写的，不是自证？ | expected 引用来自完善文档（可回查）+ 人工核对 + hit@k 是客观命中率 |
| 语料才几十条，能说明什么？ | 链路真实完整；小语料反而评测更严；重点是**可解释的检索链路** |
| 为什么不直接用现成 RAG 框架？ | 链路掌控（召回/打分/降级/成本自己设计）+ 教育领域定制（图谱/题型） |
| 这套和你们线上业务什么关系？ | RAG智能客服在路线图上（P0），RAG 是产品方向不是 demo |
