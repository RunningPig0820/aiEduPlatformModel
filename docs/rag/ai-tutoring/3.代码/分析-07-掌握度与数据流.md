## 业务情况（一道题从作答到掌握度落库的完整数据流）

### 1. 一道题多次作答 → 聚合成一条题目记录
- 会话聚合根持 `currentAttempt`（当前题聚合：rounds[] 多轮信号），换题/收尾/拍题时 `settleAttempt()` 结算。
- 每轮 decide 输出 `eval.correct` + 是否被引导（`answerRequestCount>0`）→ `onRoundSignal(correct, hinted)` 累计。
- **SWITCH 轮无作答跳过**；END/REVEAL 若无 eval（无真实作答评估）也跳过——避免把模型默认值当真实作答。

### 2. 题型名 → canonical（聚集，掌握表不裂行）
`TopicLabelAggregationService.aggregate`：
1. **字符规则归一**（全半角/空白/去标点 + 「解/求」前缀剥离，`TopicLabelRuleNormalizer`）
2. **题型名向量最近邻**（单信号，Python 桥，embedding 用 dashscope）：distance ≤ 0.2 → 归并到命中 canonical（写别名表）；0.2~0.3 中阈值区间本期保守**建新不误并**；≥0.3 异型建新——**宁可拆不误并**。
3. **首题建锚**（零锚点）：题型库建 canonical（CANDIDATE，幂等 upsert）+ 题型名向量入库（metadata.canonical_label）。
4. 失败兜底：向量库不可用 → 回退字符规则结果，不阻塞。

### 3. ScoreMapper：信号 → 生效分值
- **baseScore**：直接答对 1.0 / 引导后答对 0.5 / 答错或未完成 0.0。
- **per-题型打折**（作用于 score 不作用于结果，避免「第1题答错 → 题型 0%」假低）：第1题 0.7 / 第2题 0.8 / 第3题起 1.0（配置 `ai-edu.tutoring.signal.discount-*`）。
- 生效分值 = baseScore × discount（setScale 2 HALF_UP）。

### 4. 落库（两表 + 错误事件）
- **题目表 `t_student_question_record`**（事实源）：一道题一次作答一条记录，`source=ai`，含 content/topicLabel/canonical/score/hintCount/sessionId。PENDING 题型未识别 canonical=null 照常落（信号不丢），归属后批量聚集补。
- **掌握表 `t_student_topic_mastery`**：canonical 已锚定才聚，`applyScore` 累计平均正确率（**替代 applySignal max 单调不减**——方案口径已过时）；trainCount=该题型已训练数（打折依据）。
- **错误事件 `t_tutoring_error_event`**：B3 门控——仅 decide 原始 type 为 **hint/approach**（真实评估学生作答）且模型明确诊断出 `error_type` 才算学生错误写入；switch/end/reveal/concept 轮的 correct=false 是模型默认值（error_type=null），非真实错误不写。

### 5. 澄清卡（学生确认知识点 = 低置信纠偏，不采信模型）
- decide 输出 `mastery_signals`（`topic_label` + `mastered/practicing/struggling`）→ 前端对每个新增 label 调 `resolveKp`（`POST /kp/resolve`）。
- `resolveKp` 返回 `status=PENDING + candidates`（低置信）→ 渲染**澄清卡**（候选学科概念，学生选/跳过）。
- 学生选某概念 → `voteKp`（`POST /kp/vote`，source=student_vote）落观测；跳过 → 弃权不调接口。
- 定位：这是「**学生确认知识点**」的真实形态（非结尾确认卡）；**答疑链路不写 Neo4j**——图谱点亮由 `kp-matching-lightup` 变更独立承担。

### 6. 掌握度快照回流（决定上下文）
- 掌握表 → `KpSnapshot`（`kp_key`=题型名、label=题型展示名、mastery_level）→ decide 请求 `mastery_snapshot`。
- Python `snapshot_top_n` 按掌握度**升序**取 top-10（薄弱题型在前），让模型优先关注薄弱项；同时限体积防撑爆上下文窗口。
