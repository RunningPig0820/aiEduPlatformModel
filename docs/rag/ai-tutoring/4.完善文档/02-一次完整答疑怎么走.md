# 02 一次完整答疑怎么走

> 模块=ai-tutoring｜节=02｜问题表=操作｜权威度=高（正文）

## 为什么（语雀）

答疑入口要**低门槛、口语化**：学生用非书面化、模糊化的真实提问习惯也能用。产品目标是"答疑-分析-迭代"闭环——每次答疑既解决当下问题，又沉淀数据。

## 怎么设计（方案）

一次学生消息走"**类型先行流式**"：`decide`（出动作元数据）→ Java 护栏审批 → `generate`（流式正文）。核心安全点：**任何内容流入学生之前，type 已过护栏**——reveal 未授权时正文一个字都不会吐出去。

## 落地真相（代码）——完整链路

```
前端发消息 → Java 编排 → Python 决策+生成 → SSE 流式回前端

① 前端自动路由（useTutoringSession.send）
   无会话 → startSession（POST /api/tutoring/sessions）
   有会话 → sendMessage（POST /sessions/{id}/messages）
   点"请求答案"→ requestAnswer（POST /sessions/{id}/request-answer）
   三条都是 SSE 流式，同一组 handlers（onMeta/onToken/onDone/onAgent/onThinking）

② Java 编排（TutoringAppService 是总控）
   发起(start)：
     学科门（subject-classify，图片先传 subject-check 目录看图）
     → 非 math 直接回「仅支持数学」，不建会话
     → math 才过创建频率限制 → 建会话(ACTIVE) → 首条消息进 Redis → orchestrate
   每轮(orchestrate)：
     并发锁保护 → 组装 DecideContext → 调 Python decide（SSE 中继）
     → 等 meta → postDecide：
       安全终止 → 护栏校验 → 终止类end → 轮次达顶强制收尾
       → 放行type（护栏拒绝时降级，如 reveal→approach）
       → 落库副作用（掌握度/错误/情绪/round）失败降级继续
       → 每轮实时整写 COS（异步）→ buildStream 流式回前端

③ Python 纯智能（L0 两端点，无状态）
   decide：短路（is_new_question→switch 不调 LLM）或流式决策
     → 边吐 thinking 边收集 function-calling 参数 → ActionMeta
   generate：按已放行 action_type 流式生成正文 → meta/token/done

④ SSE 事件序列（前端所见）
   agent(guardrail,Java) → meta → agent(generate,Python) → thinking* → token* → agent(memory,Java) → done
   - decide 阶段 agent 事件(perceive/analyze/plan/decide)实时中继
   - thinking=模型真实推理分片（AI 版进度条）
   - meta 带 sessionId/status/type/roundCount/eval/masterySignals
   - done 带 status/summary/endReason

⑤ 收尾
   正常收尾 → type=end → Java 置 ARCHIVED + endReason
   主动结束 → POST /sessions/{id}/archive → ABANDONED + COS 终态写
   终止（无关/非数学/安全）→ TERMINATED，回复在 meta.reply，无 token 流
   前端判定结束：meta/done.status 为 ARCHIVED 或 TERMINATED
```

**体验关键**：decide 阶段前端显示"读取题目→解析意图→规划引导→决策"的 live 意图 + 真实推理分片，把 1-2 分钟的黑盒等待变成可见的思考过程；generate 阶段正文流式逐字流出。
