# 04 安全与防作弊（护栏）
> COS路径: rag-source/ai-tutoring/完善文档/04-安全与防作弊-护栏.md

> 模块=ai-tutoring｜节=04｜问题表=难点｜权威度=高（正文）

## 为什么（语雀）

教育产品最大的坑是**学生套答案**——直接要答案、无限刷轮次、绕过引导。核心原则：**严禁直接给答案、每轮只引导一步**。这些教育底线不能交给 LLM 自主判断（agent 的"灵活性"在这里是风险）。

## 怎么设计（方案）

Java 在**动作出口**做确定性护栏（不是写进 prompt 靠模型自觉）：任何内容流入学生之前，type 已过护栏。护栏是可单测的确定性规则，agent 路径不追求全覆盖测试。

## 落地真相（代码）——三道护栏 + 三层兜底

### 1. 答案护栏（防直接要答案）
学生点"请求答案"→ Java 合成消息进 decide → Python 判 `type=reveal` → Java 看计数：
- **第 1 次**（count<1）→ 拦，降级 `approach`（给思路），计数→1
- **第 2 次**（count≥1）→ 放行 reveal，给完答案**立即收尾** `ANSWER_REVEALED`（防反复要）
- 被拒后重决策仍 reveal → Java 直接降级**固定思路话术**（不依赖 LLM）
- 前端配套：第 2 次点击弹**确认框**（单向门）

### 2. 轮次护栏（防无限刷）
`round_count ≥ 20` 且本轮是引导类 → 强制收尾 `ROUND_LIMIT`，固定话术，无 generate。只有 hint/approach 消耗轮次（concept/switch/end/reveal 不消耗）。

### 3. 安全护栏（防高危内容）
decide 输出 `safety_flag=true` → 终止会话（TERMINATED），无 token 流，回复在 meta.reply。

### 三层兜底（防卡死/防畸形）
| 兜底 | 触发 | 行为 |
|---|---|---|
| 结构化输出四段降级 | Python 四段管线全失败 | 返回 `type=hint + degraded=true`（Java 监控降级频次），不使用 503 |
| 非法/缺失 type | decide 输出畸形 | 默认 HINT 放行（不阻断） |
| Python 调用失败 | 重试后仍失败 | 已有会话 → "网络波动，请重试"，**会话保持 ACTIVE** 可重试 |

### 判对链路的"防作弊"延伸
- 答错绝不能被"恭喜"收尾：`end` 联动护栏（COMPLETED 必须 correct && exercise_complete，否则降级 concept 保持会话）
- 知识点选对与否：AI 预判 + 学生确认双保险（澄清卡），不空点不误点

## 追问与防御

**预期追问：怎么防学生套答案？**
→ **回答要点**：靠确定性答案护栏，不靠 LLM 自觉——学生要答案时 decide 判 `reveal`，Java 看 `answer_request_count`：第 1 次拦成思路（approach，计数→1），第 2 次才放行完整答案并**立即收尾**（防反复要）；前端第 2 次弹确认框。配套轮次 20 上限、安全 flag 终止。

**预期追问：行为风控 / 题目指纹呢？**
→ **回答要点**：未落地（阶段 3 规划）。当前防套答案完全靠上述确定性规则，不用模型判断"是不是在套答案"——教育底线不能交给 LLM 自主判断。

**预期追问：触发了怎么办？**
→ **回答要点**：第 1 次 reveal 被拦降级思路；轮次达顶强制收尾（固定话术）；安全 flag 直接终止（无 token 流）。
