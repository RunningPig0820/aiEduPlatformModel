# 05 数据落库与掌握度

> 模块=ai-tutoring｜节=05｜问题表=数据关联｜权威度=高（正文）★差异最大节

## 为什么（语雀）

答疑产生的数据要支撑"学情分析 + 家长监控 + 图谱点亮"：既要留住对话数据供模型迭代，又要沉淀掌握度供学生/家长看学习进度。

## 怎么设计（方案）

**（方案口径，已演进）** 早期方案：掌握度按**知识点 URI** 落库，`mastered→75/practicing→50/struggling→25`，取 max **单调不减**，答疑与知识图谱联动点亮。**这已不是最终形态**——落地演进为题型口径（见下）。

## 落地真相（代码）——掌握度主体 = 题型，不是知识点

> ⚠️ **最大翻转**：掌握度主体从"知识点 URI"改为"**题型**"，且从"单调不减"改为"**累计平均**"。方案里 `t_student_kp_mastery` 表已删，替换为 `t_student_topic_mastery`。

### 掌握度怎么算（一道题 → 分数 → 累计平均）

```
学生做题 → decide 判 eval.correct + 是否被引导(hinted=answerRequestCount>0)
  → onRoundSignal 累计到当前题（一道题多轮信号合并）
  → 结算时：题型名 → 聚集 canonical（向量最近邻，防"鸡兔同笼"vs"鸡兔同笼问题"裂行）
  → ScoreMapper 生效分值 = baseScore × per-题型打折
       直接答对 1.0 / 引导后答对 0.5 / 答错 0.0
       × 第1题 0.7 / 第2题 0.8 / 第3题起 1.0（打折作用于分数，防"第1题答错→题型0%"假低）
  → 落题目表(事实源,一道题一条) + 掌握表累计平均(trainCount=已训练数)
```

**设计意图**：不用 max 单调不减（答错永不降、会虚高），用累计平均反映真实水平；打折鼓励学生多练同一题型。

### 数据关联全景（5 类数据 × 关联模块 × 流向）

```
AI 答疑落库 5 类数据
├─① 掌握度 t_student_topic_mastery ──▶ 题型掌握页(queryMastery 分页/分桶) + 回流 decide(mastery_snapshot)
├─② 题目记录 t_student_question_record ─▶ 掌握度页"查看原题"(session_id 跳回答疑会话) = 跨模块回溯
├─③ 错误事件 t_tutoring_error_event ──▶ 学情分析(未来,错题溯源闭环雏形)
├─④ 题型↔知识点 ──▶ 题型库(t_question_type,ADMIN维护) + 教材知识点(KgKnowledgePointPo) + 图谱点亮(kp-matching-lightup)
└─⑤ transcript(COS 每轮整写) ──▶ 历史回看(后端代理读) + 训练数据闭环
```

### 与知识图谱怎么联动（问题表答案）

decide 输出题型/知识点 label → **低置信走澄清卡**：`resolveKp`（PENDING+candidates）→ 学生选/跳过（`voteKp`）→ **AI 预判 + 学生确认双保险** → 图谱条件点亮（`kp-matching-lightup` 独立变更承担，答疑链路**不直接写 Neo4j**）。

### 错误事件的门控（B3）

只把"真实学生错误"落错误事件：仅 decide 原始 type 为 hint/approach（真实评估作答）且模型明确诊断出 `error_type` 才算——switch/end/reveal/concept 轮的 correct=false 是模型默认值，非真实错误不写。

## 追问与防御

**预期追问：为什么掌握度按题型、不按知识点？**
→ **回答要点**：这是**产品/题目分析口径的权衡**，不是技术必然——题型和知识点边界本就模糊（一元二次方程既是题型也是知识点）。落题型是因为：题目天然可聚到题型（canonical 向量聚类稳定、可打分可观测、落库不裂行）；知识点映射依赖图谱（label→URI 解析易错、需 ADMIN 维护）。若题目分析直接产出知识点，掌握度按知识点也成立——是数据口径选择，不是能力边界。

**预期追问：知识点会不会选错？**
→ **回答要点**：双保险闭环——decide 预判 label → 低置信走 `resolveKp`（PENDING+candidates）→ **学生选/跳过**（`voteKp`）→ 观测落库 → `kp-matching-lightup` 条件点亮。模型预判只给候选，最终确认权在学生，不空点不误点。答疑链路本身不直接写 Neo4j。

**预期追问：答疑/掌握度数据与图谱、学情的完整闭环？**
→ **回答要点**：5 类数据三层闭环：① 掌握度 → 题型掌握页（分页/分桶/查看原题跳回）；② 题目记录 → 题型/知识点/图谱（题目是中间环节）；③ 错误事件 → 学情分析（将来）。transcript → 历史回看 + 训练闭环。**家长端报表/多维画像未落地（阶段 3）**——当前只提供数据面（掌握度/题目/错误事件可查询），不能说有家长端。
