## 为什么（语雀）

个人项目要"低成本落地"：MVP 先跑通闭环，复杂度后置。演进要有清晰边界——哪些现在不做、为什么，哪些将来做、怎么做。

## 怎么设计（方案）

MVP = **L0 单次调用**（decide/generate 各一次 LLM），不引入 LangGraph 多步 agent；阶段 2 升级 L1/L2（工具集：查薄弱点/出变式题/错题集）。**为什么刻意不用 agent 编排**：苏格拉底引导是硬约束（不能交给 LLM 自主），业务规则必须确定（20 轮/2 次答案/掌握度），成本与可测性要求调用边界清晰。

## 落地真相（代码）——演进现状 + 踩过的坑

### 当前形态 vs 将来
| 维度 | 当前（已落地） | 阶段 2（演进） |
|---|---|---|
| Python 侧 | L0 两端点（decide/generate），无状态 | LangGraph 多步 agent（工具=Java 内部接口） |
| 智能位置 | 每一步内容生成 | 下一步动作选择 |
| 护栏 | Java 确定性护栏 | 仍 Java 守门（不搬进 Python） |
| 迁移成本 | ActionMeta 契约已预留、工具 API 早定形状 | 低摩擦 |

**MVP 不做的**：题库指纹/结构化步骤/易错分支（阶段 2 题库）、行为风控模型/多维画像/可视化报告（阶段 3）、举一反三变式题（依赖题库+图谱关联，无题库是设计）、多学科答疑（本期只数学）。

### 演进故事（面试讲"当初怎么想的"）
- **存储**：MongoDB → Redis+MySQL+COS 三层（免运维、完整对话恒在 COS）
- **状态机**：7 态流程控制 → 会话生命周期 3 态 + 护栏计数器（状态不随内容膨胀）
- **掌握度**：知识点 URI 单调不减 → 题型累计平均（见 05）
- **OCR**：OCR 主入口 → 图像优先直看 + OCR 兼容（见 06）
- **agent**：LangGraph 编排 → L0 两端点 + Java 护栏（确定性优先，阶段 2 再上）

## 追问与防御

**预期追问：为什么刻意不用 agent 编排？**
→ **回答要点**：**AI 答疑流程是固定的**（判动作→护栏审批→生成→落库），用确定性工作流就够——agent 的"灵活性"在这里是风险：可能某次就甩出完整答案、路径不可预测难测难控预算。自适应学习（"下一步教什么"需根据学生状态动态决策）才是 agent 主场（阶段 2）。届时升级 LangGraph，护栏仍在 Java——确定性边界保住，灵活性在边界内放开。

**预期追问：什么时候才升级 LangGraph？**
→ **回答要点**：当答疑需要"根据掌握度/情绪动态决定下一步"（补前置知识点/降难度/出变式题）时——那是决策问题，agent 决策循环 + 工具集（查薄弱点/出变式题，工具=Java 内部接口），ActionMeta 契约已预留，迁移成本低。
