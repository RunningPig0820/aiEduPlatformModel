# 坑档案（从 git 三端仓库提炼）

> 来源：`aiEduPlatformModel`（Python）/ `aiEduPlatform`（后端）/ `aiEduPlatformFront`（前端）三个 git 历史逐条提炼（2026-08-24）
> 用途：1.4 完善文档「项目踩过的坑」的素材；每条带 **git commit + 代码位置** 双证据，供面试官顺代码追问时指路
> 口径：坑（现象）→ 根因 → 解决，全部来自真实修复记录，**不进 RAG 正文切片**（作证据引用）

## 一、Python 端（aiEduPlatformModel）

### P1. 图片分析慢 50~145s（卡顿根源）
- **坑**：拍图识别/看图答疑肉眼不可用，慢到 50~145s。
- **根因**：doubao mini 默认**开思考** = 先写草稿再答；实测开思考 50~145s、关思考看图 **1.2s**。
- **解决**：`question_understand`/`subject_classify` 显式 `extra_body={"thinking": {"type": "disabled"}}` + 20s 内部超时 + 关 SDK 重试（慢/失败快速返回空结果，Java 降级 PENDING）。
- **证据**：`afaeb2d`；`core/tutoring/question_understand.py:81-91`、`subject_classify.py:66-73`、`ark_stream.py:1-15`（注释）。

### P2. 答疑链路"网络波动"排查
- **坑**：答疑每轮报网络波动，Python 本机自测全通。
- **根因**：后端 base-url **写死 `localhost:9527`**，部署环境访问不到。
- **解决**：转后端改 `application.yml` 一行配置（走配置不写死）。
- **证据**：`426f351`。

### P3. 答错的学生被"恭喜"
- **坑**：decide 断言答对但答案错误时输出 `type=end`，Java 真收尾，答错学生收到恭喜，summary 还可能泄出完整解答。
- **根因**：模型 end 输出与 eval 矛盾（end_reason 偶发 null/COMPLETED/ANSWER_REVEALED 与 correct=false 不一致）。
- **解决**：end 联动一致性护栏——COMPLETED 必须 `correct && exercise_complete`，end_reason 缺失即无效 end → **降级 type=concept** 保持会话 ACTIVE。
- **证据**：`8d97167`；`core/tutoring/decider.py:24-53`（_sanitize_end_consistency）。

### P4. 掌握度主体翻转（知识点→题型）
- **坑**：方案口径"掌握度按知识点/单调不减"，与落库（题型/累计平均）完全对不上。
- **根因**：掌握度事实源改题型表，`kp_key` 语义从 TextbookKP URI 变题型名。
- **解决**：`mastery_snapshot` 语义变更适配，Python 不再拿 kp_key 反查图谱。
- **证据**：`1f94358`；`models/tutoring.py:70-79`（KpSnapshot 注释）。

### P5. langchain 流式丢 thinking
- **坑**：流式想展示"思考过程"，但前端/Java 拿不到 reasoning。
- **根因**：langchain-openai 流式解析**丢弃 reasoning_content**（additional_kwargs 也为空）。
- **解决**：decide/generate 主路径改**直连方舟读原始 SSE**（`ark_stream.py`）；分层思考：decide 关思考（意图秒出）、generate 开思考（思考=AI 版进度条）。
- **证据**：`1cc9c88`、`efd35e2`；`ark_stream.py:1-15`。

### P6. decide 两分法（不答题不该收尾）
- **坑**：学生没答题/在闲聊，decide 也可能判 end 收尾。
- **根因**：模型对"是否该结束"判定过松。
- **解决**：两分法——不在答题一律 `concept` 引导回题，仅明确结束才 `end`。
- **证据**：`1f0b517`。

### P7. 集成测试 403 误报
- **坑**：`test_chat_api` integration 组合跑报 403。
- **根因**：headers 用了错误 token 来源。
- **解决**：改 `settings.INTERNAL_TOKEN`。
- **证据**：`bed0bb1`。

## 二、后端端（aiEduPlatform）

### J1. 会话卡死 SENDING（P0 防卡死）
- **坑**：会话永久卡"发送中"，前端无法恢复（会话 116 卡死根因）。
- **根因**：SSE 200 已发出后 `Flux.error` 直接断连，前端收到流结束却无终态 → 永久 SENDING。
- **解决**：**落库副作用异常降级继续** + **非 agent 异常（含 DB 落库）也兜底终态流**（meta + 兜底 token + done），会话保持 ACTIVE 可重试；前端再加 **SSE 看门狗**。
- **证据**：`d087524`；`TutoringAppService.java:669-686`（handleDecideFailure）；前端 `157b704`。

### J2. 落掌握度 ReflectionException
- **坑**：答疑落掌握度抛反射异常。
- **根因**：V21 删列后 SQL 残留 `evidence/last_session_id` 未同步。
- **解决**：`StudentTopicMasteryMapper` upsert 去残留列。
- **证据**：`139c03e`。

### J3. 答疑每次「网络波动」
- **坑**：答疑每轮都"网络波动"，以为 Python 挂了。
- **根因**：generate 请求 `mastery_signals` 序列化字段名不匹配（kp_label vs topic_label）。
- **解决**：序列化改 `topic_label`。
- **证据**：`5fd8594`。

### J4. 答对信号丢失（score=0 / 直接答对不落库）
- **坑**：学生直接答对收尾，掌握度却记 0/不落库。
- **根因**：END/REVEAL 轮整轮跳过累计，但 END 轮有真实 eval（答对 exerciseComplete）也被跳过。
- **解决**：`noRealAnswer` 判定收紧——SWITCH 恒跳过；END/REVEAL **有 eval 就是真实作答**，照常累计。
- **证据**：`1b2feb6`①；`TutoringAppService.java:734-740`。

### J5. 题型误并（一元一次/一元二次）
- **坑**：向量聚类把"一元一次方程/一元二次方程"归并成一个题型。
- **根因**：编辑距离 ≤1 近字归并——一字之差与错别字（方成/方程）同距离 1，近字归并误并。
- **解决**：**移除 nearestByEditDistance 自动归并**，近字/错别字归并全交给向量层（语义最近邻正确区分）。
- **证据**：`1b2feb6`②；`TopicLabelAggregationService.java:72-78`（注释）。

### J6. 掌握度上限 50%（所有作答算引导后答对）
- **坑**：掌握度永远上不了 50%。
- **根因**：hinted 判定过宽（roundCount 恒 >0 → 所有作答基础 0.5）。
- **解决**：hinted **只看 `answerRequestCount>0`**（学生主动要思路/答案才算引导），AI 主动 hint 不降级。
- **证据**：`1b2feb6`③；`TutoringAppService.java:737-738`。

### J7. 打折系数恒 0
- **坑**：per-题型打折系数恒 0，score 全归零。
- **根因**：`@Value` 打折字段**无默认值**。
- **解决**：补默认值 `0.7/0.8/1.0`。
- **证据**：`e858f9d`；`TutoringAppService.java:145-150`。

### J8. PENDING 题目落库冲突
- **坑**：答疑 PENDING（题型未识别）题目落库报错。
- **根因**：V20 之前 `topic_label` NOT NULL，canonical=null 无法落。
- **解决**：V20 `topic_label` 改可空，PENDING 照常落库**信号不丢**，归属后批量聚集补。
- **证据**：`e94a6ab`；`TutoringAppService.java:789-807`。

### J9. 知识图谱慢 SQL（7 表 JOIN）
- **坑**：教材树下钻接口慢到不可用。
- **根因**：7 表 JOIN + 独立 kp-coverage 聚合链路。
- **解决**：点击式下钻改造（5 层 GET）+ 删 kp-coverage 链路，JOIN 全清零。
- **证据**：`33e03bf`、`0b285d2`、`c112e60`。

### J10. COS transcript 签名 URL 泄露 / CORS
- **坑**：前端直连 COS 拿签名 URL，泄露 + CORS 依赖。
- **解决**：transcript 改**后端代理**（`GET /sessions/{id}/transcript`），前端零 COS 直连；删除 detail 签名 URL。
- **证据**：`74fadad`；前端 `5d9b68d`、`c3542b6`。

### J11. 全量知识点分页恒空
- **坑**：知识点分页查询恒空。
- **根因**：stage 中文/代码双向映射缺失（查询 code 返回中文不匹配）。
- **解决**：中文↔code 双向映射。
- **证据**：`86f90ef`。

## 三、前端端（aiEduPlatformFront）

### F1. 永久卡 SENDING（SSE 看门狗）
- **坑**：后端异常静默关流，前端永久"发送中"。
- **解决**：**SSE 看门狗**——长时间无事件判定流已断，回退可重试态（配合后端 J1 兜底）。
- **证据**：`157b704`。

### F2. 刷新后找不到 ACTIVE 会话 / 同题孤儿会话
- **坑**：generate 卡死/中断时本轮无 done，只在 done 落 localStorage → 刷新后 sessionId 归 null → 下条消息重复建会话。
- **解决**：**meta 到达即持久化**（`handleMeta` 收到 sessionId 立即写 localStorage，幂等），刷新后挂载恢复续走 sendMessage。
- **证据**：`873bd78`；`useTutoringSession.js:258-268`。

### F3. 50002 残留 ACTIVE 反复重放
- **坑**：后端清库后本地残留 ACTIVE，发消息仍走旧 id。
- **解决**：50002 是确定性响应（非网络失败）→ 清理 localStorage 陈旧条目 + 回新建态。
- **证据**：`c8fcd90`；`useTutoringSession.js:704-718`。

### F4. 图片直看超时中断
- **坑**：图片分析（多模态）最坏 ~60s，前端 30s 先超时中断。
- **解决**：timeout 30s→60s + 超时专属文案 + loading 时长提示。
- **证据**：`b9fc538`；`api/modules/tutoring.js:266-273`。

### F5. AI 步骤消息无换行
- **坑**：AI 输出的步骤列表挤成一行。
- **根因**：单换行被 markdown 折叠。
- **解决**：`remark-breaks` 保留单换行。
- **证据**：`5d0808b`。

### F6. 夜间模式覆盖无效
- **坑**：登录页跟随全局夜间模式，主题覆盖无效。
- **解决**：登录页固定白天（`data-theme=aiedu-light`）+ 生成具名主题规则。
- **证据**：`6dc6531`、`4e8e0cc`。

### F7. isEnded TDZ 白屏
- **坑**：历史链路触发 TDZ（temporal dead zone）白屏。
- **解决**：修复 isEnded 初始化时机。
- **证据**：`ef8ee61`。

### F8. OCR 粘贴死代码
- **坑**：粘贴图片走 OCR 确认流程冗余。
- **解决**：粘贴/拖拽图片**直接传图**（多模态看图），OCR 降为兜底，删死代码。
- **证据**：`111cf01`、`ed09d41`。
