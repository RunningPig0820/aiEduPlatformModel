## 业务情况（一条学生消息走完整条链路）

一次答疑交互 = **前端发消息 → Java 编排（安全预检/学科门/护栏/落库）→ Python 决策+生成 → SSE 流式回前端**。

### 1. 入口：前端发消息（自动路由）
前端 `AiQa.jsx` 提交消息 → `useTutoringSession.send()` 自动路由：
- 无会话 → `startSession`（`POST /api/tutoring/sessions`，文字）或 `startSessionWithImage`（图片 multipart）
- 已有会话 → `sendMessage`（`POST /sessions/{id}/messages`）
- 学生点「请求答案」→ `requestAnswer`（`POST /sessions/{id}/request-answer`）
三条都是 SSE 流式，前端挂同一组 handlers（onMeta/onToken/onDone/onError/onAgent/onThinking）。

### 2. Java 编排（`TutoringAppService` 是总控）
- **发起（start）**：先过**学科门**（subject-classify，图片题先传 subject-check 目录供分类器看图）→ 非 math 直接回「仅支持数学」不建会话 → math 才 `ensureCreateAllowed`（创建频率限制）→ 建 `TutoringSession`（ACTIVE）→ 首条消息进 Redis → 进 `orchestrate`。
- **每轮（orchestrate）**：并发锁保护下组装 DecideContext → 调 Python decide（SSE 中继）→ 等 meta → `postDecide`：
  1. safety_flag 终止
  2. 护栏校验（答案/轮次/安全）
  3. 终止类 end（无关/学习方法/非数学）→ TERMINATED
  4. 轮次达顶 → 强制收尾 ROUND_LIMIT
  5. 放行 type（护栏拒绝时用 fallbackType，如 reveal→approach）
  6. 新会话落库 + 消息入缓存
  7. **落库副作用**（掌握度/错误/情绪/round/换题/收尾）——失败降级继续，不阻断 SSE
  8. 每轮实时整写 COS（异步，单线程调度器）
  9. buildStream 流式回前端
- 流式在锁外执行（decide+副作用临界区持锁，generate 不持锁长流）。

### 3. Python 纯智能（L0 两端点，无状态）
- **decide**（`POST /api/tutoring/decide`）：流式决策。短路路径：`is_new_question=true`（Java 换题信号）→ 直接 `type=switch` 不调 LLM。正常路径：组装历史（截断最近 12 条）+ 掌握度快照（薄弱优先 top10）→ 直连方舟 function-calling 流式，边吐 `thinking` 边收集 tool_args → `ActionMeta`；原始流失败降级非流式四段管线。
- **generate**（`POST /api/tutoring/generate`）：按 Java 已放行的 `action_type` 流式生成正文：`meta(action_type) → thinking* → token* → done`。

### 4. SSE 事件序列（前端所见完整序列）
```
agent(guardrail, Java) → meta → agent(generate, Python) → thinking* → token* → agent(memory, Java) → done
```
- decide 阶段 agent 事件（perceive/analyze/plan/decide）由 Java 实时中继，前端「意图解析中」live 展示
- thinking = 模型真实推理分片（generate 开思考），前端「思考过程」逐字流入
- meta 携带 `sessionId/status/type/roundCount/answerRequestCount/eval/masterySignals`
- done 携带 `status/summary/endReason`

### 5. 收尾路径
- 正常收尾（学生解出/要答案/换题/放弃）→ type=end，Java `guardrail.onEnd` 置 ARCHIVED + endReason
- 主动结束 → `POST /sessions/{id}/archive` → end_reason=ABANDONED + COS 终态写 + 清 Redis
- 终止（无关/非数学/安全）→ TERMINATED，回复在 meta.reply，无 token 流
- 结束判定（前端）：meta.status / done.status 为 ARCHIVED 或 TERMINATED 均视为结束
