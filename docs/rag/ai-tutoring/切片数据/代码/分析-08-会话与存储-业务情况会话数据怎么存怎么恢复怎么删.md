## 业务情况（会话数据怎么存、怎么恢复、怎么删）

### 1. 三层存储职责
| 层 | 存什么 | 特点 |
|---|---|---|
| **Redis**（`TutoringSessionCacheImpl`） | 会话快照（生命周期+护栏计数器）、完整消息列表、该生当前 ACTIVE 索引、创建频率计数 | TTL 24h；decide 组装上下文与断点恢复的热源；**不记录题目内容** |
| **MySQL**（4 张表） | `t_tutoring_session`（会话）、`t_student_topic_mastery`（掌握度）、`t_student_question_record`（题目）、`t_tutoring_error_event`（错误事件） | 业务持久层 |
| **COS**（`TutoringTranscriptArchiver`） | 完整对话 transcript：`tutoring/transcripts/{studentId}/{sessionId}.json`，**每轮实时整写（幂等覆盖）** | 恒为完整对话；首次写即回填 transcript_url；根节点带 created_at/updated_at |

### 2. 会话生命周期（3 态，无流程状态机）
- `ACTIVE`（答疑中）→ `ARCHIVED`（正常收尾，endReason：COMPLETED/ANSWER_REVEALED/ABANDONED/ROUND_LIMIT）→ `TERMINATED`（无关/非数学/安全终止）。
- **换题不是状态跳变**：会话保持 ACTIVE，仅重置计数（round/answer 归零）——Java 零题目状态，不归档旧题/不开新会话。

### 3. 断点恢复（中断续聊）
- `GET /sessions/{id}`：Redis 热存会话 + 最近 50 条消息（`RECENT_MESSAGES_LIMIT`）；Redis 过期 → 提示学生重述题目，完整对话恒在 COS。
- 前端挂载：localStorage 有 ACTIVE 快照 → 秒渲染本地 → `reconcileSession` 与服务端对账（补 roundCount/image_url/thinking）。
- **transcript 由后端代理读 COS**：`GET /sessions/{id}/transcript`（前端零 COS 直连，无签名 URL 泄露/CORS 依赖）。

### 4. 历史会话 / 删除
- `GET /sessions`：该学生全部会话（含已归档/终止，updated_at 倒序，不含软删）。
- **删除 = 软删**（`is_deleted=1`）+ 清 Redis 三 key（session+messages+active）；COS transcript/题目图片**保留**（可恢复）。
- 前端 localStorage 只存最近 10 条快照兜底，服务端 50002（会话不存在/已软删）时清理陈旧条目。

### 5. 归档时序
- 每轮 `archiveAsync`（单线程调度器，异步，SSE 不等待 COS 上传）：先"部分写"、后"完整写"顺序执行，防止完整写被部分写覆盖。
- 会话结束（收尾/归档/终止）→ 终态写一次 + `sessionCache.clear`（清 Redis）。
