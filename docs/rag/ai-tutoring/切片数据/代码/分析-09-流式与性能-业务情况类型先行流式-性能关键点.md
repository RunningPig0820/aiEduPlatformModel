## 业务情况（类型先行流式 + 性能关键点）

### 1. SSE 类型先行（meta 先到，前端按类型渲染）
- 每轮完整事件序列（前端可见）：
```
agent(guardrail, Java) → meta → agent(generate, Python) → thinking* → token* → agent(memory, Java) → done
```
- **meta 先行** = 护栏已放行的 `type` 先到前端，前端据此决定气泡类型（hint/approach/reveal/concept/switch/end）再渲染正文——不是先吐字再判类型。
- decide 阶段 agent 事件（perceive/analyze/plan/decide）由 Java 实时中继，前端「意图解析中」live 展示；guardrail/memory 由 Java 注入，generate/thinking 由 Python 透传。

### 2. agent 事件协议（标准阶段表）
- 标准事件格式 `{level, stage, label, status, detail}`；stage 闭集：`perceive / analyze / plan / tool / decide / generate / memory / guardrail`；level 恒 sub（master 预留）。
- 前端按 stage 去重（processing→done 就地更新）、新 stage 追加尾部保持插入序。

### 3. thinking（思考过程 = AI 版进度条）
- **decide 关思考**：意图分类秒出（实测关思考 1.2s / 开思考 50~145s——思考模式=模型写草稿，是「卡顿」根源）。
- **generate 开思考**：解答段流式吐 `reasoning_content` → thinking 事件，前端「思考过程」逐字流入——思考即 AI 版进度条。
- 直连方舟读原始 SSE（`ark_stream.py`）原因：langchain-openai 流式解析会**丢弃 reasoning_content**。
- thinking 只作展示，不影响逻辑；换题/降级场景无 thinking。

### 4. 性能关键点
- **关思考 + 20s 超时 + 关 SDK 重试**（decide/understand/classify 共用）：慢/失败快速返回，不让调用方无限等。
- **decide 响应式中继**（Java `orchestrate`）：SSE 响应在 decide 一开始就建立，Python 的 thinking/agent 实时中继前端，**meta 到达后才走 postDecide**（不是 decide 同步 block 完才开流）——感知延迟大幅下降。
- **流式在锁外**：decide+副作用临界区持锁，generate 不持锁长流（锁 TTL 45s 覆盖 decide 重试窗口）。
- **history 截断**：Python 只保留最近 12 条（`DEFAULT_MAX_HISTORY`）；掌握度快照 top-10（`DEFAULT_SNAPSHOT_TOP_N`）——防上下文撑爆窗口。
- **空流兜底**：generate 零 token → 固定引导话术（Java 零 token 不落库）。
- **done 丢弃/meta 自建**：Java 过滤 Python 的 meta/done，自建 meta/done（带 sessionId/status/counters）。
