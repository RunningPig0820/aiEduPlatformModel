### J11. 全量知识点分页恒空
**1. 问题现象**：知识点分页查询恒空——查不到任何数据，但库里明明有。

**2. 触发流程**（旧链路）：`POST /api/kg/knowledge-points`（`KgKnowledgeOverviewAppService.page`）→ `kgKnowledgePointRepository.countByStage(stage)` / `findPageByStage(stage, ...)`。

**3. 根因分析**：`t_kg_textbook.stage` 库内存**中文 label**（如「初中」），但查询传的是 code（`middle`）→ 无匹配 → 恒空页。**双向映射缺失**：查询方向 code→中文、返回方向 中文→code 都没有。

**4. 排查过程**：从"恒空"反推 → 查库确认 stage 存中文 → 对比查询传 code → 确认 stage 字段语义（code vs label）在库和查询间不一致。

**5. 解决方案 & 改动点**：
- 查询前 `resolveStage(stage)` → `stageEnum.getLabel()`（code→中文）下库
- 响应 `stage` 字段由 `stageEnum.getCode()` 返回（中文→code）
- `KgStageEnum.java:26-49` 增加 `fromLabel(String)`（中文→枚举）
`TutoringAppService` 新增 `toStageCode`（中文→code，用于掌握度列表 stage 回显）。注：`page()` 端点后随 J9 下钻改造移除，但双向映射修复证据完整保留在 `86f90ef` 与 `KgStageEnum.fromLabel`。

**6. 面试口述要点**：讲"**枚举语义 code/label 不一致导致查询恒空**"——库里存 label 查询传 code。踩坑收获：**枚举值在"存"与"查"两侧必须统一语义（code 还是 label），双向映射要么在 DAO 要么在枚举里显式做**；分页恒空先怀疑过滤条件语义，别急着查数据。
