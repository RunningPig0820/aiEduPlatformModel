### J3. 答疑每次「网络波动」
**1. 问题现象**：答疑**每轮**都报"网络波动"，以为 Python 挂了，实际 Python 健康。

**2. 触发流程**：`buildStream` → `contextAssembler.buildGenerateContext`（`TutoringAppService.java:826`）→ `llmPort.generate(genCtx)`（`:829`）→ `GenerateContext` 序列化为 snake_case（`subject_hint/action_type/action_meta`）→ `action_meta.mastery_signals[0].topic_label` 被 Python 契约校验。

**3. 根因分析**：Python 08-17「掌握度信号题型化」把 `MasterySignalItem` 定稿为 `topic_label`（必填），但 Java 序列化方向仍发 `kp_label` → Python 422（`topic_label missing`）→ `buildStream` 的 `onErrorResume` 兜底「网络波动，请重试。」→ **自 08-17 起每轮正文生成必挂**。本质是**跨端契约字段名没对齐**。

**4. 排查过程**：从"每轮网络波动"反推——不是偶发网络问题；看 Python 侧日志发现 422 校验失败 `topic_label missing`；再回 Java 序列化代码确认发的是 `kp_label`。

**5. 解决方案 & 改动点**：`MasterySignalItem.java:31-33` 序列化方向改 `topic_label`，读方向用 `@JsonAlias("kp_label")` 兼容过渡期（javadoc `16-19` 注明 Java↔Python 内部契约 snake_case）。新增回归测试 `ActionMetaContractTest.serialize_generateContext_masterySignalUsesTopicLabel`（断言含 `"topic_label":"鸡兔同笼"` 且不含 `"kp_label"`）。

**6. 面试口述要点**：讲"**跨语言契约字段名不匹配被误报成网络问题**"——Python 422 校验失败，Java 兜底话术是"网络波动"掩盖了真实原因。踩坑收获：**降级话术要能暴露真实错误**；跨端 DTO 序列化方向（@JsonProperty/@JsonAlias）要用契约测试锁死。
