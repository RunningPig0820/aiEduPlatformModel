## 回答

**核心结论**：类型先行流式——decide 出动作元数据 → Java 护栏审批 → generate 流式正文，任何内容流入学生之前 type 已过护栏。

**分层展开**：
- **完整链路**：前端发消息 → Java 编排（学科门 → 建会话 ACTIVE → 消息进 Redis）→ 调 Python decide 判动作（SSE 中继）→ 等 meta → postDecide 护栏（安全/终止类/轮次上限）→ 放行 type → 落库副作用 → 调 Python generate → buildStream 流式回前端。
- **SSE 事件序**：agent(guardrail,Java) → meta → agent(generate,Python) → thinking* → token* → agent(memory,Java) → done。
- **没命中题库**：走通用引导兜底（无题库设计，质量靠大模型苏格拉底引导）。
- **图片题**：图片直传 COS → 多模态 doubao 直接看图解题；换题 = 新图 → is_new_question 短路 switch。
- **收尾**：type=end → Java 置 ARCHIVED + endReason；主动结束走 archive；安全/非数学/无关 → TERMINATED。
- **体验关键**：decide 阶段前端显示"读取题目→解析意图→规划引导→决策"的 live 意图 + 真实推理分片，把 1-2 分钟黑盒等待变成可见的思考过程。
