## 回答

**核心结论**：图像优先为主 + OCR 兼容双通道——主通道直接看图，OCR 降为兜底且要学生确认。

**分层展开**：
- **主通道（图像优先）**：图片直传 COS（tutoring/questions/{studentId}/{sessionId}/{时间戳}.ext）→ 图片 URL 作为 image_url 进 history → decide/generate 的多模态 HumanMessage(text+image_url) → doubao 直接看图解题、判对。格式白名单 jpg/jpeg/png/webp/bmp。
- **为什么图像优先**：数学题大量含公式 + 图形（受力分析图/实例图），传统 OCR 拆解必然丢信息；答疑必须看到原图。
- **独立端点 question_understand**：看图识别 1~5 个题型名 + 顺带知识点，失败返回空 topic_labels → Java 降级 PENDING，不视为错误。
- **OCR 兼容通道**：截屏/公式/手写题的兜底文本化，结果必须经学生确认/修改再进答疑（OcrConfirmModal）；oc.enabled 开关可关闭拍照入口，答疑核心不受阻。
- **换题感知**：学生发新图 = 换题，Java 检测新图 URL 首次出现 → is_new_question=true → Python 短路 switch 不调 LLM。
- **速度保障**：关思考（thinking disabled）+ 20s 超时 + 关 SDK 重试，看图实测 1.2s；前端图片分析超时放宽到 60s。
