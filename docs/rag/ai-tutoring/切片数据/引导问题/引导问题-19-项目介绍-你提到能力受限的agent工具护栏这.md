# 你提到"能力受限的 agent + 工具护栏"，这个架构怎么理解？

## 回答

**核心结论**：两个词分开理解——"能力受限"限制 agent 能做什么，"工具护栏"限制它做出去的动作，两者配合守住教育底线。

**分层展开**：
- **能力受限**：不把答疑做成自由聊天。agent 只能输出动作闭集六值（hint/approach/reveal/concept/switch/end），每次只引导一步，不能自由发挥输出任意内容。
- **工具护栏**：Java 在动作出口做确定性规则——答案要 2 次、20 轮上限、安全内容终止；护栏不是写进 prompt 靠模型自觉，是可单测的代码规则。
- **为什么这个架构**：对话天然是 agent 形态——学生中途换题/问概念/要答案/闲聊，用流程状态机控制会状态爆炸；但 agent 的"灵活性"又是风险——可能某次就甩出完整答案、路径不可预测难测难控。所以能力受限 + 护栏，决策权在 Java。
- **追问点**："为什么决策权放 Java 不放 Python？" → 裁判（审批）与选手（生成）分离，不是语言问题；审批只看 type+count、不看对话，提示词攻击骗不了；审批后果（计数/掌握度/归档）在数据所在方 Java。
