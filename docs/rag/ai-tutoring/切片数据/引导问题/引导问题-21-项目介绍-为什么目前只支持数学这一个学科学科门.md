## 回答

**核心结论**：低成本个人项目先跑通单学科闭环、复杂度后置；学科门用独立小分类器在 decide 之前前置拦截。

**分层展开**：
- **为什么只做数学**：MVP 定位低成本、免费/轻量小模型、免运维；先把数学的引导质量打磨透，多学科是演进项不是当前目标。
- **学科门（subject-classify）**：独立 stateless 端点，decide 之前调用；模型写死 doubao 全模态，输出 K12 十值闭集（math/physics/chemistry/biology/chinese/english/politics/geography/history/other）。
- **分流逻辑**：非 math → Java 直接回"仅支持数学"，不建会话；拿不准 → math（宁可不误拦）；失败/超时 → None → Java 按 math 放行（宁可漏拦不误拦）。
- **复用价值**：闭集显式枚举（SubjectType），将来分学科答疑直接复用——学科门是开关，真正的改造在提示词学科化和题型库。
- **追问点**："图片题学科门怎么判？" → 多模态（text + image_url）进模型，复用 decide 看图路径。
