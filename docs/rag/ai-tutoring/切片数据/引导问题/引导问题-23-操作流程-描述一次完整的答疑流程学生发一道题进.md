## 回答

**核心结论**：前端发消息 → Java 编排（学科门/建会话/护栏/落库）→ Python 决策+生成 → SSE 流式回前端，类型先行、护栏先过。

**分层展开**：
- **前端**：useTutoringSession.send 自动路由——无会话 startSession / 有会话 sendMessage / 请求答案 requestAnswer，三条都是 SSE，同一组 handlers（onMeta/onToken/onDone/onAgent/onThinking）。
- **Java orchestrate（总控）**：并发锁保护 → 组装 DecideContext → 调 Python decide（SSE 中继）→ 等 meta → postDecide：安全终止 → 护栏校验 → 终止类 end → 轮次达顶强制收尾 → 放行 type（护栏拒绝时降级，如 reveal→approach）→ 落库副作用 → buildStream 流式回前端。
- **Python 纯智能**：decide 短路 switch 或流式决策出 ActionMeta（边吐 thinking 边收集 function-calling 参数）；generate 按已放行 action_type 流式生成正文。
- **SSE 事件序**：agent(guardrail,Java) → meta → agent(generate,Python) → thinking* → token* → agent(memory,Java) → done。
- **收尾**：正常收尾 type=end → Java 置 ARCHIVED + endReason；主动结束 archive → ABANDONED + COS 终态写；终止（无关/非数学/安全）→ TERMINATED，回复在 meta.reply。
