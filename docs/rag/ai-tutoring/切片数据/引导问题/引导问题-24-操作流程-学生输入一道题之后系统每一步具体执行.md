## 回答

**核心结论**：六步——学科门 → 建会话 → decide 判动作 → Java 护栏 → 落库 → generate 流式输出，最终以 SSE 事件流形式回到前端。

**分层展开**：
- ① 学科门：subject-classify 判学科，非 math 直接拒（不建会话）。
- ② 建会话 ACTIVE：消息进 Redis，组装 DecideContext。
- ③ decide：读题（文本或图片）→ 输出 ActionMeta——type（闭集）、reason、eval.correct、mastery_signals、question_kps。
- ④ Java 护栏：安全（safety_flag 终止）/ 终止类 end / 轮次上限 → 放行或降级 type（reveal→approach）。
- ⑤ 落库副作用：掌握度/错误/情绪/round，失败降级继续（不影响回复）。
- ⑥ generate：按已放行 action_type 流式生成正文 → SSE 回前端。
- **最终输出**：SSE 流——meta（sessionId/status/type/roundCount/eval/masterySignals）+ thinking（推理分片）+ token（正文逐字）+ done（status/summary/endReason）。
- **追问点**："没命中题型呢？" → PENDING，落库不丢数据，后续归属补 canonical。
