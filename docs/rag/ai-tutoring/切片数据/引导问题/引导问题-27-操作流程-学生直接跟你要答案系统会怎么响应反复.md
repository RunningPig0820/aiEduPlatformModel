## 回答

**核心结论**：答案要两次——第 1 次给思路、第 2 次才给完整答案并立即收尾，防反复要答案。

**分层展开**：
- **完整流程**：学生点"请求答案"→ Java 合成消息进 decide → Python 判 type=reveal → Java 看 answer_request_count。
- **第 1 次（count<1）**：拦下，降级 approach（给思路步骤大纲），计数→1。
- **第 2 次（count≥1）**：放行 reveal 给完整答案，**给完立即收尾** ANSWER_REVEALED（防反复要答案的反复拉扯）。
- **被拒后仍 reveal**：Java 直接降级固定思路话术，不依赖 LLM（不重复调用）。
- **前端配套**：第 2 次点击弹确认框（单向门），学生明确知道"这次会给答案"。
- **为什么这样设计**：学生真的卡住要答案应该被满足（教育体验），但不能无限要——2 次既兜住"真需要"，又堵住"反复刷答案"。
- **追问点**："直接答对但没独立解出呢？" → 答对但未独立解出 → approach 续推思路，不给最终数值，不算 reveal。
