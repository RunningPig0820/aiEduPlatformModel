## 回答

**核心结论**：印象最深的是"答错的学生被恭喜收尾"——教育场景的底线事故，根因是模型 end 输出与 eval 自相矛盾。

**分层展开**：
- **现象**：decide 断言答对但答案错误时输出 type=end，Java 真收尾——答错学生收到"恭喜"，summary 还可能泄出完整解答。
- **根因**：模型 end 输出与 eval 矛盾——end_reason 偶发 null/COMPLETED/ANSWER_REVEALED 与 correct=false 不一致，Java 只信 type=end 就收尾；decide 提示词里"答对必须收尾"被模型违反。
- **解决**：end 联动一致性护栏（_sanitize_end_consistency，确定性代码不信任模型格式）——COMPLETED 必须 correct && exercise_complete；end_reason 缺失即无效 end → 降级 type=concept 保持会话 ACTIVE，清掉 end 字段、不泄解答。
- **价值**：教育场景"答错被恭喜"是产品信任崩塌级别的事故——答错学生被鼓励，下次再也不信系统；护栏把这种事故从"概率问题"变成"不可能发生"。
- **延伸**：同一链路还修了"不确定语气答案判对"（疑问句给对数值=答对收尾）、"学生断言我答对了"走确认复核（核对学生之前答案）。
