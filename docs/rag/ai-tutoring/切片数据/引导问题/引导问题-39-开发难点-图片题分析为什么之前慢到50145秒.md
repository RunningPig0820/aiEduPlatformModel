## 回答

**核心结论**：慢根因不在链路，在模型的思考开关——doubao mini 默认开思考（先写草稿再答），关思考看图 1.2s。

**分层展开**：
- **现象**：拍图识别/看图答疑肉眼不可用，慢到 50~145s，卡顿到用户放弃。
- **根因**：doubao mini 默认开思考 = 先写草稿再答；实测开思考 50~145s、关思考看图 1.2s——思考模式是"卡顿"的根源，不是网络、不是模型能力。
- **解决**：question_understand/subject_classify 显式 extra_body={"thinking": {"type": "disabled"}} + 20s 内部超时 + 关 SDK 重试（openai SDK 默认 600s 才失败）；慢/失败快速返回空结果，Java 降级 PENDING，不让调用方无限等。
- **配套**：decide 也关思考（意图秒出 1.2s）；只有 generate 长输出段开思考（思考 = AI 版进度条）；前端图片超时放宽到 60s。
- **教训**：排查慢链路先看"模型是否在做无谓的思考草稿"——一个配置项就是 50 倍差距。
