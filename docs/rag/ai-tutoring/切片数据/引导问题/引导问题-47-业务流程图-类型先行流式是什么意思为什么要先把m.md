# "类型先行流式"是什么意思？为什么要先把 meta 发给前端再流正文？

## 回答

**核心结论**：类型先行流式 = decide 先出动作元数据（meta）→ Java 护栏审批 → generate 才流式出正文，先给类型、再流内容。

**分层展开**：
- **为什么先发 meta**：① **安全**——reveal 未授权时正文一个字都不会吐出去；绝不边流边拦截（那样答案可能已漏出，护栏失效）；② **体验**——前端先拿到已放行的 type 渲染气泡类型，再收正文，把黑盒等待变可见。
- **时序**：decide（出 meta：sessionId/status/type/roundCount/eval/masterySignals）→ Java 护栏审批 → generate（thinking + token 流式）→ done。
- **前端怎么用**：meta 到达即渲染气泡类型 + 持久化 sessionId；token 逐字流入；done 落终态。
- **追问点**："meta 和 done 有什么区别？" → meta 是"这一轮的动作元数据"（先到、用于渲染），done 是"这一轮的最终状态"（status/summary/endReason，用于收尾判定）。
