## 回答

**核心结论**：职责不同、可独立控制，且护栏必须插在两者之间——拆开是"类型先行流式"安全成立的前提。

**分层展开**：
- **decide（决策器）**：只判动作，输出 ActionMeta（type 闭集/eval/mastery_signals/question_kps）。判断密集 → 关思考、低温度（0.3）、意图秒出；配结构化输出四段降级，绝不吐畸形。
- **generate（生成器）**：只按 Java 已放行的 action_type 流式生成正文。长输出段 → 开思考（思考 = AI 版进度条）；按 GENERATION_RULES 分类型渲染（hint 零步骤/approach 不给数值/reveal 才给完整解答）。
- **为什么拆**：① Java 护栏插中间——审批 type 才放行正文，任何内容流入学生之前已过护栏；② 每子任务独立可控、可单测、可换模型；③ 故障边界清晰——decide 出问题不影响已放行的 generate。
- **追问点**："能不能合成一个接口？" → 合成就无法在决策和生成之间插确定性护栏，安全模型崩塌；两段式是安全与体验的结构性选择。
