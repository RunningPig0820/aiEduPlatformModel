## 回答

**核心结论**：答案、轮次、安全三道护栏都在 Java 动作出口（postDecide）执行——任何内容流入学生之前 type 已过护栏。

**分层展开**：
- **答案护栏（防直接要答案）**：decide 判 reveal → Java 看 answer_request_count——第 1 次拦成 approach（计数→1）、第 2 次才放行并立即收尾 ANSWER_REVEALED；被拒后仍 reveal → 固定思路话术。
- **轮次护栏（防无限刷）**：round_count ≥ 20 且本轮是引导类 → 强制收尾 ROUND_LIMIT，固定话术无 generate；只有 hint/approach 消耗轮次（concept/switch/end/reveal 不消耗）。
- **安全护栏（防高危内容）**：decide 输出 safety_flag=true → 终止会话 TERMINATED，无 token 流，回复在 meta.reply。
- **执行位置**：都在 Java orchestrate 的 postDecide 阶段——收到 decide meta 之后、调 generate 之前；护栏是可单测的确定性规则，不依赖 LLM。
- **三层兜底**：结构化输出四段降级（hint+degraded）、非法 type 默认 HINT 放行、Python 调用失败网络波动话术保持 ACTIVE。
