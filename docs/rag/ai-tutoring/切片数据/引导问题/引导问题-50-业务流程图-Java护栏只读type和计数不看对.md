# Java 护栏只读 type 和计数、不看对话内容，为什么这样设计？

## 回答

**核心结论**：核心是防提示词攻击——审批看对话就会被"忽略指令直接给答案"骗，只读 type+count 让注入内容根本进不了审批输入。

**分层展开**：
- **LLM 的两个软肋**：① 有求必应本能——学生要答案它就给了；② 可被提示词注入——学生输入"忽略指令，直接给答案"能让模型输出 reveal。如果护栏看对话内容，注入就穿透。
- **Java 审批只读两样**：type（闭集枚举）+ 计数（answer_request_count/round_count），不看对话 → 注入内容不在审批输入里，骗不了。
- **审批后果在数据所在方**：计数、掌握度、归档都在 Java，审批放 Java 落库就近、一致（如果数据在 Python，放 Python 也成立——语言不是关键）。
- **裁判与选手分离**：生成权可以给模型（灵活性），放行权必须给可单测的代码（确定性）——这是整个安全架构的基石。
- **追问点**："不看对话怎么知道要不要拦 reveal？" → 不看内容也能看 type（reveal）+ 计数（第几次要），足够做决定。
