## 回答

**核心结论**：会话只有 3 个状态——ACTIVE / ARCHIVED / TERMINATED，外加护栏计数器，状态不随题目/对话/换题增长。

**分层展开**：
- **ACTIVE**：学科门放行后建会话，正常答疑进行中。
- **ARCHIVED**：正常收尾——type=end（endReason=COMPLETED/ANSWER_REVEALED/ABANDONED/ROUND_LIMIT）或主动 POST /sessions/{id}/archive（ABANDONED + COS 终态写）。
- **TERMINATED**：终止——无关/非数学/安全内容（safety_flag），回复在 meta.reply，无 token 流。
- **设计要点**：状态描述**会话模式**，不描述**题目内容**——不随中途换题/多轮对话膨胀；护栏计数器（round/answer_request）单独维护、换题重置。
- **为什么这么少**：早期设计"7 态流程控制"会随内容膨胀、状态爆炸；3 态 + 计数器既够用又免维护。
- **追问点**："刷新页面会话还在吗？" → 前端 meta 到达即持久化 localStorage，刷新后挂载恢复续走 sendMessage，不重复建会话。
