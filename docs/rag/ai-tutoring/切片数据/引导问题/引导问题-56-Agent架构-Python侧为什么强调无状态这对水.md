## 回答

**核心结论**：无状态 = Python 零题目状态，题目从 history 推断——这是可水平扩展的前提，也是状态归位的前提。

**分层展开**：
- **契约**：DecideRequest 无 current_question 字段，当前题目由 Python 从对话历史推断；Java 也零题目状态，只认 type=switch 重置计数。
- **每次调用全量传**：Java 组装 history（截断 12 条）+ 掌握度快照（top-10）传入，单次调用可重试，不依赖服务端会话。
- **水平扩展收益**：无状态服务可以随意加实例（多副本/负载均衡），不共享会话内存；任何实例处理任何请求都等价。
- **状态归位**：会话状态只在 Java Redis 一处，Python 不存——避免双写不一致、状态漂移。
- **换题判定为什么在 Java**：Python 无状态，区分不了"本轮刚换 vs 早几轮已换"；只有 Java 知道何时收到新图——无状态的信息劣势由 Java 的信号补位。
- **追问点**："无状态会不会每次都重新理解题目？" → 会，但换来可扩展性；history 截断 12 条足够模型推断当前题目，且每次决策是独立的。
