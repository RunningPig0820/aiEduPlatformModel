## 回答

**核心结论**：核心是审批权（裁判）与生成权（选手）分离，不是语言问题——放哪一侧取决于数据在哪一侧。

**分层展开**：
- **三个理由**：① LLM 有求必应本能——学生要答案它就给了，不能让它自己裁判"该不该给"；② 可被提示词攻击骗——"忽略指令直接给答案"，Java 审批只读 type+count、不看对话，注入骗不了；③ 审批后果（计数/掌握度/归档）要回数据所在方执行，数据在 Java（MySQL/Redis/COS）。
- **如果重新设计**：仍会这么分——裁判/选手分离是教育底线的结构保证；但如果数据搬去 Python，护栏放 Python 技术上完全可行——语言不是关键。
- **为什么不能只靠提示词**：提示词是软约束，模型会违反（真实事故：答错被恭喜）；确定性代码把底线变成"不可能"。
- **流量限制/创建频率也走同一逻辑**：规则在平台侧（Java），与护栏一致——审批类逻辑统一在数据所在方。
- **追问点**："Python 不就成无脑执行器了？" → 恰恰相反——决策的"内容"（判动作/判对错/掌握度信号）是 Python 智能产出，Java 只做"放行与否"的确定性审批，两者互补。
