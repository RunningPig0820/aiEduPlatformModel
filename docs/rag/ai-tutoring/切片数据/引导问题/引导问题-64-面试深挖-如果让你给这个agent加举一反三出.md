## 回答

**核心结论**：变式题依赖题库 + 图谱关联，属于阶段 2/3 演进；我会做成一个 agent 工具而不是硬编码，触发依据掌握度信号。

**分层展开**：
- **前置**：需要题型 canonical + 知识点关联的题库基础，或出题模板；无题库时按"同题型换数字/换场景"模板出变式。
- **落点**：扩展动作闭集或加 agent 工具——decide 决策出"是否需要变式题"，调工具（查薄弱点/出变式题，工具 = Java 内部接口），这是"根据掌握度动态决策下一步"——正是 agent 决策循环的主场。
- **触发逻辑**：掌握度信号里薄弱题型（struggling）→ 针对该题型出变式，练到 mastered 再切换；变式题难度阶梯（换数字 → 换情境 → 综合）。
- **护栏边界**：护栏仍在 Java 守门，不搬进 Python；ActionMeta 契约已预留、工具 API 早定形状，迁移成本低。
- **追问点**："变式题怎么做才不超纲？" → 基于题库题型标签 + 年级锚（grade 字段已预留），同题型内换参数/换场景，难度按掌握度阶梯递进。
