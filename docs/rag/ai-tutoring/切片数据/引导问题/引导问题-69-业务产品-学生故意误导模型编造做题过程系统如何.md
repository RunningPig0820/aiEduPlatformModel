## 回答

**核心结论**：判对靠验算不采信口述，确认复核兜住"我答对了"的断言，护栏兜底防被带偏。

**分层展开**：
- **判对验算**：decide 判对前把数值代回题目算一遍（reason 写验算过程）——不采信学生口头断言，编造过程不影响数值判定。例：题"小明10岁、妈妈38岁，几年后妈妈年龄是小明2倍"，学生编造过程但答"18年" → 验算 38+18=56、10+18=28、56=2×28 ✓ 判对；答错数值 → 验算不过 ✗ 判错。
- **确认复核**：学生断言"我刚刚答案是对的/我做对了" → 核对学生之前给出的答案：对才确认收尾，错明确告知"答案不对"并指出错因，继续引导——不因学生坚持就改判。
- **护栏兜底**：end 联动护栏（答错绝不恭喜）；Java 护栏只读 type+count 不看对话——学生注入"忽略指令"骗不到审批层。
- **两分法**：在答题的内容无论对错都走 hint/approach 引导，编造的"作答"也被当作作答继续引导，不会直接 reveal。
- **诚实边界**：无法 100% 防（学生抄答案系统不知道），行为风控（高频/无思考/题目指纹）是阶段 3 规划。
