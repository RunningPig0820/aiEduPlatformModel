## 回答

**核心结论**：中断轮不产生错误掌握度，落库副作用失败降级，会话保持 ACTIVE 可重试——脏数据面很窄、有兜底。

**分层展开**：
- **掌握度**：只在有真实 eval 的作答轮累计（END/REVEAL 有 eval 也算——J4 修复）；中断无 done → 不产生错误累计，不会因中断把学生掌握度拉低或虚高。
- **落库副作用失败**：降级继续（不影响回复）——不会因 DB 失败把会话打挂（J1 修复）。
- **错误事件门控**：只落真实错误（hint/approach + 明确 error_type），模型默认值不写（B3）——中断轮的 correct=false 默认值不会污染错误事件。
- **transcript**：COS 每轮整写，中断轮可能缺终态；前端 meta 到达即持久化，刷新后可续走 sendMessage 重试。
- **会话状态**：中断保持 ACTIVE 可重试；前端 SSE 看门狗判流断回退可重试态。
- **追问点**："会不会重复落库？" → 重试可能重复写题目记录，靠幂等（session_id + 轮次）规避；掌握度累计是聚合操作，重复一次影响有限，可对账。
