## 回答

**核心结论**：掌握度是聚合值天然不膨胀，膨胀点（transcript/题目记录）用 COS 外置 + 归档分层解决。

**分层展开**：
- **掌握度**：题型粒度聚合表（每题型一行累计平均 + trainCount），不随会话数线性增长——这是设计红利，不是后补策略。
- **transcript**：已外置 COS（每轮整写），不占 DB；长期保留作训练数据 + 历史回看，Redis 会话历史有时效。
- **题目记录/错误事件**：按时间归档，冷数据转 COS 或分表，热点近期数据可查询；学段/年级/日期分区。
- **裁剪策略**：会话状态只留 3 态 + 计数器（不随内容膨胀）；掌握度按题型聚合，除非题型库膨胀否则表稳。
- **追问点**："Redis 会话历史留多久？" → 时效配置 + ACTIVE 会话语义由 Java 管理；transcript 是完整记录、长期保留，Redis 只是活跃会话的快速读写层。
