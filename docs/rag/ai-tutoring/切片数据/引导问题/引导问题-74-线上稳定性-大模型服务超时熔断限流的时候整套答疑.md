## 回答

**核心结论**：降级原则——不阻断、保会话可重试、永远有兜底终态；用户端看到的是"可重试"而不是"卡死/空回复"。

**分层展开**：
- **Python 侧**：decide 超时 → 结构化四段降级返回 type=hint（绝不阻塞）；generate 空流 → 固定兜底话术（"我这边有点卡顿，我们换个角度…"）；图片/分类端点 20s 超时快速返回空结果（Java 降级 PENDING）。
- **Java 侧**：Python 调用失败 → "网络波动，请重试"话术，会话保持 ACTIVE 可重试；非 agent 异常（含 DB 落库）也兜底终态流（meta + 兜底 token + done），不让前端永久 SENDING。
- **前端侧**：SSE 看门狗判流断、超时专属文案、回退可重试态；创建频率限制防刷。
- **限流**：会话创建频率限制 + 并发锁，超限确定性拒绝，不静默挂起。
- **核心保障**：任何故障都不给学生空回复、不卡会话——用户体验底线是"能重试、不丢现场、有终态"。
