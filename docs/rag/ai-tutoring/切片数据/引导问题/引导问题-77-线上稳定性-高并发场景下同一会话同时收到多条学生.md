# 高并发场景下，同一会话同时收到多条学生消息，如何防止并发乱序、状态错乱？

## 回答

**核心结论**：Java 并发锁串行化同一会话 + 极简会话状态（3 态 + 计数器），天然防乱序、防状态错乱。

**分层展开**：
- **并发锁**：orchestrate 对同一会话加锁，多条消息排队处理（同一会话串行），不同会话并行——不丢消息、不乱序。
- **极简状态**：会话 3 态（ACTIVE/ARCHIVED/TERMINATED）+ 护栏计数器（round/answer_request）——不随题目/对话/换题膨胀，状态错乱面小；状态描述会话模式，不描述内容。
- **轮次原子**：round_count 在锁内更新，不会并发超发（两个请求同时 +1 变 +2 的竞态）。
- **Python 无状态**：每次调用都是独立的 DecideRequest，天然无并发状态问题——并发压力在 Java 侧锁和 Redis。
- **前端**：单会话"发送中"锁，避免连点连发把消息叠出去。
- **追问点**："锁会阻塞其他会话吗？" → 锁是 per-session（同一会话），不同会话并行；decide+副作用临界区持锁 45s，generate 长流不持锁。
