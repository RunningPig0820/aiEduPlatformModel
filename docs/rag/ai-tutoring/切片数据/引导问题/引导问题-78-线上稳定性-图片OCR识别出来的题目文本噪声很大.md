# 图片OCR识别出来的题目文本噪声很大，对后续decide、知识点匹配会带来哪些连锁问题，如何缓解？

> summary: 主通道已是多模态直看图（避开 OCR 文本），OCR 降为兜底且有学生确认闸——噪声问题在默认路径不存在。
> 权威度: 1.0 ｜ 来源: 引导问题 ｜ 锚点: 图片OCR识别出来的题目文本噪声很大，对后续decide、知识点匹配会带来哪些连锁问题，如何缓解？
> 模块: ai-tutoring ｜ 节: 线上稳定性
> 类别：开发难点

## 回答

**核心结论**：主通道已是多模态直看图（避开 OCR 文本），OCR 降为兜底且有学生确认闸——噪声问题在默认路径不存在。

**分层展开**：
- **主通道（图像优先）**：图片直传 COS → doubao 多模态直接看图解题、判对——不经过 OCR 文本，噪声问题在默认路径不存在（这是 2026-08 从"OCR 主入口"反转决策的核心）。
- **OCR 兜底通道**：截屏/公式/手写题才走 OCR，且结果必须经学生确认/修改再进答疑（OcrConfirmModal）——噪声拦在学生确认前，不进 decide。
- **连锁缓解**：即使噪声文本进了 decide，判对靠代入验算（数值代回），不靠文本语义——减少误判；question_kps 识别失败 → PENDING 不丢数据。
- **开关**：oc.enabled 可关闭拍照入口（仅手打/粘贴），答疑核心不受阻。
- **演进**：OCR 定位为兜底文本化工具，不是答疑主入口——答疑核心不依赖 OCR。
