# 当前是decide+generate双接口确定性Workflow，什么场景下你才会考虑迁移到LangGraph？

## 回答

**核心结论**：当答疑需要"根据掌握度/情绪动态决定下一步"时迁移——那时是决策问题，agent 决策循环 + 工具才合适；现在是固定流水线，确定性工作流最优。

**分层展开**：
- **触发场景**：补前置知识点、降难度、出变式题——"下一步教什么"不再是固定流水线（判动作→护栏→生成→落库），需要读学生状态做动态决策，agent 决策循环 + 工具集（查薄弱点/出变式题，工具 = Java 内部接口）才合理。
- **迁移形态**：LangGraph 多步 agent——决策循环 + 工具调用，护栏仍在 Java 守门（不搬进 Python），确定性边界保住、灵活性在边界内放开。
- **迁移成本低的原因**：ActionMeta 契约已预留（eval/Decision 独立子结构可单独绑定函数）、工具 API 早定形状——升级是加一层决策循环，不是推翻契约。
- **现在不迁的原因**：答疑流程固定，agent 灵活性是风险——可能某次甩出完整答案、路径不可预测难测难控预算；苏格拉底引导是硬约束，不能交给 LLM 自主。
- **追问点**："怎么判断该不该迁？" → 当"下一步动作"需要查数据（掌握度/错题/情绪）做判断，而不是固定规则推进时——那是 agent 主场。
