## 回答

**核心结论**：以已落库的 transcript 和逐轮信号为基础，补"回看 UI + bad case 检索 + 回流闭环"三块能力，评测白盒正好承接回流。

**分层展开**：
- **数据埋点（已具备）**：每轮 transcript（COS 整写）、meta（type/eval/mastery_signals）、error_type、耗时、降级标志（degraded）、网络波动标记。
- **能力一：会话回看**：后端代理读 transcript（前端零 COS 直连），按 session_id 完整回放逐轮 问题/引导/作答/收尾。
- **能力二：bad case 检索**：按题型/错误类型/降级标志筛选异常会话——如"某题型普遍答错"（共性错误 = 引导问题）、"降级频次高"（工程问题）、"答错被收尾"（正确性问题）。
- **能力三：回流闭环**：bad case 标记 → 评测集扩面 → 修正提示词/切片 → 复测——现有 eval/report 白盒（hit@k/质量分/降级监控）正好承接。
- **现状**：数据面已齐（transcript/meta/error_type），人工复盘 UI 未落地（阶段 2/3）。
- **追问点**："怎么定位一个具体 bad case？" → 三层下钻：指标异常（掌握度骤降/降级高）→ 检索相关会话 → transcript 回放定位到具体一轮的 decide 决策错误。
