## 回答

**核心结论**：一次答疑 = 前端发消息 → Java 编排（学科门/建会话/护栏/落库）→ Python 决策+生成 → SSE 流式回前端，类型先行、护栏先过。完整流程图（基于代码 `api/tutoring.py` 四端点 + Java `TutoringAppService` orchestrate）：

```
┌─ 前端 React ─────────────────────────────────────────────┐
│ useTutoringSession.send 自动路由                          │
│   无会话  → startSession   → POST /sessions               │
│   有会话  → sendMessage    → POST /sessions/{id}/messages │
│   请求答案 → requestAnswer  → POST .../request-answer     │
│   (图片)  → sendWithImage  → sessions(图片 multipart)     │
│ SSE 消费: onMeta/onToken/onDone/onAgent/onThinking        │
│ meta 到达即持久化 localStorage; SSE 看门狗防卡死           │
└──────────────────────────────────────────────────────────┘
        │ POST /sessions (SSE 上行)
        ▼
┌─ Java 平台层 (TutoringAppService 总控) ─────────────────┐
│ 发起(start):                                             │
│  ① 学科门: POST /api/tutoring/subject-classify          │
│     (图片先传 subject-check 目录看图)                    │
│     → 非 math: 直接回「仅支持数学」, 不建会话            │
│     → math: 创建频率限制 → 建会话(ACTIVE) → 消息进 Redis │
│ 每轮(orchestrate, 并发锁):                              │
│  ② 组装 DecideContext(history/掌握度快照/计数)          │
│  ③ 调 Python decide(SSE 中继) → 等 meta(ActionMeta)     │
│  ④ postDecide 护栏:                                     │
│     · 安全终止(safety_flag) → TERMINATED                │
│     · 终止类 end → 放行                                  │
│     · 轮次达顶(≥20) → ROUND_LIMIT 强制收尾              │
│     · 放行 type(护栏拒绝降级: reveal→approach)          │
│  ⑤ 落库副作用: 掌握度/错误/情绪/round(失败降级继续)     │
│  ⑥ 每轮实时整写 COS(异步)                              │
│  ⑦ 调 Python generate → buildStream 流式回前端          │
└──────────────────────────────────────────────────────────┘
        │ /api/tutoring/decide    /api/tutoring/generate
        ▼
┌─ Python 纯智能 (无状态) ─────────────────────────────────┐
│ decide:                                                  │
│   is_new_question=true → 短路 type=switch(不调 LLM)      │
│   否则 流式决策(直连方舟, 关思考):                        │
│     → thinking*(真实推理, 可多条)                        │
│     → function-calling 累积 tool args → ActionMeta       │
│     → 四段降级兜底 + end 联动护栏(不吐畸形/不误收尾)      │
│   SSE: agent(perceive→analyze→plan→decide) + thinking*  │
│        + meta(ActionMeta) + done                         │
│ generate:                                                │
│   按已放行 action_type 渲染 GENERATION_RULES             │
│   → 直连方舟(开思考) → meta → thinking* + token* → done  │
│ question-understand / subject-classify: 同步 JSON(独立)  │
└──────────────────────────────────────────────────────────┘
        │ SSE 事件流: agent(guardrail,Java)→meta→
        │ agent(generate,Python)→thinking*→token*→
        │ agent(memory,Java)→done
        ▼
┌─ 收尾 ───────────────────────────────────────────────────┐
│ type=end        → Java 置 ARCHIVED + endReason            │
│ 主动结束 /archive → ABANDONED + COS 终态写               │
│ 终止(无关/非数学/安全) → TERMINATED, 回复在 meta.reply    │
│ 前端判定结束: meta/done.status ∈ {ARCHIVED, TERMINATED}  │
└──────────────────────────────────────────────────────────┘
```

**分层解释**：
- **前端**：三条入口都是 SSE，同一组 handlers（onMeta/onToken/onDone/onAgent/onThinking）；meta 到达即渲染气泡类型 + 持久化 sessionId。
- **Java**：学科门前置（不建会话拦非数学）；orchestrate 每轮"调 decide → 护栏审批 → 落库 → 调 generate"，落库失败降级继续、非 agent 异常兜底终态流。
- **Python**：四个端点——decide/generate 是 SSE（类型先行流式），question-understand/subject-classify 是同步 JSON；无状态，题目从 history 推断。
