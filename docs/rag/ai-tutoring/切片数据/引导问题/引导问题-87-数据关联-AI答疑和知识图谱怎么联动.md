## 回答

**核心结论**：AI 预判 + 学生确认双保险 → 条件点亮 → 更新掌握度——答疑产出题型/知识点 label，图谱按订阅式协作点亮，答疑链路本身不直接写 Neo4j。

**分层展开**：
- **联动链路**：decide 输出题型/知识点 label → 低置信走澄清卡 resolveKp（PENDING + candidates）→ 学生选/跳过 voteKp → 观测落库 → kp-matching-lightup 条件点亮。
- **为什么要点亮**：学习进度可视化——学生/家长看到知识点逐步点亮，配合掌握度（题型口径）形成"学情"闭环；不点亮的题保持 PENDING，数据不丢。
- **回流**：掌握度快照回流 decide（snapshot_top_n 薄弱优先），让引导更贴合学生水平——图谱点亮不是终点，是决策数据源之一。
- **边界**：答疑链路不直接写 Neo4j，点亮由独立变更（kp-matching-lightup）承担——职责清晰、可独立回滚、不耦合高频答疑写入。
- **追问点**："如果学生跳过确认？" → 不点亮、保持 PENDING，不阻塞答疑主线，后续可再确认。
