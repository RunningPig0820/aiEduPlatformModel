## 回答

**核心结论**：题型/知识点的补充是"答疑落库 → canonical 聚集 → ADMIN 维护 → 图谱/掌握度消费"的闭环，不是答疑现场临时建的。

**分层展开**：
- **答疑产出**：decide 每轮输出 topic_label（题型名）+ question_kps（顺带知识点）；question_understand 看图识别 1~5 个题型名——这些是"候选标签"，不直接入库为权威。
- **canonical 聚集**：题型名 → 向量最近邻归一到 canonical（COS topic-index，768 维）——"鸡兔同笼"/"鸡兔同笼问题"落库到同一题型，防裂行。
- **题型库 ADMIN 维护**：t_question_type 是权威题型库，canonical 口径由 ADMIN 维护；模型输出只是候选，最终归属由聚集层 + 维护层决定。
- **知识点映射**：题型 ↔ 教材知识点（KgKnowledgePointPo）由后端维护接口承担，知识点从题型派生。
- **补充路径**：未识别的 PENDING 题目不丢数据，归属后批量聚集补 canonical；未命中题库的题标记"待入库"给教研（阶段 2 题库）；掌握度按题型累计平均（trainCount 记录训练数）。
- **追问点**："新题型怎么进库？" → 聚集层发现高频未归一的题型名 → 人工（ADMIN）确认为新 canonical → 题型库 + 知识点映射补齐。
