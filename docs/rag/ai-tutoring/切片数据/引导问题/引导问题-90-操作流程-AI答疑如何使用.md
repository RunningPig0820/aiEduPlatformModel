## 回答

**核心结论**：学生端"拍题/打字/粘贴 → 逐轮引导作答 → 独立解出或收尾"的使用闭环，前端三条自动路由入口。

**分层展开**：
- **进入答疑**：打开答疑页（前端自动路由 useTutoringSession.send）——无会话自动 startSession（POST /sessions），有会话自动 sendMessage（POST /sessions/{id}/messages）。
- **输入题目**：三种方式——① 打字/粘贴题目文本；② 拍题/选图/拖拽（sendWithImage，图片 multipart 上传 COS → 多模态 doubao 看图）；③ 截屏/公式/手写走 OCR 确认（可选，需学生确认文本）。
- **学科门**：系统先判学科（subject-classify）——非数学直接提示"仅支持数学"不建会话；数学才进入答疑。
- **逐轮引导**：系统 decide 判动作 → Java 护栏 → generate 流式输出——hint（反问推一步）→ 学生作答 → 判对/继续引导 → approach（思路大纲）→ 再作答……前端实时显示"读取题目→解析意图→规划引导→决策" + 思考过程。
- **出口**：① 独立解出 → 系统肯定收尾（COMPLETED）；② 想要答案 → 点"请求答案"（requestAnswer），第 2 次才给完整解答并收尾；③ 换题 → 贴新题即 switch；④ 不想做了 → 明确说结束 → 收尾（ABANDONED）；⑤ 20 轮上限强制收尾（ROUND_LIMIT）。
- **使用后**：掌握度落库 → 题型掌握页可看进度；题目记录可"查看原题"跳回会话。
- **追问点**："没看懂引导怎么办？" → 明确说"我不会/太难了" → 系统升 approach 给思路大纲；再不行走 reveal 或放弃，有完整退出路径。
