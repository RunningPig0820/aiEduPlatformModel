## 1. `/api/tutoring/rag/query` 请求：新增 `current_project` + `history` 字段

**变化**：`RAGQueryRequest` 新增 `current_project`（默认 `ai-tutoring`）+ `history`（最近 3 轮，追问改写/展开用）。

```json
// Java 调用 POST /api/tutoring/rag/query
{
  "question": "能说的详细一点吗",
  "top_k": 5,
  "current_project": "ai-tutoring",   // 当前上下文模块(用户在哪个功能页)
  "history": [                        // 最近 3 轮(追问改写补全省略/上一轮答案作展开基础)
    {"question": "流程图是什么样的", "answer": "一次答疑=前端→Java→Python→SSE", "anchor": "ai-tutoring"}
  ]
}
```

**作用**：
- `current_project`：intent LLM 倾向保持该模块（prompt 带"当前上下文模块，除非问题明确属其他模块"）。不传 → 默认 ai-tutoring，多模块下会路由不准。
- `history`：追问"能说的详细一点吗"省略主语时，Python `rewrite_query` 结合 history 补全（实测 → "ai-tutoring 流程图详细说明" → 命中流程图块）；生成时上一轮 answer 作展开基础。

**模块闭集**：`ai-tutoring`（AI答疑）/ `rag-system`（RAG项目）/ `knowledge-graph`（知识图谱）/ `question-analysis`（题型分析）。

**Java 待办**：
1. 调用时传用户当前所在模块页（current_project）
2. 传最近 3 轮 history（会话存 Java Redis，Python 只消费最近 3 轮，`HISTORY_LIMIT=3`；传多了 Python 也截断）
3. **Redis TTL 建议**：会话历史 TTL 从 10min 收到 **3~5min**（覆盖用户一轮思考间隔即可；太短追问丢上下文，太长浪费 Redis）——保存时长由 Java `setex/expire` 控制，与 langchain 无关

**变化**：`file_path` 从本地相对路径 → COS 普通桶 key。

| 以前 | 现在 |
|---|---|
| `4.完善文档/04-安全与防作弊.md` | `rag-source/ai-tutoring/完善文档/04-安全与防作弊-护栏.md` |

**规则**（见 `向量桶入桶清单.md` 7.2）：
- 源语料：`rag-source/<模块>/<源目录>/<文件名>.md`
- 切片视图：`rag-slices/<模块>/<子目录>/<文件名>.md`

**前端"查看原文"链路**（U4 完成后）：
```
前端 file_path = "rag-slices/ai-tutoring/坑档案/坑档案-J1-...md"
  → GET /api/rag/source/{file_path}
  → Python 读 COS: ai-edu-1318177119 / 该 key → 返回文件内容
```

**Java 待办**：前端直接透传 `file_path` 到 `/api/rag/source`，不做本地路径拼接。

## 6. M6 引导底座池改造（2026-08-26 Python 完成，Java 需适配）

> **背景**：引导问题不能自由发挥（后端问题6）——开始引导/结束建议都围绕 `引导问题.md` 底座池，保证池内问题都能被语料答出。Python 侧已落地（`core/rag/guide_pool.py` + assistant 改造 + 问候识别）。

**Java/前端适配点**：

1. **`GET /api/rag/assistant/guide` 新增可选 `?current_project=`**：进页面/切换功能时传当前模块（ai-tutoring/knowledge-graph/question-analysis/rag-system）。不传/未知 → Python 兜底 ai-tutoring。每功能引导问题不同，必须以当前功能为准。

2. **guide `direction` 值变更**：旧 `architecture/data_flow/evaluation` → 新 `intro/operation/data_relation/difficulty/rag`。前端如果按旧方向值硬编码（展示标签/图标映射）需适配；仅透传展示则无影响。

3. **`done.suggestions` 语义变更**：结束建议从自由生成 → 池内约束（LLM 只能生成与池内问题方向类似的，兜底池内随机 2 条必含 ≥1 条 rag）。格式仍为字符串列表（`["...", "..."]`），前端结构不变。

4. **问候识别**：`intent` 的 `category` 可能出现 `问候`（新增枚举），`ambiguous=false`（不再误触发 clarify）。问候轮 done 返回固定欢迎话术 + 引导建议，`answer` 非空但 `tokens_usage.total_tokens=0`，前端可作"欢迎语"正常渲染。
