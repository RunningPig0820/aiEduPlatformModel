## 2. 入桶字段结构（每条记录）

写入 payload = `{key, data, metadata}`（build_index.py）：

- **key**：`rag-{pool}/{file}/{anchor}#{idx}`（池前缀防两池冲突；同 key upsert）
  - 全量池 `rag-full/...`、切片池 `rag-slice/...`
- **data**：`float32` 向量，**768 维**，embedding 输入 = `summary + "\n" + text`
- **metadata（10 字段，≤COS 向量索引单条上限）**：`version / module / category / source / authority / section / file / file_path / anchor / summary`
  - `version` = `YYYY-MM-DD-<语料sha1[:6]>`，语料变→版本变，走 metadata 不走索引名
  - `module` = 模块闭集 id（ai-tutoring/knowledge-graph/question-analysis/rag-system），Filter 按它筛
  - `category` = **9 类闭集标签**（项目介绍/操作流程/数据关联/开发难点/业务流程/架构设计/业务视角/数据存储/未来演进）——**入桶字段，查询不再按它过滤**（2026-08-26 决策）
  - `source` = 语料来源（完善文档/语雀/OpenSpec/代码/坑档案/引导问题）
  - `authority` = 权威度（1.0/0.8/0.7）
  - `file` = 源文件名（去 .md）；`file_path` = **COS key**（`rag-source|rag-slices/<模块>/...`，前端"查看原文"用）
  - `anchor` = 块锚点；`summary` = LLM 生成的"解决什么问题"一句话
- **text 正文不进 metadata**（COS 向量索引 ~20KB/条限制），留在 `rag_slices.jsonl`，命中后按 key 反查
- 注：`doc_type` 已去掉（与 module 同值冗余，且 10 字段是 COS 单条上限）

## 6. 维护注意

- **新增模块**（知识图谱/题型分析/RAG 项目）→ 语料入 `docs/rag/<模块>/` → `md_to_jsonl.py`（切片池）/`slice_full.py`（全量池）生成该模块块（tags.module=模块id）→ `build_index.py --pool full/slice` 入同桶 → 检索自动按模块路由
- **重建索引（双池）**：
  - 全量池：`cd ai-edu-ai-service && python scripts/rag/build_index.py --pool full --clear`
  - 切片池：`cd ai-edu-ai-service && python scripts/rag/build_index.py --pool slice --clear`
  - （两池各清各的，幂等）
- **⚠️ 切片池 jsonl 从 `切片数据/` md 生成（`md_to_jsonl.py`）**：改数据直接改 md 再重生成，不重跑 slice_corpus（切归切、改归改）
- **⚠️ `slice_full.py` 从源文件重新生成全量池**：会覆盖当前 jsonl；完善文档 01 增强段已补回源文件，重生成无损
- **入桶前校验**：`rag_slices.jsonl` 每块含 `tags.category`（9 类闭集）+ `tags.pool`（slice/full）；`build_index.py` metadata 10 字段（module/category/COS key）

## 7. COS 路径设计（2026-08-26 定稿）

> 目的：切片文件 + 源语料上传 COS 普通桶，`file_path` 记录 COS key，前端"查看原文"走后端代理从 COS 取，不依赖本地路径（解决"文件不存在"）。

### 7.1 目标桶与访问方式（用户决策）

| 项 | 结论 |
|---|---|
| 目标桶 | `ai-edu-1318177119`（Java 普通桶，region ap-guangzhou） |
| 上传内容 | **切片数据 + 源语料都传**（`切片数据/` + `1.语雀/` + `2.OpenSpec/` + `3.代码/` + `4.完善文档/` + `5.难点/` 等） |
| 访问方式 | **后端代理 COS**——前端仍调 `GET /api/rag/source/<key>`，后端从 COS 读返回 |

### 7.2 COS key 规则（文档类别前缀 + 模块区分）

**顶层 = 文档类别**（`rag-source` 源语料 / `rag-slices` 切片视图，两类全局并列），次层 = 模块标识（桶里多模块共存，不冲突），再后是自己的路径：

| 数据 | COS key | 例 |
|---|---|---|
| **切片视图** | `rag-slices/<模块>/<子目录>/<文件名>` | `rag-slices/ai-tutoring/坑档案/坑档案-J1-会话卡死-SENDINGP0-防卡死.md` |
| **源语料** | `rag-source/<模块>/<源目录>/<文件名>` | `rag-source/ai-tutoring/完善文档/01-模块定位与核心价值.md` |

模块标识 = module 闭集 id：`ai-tutoring`（AI答疑）/ `knowledge-graph`（知识图谱）/ `question-analysis`（题型分析）/ `rag-system`（RAG 项目）/ `org-center`（组织中心）。

### 7.3 file_path 记录（jsonl + metadata）

每块 `file_path` 改为完整 COS key：
```json
// 切片块
"file_path": "rag-slices/ai-tutoring/坑档案/坑档案-J1-会话卡死-SENDINGP0-防卡死.md"
// 源语料块(全量池)
"file_path": "rag-source/ai-tutoring/完善文档/01-模块定位与核心价值.md"
```

### 7.4 访问链路（后端代理 COS）

```
前端 file_path = "rag-slices/ai-tutoring/坑档案/坑档案-J1-...md"
  → GET /api/rag/source/rag-slices/ai-tutoring/坑档案/坑档案-J1-...md
  → 后端读 COS: ai-edu-1318177119 / rag-slices/ai-tutoring/坑档案/坑档案-J1-...md
  → 返回文件内容 → 前端渲染
```
