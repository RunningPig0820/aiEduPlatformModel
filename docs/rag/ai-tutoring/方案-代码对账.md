## 一、真实链路（代码确认）

```
前端 /student/ai-qa（AiQa.jsx + useTutoringSession.js）
  ├─ 文字题   → POST /api/tutoring/sessions {message}
  ├─ 图片题   → POST /api/tutoring/sessions (multipart file)    ← 直接传图，多模态看图
  ├─ 换题     → POST /api/tutoring/sessions/{id}/messages (multipart 新图)
  ├─ 请求答案 → POST /api/tutoring/sessions/{id}/request-answer
  └─ OCR     → POST /api/tutoring/ocr（识别 → 学生确认 → 转文字进答疑）
        │
        ▼
后端 TutoringAppService（编排核心）
  1. 学科门 subject-classify（decide 之前）：非 math → 不建/不续会话、不落库，直接「仅支持数学」提示流
  2. Redis 会话并发锁（45s）+ 建会话（含创建频率限制 50004）
  3. orchestrate：decide 流式中继（thinking + agent 事件 perceive/analyze/plan/decide 透传）→ meta 到达
  4. postDecide：
     · safety_flag → 终止（TERMINATED，无 token 流）
     · 护栏校验（答案/轮次/安全）
     · 终止类 end（type=end 且 end_reason 空 = 无关/学习方法/非数学）→ TERMINATED 直接回复
     · 轮次护栏拒绝（fallback=end）→ ROUND_LIMIT 固定话术收尾
  5. 落库副作用：答案计数 / 换题重置 / 轮次 / 情绪 + 题型掌握度 UPSERT + 错误事件（B3 门控）
  6. COS 每轮实时整写（异步，恒完整对话）
  7. 流式：agent(guardrail) → meta → agent(generate) → thinking* → token* → agent(memory) → done
```

关键代码位置：
- 编排核心：`ai-edu-backend/.../learning/TutoringAppService.java`
- 护栏：`.../learning/TutoringGuardrailService.java`
- API 入口：`ai-edu-interface/.../api/learning/TutoringController.java`
- 前端会话 hook：`ai-edu-front/src/hooks/useTutoringSession.js`
- 前端 API：`ai-edu-front/src/api/modules/tutoring.js`

## 三、差异点（文档 ≠ 代码，完善文档必须按代码口径写）

### 差异 1 ⚠️ 掌握度主体已翻转：知识点 → 题型（最严重，方案过时）

- **方案**（`design-backend-ai-tutoring` 决策8/9）：掌握度=**知识点**，按 `TextbookKP URI` 落 `t_student_kp_mastery`；
  `mastered→75 / practicing→50 / struggling→25`，取 max **单调不减**；收尾按 end_reason 校正（COMPLETED→75+）。
- **代码**（`TutoringAppService.applyMasteryAndErrors` 726-776 + `persistQuestionAttempt` 784-818）：
  掌握度=**题型（canonical）**，落 `t_student_topic_mastery` + `t_student_question_record`（题目表，事实源）；
  打分走 `ScoreMapper.effectiveScore(correct, hinted, trainCount)` = 答对1.0 / 提示后0.5 / 答错0.0，per-题型打折（0.7/0.8/1.0）→ **applyScore 累计平均**。
  `mastery_signals` 的 signal 值（75/50/25）**不参与落库**，仅做前端 chips 展示 + memory 事件文案；`kpResolver` 只用于错误事件的 `firstKpUri`。
- **根因**：`ai-tutoring-topic-mastery-signal` 变更（Python 仓库）把掌握度主体翻转过来了，`design-backend-ai-tutoring` 决策9 是翻转前的旧设计。
- **完善文档写法**：主口径 = 题型掌握度（label→canonical 聚集→ScoreMapper→累计平均）；旧口径（TextbookKP URI 单调不减）降级为"演进故事"（掌握度主体从知识点演化为题型）。

### 差异 2 「学生确认知识点」的真实形态 = 低置信题型澄清卡

- **方案**：AI 预判 + 学生确认 → 条件点亮图谱（结尾一次性确认卡）。
- **代码**：`mastery_signals` 里新增 label → 前端 `checkClarifications` 调 `/kp/resolve`；若返回 **PENDING + candidates** → 弹**澄清卡**（学生选候选 / 跳过）→ `/kp/vote` 落 `source=student_vote` 观测。
- **本质**：这不是"确认知识点去点亮图谱"，是**低置信题型 label 的解析归属确认**（resolve 命中不了 URI 时的候选选择）；答疑链路本身**不写 Neo4j**。图谱点亮（kp-matching-lightup）是另一条独立变更，消费答疑产出的题型/知识点观测。
- **完善文档写法**：讲"知识点确认"要落在这个澄清卡机制上；图谱点亮单独讲（由 kp-matching-lightup 承担），别把两者搅在一起。

### 差异 3 OCR 不是被"反转"掉，是双通道共存

- **方案**：决策15"图像优先反转 OCR 决策"（不做传统 OCR）。
- **代码**：**图片直传（主，多模态看图）+ OCR 识别确认入口完整保留**（`POST /api/tutoring/ocr`，`ocr.enabled` 开关控制前端拍照入口显隐）。前端同时暴露：拍照→OCR→确认→发文本；图片直传→多模态直接进答疑。
- **完善文档写法**：讲"图像优先"为主，但说明 OCR 作为**降级/兼容通道**保留（带开关），不是被丢弃。

### 差异 4 代码新增实现（方案没写，面试可讲）

- **Redis 会话并发锁**（45s TTL，decide+副作用临界区串行化，generate 在锁外）——`withSessionLockReactive`
- **会话创建频率限制**（50004，配置 `create-window` / `create-limit`）——`ensureCreateAllowed`
- **题目表 `t_student_question_record`** 作为掌握度事实源（一道题一次作答一条记录，含 score/hintCount/answerRequestCount/sessionId，支持「查看原题」跳回）
- **题型动态聚集** `topicLabelAggregationService.aggregate`（散题型名 → canonical，掌握表不裂行）——题型掌握度不裂行的关键
- **错误事件 B3 门控**：仅当 decide 原始 type 为 hint/approach 且模型明确诊断 `error_type` 非空才写错误事件（防 switch/end/reveal/concept 轮的默认 `correct=false` 误记）

### 差异 5 安全/防套答案的"护栏兜底"细节

- 方案讲"答案护栏 + 轮次护栏"；代码还确认了**护栏被拒后的重决策兜底**：reveal 被拒重决策仍 reveal → Java 直接降级固定思路话术 `FALLBACK_APPROACH_SPEECH` + count→1（不依赖 LLM，保证兜底可用）。
- 结构化输出兜底：Python `degraded=true`（type=hint）→ Java 按普通 hint 放行 + 记日志，**不使用 503**。

## 五、对完善文档（8节）的写作指引

1. **核心链路一节按差异1-5 的代码口径写**，每节给代码位置引用（面试官可顺着看）。
2. **掌握度/知识点联动一节**：主口径 = 题型掌握度（ScoreMapper 累计平均）；知识点确认 = 低置信澄清卡（resolve/vote）；图谱点亮 = kp-matching-lightup 独立线，三者分清。
3. **旧方案口径**（TextbookKP URI 单调不减、结尾确认卡、OCR 反转、行为风控）作为**演进故事**保留在"为什么这样设计"里，不当作现状。
4. 面试问题 `ai-tutoring.md` **一条不改**——完善文档必须能回答问题表全部提问，且答案与代码一致。
