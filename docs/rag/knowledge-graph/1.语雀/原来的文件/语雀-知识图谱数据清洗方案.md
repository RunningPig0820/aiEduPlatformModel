## 一、专家级核心疑问（落地前必须明确，直接决定图谱生死）
这些问题是教育知识图谱 90% 项目踩坑的根源，精准贴合你的业务场景，你需要先明确边界：

1. **知识点的粒度是如何定义的？** 是「一元一次方程」（章节级大知识点），还是「一元一次方程的移项法则」（最小考点粒度）？这个直接决定 GraphRAG 的召回精度、学情诊断的颗粒度、AI 组卷的精准度，是整个图谱的根基。
2. **教材版本的差异，本质是归属不同，还是内容不同？** 比如人教版和苏教版的「勾股定理」，是同一个知识点放在不同年级 / 章节，还是知识点本身的内容、考法有增减？这个决定了「教材 - 章节 - 知识点」的核心关系模型。
3. **AI 答疑的引导逻辑，核心依赖什么关联？** 是知识点的**前置学习依赖**（先学整式加减，再学一元一次方程），还是**解题方法关联**（行程问题→方程法 / 算术法），还是**考点 - 考法关联**？这个直接决定你图谱核心关系的设计优先级。
4. **学情掌握度的计算规则是什么？** 是仅基于「题目正确率→对应知识点的掌握度」，还是要结合前置依赖链路（比如前置知识点没掌握，就算当前题目做对，也判定存在掌握风险）？这个决定了图谱的查询路径和深度设计。
5. **新题目入库的审核流是怎样的？** 是 AI 自动提取知识点关联后直接入库，还是必须经过教研人工复核？这个决定了你的数据流和业务层 CSV 的维护流程。
6. **AI 组卷的核心约束是什么？** 是仅按「知识点范围、难度、题型」选题，还是必须保证「知识点覆盖度、前置依赖的完整性、不超纲」？这个决定了组卷场景的图谱查询逻辑。
7. **十万级数据量的构成是什么？** 是仅知识点节点，还是「知识点 + 题目 + 教材 + 章节」的全量节点？比如知识点是万级，题目是十万级，关系是百万级？这个决定了 Neo4j 的性能优化和导入方案。

### 3. 适配你业务的导入方案优化
针对十万级以上数据量，分两种场景做性能优化：

1. **首次全量导入（基准库 + 历史业务数据）**使用 Neo4j 原生的`neo4j-admin import`离线批量导入，这是 Neo4j 性能最高的导入方式，十万级节点 + 百万级关系秒级完成，适合首次初始化图谱。核心要求：CSV 严格符合 Neo4j 格式规范，提前给所有节点设置唯一主键，避免生成重复节点。

## 四、核心业务场景的图谱能力落地示例
### 1. AI 答疑场景（你的核心需求）
**工作流**：学生提问题目 → GraphRAG 提取题目核心知识点 → Neo4j 查询该知识点的前置依赖、对应考法、典型例题 → 生成「前置知识点回顾→考点讲解→解题步骤引导→易错点提醒」的引导式答疑内容。

**核心查询 Cypher 示例**：

cypher

```plain
// 输入目标知识点ID，查询AI答疑所需的全链路关联信息
MATCH (target:知识点{知识点ID: $target_id})
// 1-2层前置依赖，避免链路过长导致内容冗余
OPTIONAL MATCH (target)-[:前置依赖*1..2]->(pre:知识点)
// 知识点对应的考点考法
OPTIONAL MATCH (target)-[:对应]->(exam:考法)
// 匹配同难度的典型例题
OPTIONAL MATCH (target)<-[:考察]-(question:题目) 
WHERE question.难度 <= target.难度
RETURN 
  target AS 核心知识点,
  collect(DISTINCT pre) AS 前置必备知识点,
  collect(DISTINCT exam) AS 考点考法,
  collect(DISTINCT question)[0..3] AS 典型例题
```

### 2. 学情诊断场景
**工作流**：学生答题记录入库 → 提取错题对应的知识点 → Neo4j 查询知识点的前置依赖链路 → 结合答题正确率、答题次数，计算每个知识点的掌握度 → 定位薄弱点的根源（是当前知识点没掌握，还是前置知识点没学好）。

### 3. AI 组卷场景
**工作流**：教研老师选择教材、章节、难度、题型、题量 → Neo4j 查询该章节包含的所有知识点 → 匹配对应知识点的题目 → 按「知识点全覆盖、难度梯度合理、题型占比达标」的规则自动生成试卷 → 教研老师人工调整后导出。

### 4. 题目入库场景
**工作流**：新题目基础信息录入 → AI 自动提取题目对应的核心知识点 → 匹配 Neo4j 基准知识点库 → 生成「题目 - 知识点」关联关系 CSV → 教研人工审核 → 增量导入 Neo4j，完成图谱迭代。

## 五、针对「知识点固定，不同教材章节不一致」的专属解决方案
这是教育知识图谱最核心的痛点，给你 2 个可直接落地的方案，按需选择：

### 1. 标准方案（90% 场景适用）：多对多归属关系
+ 知识点节点唯一、永久固定（基准层），绝不因教材版本变化而修改
+ 每个教材版本的章节是独立的业务节点，互不影响
+ 用「章节 - 包含 - 知识点」的关系，定义同一个知识点在不同教材、不同章节的归属
+ **核心优势**：完全解耦，新增教材版本仅需新增章节节点和对应的包含关系 CSV，教研老师可直接在 Excel 里维护，零技术门槛
+ **示例**：「勾股定理」这个知识点，同时属于「人教版八年级下册第 17 章」和「苏教版八年级上册第 3 章」，仅需 2 条「包含」关系即可，知识点本身完全不变。

### 2. 进阶方案（多版本差异大的场景适用）：关系属性标签隔离
+ 在「章节 - 包含 - 知识点」的关系上，增加「教材版本」「年级」「学段」的属性标签
+ 查询时通过标签过滤，仅返回对应教材版本的章节归属，查询性能更高
+ **适用场景**：教材版本超过 5 个、不同版本的知识点归属差异极大的场景

## 六、专家级避坑提醒（教育知识图谱 90% 项目踩过的坑）
1. **绝对不要修改原始基准 TTL 库**。教育场景的知识点权威性是第一位的，一旦修改基准库，后续所有的题目、教材、考法的关联都会失去锚点，后患无穷。
2. **知识点粒度必须 100% 统一**。要么全是最小考点粒度，要么全是章节级粒度，绝对不能一半粗一半细，否则会直接导致 GraphRAG 召回不准、学情诊断混乱、组卷覆盖度失效，整个图谱直接报废。
3. **前置依赖关系的层级不要超过 3 层**。AI 答疑时链路太长会导致引导内容冗余，学生抓不住重点，同时查询性能会急剧下降，1-2 层是最优解。
4. **所有业务关联关系必须有教研审核环节**。AI 自动生成的关系必须经过教研老师确认，否则会出现知识点归属错误、前置依赖逻辑错误，直接导致 AI 答疑、组卷出错，影响教学效果。
5. **必须给核心字段加唯一性约束和索引**。知识点 ID、题目 ID、教材 ID 必须加唯一性约束，避免重复节点；针对高频查询的字段（知识点名称、题型、难度）必须加索引，十万级以上数据量，查询性能会提升 10 倍以上。
6. **绝对不要把题目大文本存在 Neo4j 里**。题干、解析等大文本内容存在 MySQL/ES 中，Neo4j 仅存题目核心属性和关联关系，否则会导致 Neo4j 的存储和查询性能急剧下降。
