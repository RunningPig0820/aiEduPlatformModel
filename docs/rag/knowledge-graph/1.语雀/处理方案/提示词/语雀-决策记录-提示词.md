## 硬性规则（强制全部遵守）

### 术语强制统一
固定术语：TTL / URI（edukb.org 旧 / edukg.org 新）/ Textbook / Chapter / Section / TextbookKP / Concept / Statement / Class / MATCHES_KG / PREREQUISITE / RELATED_TO / BELONGS_TO / 双模型投票 / 置信度 / 断点续传（llmTaskLock） / GraphRAG。禁止自行创造别名。

### 状态判定标准（严格区分，禁止混淆）
- ✅【已落地设计】：代码可观测到实现逻辑；语雀文档描述+代码同时存在。
- ⚠️【建议项(未实现)】：仅语雀方案文档描述，代码无对应实现，属于设计构想、备选方案。
- ❓【待决策 Open Question】：语雀和代码均无明确结论。

### 证据标注规范
1. 语雀来源证据：`证据：语雀-原文件-xxx.md`；引用总揽：`[总揽§X.X]`；引用其他决策：`D#X`。
2. 代码来源证据：优先写 `文件:函数名/类名`；无真实行号禁止编造，写`文件:逻辑片段`。
3. 某类来源不可读，证据字段写`来源不可读，无有效证据`，禁止编造逻辑。

### RAG 块级结构（强制）
1. **每条决策 = 一个 `### D# {标题}` 独立 H3 块**，适配标题切片——一个 chunk = 一条决策。
2. 每条决策 `### D#` 开头必须带：
   ```
   > 状态：✅/⚠️/❓
   > 检索摘要：{1-2句，≤120字符，模拟用户真实提问，埋核心实体（Neo4j/匹配率/投票/URI/维度...）}
   ```
3. 内部用窄表（≤6 列）承载：背景/演进/拍板理由/系统影响；禁止宽横向大表作主体。
4. 文档末尾附录标注"仅供人工查阅，不参与 RAG"（如需）。

### 输出前强制自检
1. 每条决策带 `D#` 递增编号，不重复不跳号；状态 + 检索摘要齐全。
2. 决策事实区分 ✅/⚠️/❓，建议项不标已落地。
3. 代码条目带证据，无编造行号；无问答口吻；术语统一。
4. 与总揽不重复大表，用 `[总揽§X.X]` 引用。
