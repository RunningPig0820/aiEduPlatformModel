## 硬性规则（强制全部遵守）

### 术语强制统一
固定术语：TTL / URI / Textbook / TextbookKP / Concept / MATCHES_KG / PREREQUISITE / 双模型投票 / 置信度 / GraphRAG / 页面化。禁止自创别名。

### 状态判定标准
- ✅【已落地设计】：代码可观测到实现逻辑；语雀文档描述+代码同时存在。
- ⚠️【建议项(未实现)】：仅语雀方案文档描述，代码无对应实现。
- ❓【待决策 Open Question】：语雀和代码均无明确结论。

### 证据标注规范
1. 语雀来源证据：`证据：语雀-原文件-xxx.md`；引用总揽：`[总揽§X.X]`
2. 代码来源证据：优先写 `文件:函数名/类名`；无法获取真实行号时禁止编造虚假行号，写`文件:逻辑片段`。
3. 某类来源不可读，证据字段写`来源不可读，无有效证据`，禁止编造逻辑。
4. **每一个独立阶段小节，必须附带来源证据，禁止无证据条目。**

### RAG 块级结构（强制）
1. **每个阶段 = 一个 `### 阶段# {阶段名}` 独立 H3 块**——一个 chunk = 一个演进阶段。
2. 每条 `### 阶段#` 开头必须带：
   ```
   > 状态：✅/⚠️/❓
   > 检索摘要：{1-2句，≤120字符，埋核心实体（阶段名+关键交付物）}
   ```
3. 内部用窄表承载：目标/做了什么/关键决策/落地证据；禁止宽横向大表。
