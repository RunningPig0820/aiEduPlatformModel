## 硬性规则（强制全部遵守）

### 术语强制统一
固定术语：TTL / URI / Textbook / TextbookKP / Concept / MATCHES_KG / PREREQUISITE / 双模型投票 / 置信度 / GraphRAG / 页面化。禁止自行创造别名。

### 状态判定标准（严格区分，禁止混淆）
- ✅【已落地设计】：代码可观测到实现逻辑；语雀文档描述+代码同时存在。
- ⚠️【建议项(未实现)】：仅语雀方案文档描述，代码无对应实现。
- ❓【待决策 Open Question】：语雀和代码均无明确结论。

> 边界场景的状态判定依据「当前处理」：✅=已处理(有落地逻辑或兜底)；⚠️=未处理/待补强(当前处理填"未处理"或依赖建议项)；❓=待决。

### 证据标注规范
1. 语雀来源证据：`证据：语雀-原文件-xxx.md`；引用总揽：`[总揽§X.X]`
2. 代码来源证据：优先写 `文件:函数名/类名`；无法获取真实行号时禁止编造虚假行号，写`文件:逻辑片段`。
3. 某类来源不可读，证据字段写`来源不可读，无有效证据`，禁止编造逻辑。

### RAG 块级结构（强制）
1. **每个场景 = 一个 `### 场景# {场景名}` 独立 H3 块**——一个 chunk = 一个边界场景。
2. 每条 `### 场景#` 开头必须带：
   ```
   > 状态：✅/⚠️/❓
   > 检索摘要：{1-2句，≤120字符，埋核心实体（场景+当前处理）}
   ```
3. 内部用窄表承载：触发条件/当前处理/兜底/风险；禁止宽横向大表。

## 边界场景候选（从语料/代码初筛，执行时补全）

| 场景 | 候选 |
|---|---|
| 数据源缺失 | TTL/教材/entities 某来源不可读 → 来源不可读标注，不硬连 |
| 匹配失败 | 匹配率 3% 失败 → 置信度 0.5 不硬连 + 留人工审核 |
| 双模型投票不一致 | DS vs GLM 不一致 → 置信度 <0.7 丢弃 |
| 维度不一致 | bge 512 / dashscope 768 → 索引维度固定不可改 |
| 内存过大 | 本地 embedding 懒加载 3.5GB → 预构建索引 10MB + checksum |
| 索引过期 | 数据改了索引 → checksum 失配强制重建，状态机"待重索引" |
| 前置依赖低置信 | 三来源置信度低 → 过滤丢弃 + 人工 |
| 断点续传 | LLM 推断中断 → llmTaskLock 续传 |
| 页面化同步失败 | Neo4j→MySQL 同步失败 → 幂等重跑/一键同步按钮 |
| 知识点点亮 | 匹配到图谱/未匹配 → 只读查询 + 点亮展示 |
