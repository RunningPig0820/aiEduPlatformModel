## 1. 整体架构与分层模型

系统核心 = **两层图谱结构 + Neo4j 存储 + 离线构建/在线消费分离**，核心哲学为"**无限的业务事实**与**有限的权威结构**分存"：

```
┌─────────────────────────────────────────────┐
│ 语义层（EduKG 概念，有限）                     │
│   Concept(1295) / Statement(2932) / Class(39)│
│   关系: RELATED_TO / HAS_TYPE / SUB_CLASS_OF  │
└─────────────────────▲────────────────────────┘
          MATCHES_KG（匹配率 97.1%，教材↔概念）
┌─────────────────────┴────────────────────────┐
│ 教材结构层（人教 K-12 数学，真值）              │
│   Textbook(23) / Chapter(148) / Section(580)  │
│   / TextbookKP(1740)                          │
│   关系: CONTAINS / IN_UNIT                    │
└─────────────────────┬────────────────────────┘
         Neo4j 最终存储（bolt://81.71.130.57:7687）
         Python 离线构建 → CSV → 批量导入（MERGE 幂等）
         Java 页面化同步 → MySQL ai_edu_kg → 前端 SPA 读
         图谱关系（MATCHES_KG/PART_OF/RELATED_TO）直查 Neo4j
```

- **教材结构层**：从人教版教材（爬虫教师之家 + 数据生成）解析出的真实教学结构（学科→学段→年级→教材→章节→小节→知识点 6 层），节点带 URI，是"事实"。
- **语义层**：EduKG 开源概念（TTL v0.1 导入），Concept/Statement/Class，是"概念"。两层通过 `MATCHES_KG` 匹配连接（TextbookKP → Concept，置信度 ≥0.5，方向固定不可逆）。
- **计算与存储分离**：关系处理在 Python 内存/CSV 完成，"离线构建 → 批量导入"，Neo4j 只是最后仓库；`neo4j-admin import` 对 CSV 批量导入性能是 TTL 导入 10 倍以上（方案选型选 **方案 C：CSV→Neo4j**）。
- **权威图谱零写入**：EduKG 静态权威库冻结只读；业务派生数据（掌握度/点亮/题型）存 MySQL，无限业务事实永远不写权威图（后续 kp-matching-lightup 模块复用此原则）。
- **三端分工**：Python（edukg 管道 + ai-edu-ai-service 桥）离线构建 + 在线 API；Java（Spring Boot + MyBatis-Plus，双数据源）页面化接口 + 掌握度派生；前端（React SPA）三栏布局（树+图谱+详情）只读消费。

## 2. 核心概念与术语

| 术语 | 定义 |
|---|---|
| TTL | 语义网 RDF 数据格式，EduKG 开源数据源（`ttl/*.ttl` v0.1 知识点 + `relations/*.ttl` 关系 + `main.ttl` v3.0 教材出处 + `entities/*.json` 实体列表） |
| URI | 节点唯一标识，正式数据一律 `http://edukg.org/knowledge/{version}/...`（edukb.org 仅出现在下载脚本/旧 TTL 兼容分析） |
| Textbook / Chapter / Section | 教材结构层节点（人教 K-12 数学，23/148/580） |
| TextbookKP | 教材知识点（1740，教学粒度），经 MATCHES_KG 匹配到 Concept |
| Concept / Statement / Class | 语义层节点（EduKG，1295/2932/39）；content 属性在 **Statement**，不在 Concept |
| MATCHES_KG | 教材知识点↔概念匹配关系（1690，97.1%），方向 TextbookKP→Concept |
| PREREQUISITE | 前置依赖（学习依赖），业务查询用；PREREQUISITE_ON 为 EduKG 标准互操作 |
| PREREQUISITE_CANDIDATE | 低置信前置候选（<0.6/<0.8），待确认 |
| TEACHES_BEFORE | 教学顺序（教材章节顺序），≠ 学习依赖（勾股定理先于圆，但学圆不需先学勾股定理） |
| 双模型投票 | DeepSeek(0.6) + GLM(0.4) 加权投票，threshold 0.5；两模型一致取平均置信度 |
| 置信度 | 匹配/关系可信度；匹配 <0.5 跳过、前置 <0.6 降级候选、<0.7 丢弃、≥0.8 才 PREREQUISITE |
| 断点续传 llmTaskLock | TaskState + CachedLLM(SHA256 缓存) + ProcessLock 三件套，LLM 长任务中断可续 |
| GraphRAG | 向量命中 Concept → 沿关系扩展邻居 → 可解释推理路径 |
| 年级推断 | TEXTBOOK_TO_GRADE 映射表 + STAGE_FALLBACK + mark 字段兼容解析（6.2.1/6-2-1/第六章第二节） |

## 5. 数据清洗与增强

- **DataCleaner**（`data_cleaner.py`）：检测"通用"标签跨小节复用（88 组，非错误）、Section 标签序号前缀提取到 `order_in_book`、移除末尾冒号/全角→半角、数据质量检查（全角字符/多余空格）。
- **ChapterEnhancer**（`chapter_enhancer.py`）：基于章节名关键词匹配 4 大专题（数与代数/图形与几何/统计与概率/综合与实践）+ 默认"其他"，匹配 17 个数学专题。
- **KPAttributeInferer**（`kp_attribute_inferer.py`）：**纯规则、无 LLM**——difficulty 1~5（年级基础难度 + 关键词 ±1 调整）、importance（核心>重要>了解）、cognitive_level（分析>应用>理解>识记，布卢姆）、topic 直接继承章节 topic。
- **知识点过滤**（`filters.py`）：`NON_KNOWLEDGE_POINT_MARKERS`（数学活动/小结/整理和复习/本章综合与测试/复习题等）+ 前缀 + 正则（`^例\d`）+ 章节编号。
- **执行顺序坑**：早期属性增强在 LLM 推断**之前**执行导致 enhanced 覆盖率仅 22%（299/1350），修复为 LLM 推断完成后重跑属性增强补 1052 个。

## 6. LLM 推断

- **目标**：小学 1-6 年级、高中必修教材原始 JSON 的 `knowledge_points` 为空，需 LLM 推断；初中 7-9 年级完整（~252）无需推断。
- **TextbookKPInferer**：根据章节信息（学段/年级/章节名/小节名）推断知识点；缺失章节 295 个 → 推断 **1,052 个**知识点，平均置信度 **0.93**；合并后总计 1350 → 最终清洗后 1740。
- **断点续传 llmTaskLock**（`core/llmTaskLock/`）：`TaskState`（检查点/进度）、`CachedLLM`（SHA256 缓存键，同 Prompt 不重复调用）、`ProcessLock`（portalocker 文件锁）；推断 2-3 小时、匹配 1-2 小时，中断可续（`--resume`）；先修关系推断 ~8,980 次调用断点续传价值最高。
- **双模型投票**（`dual_model_voter.py`）：主模型 `glm-4-flash`（免费）、副模型 `deepseek-chat`（DeepSeek-V3）；两模型一致 → 取平均置信度采纳；不一致 → 加权投票 `WEIGHT_DS=0.6 / WEIGHT_GLM=0.4 / THRESHOLD=0.5`，仅 DeepSeek=True 才可能过阈值（DS 否决），不一致时置信度 ×0.7。
- **成本控制**：GLM-4-flash 免费主力；数学 4490 知识点、批大小 50 → 约 90 次调用 ×2 模型 ×1.1 重试 ≈ 200 次，**数学全流程约 1-2 元**；全学科 56,391 知识点 ~1,120 次、DeepSeek 约 10-20 元；日预算 5000 分/总预算 20000 分/70% 告警。
- **工程化状态管理**：MySQL 状态表（processing_state/llm_cache/cost_tracking/chapter_state+subbatch_state 两层/failed_batches/progress_view）、优雅退出（SIGINT/SIGTERM）、重试策略（超时 2 次/格式错误 1 次/网络 3 次）。

## 7. 匹配与置信度

- **匹配流水线（最终实现）**：标准化精确匹配（+完整词同义词）→ 向量粗筛 top-20 → LLM 双模型投票；三步全链路。
- **匹配统计（最终）**：总知识点 1,740；精确匹配 1,511（86.8%）；LLM 匹配 179（10.3%）；未匹配 50（2.9%）；**匹配率 1,690/1,740 = 97.1%**；平均置信度 **0.975**。
- **匹配阈值**：相似度 <0.5 跳过（跳过候选）；LLM 候选上限前 3 个 + 早停；投票 DS=0.6/GLM=0.4、threshold=0.5（设计期 D4.1 口径 ≥0.9 MATCHES_KG / 0.7-0.9 CANDIDATE / <0.7 不匹配，为候选分档参考）。
- **低匹配根因**：初始匹配率仅 17%（LLM 仅 2%）；小学 69.6% 教材知识点（如「1-5 的认识」）无法匹配以高中抽象概念为主的 EduKG → LLM 推断标准化名再匹配（「1-5 的认识」→「自然数的基本概念」→ 匹配 EduKG「自然数」）。
- **性能优化**：LLM 调用从 500 万 → 2.7 万（下降 99%）；三重优化后整体提速约 50 倍；8,255 个缓存节省 16,510 次 API 调用。
- **匹配评审**（`kp-match-review-system`）：308 个未匹配（297 条"投票不通过" + 11 条"无候选通过"）进 MySQL 审核表 `textbook_kp_match_review`（前 5 候选 JSON + review_status pending/approved/rejected/new_kp），LLM 推荐接口 `/api/kp-match/recommend`，审核后导入 Neo4j。

## 8. 前置依赖与学习路径

- **核心原则**：教学顺序（TEACHES_BEFORE）≠ 学习依赖（PREREQUISITE）——教材顺序只生成 TEACHES_BEFORE，不直接转 PREREQUISITE。
- **多证据融合**（`PrerequisiteInferer.fuse_results`）：

| 证据 | 设计权重 | 代码落地 | 产物 |
|---|---|---|---|
| 教材章节顺序 | 0.7 | conf 1.0, source=textbook_order（仅章节内部） | TEACHES_BEFORE |
| 定义/定理依赖 | 0.85 | conf 0.9（已有 TEACHES_BEFORE 则升级 PREREQUISITE） | PREREQUISITE |
| LLM 多模型投票 | 0.8 | 已有前置则升级，conf `min(existing+0.1, 1.0)` | PREREQUISITE/CANDIDATE |
| 教师标注 | 1.0 | demo 不做 | 人工 |

> **口径标注**：设计文档证据权重表为 0.7/0.85/0.8/1.0；**代码最终常量无 0.85**，落地为 TEACHES_BEFORE conf 1.0 / DEFINITION_DEP conf 0.9 / LLM +0.1 封顶 1.0；阈值 HIGH=0.8 / LOW=0.6。

- **投票分类**（`vote_prerequisite`）：两模型一致且 ≥0.8 → PREREQUISITE；一致 ≥0.6 → PREREQUISITE_CANDIDATE；不一致 → 不采纳。
- **年级倒置惩罚**：前置年级高于目标年级按跨度乘 0.95（相邻）/0.9（跨 1 学段）/0.5（跨 2 学段）/0.3（跨度太大）；惩罚后 <0.6 降级 PREREQUISITE_CANDIDATE。
- **DAG 验证**（`validate_dag.py`）：DFS 环检测（`detect_cycles`），退出码 0=无环/1=有环，输出覆盖率/平均链长/置信度分布。
- **学习路径**：Cypher `MATCH path=(start)-[:PREREQUISITE*..10]->(target) RETURN path ORDER BY LENGTH(path)`；离线预计算 prerequisite_level 属性（BFS 最长前置路径）优化。
- **知识缺陷诊断**：给定已掌握集合，多跳查未掌握的前置点（业务优先级 P0=前置依赖查询、P1=知识点识别+缺陷诊断、P2=学习路径推荐）。
- **质量目标（demo）**：前置覆盖率 ≥30%、DAG 合规 100%、平均前置链 2-4 跳、年级倒置率 ≤5%、高置信度(≥0.8)占比 ≥60%、抽样准确率 ≥70%。

## 9. 向量索引与 embedding

- **匹配侧（bge 本地）**：`BAAI/bge-small-zh-v1.5`，`VECTOR_DIM=512`，numpy 暴力搜索（≤5000 条 <10ms）+ sentence-transformers；粗筛 top-20。资源：模型 2.5GB + 向量 5000×512×4B≈10MB，总计约 3.5GB。
- **索引文件**：`kg_vectors.npy`（形状 1295×512）/`kg_texts.json`/`kg_concepts.json`/`index_meta.json`；构建约 60 秒（预构建一次、多次复用）。
- **懒加载 vs 预构建**：`LocalVectorRetriever`（懒加载）每次运行加载模型构建向量，内存约 3.5GB、单次检索 <10ms；`PrebuiltIndexRetriever`（预构建，`--use-prebuilt-index`）仅加载 numpy 约 10MB、单次检索 <5ms。
- **checksum**：MD5（按 uri+label 排序拼接）存 `index_meta.json['neo4j_checksum']`，用于索引有效性校验；失配强制回退懒加载重建。
- **服务侧 RAG embedding（dashscope）**：`text-embedding-v3`、768 维（显式，模型默认 1024），base `https://dashscope.aliyuncs.com/compatible-mode/v1`；答疑/掌握度服务侧向量检索用。
- **维度口径**：bge 512 维（匹配侧本地）、dashscope 768 维（服务侧 RAG）；索引维度固定不可改。

## 10. 服务接入（GraphRAG）

- **GraphRAG 工作流**：学生提问题目 → 提取核心知识点 → Neo4j 查该知识点的前置依赖/对应考法/典型例题 → 生成「前置知识点回顾→考点讲解→解题步骤引导→易错点提醒」引导式答疑；Cypher 用 `[:前置依赖*1..2]` 控制链路深度、`collect(DISTINCT pre)` 等。
- **与掌握度联动**：学生答题记录 → 错题对应知识点 → 查前置依赖链路 → 结合正确率/答题次数算每个知识点掌握度 → 定位薄弱根源（当前点没掌握 vs 前置没学好）。
- **与答疑闭环**：知识图谱作为 AI 对话助手"活文档"，「学生提问→知识图谱检索→引导式答疑→精准回复」，答疑记录回流支撑家长端薄弱点报表。
- **与题型分析**：题目"考察"知识点关系支撑 AI 组卷（按知识点全覆盖/难度梯度/题型占比）。
- **Python 服务 API**（`api/kg.py`，prefix `/api/kg`）：`/entities` 搜索、`/entity/{uri}` 详情、`/link` 实体识别、`/subject/{subject}/tree` 知识树（depth 默认3 最大5）、`/subject/{subject}/classes`、`/student/{id}/progress`、`/recommend`、`/learning-path`。
- **Neo4j 通用 API**（`api/neo4j.py`，prefix `/api/neo4j`，`x-internal-token` 鉴权）：`/health`、`/stats`、`/nodes/{label}`（+batch/search/count）、`/relationships`、`/query`（裸 Cypher，read_only 默认 true）。
- **实体链接**（`core/kg/entity_linker.py`）：jieba 分词 + 内存实体字典（从 `data/edukg/entities/*_entities.json` 加载，~40,000 实体约 10MB）做实体链接。

## 11. 页面化与同步

- **方案 B（已拍板）**：Neo4j 知识点数据同步到 MySQL，前端 SPA 读 MySQL；图谱关系（MATCHES_KG/PART_OF/RELATED_TO 等）**不同步**，后续 Neo4j 直查（Redis 缓存 TTL 300s + 降级 `neo4jAvailable:false`）。
- **MySQL 表（8 张）**：4 张节点主表（`t_kg_textbook/chapter/section/knowledge_point`，**URI 主键** + status + merged_to_uri）+ 3 张层级关联表（含 order_index）+ 1 张同步记录表（edition/subject/stage/grade 维度 + reconciliation_status）。
- **同步策略**：手动按需触发（非实时/CDC）+ UPSERT（按 URI）+ 状态机 active/deleted/merged + 大事务（按年级拆分子任务 + 细粒度锁 `...:{edition}:{subject}:{stage}:{grade}`，失败仅影响该年级）+ 对账校验；URI 校验（以 `http://edukg.org/knowledge/` 开头）；6,757 节点预计 <10s。
- **双数据源**：`dynamic-datasource-spring-boot3-starter` 4.x + `@DS("kg")` 注解 + Mapper 包路径隔离；`/api/kg/**` → `ai_edu_kg`，其余业务 → `ai_edu_user` 物理隔离；HikariCP 每源 5-20 连接。
- **API 面**：教材列表/章节树/小节知识点/知识点详情（2 层父级）/年级知识体系/年级统计/Neo4j 健康检查/批量概念关联（Redis TTL 300s + 降级）。
- **前端**：React SPA 三栏布局（树+图谱+详情），React Flow 关系图谱（力导向；节点 >50 提供"简化视图"Top 10），树形导航逐级懒加载（6,757 节点不宜一次渲染），同步管理页面 + 系统统计面板。

## 12. 已知风险与漏洞

| 风险 | 现状/兜底 |
|---|---|
| 小学 3-6 年级知识点空 / 高中必修 0 | LLM 推断补 1,052 个（平均置信 0.93） |
| 匹配失败 3%（50 个） | 小学 69.6% 教材知识点与 EduKG 高中抽象概念不对齐；置信度 0.5 不硬连 + 评审系统人工审核 |
| 属性增强覆盖率 22% | 执行顺序 bug（增强在推断前），修复为推断后重跑 |
| topic 继承偏差 | 知识点直接继承章节 topic 导致语义矛盾（「加法」在「位置」章被错继承），基于匹配 Concept 的 Class 类型修正 144 个 |
| 维度不一致 v0.1 vs v3.0 | TTL 与 main.ttl 数据不匹配，靠标签匹配容忍缺失 |
| LLM 自证循环 | LLM 修正 LLM 可能自我强化；强制"每次判断被客观信号校准"（做题结果/多模型交叉/学生意图），冷启动弱化（WEAK 态等第二独立信号） |
| 开发者打标脱离解题 | 人工仅边界仲裁，找懂学科的人，不做日常打标 |
| Neo4j 内存/存储 | 社区版 4.4.x 单机 4G/8G 内存、100G+ 存储（实际 docker 5-enterprise 2G heap/1G pagecache） |
| 联调问题 | 教材导航 API 空数组、图谱关系 API 未验证、同步并发冲突/URI 脏数据（对账校验缓解）、前端节点上限 50 |
| 权威图零写入约束 | 派生数据（掌握度/点亮）只存 MySQL，物理上不污染权威图谱 |

**设计期避坑原则（方案 C 专家）**：绝不修改基准 TTL；知识点粒度必须统一；前置依赖层级不要超过 3 层（1-2 层最优）；业务关联必须有教研审核；核心字段加唯一约束+索引；题目大文本不要存 Neo4j。
