## 一、数据与匹配边界

### 场景1 数据源缺失/不可读
> 状态：✅
> 检索摘要：图谱数据源读不到怎么办？某来源不可读如实标注来源不可读，不硬连；多来源（TTL/main.ttl/爬虫/课标）互补兜底。

| 属性 | 内容 |
|---|---|
| 触发条件 | TTL/教材 JSON/entities 某来源缺失或解析失败 |
| 当前处理 | 来源不可读标注，跳过该来源信息，不编造 |
| 兜底 | 四类数据源互补；爬虫断点续爬（--no-resume 重爬） |
| 风险 | 覆盖不全（小学初中 main.ttl 缺失靠爬虫补） |
| 证据 | 证据：语雀-产品中心-问题记录.md / design-textbook-crawler |

### 场景2 匹配失败（3%，50 个）
> 状态：✅
> 检索摘要：教材知识点匹配不上怎么办？匹配率 97.1% 余下 3%（50 个）不硬连，进 MySQL 审核表人工确认，新知识点用 v3.2 URI。

| 属性 | 内容 |
|---|---|
| 触发条件 | 小学 69.6% 教材知识点与 EduKG 高中抽象概念不对齐（如「1-5 的认识」） |
| 当前处理 | 置信度 <0.5 跳过；LLM 推断标准化名再匹配；308 未匹配进评审系统人工确认 |
| 兜底 | 匹配率 97.1% 背书；审核后导入 Neo4j（MATCHES_KG） |
| 风险 | 批量误确认（reviewer_id/time 回溯） |
| 证据 | 证据：语雀-产品中心-问题记录.md / design-kp-match-review-system |

### 场景3 双模型投票不一致
> 状态：✅
> 检索摘要：DeepSeek 和 GLM 判断不一致怎么办？加权投票 DS=0.6/GLM=0.4，仅 DeepSeek=True 才可能过阈值（DS 否决），不一致时置信 ×0.7。

| 属性 | 内容 |
|---|---|
| 触发条件 | 匹配/前置推断时两模型结论不一致 |
| 当前处理 | 两模型一致 → 平均置信采纳；不一致 → 加权投票，DS 否决权，置信 ×0.7 |
| 兜底 | 前置投票不一致 → 不采纳；匹配不一致 → 走候选/人工 |
| 风险 | 系统性偏见双模型同向错 |
| 证据 | 证据：edukg/core/llm_inference/dual_model_voter.py:354-396 |

### 场景4 维度不一致 v0.1 vs v3.0
> 状态：✅
> 检索摘要：EduKG 版本数据不一致怎么办？TTL v0.1 与 main.ttl v3.0 数据不匹配，靠标签匹配容忍缺失，URI 版本前缀区分。

| 属性 | 内容 |

| 兜底 | 权威图零写入，不污染 |
| 风险 | 属性覆盖率低 |
| 证据 | 证据：语雀-方案设计1/2/3.md |

## 二、性能与索引边界

### 场景5 本地 embedding 内存过大
> 状态：✅
> 检索摘要：本地 embedding 内存不够怎么办？bge 懒加载 3.5GB → 预构建索引仅 10MB（--use-prebuilt-index），numpy 单次检索 <5ms。

| 属性 | 内容 |
|---|---|
| 触发条件 | 每次匹配重新加载模型+建索引约 60 秒、内存 3.5GB |
| 当前处理 | 预构建一次（kg_vectors.npy 等 4 文件）、多次复用；内存约 10MB |
| 兜底 | checksum 失配回退懒加载 |
| 风险 | 索引过期 |
| 证据 | 证据：语雀-产品中心-问题记录.md / edukg/core/textbook/vector_index_manager.py |

### 场景6 索引过期（数据改了）
> 状态：✅
> 检索摘要：图谱数据改了向量索引怎么办？checksum MD5 存 index_meta，失配强制重建索引，保证向量与图谱一致。

| 属性 | 内容 |
|---|---|
| 触发条件 | Neo4j 数据变更后向量索引未同步 |
| 当前处理 | `neo4j_checksum`（MD5 按 uri+label 排序拼接）校验 `is_index_valid`；失配回退懒加载重建 |
| 兜底 | 预构建索引 + 懒加载双轨 |
| 风险 | 索引重建需 60s |
| 证据 | 证据：edukg/core/textbook/vector_index_manager.py:204-246 |

### 场景7 前置依赖低置信/年级倒置
> 状态：✅
> 检索摘要：低置信前置关系怎么办？<0.7 丢弃、<0.6 降级 PREREQUISITE_CANDIDATE；年级倒置按跨度惩罚 ×0.95/0.9/0.5/0.3。

| 属性 | 内容 |
|---|---|
| 触发条件 | LLM 前置推断置信度低或前置年级高于目标年级 |
| 当前处理 | 投票 ≥0.8 → PREREQUISITE、≥0.6 → CANDIDATE、不一致不采纳；年级倒置惩罚 |
| 兜底 | 候选保留可补审；质量目标年级倒置率 ≤5% |
| 风险 | 候选膨胀 |
| 证据 | 证据：语雀-方案设计3.md / design-data-research 9.2/9.3 |

### 场景8 LLM 推断中断
> 状态：✅
> 检索摘要：LLM 长任务中断怎么办？llmTaskLock 断点续传（--resume），推断 2-3 小时/匹配 1-2 小时可续，缓存键 SHA256 不重复调用。

| 属性 | 内容 |
|---|---|
| 触发条件 | 进程中断/网络失败/超时 |
| 当前处理 | TaskState 检查点 + CachedLLM 缓存 + ProcessLock；重试策略（超时 2/格式 1/网络 3 次） |
| 兜底 | 优雅退出（SIGINT/SIGTERM）；MySQL 状态表两层（chapter+subbatch） |
| 风险 | 缓存文件损坏（备份+原子写） |
| 证据 | 证据：edukg/core/llmTaskLock/README.md |

## 三、页面化与消费边界

### 场景9 页面化同步冲突/脏数据
> 状态：✅
> 检索摘要：Neo4j→MySQL 同步失败或冲突怎么办？按年级拆分子任务 + 细粒度锁，失败仅影响该年级；URI 校验拦截非法 + 对账校验 reconciliation。

| 属性 | 内容 |
|---|---|
| 触发条件 | 同步任务并发、URI 脏数据、同步后不一致 |
| 当前处理 | 细粒度锁 `...:{edition}:{subject}:{stage}:{grade}`；URI 校验（edukg.org/knowledge/ 开头）；对账校验 reconciliation_status；MERGE/UPSERT 幂等 |
| 兜底 | 失败仅影响该年级；手动按需重触发 |
| 风险 | 状态膨胀（定期清理）；关联表重建开销（DELETE+INSERT） |
| 证据 | 证据：语雀-联调-知识图谱同步接口.md / 语雀-页面化-联调问题.md |

### 场景12 图谱节点数过大（前端渲染）
> 状态：✅
> 检索摘要：前端图谱节点太多怎么办？6,757 节点树形懒加载、React Flow 图谱 >50 节点简化视图（Top 10）、后端限制 ≤50 节点。

| 属性 | 内容 |

### 场景13 Neo4j 不可用（图谱关系降级）
> 状态：✅
> 检索摘要：Neo4j 挂了对前端影响什么？图谱关系直查降级——Redis TTL 300s 缓存 + neo4jAvailable:false 隐藏模块，不抛异常。

| 属性 | 内容 |
|---|---|
| 触发条件 | Neo4j 服务不可用/网络故障 |
| 当前处理 | Redis key `kg:neo4j:{uri}:{query_type}` TTL 300s；降级返回空关联 + `neo4jAvailable:false` 前端隐藏图谱关系模块 |
| 兜底 | `/api/kg/neo4j/health` 健康检查；批量概念关联避免 N+1 |
| 风险 | 缓存与实时数据不一致（300s 窗口） |
| 证据 | 证据：design-backend-ui Decision 5 |
