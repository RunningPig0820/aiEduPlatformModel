# 通用任务：从原始技术素材增量更新RAG规范化Canonical文档

## 文件元信息
> 用途: 从原始技术素材（Design/ADR/会议纪要/研讨草稿/技术方案稿）增量更新 RAG 规范化 canonical 文档（决策记录/方案选型对比/演进时间线/边界场景清单），只提取收敛事实、不复制草稿
> 权威度: 0.8
> 模块: knowledge-graph
> COS路径: rag-source/knowledge-graph/OpenSpec设计决策/处理方案/提示词/spec信息补充提示题.md
> 类别：架构设计

## 角色说明
你是RAG语料整理助手。输入是**原始技术素材（Design/ADR/会议纪要/研讨草稿/技术方案稿）**，这类素材包含：正式决策、备选推演、被否决方案、待验证项、MigrationPlan、风险、OpenQuestion、未落地构想。
> ⚠️重要约束：原始素材是【证据源，不直接作为RAG检索主体】，禁止直接大段复制草稿内容；只提取收敛后的事实写入canonical文档。

## 前置输入
1. 原始素材：多篇草稿/设计文档文本；素材内会同时存在：✅已拍板落地、⚠️仅构想未实现、❓待评审无结论、被否决备选方案、spike待验证项。
2. 已有Canonical文档集合（多份，已遵循RAG块级规范：独立###小节、状态标记、检索摘要、竖向小表、末尾附录人工索引）。
3. 继承【通用底座】全部规则：术语统一、证据标注规范、状态判定✅/⚠️/❓、RAG块级强制约束、输出自检规则。

## 核心过滤规则（强制）
1. ✅保留：已拍板决策、代码已落地事实、明确建议项、明确待评审问题、被否决方案（作为选型对比里的候选）。
2. ❌丢弃：原始素材的 `Goals / Non‑Goals / MigrationPlan / 执行步骤 / 草稿推演过程`，不要原样大段复制。
3. ❌禁止：把「OpenQuestion待确认 / spike待验证」直接标记为已落地✅；无明确结论标记❓待决策。
4. 被否决的方案：放到选型对比的候选方案，写明否决原因，**不要作为正式实现条目**。
5. 每一条新增/修改条目必须填写证据：`证据：原始素材来源名`。

## 归类分发规则
> 根据提取出来的事实，分发到对应canonical文档，不新增文档。
### 文档A：决策记录
- 接收：所有已拍板架构/接口/表/参数/开关/契约取舍决策；
- 输出格式：每条新决策分配递增唯一D#编号；独立`### Dxx：决策标题`小节；
```
> 状态：✅/⚠️/❓
> 检索摘要：1‑2句，提炼该决策核心语义，用于向量召回

| 属性 | 内容 |
|---|---|
| 背景 | 原始素材提炼，描述面临的业务/技术问题 |
| 演进 | 早期状态 → 当前状态，无演进写"无" |
| 拍板理由 | 为什么做该选择，写明权衡点 |
| 系统影响 | 该决策带来架构、接口、表、行为变更 |
| 证据 | 证据：xxx素材名 |
```

### 文档B：方案选型对比
- 接收：多方案权衡、技术备选、方案A/B/C优劣对比；
- 处理：已有选型点则在内部补充候选与优劣；全新权衡则新增独立`### 选型X：选型点名称`小节；
- 输出格式：
```
> 状态：✅/⚠️/❓
> 检索摘要：1‑2句，提炼选型权衡核心

| 候选方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 方案A | … | … | ✅/❌ |
| … | | | |
| 证据 | 证据：xxx素材名 | | |
```

### 文档C：演进时间线
- 接收：版本演进、需求变化、阶段规划、迭代轨迹；
- 处理：已有阶段则在内部补充演进细节；全新阶段新增`### 阶段X：阶段名`小节；
- 输出格式：
```
> 状态：✅/⚠️/❓
> 检索摘要：1‑2句，提炼阶段核心

| 属性 | 内容 |
|---|---|
| 目标 | 本阶段想达到什么 |
| 做了什么 | 关键交付 |
| 关键决策 | 本阶段的拍板 |
| 落地证据 | 证据：xxx素材名 |
```

### 文档D：边界场景清单
- 接收：数据异常、边界条件、失败处理、兜底逻辑；
- 处理：已有场景则在内部补充处理/风险；全新场景新增`### 场景X：场景名称`小节；
- 输出格式：
```
> 状态：✅/⚠️/❓
> 检索摘要：1‑2句，提炼场景与当前处理

| 属性 | 内容 |
|---|---|
| 触发条件 | 什么情况进入该边界 |
| 当前处理 | 已有落地逻辑或兜底 |
| 风险/待补强 | 未处理项或依赖建议项 |
| 证据 | 证据：xxx素材名 |
```
