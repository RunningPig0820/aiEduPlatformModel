## 业务描述与业务场景

**业务描述**：教材目录爬下来是原始网页结构，直接建图谱会有"通用"标签跨小节复用、小节名带序号前缀、全角字符、非知识点条目混入等问题——这段代码就是把 23 册教材 JSON 清洗成规范、无冗余、可入库的结构化数据，是图谱质量的第一道防线。

**业务场景**：
- 教研上传教材目录后，系统自动检测"通用"标签在多个章节复用（避免一个「通用」小节被重复挂到 N 个章节下）
- 小节名「1.1 正数和负数」要提取序号到 order_in_book 字段，保证排序正确
- 「数学活动」「复习题」「例1」这类非知识点条目不能建图谱节点（否则图谱被污染）

## 职责

**职责**：教材原始 JSON → 规范化中间 JSON（chapters/sections/textbook_kps），去除冗余标签、规范小节名、补全属性、过滤非知识点。
**不做什么**：不做 LLM 推断（那是 infer_textbook_kp）、不做图谱匹配（那是 match_textbook_kp）、不改 EduKG 权威数据。
**分工要点**：DataCleaner（清洗）+ ChapterEnhancer（专题）+ KPAttributeInferer（属性）+ filters（过滤）都在 `edukg/core/textbook/`，CLI 入口 `clean_textbook_data.py`（仅清洗部分）。

## 高层业务调用链（教材数据清洗规范化）

```
generate_textbook_data.py（生成节点/关系 JSON）
   │
   ▼
clean_textbook_data.py --analyze        ← 只分析，输出 duplicate_detection_report.json
   │  DataCleaner.analyze()
   │    · 通用标签跨小节复用检测（duplicate_same/different_textbook）
   │    · Section 需清洗检测（序号前缀/末尾冒号/全角）
   ▼  ── 人工确认报告 ──
clean_textbook_data.py --clean          ← 执行清洗，写 clean_log.json
   │  DataCleaner.clean_sections()
   │    · extract_section_order（序号→order_in_book）
   │    · 移除末尾冒号 / 全角→半角
   ▼
中间 JSON（清洗后）
   │
   ├── ChapterEnhancer.enhance()        专题增强（章节名→4 大专题/17 个数学专题）
   ├── KPAttributeInferer.infer()       属性补全（difficulty/importance/cognitive_level/topic，纯规则）
   └── filters.NON_KNOWLEDGE_POINT_MARKERS  过滤（数学活动/小结/复习题/例\d 等）
   ▼
规范化输出 → Phase 2 匹配（build_vector_index → match_textbook_kp）
```

## 代码事实

### 端点清单（CLI）
| 命令 | 作用 | 证据 |
|---|---|---|
| `python clean_textbook_data.py --analyze` | 分析清洗需求，输出报告（默认模式） | clean_textbook_data.py:69 |
| `python clean_textbook_data.py --clean` | 执行清洗（需先确认报告） | clean_textbook_data.py:121 |
| `python clean_textbook_data.py --force` | 强制执行，不检查报告 | clean_textbook_data.py:208 |
| `python clean_textbook_data.py --stats` | 显示清洗统计 | clean_textbook_data.py:174 |

### 关键机制（DataCleaner，`data_cleaner.py`）
1. **通用标签复用检测**：`detect_generic_duplicates` 检测"通用"标签跨小节复用，区分 `duplicate_same_textbook`（同教材）与 `duplicate_different_textbook`（跨教材）；结果 88 组（PROJECT_SUMMARY 记为非错误，是教材结构特征）。
2. **Section 序号清洗**：`extract_section_order` 提取序号前缀（`3.1-`/`18.1.1-`/`8-`）到 `order_in_book` 字段；`clean_sections` 移除末尾冒号、全角→半角。
3. **数据质量检查**：`check_data_quality` 检查全角字符/多余空格/末尾空格。
4. **先分析后清洗**：`run_clean` 检查 `duplicate_detection_report.json` 是否存在，不存在则报错"请先运行 --analyze"——强制人工确认防误删。

### 关键机制（ChapterEnhancer + KPAttributeInferer + filters）
1. **ChapterEnhancer**（`chapter_enhancer.py`）：基于章节名关键词规则匹配 4 大专题（数与代数/图形与几何/统计与概率/综合与实践）+ 默认"其他"，`MATH_TOPICS` 关键词子集；PROJECT_SUMMARY 称匹配 17 个数学专题。
2. **KPAttributeInferer**（`kp_attribute_inferer.py`）：**纯规则、无 LLM**——
   - `difficulty` 1~5：`GRADE_BASE_DIFFICULTY`（一~二年级=1 … 必修三=5）+ `DIFFICULTY_ADJUST_KEYWORDS` 关键词 ±1 调整
   - `importance`：核心 > 重要 > 了解 关键词优先级
   - `cognitive_level`：分析 > 应用 > 理解 > 识记（布卢姆分类关键词）
   - `topic`：直接继承章节 topic
3. **filters**（`filters.py`）：`NON_KNOWLEDGE_POINT_MARKERS`（数学活动/小结/整理和复习/本章综合与测试/复习题等）+ 前缀 + 正则（`^例\d`）+ 章节编号，过滤非知识点条目。

### 枚举/常量/配置
| 类型 | 名称 | 取值 | 出处 |
|---|---|---|---|
| 过滤词 | NON_KNOWLEDGE_POINT_MARKERS | 数学活动/小结/整理和复习/复习题… | filters.py:11-75 |
| 正则 | 例\d 前缀 | `^例\d` | filters.py |
| 专题 | MATH_TOPICS | 数与代数/图形与几何/统计与概率/综合与实践 | chapter_enhancer.py:39-152 |
| 年级难度 | GRADE_BASE_DIFFICULTY | 一~二年级=1 … 必修三=5 | kp_attribute_inferer.py:26-119 |
| 难度调整词 | DIFFICULTY_ADJUST_KEYWORDS | 关键词 ±1 | kp_attribute_inferer.py |

### 边界与降级
- 报告不存在 → `--clean` 拒绝执行（报错提示先 analyze）；`--force` 可绕过。
- 章节文件缺失 → `FileNotFoundError`，提示先运行 generate_textbook_data.py。
- 清洗后写 clean_log.json（original → cleaned 变更记录），可回溯。

## 隐性坑与注意事项
- **属性增强执行顺序**：早期 KPAttributeInferer 在 LLM 推断**之前**跑，导致 enhanced 覆盖率仅 22%（299/1350）——必须"推断后增强"（产品中心问题记录）。
- **topic 继承偏差**：`topic` 直接继承章节，章节语义与知识点不符时错继承（「加法」在「位置」章 → 图形与几何），靠匹配 Concept 的 Class 类型修正 144 个。
- **全角/半角**：教材文本混全角字符，清洗统一转半角，否则匹配/检索时"（" vs "(" 不一致漏配。
- **先分析后清洗是安全设计**：防 LLM/脚本误删；通用标签 88 组是教材结构特征不是脏数据。

## 设计要点
- **纯规则不用 LLM**：属性推断（difficulty/importance/cognitive_level）用规则——低成本、可复现、不引入 LLM 噪声；LLM 只用于"推断缺失知识点"（语义任务）。
- **清洗与入库分离**：清洗输出中间 JSON，人工确认后才进匹配/导入，防脏数据污染 Neo4j。
- **可回溯**：clean_log.json + duplicate_detection_report.json 记录每次变更，可回滚。
