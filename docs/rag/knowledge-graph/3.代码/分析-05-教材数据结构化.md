# 分析-05 教材数据结构化（代码真相）

> summary: 解答「人教版教材原始 JSON 怎么变成可入库的图谱节点/关系、知识点名怎么标准化成 EduKG 术语」——generate_textbook_data.py(CLI)+TextbookDataGenerator 把 23 册教材 JSON 解析成 Textbook/Chapter/Section/TextbookKP 节点与 CONTAINS/IN_UNIT 关系(TextbookKP 用全局序号 textbook-{stage}-{seq:05d} 保证 URI 唯一, 非知识点过滤前置), URIGenerator v3.1 编码(出版社/年级/学期), KPNormalizer 只用 DeepSeek 把"1-5的认识"标准化成"自然数"(md5 缓存+原子写+断点续传, 失败降级原名称) 提高与 EduKG 匹配率。

## 业务描述与业务场景

**业务描述**：教师之家爬下来的人教版 K12 数学教材目录是原始 JSON，结构杂、含非知识点条目、知识点名是教材口语（"1-5的认识"）——这段代码把它变成图谱里规范的"教材结构层"（教材→章→节→知识点节点 + 归属关系），再把知识点名标准化成 EduKG 能对上的术语，是后续匹配和答疑检索的前提。

**业务场景**：
- 教研把 23 册教材 JSON 放进来，跑一次生成脚本得到 textbooks/chapters/sections/textbook_kps 标准文件，供 Phase 3 导入 Neo4j
- 「数学活动」「小结」「复习题」这类非知识点条目不能建节点，过滤规则在生成时就拦掉
- 「1-5的认识」这种口语知识点名匹配不上 EduKG 的高中抽象概念，先用 DeepSeek 标准化成「自然数」再向量检索，匹配率从 17% 提到 97.1%

## 职责

**职责**：教材原始 JSON → 标准节点/关系 JSON（Textbook/Chapter/Section/TextbookKP + CONTAINS/IN_UNIT），并用 LLM 把教材知识点名标准化为 EduKG 术语以提高匹配率。
**不做什么**：不做数据清洗/专题增强/属性补全（那是 clean_textbook_data/enhance_chapters/enhance_kp_attributes 主题）；不做匹配与双模型投票（那是 match_textbook_kp 主题，本主题只产出标准化名供其使用）；不直接导入 Neo4j（那是 Phase 3 import/*）。
**分工要点**：核心逻辑在 `edukg/core/textbook/`（data_generator/uri_generator/kp_normalizer/config），CLI 入口在 `edukg/scripts/kg_data/textbook/`（generate_textbook_data.py/normalize_textbook_kp.py）；本主题仅 Python 管道。

## 代码事实

### 关键机制：TextbookDataGenerator（`data_generator.py`）

1. **文件发现**：小学 `primary/grade{1-6}/{shang,xia}.json`（12 册）、初中 `middle/grade{7-9}/{shang,xia}.json`（6 册）、高中 `high/bixiu*/textbook.json` + `high/xuanxiu_bixiu*/textbook.json`（5 册）共 23 册（data_generator.py:71-113）
2. **教材节点**：`label = {stage_name}{grade}{semester}`（学期为"未知学期"则省略）；`subject` **硬编码"数学"**（data_generator.py:142-153,145-149）
3. **知识点过滤前置**：`filter_knowledge_points(kps)` 在生成 TextbookKP 前过滤非知识点条目（data_generator.py:230）；过滤规则 `NON_KNOWLEDGE_POINT_MARKERS`（数学活动/小结/整理和复习/复习题/数学乐园等，见 5_教材目录README:437-443）
4. **TextbookKP URI 全局序号**：`self._kp_seq` 跨所有教材递增，`textbookkp_uri(stage, seq)` → `http://edukg.org/knowledge/3.1/instance/math#textbook-{stage}-{seq:05d}`（data_generator.py:232-233；uri_generator.py:147-159）
5. **关系生成**：`_generate_contains_relations` 生成 Textbook→Chapter（148）+ Chapter→Section（580）= 728 条 CONTAINS（data_generator.py:355-375）；`IN_UNIT`（TextbookKP→Section）在 `_parse_sections` 内生成（data_generator.py:248-253）
6. **输出**：`generate_all` 写 6 个 JSON + `import_summary.json` 统计（data_generator.py:377-430）；CLI 的 `IMPORT_OUTPUT_DIR = OUTPUT_DIR.parent`，导入文件输出到教材目录根路径、中间文件仍在 output/（generate_textbook_data.py:32）
7. **缓存/增量**：`generate_textbooks()`/`generate_chapters()` 只生成对应节点；`generate_sections()`/`generate_textbook_kps()`/`generate_relations()` 会触发 `_generate_all_data()` 全量生成（data_generator.py:257-316）

### 关键机制：URIGenerator（`uri_generator.py`）

1. **ID 编码**：`textbook_id = {pub_code}-{grade_code}{sem_code}`（`renjiao-g1s`）；`chapter_id = {textbook_id}-{order}`（`renjiao-g1s-1`）；`section_id = {chapter_id}-{order}`（`renjiao-g1s-1-1`）（uri_generator.py:45-107）
2. **编码表**（`config.py`）：年级 g1-g6 / g7-g9 / bixiu1-3 / xbixiu1-3（config.py:46-56）；学期 上册=s、下册=x、高中空（config.py:59-62）；出版社 人民教育出版社/人教版 → renjiao（config.py:65-68）
3. **URI 前缀**：`http://edukg.org/knowledge/3.1/{type}/math#{id}`（textbook/chapter/section/instance），`URI_VERSION="3.1"` 避免与 EduKG v0.1/v0.2 冲突（config.py:10-11；uri_generator.py:111-159）
4. **反向解析**：`parse_textbook_id` 按 `-` 拆 publisher/grade+semester，兼容 `bixiu1` 无学期形式（uri_generator.py:204-237）

### 关键机制：KPNormalizer（`kp_normalizer.py`，DeepSeek 单模型标准化）

1. **模型选择**：`normalize` 调用 `self.voter._call_llm(self.voter.secondary_model, prompt)`——**只用 DeepSeek（secondary_model）单模型**，注释"只用 DeepSeek，标准更严格"（kp_normalizer.py:220-222）；不走双模型投票
2. **流程**：教材知识点 → LLM 推断标准概念名（concepts 列表 + best_match）→ 供后续向量检索（kp_normalizer.py:6-13）
3. **缓存**：缓存键 `md5(f"{kp_name}_{stage}_{grade}")`，文件存 `output/normalizer_cache/{key}.json`；原子写（临时文件 + os.replace）（kp_normalizer.py:97-100,117-141）
4. **并发防重**：`asyncio.Lock` + `_processing_keys` 集合防同 key 并发重复调用；等待超时 60s 仍处理中 → 返回 `{concepts:[kp_name], best_match:kp_name, confidence:0.0}`（kp_normalizer.py:171-212）
5. **失败降级**：LLM 调用异常 → 返回原名称 + confidence 0.0 + reason（kp_normalizer.py:239-248）；JSON 解析失败 → 空 concepts（kp_normalizer.py:254-278）
6. **批量并发**：`normalize_batch` 默认 `max_concurrent=5`，asyncio.gather 并发（kp_normalizer.py:280-307）；CLI `--concurrency` 默认 5（normalize_textbook_kp.py:261）
7. **断点续传**：`NormalizationRunner` 基于 `CACHE_DIR` 实际缓存文件（glob `*.json`）判断已完成 URI，跳过已缓存只处理 pending（normalize_textbook_kp.py:126-152）；全缓存则直接加载写 `normalized_kps_complete.json`（normalize_textbook_kp.py:154-168）

### 边界与降级

- 标准化 LLM 失败 → 返回原名称 `{concepts:[kp_name], best_match:kp_name, confidence:0.0}`，不中断批量（kp_normalizer.py:239-248）
- 缓存文件损坏（JSONDecodeError）→ 日志告警 + 当未命中重新处理（kp_normalizer.py:109-114）
- 并发同 key 等待超时 60s → 放弃处理返回默认结果，避免重复调用（kp_normalizer.py:196-208）
- 提示词模板文件不存在 → `FileNotFoundError`（kp_normalizer.py:45-46）
- 无 pending（全部已缓存）→ 直接加载缓存结果写完整输出（normalize_textbook_kp.py:154-168）

## 隐性坑与注意事项

- **`subject` 硬编码"数学"**：Textbook 节点 `"subject": "数学"`（data_generator.py:147），URI 生成器 `subject="math"` 默认（uri_generator.py:32-42）——换学科要改代码，非配置化。
- **TextbookKP URI 用全局序号而非语义名**：`textbook-primary-00001` 依赖 `_kp_seq` 全量递增（data_generator.py:232-233）；若只调 `generate_textbooks()` 再单独调其他方法，`_kp_seq` 从头计会导致 URI 碰撞/重复（`_generate_all_data` 幂等缓存 `_textbooks` 防重入，但方法间混用有风险）。
- **标准化只用 DeepSeek 单模型，不走双模型投票**：`voter._call_llm(self.voter.secondary_model)` 是私有方法直调（kp_normalizer.py:222）；面试说"双模型投票"指的是匹配阶段（match_textbook_kp），不是标准化阶段。
- **标准化缓存按 `kp_name+stage+grade` 共享**：同名知识点（如"加法"）跨教材同阶段共用一条缓存，跨教材语义差异会被抹平。
- **normalize_textbook_kp.py 把 `output_file` 写两次**（normalize_textbook_kp.py:226-231）：无害但冗余。
- **`generate_textbook_data.py` 的导入文件输出到 `OUTPUT_DIR.parent`**（教材目录根路径）而非 output/（generate_textbook_data.py:32）——找文件别找错目录。
- **数据质量靠人审**：core/textbook/README.md:7 与 5_教材目录README 反复强调"爬虫下载数据不准，需要人工校验"；自动生成的中间 JSON 应人工确认再进匹配/导入。
- **PROJECT_ROOT 计算**：`config.py` 用 `Path(__file__).parent.parent.parent.parent` 指向仓库根（config.py:15），而 `kp_normalizer.py` 的 `PROJECT_ROOT = Path(__file__).parent.parent.parent` 指向 `edukg/`（kp_normalizer.py:34），提示词文件实际路径是 `edukg/core/llm_inference/prompts/kp_normalizer.txt`——改路径需两头对齐。

## 设计要点

- **先过滤后建点**：非知识点条目（数学活动/小结/复习题）在生成 TextbookKP 前就用 filters 拦掉，防污染图谱（data_generator.py:230 + filters）。
- **序号化 URI 保证唯一**：TextbookKP 用全局递增序号 + 学段前缀（`textbook-{stage}-{seq:05d}`），简单可靠，不依赖语义去重；结构节点用 `publisher-grade-semester-order` 层级编码可读可解析（uri_generator.py）。
- **URI 版本隔离**：v3.1 前缀避免与 EduKG v0.1/v0.2 冲突，教材数据与权威语义层物理上可分、逻辑上靠 MATCHES_KG 连接（config.py:9-11）。
- **标准化用"更严格的 DeepSeek"**：用副模型单模型而非双模型，注释"标准更严格"（kp_normalizer.py:220）——标准化是纯名称映射任务，单强模型足够且省一半调用。
- **缓存 + 原子写 + 断点续传**：LLM 标准化 10-20 分钟可中断恢复；原子写（temp+rename）防并发损坏；`_processing_keys` 防同 key 并发重复 API 调用——LLM 长任务工程化的三件套。
- **批量并发限流**：Semaphore=5 控制并发度，避免打爆 LLM API 限流（normalize_textbook_kp.py:179-187）。
