## 为什么（语雀）

学习路径推荐和知识缺陷诊断的核心，是"知识点之间的前置/后置依赖关系"——这也是知识图谱选 Neo4j 而非 MySQL/ES 的首要理由（图遍历、前置链查询、可解释路径，语雀 D1）。但教材"先教"不等于"必须先学"：勾股定理在圆之前教，学圆却不需要先学勾股定理，所以教学顺序（TEACHES_BEFORE）与学习依赖（PREREQUISITE）必须严格区分（语雀 D8）。单一证据（章节顺序/LLM 直觉）都不可靠，需多源交叉确认（语雀 D9）。早期方案曾把教材章节顺序直接转成 PREREQUISITE（单来源简单版），已演进为"教学顺序只产 TEACHES_BEFORE、学习依赖多证据融合确认"。

## 怎么设计（方案）

**（方案口径，已演进）** 早期方案：把教材章节顺序直接转 PREREQUISITE（方案设计1 单来源简单版）。**已演进**：教学顺序只生成 TEACHES_BEFORE（章节内部），学习依赖（PREREQUISITE）需教材顺序/定义依赖/LLM 双模型/教师标注多证据融合确认（方案设计2/3，语雀 D8/D9）；低置信结果不丢弃、降级候选待人工补审；产物过 DAG 无环验证后才可作为学习路径。

### 三来源融合与阈值分档（设计口径）

```
【演进前 → 演进后】
单来源（章节顺序直接转 PREREQUISITE）→ 三来源融合（顺序只产 TEACHES_BEFORE，学习依赖需融合确认）

【证据权重（设计口径）】
教材顺序（章节内部）     0.7  → 只产 TEACHES_BEFORE（conf 1.0，教学顺序≠学习依赖）
LLM 双模型投票           0.8  → 区间 0.6~0.9（见阈值分档；已有前置则升级 +0.1 封顶 1.0）
教师标注                 1.0  → 人工最高权重（demo 不做）
补充：定义/定理依赖      0.85 → 直接 PREREQUISITE（代码最终落地 0.9，见翻转③）

【阈值分档（设计口径）】
两模型一致 且 conf ≥ 0.8        → PREREQUISITE（学习依赖）
两模型一致 且 0.6 ≤ conf < 0.8  → PREREQUISITE_CANDIDATE（低置信候选，待人工补审）
两模型不一致                    → 不采纳（丢弃）

【年级倒置惩罚（设计口径）】
前置年级 > 目标年级时按跨度乘惩罚系数：
  相邻年级     ×0.95
  跨 1 学段    ×0.9
  跨 2 学段    ×0.5
  跨度太大     ×0.3
惩罚后 < 0.6 → 降级 PREREQUISITE_CANDIDATE；质量目标：年级倒置率 ≤5%

【产物（设计口径）】
teaches_before.json + definition_deps.json + llm_prereq.json
  → fuse_results 三来源融合 → final_prereq.json → validate_dag（DAG 无环）
```

- **投票机制**（设计 D2/D7）：主模型 glm-4-flash（免费）+ 副模型 deepseek-chat 双模型投票；两模型一致 → 取平均置信度采纳；不一致 → 加权 `WEIGHT_DS=0.6/WEIGHT_GLM=0.4/THRESHOLD=0.5`，仅 DeepSeek=True 才可能过阈值（DS 一票否决），置信度=胜者×0.7。
- **TEACHES_BEFORE ≠ PREREQUISITE**（D8）：`infer_from_textbook_order` 仅章节内部按小节顺序生成 TEACHES_BEFORE（conf=1.0）；LLM 投票产出 PREREQUISITE / PREREQUISITE_CANDIDATE。relateTo 与 PREREQUISITE 语义严格区分。
- **DAG 无环验证**：`validate_dag.py` DFS 环检测（detect_cycles），退出码 0=无环/1=有环；输出覆盖率/平均链长/置信度分布（high≥0.8 / 0.5≤medium<0.8 / low<0.5）。保证学习路径不会出现"A 前置 B、B 前置 A"的死循环。
- **学习路径**：Cypher `MATCH path=(start)-[:PREREQUISITE*..10]->(target) RETURN path ORDER BY LENGTH(path)` 控深 ≤10；离线预计算 prerequisite_level 属性（BFS 最长前置路径）优化查询。
- **知识缺陷诊断**：给定"已掌握集合"，沿前置链多跳查未掌握的前置点（业务优先级 P0=前置依赖查询、P1=知识点识别+缺陷诊断、P2=学习路径推荐）。
- **质量目标（demo）**：前置覆盖率 ≥30%、DAG 合规 100%、平均前置链 2-4 跳、年级倒置率 ≤5%、高置信(≥0.8)占比 ≥60%。
- **Non-Goal（方案口径，非已实现）**：教师标注 1.0 仅预留（demo 不做）；不处理其他学科（物理/化学）；不做人工审核（Demo 阶段自动化）。

## 落地真相（代码）

> ⚠️ **最大翻转**：三来源融合是**设计目标非落地现状**——`fuse_results` 方法完整实现但**主链路未接入**，CLI 只产 `llm_prereq.json`，`final_prereq.json` 无任何脚本生产；年级倒置惩罚代码中不存在；主链路实际是"LLM 双模型投票 + 0.8 单阈值"单路径。面试被追问"前置依赖怎么融合"要如实讲：当前是 LLM 单路径，融合是设计目标非落地现状（`prerequisite_inferer.py:261-336` / `infer_prerequisites.py` 主流程）。

**当前主链路（LLM 单路径，✅落地）**：
- CLI：`python infer_prerequisites.py`（`--dry-run` 成本估算 / `--batch-size N` / `--stats` 统计），全流程推断输出 `llm_prereq.json`（infer_prerequisites.py:213）。
- 候选对生成：`generate_kp_pairs` 为"简化版本"——从 Neo4j 加载 Concept（约 1275+ 个，`MATCH (c:Concept) OPTIONAL MATCH (s:Statement)-[:RELATED_TO]->(c)`），每概念与按 label 排序前后 ±5 个配对，约 10×N 个有序对（infer_prerequisites.py:110-125；注释自述"应基于启发式规则筛选候选对"）。
- 投票：`DualModelVoter` 并行调 GLM-4-flash + DeepSeek；两模型 decision 一致 → 采纳取均值；不一致 → 加权 `DS=0.6/GLM=0.4/阈值0.5`，仅 DeepSeek=True 可过线（DS 一票否决），置信度=胜者×0.7（dual_model_voter.py:354-386）。
- 分类：`_infer_pair` 用 `confidence >= 0.8` 判定 PREREQUISITE，否则 PREREQUISITE_CANDIDATE（prerequisite_inferer.py:127）。
- DAG 验证：`validate_dag.py` 把 PREREQUISITE 与 PREREQUISITE_CANDIDATE 建图（:87），DFS 环检测，输出覆盖率/平均链长/置信度分布，有环 `sys.exit(1)`（validate_dag.py:212-214,356）。

**关键翻转（逐条）**：

> ⚠️ **翻转①（核心）：三来源融合未接入主链路，final_prereq.json 无生产方**。`fuse_results(teaches_before, definition_deps, llm_prereq)` 按 (kp_a_uri,kp_b_uri) 去重；定义依赖标记 DEFINITION_DEP、与 TEACHES_BEFORE 重合升级 PREREQUISITE(0.9)；LLM 结果与已有前置重合升级 PREREQUISITE、置信度 `min(已有+0.1, 1.0)`、source=multi_evidence——方法完整存在（prerequisite_inferer.py:261-336），但 `infer_prerequisites.py` 主流程只调 `infer_batch` → `save_results(LLM_PREREQ_FILE)`，**从不调** `infer_from_textbook_order/extract_from_definition/fuse_results`；因此 `final_prereq.json` 无任何脚本产出，直接跑 `validate_dag.py`（默认读 final_prereq.json）会 FileNotFoundError，需 `--input` 指定 llm_prereq.json 或先手动融合（validate_dag.py:70-71,358-360）。

> ⚠️ **翻转②：年级倒置惩罚代码中不存在**。语雀 D10 的 ×0.95/0.9/0.5/0.3 跨年级惩罚在代码中搜不到（validate_dag 也无年级倒置检测）——方案有、代码无；"惩罚后 <0.6 降级候选、年级倒置率 ≤5%"是设计质量目标非现状。

> ⚠️ **翻转③：定义依赖权重代码实际 0.9 非设计 0.85**。设计权重表 0.7/0.85/0.8/1.0；代码最终常量无 0.85——落地为 TEACHES_BEFORE conf 1.0 / 定义依赖 conf 0.9（prerequisite_inferer.py:302）/ LLM 升级 `+0.1` 封顶 1.0（prerequisite_inferer.py:261-336）。

> ⚠️ **翻转④：前置投票阈值部分落地**。主链路 `_infer_pair` 只用 ≥0.8 **一个分界**（prerequisite_inferer.py:127）；`config.CONFIDENCE_THRESHOLD_LOW=0.6`（config.py:17）与 `vote_prerequisite()`（≥0.8→PREREQUISITE、≥0.6→CANDIDATE、<0.6→None）**存在但未被 infer_batch 主链路调用**——README/语雀口径"<0.6 丢弃"在主链路不存在，0.6 形同虚设。

> ⚠️ **翻转（附带）：断点续传 `--resume` 未落地**。design D5/D11 要求 llmTaskLock（TaskState/CachedLLM/ProcessLock）+ `--resume`，但 `infer_prerequisites.py` 参数只有 `--dry-run/--batch-size/--stats`，`PrerequisiteInferer.infer_batch` 签名无 resume——推断中途失败需重跑（成本虽低）。

**✅ 落地（与方案一致）**：
- **TEACHES_BEFORE ≠ PREREQUISITE 严格区分**：`infer_from_textbook_order` 仅章节内部按小节顺序生成 TEACHES_BEFORE，conf=1.0、source=textbook_order（prerequisite_inferer.py:140-181）——方法存在（虽未挂 CLI 主流程）。
- **两级置信产出**：PREREQUISITE（≥0.8）/ PREREQUISITE_CANDIDATE（<0.8）保留低置信候选供人工补审，不丢弃。
- **DS 一票否决**：加权 DS=0.6>阈值 0.5，用更严格模型压误判（dual_model_voter.py:365 注释"只有 DeepSeek=True 才可能过阈值"）。
- **DAG 环检测**：DFS `detect_cycles`，退出码 0=无环/1=有环，保证学习路径无死循环。
- **成本优先**：GLM-4-flash 免费主力 + DeepSeek 兜底，数学 1295 概念全推断成本 <0.01 元（README:280-288）。

**边界与降级（代码现状）**：
- **模拟模式静默**：`_get_llm_gateway` 导入 LLMFactory 失败时降级返回固定 `{"is_prerequisite": true, "confidence": 0.8}`——测试/离线可用，线上会产假真值（dual_model_voter.py:75-91,137-156）。
- **投票失败/解析失败**：`vote()` 捕获 LLMCallError 返回 consensus=False 丢弃该对；`vote_with_retry` 仅对"响应解析失败"和异常重试（≤MAX_RETRIES=3），对"判断不一致"不重试（dual_model_voter.py:239-248,500-507）。
- **成本估算失真**：`generate_kp_pairs` 实际产 ~10N 对，`estimate_inference_cost` 按 2N 对估算（prerequisite_inferer.py:350），成本预估偏低约 5 倍。
- **投票不一致可被采纳**：只要 DeepSeek=True 且 GLM=False，加权 0.6≥0.5 就采纳为 PREREQUISITE，与 D7"两模型一致才采纳"口径不符（代码实际允许 DS 一票通过）。

## 追问与防御

**预期追问：前置依赖关系怎么来的？**
→ **回答要点**：当前主链路是 LLM 单路径——Neo4j 加载 Concept（约 1275+）→ 按 label 排序前后 ±5 邻居配对（~10N 对）→ GLM-4-flash + DeepSeek 双模型投票（一致采纳、不一致加权 DS=0.6 一票否决、置信×0.7）→ ≥0.8 落 PREREQUISITE、<0.8 落 CANDIDATE → DAG 无环验证。教材顺序只产 TEACHES_BEFORE（章节内 conf=1.0），与 PREREQUISITE 严格区分。

**预期追问：置信度低怎么办？**
→ **回答要点**：两级置信产出兜底——<0.8 不丢弃，落 PREREQUISITE_CANDIDATE 保留待人工补审；投票不一致不采纳（但加权路径 DS=True 可一票通过，此时置信 ×0.7 打折防高置信冒充）。年级倒置惩罚（×0.95/0.9/0.5/0.3）是设计构想，代码中不存在，面试要如实说明现状。

**预期追问：学习路径怎么生成？**
→ **回答要点**：基于 PREREQUISITE 关系——Cypher `[:PREREQUISITE*..10]` 控深 ≤10 沿链查，离线预计算 prerequisite_level（BFS 最长前置路径）优化；前置链必须先过 DAG 环检测（detect_cycles 退出码 0）才可作路径。知识缺陷诊断 = 给定已掌握集合，沿前置链多跳查未掌握的前置点（P0 前置依赖查询→P1 缺陷诊断→P2 路径推荐）。

**预期追问：三来源融合真落地了吗？**
→ **回答要点**：没有。`fuse_results` 方法完整实现（去重/升级 PREREQUISITE/conf=min(已有+0.1,1.0)/multi_evidence）但主链路未接入；CLI 只产 llm_prereq.json，final_prereq.json 无生产方，直接跑 validate_dag.py 会 FileNotFoundError。融合是语雀 D9 的**设计目标非落地现状**，如实讲当前是 LLM 单路径 + 0.8 单阈值。
