# 09 业务闭环与图谱价值落地

## 为什么（语雀）

图谱数据加工（6757 节点 / 20887 关系 / 匹配率 97.1%）只是**前半场**——如果图谱不能支撑答疑点亮、掌握度、学习路径、家长报表，就只是"数据做了放着"。业务方与面试真正关心的是**整条业务闭环怎么转**：学生一道题进来，图谱在哪一环被消费、信号落到哪、怎么回流成下一次答疑/补课的决策依据。核心哲学是"**无限业务事实与有限权威结构分存、权威图谱零写入**"——掌握度/点亮这些派生信号绝不写进权威图，图谱靠 MATCHES_KG / PREREQUISITE / RELATED_TO 被各业务环节消费来证明价值。（`1.语雀/语雀-方案总揽.md（§1 / §3 完整业务流程）`）

早期方案曾把教材章节顺序直接转成前置依赖，已演进为 TEACHES_BEFORE 与 PREREQUISITE **严格区分**——教学顺序只生成 TEACHES_BEFORE，学习依赖靠多证据/LLM 确认，悬念留给"怎么设计"展开。

## 怎么设计（方案）

**（方案口径，已演进）** 早期图谱定位是"数据做了放着"的展示件；演进后图谱是答疑→掌握度→学习路径→家长报表闭环的**知识底座**，业务派生信号只存 MySQL、权威图零写入。

**端到端闭环全景图（文字流程图）**：

```
数据加工(TTL/人教版教材爬虫/课标 四类来源)
  → 入库 Neo4j(两层图谱: 教材结构层 + 语义层, 6757 节点/20887 关系, MATCHES_KG 连接两层)
  → 向量索引(匹配侧 bge 512 维 / 服务侧 dashscope 768 维)
  → AI 答疑/题型命中(实体链接/知识点提取 → MATCHES_KG 命中 Concept → 图谱节点点亮)
  → 掌握度(错题→对应知识点→前置依赖链→结合正确率算掌握度→定位薄弱根因)
  → 学习路径(PREREQUISITE 前置链 → 补课顺序推荐, Cypher [:前置依赖*1..2] 控深)
  → 家长报表(掌握度/薄弱点汇总展示, 答疑记录回流支撑报表)
```

**图谱在闭环中的角色表**（各业务环节消费图谱什么）：

| 业务环节 | 消费图谱什么 | 图谱角色 |
|---|---|---|
| AI 答疑知识点点亮 | MATCHES_KG（TextbookKP→Concept，97.1%） | 答疑自由文本标签落地到有限权威结构，才能点亮图谱节点 |
| 掌握度诊断 | PREREQUISITE 前置链 + RELATED_TO 语义关联 | 沿前置链定位"当前点没掌握 vs 前置没学好" |
| 学习路径 | PREREQUISITE 前置关系 | 生成补课顺序（前置链） |
| 家长报表 | 掌握度 + 薄弱点 | 消费端展示，让图谱价值可感知 |
| 页面化浏览 | 教材结构层 6 级导航 + 点亮状态 | 只读消费；图谱关系直查 Neo4j + Redis TTL 300s 降级 |

**GraphRAG 落地设计**：学生提问 → 提取核心知识点 → **向量命中 Concept** → 沿 PREREQUISITE / RELATED_TO **扩展邻居** → 生成「前置知识点回顾→考点讲解→解题引导→易错提醒」引导式答疑（Cypher `[:前置依赖*1..2]` 控制深度）→ 路径带前置依据 = **可解释推理路径**。与掌握度联动：错题→前置链→算掌握度→定位薄弱根因；与答疑闭环：图谱作为 AI 对话助手"活文档"，答疑记录回流支撑家长端报表。（`1.语雀/语雀-方案总揽.md（§3.3 消费侧 / §10 GraphRAG）`）

**权威图谱零写入**：掌握度/点亮/题型派生数据只存 MySQL，物理不污染权威图（`1.语雀/语雀-决策记录.md（D17）`）；派生态解析靠 kp_uri 钩子"借"权威结构，图逻辑走 Neo4j 只读展开（`2.OpenSpec design 决策/design-backend-kp-matching-lightup.md（D1）`）。

## 落地真相（代码）

> ⚠️ **最大翻转**：图谱→答疑→掌握度→学习路径的"完整闭环"在代码侧是**分段落地 + 多处规划中**——匹配评审审核闭环（D16）代码只有 `candidate_review` 字段、前置依赖三来源融合未接入主链路（实际 LLM 单路径 + 0.8 阈值）、Python 桥的知识树/学习路径是简化桩、掌握度主体翻转与点亮渲染属 Java 侧（代码不在本仓）。正文答案以代码现状为准。

- ✅ **数据加工→入库已落地**：Phase0-3 全链路（爬取→生成→清洗→LLM 推断→匹配→导入），Neo4j 落地 6757 节点 / 20887 关系，MATCHES_KG 1690 条（97.1%），离线/在线分离，MERGE 幂等导入。（`3.代码/分析-01-知识图谱整体架构与数据链路.md`）
- ⚠️ **翻转（匹配评审系统）**：方案 D16「MySQL 审核表 + `/api/kp-match/recommend` + 审核导入」**是规划**——edukg 脚本与 ai-service API 均无实现，代码只有 `candidate_review` 记录字段，审核闭环未上线；未匹配的 50 个知识点实际走"置信度 <0.5 不硬连"留在图谱外。（`方案-代码对账.md（#4 匹配评审系统）`、`1.语雀/语雀-决策记录.md（D16）`）
- ⚠️ **翻转（GraphRAG 实际落地范围）**：方案描述的"向量命中 Concept → 沿关系扩展邻居 → 可解释路径"在**服务侧并未主链路真接**——`api/kg.py` 的 `/learning-path` 只返回目标实体自身一项、`/tree` 是前 100 实体平铺的简化桩、`/recommend` 只看一跳邻居（`service.py:436-455, 180-208`）；`core/rag/query.py` 是 AI 答疑**口述 RAG 检索**（图谱是其语料模块锚点之一），不是图遍历。另外在线查询统一用 `MATCH (e:Entity {uri...})` 而离线导入用 Textbook/Chapter/... 具体标签，标签体系可能不匹配（`service.py:101-109, 180-185`）。（`3.代码/分析-01-知识图谱整体架构与数据链路.md`）
- ⚠️ **翻转（掌握度主体/点亮只读属 Java 侧）**：掌握度主体从知识点翻转为题型（topic_key）、解析管线五步、点亮渲染"疑似态"、权威图谱零写入——这些都在 `design-backend-kp-matching-lightup.md`（D2/D16/D17），但 **Java/前端代码不在本仓**，分析-11 明确标注"非代码真值"；页面化同步（Neo4j→MySQL 8 张表 / 双数据源 @DS("kg") / 状态机）同样只能以 design 口径引用。（`3.代码/分析-11-Java同步与前端页面.md`、`方案-代码对账.md（#19）`）
- ⚠️ **翻转（前置依赖三来源融合未接入主链路）**：方案 D9「教材顺序(0.85)/定义依赖/LLM/教师 多证据融合出 final_prereq.json」**未接主链路**——`fuse_results` 方法存在但 CLI 只产 `llm_prereq.json`，`final_prereq.json` 无任何脚本生产（对账项 #11）；学习路径生成依赖的 PREREQUISITE **实际是 LLM 双模型投票 + 0.8 一个分界**（`prerequisite_inferer.py:127`）；定义依赖权重代码是 **0.9** 非设计 0.85（`prerequisite_inferer.py:302`），年级倒置惩罚 ×0.95/0.9/0.5/0.3 代码不存在（对账项 #13）。（`3.代码/分析-08-前置依赖推断.md`、`方案-代码对账.md（#11/#12/#13）`）

- ✅ **权威图谱零写入落地**：派生数据（掌握度/点亮）只存 MySQL，Neo4j 只读，`MATCHES_KG`/`PART_OF`/`RELATED_TO` 关系直查 Neo4j + Redis TTL 300s + `neo4jAvailable:false` 降级（`3.代码/分析-01-知识图谱整体架构与数据链路.md`、`1.语雀/语雀-方案总揽.md（§11/§12）`）。
- ✅ **前置依赖 TEACHES_BEFORE≠PREREQUISITE 已区分**：`infer_from_textbook_order` 仅产章节内部 TEACHES_BEFORE（conf=1.0），LLM 投票产 PREREQUISITE/PREREQUISITE_CANDIDATE（`3.代码/分析-08-前置依赖推断.md`）。

## 追问与防御

**预期追问：整个业务闭环怎么走（一句话盘面）？**
→ **回答要点**：数据从 TTL/教材/课标进管线 → 入库 Neo4j（两层图谱 + MATCHES_KG 连接）→ 建向量索引 → 答疑/题型分析命中 Concept 点亮图谱 → 沿 PREREQUISITE 前置链算掌握度、出学习路径 → 薄弱点回流家长报表——**加工、命中、诊断、补学、报表环环相扣**；消费端信号只存 MySQL，权威图零写入。

**预期追问：图谱是不是只是展示、没有真实业务价值？**
→ **回答要点**：不是摆设——答疑靠 MATCHES_KG 把自由文本标签点亮到权威知识点、掌握度靠 PREREQUISITE 前置链定位"当前没掌握 vs 前置没学好"、学习路径靠前置关系出补课顺序，家长报表是消费端落点。**三个消费环（点亮+掌握度+学习路径）都真实消费图谱关系**，页面化只是其中一环。（参考 `07-GraphRAG 与图谱联动`）

**预期追问：GraphRAG 可解释性从哪来？**
→ **回答要点**：路径带前置依据——向量命中 Concept 后沿 PREREQUISITE/RELATED_TO 展开，每个邻居都能回指"为什么先学它"的前置知识点，Cypher 控深 1-2 跳（`[:前置依赖*1..2]`）；但当前服务侧学习路径/知识树是简化桩，可解释推理路径是设计目标，落地要看 Java/MySQL 侧或后续接 GraphRAG 主链路。

**预期追问：图谱价值怎么证明？**
→ **回答要点**：三层证据——①数据真值：6757 节点 / 20887 关系 / 匹配率 97.1%（精确+向量粗筛 top-20+双模型投票，DS=0.6/GLM=0.4）；②消费闭环：答疑点亮、掌握度、学习路径都吃图谱关系；③如实防御：匹配评审审核闭环（D16）是规划非已上线、前置融合未接主链路（现为 LLM 单路径 + 0.8 阈值）——**讲清方案与现状的边界本身就是可信度**。
