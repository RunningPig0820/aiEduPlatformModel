# 4.完善文档 处理方案

> 状态：2026-08-27 建目录，9 节标题规划见下；正文待 ①~③ 步语料/对账/分析完成后按提示词生成。

## 一、完善文档定位

**权威正文层（权威度 1.0，直接整篇进全量池 rag-full）**——一节 = 一个视角的完整答案，**整篇作为一个 chunk，禁止内部切片**。与 `3.代码/`（证据层，切片池 doc_type=code_analysis）互补：完善文档答"业务是什么/为什么"（权威正文），代码层答"代码真实行为"（精确机制）。

> **权威度 1.0 前置校验**：生成完善文档必须同时具备「语雀/design 方案素材」+「对应主题的代码分析文档作为落地真值」；**缺失代码证据，禁止输出 1.0，降级为 0.8**。不能仅凭设计稿生成 1.0 正文。

### 与 1.语雀 的区别（防混淆）

| 维度 | 1.语雀（产品意图/设计决策层） | 4.完善文档（权威正文层） |
|---|---|---|
| 组织维度 | 按**信息类型**（总揽/决策/选型/时间线/术语/边界） | 按**视角**（项目介绍/操作/难点/数据关联/架构/演进） |
| 权威度 | 0.8（意图层） | **1.0（正文层）** |
| 进池形态 | 切块进**切片池**（细粒度，doc_type=canonical） | 整篇进**全量池**（一节=一个完整答案） |
| 回答的问题 | "为什么 Neo4j 不用 ES""匹配率 97.1% 怎么保证""匹配失败怎么办" | "图谱模块做什么""入库主流程怎么走""知识点怎么匹配" |
| 对 RAG 的职责 | 切片池**设计意图补充** | 全量池**主答案**（权威 1.0，优先召回） |

> **检索规则**：先回权威正文（完善文档 1.0），正文答不了的"为什么/权衡/演进"才落到语雀意图层（0.8 切片池）。

## 四、更新流水线（强制顺序）

代码/design 变更时：先增量更新 `3.代码/分析-*.md` → 再增量更新 `4.完善文档/0N-*.md`（**禁止全量重写正文**）→ 更新后跑辅助校验器复核：①所有 `> ⚠️ **翻转**` 是否仍成立 ②证据引用的文件路径是否存在 ③Non-Goal 有没有被误写为已实现。
