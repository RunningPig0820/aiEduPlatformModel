# 知识图谱 — 面试问题整理

> 模块定位：Neo4j 知识图谱（6757 节点 / 20887 关系 / 匹配率 97.1%），两层图谱（教材结构层 + 语义层）靠 MATCHES_KG 软连接，支撑 AI 答疑知识点点亮、掌握度诊断、学习路径、GraphRAG 与页面化浏览。
> 所属大纲段：1 项目介绍 / 3 数据入库 / 4 数据关联 / 5 难点
> 来源：问答表（引导/亮点/追问 + 防御）= 模块主文档问题表迁移 + 完善文档 01~09 提炼；**全量 64 问见 `问题列表.md`**（9 视角，引导池 + 评测集共用）
> 口径提示：凡涉及"融合/审核/页面化/倒置惩罚"等设计项，答案均区分**设计口径 vs 落地现状**，如实标注"规划非已上线"。

## 1. 项目介绍

| 引导（扬长） | 亮点 | 预期追问 |

## 2. 操作流程

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 图谱数据从哪来？ | 四类来源：EduKG TTL v0.1 + main.ttl v3.0 教材出处 + 人教版爬虫 23 册 + 课标2022 OCR | "TTL 怎么和教材合一？" → 不合一，两层分存 + MATCHES_KG 软连接，URI 版本化区分来源 |
| 数据入库完整流程怎么走？ | Phase0 爬取 → Phase1 生成/清洗/增强/推断 → Phase2 匹配 → Phase3 导入 → 校验 → 向量，单向离线流水线 | "哪一步最容易出问题？" → 属性增强顺序 bug（先增强只覆盖 22%）、匹配率 17% 的语义错位 |
| TTL 那么大怎么按学科拆？ | main.ttl 按 URI 学科前缀 `instance/{subject}#` 正则拆；material.ttl 按 C3 类型+P4 名称关键词+BFS 沿 P13/P2/P3 传播 | "拆错学科怎么办？" → unknown 兜底 + 三元组数量校验 + 人工确认 |
| 小学/高中没知识点怎么补？ | TextbookKPInferer 双模型投票（GLM-4-flash 主 + deepseek-chat 副）按章节推断，295 节→补 1052 个、平均置信 0.93 | "补的是不是编的？" → 双模型都有输出才采纳、带 confidence、断点续传可回溯，`source=llm_inferred` 标记 |
| 年级信息从哪来？ | 数据不自带，`TEXTBOOK_TO_GRADE` 映射表反推（"必修第一册"→高一）+ `STAGE_FALLBACK` 兜底 + `mark` 字段兼容解析 | "反推错怎么办？" → 映射表是显式可维护的，学段兜底只在表外生效 |
| 入库前几道质量防线？ | 解析生成 → 清洗（DataCleaner）→ 增强（纯规则）→ 过滤（数学活动/复习题/例\d 不建点） | "为什么增强用规则不用 LLM？" → 属性客观可枚举，快、可复现、不编造 |
| 知识点匹配这步怎么走？ | 精确匹配（标准化+同义词）兜确定性 → 向量粗筛 top-20 压候选 → 双模型投票只处理拿不准的；产出 matches_kg_relations.json | "产出里为什么有 exact/llm_vote/candidate_review？" → method 字段标记匹配来源，未匹配留人工审核 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 数据源可信吗？ | 四层来源各有背书（清华 EduKG 学术开源 + 官方 SPARQL / 教材基准 / 课标 OCR+人工）；匹配率 97.1% 是质量答卷 |
| 匹配失败怎么办？ | 不硬连（阈值 0.5 不过不建 MATCHES_KG），记 candidate_review 留人工；评审闭环是规划未上线，如实讲 |
| 清洗会不会误删？ | `--clean` 强制先 `--analyze` 出报告人工确认才执行，防脚本误删教材结构 |

## 3. 数据关联

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 图谱有哪些关系？ | MATCHES_KG(97.1%) / PREREQUISITE / RELATED_TO / BELONGS_TO / HAS_TYPE / CONTAINS / IN_UNIT 等 8 类 | "关系哪来的？" → TTL 原生 + 教材结构生成 + LLM 双模型推理 |
| MATCHES_KG 怎么保证对得准？ | 匹配前 LLM 标准化预处理（"1-5 的认识"→"自然数"）+ 精确匹配 + 向量粗筛 + 双模型投票；方向固定 TextbookKP→Concept、置信度≥0.5 | "置信度低怎么办？" → 投票 <0.7 丢弃 / 不过 0.5 不硬连，留 candidate_review |
| 双模型投票怎么工作？ | 一致采纳取平均；不一致加权 DS=0.6/GLM=0.4/阈值 0.5（DeepSeek 一票否决）+ 置信度×0.7 打折 | "为什么不是 majority vote？" → 两模型没有多数，加权是最小可行仲裁；用更严格模型压误判 |
| 前置依赖怎么构建？ | 主链路：Neo4j 加载 Concept → ±5 邻居配对（~10N 对）→ 双模型投票 → ≥0.8 落 PREREQUISITE、<0.8 落 CANDIDATE → DAG 无环验证 | "教学顺序能用吗？" → 只能产 TEACHES_BEFORE（章节内 conf=1.0），教学顺序≠学习依赖 |
| 学习路径怎么生成？ | 沿 PREREQUISITE 前置链，Cypher `[:PREREQUISITE*..10]` 控深 ≤10，离线预计算 prerequisite_level 优化 | "为什么先过 DAG？" → 防"A 前置 B、B 前置 A"死循环，DFS 环检测退出码 0 才可用 |
| 图谱和向量怎么配合（GraphRAG）？ | 向量命中 Concept → 沿 PREREQUISITE/RELATED_TO 扩展邻居 → 可解释推理路径；向量负责召回、图谱负责解释 | "路径为什么能解释？" → 前置知识点是依据，不是黑盒相似度 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 匹配率 97.1% 怎么做到的？ | 瓶颈不是模型强，是"把教材名先翻译成图谱语言"（LLM 标准化预处理）；三段式互补，LLM 调用 500万→2.7万 |
| 前置融合真落地了吗？ | 没有——fuse_results 方法存在但主链路未接入，CLI 只产 llm_prereq.json，当前是 LLM 单路径 + 0.8 单阈值，如实讲 |
| GraphRAG 可解释性实现了吗？ | 向量索引 + 前置依赖入库真实；邻居扩展在 Python 桥是简化桩，可解释路径是设计目标，落地看 Java/MySQL 侧 |

## 4. 开发难点

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 匹配率 17%→97% 关键是什么？ | 小学 69.6% 知识点是教学名（"连加连减"），EduKG 是抽象概念（"减法"），语义层级错位；LLM 标准化预处理把教材名翻译成概念名是性价比最高的提点手段 | "剩下的 3% 呢？" → 不过阈值不硬连，candidate_review 50 + none 8 留人工 |
| 双模型投票怎么防误判？ | 两模型一致才采纳抑制单模型幻觉；DeepSeek 更严格给 0.6、GLM 宽松给 0.4，等价"DeepSeek 同意才过、否决就挂" | "不一致怎么办？" → 加权仲裁 + 置信度×0.7 打折，不丢也不冒充高置信 |
| 本地 embedding 内存 3.5GB 怎么压？ | 懒加载每次"模型加载 + 全量 encode 1295 概念"≈3.5GB/60s；预构建索引把结果落盘，运行期只读文件约 3.1MB/<5ms | "索引过期怎么办？" → checksum（MD5 uri+label 排序拼接）失配告警，回退懒加载或 --force 重建 |
| LLM 长任务中断怎么办？ | llmTaskLock 三件套：TaskState 检查点 + CachedLLM（SHA256 缓存）+ ProcessLock 进程锁，推断/匹配 1-3 小时中断可续 | "缓存键是什么？" → SHA256(prompt)[:16]，改提示词模板旧缓存全失效 |
| 属性增强顺序出过什么 bug？ | 增强跑在 LLM 推断前，新增 1052 个知识点全没属性，覆盖率仅 22%——必须"先推断后增强"，规则步骤 `--force` 幂等重跑 | "topic 还会错吗？" → 继承章节会错（"加法"在"位置"章→图形与几何），靠匹配 Concept 的 Class 类型修正 144 个（数据级一次性） |
| 同义词扩展有什么坑？ | 早期 `key in name` 子串匹配把"加法交换律"匹配到"加法"——改完整词匹配（全等才扩展），组合词交给向量/LLM 语义层 | "原则是什么？" → 规则层只处理字面等价，语义模糊交向量/LLM |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 年级倒置惩罚实现了吗？ | 没有——×0.95/0.9/0.5/0.3 跨年级惩罚代码搜不到，validate_dag 也无年级倒置检测，是设计质量目标非现状 |
| 0.6 阈值怎么回事？ | 主链路 `_infer_pair` 只用 ≥0.8 一个分界，CONFIDENCE_THRESHOLD_LOW=0.6 只在未调用的 vote_prerequisite() 里，形同虚设 |
| 索引维度能改吗？ | 索引构建期定死（匹配侧 bge 512 / 服务侧 dashscope 768），换模型/维度必须重建索引，checksum 失配强制重建 |

## 6. 架构设计

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 模块怎么分工？ | 五端：Python edukg 管道离线构建 + Neo4j 最终存储 + ai-service 桥在线暴露 + Java 同步 MySQL + 前端 React SPA 只读 | "数据流向？" → 数据源→Python→Neo4j→（ai-service 桥 / Java 同步 MySQL→前端）单向 |
| 为什么离线构建/在线消费分离？ | 关系处理在 Python/CSV 完成，Neo4j 只是最后仓库，MERGE 幂等可重跑；Neo4j 只读零写入 | "在线查询慢怎么办？" → 图谱关系直查 Neo4j + Redis TTL 300s + 空关联降级 |
| Python 桥提供什么？ | api/kg.py 业务查询（10 路由）+ api/neo4j.py 通用 CRUD（12 路由，x-internal-token 鉴权） | "Java 怎么调？" → 经桥调 Neo4j；裸 /query 是后门，read_only 默认 true 生产防 token 泄露 |
| 页面化为什么方案 B？ | 方案 A（Neo4j 实时查询）被否：Java 无 Neo4j 集成、前端独立 SPA、实时查询重；改为同步 MySQL 前端只读 | "怎么保证一致？" → 手动按需 UPSERT 幂等 + 状态机 active/deleted/merged + 单事务 + 对账 |
| 权威图谱零写入怎么实现？ | 派生数据（掌握度/点亮）只存 MySQL，Neo4j 只读；派生态靠 kp_uri 钩子"借"权威结构 | "图谱关系怎么查？" → 关系直查 Neo4j + Redis TTL 300s + `neo4jAvailable:false` 降级，导航不依赖图谱可用性 |
| core/rag/query.py 是图谱查询桥吗？ | 不是——它是 AI 答疑 RAG 检索编排，检索图谱文档切片（模块锚点召回），不是 Neo4j 节点数据；图谱数据查询走 api/kg.py + api/neo4j.py，两条链路独立 | "别混了什么？" → 面试表述勿把 RAG 语料检索说成图谱数据查询 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 图谱在线查询查不到导入的节点？ | 在线统一 `MATCH (e:Entity)`，离线导入用 Textbook/Concept 等具体标签，标签体系可能不匹配——联调前必须对齐（Entity 由 Java 动态建 or 查询是期望面） |
| 页面化真的落地了吗？ | 方案 B 已拍板、design 三份一致，但 Java/前端代码不在本仓、graph 接口未实现、API 前缀前后端不一致（/api/kg/** vs /api/auth/kg/**），属"联调收口"状态，不能讲成已上线 |
| Python 桥能力够用吗？ | 知识树/学习路径/推荐是简化桩，页面化真层级走 Java 同步 MySQL 侧，别从 Python 桥期待完整图谱能力 |

| 掌握度数值可靠吗？ | 事件驱动可追溯 + 双模型投票带 reason + 低置信过滤，非拍脑袋 |

## 8. 数据存储

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 图谱数据分别存哪？ | Neo4j（7 类节点/8 类关系，URI 主键，权威只读）+ MySQL 页面化（8 张表，@DS("kg") 双数据源）+ COS 向量索引（服务侧 768 维） | "谁写谁读？" → Python import 脚本写 Neo4j；Java 同步写 MySQL；vector_store 写 COS；前端只读 |
| URI 为什么要版本化？ | v0.1 EduKG 原始 / v0.2 小学新增 / v3.1 教材，物理隔离来源、避免冲突，改数据走合并流程不改 URI | "URI 是什么格式？" → `http://edukg.org/knowledge/3.1/{type}/math#{id}`，TextbookKP 用全局序号 `textbook-{stage}-{seq:05d}` |
| 为什么主键用 URI 不用自增 ID？ | 跨 Neo4j/MySQL 唯一锚点，同步按 URI UPSERT，URI 永不修改（改动走合并） | "性能够吗？" → <1 万节点 VARCHAR(255) 主键可行，暴涨才考虑整型代理键 |
| 两套 embedding 维度为什么不同？ | 匹配侧 bge 本地 512 维（离线批量粗筛）+ 服务侧 dashscope 768 维（在线 RAG），各管一段、互不通用 | "维度不一致怎么办？" → 索引构建期定死，换模型必须重建索引，checksum 失配强制重建 |
| 图谱关系为什么不同步 MySQL？ | 关系（MATCHES_KG/PART_OF/RELATED_TO）直查 Neo4j，避免无限业务事实污染权威图谱 + 减少同步复杂度 | "查不到怎么办？" → Redis TTL 300s 缓存 + 空关联降级，导航不依赖图谱可用性 |
| 向量索引存哪、怎么防过期？ | 匹配侧落盘 kg_vectors.npy(1295×512) + index_meta.json（MD5 checksum）；服务侧写 COS 桶（put 后约 10s 异步生效） | "checksum 算什么？" → MD5(uri+label 按 uri 排序拼接)，图谱变则失配回退懒加载/重建 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 索引 put 后查不到？ | COS 向量索引异步生效 ~10s，写入成功不立即可查，紧跟 query 可能 miss |
| 两套向量混了会怎样？ | 512/768 维度不同互相不通用，混用会维度报错/语义错位，路由靠 vector_type 区分 |
