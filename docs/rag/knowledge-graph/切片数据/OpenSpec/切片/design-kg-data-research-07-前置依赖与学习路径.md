> 检索摘要：前置依赖怎么定义、证据从哪来？核心原则：教学顺序≠学习依赖，教材顺序存 TEACHES_BEFORE，真正学习依赖存 PREREQUISITE；证据来源四类：教材章节顺序0.7/定义定理依赖0.85/LLM多模型投票0.8/教师标注1.0；定义依赖抽取用词边界匹配+停用词+同义词+概念层级防误报。

**核心原则（状态：）**：教学顺序 ≠ 学习依赖。教材章节顺序是教学安排顺序，不一定等于学习依赖顺序。例如"勾股定理"在教材中先于"圆"，但学圆不需要先学勾股定理。因此：教材顺序存为 TEACHES_BEFORE，真正的学习依赖存为 PREREQUISITE。

**证据来源分类（状态：）**

| 证据类型 | 说明 | 基础权重 | Demo 阶段策略 |
|---|---|---|---|
| 教材章节顺序 | 同章节内按 mark 顺序 | 0.7 | → TEACHES_BEFORE |
| 定义/定理依赖 | 从定义文本中抽取的关键概念 | 0.85 | → PREREQUISITE（实现） |
| LLM 多模型投票 | GLM + DeepSeek 两模型一致 | 0.8 | → PREREQUISITE/CANDIDATE |
| 教师标注 | 人工审核 | 1.0 | Demo 阶段不做 |

**教材章节顺序（仅生成 TEACHES_BEFORE，状态：）**：infer_teaches_before 按教材和章节分组、按 mark 顺序生成关系，**仅同章节内**生成，confidence 0.85、source "textbook_chapter"、evidence ["chapter_order"]；注意这是教学顺序，不直接转化为 PREREQUISITE。

**定义依赖抽取（强证据）- 改进版（状态：）**：原方案使用简单字符串匹配（if other_kp.name in kp.definition）容易产生误报（如"指数"匹配"指数函数"、"合"匹配"集合"）。改进为：
- 词边界匹配 + 停用词表：STOPWORDS = {方法,概念,问题,性质,定理,公式,定义,计算,求解,证明,分析,结论,结果,技巧,步骤,过程,情况,条件}；用 `\b` 词边界确保完整词匹配非子串；preprocess_definition 预处理（移除 Markdown 链接/加粗标记、统一中英文标点、压缩空白）。
- 知识点类型标准化：TYPE_MAPPING——公理/定律/原理→定理；方程/表达式→公式；概念/术语→定义；特征/属性→性质；算法/技巧→方法；未映射保留原值。
- 同义词映射（按学科）：math 方程→[等式,方程式]、函数→[映射,对应关系]、直线→[一次函数图像,线性函数图像]、绝对值→[模]、平方→[二次方]、立方→[三次方]；physics 速度→[速率]（严格说不等价但定义中常混用）、力→[力的作用]。匹配扩展提高召回。
- 概念层级依赖：沿 CONCEPT_HIERARCHY 向上追溯父类。如"整式方程"→"方程"、"分式方程"→"方程"；"一元二次方程"→"整式方程"→"方程"（传递依赖）；定义中出现子类则间接依赖父类。

示例：知识点"一元二次方程"定义"含有一个未知数，且未知数的最高次数是 2 的整式方程" → 词边界匹配出"整式方程""方程" → 停用词表过滤"方法""概念"等泛化词 → 同义词可扩展"方程"→[等式,方程式] → 层级依赖推断"整式方程"依赖"方程"。
