# 页面化与服务化：学习报告三视图与题型分析

> summary: 学习报告三视图与题型分析
> 权威度: 0.7
> 模块: knowledge-graph
> COS路径: rag-slices/knowledge-graph/OpenSpec/design-kp-lightup-frontend-10-页面化与服务化-2.md
> 类别：操作流程

> 检索摘要：学习报告为总纲（摘要卡：题型计数）下挂掌握度（题型四类明细，点题型展开它派生的知识点）与知识点总览（题型派生的全量知识地图）两视图；题型分析（题型→知识点派生关系）合并进掌握度页，不再设独立子菜单，也不挂错题本下。

**掌握度主体 = 题型（知识点派生）**
掌握度 SHALL 以题型为主体展示：四类明细（已掌握/练习中/待巩固/待确认）的每一项是题型（topicLabel），不是知识点。知识点掌握度不由直接观测得到，而由「题型→知识点映射」派生。理由：题型是掌握度的直接观测主体——学生做题，观测到的是「会不会做鸡兔同笼」这类题型能力；知识点是题型背后的抽象，学会一个题型只覆盖知识点的局部（ratio < 1）。把掌握度直接落在知识点上，等于把「会做鸡兔同笼」夸大成「掌握二元一次方程」。

**学习报告总纲 + 掌握度子视图**
学习报告为总纲（摘要卡：已掌握/练习中/待巩固/待确认 的题型计数），下挂「掌握度」（题型四类明细，点某题型展开它派生的知识点）与「知识点总览」（题型派生的全量知识地图）。理由：摘要 + 明细 + 全图诉求不同，混一页会重；但「题型明细」与「题型→知识点」是同一维度的两层，合成一页。菜单已有「学习报告」占位，翻 active 即接入。

**知识点总览 = 题型派生的全量知识地图**
知识点总览展示全量知识地图（学段→章节→知识点），但知识点的着色不是直接观测，而是派生覆盖度——由「覆盖该知识点的已掌握题型的掌握度 × ratio」加权得到。学生掌握题型 → 派生覆盖知识点，未覆盖灰占位。理由：知识点是题型的派生物，所以知识点总览反映的是「你的题型能力覆盖了哪些知识点」，而非独立的「知识点掌握度」。学段分组仍按「学段（小学/初中/高中）→章节→知识点」——学生掌握点跨年级，学段更宽更稳，这一诉求不变。

**题型分析合并进掌握度页**
题型↔知识点关联是本期主功能，也是「知识点派生」的机制本身：展示题型库（`QuestionType`）+ 某题型的关联知识点（`QuestionTypeKp`：kpUri + ratio 占比）。学生看到的「题型 → 它派生的知识点」就是掌握度的派生依据。已定：掌握度（题型）与题型分析（题型→知识点）合并为一页——掌握度页列出学生掌握的题型，点某题型展开它派生的知识点。不再设独立「题型分析」子菜单，也不挂在错题本下（错题本是「错题」维度，题型分析是「掌握度」维度）。
