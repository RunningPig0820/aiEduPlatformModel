## 架构分工（离线构建 / 在线消费分离）

系统按"离线 / 在线"切成两层，跨 Python 管道、Python 桥、Java、前端四端：

- **离线构建管道（Python）**：把原始来源（EduKG TTL、人教版教材爬虫、课标）加工成图谱，分 Phase0 爬取 → Phase1 生成/清洗/增强/LLM 推断/合并 → Phase2 知识点匹配 → Phase3 导入 Neo4j。关系处理在 Python/CSV 完成，**Neo4j 只做最终仓库**，导入用幂等 MERGE 避免重跑重复。
- **Python 桥（在线）**：两套接口分层——**业务查询桥**（面向前端/答疑：实体搜索、实体详情、文本实体识别、知识树、学科分类、学生进度、进度更新、统计、推荐、学习路径）与**通用 CRUD 桥**（面向 Java 做任意节点/关系操作，内部 token 鉴权，并暴露裸 Cypher 查询供 Java 扩展，风险自担）。
- **Java 后端**：页面化同步（Neo4j→MySQL 双数据源）+ 掌握度派生。
- **前端**：React SPA 只读消费。

**核心取舍**：离线构建与在线消费解耦——重计算放离线管道，在线服务只做查询；业务查询与通用 CRUD 分开，通用层用 token 保护、暴露裸查询，方便 Java 侧扩展但防护责任下放。

## 数据模型设计（两层图谱）

图谱分两层互连：

- **教材结构层**：Textbook 23 / Chapter 148 / Section 580 / TextbookKP 1740，用 `CONTAINS`/`IN_UNIT` 结构关系组织，表达"教材→章→节→知识点"的导航结构。
- **语义层**：Concept 1295 / Statement 2932 / Class 39，用 `HAS_TYPE`/`RELATED_TO`/`BELONGS_TO`/`PART_OF`/`SUB_CLASS_OF` 表达概念语义关系。
- 两层靠 `MATCHES_KG` 连接（TextbookKP→Concept，1690 条，置信度≥0.5 才连边）。

关键约束：每个 TextbookKP 有且仅有一个 IN_UNIT 指向 Section；RELATED_TO 方向固定 Statement→Concept；`content` 属性在 Statement 上不在 Concept 上；所有关系不可逆。URI 按版本区分数据来源：v0.1 EduKG 原始 / v0.2 小学新增 / v3.1 教材。

**设计动机**：两层图谱刻意解耦"无限业务事实"与"有限权威结构"——教材结构层是逐年可增的业务事实，语义层是有限的权威概念，靠 MATCHES_KG 软连接互不污染；权威图谱零写入，业务派生数据（掌握度/点亮）一律存 MySQL，Neo4j 只放事实与概念。

## 在线服务关键机制

- **懒加载 + 单例**：图谱服务懒加载 Neo4j 客户端与实体链接器；Neo4j 客户端单例带连接池（上限 50、超时 30s），读/写/裸事务分封装。
- **实体链接**：用 jieba 分词 + 内存实体字典（按学科 9 个文件加载，加入 jieba 自定义词典）做文本到实体的识别。
- **桥 API 分层**：业务查询与通用 CRUD 分离，通用层全部走内部 token 鉴权。

## RAG 检索中的知识图谱接入（两条独立链路）

AI 答疑的 RAG 检索把知识图谱作为**语料模块锚点之一**：按关键词（知识图谱/图谱/neo4j/知识点/概念/关系/节点）锚定到知识图谱模块，流程为意图识别（LLM 结构化意图，失败回退关键词）→ 双池检索（全量池向量 + 切片池双向量 + BM25）→ RRF×权威度×节锚定加权融合 → 生成面试口述答案。

**重要定位**：这条 RAG 检索的是图谱**文档切片**，不是 Neo4j 节点数据；图谱的**数据查询**走业务查询桥 + 通用 CRUD 桥。两条链路用途不同，表述不能混。

## 边界与降级

- 实体查询不到返回 404；进度更新异常返回 `success=False` 不抛错。
- 知识树、学习路径、推荐是**简化实现**（非真层级/非前置链/只跳一跳邻居），页面化真层级能力在 Java 同步 MySQL 侧。
- Neo4j 健康检查失败 → 健康接口返回 unhealthy。
- RAG 检索降级：意图识别 LLM 失败回退关键词锚定；改写失败回退原问题。

## 设计要点

- **离线构建/在线消费分离**：重关系处理在离线管道完成，Neo4j 只当仓库，导入幂等可重跑。
- **权威图谱零写入**：Neo4j 只放事实与概念，掌握度/点亮等派生数据存 MySQL——权威库不被业务数据污染。
- **两层图谱解耦**：教材结构层（可增业务事实）与语义层（有限权威概念）靠 MATCHES_KG 软连接，互不污染。
- **桥 API 分层**：业务查询与通用 CRUD 分离，通用层 token 保护 + 暴露裸查询，扩展灵活但防护自担。
