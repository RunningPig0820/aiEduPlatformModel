## 两套拆分机制（main 与 material 差异化设计）

同一个"按学科拆分"目标，针对两个数据源结构差异采用了完全不同的两套机制：

**split_main_ttl（知识点）按 URI 学科前缀拆分**：EduKG 知识点实体 URI 自带学科前缀（instance/学科#），用正则从 URI 提取学科代码；默认覆盖 8 个学科（数理化生政史地语），也支持 `--auto-discover` 从图中自动发现全部学科 URI。拆分时保留 TTL 头部 @prefix 定义，写文件后校验三元组总数（原始数 = 写入数才打 ✓）。

**split_material_ttl（教材）按名称关键词 + 关系传播拆分**：教材实体 URI 不含学科信息，无法用前缀正则，改用 RDF 类型 C3（Textbook）识别教材实体，再用 P4 名称属性 + 学科关键词映射（10 个关键词 → 9 个学科代码）确定教材归属；随后沿三条真实包含关系 P13（教材→章）/P2（章→单元）/P3（单元→节）BFS 递归把学科传播到所有子实体，保证"教材→章→节→子节"全链路学科一致。无归属实体兜底归 unknown，可整体丢弃。

**为什么两套机制**：main 的 URI 含学科前缀可直接正则；material 的 URI 不体现学科，必须靠类型 + 名称 + 关系传播。这是"同一目标、按数据源特征分治"的典型取舍。

## Neo4j schema 设计

- **只建唯一约束，不建性能索引**：schema 阶段只建 3 个唯一约束（知识点 uri、学科 code、教材 isbn），防重复数据；性能索引延迟到数据导入后创建——先建索引再批量插入会导致导入时间 10x+ 变慢并产生索引碎片。这是 design 明确的设计决策。
- **节点标签 6 个**：Subject / Stage / Grade / Textbook / Chapter / KnowledgePoint。
- **关系类型不预定义**：Neo4j 关系类型在写入时自动创建，10 个关系类型枚举只作文档参考，无需在 schema 阶段预建。
- **验证器校验 schema 就绪**：用 Neo4j 元数据（`CALL db.labels()` 取标签、`SHOW CONSTRAINTS` 取约束）比对期望的 6 标签 + 3 约束；全过退出码 0，缺项退出码 1 并提示先建 schema。明确不验证性能索引。
- **dry-run 友好**：建 schema 支持 dry-run 只打印 Cypher 不执行，验证支持 verbose，便于 CI 前预览。

## 容错与降级策略

- 输入 TTL 文件不存在 → 报错退出码 1。
- 拆分后三元组数量不等 → 只打 ✗ 告警，不中断流程，照常返回统计。
- 无名称的实体（如无路径的图片资源）→ 归 unknown；可跳过不写文件。
- 约束创建单条失败 → 记录错误继续，不中断整体建 schema。
- Neo4j 连接失败 → 建/验证主流程捕获异常退出码 1。

## 设计要点

- **性能索引延迟创建**：先唯一约束（防重复）→ 批量导入 → 后建性能索引，避免导入 10x 变慢与索引碎片化。
- **material 用 RDF 类型而非 URI 模式识别学科**：main URI 含学科可直接正则，material URI 不体现学科，故改用 C3 类型 + P4 名称关键词 + 关系传播。
- **关系传播 BFS 化**：只沿真实包含关系（P13/P2/P3）递归传播，保证教材到子节全链路学科一致。
- **不验证不阻断**：拆分数量校验仅告警、约束创建失败单条 continue，让"数据质量门禁"更靠后的导入/校验阶段把关。
