## 业务描述与业务场景

教材目录从网页爬下来是原始结构，直接建图谱会有「通用」标签跨小节复用、小节名带序号前缀、全角字符、非知识点条目混入等问题。这段代码就是把 23 册教材 JSON 清洗成规范、无冗余、可入库的结构化数据，是图谱质量的第一道防线。

典型场景：
1. 教研上传教材目录后，系统自动检测「通用」标签在多个章节复用——避免一个「通用」小节被重复挂到 N 个章节下。
2. 小节名「1.1 正数和负数」要提取序号到 order_in_book 字段，保证排序正确。
3. 「数学活动」「复习题」「例1」这类非知识点条目不能建图谱节点，否则图谱被污染。

## 职责

教材原始 JSON → 规范化中间 JSON（chapters/sections/textbook_kps），去除冗余标签、规范小节名、补全属性、过滤非知识点。不做 LLM 推断、不做图谱匹配、不改 EduKG 权威数据。

分工：DataCleaner（清洗）+ ChapterEnhancer（专题）+ KPAttributeInferer（属性）+ filters（过滤），CLI 入口 clean_textbook_data.py（仅清洗部分）。

## 高层业务调用链（教材数据清洗规范化）

```
generate_textbook_data.py（生成节点/关系 JSON）
   │
   ▼
clean_textbook_data.py --analyze        ← 只分析，输出 duplicate_detection_report.json
   │  DataCleaner.analyze()
   │    · 通用标签跨小节复用检测（duplicate_same/different_textbook）
   │    · Section 需清洗检测（序号前缀/末尾冒号/全角）
   ▼  ── 人工确认报告 ──
clean_textbook_data.py --clean          ← 执行清洗，写 clean_log.json
   │  DataCleaner.clean_sections()
   │    · extract_section_order（序号→order_in_book）
   │    · 移除末尾冒号 / 全角→半角
   ▼
中间 JSON（清洗后）
   │
   ├── ChapterEnhancer.enhance()        专题增强（章节名→4 大专题/17 个数学专题）
   ├── KPAttributeInferer.infer()       属性补全（difficulty/importance/cognitive_level/topic，纯规则）
   └── filters.NON_KNOWLEDGE_POINT_MARKERS  过滤（数学活动/小结/复习题/例\d 等）
   ▼
规范化输出 → Phase 2 匹配（build_vector_index → match_textbook_kp）
```

**文字复述**：先生成节点/关系 JSON → --analyze 只分析不修改（检测「通用」标签跨小节复用、检测 Section 需清洗项）输出报告 → 人工确认后 --clean 执行清洗（序号提取到 order_in_book、去末尾冒号、全角转半角）→ 清洗后中间 JSON 再经专题增强、属性补全（纯规则）、非知识点过滤 → 规范化输出进入 Phase 2 匹配。
