## 隐性坑与注意事项

1. **属性增强执行顺序**：早期 KPAttributeInferer 在 LLM 推断**之前**跑，导致 enhanced 覆盖率仅 22%（299/1350）——必须「推断后增强」。
2. **topic 继承偏差**：topic 直接继承章节，章节语义与知识点不符时会错继承（「加法」在「位置」章 → 被归为图形与几何），靠匹配 Concept 的 Class 类型修正 144 个。
3. **全角/半角**：教材文本混全角字符，清洗统一转半角，否则匹配/检索时「（」vs「(」不一致漏配。
4. **先分析后清洗是安全设计**：防 LLM/脚本误删；通用标签 88 组是教材结构特征、不是脏数据。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**清洗类名四件套 —— ✅落地**
原始方案文档称 DataCleaner/ChapterEnhancer；实际落地为 data_cleaner / chapter_enhancer / kp_attribute_inferer / filters 四件套。影响：清洗能力拆成可独立复用的模块，与文档口径一致、全部可回源。

**清洗粒度 —— ✅落地**
原始方案描述为「清洗增强」；实际按 清洗（DataCleaner）→ 专题（ChapterEnhancer）→ 属性（KPAttributeInferer）→ 过滤（filters）分步落地。影响：比笼统的「清洗增强」粒度更细，每一步职责单一、可单独校验。

**--clean 前置校验 —— ✅落地（安全设计）**
原始方案无明确前置校验；实际强制先 --analyze，报告不存在则拒绝执行（--force 可绕过）。影响：人工确认关口前置，防 LLM/脚本误删数据，与 design 口径一致。
