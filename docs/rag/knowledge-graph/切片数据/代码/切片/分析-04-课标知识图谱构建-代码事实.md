### 关键机制：课标知识点"核心概念+教学属性"拆分（方案C，`teaching_kp_parser.py`）
- 拆分示例（`curriculum/README.md:94-98, 238-257`）：
  - `100以内数的认识` → 核心概念 `数`（uri 0.1/instance/math#341，置信度 1.0）+ scope/action
  - `三角形内角和` → `三角形` + property
  - `20以内加法` → `加法` + scope
- 设计理由：教学知识点是"概念+教学属性"复合体，直接建点会污染概念图谱；只建核心概念节点，属性作字段保留完整信息。

### 关键机制：URI 版本化（`concept_matcher.py` / `kg_builder.py`）
- 匹配到 EduKG 已有概念 → 用 **v0.1 URI**（复用现有节点）
- 新增概念 → 用 **v0.2 URI**（`{拼音}-{md5_32bit}`）
- 每个概念带 `version` / `is_existing` 字段（`curriculum/README.md:31-36, 277-287`）
- 结果：434 → 122 概念（102 v0.1 + 20 v0.2），过滤 15 非核心（`README.md:103-117, 349-371`）

### 关键机制：关系生成"规则 vs LLM"分流（`relation_extractor.py` + `MAPPING.md:196-202`）
| 关系 | 生成方式 | 成本 |
|---|---|---|
| SUB_CLASS_OF | 规则映射（class_parents） | 零 |
| HAS_TYPE | 规则 + LLM 推断 | 低 |
| RELATED_TO | **规则匹配**：Statement 标签去"的定义"即关联 Concept | 零、100% 可解释 |
| PART_OF / BELONGS_TO | LLM 分析（语义最模糊） | 贵 |
- 结果：312 关系 = relatedTo 122 + partOf 46 + belongsTo 1 + HAS_TYPE 142 + SUB_CLASS_OF 1，**仅 47 条花 LLM 钱**（`README.md:389-399`）

### 关键机制：数据质量门禁（`README.md:402-562`）
- **6 类本地校验**：关系类型合法 / 三元组完整 / URI 格式 / 自环 / 重复 / **双向冲突**（A→partOf→B 与 B→belongsTo→A 不能并存）
- **3 类数据库冲突校验**：Cypher 查 Neo4j 已有边；冲突时"保留数据库版本、删生成版本"（`db_conflicts` 明细返回 generated vs existing）

## 设计要点

- **方案C 拆分**：非结构化课标文本 → 图谱 Schema 的关键决策——"概念 + 教学属性"分离，既保语义又防污染。
- **规则优先、LLM 兜底**：能规则化（类型/层级/定义关联）全部规则化，只有语义最模糊的才交 LLM——成本控制贯穿全链路。
- **版本化扩图**：v0.1/v0.2 + is_existing 让增量扩图可溯源、可回滚，不破坏已有图谱。
- **人在环质量门禁**：导入前 6+3 校验 + DB 冲突保留已有，自动化 + 人工确认结合。
