## 隐性坑与注意事项

- **直接建点污染图谱**：不拆复合体直接把"100以内数的认识"建 Concept 会污染概念图谱——方案C 拆分是前提。
- **新数据覆盖已有**：DB 冲突校验是硬门禁，冲突默认保留已有图谱，不覆盖权威数据。
- **OCR 一次性成本**：百度 OCR 收费，跑完一次就够；重跑要重花 OCR 钱，OCR 结果落盘复用。
- **双向冲突语义**：partOf 和 belongsTo 方向不能同时存在，否则图谱语义自相矛盾。

## 对账要点

对账结论逐条复盘（原始方案 → 实际落地 → 业务影响）：

- **小学数据来源**：语雀/design 口径称"小学数据从课标补充"；实际落地为 curriculum 8 步流水线 + eduBureau/math 课标 OCR 数据文件，形成完整可执行的"课标→小学图谱"管道。业务影响：小学知识点缺口被系统性补齐，不再依赖手工补数。落地——小学数据来源落地为 curriculum 8 步流水线 + 课标 OCR 数据文件。
- **关系成本**：文档口径称"关系规则为主"；实际落地 312 条关系仅 47 条花 LLM（partOf/belongsTo 语义最模糊），其余全部规则化零成本。业务影响：成本控制符合预期，LLM 只在不可规则化处消耗。落地——关系成本"规则为主"落地为仅 47/312 条走 LLM。
- **数据污染防护**：文档口径称"版本区分"；实际落地 v0.1/v0.2 双 URI + is_existing 可溯源字段 + DB 冲突时保留已有版本。业务影响：增量扩图不污染已有语义层，可溯源、可回滚。落地——数据污染防护从"版本区分"落地为版本号 + is_existing + 冲突保留已有。
- **接口契约（校验输出）**：文档口径称"质量门禁"；实际落地 6 类本地校验 + 3 类 DB 冲突校验，`db_conflicts` 明细返回 generated vs existing。业务影响：导入前质量可控，冲突条目可人工复核后再决定。落地——质量门禁落地为 6 类本地 + 3 类 DB 冲突校验。
