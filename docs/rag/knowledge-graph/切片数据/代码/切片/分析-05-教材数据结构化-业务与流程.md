## 业务描述与业务场景

**业务描述**：教师之家爬下来的人教版 K12 数学教材目录是原始 JSON，结构杂、含非知识点条目、知识点名是教材口语（"1-5的认识"）——这段代码把它变成图谱里规范的"教材结构层"（教材→章→节→知识点节点 + 归属关系），再把知识点名标准化成 EduKG 能对上的术语，是后续匹配和答疑检索的前提。

**业务场景**：
- 教研把 23 册教材 JSON 放进来，跑一次生成脚本得到 textbooks/chapters/sections/textbook_kps 标准文件，供 Phase 3 导入 Neo4j
- 「数学活动」「小结」「复习题」这类非知识点条目不能建节点，过滤规则在生成时就拦掉
- 「1-5的认识」这种口语知识点名匹配不上 EduKG 的高中抽象概念，先用 DeepSeek 标准化成「自然数」再向量检索，匹配率从 17% 提到 97.1%

## 职责

**职责**：教材原始 JSON → 标准节点/关系 JSON（Textbook/Chapter/Section/TextbookKP + CONTAINS/IN_UNIT），并用 LLM 把教材知识点名标准化为 EduKG 术语以提高匹配率。
**不做什么**：不做数据清洗/专题增强/属性补全（那是 clean_textbook_data/enhance_chapters/enhance_kp_attributes 主题）；不做匹配与双模型投票（那是 match_textbook_kp 主题，本主题只产出标准化名供其使用）；不直接导入 Neo4j（那是 Phase 3 import/*）。
**分工要点**：核心逻辑在 core/textbook（data_generator/uri_generator/kp_normalizer/config），CLI 入口在 scripts/kg_data/textbook（generate_textbook_data/normalize_textbook_kp）；本主题仅 Python 管道，Java/前端不参与教材数据生成与标准化。

## 高层业务调用链（教材 JSON → 图谱节点/关系 + 知识点标准化）

```mermaid
flowchart TD
    A[23册原始教材JSON<br/>primary/middle/high] --> B[generate_textbook_data.py<br/>--dry-run / --stats / --output-dir]
    B --> C[TextbookDataGenerator.discover_files<br/>primary grade1-6 上下册<br/>middle grade7-9 上下册<br/>high bixiu/xuanxiu textbook.json]
    C --> D[_parse_textbook/_parse_chapters/_parse_sections<br/>filter_knowledge_points 过滤非知识点]
    D --> E[TextbookKP URI 全局序号<br/>textbook-{stage}-{seq:05d}]
    E --> F[输出6 JSON<br/>textbooks/chapters/sections/<br/>textbook_kps/contains/in_unit]
    F --> G[normalize_textbook_kp.py --resume<br/>NormalizationRunner 批量]
    G --> H[KPNormalizer.normalize<br/>只用 DeepSeek secondary_model]
    H --> I[normalized_kps_complete.json<br/>+ normalizer_cache 断点续传]
    I --> J[Phase2 match_textbook_kp 消费]
    F -- 标准化失败/超时 --> H2[降级: concepts=[原名称]<br/>confidence=0.0]
    C -- 无文件 --> K[DRY-RUN 提示 / stats 无数据]
```

**文字复述链路**：23 册原始教材 JSON（小学 primary/初中 middle/高中 high）先进生成 CLI → TextbookDataGenerator 按学段/年级/上下册发现文件、解析教材/章/节并在生成 TextbookKP 前用 filter_knowledge_points 过滤非知识点 → 知识点用全局序号生成唯一 URI（textbook-{stage}-{seq:05d}）→ 输出 6 个 JSON（textbooks/chapters/sections/textbook_kps/contains/in_unit）→ 再进标准化 CLI（--resume 支持断点）→ KPNormalizer 只用 DeepSeek 单模型批量标准化知识点名 → 输出 normalized_kps_complete.json + normalizer_cache 缓存供断点续传 → 交给 Phase 2 匹配阶段消费；标准化失败/超时降级为返回原名称（confidence=0.0）；发现阶段无文件则 DRY-RUN 提示/stats 无数据。
