## 业务描述与业务场景

人教版小学 1-6 年级、高中必修的教材原始 JSON 里没有知识点列表，只有初中（7-9 年级）带完整知识点（约 252 个）。这条管道就是让大模型照着教材章节名，把小节里"学生必须掌握的核心知识点"推断出来，补全教材侧的知识点缺口，是图谱节点的重要来源之一。

典型场景：
1. 教研拿到小学三年级上册"时、分、秒"章节，系统自动推断出"秒的概念""秒与分的关系""时间的读写"这类知识点。
2. 推断任务跑 2-3 小时中途断了，希望从断点接着跑而不是从头再来。
3. 同一个章节重复推断不能重复花 LLM 钱——相同提示词直接命中缓存。

## 职责

负责"缺失知识点章节分析 → LLM 双模型投票推断 → 断点续传/缓存 → 输出推断结果 → 合并入库"。不做初中推断（初中已有知识点）、不做属性推断/专题增强、不做图谱匹配、不直接写 Neo4j（输出 JSON 供合并/导入）。仅 Python 离线管道一端参与。

## 高层业务调用链（教材知识点 LLM 推断→合并入库）

```mermaid
flowchart TD
    A[教材 JSON: sections/textbook_kps/textbooks] --> B[infer_textbook_kp.py 加载]
    B --> C{analyze_missing_kps 筛选}
    C -- 小学1-6年级 且 知识点为空 --> D[需推断]
    C -- 高中 且 知识点为空 --> D
    C -- 初中7-9 知识点完整 --> X[不推断]
    D --> E[缺失章节列表 433 节]
    E --> F[TextbookKPInferer.infer_batch]
    F --> G{TaskState 断点续传: 已完成检查点?}
    G -- 已完成 --> H[跳过]
    G -- 未完成 --> I[ProcessLock 进程锁保护]
    I --> J[每节: format_textbook_kg_prompt]
    J --> K{llm_cache SHA256 缓存命中?}
    K -- 命中 --> L[直接返回缓存结果]
    K -- 未命中 --> M[DualModelVoter.vote 双模型并行]
    M -- 两模型都有 knowledge_points --> N[采纳主模型 GLM 结果, 平均置信度]
    M -- 任一模型无输出/解析失败 --> O[保留已有知识点, confidence=0.0]
    L --> P[结果写 TaskState 检查点, 每10节保存一次]
    N --> P
    O --> P
    P --> Q[textbook_kps_inferred.json]
    Q --> R[merge_inferred_kps.py 合并→textbook_kps.json + IN_UNIT 关系]
```

**文字复述**：加载教材 JSON → 按"小学 1-6 年级且知识点为空 / 高中且知识点为空"筛出需推断章节（初中知识点完整直接跳过），共 433 节（小学 361 + 高中 72）→ 批量推断：先查断点检查点，已完成跳过，未完成的进进程锁保护 → 每节组提示词 → 先查缓存命中直接返回，未命中走双模型并行投票（主模型 GLM + 副模型 DeepSeek）：两模型都有输出则采纳主模型结果并取置信度平均，任一模型无输出/解析失败则保留已有知识点、置信度 0 → 结果写检查点（每 10 节保存一次）→ 落盘推断结果 JSON → 合并进正式知识点文件并生成章节归属（IN_UNIT）关系。
