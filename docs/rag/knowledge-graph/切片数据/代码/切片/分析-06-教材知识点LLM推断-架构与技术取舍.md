## 架构与技术取舍

### 免费模型当主模型（成本与质量权衡）
主模型用免费的 GLM-4-flash，副模型用付费的 DeepSeek-chat。投票结果**采纳主模型输出**，只在"有分歧风险"的匹配/前置任务里才让 DeepSeek 拿否决权。推断场景的双模型投票主要兜底"模型无输出/解析失败"，不追求内容级校验。

### 双模型投票的推断特判
推断任务的投票走独立分支：**不比较两模型内容是否一致**，只要两模型都有非空知识点输出就采纳主模型结果，置信度取两模型自报值的平均；任一模型无输出或解析失败则判定不一致，降级为保留已有知识点、置信度 0。置信度来自模型自报，不是外部验证。

### 断点续传三件套（解耦复用的基础设施）
状态检查点 + 缓存 + 进程锁（互斥）独立成一套 llmTaskLock 基建，复用给推断/匹配/标准化多个任务：
- **状态检查点**：按章节存完成/未完成，恢复时只跑未完成节，每 10 节落一次盘——任务跑 2-3 小时中断可从断点接着跑。
- **缓存**：以提示词的 SHA256 作键，相同提示词直接命中，不重复花 LLM 钱。
- **进程锁**：防止多进程并发跑同一推断。

### JSON 文件状态、不依赖外部服务
状态与缓存都落本地 JSON 文件（原子写：临时文件 + rename + 备份），无 MySQL 依赖，离线管道自洽；状态机完备（任务与检查点均含 pending/in_progress/completed/failed），恢复时取 pending + failed。

### 失败降级与重试
模型响应 JSON 解析有 5 级 fallback；LLM 调用异常 / 解析失败走重试（最多 3 次），一致性不一致不重试；LLM 网关加载失败时降级"模拟模式"（仅测试用）。

## 设计要点

- **免费模型当主模型**：GLM-4-flash 免费、DeepSeek 付费，投票采纳主模型输出，只在有分歧风险的任务里让 DeepSeek 拿否决权。
- **断点续传三件套解耦**：状态 + 缓存 + 进程锁独立成 llmTaskLock，复用给推断/匹配/标准化多个任务。
- **JSON 文件状态、不依赖外部服务**：原子写落本地进度文件，无 MySQL，离线管道自洽。
- **状态机完备**：任务/检查点均有 pending/in_progress/completed/failed，恢复取 pending + failed。
