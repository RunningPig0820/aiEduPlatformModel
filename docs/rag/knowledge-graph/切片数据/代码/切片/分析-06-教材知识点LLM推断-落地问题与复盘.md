## 隐性坑与注意事项

1. **推断 ≠ 严格一致性校验**：推断任务的投票只要求"两模型都有输出"，不比对内容——主模型输出 3 条、副模型输出 5 条仍判一致、采纳主模型 3 条。想校验内容一致性需另改逻辑。
2. **置信度来自模型自报**：推断置信度是模型自填的两模型平均，不是外部验证，0.934 只代表模型自身把握度。
3. **断点续传按节、不按 Prompt 级缓存去重**：恢复以状态检查点优先，缓存是第二道（相同提示词直接命中）。
4. **默认开启续传**：想全量重跑必须显式禁用续传，否则已完成检查点全跳过。
5. **进程锁依赖 portalocker**：未安装直接报错。
6. **缓存键是提示词的 SHA256**：改提示词模板 = 旧缓存全部失效，重跑会重新调 LLM。
7. **推断结果必须合并才生效**：推断只输出中间结果 JSON，不合并，下一步强制合并入库。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**断点续传三件套（落地）**
原始方案状态检查点 + 缓存 + 进程锁三件套 → 落地三模块全实现，且复用给推断/匹配多个任务。影响：2-3 小时长任务中断可断点续跑，避免重复花 LLM 钱。

**状态存储翻转：MySQL → JSON 文件（翻转）**
语雀 D12 称状态存储"用 MySQL 替代早期 SQLite" → 实际 Python 管道用 JSON 文件落本地进度目录（原子写），无 MySQL。影响：离线管道不依赖外部服务、自洽可迁移。

**前置依赖权重翻转：0.85 → 0.9（翻转）**
语雀 D9 定义依赖权重 0.85 → 实际落地定义依赖升级用 0.9，LLM 升级再加 0.1 封顶 1.0。影响：与文档口径不一致，但文档已自注；属于前置依赖侧任务，本推断主题不直接触发。

**推断阈值翻转：0.5/0.6/0.8 不作用于推断路径（翻转）**
语雀 D7 提"阈值 0.5/0.6/0.8" → 实际推断任务无硬阈值，只要求两模型都有输出；0.8/0.6 阈值只在另一个前置投票方法内且当前管线未调用。影响：推断采纳与否不靠置信度阈值卡，靠"两模型是否都有输出"。

**缓存命中统计（数据观察）**
语雀称推断缓存命中高 → 实际该批次推断结果中 from_cache=0（缓存未命中）。影响：该批为首次推断无缓存可命中，属正常数据观察，非缺陷。
