## 业务描述与业务场景

教材里"1-5 的认识"这种教学知识点，和图谱里的抽象概念"自然数"说的是同一回事，但名字对不上——这条管道就是把每个教材知识点对到图谱里语义对应的 EduKG 概念上（产出 MATCHES_KG 关系），让答疑时能通过图谱定位知识点。

典型场景：
1. 学生在答疑页问一道小学题，系统要能定位到图谱知识点，先决条件是教材知识点和图谱概念已建立关联。
2. 小学"连加连减"这类具体说法，直接字符串匹配永远对不上"减法"这种抽象概念，需要先翻译再匹配。
3. 五千多个图谱概念不可能每个都让大模型判断一遍，必须先粗筛出最像的少数几个候选。

## 职责

教材知识点 → EduKG 概念匹配，输出 `matches_kg_relations.json`（含精确匹配/LLM 投票/未匹配候选三态）。
**不做什么**：不做 LLM 推断知识点；不做匹配前标准化之外的其他清洗；不直接导入 Neo4j（输出 JSON 供导入脚本）；评审系统（MySQL 审核表/LLM 推荐接口/导入脚本）**代码中未见实现**。
**分工要点**：CLI 入口负责加载/成本估算/参数；KPMatcher 负责精确匹配+粗筛+LLM 投票；DualModelVoter 负责加权投票；KPNormalizer 负责标准化预处理。本主题仅 Python edukg 端。

## 高层业务调用链（教材知识点→图谱 MATCHES_KG 匹配）

```mermaid
flowchart TD
    A[教材知识点 1905 + 图谱 Concept 1295] --> B[匹配入口加载]
    B --> C[匹配器逐批处理]
    C --> D[初始化向量检索器]
    D -- 预构建索引校验通过 --> E[预构建索引检索器 10MB]
    D -- 无预构建/过期 --> F[本地向量检索 bge 3.5GB 懒加载]
    D -- 模型不可用 --> G[difflib 字符匹配回退]
    E --> H[逐个知识点处理]
    F --> H
    G --> H
    H --> I{① 标准化+同义词精确匹配?}
    I -- 命中 --> J[置信度=1.0, exact_match]
    I -- 未命中 --> K[② 向量粗筛 top-20]
    K --> L[LLM 匹配(带缓存)]
    L --> M{相似度 < 0.5?}
    M -- 是 --> N[跳过, 不进 LLM]
    M -- 否 --> O{LLM 调用数 < 3?}
    O -- 否 --> P[记录最佳候选待审核]
    O -- 是 --> Q[双模型投票]
    Q -- 两模型一致 --> R[采纳, 平均置信度, 早停]
    Q -- 不一致加权过 0.5 --> S[采纳, 置信度×0.7]
    Q -- 加权不过/全拒 --> T[最佳候选待审核 / 无匹配]
    J --> U[结果 JSON 1847 匹配 + 58 未匹配]
    R --> U
    S --> U
    P --> U
    T --> U
    U --> V[导入图谱建 MATCHES_KG 关系]
```

**文字链路复述**：匹配入口加载教材知识点（1905）与图谱 Concept（1295）后进入逐批处理；先初始化向量检索器——有预构建索引且校验通过用 10MB 预构建，无/过期则懒加载 bge 本地向量（3.5GB），模型不可用回退 difflib 字符匹配。对每个知识点：① 标准化+同义词精确匹配命中 → 置信度=1.0；未命中 → ② 向量粗筛 top-20 → ③ LLM 匹配（带缓存）：相似度<0.5 跳过不进 LLM，调用数≥3 记录最佳候选待审核，否则双模型投票——两模型一致采纳（平均置信度）并早停；不一致按 DS=0.6/GLM=0.4 加权过 0.5 采纳（置信度×0.7）；加权不过/全拒 → 待审核或无匹配。结果汇入 JSON（1847 匹配 + 58 未匹配），再导入图谱建 MATCHES_KG 关系。
