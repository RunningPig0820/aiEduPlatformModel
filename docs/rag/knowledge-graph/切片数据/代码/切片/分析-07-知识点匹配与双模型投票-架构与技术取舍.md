## 架构与技术取舍

### 三段式匹配流水线（成本逐层收敛）
精确匹配（0 元）→ 向量粗筛（本地 0 元）→ LLM 投票（最贵）逐层收敛：先把五千多图谱概念经粗筛压到 top-20 最像候选，再靠 0.5 相似度阈值 + 候选上限 3 + 命中早停，把 LLM 调用从"全量 5000+ 候选"压到实际 **2 次/知识点**（早期 40 次）。这是"先零成本拦截、再让贵模型只在极小候选集上判断"的成本控制思路。

### 精确匹配优先（零成本高命中）
匹配前先做标准化 + 同义词精确匹配：读标准化缓存里的 best_match + 完整词同义词展开（防止"加法交换律"误配到"加法"）+ 名称规范化（小写/去空格/统一括号）。命中即置信度=1.0、标记 exact_match，直接收敛不走 LLM。实际 1905 条里 exact_match 占 1639（约 86%），大头被零成本层消化。

### 向量粗筛 top-20
粗筛优先用向量检索器取 top-N 候选；异常/不可用回退 difflib 字符相似度（包含关系加分 0.2）。粗筛的意义：大模型不需要判断所有图谱概念，只在 20 个最像候选里判。

### 双模型投票抑制幻觉
两个模型（GLM-4-flash + DeepSeek）并行投票，读 is_match/decision 字段：
- 两模型一致 → 采纳，取平均置信度；
- 不一致 → 加权 `WEIGHT_DS=0.6 / WEIGHT_GLM=0.4 / THRESHOLD=0.5`。由于权重结构，只有 DeepSeek 判 True 时加权分才可能过阈值——DeepSeek 事实上拿"否决权"（它更严格），采纳时置信度 = 胜者置信度 × 0.7（降权反映意见分歧）。
- 模型返回的置信度字符串归一：high=0.95 / medium=0.7 / low=0.4 / 默认 0.5。

### LLM 调用三重优化
1. 相似度 < 0.5 直接跳过不进 LLM；
2. 每个知识点最多调 3 个候选；
3. 命中即早停。
配合粗筛实现 40→2 次/知识点的成本下降。

### 缓存设计（并发安全 + 可审计）
缓存键 = `SHA256(prompt)[:16]`；缓存存完整投票结果（含两模型响应/决策/理由），能解释"为何判不匹配"，可审计。`asyncio.Lock` 保护读写，并发匹配安全。注意：缓存命中不重投，改阈值/权重后旧缓存仍按旧结果返回（缓存键不含权重参数）。

### 并发匹配与未匹配兜底
信号量控制最大并发（默认串行，可调 5），同一知识点去重防重复处理；等待超时 30s 记 timeout。全部候选无匹配 → 返回 best_candidate 记录、标记 candidate_review，供人工审核进候选池。

### 实际结果
1905 条 = exact_match 1639 + llm_vote 208（匹配 1847，率 96.96%）+ candidate_review 50 + none 8（未匹配 58）。匹配平均置信度 0.973。

## 设计要点

- **三段式成本控制**：精确→粗筛→LLM 逐层收敛，LLM 调用从全量压到 2 次/知识点。
- **LLM 标准化预处理解决抽象层级错位**：匹配前先用 DeepSeek 把"1-5 的认识"翻译成 `["数的认识","自然数","数字"]`，best_match 作向量检索 query——先翻译解决"教学说法 vs 抽象概念"的名字对不上。
- **双模型共识抑制幻觉**：单模型可能自信地错，两模型一致才采纳；不一致时 DeepSeek 更严格的一方拿否决权。
- **缓存可审计**：缓存存完整 vote_result（含两模型响应/reason），能解释"为何判不匹配"。
