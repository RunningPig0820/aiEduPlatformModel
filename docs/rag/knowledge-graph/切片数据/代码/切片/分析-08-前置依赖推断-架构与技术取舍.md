## 架构与技术取舍

### 双模型投票机制（成本优先 + 更严格模型否决）
主模型用 GLM-4-flash（免费）降低成本、DeepSeek 做兜底，两个模型以并行方式对同一候选对分别判断「A 是不是 B 的前置」。两模型判断一致 → 采纳，置信度取两模型均值；判断不一致 → 走加权投票（DeepSeek 权重 0.6、GLM 权重 0.4、过线阈值 0.5），由于 DeepSeek 权重已经高于过线阈值，实际只有 DeepSeek 判 True 时加权结果才能过线——即 DeepSeek 拥有一票否决权，用更严格的模型压住误判；不一致采纳时置信度再打 0.7 折，表达"有分歧"的保守。全流程成本估算不到 0.01 元，数学 1295 个概念全量推断代价可忽略。

### 两级置信产出（低置信不丢弃）
推断结果按置信度分两档：PREREQUISITE（≥0.8）为确定前置、PREREQUISITE_CANDIDATE（<0.8）为候选前置。低置信候选保留下来供人工补审，而不是直接丢弃。口径上曾设计 0.6 低阈值三档（≥0.8 前置 / ≥0.6 候选 / <0.6 丢弃），但该逻辑所在方法未被主流程调用——主流程实际只有 0.8 一个分界。

### TEACHES_BEFORE 与 PREREQUISITE 严格区分
教学顺序与学习前置是两个不同概念：教材顺序只作为弱证据。代码里教材顺序按"章节内部小节顺序"生成 TEACHES_BEFORE（置信度固定 1.0，来源标记为教材顺序）；LLM 投票产出的是 PREREQUISITE/PREREQUISITE_CANDIDATE。两者语义严格分开，不混用。

### 三来源融合（半落地）
设计上要把三个证据来源融合出最终前置文件：教材顺序 + 定义依赖 + LLM 投票结果。融合规则：按知识点对去重；定义依赖打 DEFINITION_DEP 标记，与教材顺序重合升级为 PREREQUISITE(0.9)；LLM 结果与已有教材顺序/定义依赖重合时升级为 PREREQUISITE、置信度在已有基础上加 0.1（封顶 1.0）、来源标记 multi_evidence。但融合方法虽已实现，主流程 CLI 从不调用——实际只产出 LLM 原始投票结果，融合产物无生产方。

### DAG 无环验证
把 PREREQUISITE 与 CANDIDATE 建图（A→B 表示 A 是 B 的前置），做四项校验：DFS 找环（有环即退出码 1 拦截报警）、覆盖率（有前置的节点占比）、平均链长（根到各节点最长路径的均值）、置信度分布（high≥0.8 / medium 0.5-0.8 / low<0.5），最后产出校验报告。这是保证"学生补课顺序不会死循环"的关键闸门。

### 可解释性与降级策略
每对结果带 reason 字段（主因/次因），多来源融合时标记 multi_evidence，方便人工核对。核心推断逻辑与 CLI 入口分层（推断核心模块 + 脚本入口 + 校验脚本），但融合/顺序推断方法未挂到 CLI 属于"半落地"。降级：LLM 网关不可用时进入"模拟模式"返回固定真值+0.8（测试/离线可用，线上会产假真值）；投票失败/解析失败重试 ≤3 次、判断不一致不重试；单对产出失败则丢弃该对不写入结果。

## 设计要点

- **成本优先**：GLM-4-flash 免费做主模型 + DeepSeek 兜底，全流程成本估算 <0.01 元——数学 1295 概念全推断代价可忽略。
- **DS 一票否决设计**：加权权重使 DeepSeek 拥有否决权（只有 DeepSeek=True 才可能过阈值），用更严格模型压误判。
- **两级置信产出**：PREREQUISITE（≥0.8）/ PREREQUISITE_CANDIDATE（<0.8）保留低置信候选供人工补审，不丢弃。
- **可解释性**：每对产出带 reason（主/次原因），融合标记 multi_evidence，便于人工核对。
- **核心与 CLI 分离**：推断逻辑与入口分离，脚本只做入口——但融合/顺序推断方法未挂到 CLI 属"半落地"。
