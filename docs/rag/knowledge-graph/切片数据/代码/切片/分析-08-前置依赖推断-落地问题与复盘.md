## 隐性坑与注意事项

1. **最终前置文件没有生产方**：推断脚本只写 LLM 原始投票结果文件；DAG 校验默认读最终融合文件，但三来源融合未接入 CLI，没有任何脚本产出最终文件——直接跑校验会文件不存在报错，需手动指定输入文件或先手动融合。
2. **低阈值 0.6 形同虚设**：主链路只用 0.8 一个分界，0.6 阈值只在未被调用的方法里生效；文档口径"<0.6 丢弃"在代码主链路不存在。
3. **候选对数量与成本估算严重不符**：实际生成约 10N 个候选对，成本估算按 2N 对估算，成本预估偏低约 5 倍。
4. **断点续传未落地**：设计方案要求 `--resume` + 任务锁，但 CLI 参数只有 `--dry-run/--batch-size/--stats`，推断中途失败需整段重跑（成本虽低）。
5. **年级倒置惩罚未实现**：方案中的 ×0.95/0.9/0.5/0.3 惩罚在代码中搜不到——方案有、代码无。
6. **投票不一致的加权路径会放大误判**：只要 DeepSeek 判 True 且 GLM 判 False，加权 0.6≥0.5 就采纳为前置，与"两模型一致才采纳"口径不符——代码实际允许 DeepSeek 一票通过。
7. **模拟模式静默**：无网关时返回全 True+0.8 的假数据，跑完整流程不报错，容易把假前置导入。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**投票规则翻转：一致才采纳 → 0.8 单分界 + 不一致可加权采纳**
原始方案"两模型一致才采纳；≥0.8 前置、≥0.6 候选、不一致不采纳"。实际落地主链路只用 0.8 一个分界，不一致时走加权投票（DS=0.6/GLM=0.4，置信度×0.7）仍可采纳。影响：DeepSeek 拥有实际否决权，只要 DS 判 True 就可能被采纳为前置，比原始口径宽松，存在误判放大风险。

**年级倒置惩罚方案有/代码无**
原始方案设计了年级倒置惩罚（×0.95/0.9/0.5/0.3，<0.6 降级候选）。代码中无任何年级/学段惩罚逻辑。影响："低年级学高年级知识点"的倒置场景没有惩罚兜底。

**断点续传方案有/代码无**
原始方案要求任务锁 + `--resume` 断点续传。CLI 无 `--resume` 参数。影响：推断中途失败需整段重跑，长任务不友好（本任务成本低，影响有限）。

**三来源融合半落地**
原始方案要求教材顺序+定义依赖+LLM 多证据融合产出最终文件。融合方法已实现，但 CLI 只产 LLM 原始结果、从不调融合，最终文件无生产方。影响：多证据融合的增强效果（重合升级、multi_evidence 标记）在实际产物里看不到，DAG 校验只能对着单来源结果跑。

**TEACHES_BEFORE≠PREREQUISITE（✅落地）**
设计上严格区分教学顺序与学习前置。代码确实让教材顺序只产 TEACHES_BEFORE（章节内、置信度 1.0），LLM 产 PREREQUISITE。但该能力未接入主流程——独立方法存在、主流程不调用。影响：区分口径落地，但教材顺序这一弱证据实际没进入产物。

**DAG 默认输入契约断裂**
DAG 校验默认读最终融合文件。但没有任何脚本产出该文件，直接跑会文件不存在报错，需 `--input` 指定。影响：推断与校验两个环节衔接断裂，靠手动指定输入桥接，全自动链路不成立。

**候选对生成注释如实（✅落地）**
注释自称"简化版本，应基于启发式规则筛选候选对（同章节/同类型/有相关关系）"。实际实现就是按标签排序前后±5 邻居配对。影响：候选对质量依赖排序邻近假设，非启发式精确筛选，召回质量有上限。

**成本估算失真**
注释假设每个知识点平均 2 个潜在前置。实际配对约 10N 对，成本预估偏低约 5 倍。影响：成本预估偏乐观，实际模型调用量约为预估 5 倍（好在单次成本极低，整体仍可接受）。
