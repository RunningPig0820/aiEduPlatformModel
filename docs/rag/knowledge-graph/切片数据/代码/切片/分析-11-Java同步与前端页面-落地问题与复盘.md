## 隐性坑与注意事项

1. **graph 接口未实现**：前端原计划用知识点图谱关系接口，但 design 文档标注"后端当前未实现此接口"，替代方案待确认（补接口 / 批量关系接口自建 / 其他接口组合）。
2. **路径前缀不一致**：后端 design 写 `/api/kg/**`，前端 design 全部用 `/api/auth/kg/**` 前缀——两者口径未对齐，联调易 404。
3. **首次下拉为空**：年级下拉数据来自教材表的 DISTINCT 年级，必须先做一次全量同步才有数据。
4. **关联表重建有窗口**：同步先 DELETE 再 INSERT 关联表，依赖单事务保证前端看不到中间态；若事务失效会重现"空目录"联调问题。
5. **deleted 数据膨胀**：status='deleted' 的软删除数据会累积，定期物理清理需先确认无下游引用。
6. **URI 主键性能**：<1 万节点用 VARCHAR(255) 主键可行，节点暴涨才考虑换整型代理键。

## 方案 vs 落地的复盘（原始设计 → 实际状态 → 影响）

**Java/前端代码是否落地：无法核实（非代码真值）**
语雀 D13/D14 描述了页面化落地，但代码实际不在本仓（aiEduPlatform/aiEduPlatformFront 不存在），仅有 design 文档——面试/对账时不能把设计当已实现。

**图谱 graph 接口契约：契约断裂（design 内自相矛盾）**
后端 design 列出了知识点图谱关系接口，前端 design 却标注该接口后端未实现——同一份方案库内部口径冲突，落地前必须确认补接口还是换组合。

**API 前缀口径：口径不一致**
后端写 `/api/kg/**`、前端写 `/api/auth/kg/**`，两端约定未对齐，联调极易 404。

**8 张表：文档层面一致**
语雀 D13 描述"4 节点主表+3 层级关联+1 同步记录"，后端 design 的表结构与状态机与之完全一致。

**双数据源：文档层面一致**
语雀 D14 的 `@DS("kg")` 路由 ai_edu_kg，与后端 datasource design 的全链路设计一致。

**前端三栏/懒加载/React Flow：文档层面一致**
前端 design 的三栏布局、逐级懒加载、React Flow 关系图目标与方案口径一致。

**Flyway 迁移：设计降级**
设计为双库分组管理，实际落地是 Flyway 当前全禁用、表手动创建——自动化迁移被降级为人工建表。
