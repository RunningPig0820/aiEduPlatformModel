# 切片数据 / 代码 处理方案

1. **源头就绪**：`3.代码/分析-01~10.md`（10 份，权威 0.8，8 节结构）
2. **开发向切片**：`提示词/切片-开发向-提示词.md` —— 每份语义合并 3 块（业务链路/代码事实/坑与对账），**保留全部代码证据**（文件:行号/API/枚举表），`target: 开发对账`
3. **面试向切片**：`提示词/切片-分组-提示词.md` —— 每份语义合并 3 块（业务与流程/架构与技术取舍/落地问题与复盘），**过滤代码噪声转述**，`target: 面试项目问答`
4. 双切片全落 `切片/`，靠文件名（面试向带块名后缀）+ target 区分；每块带证据指针（可回源 分析-0X / 完善文档 0X）
5. 入桶：COS路径 `rag-slices/knowledge-graph/代码/...`（面试向 `rag-slices/interview/knowledge-graph/...`），`doc_type=code_analysis`，权威 0.8

> 与 question-analysis 同构：代码层双切片（开发 3 块 + 面试向 3 块/每份）用 `切片-开发向-提示词.md` + `切片-分组-提示词.md`（改模块 id / 源路径 / 块名表）。
