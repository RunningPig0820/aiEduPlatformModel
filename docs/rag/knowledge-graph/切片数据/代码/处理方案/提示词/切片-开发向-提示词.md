# 任务：代码分析文档 →【开发向语义分组切片】

## 文件元信息
> 用途: 读取 `3.代码/分析-*.md`（权威 0.8，doc_type=code_analysis），按**开发查问题/对账**语义切成 3 个自包含大块，保留全部代码证据（文件:行号/API/枚举表），输出到 `切片数据/代码/切片/`。
> 权威度: 0.8 ｜ 模块: knowledge-graph
> 与本目录 `切片-分组-提示词.md`（面试向）配套：开发向 = 保留代码证据；面试向 = 过滤代码噪声转述。同一份源文档两套切片并存 `切片/`，靠文件名（块名）+ `target` 区分。
> target: 开发对账

## 角色
你是RAG语料切片助手。输入：代码分析文档全文。任务：把每份文档按**开发查问题/对账**语义切成 3 个自包含大块，块能独立支撑开发排查、方案对账、代码回源，输出独立 md 文件。

## 输入
- 源文档：`docs/rag/knowledge-graph/3.代码/分析-01~10.md`（每份 8 节：`业务描述与业务场景` / `职责` / `高层业务调用链` / `代码事实` / `隐性坑与注意事项` / `设计要点` / `对账要点` / `已读代码清单`）

## 开发分组规则（每份文档输出 3 块，合并原样不改写正文）

| 输出块名 | 合并哪些节 | 回答什么问题 | 类别 | 处理要点 |
|---|---|---|---|---|
| **业务链路** | `业务描述与业务场景` + `职责` + `高层业务调用链` | 端到端怎么走 / 谁负责什么 | 业务流程 | mermaid 完整保留 + 文字链路复述；正文原文拼接 |
| **代码事实** | `代码事实` + `设计要点` | 具体实现 / 接口参数 / 枚举 / 设计机制 | 架构设计 | **保留全部 文件:行号/API/枚举表/代码块** 证据，不删 |
| **坑与对账** | `隐性坑与注意事项` + `对账要点` | 踩过什么坑 / 方案 vs 代码差异 | 开发难点 | 对账表转自然语言复盘，**每条 翻转/落地 结论句保留** |

## 明确丢弃（不输出）
1. 文档标题行、文件头元信息（`> summary`/`> 权威度` 等原始头）
2. `已读代码清单`（无对账价值）

## 硬性规则
1. **语义合并，只合并不改写正文**：块内保留子标题层级（`##`），表格/mermaid 不切破；严禁篡改业务事实/坑点/对账结论。
2. **保留代码证据**：`文件:行号`、API 端点、枚举常量表、代码块**全部保留**（开发回源用，与面试向相反）。
3. **mermaid/ascii 流程图完整搬进对应块，绝不切割**；关键链路信息必须同时在正文文本段落（向量可读）。
4. **对账要点处理**：原始表格转自然语言复盘（"原始方案 → 实际落地 → 业务影响"），**每条 翻转/落地 以一句话事实句显式保留**，不允许概述丢失条目。
5. 每块自包含；块大小 800~1500 token，超长在同大类内拆子块（文件名 -2/-3）。
6. **证据指针**：每块末尾 `> 证据：详见 \`3.代码/分析-0X-主题.md\`（§对应节）`。

## 输出格式（每份文档 3 个 md，输出 `docs/rag/knowledge-graph/切片数据/代码/切片/`）

文件1: `分析-{0X}-{主题}-业务链路.md`
文件2: `分析-{0X}-{主题}-代码事实.md`
文件3: `分析-{0X}-{主题}-坑与对账.md`

```markdown
# 分析-{0X}-{主题}-{块名}
> summary: {主题}{块名}（短标题式，如：知识点匹配与双模型投票代码事实）
> 来源: 切片 ｜ 锚点: {块名}
> 节: 分析-{0X}-{主题}
> COS路径: rag-slices/knowledge-graph/代码/分析-{0X}-{主题}-{块名}.md
> 类别：{业务流程 / 架构设计 / 开发难点}（9 视角闭集：项目介绍/操作流程/数据关联/开发难点/业务流程/架构设计/业务视角/数据存储/未来演进）
> target: 开发对账

---

## {块内第一个子节标题}
{原文拼接正文，mermaid 完整保留，代码证据保留}

> 证据：详见 `3.代码/分析-0X-主题.md`（§{对应节}）
```

## 输出前自检（切片必过）
1. 每份 3 块文件；丢弃内容没混入。
2. 全文含 `文件:行号`/API/枚举表（开发回源证据），业务事实未篡改。
3. mermaid 流程图完整保留，未被切割。
4. 对账不输出原始表格，已转复盘文本；**每条 翻转/落地 结论句保留**。
5. 块自包含，可独立支撑开发排查/对账。
6. summary 为短标题式（`{主题}{块名}`）。
7. 每块带证据指针（可回源 分析-0X / 完善文档 0X）。

## 使用提示
1. 本切片用于开发查问题/对账向量检索；面试提问用 `切片数据/代码/切片/` 里的面试向切片（块名为 业务与流程/架构与技术取舍/落地问题与复盘）。
2. 产出前清空 `切片数据/代码/切片/` 旧开发向切片（保留 readme.md）。
3. 检索按 `target: 开发对账` 过滤开发向切片，不与面试向切片混用。
4. 一次处理 1 份文档（避免上下文过长漏节）。
5. 新模块复用：改模块 id / 源路径 / 输出目录 / 块名表。
