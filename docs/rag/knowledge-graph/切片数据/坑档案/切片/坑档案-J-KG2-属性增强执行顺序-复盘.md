## 坑点复盘
**现象**：教材知识点文件里 1350 个知识点只有 299 个带难度/重要性/认知水平/专题属性，覆盖率仅 22%，大量知识点在教学属性面板上显示为默认值/缺失。

**触发链路**：数据加工管道按顺序执行——先对已有 299 个知识点做属性增强，再用 LLM 推断出 1052 个缺失知识点，最后合并成 1350 个；属性增强只跑在第一步，后生成的推断知识点从没经过属性增强。

**根因**：执行顺序错误——属性增强作为独立步骤先跑，天然覆盖不到后生成的推断知识点；属性推断器只遍历传入的知识点列表，不会自愈补跑。

**解决思路与权衡**：对全部 1350 个知识点重新跑属性增强并强制覆盖，再合并回主文件。属性推断是纯规则（无 LLM），重跑成本低，所以能用"重跑 + 覆盖"低成本修复。

## 面试口述要点
管道化数据加工最典型的坑是步骤依赖顺序被隐式假设——属性增强依赖"所有知识点已生成"，但生成被拆成"先规则后 LLM 两批"，顺序写错就漏掉一批。教训是：规则类步骤要设计成可强制重跑的幂等操作，发现覆盖率不对能低成本补；同时把步骤间前置关系显式写进编排脚本，而不是靠人脑记。
