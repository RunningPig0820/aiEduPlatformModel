## 坑点复盘
**现象**：每次跑知识点匹配脚本都要等约 60 秒加载本地 embedding 模型、预计算图谱所有概念向量，进程内存冲到约 3.5GB；反复跑同一批数据，同样的重活每次都做，浪费严重。

**触发链路**：匹配脚本启动时初始化向量检索器 → 默认懒加载模式：加载 BAAI/bge-small-zh-v1.5 模型并 encode 全部图谱概念向量（1295+ 条、维度 512）。

**根因**：懒加载模式下每次运行都做"模型加载 + 向量全量重算"，而同一份图谱数据在多次匹配之间并没有变化，属于重复计算——encode 全量 + 内存常驻，所以启动约 60s、内存约 3.5GB。

**解决思路与权衡**：把重活沉淀成离线产物——用一次性脚本预构建索引落盘（向量文件 + 概念清单 + 元信息），运行期只读文件、只对查询做编码，内存降到约 10MB、启动 <5ms；同时用 checksum 把索引与它依赖的 Neo4j 数据快照绑定，数据一变就告警"索引已过期"，回退懒加载或强制重建，避免拿过期索引静默算错。

## 面试口述要点
可重复计算要缓存到"结果"而不只是"过程"——把"模型加载 + 向量全量编码"这种重活做成离线产物，运行期只读文件。3.5GB→10MB 不是模型变小了，而是把预计算结果落盘、运行期只保留查询编码。checksum 解决的是缓存一致性：索引必须和它依赖的数据快照绑定，数据变了要么重建要么回退，不能拿过期索引静默算错。还可以讲"索引维度 512 固定、建好不可改"的连带约束。
