**1. 问题现象**："加法交换律""加法结合律"被精确匹配到图谱里的"加法"概念，匹配结果语义错误——把上位概念当下位概念用。

**2. 触发流程**：`exact_match` 先 `_expand_with_synonyms` 扩展同义词 → 修前用 `key in name`（子串包含）判断 → "加法交换律"包含"加法"，命中 `SYNONYM_MAP["加法"]` 扩展出 ["加法","加","加法运算"...] → 精确匹配到"加法"。

**3. 根因分析**：**子串匹配做同义词扩展**——`problems_and_solutions.md` §四记录："原方案使用 `key in name` 进行同义词扩展，导致过度匹配；'加法交换律'不应等同于'加法'"。扩展出的短词污染了匹配集，把具体的定律匹配到抽象运算概念。

**4. 排查过程**：抽查精确匹配结果发现一批"XX律/XX定理"都落到了短概念上；对照 SYNONYM_MAP 看是 `in` 子串命中。

**5. 解决方案 & 改动点**：改为**完整词匹配**：`kp_matcher._expand_with_synonyms`（`kp_matcher.py:541-573`）只用 `normalized_name == normalized_key`（完全相等）才扩展同义词，反向查找也要求全等（`:564-570`）；注释明写"只在精确匹配时使用完整词匹配，避免'加法交换律'匹配到'加法'"（`kp_matcher.py:545-547`）。提交：`126d210 [知识图谱]-[添加 sentence-transformers 模型]`（SYNONYM_MAP + problems 文档 §四）。

**6. 面试口述要点**：词典/同义词扩展的经典坑——**用子串包含做等价扩展**会把"含关键词的组合词"误当成"关键词本身"。等价比对必须全等，组合词交给向量/LLM 语义层去处理，规则层只处理"字面等价"。这是"规则匹配要保守、语义匹配才激进"的分工原则。
