**核心结论**：知识图谱是"答疑/掌握度/学习路径"的知识底座——一张"教材结构 + 概念语义"两层互连的结构图，支撑 AI 答疑知识点定位与前置回顾、掌握度薄弱根因诊断、学习路径推荐、GraphRAG 与图谱页面浏览。

## 分层展开
- **角色定位**：不是扁平的知识点标签表，而是一张"知识点之间如何关联"的结构图，回答"这个题考哪个知识点、这个知识点前置是什么"这类问题（依据：完善文档 01 为什么）
- **两层结构**：教材结构层（Textbook/Chapter/Section/TextbookKP 教学真值）+ 语义层（EduKG Concept/Statement/Class 概念），两层靠 MATCHES_KG 匹配连接（TextbookKP→Concept，1690 条，置信度≥0.5）（依据：完善文档 01 / 分析-01）
- **支撑能力**：AI 答疑知识点点亮与前置回顾、掌握度沿前置链诊断薄弱根因、学习路径推荐、图谱页面浏览，并作为模块锚点接入 RAG 检索（依据：完善文档 01 追问与防御 / 分析-01）
- **消费现状（落地差异）**：Python 桥知识树/学习路径/推荐是简化桩，真实消费在 Java 同步 MySQL + 前端页面侧；在线查询统一 `MATCH (e:Entity)` 而离线导入用具体标签，联调前直接调 `/entities`、`/tree` 可能查不到离线数据（依据：完善文档 01 落地真相 / 分析-01）

## 追问防御
- **可能追问：图谱是不是摆设？真用上了吗？** → 不是。它支撑答疑知识点识别与前置回顾、掌握度薄弱根因诊断、学习路径推荐、页面化浏览，并作为模块锚点接入 RAG 检索；Python 桥知识树/学习路径是简化桩，真实消费在 Java 同步 MySQL + 前端页面侧（依据：完善文档 01 追问与防御）
- **可能追问：图谱在线查询查不到导入的节点怎么办？** → 这是真实运维坑：在线 service.py 统一用 `:Entity` 标签，离线 import 脚本用 Textbook/Concept 等具体标签，标签体系可能不匹配——要么 `Entity` 由 Java 通过 api/neo4j.py 动态建，要么查询是"期望面"而非"实际数据面"，联调前必须对齐（依据：完善文档 01 / 分析-01 隐性坑）
