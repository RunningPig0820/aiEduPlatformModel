# 数据入库前有几道质量防线？每道防线做什么？

**核心结论**：四道质量防线：解析生成（统一结构）→ 清洗（DataCleaner，"通用"标签复用 88 组/序号→order_in_book/全角→半角）→ 增强（属性纯规则不用 LLM）→ 过滤（数学活动/复习题/例\d 不建点）。

## 分层展开
- **第一道·解析生成**：教材 JSON → 统一结构节点/关系 JSON（textbooks/chapters/sections/textbook_kps），先确立统一结构再谈质量（依据：完善文档 02 关键设计 / 落地真相表）
- **第二道·清洗**：DataCleaner 处理"通用"标签复用 88 组、序号前缀→order_in_book、全角→半角；`--clean` 强制先 `--analyze` 出报告（duplicate_detection_report.json）人工确认才执行，防脚本误删教材结构（依据：完善文档 02 关键设计 / 引导问题.md 操作流程可能防御）
- **第三道·增强**：属性增强（difficulty 1-5/importance/cognitive_level/topic 继承章节）**纯规则不用 LLM**——属性客观可枚举、快、可复现、不编造（依据：完善文档 02 关键设计 / 引导问题.md 操作流程）
- **第四道·过滤**：数学活动/复习题/`例\d` 不建点（依据：完善文档 02 关键设计）
- **顺序要求**：增强必须在 LLM 推断**之后**跑——早期先增强只覆盖 22%，修复为推断后重跑补 1052 个（依据：完善文档 02 隐性坑② / 坑档案 J-KG2）

## 追问防御
- **可能追问：为什么增强用规则不用 LLM？** → 属性客观可枚举，规则快、可复现、不编造；规则步骤可 `--force` 幂等重跑，发现覆盖率不对能低成本补（依据：引导问题.md 操作流程 / 坑档案 J-KG2 口述要点）
- **可能追问：清洗会不会误删？** → `--clean` 强制先 `--analyze` 出报告人工确认才执行，防脚本误删教材结构（依据：引导问题.md 操作流程可能防御）
