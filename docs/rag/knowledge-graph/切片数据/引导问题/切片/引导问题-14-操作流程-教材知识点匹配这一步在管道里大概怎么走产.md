**核心结论**：教材知识点经"标准化精确匹配（LLM 标准化预处理 + 同义词完整词匹配）→ bge 向量粗筛 top-20 → 双模型投票（DS=0.6/GLM=0.4/阈值 0.5，DeepSeek 否决）"三段式落到 EduKG Concept，产出 matches_kg_relations.json（1905 条 = exact 1639 + llm_vote 208 + candidate_review 50 + none 8）。

## 分层展开
- **管道位置**：Phase2 匹配阶段，`build_vector_index.py` → `normalize_textbook_kp.py` → `match_textbook_kp.py`（依据：完善文档 02 / 分析-01）
- **三段式匹配**：①标准化精确匹配兜确定性（LLM 把教材名标准化成概念名 + 同义词**完整词匹配**）；②bge 向量粗筛 top-20 压候选；③只有拿不准的交双模型投票；相似度 <0.5 跳过、候选上限 3、命中早停（依据：完善文档 02 关键设计 / 坑档案 J-KG5）
- **标准化是关键**：LLM 标准化预处理把"教学名"翻译成"图谱概念名"（"1-5 的认识"→"自然数"），是匹配率从 17% 提到 97% 的关键——瓶颈不是投票模型不强，是输入与候选语义空间不一致（依据：坑档案 J-KG1 / 完善文档 01）
- **投票规则**：两模型一致采纳取平均；不一致加权 DS=0.6/GLM=0.4/阈值 0.5，只有 DeepSeek=True 才过线（DeepSeek 否决），置信度=胜者×0.7（依据：完善文档 02 落地真相 / 分析-07 口径参考 / 坑档案 J-KG6）
- **产出文件**：`matches_kg_relations.json`，1905 条 = exact 1639 + llm_vote 208 + candidate_review 50 + none 8；`method` 字段标记匹配来源（exact/llm_vote/candidate_review/none）（依据：完善文档 02 落地真相表）
- **评审系统（未落地）**：未匹配 50 条 `candidate_review` 目前**没有线上审核闭环**——design D16 规划的匹配评审系统（MySQL 审核表 + `/api/kp-match/recommend` + 审核后导入）在代码中无对应实现，属规划非已上线功能（依据：完善文档 02 局部翻转）

## 追问防御
- **可能追问：产出里为什么有 exact/llm_vote/candidate_review？** → method 字段标记匹配来源：exact 是确定性精确匹配、llm_vote 是双模型投票产出、candidate_review 是拿不准留人工审核、none 是未匹配不硬连（依据：引导问题.md 操作流程 / 完善文档 02）
- **可能追问：匹配失败怎么办？** → 不硬连（阈值 0.5 不过不建 MATCHES_KG），记 candidate_review 留人工；如实说明评审系统未落地，审核闭环是规划非已上线（依据：引导问题.md 操作流程可能防御 / 完善文档 02）
