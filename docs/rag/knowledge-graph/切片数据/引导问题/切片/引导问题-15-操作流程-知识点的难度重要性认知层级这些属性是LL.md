**核心结论**：规则算的——`enhance_kp_attributes.py` 的 KPAttributeInferer 纯规则推断（difficulty 1-5/importance/cognitive_level/topic 继承章节），不用 LLM；因为属性客观可枚举、快、可复现、不编造。

## 分层展开
- **规则实现**：KPAttributeInferer 纯规则推断 difficulty 1-5 / importance / cognitive_level / topic（topic 继承章节），脚本 `enhance_kp_attributes.py`（依据：完善文档 02 落地真相表 / 关键设计）
- **为什么不用 LLM**：属性客观可枚举，规则快、可复现、不编造——这是与缺失知识点推断（LLM 补 1052 个）分工不同的原因（依据：引导问题.md 操作流程 / 完善文档 02 关键设计）
- **顺序坑（⚠️ 落地教训）**：必须"先 LLM 推断后增强"——早期增强跑在推断前，新增 1052 个知识点全没属性、覆盖率仅 22%，靠 `--force` 幂等重跑补齐（依据：坑档案 J-KG2 / 完善文档 02 隐性坑②）
- **topic 继承坑（⚠️ 落地教训）**：topic 继承章节会错——"加法"在"位置"章被标成"图形与几何"，靠匹配 Concept 的 Class 类型修正 144 个；该修正是按批数据一次性修正，未固化进属性推断代码，重跑会退回章节继承（依据：坑档案 J-KG3 / 完善文档 02 隐性坑③）

## 追问防御
- **可能追问：为什么增强用规则不用 LLM？** → 属性客观可枚举，规则快、可复现、不编造；规则类步骤可 `--force` 幂等重跑，发现覆盖率不对能低成本补（依据：引导问题.md 操作流程 / 坑档案 J-KG2 口述要点）
- **可能追问：topic 还会错吗？** → 当前代码默认仍是章节 topic 继承，Class 修正是数据级一次性修正未固化进代码——重跑属性增强会退回章节继承，这是"数据级修正未落到代码"的教训（依据：坑档案 J-KG3 / 完善文档 02 隐性坑③）
