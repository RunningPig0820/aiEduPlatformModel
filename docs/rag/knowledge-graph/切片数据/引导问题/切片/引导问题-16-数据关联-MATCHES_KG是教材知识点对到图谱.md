# MATCHES_KG 是教材知识点对到图谱概念的连接，它怎么保证对得准？方向和置信度有什么约束？
> summary: 数据关联引导问题回答：MATCHES_KG 靠 LLM 标准化预处理 + 三段式匹配 + 双模型加权投票保证对得准，方向固定 TextbookKP→Concept、置信度≥0.5 才建、投票<0.7 丢候选待人工

**核心结论**：MATCHES_KG 是教材知识点（TextbookKP）→ 图谱概念（Concept）的匹配关系，靠"匹配前 LLM 标准化预处理 + 三段式匹配（精确→向量粗筛→双模型投票）"保证对得准；方向固定 TextbookKP→Concept，置信度≥0.5 才建 MATCHES_KG（不硬连）、投票<0.7 丢候选待人工。

## 分层展开
- **标准化预处理解决"对不准"根因**：匹配前先用 LLM 把教学名翻译成抽象概念（"1-5 的认识"→["数的认识","自然数","数字"]），best_match 作向量检索 query——解决 17% 根因：抽象层级错位，69.6% 小学教材名是具体教学名、EduKG 是抽象概念（依据：完善文档 05 / 坑档案 J-KG1）。
- **三段式匹配（对得准的主体机制）**：①精确匹配（标准化+同义词完整词匹配），命中→confidence=1.0、method=exact_match，覆盖约 86%；②未命中→向量粗筛 bge-small-zh-v1.5 512 维取 top-20 候选；③top-20 中相似度≥0.5 的候选进双模型投票（依据：完善文档 05 / 分析-07）。
- **双模型投票抑制单模型幻觉**：GLM-4-flash + DeepSeek 并行，两模型一致→采纳取平均置信度；不一致→加权 WEIGHT_DS=0.6/GLM=0.4/THRESHOLD=0.5，只有 DeepSeek=True 才可能过线（DS 一票否决），采纳时置信度×0.7 打折（依据：完善文档 05 / 分析-07 / 坑档案 J-KG6）。
- **方向与置信度约束**：方向固定 TextbookKP→Concept；THRESHOLD=0.5 不过不创建 MATCHES_KG 硬连接；投票<0.7 丢弃进 candidate_review 待人工；当前数据 1905 条 = exact_match 1639 + llm_vote 208，匹配率 96.96%、平均置信 0.973（依据：完善文档 05 / 分析-07）。
- **口径提醒（翻转）**："投票<0.7 丢弃"是 design/面试口径，代码主链路实际过线阈值是加权 THRESHOLD=0.5；匹配率 97.1% 是 1690/1740 早期里程碑，当前 1905 基线是 96.96%；缓存键是 SHA256(prompt)[:16] 不是 md5（依据：完善文档 05 / 分析-07）。

## 追问防御
- **可能追问：匹配率 97.1% 是真的吗？** → 两个口径：97.1% 是 1690/1740 早期里程碑，当前数据文件 1905 条基线匹配率 96.96%、平均置信 0.973——对外讲"~97%"准确，精确数字必须带基线（依据：完善文档 04 / 分析-07）。
- **可能追问：剩下的 3% 怎么处理？** → 不硬连——不过阈值不建 MATCHES_KG，未匹配记 candidate_review（保留 best_candidate）留人工；当前 58 个未匹配（candidate_review 50 + none 8），非语雀的 308（不同批次）（依据：完善文档 05 / 分析-07）。
- **可能追问：匹配评审系统上线了吗？** → 没有——D16 的 MySQL 审核表 textbook_kp_match_review + /api/kp-match/recommend + 审核导入均无代码实现，唯一痕迹是 method='candidate_review' 的 best_candidate 记录字段，审核闭环是规划非已上线（依据：完善文档 05 / 分析-07）。
