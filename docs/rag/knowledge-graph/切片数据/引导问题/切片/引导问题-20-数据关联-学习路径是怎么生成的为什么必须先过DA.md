# 学习路径是怎么生成的？为什么必须先过 DAG 环检测？

**核心结论**：学习路径基于 PREREQUISITE 前置依赖关系生成——Cypher `[:PREREQUISITE*..10]` 沿链查询、控深≤10，离线预计算 prerequisite_level 优化；必须先过 DAG 无环验证（validate_dag.py DFS 环检测），否则会出现"A 前置 B、B 前置 A"的死循环路径。

## 分层展开
- **生成方式**：`MATCH path=(start)-[:PREREQUISITE*..10]->(target) RETURN path ORDER BY LENGTH(path)`，沿前置依赖链查询并控制深度≤10（依据：完善文档 06）。
- **性能优化**：离线预计算 prerequisite_level 属性（BFS 最长前置路径），避免每次在线查询重复算链（依据：完善文档 06）。
- **为什么必须过 DAG 环检测**：前置依赖若成环（A 前置 B、B 前置 A），补课顺序会死循环；`validate_dag.py` 用 DFS `detect_cycles` 找环，有环退出码 1、无环退出码 0，退出码 0 才可作路径（依据：分析-08 / 完善文档 06）。
- **知识缺陷诊断联动**：给定"已掌握集合"，沿前置链多跳查未掌握的前置点——业务优先级 P0=前置依赖查询、P1=知识点识别+缺陷诊断、P2=学习路径推荐（依据：完善文档 06）。
- **落地边界（翻转）**：当前前置依赖是 LLM 单路径 + 0.8 分界（三来源融合未接入）；Python 桥 `get_learning_path` 是简化桩，只返回目标实体自身一项，页面化真层级走 Java 同步 MySQL 侧（依据：完善文档 07 / 分析-01）。

## 追问防御
- **可能追问：路径会不会绕死？** → 不会——前置链必须先过 DAG 无环验证（detect_cycles 退出码 0）才可作路径，从根上防死循环（依据：完善文档 06 / 分析-08）。
- **可能追问：为什么控深≤10？** → 深度受限防路径爆炸；质量目标平均前置链 2-4 跳，实际学习路径不会用到很深的深度（依据：完善文档 06）。
- **可能追问：路径在服务侧真能查吗？** → Python 桥是简化桩（get_learning_path 只返回目标实体自身），页面化/掌握度消费在 Java 侧（kp-matching-lightup，本仓不可核验），要如实讲分层边界（依据：完善文档 07）。
