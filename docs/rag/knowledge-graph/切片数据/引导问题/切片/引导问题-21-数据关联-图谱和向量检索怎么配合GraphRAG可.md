# 图谱和向量检索怎么配合（GraphRAG）？可解释性从哪来？
> summary: 数据关联引导问题回答：向量负责召回、图谱负责解释——向量命中 Concept 后沿 PREREQUISITE/RELATED_TO 扩展邻居成可解释路径；可解释性来自"前置知识点是依据"而非黑盒相似度；但主答疑链路未真接图遍历需如实讲

**核心结论**：GraphRAG 的分工是"向量负责召回、图谱负责解释"——向量命中 Concept（或经 MATCHES_KG 命中教材知识点）→ 沿 PREREQUISITE/RELATED_TO 扩展邻居 → 形成可解释推理路径；可解释性来自"前置知识点是依据"的关系语义，不是黑盒相似度；但主答疑链路未真接图遍历，落地范围要如实讲。

## 分层展开
- **工作流**：学生提问 → 提取核心知识点 → 向量命中 Concept → 沿前置依赖/语义关系扩一到两跳 → 引导式答疑（前置知识点回顾→考点讲解→解题步骤引导→易错点提醒）（依据：完善文档 07）。
- **向量侧落地**：匹配侧 bge-small-zh-v1.5 本地 512 维离线粗筛（kg_vectors.npy 1295×512 + checksum 校验）；服务侧 dashscope text-embedding-v3 768 维在线 RAG，写 COS 向量桶（put 后约 10s 异步生效）——"向量召回"能力是真实代码（依据：完善文档 07 / 分析-09）。
- **图谱侧落地**：PREREQUISITE（双模型投票一致且≥0.8 落正式、<0.8 落候选）、RELATED_TO（Concept/Statement 语义关联）已由 import 脚本 MERGE 导入 Neo4j，是学习路径/缺陷诊断的数据基础（依据：完善文档 07 / 分析-08）。
- **可解释性来源**：路径由前置依赖关系构成，不是黑盒相似度——PREREQUISITE 带置信度（≥0.8 才落正式），双模型投票每对带 reason（primary/secondary_reason）可回溯（依据：完善文档 07）。
- **落地边界（最大翻转）**："向量命中→沿关系扩展邻居→可解释路径"在**主答疑链路未真接图遍历**——Python 桥 get_knowledge_tree/get_learning_path/get_recommendations 是简化桩（学习路径只返回目标实体自身一项）；core/rag/query.py 检索的是图谱文档切片不是 Neo4j 节点；点亮/掌握度联动在 Java 侧（kp-matching-lightup）本仓不可核验（依据：完善文档 07 / 分析-01）。

## 追问防御
- **可能追问：GraphRAG 算落地了吗？** → 分层如实：向量索引 + 前置依赖入库 + Python 桥接口是本仓可核验的真实落地；"邻居扩展/可解释路径"是设计目标 + 部分桩实现，Java 侧不可核验（依据：完善文档 07）。
- **可能追问：路径为什么能解释？** → 因为路径由前置依赖关系构成，每对带置信度和 reason，沿关系往回找（"分数除法学不懂→前置分数乘法/倒数"），依据是"前置知识点"的关系语义，不是相似度排序（依据：完善文档 07）。
- **可能追问：两套 embedding 维度不同不冲突吗？** → 各司其职：匹配侧 bge 512 离线粗筛、服务侧 dashscope 768 在线 RAG，维度固定不可混用，路由靠 vector_type 区分（依据：完善文档 05 / 分析-09）。
