# 掌握度诊断是怎么沿前置链定位薄弱点的？"当前点没掌握 vs 前置没学好"怎么区分？

**核心结论**：掌握度诊断链路是"错题→对应知识点→沿 PREREQUISITE 前置链多跳查未掌握的前置点→结合正确率/答题次数算掌握度→定位薄弱根因"；区分"当前点没掌握 vs 前置没学好"靠沿前置链检查已掌握集合里哪个前置点缺失——前置缺失就先补前置，前置齐了才是当前点本身的问题。

## 分层展开
- **诊断链路**：错题 → 对应知识点 → 前置链 → 结合正确率/答题次数算掌握度 → 定位"当前点没掌握 vs 前置没学好"（依据：完善文档 07 / 引导问题.md 5）。
- **诊断依据**：PREREQUISITE 前置链 + RELATED_TO 语义关联——错题对应知识点后，沿链往回查依赖哪些前置（依据：引导问题.md 5）。
- **缺陷诊断算法**：给定"已掌握集合"，沿前置链多跳查未掌握的前置点；业务优先级 P0=前置依赖查询、P1=知识点识别+缺陷诊断、P2=学习路径推荐（依据：完善文档 06）。
- **"当前点 vs 前置"的区分逻辑**：沿链查已掌握集合——若某个前置点缺失，说明薄弱根因在前置没学好，应优先补前置；前置全齐但当前点掌握度仍低，才是当前点本身没掌握（依据：完善文档 06 / 引导问题.md 5）。
- **落地边界（翻转）**：掌握度/点亮消费属 Java 侧 kp-matching-lightup（派生层 3 表存 MySQL、权威图谱零写入），本仓不可核验，如实标注设计口径；Python 桥 get_recommendations 只看一跳邻居，不是方案说的沿 PREREQUISITE 多跳扩展（依据：完善文档 07）。

## 追问防御
- **可能追问：孩子到底是当前点没会还是前置没会？** → 沿前置链查"已掌握集合"缺哪个前置——前置缺失则薄弱根因在前置（先补前置），前置齐则问题在当前点本身；这是 P1 缺陷诊断的定位逻辑（依据：完善文档 06）。
- **可能追问：诊断依据可信吗？** → 前置关系带置信度 + reason（双模型投票产出可回溯）；但当前前置依赖是 LLM 单路径 + 0.8 分界、消费在 Java 侧本仓不可核验，要如实讲（依据：完善文档 06 / 分析-08）。
- **可能追问：掌握度数值可靠吗？** → 事件驱动可追溯：错题→知识点→前置链→正确率/次数算出，非拍脑袋；权威图谱零写入，派生信号只存 MySQL（依据：引导问题.md 7 / 完善文档 07）。
