# 前置依赖设计上说了"三来源融合"，现在主链路真的融合了吗？

> 类别：数据关联

**核心结论**：没有真正融合。`fuse_results` 三来源融合方法完整实现（教材顺序/定义依赖/LLM 投票）但**主链路未接入**——CLI 只产 llm_prereq.json，final_prereq.json 无任何脚本生产，当前前置依赖实际是"LLM 双模型投票 + 0.8 单阈值"单路径。

## 分层展开
- **设计口径**：三来源 = 教材顺序（权重 0.7，只产 TEACHES_BEFORE）+ LLM 双模型（0.8）+ 教师标注（1.0，demo 不做）+ 定义/定理依赖（0.85，代码实际 0.9）；融合产物 final_prereq.json → validate_dag（依据：完善文档 06）。
- **fuse_results 方法已实现**：按 (kp_a_uri, kp_b_uri) 去重；定义依赖标记 DEFINITION_DEP、与 TEACHES_BEFORE 重合升级 PREREQUISITE(0.9)；LLM 结果与已有前置重合升级 PREREQUISITE、置信度 min(已有+0.1, 1.0)、source=multi_evidence——方法完整存在（prerequisite_inferer.py:261-336）（依据：分析-08 / 完善文档 06）。
- **主链路未接入**：infer_prerequisites.py 主流程只调 infer_batch → save_results(LLM_PREREQ_FILE)，**从不调** infer_from_textbook_order / extract_from_definition / fuse_results（依据：分析-08 / 完善文档 06）。
- **后果**：final_prereq.json 无任何脚本产出，直接跑 validate_dag.py（默认读 final_prereq.json）会 FileNotFoundError，需 --input 指定 llm_prereq.json 或先手动融合（依据：分析-08）。
- **其他未落地项**：年级倒置惩罚（×0.95/0.9/0.5/0.3）代码中不存在；CONFIDENCE_THRESHOLD_LOW=0.6 只在未调用的 vote_prerequisite() 里形同虚设；断点续传 --resume 未落地（依据：完善文档 06 / 分析-08）。

## 追问防御
- **可能追问：那现在前置依赖到底怎么来的？** → LLM 单路径：Neo4j 加载 Concept → ±5 邻居配对 → GLM+DeepSeek 双模型投票 → ≥0.8 落 PREREQUISITE、<0.8 落 CANDIDATE → DAG 无环验证（依据：分析-08）。
- **可能追问：面试被问"融合怎么做的"怎么答？** → 如实翻转：融合是语雀 D9 的**设计目标非落地现状**，fuse_results 存在但未挂 CLI；当前是 LLM 单路径 + 0.8 单阈值，讲清设计口径 vs 落地现状本身就是可信度（依据：完善文档 06 / 引导问题.md 3）。
- **可能追问：既然方法写了为什么不接？** → 半落地状态——核心逻辑与 CLI 分离，融合/顺序推断方法未挂到 CLI；语料未说明具体未接入原因，如实表述"设计目标非现状"即可（依据：分析-08）。
