# 匹配率从 17% 提到 97% 关键卡点是什么？为什么说瓶颈不是投票模型不强？
> summary: 开发难点引导问题回答：卡点是语义颗粒度错位——教材名是教学名（"1-5的认识"）、EduKG 是抽象概念（"自然数"），17% 时小学 69.6% 几乎全未匹配；解决靠 LLM 标准化预处理把教材名翻译成概念名，不是换更强模型

**核心结论**：卡点是**语义颗粒度错位**——教材知识点是贴近教学场景的具体名（"1-5 的认识""连加连减"），EduKG 图谱是抽象数学概念（"自然数""减法"），17% 时小学 940 个（占 69.6%）几乎全未匹配；解法是匹配前加 **LLM 标准化预处理**把教材名翻译成概念名，瓶颈不是投票模型不强。

## 分层展开
- **现象**：1350 个教材知识点仅 229 个匹配成功（202 精确 + 27 LLM），1121 个未匹配（83%）——图谱页面大量知识点点不亮（依据：坑档案 J-KG1）。
- **根因**：抽象层级错位——小学 940 个教材知识点是教学场景名（69.6%），EduKG 只有 1295 个抽象概念（函数/方程/几何），几乎没有小学具体知识点；直接用原始教材名去向量检索/LLM 投票，查询词与候选不在同一语义空间（依据：坑档案 J-KG1 / 完善文档 04）。
- **解法（提点关键）**：引入 LLM 标准化预处理 KPNormalizer——把"1-5 的认识"翻译成 ["数的认识","自然数","数字"]，best_match 作向量检索 query，再用标准名走"精确匹配→向量粗筛→双模型投票"（依据：坑档案 J-KG1 / 完善文档 05）。
- **为什么瓶颈不是投票模型不强**：投票模型只判断"候选对不对"，输入名没被翻译成图谱语言时，再强的模型也无从判断——标准化是性价比最高的提点手段（依据：坑档案 J-KG1 / 完善文档 05）。
- **结果**：最终 1905 条基线匹配 1847（exact 1639 + LLM 208）≈ 96.96%，早期里程碑 97.1%（1690/1740）；标准化结果也走缓存（normalizer_cache/）控成本（依据：坑档案 J-KG1 / 完善文档 04）。

## 追问防御
- **可能追问：剩下的 3% 呢？** → 不过阈值不硬连，未匹配记 candidate_review（50）+none（8）留人工；匹配评审系统是规划未上线（依据：完善文档 05 / 分析-07）。
- **可能追问：标准化本身有成本吗？** → 有，但标准化结果走 normalizer_cache/ 缓存，且只对精确匹配未命中的知识点触发（依据：坑档案 J-KG1 / 完善文档 05）。
- **可能追问：为什么不直接换更强的匹配模型？** → 17% 根因是"教材名 ≠ 概念名"的结构错位，不是投票逻辑坏了；先翻译再匹配，比盲目加模型性价比高得多（依据：坑档案 J-KG1）。
