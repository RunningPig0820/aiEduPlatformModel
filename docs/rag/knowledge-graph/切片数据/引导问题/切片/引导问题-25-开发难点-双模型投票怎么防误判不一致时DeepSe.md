# 双模型投票怎么防误判？不一致时 DeepSeek 为什么有否决权？
> summary: 开发难点引导问题回答：两模型一致才采纳抑制单模型幻觉；DeepSeek 更严格（几乎不误报）给 0.6、GLM 宽松给 0.4，等价"DS 同意才过、否决就挂"，把低误报模型意见设成硬约束；不一致通过时置信度×0.7 打折

**核心结论**：双模型投票靠"两模型一致才采纳"抑制单模型幻觉；不一致时按可信度加权——DeepSeek 更严格（几乎不误报）给 0.6、GLM 宽松给 0.4，阈值 0.5 下只有 DeepSeek=True 才可能过线，等价"DeepSeek 同意才过、DeepSeek 否决就挂"；通过时置信度再×0.7 打折，防止仲裁结果冒充高置信。

## 分层展开
- **一致才采纳**：单模型可能自信地错，两模型一致才采纳，两模型一起错的概率低得多——这是防误判的第一道闸（依据：完善文档 05 / 坑档案 J-KG6）。
- **DS 否决权的数学结构**：加权 weighted_score = 0.4×(GLM=True) + 0.6×(DS=True)，THRESHOLD=0.5；0.6+0.4 结构下只有 DS=True 时 weighted_score≥0.5 才成立——DS 一票否决是数学结果，不是显式分支（依据：分析-07 / 坑档案 J-KG6）。
- **为什么 DeepSeek 更严格**：抽查发现 GLM 大多答 True、DeepSeek 答 False，且 DeepSeek 答 True 时往往确实匹配——严格模型的正例可信度高，权重=把低误报模型的意见设成硬约束（依据：坑档案 J-KG6）。
- **置信度打折**：不一致被仲裁通过时 confidence = winner×0.7，标记 vote_type='weighted'，避免"仲裁出来的结果"冒充高置信（依据：分析-07 / 完善文档 05）。
- **口径提醒（翻转）**：`vote_match`/`vote_prerequisite` 是死代码（定义未调用），design 的 0.9/0.7 匹配分档在死代码里未生效；匹配主链路实际走 vote()→_check_consensus→加权 0.5 过线（依据：完善文档 05 / 分析-07）。

## 追问防御
- **可能追问：为什么不 majority vote？** → 只有两个模型，没有多数；加权是最小可行的仲裁，同时把模型质量不对称（DS 更严格）编码进权重（依据：完善文档 05 / 坑档案 J-KG6）。
- **可能追问：不一致全丢弃不行吗？** → 牺牲召回——两模型对语义边界天然有分歧，直接丢把"可仲裁的冲突"当"不可用结果"；加权仲裁在保召回的同时用严格模型压误判（依据：坑档案 J-KG6）。
- **可能追问：加权通过的一定对吗？** → 不一定，但置信度×0.7 打折 + DS 更严格（0.6 权重）把误判压到可接受水平；缓存存完整 vote_result 可审计（依据：分析-07 / 坑档案 J-KG6）。
