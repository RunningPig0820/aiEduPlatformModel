# 图谱数据变了，预构建的向量索引会不会静默失效？怎么兜底？
> summary: 开发难点引导问题回答：会，所以用 checksum 绑定索引与 Neo4j 数据快照——MD5(uri+label 排序拼接) 失配即告警"索引已过期"并回退懒加载/强制重建，宁可回退慢的懒加载也不拿脏索引静默匹配
> 权威度: 1.0（合成问答答案切片，非原始证据）
> 模块: knowledge-graph
> COS路径: rag-slices/knowledge-graph/引导问题/引导问题-27-开发难点-图谱数据变了预构建的向量索引会不会静默失.md
> 类别：开发难点

**核心结论**：会静默失效，所以用 **checksum 把索引与 Neo4j 数据快照绑定**——MD5(uri:label 按 uri 排序拼接) 存进 index_meta.json，匹配启动时实时算指纹比对，失配即告警"索引已过期"并回退懒加载（3.5GB）或 `--force` 重建；宁可回退慢的懒加载，也不拿脏索引静默匹配。

## 分层展开
- **checksum 算法**：`MD5("".join(f"{uri}:{label}" for c in sorted(concepts, key=uri)))`——只含 uri+label，description 变化不影响指纹（vector_index_manager.py:204-218）（依据：分析-09 / 完善文档 04）。
- **校验时机**：匹配启动时 `check_index_validity` 用当前 Neo4j 概念实时算指纹，与 `index_meta.json.neo4j_checksum` 比对（依据：分析-09 / 坑档案 J-KG7）。
- **失配兜底链**：失配→告警"索引已过期"并回退懒加载 LocalVectorRetriever（3.5GB）；懒加载失败→回退 difflib 字符匹配；或显式 `--force-build-index` 重建（依据：分析-09 / 完善文档 04）。
- **服务侧同理**：dashscope 768 维写 COS 向量桶，put 后约 10s 异步生效，紧跟的 query 可能 miss（依据：分析-09）。
- **隐性坑**：checksum 只含 uri+label——只改 description 不会触发过期检测，可能拿到语义旧向量；索引维度 512 建好不可改，换模型/维度必须重建（依据：分析-09）。

## 追问防御
- **可能追问：索引失效最坏会怎样？** → 最坏是回退到慢的懒加载（3.5GB/60s），不会用脏索引静默算错——checksum 失配强制走降级链（依据：完善文档 04 / 分析-09）。
- **可能追问：改了描述为什么不触发重建？** → checksum 只含 uri+label 是当前实现局限，语料未说明后续是否扩展；面试可如实讲"目前 description 变化不触发指纹失配"（依据：分析-09）。
- **可能追问：两套向量混了会怎样？** → 匹配侧 512 维与服务侧 768 维维度不同互不通用，混用会维度报错/语义错位，路由靠 vector_type 区分（依据：引导问题.md 8 / 分析-09）。
