# 同义词扩展出过什么坑？"加法交换律"为什么会匹配到"加法"？
> summary: 开发难点引导问题回答：早期用 `key in name` 子串包含做同义词扩展，"加法交换律"包含"加法"被误扩成"加法"并精确匹配到上位概念；改完整词匹配（全等才扩展），组合词交给向量/LLM 语义层
> 权威度: 1.0（合成问答答案切片，非原始证据）
> 模块: knowledge-graph
> COS路径: rag-slices/knowledge-graph/引导问题/引导问题-30-开发难点-同义词扩展出过什么坑加法交换律为什么会匹.md
> 类别：开发难点

**核心结论**：早期 `_expand_with_synonyms` 用 `key in name`（子串包含）做同义词扩展，导致"加法交换律"包含"加法"被误扩展出 ["加法","加",...] 并精确匹配到上位概念"加法"；改为**完整词匹配**（`normalized_name == normalized_key` 全等才扩展），组合词交给向量/LLM 语义层。

## 分层展开
- **现象**："加法交换律""加法结合律"被精确匹配到图谱里的"加法"概念，把上位概念当下位概念用，匹配结果语义错误（依据：坑档案 J-KG9）。
- **根因**：exact_match 先 `_expand_with_synonyms` 扩展同义词，修前用 `key in name` 子串包含判断——"加法交换律"包含"加法"，命中 SYNONYM_MAP["加法"] 扩展出短词，污染了匹配集（依据：坑档案 J-KG9 / 完善文档 05）。
- **解法**：改完整词匹配——`_expand_with_synonyms` 只在 `normalized_name == normalized_key`（完全相等）时才扩展同义词，反向查找也要求全等；注释明写"避免'加法交换律'匹配到'加法'"（依据：坑档案 J-KG9 / 分析-07）。
- **分工原则**：规则层只处理"字面等价"（完整词匹配），语义模糊的组合词交给向量粗筛 + LLM 双模型投票语义层——"规则匹配要保守、语义匹配才激进"（依据：坑档案 J-KG9）。
- **落地现状**：SYNONYM_MAP 16 组（加法/减法/百分数/三角形等），完整词匹配逻辑真实存在（kp_matcher.py:541-573）（依据：分析-07）。

## 追问防御
- **可能追问：组合词怎么匹配？** → 交给向量粗筛 top-20 + LLM 投票语义层，规则层只处理字面等价（依据：坑档案 J-KG9 / 完善文档 05）。
- **可能追问：等价判断要全等会不会漏匹配？** → 会，但这是有意的保守——宁可少扩展（交给语义层）也不把上位概念当下位概念用（依据：坑档案 J-KG9）。
- **可能追问：这个坑和 17%→97% 有关吗？** → 是匹配质量的一部分：早期子串扩展制造了一批"张冠李戴"的假匹配，修掉后精确匹配才可信（依据：坑档案 J-KG9 / J-KG1）。
