# 图谱在整个业务闭环里怎么转？从数据加工到家长报表完整走一遍？

> summary: 业务流程引导问题回答：数据加工→入库Neo4j→向量索引→答疑点亮→掌握度→学习路径→家长报表环环相扣，消费端信号只存MySQL、权威图零写入

> 模块: knowledge-graph
> COS路径: rag-slices/knowledge-graph/引导问题/引导问题-32-业务流程-图谱在整个业务闭环里怎么转从数据加工到.md
> 类别：业务流程

**核心结论**：端到端链路是「数据加工 → 入库 Neo4j → 向量索引 → 答疑点亮 → 掌握度沿前置链诊断 → 学习路径 → 家长报表」环环相扣；消费端的派生信号只存 MySQL，权威图谱零写入。

## 分层展开
- **端到端闭环全景（文字链路）**：数据加工（TTL/人教版教材爬虫/课标四类来源）→ 入库 Neo4j（两层图谱：教材结构层+语义层，6757 节点/20887 关系，MATCHES_KG 连接两层）→ 向量索引（匹配侧 bge 512 维 / 服务侧 dashscope 768 维）→ AI 答疑/题型命中（实体链接 → MATCHES_KG 命中 Concept → 图谱节点点亮）→ 掌握度（错题→对应知识点→前置依赖链→结合正确率算掌握度→定位薄弱根因）→ 学习路径（PREREQUISITE 前置链 → 补课顺序推荐，Cypher `[:前置依赖*1..2]` 控深）→ 家长报表（掌握度/薄弱点汇总展示，答疑记录回流支撑报表）。（依据：完善文档 09 / 分析-01）
- **图谱在闭环中的角色表**：答疑点亮消费 MATCHES_KG（TextbookKP→Concept，97.1%）；掌握度诊断消费 PREREQUISITE 前置链 + RELATED_TO 语义关联；学习路径消费 PREREQUISITE 前置关系；家长报表消费掌握度+薄弱点，是消费端展示；页面化浏览只读消费教材结构层 6 级导航+点亮状态。（依据：完善文档 09）
- **信号只存 MySQL、权威图零写入**：掌握度/点亮/题型等派生信号物理不写进权威图，Neo4j 只读；派生态解析靠 kp_uri 钩子"借"权威结构。（依据：完善文档 09 / 分析-01）
- **落地边界（最大翻转）**：完整闭环在代码侧是「分段落地 + 多处规划中」——匹配评审审核闭环（D16）是规划非已上线；前置依赖三来源融合未接主链路（实际 LLM 单路径 + 0.8 阈值）；Python 桥的知识树/学习路径是简化桩；掌握度主体翻转与点亮渲染属 Java 侧（代码不在本仓），正文以代码现状为准。（依据：完善文档 09 / 分析-01 / 分析-08 / 分析-11）

## 追问防御
- **可能追问：闭环是不是断的？** → 分段落地 + 多处规划中（融合未接入/审核未上线/桥是简化桩），讲清方案与现状的边界本身就是可信度；已落地的是数据加工→入库→向量索引全链路，以及权威零写入。（依据：完善文档 09）
- **可能追问：图谱价值怎么证明？** → 三层证据：①数据真值（6757 节点/20887 关系/匹配率~97%）；②消费闭环（答疑点亮、掌握度、学习路径三个消费环真实吃图谱关系）；③如实防御（方案与现状边界讲清）。（依据：完善文档 09）
- **可能追问：GraphRAG 在这条链里接哪？** → 设计上是答疑→掌握度→学习路径的推理底座，但服务侧主链路未真接图扩展，落地看 Java/MySQL 侧或后续接 GraphRAG 主链路（详见业务流程第 37 问）。（依据：完善文档 09）
