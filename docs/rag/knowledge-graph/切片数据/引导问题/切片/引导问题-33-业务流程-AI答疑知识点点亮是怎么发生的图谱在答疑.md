# AI 答疑知识点点亮是怎么发生的？图谱在答疑里消费了什么？

> 类别：业务流程

**核心结论**：答疑自由文本标签经 MATCHES_KG（TextbookKP→Concept 软连接）落到有限权威知识点，才能点亮图谱节点；点亮是只读消费、借 kp_uri 零写入，图谱在答疑里消费的就是 MATCHES_KG 这条连接。

## 分层展开
- **点亮机制**：答疑自由文本 → 实体链接/知识点提取 → 落到教材知识点（TextbookKP）→ 经 MATCHES_KG（TextbookKP→Concept，1690 条，置信度≥0.5）命中语义层权威 Concept → 图谱节点点亮。（依据：完善文档 09 / 分析-01）
- **为什么需要 MATCHES_KG**：答疑产出的是"自由文本标签"，而图谱点亮必须落在"有限权威结构"上——MATCHES_KG 就是两者之间的桥，把自由标签锚定到权威概念才能点亮。（依据：完善文档 09）
- **只读消费、零写入**：点亮不写图谱，只读借 kp_uri 钩子"借"权威结构；点亮状态属派生信号，只存 MySQL，物理不污染权威图（决策 D17）。（依据：完善文档 09 / 分析-01）
- **落地边界**：点亮渲染"疑似态"、掌握度主体翻转（题型 topic_key）、解析管线五步等都在 design-backend-kp-matching-lightup（D2/D16/D17），但 Java/前端代码不在本仓，分析-11 明确标注"非代码真值"，只能以 design 口径引用。（依据：完善文档 09 / 分析-11）
- **答疑还消费什么**：答疑沿 PREREQUISITE/RELATED_TO 做前置回顾与引导（GraphRAG 设计），但服务侧主链路未真接图扩展，Python 桥学习路径/知识树是简化桩。（依据：完善文档 09 / 分析-01）

## 追问防御
- **可能追问：点亮写图谱吗？** → 不写，权威图谱零写入——只读借 kp_uri 借权威结构，点亮状态存 MySQL。（依据：完善文档 09）
- **可能追问：点亮在哪一端实现？** → 掌握度主体翻转与点亮渲染属 Java 侧（design 口径），代码不在本仓、非代码真值，如实讲。（依据：完善文档 09 / 分析-11）
- **可能追问：图谱节点没匹配上会怎样？** → MATCHES_KG 置信度<0.5 不硬连，留在图谱外（candidate_review 50 + none 8 留人工，审核闭环是规划未上线）。（依据：完善文档 09 / 完善文档 01）
