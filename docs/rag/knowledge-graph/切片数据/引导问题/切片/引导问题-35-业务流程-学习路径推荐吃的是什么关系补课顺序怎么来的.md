**核心结论**：学习路径推荐吃的是 PREREQUISITE（前置依赖）关系，沿前置链生成补课顺序，Cypher `[:前置依赖*1..2]` 控深 1-2 跳；路径过 DAG 无环验证才可作推荐。

## 分层展开
- **消费的关系**：学习路径吃 PREREQUISITE 前置关系——沿前置链生成补课顺序，这是路径推荐的核心输入。（依据：完善文档 09）
- **控深策略**：Cypher `[:前置依赖*1..2]` 控制深度 1-2 跳，避免路径无限展开。（依据：完善文档 09）
- **可信度**：前置关系带置信度 + reason（primary_reason/secondary_reason），路径过 DAG 无环验证（validate_dag DFS 环检测，有环退出码 1）才可作路径，保证补课顺序无死循环。（依据：完善文档 09 / 分析-08）
- **教学顺序≠学习依赖**：教材章节顺序只生成 TEACHES_BEFORE（章节内 conf=1.0），学习依赖靠 LLM 双模型投票确认产 PREREQUISITE——补课顺序按学习依赖而非教材顺序，更科学（如勾股定理先于圆，学圆不需先学勾股定理）。（依据：完善文档 09 / 分析-08）
- **⚠️ 落地边界**：服务侧 `api/kg.py` 的 `/learning-path` 只返回目标实体自身一项（简化桩，service.py:436-455），真前置链在 Java/MySQL 侧或后续接 GraphRAG 主链路；PREREQUISITE 主链路为 LLM 单路径 + 0.8 阈值，三来源融合未接主链路。（依据：完善文档 09 / 分析-01 / 分析-08）

## 追问防御
- **可能追问：路径会不会绕死？** → 不会——DAG 无环验证保证前置链无环（A 前置 B 且 B 前置 A 会被拦截），退出码 0 才可作路径。（依据：分析-08 / 完善文档 09）
- **可能追问：补课顺序为什么不按教材章节？** → 教材先教≠必须先学（勾股定理先于圆），教学顺序只能作弱证据产 TEACHES_BEFORE，学习依赖靠 LLM 确认，两者严格区分。（依据：完善文档 09 / 分析-08）
- **可能追问：学习路径现在真能生成吗？** → Python 桥 `/learning-path` 是简化桩只返回单点，可解释前置链是设计目标，落地看 Java/MySQL 侧或后续 GraphRAG 主链路，如实讲分层边界。（依据：完善文档 09 / 分析-01）
