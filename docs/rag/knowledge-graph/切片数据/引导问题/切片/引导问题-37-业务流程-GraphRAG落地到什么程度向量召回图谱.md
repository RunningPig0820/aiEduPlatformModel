# GraphRAG 落地到什么程度？"向量召回 + 图谱解释"现在实现了吗？

> summary: 业务流程引导问题回答：分层边界——向量索引+前置依赖入库是真实的，"向量命中→沿关系扩展邻居→可解释路径"在服务侧主链路未真接，Python桥是简化桩

> 类别：业务流程

**核心结论**：分层边界——向量索引 + 前置依赖入库是真实落地的；但"向量命中 Concept → 沿关系扩展邻居 → 可解释推理路径"在服务侧主链路**未真接图扩展**，Python 桥是简化桩，Java 侧不可核验，属于设计目标 + 部分桩实现。

## 分层展开
- **设计目标（GraphRAG 全链路）**：学生提问 → 提取核心知识点 → 向量命中 Concept → 沿 PREREQUISITE/RELATED_TO 扩展邻居 → 生成「前置知识点回顾→考点讲解→解题引导→易错提醒」引导式答疑（Cypher `[:前置依赖*1..2]` 控深）→ 路径带前置依据 = **可解释推理路径**。（依据：完善文档 09）
- **已落地部分**：向量索引真实——匹配侧 bge 512 维（离线批量粗筛）/ 服务侧 dashscope 768 维（在线 RAG）；前置依赖入库真实——PREREQUISITE 由 LLM 双模型投票产出并过 DAG 验证。（依据：完善文档 09 / 分析-01 / 分析-08）
- **未真接（最大翻转）**：服务侧主链路未真接图扩展——`api/kg.py` 的 `/learning-path` 只返回目标实体自身一项、`/tree` 是前 100 实体平铺的简化桩、`/recommend` 只看一跳邻居（service.py:436-455, 180-208）；`core/rag/query.py` 是 AI 答疑**口述 RAG 检索**（图谱是其语料模块锚点之一），不是图遍历。（依据：完善文档 09 / 分析-01）
- **可解释性来源（设计）**：路径带前置依据——向量负责召回、图谱负责解释，每个邻居回指"为什么先学它"的前置知识点；落地要看 Java/MySQL 侧或后续接 GraphRAG 主链路。（依据：完善文档 09 / 引导问题.md §3）
- **与掌握度/答疑联动（设计）**：错题→前置链→算掌握度→定位薄弱根因；答疑记录回流支撑家长端报表——图谱作为 AI 对话助手"活文档"。（依据：完善文档 09）

## 追问防御
- **可能追问：可解释路径算不算做了？** → 是设计目标 + 部分桩实现——向量索引/前置依赖真实，邻居扩展在 Python 桥是简化桩，Java 侧不可核验，如实讲分层边界。（依据：完善文档 09 / 分析-01）
- **可能追问：GraphRAG 可解释性从哪来？** → 路径带前置依据——向量命中 Concept 后沿 PREREQUISITE/RELATED_TO 展开，每个邻居回指"为什么先学它"的前置知识点，Cypher 控深 1-2 跳，不是黑盒相似度。（依据：完善文档 09 / 引导问题.md §3）
- **可能追问：向量召回和图谱解释现在接上了吗？** → 服务侧主链路未真接——Python 桥学习路径/知识树/推荐均为简化桩，可解释推理路径是设计目标，落地看 Java/MySQL 侧或后续主链路。（依据：完善文档 09 / 分析-01）
