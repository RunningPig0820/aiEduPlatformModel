# 权威图谱零写入在架构上是怎么实现的？图谱关系查询怎么降级？

> 类别：架构设计

**核心结论**：权威图谱零写入 = 派生数据（掌握度/点亮/题型）只存 MySQL、Neo4j 只读；派生态靠 kp_uri 钩子"借"权威结构；图谱关系直查 Neo4j + Redis TTL 300s + `neo4jAvailable:false` 空关联降级。

## 分层展开
- **零写入的实现**：掌握度/点亮/题型等派生信号只存 MySQL，物理不污染权威图（决策 D17）；Neo4j 里只有事实与概念，权威冻结只读。（依据：完善文档 09 / 分析-01 / 完善文档 03）
- **kp_uri 钩子**：派生态解析靠 kp_uri 钩子"借"权威结构，图逻辑走 Neo4j 只读展开（design-backend-kp-matching-lightup D1）——派生数据要引用图谱时不写回，只读借用。（依据：完善文档 09）
- **只读消费**：MATCHES_KG/PART_OF/RELATED_TO 关系直查 Neo4j；答疑点亮只读借 kp_uri，零写入。（依据：完善文档 09 / 分析-01）
- **图谱关系查询降级**：Redis key `kg:neo4j:{uri}:{query_type}` TTL 300s（5 分钟）缓存；Neo4j 不可用返回空关联 + `neo4jAvailable:false`，不抛异常；批量接口 `/concepts/batch-relations` 避免 N+1；导航/核心页面不依赖图谱服务可用性。（依据：完善文档 03 / 分析-11 / 分析-01）
- **⚠️ 落地边界（在线查询标签坑）**：在线查询统一 `MATCH (e:Entity {uri...})` 而离线导入用具体标签（Textbook/Chapter/.../Concept），标签体系可能不匹配——要么 Entity 由 Java 经 api/neo4j.py 动态建，要么查询是"期望面"，降级/联调前必须对齐，否则 /entities、/tree 可能查不到导入数据。（依据：分析-01 / 完善文档 03）

## 追问防御
- **可能追问：点亮要写图谱怎么办？** → 只读借 kp_uri 借权威结构，零写入——点亮状态是派生信号，只存 MySQL。（依据：完善文档 09）
- **可能追问：降级后页面什么样？** → Neo4j 不可用时图谱关系接口返回空关联 + `neo4jAvailable:false`，前端隐藏图谱模块，导航（MySQL 侧）不受影响。（依据：分析-11 / 完善文档 03）
- **可能追问：缓存多久失效？** → Redis key `kg:neo4j:{uri}:{query_type}` TTL 300s（5 分钟），超时重新直查 Neo4j。（依据：分析-11 / 完善文档 03）
