**核心结论**：靠可解释、可追溯的掌握度答——掌握度由「错题 → 对应知识点 → 前置依赖链 → 正确率/次数」事件链算出，可追溯到每道题；再沿前置链定位"当前点没掌握 vs 前置没学好"，不是拍脑袋。

## 分层展开
- **掌握度事件链**：错题 → 对应知识点 → 前置依赖链 → 结合正确率/次数算出掌握度 → 定位薄弱根因。（依据：完善文档 09）
- **诊断依据**：靠 PREREQUISITE 前置链 + RELATED_TO 语义关联，沿链区分"当前点没掌握"还是"前置没学好"——这是回答"孩子到底会不会"的根因机制。（依据：完善文档 09）
- **可追溯**：掌握度由事件驱动计算，每道题对错都有记录可回溯，不是拍脑袋；前置依赖带置信度 + reason 可核对。（依据：引导问题.md §7 / 完善文档 09）
- **派生信号零写入**：掌握度只存 MySQL，不写权威图——结论建立在干净权威结构 + MySQL 派生信号之上。（依据：完善文档 09 / 分析-01）
- **⚠️ 落地边界**：掌握度主体从知识点翻转为题型（topic_key）、解析管线五步、点亮渲染"疑似态"都在 design-backend-kp-matching-lightup（D2/D16/D17），Java/前端代码不在本仓，属"非代码真值"，如实标注。（依据：完善文档 09 / 分析-11）

## 追问防御
- **可能追问：孩子到底是当前点没会还是前置没会？** → 沿前置链定位薄弱根因——靠 PREREQUISITE 前置链 + RELATED_TO 语义关联区分"当前点没掌握 vs 前置没学好"。（依据：完善文档 09）
- **可能追问：掌握度数值可靠吗？** → 事件驱动可追溯 + 双模型投票带 reason + 低置信过滤，非拍脑袋。（依据：引导问题.md §7）
- **可能追问：数据量少时可靠吗？** → 掌握度是事件驱动累计，训练样本少时参考性有限——如实讲清楚样本边界，不夸大结论。（依据：完善文档 09）
