# 图谱对"补课/学习路径"推荐意味着什么？

> summary: 业务视角引导问题回答：图谱提供PREREQUISITE前置依赖，补课顺序按学习依赖而非教材顺序，比按章节更科学；过DAG无环验证保证无死循环

> 类别：业务视角

**核心结论**：图谱提供 PREREQUISITE（前置依赖）关系，让补课顺序按**学习依赖**而非教材顺序生成，比按章节顺序推荐更科学；路径过 DAG 无环验证，保证补课顺序不会死循环。

## 分层展开
- **前置依赖价值**：学习路径吃 PREREQUISITE 前置关系，沿链生成补课顺序（Cypher `[:前置依赖*1..2]` 控深）——这是"补课先补什么"的决策依据。（依据：完善文档 09）
- **为什么更科学**：教学顺序≠学习依赖——教材先教≠必须先学（勾股定理先于圆，学圆不需先学勾股定理）；章节顺序只产 TEACHES_BEFORE（教学顺序，conf=1.0），学习依赖靠 LLM 双模型投票确认产 PREREQUISITE，两者严格区分，所以补课顺序按学习依赖更合理。（依据：完善文档 09 / 分析-08）
- **无环保证**：路径过 DAG 无环验证（validate_dag DFS 环检测，有环退出码 1）才可作路径，防"A 前置 B、B 前置 A"死循环。（依据：完善文档 09 / 分析-08）
- **置信度可信**：前置关系带置信度 + reason（primary/secondary_reason），低置信留候选（PREREQUISITE_CANDIDATE）供人工补审，不冒充高置信。（依据：分析-08）
- **⚠️ 落地边界**：服务侧 `/learning-path` 只返回目标实体自身一项（简化桩），可解释前置链是设计目标，落地看 Java/MySQL 侧或后续 GraphRAG 主链路；PREREQUISITE 主链路为 LLM 单路径 + 0.8 阈值，三来源融合未接主链路。（依据：分析-01 / 分析-08 / 完善文档 09）

## 追问防御
- **可能追问：路径会不会绕死？** → 不会——DAG 无环验证保证前置链无环（A 前置 B 且 B 前置 A 被拦截），退出码 0 才可作路径。（依据：分析-08 / 完善文档 09）
- **可能追问：补课顺序和章节顺序什么关系？** → 严格区分：章节顺序只产 TEACHES_BEFORE（教学顺序），学习依赖靠 LLM 确认产 PREREQUISITE，补课按学习依赖而非教材顺序。（依据：完善文档 09 / 分析-08）
- **可能追问：推荐现在能用吗？** → Python 桥 `/learning-path` 是简化桩只返回单点，可解释补课链是设计目标，落地看 Java/MySQL 侧或后续主链路，如实讲分层边界。（依据：分析-01 / 完善文档 09）
