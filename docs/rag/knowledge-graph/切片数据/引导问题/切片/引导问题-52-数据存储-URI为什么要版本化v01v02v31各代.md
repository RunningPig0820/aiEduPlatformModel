# URI 为什么要版本化？v0.1 / v0.2 / v3.1 各代表什么？

> summary: 数据存储引导问题回答：URI 版本化用于物理隔离来源、避免多来源冲突——v0.1=EduKG 原始、v0.2=小学新增、v3.1=教材；URI 永不修改，改动数据走合并流程不改 URI

**核心结论**：URI 版本化用于物理隔离来源、避免多来源冲突——v0.1 是 EduKG 原始、v0.2 是小学新增、v3.1 是教材；URI 永不修改，改动数据走合并流程不改 URI。

## 分层展开
- **为什么版本化**：图谱数据来自多个来源（EduKG 开源 / 小学新增 / 教材），物理隔离来源、避免 URI 冲突；URI 永不修改，改动数据走合并流程（依据：引导问题.md 数据存储 / 完善文档 02 追问与防御）
- **v0.1**：EduKG 原始，格式 `/0.1/instance/math#xxx`（依据：分析-01 代码事实 / 完善文档 02）
- **v0.2**：小学新增，格式 `/0.2/...`（依据：分析-01 / 完善文档 02）
- **v3.1**：教材，格式 `/3.1/textbook|chapter|section/...`；TextbookKP 用全局序号 `textbook-{stage}-{seq:05d}`（依据：分析-01 / 引导问题.md 数据存储）
- **完整 URI 格式**：`http://edukg.org/knowledge/3.1/{type}/math#{id}`（依据：引导问题.md 数据存储）

## 追问防御
- **可能追问：URI 是什么格式？** → `http://edukg.org/knowledge/3.1/{type}/math#{id}`，TextbookKP 用全局序号 `textbook-{stage}-{seq:05d}`；v0.1/v0.2 前缀对应 EduKG 原始与小学新增（依据：引导问题.md 数据存储）
- **可能追问：改数据怎么办？** → 改数据走合并流程不改 URI，保证 URI 作为主键永不漂移；两库（Neo4j/MySQL）都按 URI 作为唯一锚点（依据：引导问题.md 数据存储 / 完善文档 02 存储拓扑）
