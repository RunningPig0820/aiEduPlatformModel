# 为什么节点主键用 URI 而不是自增 ID？

> summary: 数据存储引导问题回答：URI 是跨 Neo4j/MySQL 的唯一锚点，同步按 URI UPSERT，URI 永不修改（改动走合并）；<1 万节点 VARCHAR(255) 主键可行，暴涨才考虑整型代理键

**核心结论**：URI 是跨 Neo4j/MySQL 的唯一锚点，同步按 URI UPSERT，URI 永不修改（改动走合并）；<1 万节点 VARCHAR(255) 主键可行，暴涨才考虑整型代理键。

## 分层展开
- **唯一锚点**：URI 在跨库（Neo4j/MySQL）间唯一，Java 页面化同步按 URI UPSERT 保证两边一致（依据：引导问题.md 数据存储 / 完善文档 02 存储拓扑）
- **永不修改**：URI 永不改，改动数据走合并流程，避免主键变更引起跨库连锁（依据：引导问题.md 数据存储）
- **性能可行**：<1 万节点规模下 VARCHAR(255) 主键可行；暴涨才考虑整型代理键（依据：引导问题.md 数据存储 可能追问）
- **落地证据**：Neo4j 与 MySQL 页面化 8 表均 URI 主键；落地 URI 唯一 100%（依据：完善文档 01 / 完善文档 02 存储拓扑）
- **配套注意**：`/api/neo4j` 默认 `id_property="id"`，而节点主键是 `uri`——Java 调用需显式传 `id_property=uri` 否则查不到（依据：分析-01 隐性坑）
