# 匹配用的向量索引文件存在哪？它怎么知道自己对应的 Neo4j 数据版本？

> summary: 数据存储引导问题回答：匹配侧落盘 output/vector_index/kg_vectors.npy(1295×512)+kg_texts.json+kg_concepts.json+index_meta.json（含 neo4j_checksum=MD5(uri+label 排序拼接)）；启动时 check_index_validity 重算 checksum 比对，失配即"索引过期"回退懒加载或 --force 重建

> 模块: knowledge-graph

> 类别：数据存储

**核心结论**：匹配侧落盘 `output/vector_index/kg_vectors.npy`(1295×512) + `kg_texts.json` + `kg_concepts.json` + `index_meta.json`（含 neo4j_checksum = MD5(uri+label 按 uri 排序拼接)）；启动时 check_index_validity 重算 checksum 比对，失配即"索引过期"回退懒加载或 `--force` 重建。

## 分层展开
- **存在哪**：匹配侧本地 `output/vector_index/`——kg_vectors.npy（约 2.6MB）+ kg_concepts.json（约 0.29MB）+ kg_texts.json（约 0.15MB）+ index_meta.json，合计约 3.1MB；服务侧另写 COS 桶（dashscope 768 维）（依据：分析-09 代码事实 / 实际数据）
- **怎么知道对应版本**：index_meta.json 里存 `neo4j_checksum` = MD5("".join(f"{uri}:{label}" for c in sorted(concepts, key=uri)))——**只含 uri+label**，description 变化不影响 checksum（依据：分析-09 代码事实）
- **过期检测**：`check_index_validity` 用当前 Neo4j 概念重算 checksum 对比 index_meta.neo4j_checksum，不匹配→告警"索引过期，回退到懒加载模式"（3.5GB）；加载失败同样回退；再失败回退 difflib（依据：分析-09 代码事实 / 坑档案 J-KG7）
- **重建方式**：`build_vector_index.py --force` 强制重建；`--status` 只读元数据+联网算 checksum 判有效/过期（依据：分析-09 代码事实）
- **约束**：checksum 只含 uri+label，只改 description 不会触发过期检测，可能拿到语义旧向量（依据：分析-09 隐性坑）

## 追问防御
- **可能追问：checksum 算什么？** → MD5(uri+label 按 uri 排序拼接)，图谱变则失配回退懒加载/重建；宁可回退慢的懒加载（3.5GB）也不拿脏索引静默匹配（依据：引导问题.md 数据存储 / 坑档案 J-KG7）
- **可能追问：预构建索引是不是不用加载模型？** → 不是——PrebuiltIndexRetriever 只省了 1295 个概念的 encode 时间和内存，查询编码仍需加载 SentenceTransformer 模型，首次启动仍要读模型文件（依据：分析-09 隐性坑）
- **可能追问：索引 put 后查不到？** → COS 向量索引异步生效 ~10s，写入成功不立即可查，紧跟 query 可能 miss（依据：引导问题.md 数据存储可能防御 / 分析-09）
