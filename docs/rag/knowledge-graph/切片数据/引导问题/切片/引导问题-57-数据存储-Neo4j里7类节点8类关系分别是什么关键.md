**核心结论**：7 类节点 = Textbook/Chapter/Section/TextbookKP + Concept/Statement/Class；8 类关系 = CONTAINS/IN_UNIT/MATCHES_KG/HAS_TYPE/RELATED_TO/BELONGS_TO/PART_OF/SUB_CLASS_OF；关键约束：TextbookKP 有且仅有一个 IN_UNIT 指向 Section、RELATED_TO 方向固定 Statement→Concept、所有关系不可逆、URI 唯一 100%、MATCHES_KG 置信度≥0.5 才连。

## 分层展开
- **7 类节点**：教材结构层 Textbook 23 / Chapter 148 / Section 580 / TextbookKP 1740 + 语义层 Concept 1295 / Statement 2932 / Class 39 = 6757 个（依据：分析-01 / 完善文档 02 存储拓扑）
- **8 类关系**：CONTAINS/IN_UNIT（结构关系）+ MATCHES_KG（匹配连接）+ HAS_TYPE/RELATED_TO/BELONGS_TO/PART_OF/SUB_CLASS_OF（语义关系）= 20887 条（依据：分析-01 / 完善文档 02）
- **关键约束**：每个 TextbookKP 有且仅有一个 IN_UNIT 指向 Section；RELATED_TO 方向固定 Statement→Concept；`content` 属性在 Statement 上不在 Concept 上；**所有关系不可逆**（依据：分析-01 代码事实）
- **匹配约束**：MATCHES_KG 置信度≥0.5 才连边、方向固定 TextbookKP→Concept（不可逆）（依据：完善文档 01 / 分析-01）
- **唯一约束**：URI 唯一 100%；`create_neo4j_schema.py` 建 3 个唯一约束（kp_uri_unique/subject_code_unique/textbook_isbn_unique），性能索引延迟到数据导入后创建（依据：完善文档 01 / 分析-02）

## 追问防御
- **可能追问：关系哪些是 TTL 原生的、哪些是 LLM 推的？** → TTL 原生（语义层 RELATED_TO/HAS_TYPE 等）+ 教材结构生成（CONTAINS/IN_UNIT）+ LLM 双模型推理（MATCHES_KG 投票、PREREQUISITE 前置）（依据：引导问题.md 数据关联 / 完善文档 02）
- **可能追问：schema 唯一约束够用吗？** → 只建 3 个唯一约束防重复（性能索引延迟到导入后，避免导入 10x 变慢）；约束防的是"按本 schema 命名"的数据重复，跨命名需先统一标签口径（依据：分析-02 隐性坑 / 设计要点）
