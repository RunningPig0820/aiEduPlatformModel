**核心结论**：已落地**阶段 0-3 数据管道**（Neo4j 7 类节点 6,757 个 + 8 类关系 20,887 条、两层图谱 + MATCHES_KG 连接真实导入）和**阶段 5 页面化方案 B 拍板**；刻意不做的 Non-Goal = 全学科扩展 / 复杂关系可视化 / Neo4j 实时查询 / 管理员审核重跑 / 批量定时任务 / 多版本教材。

## 分层展开
- **已落地（阶段0-3 Python 数据管道）**：Phase0 爬取 → Phase1 生成/清洗/推断（LLM 补 1052 知识点、平均置信 0.93）→ Phase2 匹配（精确+向量粗筛+双模型投票）→ Phase3 导入 MERGE 幂等；Neo4j 7 类节点 6,757/8 类关系 20,887（依据：完善文档 08 / 分析-01）。
- **已落地（阶段1 工程化）**：llmTaskLock 断点续传三件套（TaskState + CachedLLM SHA256 + ProcessLock）真实存在；向量索引 bge 512 预构建 + MD5 checksum 校验（依据：完善文档 08 / 坑档案 J-KG8）。
- **阶段5 页面化（方案已拍板，代码不在本仓）**：方案 B（Neo4j→MySQL 同步 8 表 + 双数据源 @DS("kg") + React Flow 三栏）设计完成，但 Java/前端代码不在本仓，design 标注 graph 接口未实现、API 前缀前后端不一致，属"联调收口"状态，不能讲成已上线（依据：完善文档 08 / 分析-11）。
- **Non-Goal 清单及原因**：全学科扩展（全学科 56,391 知识点、成本/优先级未定）、复杂关系可视化（Statement/Class/PART_OF 语义重、直查 Neo4j、渲染成本高）、Neo4j 实时查询（Java 无 Neo4j 集成、7 表 JOIN 慢 SQL 坑在前）、管理员审核重跑（评审系统是规划无代码）、批量定时任务（同步为手动按需、避免定时复杂度）、多版本教材（专注人教版）（依据：完善文档 08）。
- **口径提醒（翻转）**：匹配评审系统是规划非已上线；匹配率当前批次 96.96%（1905 基线）vs 历史 97.1%（1740 基线）；TaskState 用 JSON 文件落 output/progress/ 而非 design 说的 MySQL 状态表（依据：完善文档 08）。

## 追问防御
- **可能追问：前置融合/审核这些是不是没做完？** → 如实讲是设计目标非落地现状——三来源融合未接主链路、匹配评审系统未上线、年级倒置惩罚无代码；讲清方案与现状边界本身就是可信度（依据：完善文档 08 / 引导问题.md 9）。
- **可能追问：6757 节点是真的吗？** → 来源逐类可讲（EduKG TTL + 人教版爬虫 + 课标），自建 Phase0-3 清洗/推断/匹配管线，匹配率"~97%"背书（依据：引导问题.md 1 / 完善文档 04）。
- **可能追问：为什么这些 Non-Goal 不做？** → 本期只做人教版数学，复杂度后置，每项都有明确前置条件（v3.2 URI/审核 UI/调度基础设施等）（依据：完善文档 08）。
