# "权威图谱零写入"是什么意思？为什么业务数据不能写进权威图？

> summary: 项目介绍引导问题回答：EduKG 静态权威库冻结只读，业务派生数据（掌握度/点亮/题型）只存 MySQL，物理上不污染权威图；业务"点亮"只读借 kp_uri 借权威结构，零写入

**核心结论**："权威图谱零写入"指 EduKG 静态权威库冻结只读，业务派生数据（掌握度/知识点点亮/题型）只存 MySQL，物理上不污染权威图；业务要"点亮"只读借 kp_uri 借权威结构，不写进图谱。

## 分层展开
- **定义**：权威库（EduKG 静态权威 + 教材结构真值）冻结只读，业务派生数据只存 MySQL（依据：完善文档 01 / 分析-01 设计要点）
- **为什么不能写**："无限的业务事实与有限的权威结构分存"——业务事实（掌握度/点亮/题型）变化快、量大，是业务状态而非结构事实，写进权威图会污染概念真值（依据：完善文档 01 / knowledge-graph.md）
- **怎么实现**：Neo4j 里只有事实与概念，业务派生数据存 MySQL；业务借 kp_uri 钩子"借"权威结构做点亮/诊断，只读不写（依据：分析-01 设计要点 / 引导问题.md 项目介绍）
- **在线实现（落地差异）**：在线查询统一 `MATCH (e:Entity {...})`，离线导入用 Textbook/Concept 等具体标签，标签体系可能不匹配——联调前需对齐（依据：完善文档 01 落地真相 / 分析-01）

## 追问防御
- **可能追问：点亮要写图谱怎么办？** → 只读借 kp_uri 借权威结构，零写入——点亮信号落 MySQL，图谱不动（依据：引导问题.md 项目介绍）
- **可能追问：业务数据不进图谱，图谱数据会过时吗？** → 权威层是静态冻结的（EduKG 开源 + 教材真值），变化走合并流程重导入，不因业务操作变化；派生状态与权威结构分离本身就是设计目标（依据：完善文档 01 / 引导问题.md）
