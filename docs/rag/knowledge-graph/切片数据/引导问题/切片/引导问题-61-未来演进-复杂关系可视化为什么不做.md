**核心结论**：复杂关系可视化（Statement/Class/PART_OF）是页面化设计的明确 Non-Goal——前端只展示"教材知识点→概念"这一层关联，复杂关系语义重、直查 Neo4j，多类型节点/关系渲染的性能与布局成本高，复杂度后置。

## 分层展开
- **前端展示范围**：页面化只展示"教材知识点→概念"关联，React Flow 力导向图呈现，节点 >50 提供"简化视图"只显示 Top 10（依据：完善文档 08 / 分析-11）。
- **不做原因**：Statement/Class/PART_OF 这类关系语义重、直查 Neo4j；多类型节点/关系渲染性能和布局成本高；页面化 design 明确"不做知识图谱关系可视化"（依据：完善文档 08）。
- **将来做的前提**：需前端复杂关系可视化范围确认 + React Flow 扩展；在范围确认前不做（依据：完善文档 08）。
- **落地边界**：复杂关系可视化属于 Non-Goal，任何一节不得描述成已实现功能——它只在方案演进口径出现（依据：完善文档 08）。

## 追问防御
- **可能追问：将来做吗？** → 需前端复杂关系可视化范围确认 + React Flow 扩展，复杂度后置（依据：完善文档 08）。
- **可能追问：那页面看不到复杂关系，怎么解释学习依赖？** → 图谱关系（MATCHES_KG/PART_OF/RELATED_TO）由后端直查 Neo4j 提供（Redis TTL 300s 缓存 + 降级），只是不在前端做多类型可视化渲染（依据：完善文档 08 / 分析-11）。
- **可能追问：为什么不是已实现能力？** → 复杂关系可视化在 Non-Goal 清单里，属方案边界非现状——本期前端只做"教材知识点→概念"关联（依据：完善文档 08）。
