**核心结论**：下一步演进是**三条线**——①全学科扩展（P1 数理化生，管道复用）；②页面化联调收口（补 graph 接口、对齐 /api/kg 前缀、点亮前端）；③GraphRAG 全链路（答疑/掌握度/学习路径消费闭环）；背后是数据飞轮：答疑越多→掌握度越准→学习路径越准→更多答疑。

## 分层展开
- **三条演进线**：全学科扩展 + 页面化联调收口 + GraphRAG 全链路（依据：完善文档 08 / 引导问题.md 9）。
- **GraphRAG 全链路（设计路径）**：向量命中 Concept → 沿 PREREQUISITE/RELATED_TO 扩展邻居 → 可解释推理路径 → 引导式答疑（前置回顾）+ 掌握度薄弱诊断 + 学习路径补课顺序（依据：完善文档 07 / 完善文档 08）。
- **现状边界（翻转）**：向量索引（bge 512 / dashscope 768）+ 前置依赖 PREREQUISITE 入库是本仓可核验的真实落地；"邻居扩展/可解释路径"在 Python 桥是简化桩（get_learning_path 只返回目标实体自身），点亮/掌握度消费在 Java 侧（kp-matching-lightup）本仓不可核验（依据：完善文档 07）。
- **数据飞轮**：答疑越多→掌握度越准→学习路径越准→更多答疑（依据：完善文档 08）。
- **优先级**：页面化收口（已拍板）+ GraphRAG 落地最直接；全学科取决于教研优先级（依据：引导问题.md 9）。

## 追问防御
- **可能追问：先做哪条？** → 看业务：页面化收口（方案 B 已拍板）+ GraphRAG 落地最直接；全学科取决于教研优先级（依据：引导问题.md 9）。
- **可能追问：GraphRAG 可解释路径算做了吗？** → 设计目标 + 部分桩实现——本仓可核验的是向量索引 + 前置依赖入库 + Python 桥接口，主答疑链路未真接图遍历，如实讲分层边界（依据：完善文档 07）。
