> 类别：未来演进

**核心结论**：多版本教材（北师大/苏教版）**现在不做**——design D13 明确当前阶段不实现、专注人教版；将来要做需 v3.2 多版本教材（URI 改 {edition}-{grade}{semester}）+ version_code 字段 + 版本对比能力，复杂度后置。

## 分层展开
- **现状**：本期只做人教版数学，多版本教材在 design D13 记录"当前阶段不实现"——专注人教版先把数据管道和两层图谱打通（依据：完善文档 08 / 引导问题.md 9）。
- **将来前置条件**：需 v3.2 多版本教材（URI 改 {edition}-{grade}{semester}）+ version_code 字段 + 版本对比能力（依据：完善文档 08 / 引导问题.md 9）。
- **为什么后置**：多版本会放大 URI 前缀、同步按版本对账、跨版本对比等复杂度，且当前无教研需求；先验证"两层图谱 + MATCHES_KG + 学习路径"可行性（依据：完善文档 08）。
- **落地边界**：多版本教材属于 Non-Goal，任何一节不得描述成已实现功能——只在方案演进口径出现（依据：完善文档 08）。

## 追问防御
- **可能追问：多版本会带来什么复杂度？** → URI 要带 edition 前缀（{edition}-{grade}{semester}）、同步要按版本对账、需要 version_code 和版本对比，复杂度高（依据：完善文档 08）。
- **可能追问：将来做吗？** → 做，但需 v3.2 多版本教材设计 + version_code + 版本对比前置，本期专注人教版（依据：引导问题.md 9 / 完善文档 08）。
- **可能追问：为什么专注人教版？** → 数学人教版结构化最清晰、JSON 初中完整可作调试基线；MVP 先验证可行性再横向扩展（依据：完善文档 08 / 引导问题.md 7）。
