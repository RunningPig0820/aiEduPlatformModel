**核心结论**：PREREQUISITE 前置依赖记录"学 A 之前必须先掌握 B"，支撑学习路径推荐（补课顺序）和掌握度薄弱根因诊断（沿前置链定位是当前点没掌握还是前置没学好）。

## 分层展开
- **定义**：PREREQUISITE 是学习依赖关系（A 是 B 的前置），与教学顺序 TEACHES_BEFORE 严格区分——教材先教≠必须先学（如勾股定理先于圆，但学圆不需先学勾股定理）（依据：分析-08 / 引导问题.md 数据关联）
- **支撑能力 1·学习路径**：沿 PREREQUISITE 前置链生成补课顺序（Cypher 控深），过 DAG 无环验证避免"A 前置 B、B 前置 A"死循环（依据：引导问题.md 数据关联 / 分析-08）
- **支撑能力 2·掌握度诊断**：错题→对应知识点→沿前置链判断"当前点没掌握 vs 前置没学好"，定位薄弱根因（依据：完善文档 01 / 引导问题.md 数据关联）
- **构建方式**：Neo4j 加载 Concept → 前后 ±5 邻居配对（~10N 对）→ 双模型投票（一致采纳、不一致加权 DS=0.6/GLM=0.4×0.7）→ ≥0.8 落 PREREQUISITE、<0.8 落 PREREQUISITE_CANDIDATE → validate_dag 环检测（依据：分析-08）
- **落地现状（⚠️ 翻转）**：主链路是 LLM 单路径 + 0.8 单阈值；三来源融合 fuse_results 方法已实现但**未接入 CLI**，final_prereq.json 无生产方；年级倒置惩罚（×0.95/0.9/0.5/0.3）代码中搜不到——这些是设计目标非现状（依据：分析-08 / 引导问题.md 数据关联可能防御）

## 追问防御
- **可能追问：教学顺序能用吗？** → 只能产 TEACHES_BEFORE（章节内 conf=1.0），教学顺序≠学习依赖，只能作弱证据；真正的学习依赖走 LLM 投票产 PREREQUISITE（依据：引导问题.md 数据关联 / 分析-08）
- **可能追问：前置融合真的落地了吗？** → 没有——fuse_results 方法存在但主链路未接入，CLI 只产 llm_prereq.json，当前是 LLM 单路径 + 0.8 单阈值，如实讲（依据：引导问题.md 数据关联可能防御 / 分析-08 对账要点）
