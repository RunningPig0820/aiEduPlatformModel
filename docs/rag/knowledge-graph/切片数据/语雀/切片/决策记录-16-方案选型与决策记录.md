## 决策总览摘要（D1~D17）

> 解答「知识图谱模块每一项关键设计决策的背景、演进、拍板理由与系统影响分别是什么？」本文是知识图谱模块全部 17 项设计决策（D1~D17，=已落地）的汇总决策记录，按五大类组织，覆盖选型、数据加工、数据来源、URI、embedding、匹配、前置依赖、工程化、页面化、数据源、主键、评审与零写入主题，可答「为什么选/怎么落地/影响是什么」类问题。存储与数据源：D1 选 Neo4j 而非 MySQL/ES——图遍历、前置依赖链、可解释路径，MySQL/ES 做不了多跳关系；neo4j-admin import 批量导入是 TTL 的 10 倍以上，十万节点百万关系秒级导入，最终存 7 类节点/8 类关系（docker 5-enterprise 2G heap/1G pagecache）。D2 数据加工选方案 C（CSV→Neo4j）：关系处理在 Python 内存/CSV 完成、MERGE 幂等批量导入，权威基准冻结、教研可维护 CSV、计算与存储分离，Neo4j 只是最后仓库。D3 数据来源四类：EduKG TTL 语义层 + main.ttl 教材出处（仅高中 28,438 条）+ 人教版爬虫补小初 + 课标 2022/2017 作层级基准，全学科 56,391 知识点。D4 URI v3.1：统一 http://edukg.org/knowledge/3.1/{type}/math#{id}，演进 v0.1 原始→v0.2 小学→v3.0 EduKG→v3.1 自建人教；ID 编码含出版社-年级-学期，URI 永不修改（v3.2 预留）。embedding 与匹配：D5 双轨 embedding——匹配侧 bge-small-zh-v1.5 本地 512 维（kg_vectors.npy 1295×512、内存约 3.5GB、numpy 暴力搜索 ≤5000 条 <10ms）+ 服务侧 RAG 用 dashscope text-embedding-v3 768 维（rag-full/rag-slice 桶），维度固定不可改。D6 匹配流水线：标准化精确匹配（+同义词，覆盖 86.8%）→ 向量粗筛 top-20 → LLM 双模型投票，调用从 500 万降至 2.7 万（-99%）、提速约 50 倍，匹配率 1690/1740=97.1%、平均置信 0.975，未匹配进评审系统。D7 双模型投票：GLM-4-flash 免费主力 + DeepSeek；两模型一致→平均置信采纳；不一致→加权 DS=0.6/GLM=0.4 阈值 0.5，仅 DeepSeek=True 可过（DS 否决权），置信 ×0.7。前置依赖：D8 严格区分教学顺序 TEACHES_BEFORE（教材章节内部）与学习依赖 PREREQUISITE（业务查询用，需多证据确认），另有 PREREQUISITE_ON（EduKG 互操作）与 PREREQUISITE_CANDIDATE（低置信候选），勾股定理先于圆但学圆不需先学勾股。D9 多证据融合：教材顺序 0.7、定义依赖 0.85（代码 conf 0.9）、LLM 双模型 0.8（已有前置升级 +0.1 封顶 1.0）、教师 1.0（demo 不做）；阈值 HIGH=0.8/LOW=0.6，≥0.8→PREREQUISITE、≥0.6→CANDIDATE、不一致不采纳。D10 年级倒置惩罚：前置高于目标年级按跨度 ×0.95/0.9/0.5/0.3，惩罚后 <0.6 降级候选，目标倒置率 ≤5%。工程化：D11 llmTaskLock 断点续传——TaskState 检查点 + CachedLLM（SHA256 缓存键）+ portalocker 文件锁，JSON 文件状态不依赖 MySQL，--resume 续跑（推断 2-3 小时/匹配 1-2 小时）。D12 状态存储 SQLite→MySQL：已有环境/并发安全/运维备份成熟；表结构 processing_state/llm_cache/cost_tracking/chapter_state+subbatch_state/failed_batches/progress_view；成本预算日 5000 分/总 20000 分/70% 告警。页面化与消费：D13 页面化方案 B——Neo4j 知识点同步 MySQL、前端 SPA 只读 MySQL，图谱关系（MATCHES_KG 等）不同步、Neo4j 直查 + Redis TTL 300s + 降级；8 张表（4 节点主表 URI 主键 + 3 层级关联 + 1 同步记录），6,757 节点同步 <10s。D14 双数据源 dynamic-datasource + @DS("kg")：ai_edu_kg 与业务库 ai_edu_user 物理隔离，Mapper 包路径隔离，HikariCP 每源 5-20 连接，@Transactional("kg")。D15 图谱主键用 URI（非自增 ID）：URI 是跨 Neo4j/MySQL 唯一锚点，校验以 edukg.org/knowledge/ 开头，<1 万节点 VARCHAR(255) 可行，合并走 merged_to_uri。D16 匹配评审系统：308 个未匹配（297 投票不通过 + 11 无候选）进 MySQL 审核表 textbook_kp_match_review（前 5 候选 JSON + pending/approved/rejected/new_kp），/api/kp-match/recommend LLM 推荐，审核后导入 Neo4j，新 KP 用 v3.2 前缀。D17 权威图谱零写入：业务派生数据（掌握度/点亮/题型库）只存 MySQL（ai_edu_learning），解析管线最终 kp 必经镜像校验（SHALL NOT 凭空生成），图谱只读、GraphRAG 消费。
