## 数据不是拿来就用：四道质量防线

### 第一道：解析与生成——把原始素材变成结构化数据

原始数据进来第一件事是**解析成统一结构**：

- TTL 用 rdflib 解析，自动处理 Unicode 解码（`一` → 中文）
- 教材 JSON 生成标准的 Textbook/Chapter/Section/TextbookKP 节点 + 层级包含关系

这一步不做任何判断，只是把"原始素材"变成"统一格式"，为后面清洗打底。

### 第二道：清洗——去掉教材自带的"脏"

爬下来的教材有个很现实的"脏"：

- **"通用"标签复用**：教材里"通用"这种标签会被反复复用到多个章节（检测出 88 组），不清掉一个知识点会被挂到 N 个地方
- **小节名带序号**：`1.1 正数和负数` 这种，序号不单独提出来，排序就是乱的
- **全角字符**：教材混全角标点，不统一成半角，后面匹配"（" vs "(" 会漏配

清洗的**安全设计**很重要：**先跑分析出报告 → 人工确认 → 再动手清洗**。宁可慢一点，也不能让脚本误删教材结构。每次清洗有日志（谁改了什么、原来是什么）可回溯。

> 一句话面试答案："教材自带'通用标签复用、序号混在标题里、全角字符'这些脏，清洗前先出报告人工确认再动手，防止误删。"

### 第三道：增强——给知识点补上"属性"

知识点建出来还得有属性才有业务价值：**难度、重要性、认知层级、所属专题**。这里有个关键决策——**用规则，不用 LLM**：

- **难度 1~5**：按年级给基础难度（一年级=1、必修三=5），再按关键词微调
- **重要性**：核心 > 重要 > 了解，关键词优先级
- **认知层级**：分析 > 应用 > 理解 > 识记，布卢姆分类
- **所属专题**：章节名关键词匹配，分成数与代数/图形与几何/统计与概率/综合与实践

为什么不用 LLM？属性是**客观可枚举**的，规则又快又可复现，LLM 反而可能给你"编"一个不存在的属性——该用规则的地方用规则，LLM 只留给真正需要语义判断的地方。

> 一句话面试答案："属性推断刻意用规则不用 LLM——属性客观可枚举，规则快且可复现，LLM 该用在真正需要语义的地方。"

### 第四道：过滤——别把"活动/复习题"当成知识点

教材目录里混着很多**不是知识点**的东西：数学活动、小结、整理和复习、复习题、`例1` 这种例题。这些如果不拦下来，图谱里会全是垃圾节点：

- 用**关键词黑名单**（数学活动/小结/整理和复习/复习题…）
- 加**前缀 + 正则**（`^例\d` 这类例题编号）
- 过滤掉的不建节点，保证图谱里每一个 TextbookKP 都是真知识点
