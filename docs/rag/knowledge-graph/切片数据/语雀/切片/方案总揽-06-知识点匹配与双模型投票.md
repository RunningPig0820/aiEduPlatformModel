## 匹配流水线（最终实现）（§7）

三段式：**标准化精确匹配（+完整词同义词）→ 向量粗筛 top-20 → LLM 双模型投票**；三步全链路。

- **匹配统计（最终）**：总知识点 1,740；精确匹配 1,511（86.8%）；LLM 匹配 179（10.3%）；未匹配 50（2.9%）；**匹配率 1,690/1,740 = 97.1%**；平均置信度 **0.975**。
- **匹配阈值**：相似度 <0.5 跳过（跳过候选）；LLM 候选上限前 3 个 + 早停；投票 DS=0.6/GLM=0.4、threshold=0.5（设计期 D4.1 口径 ≥0.9 MATCHES_KG / 0.7-0.9 CANDIDATE / <0.7 不匹配，为候选分档参考）。
- **性能优化**：LLM 调用从 500 万 → 2.7 万（下降 99%）；三重优化后整体提速约 50 倍；8,255 个缓存节省 16,510 次 API 调用。

## 双模型投票机制（§6）

（`dual_model_voter.py`）：主模型 `glm-4-flash`（免费）、副模型 `deepseek-chat`（DeepSeek-V3）；两模型一致 → 取平均置信度采纳；不一致 → 加权投票 `WEIGHT_DS=0.6 / WEIGHT_GLM=0.4 / THRESHOLD=0.5`，仅 DeepSeek=True 才可能过阈值（**DS 否决权**），不一致时置信度 ×0.7。

## 低匹配根因与 LLM 标准化

初始匹配率仅 17%（LLM 仅 2%）；小学 69.6% 教材知识点（如「1-5 的认识」）无法匹配以高中抽象概念为主的 EduKG → LLM 推断标准化名再匹配（「1-5 的认识」→「自然数的基本概念」→ 匹配 EduKG「自然数」）。

## 匹配评审（人在环审核 308）

308 个未匹配（297 条"投票不通过" + 11 条"无候选通过"）进 MySQL 审核表 `textbook_kp_match_review`（前 5 候选 JSON + review_status pending/approved/rejected/new_kp），LLM 推荐接口 `/api/kp-match/recommend`，审核后导入 Neo4j（新知识点 URI 用 v3.2 前缀）。
