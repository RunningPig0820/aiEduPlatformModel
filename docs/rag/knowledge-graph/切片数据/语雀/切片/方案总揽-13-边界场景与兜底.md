## 已知风险与兜底（§12）

| 风险 | 现状/兜底 |
|---|---|
| 小学 3-6 年级知识点空 / 高中必修 0 | LLM 推断补 1,052 个（平均置信 0.93） |
| 匹配失败 3%（50 个） | 小学 69.6% 教材知识点与 EduKG 高中抽象概念不对齐；置信度 0.5 不硬连 + 评审系统人工审核 |
| 属性增强覆盖率 22% | 执行顺序 bug（增强在推断前），修复为推断后重跑 |
| topic 继承偏差 | 知识点直接继承章节 topic 导致语义矛盾（「加法」在「位置」章被错继承），基于匹配 Concept 的 Class 类型修正 144 个 |
| 维度不一致 v0.1 vs v3.0 | TTL 与 main.ttl 数据不匹配，靠标签匹配容忍缺失 |
| LLM 自证循环 | LLM 修正 LLM 可能自我强化；强制"每次判断被客观信号校准"（做题结果/多模型交叉/学生意图），冷启动弱化（WEAK 态等第二独立信号） |
| 开发者打标脱离解题 | 人工仅边界仲裁，找懂学科的人，不做日常打标 |
| Neo4j 内存/存储 | 社区版 4.4.x 单机 4G/8G 内存、100G+ 存储（实际 docker 5-enterprise 2G heap/1G pagecache） |
| 联调问题 | 教材导航 API 空数组、图谱关系 API 未验证、同步并发冲突/URI 脏数据（对账校验缓解）、前端节点上限 50 |
| 权威图零写入约束 | 派生数据（掌握度/点亮）只存 MySQL，物理上不污染权威图谱 |

## 设计期避坑原则（方案 C 专家）

绝不修改基准 TTL；知识点粒度必须统一；前置依赖层级不要超过 3 层（1-2 层最优）；业务关联必须有教研审核；核心字段加唯一约束+索引；题目大文本不要存 Neo4j。
