## 决策总览摘要（选型 1~14）

> 解答「知识图谱 14 项关键技术选型为何这样设计、为何不选其他候选」——本文档是知识图谱模块选型横向对比总表（权威度 0.8），状态口径：=已拍板、=建议、=待决；证据：语雀原方案 + edukg 代码真值 + 2.OpenSpec design 决策 13 份。

一、存储选型：图谱存储选 Neo4j 否决 MySQL/ES——原生图查询、前置依赖链、可解释路径、批量导入快（代价运维成本）；MySQL 多跳难、ES 无图语义。数据加工选方案C（CSV→Neo4j）唯一最优——权威基准冻结、CSV 可维护、导入快、计算存储分离；方案A/B TTL 导入慢排除。导入选 CSV 批量（LOAD CSV/UNWIND/MERGE）快 10x+、MERGE 幂等、断点可控、需先生成 CSV；n10s TTL 直导性能差，早期放弃。二、匹配与 embedding：匹配粗筛选 bge-small-zh-v1.5 + numpy（采纳 DeepSeek 建议）替代 difflib——中文 SOTA、语义强、≤5000 条 <10ms、内存约 3.5GB、建索引 60s，准确率提升 10-20%。LLM 主模型 GLM-4-flash 免费主力（单模型误判）+ DeepSeek-V3 双模型投票（约 0.001 元/千 token），百炼 qwen 付费未采用，数学全流程成本 1-2 元。匹配策略三段式：精确 86.8% 兜底 + 向量粗筛降候选 + LLM 双模型投票，匹配率 97.1%、LLM 调用降 99%（实现复杂）；纯 LLM 调用爆炸 500 万匹配率仅 17%、纯精确小学 69.6% 不匹配，均否决。三、前置依赖：前置依赖构建选多证据融合（顺序/定义/LLM/教师）非直转——避免"教学顺序≠学习依赖"（勾股定理先于圆）误连：教材顺序仅作 TEACHES_BEFORE、定义/LLM 投票才出 PREREQUISITE，含年级惩罚。低置信处置选降级候选（PREREQUISITE_CANDIDATE）非直接丢弃——早期 <0.7 丢弃，演进为降级保留待补审、需维护候选，两模型一致 ≥0.8 才转正式。四、工程化：断点续传选 llmTaskLock（JSON 状态 + SHA256 缓存 + portalocker 锁）+ --resume，2-3 小时可续、缓存省调用、文件管理成本；否决全量重跑。状态存储选 MySQL（ai_edu_kg）替代早期 SQLite——并发/运维/备份更成熟、需配置，SQLite 并发弱、备份差被演进放弃。五、页面化与消费：页面化同步选方案B——Neo4j→MySQL 同步、前端读 MySQL，图谱关系直查 Neo4j + Redis 缓存降级，不做实时查询、需同步机制。后端双数据源选 dynamic-datasource + @DS("kg") + Mapper 包隔离，比手动路由（AbstractRoutingDataSource）、多套 Config 简洁（GitHub 10k+ stars，三方依赖）。前端图谱库选 React Flow——React 原生、力导向布局内置、生态相对小，比 D3 集成成本低、比 ECharts 更合 React 范式。图谱主键选 URI（非自增 ID）——永不修改、跨 Neo4j/MySQL 对齐、改动走合并流程；自增 ID 无法对齐/漂移，VARCHAR <1 万节点可行。
