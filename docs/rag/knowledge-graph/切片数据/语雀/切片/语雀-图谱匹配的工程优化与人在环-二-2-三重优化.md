### 三重优化：相似度阈值 + 候选上限 + 命中早停
> 检索摘要：LLM 调用怎么降下来？三重优化——相似度 <0.5 直接跳过（不调 LLM）+ 候选上限 3 个 + 首候选命中即早停，每个知识点从 40→2 次 API，整体提速约 50 倍。

三个参数把 LLM 调用压下来：

| 优化 | 参数 | 效果 |
|---|---|---|
| 相似度阈值跳过 | `SIMILARITY_THRESHOLD=0.5`，低于直接跳过 | 大多数知识点根本不进 LLM |
| 候选上限 | `LLM_CANDIDATE_LIMIT=3` | 最多调 3 个候选 |
| 命中早停 | 首候选匹配成功即停 | 从 40→2 次 API（20 倍） |

**整体效果：约 50 倍提速**，LLM 调用从 500 万 → 2.7 万（降 99%）。

> 一句话面试答案："LLM 调用爆炸是因为全量遍历候选——40 次 API/知识点；三重优化（相似度<0.5 跳过、候选上限 3、命中早停）压到 2 次，整体提速约 50 倍、调用降 99%。"
