### 数据源整合：source 编码当跨图谱 join key
> 检索摘要：多数据集怎么打通？同一领域数据散在 4 个独立数据集（EduKG 0.1 图谱 / material.ttl 3.0 教材 / all_concept Class / meta 分类）且 ontology 版本不同，用知识点 source 编码（1.1.1.1.1）和教材章节编码（1.1）做前缀映射，不改模型就打通知识点↔章节。

数据不是"一个库"，同一领域的数据散在 **4 个独立数据集**而且 ontology 版本不同（0.1 vs 3.0），缺统一关联机制：

| 数据集 | ontology 版本 | 内容 |
|---|---|---|
| EduKG math | 0.1 | 知识点图谱 |
| material.ttl | 3.0 | 教材结构 |
| all_concept | - | Class 概念 |
| meta/math | - | Category 分类 |

整合方案对比（三选一）：
- **章节编码映射（低成本启发式，选它）**：知识点 `source=1.1.1.1.1` 与教材章节 `1.1` 做编码前缀映射，**不改模型就打通知识点↔教材章节**
- 统一数据模型（规范但重构大）
- SPARQL 整合（直接拉取，但耦合源）

> 一句话面试答案："多数据集整合用编码映射——知识点 source=1.1.1.1.1 和教材章节 1.1 做前缀匹配，不改模型就打通了知识点和章节的关系。"

> 证据：详见 `1.语雀/语雀-数据源与数据源清理.md`（§一·数据源整合）
