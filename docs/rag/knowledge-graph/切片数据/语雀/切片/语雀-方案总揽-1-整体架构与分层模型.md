### 1. 整体架构与分层模型

系统核心 = **两层图谱结构 + Neo4j 存储 + 离线构建/在线消费分离**，核心哲学为"**无限的业务事实**与**有限的权威结构**分存"：

```
┌─────────────────────────────────────────────┐
│ 语义层（EduKG 概念，有限）                     │
│   Concept(1295) / Statement(2932) / Class(39)│
│   关系: RELATED_TO / HAS_TYPE / SUB_CLASS_OF  │
└─────────────────────▲────────────────────────┘
          MATCHES_KG（匹配率 97.1%，教材↔概念）
┌─────────────────────┴────────────────────────┐
│ 教材结构层（人教 K-12 数学，真值）              │
│   Textbook(23) / Chapter(148) / Section(580)  │
│   / TextbookKP(1740)                          │
│   关系: CONTAINS / IN_UNIT                    │
└─────────────────────┬────────────────────────┘
         Neo4j 最终存储（bolt://81.71.130.57:7687）
         Python 离线构建 → CSV → 批量导入（MERGE 幂等）
         Java 页面化同步 → MySQL ai_edu_kg → 前端 SPA 读
         图谱关系（MATCHES_KG/PART_OF/RELATED_TO）直查 Neo4j
```

- **教材结构层**：从人教版教材（爬虫教师之家 + 数据生成）解析出的真实教学结构（学科→学段→年级→教材→章节→小节→知识点 6 层），节点带 URI，是"事实"。
- **语义层**：EduKG 开源概念（TTL v0.1 导入），Concept/Statement/Class，是"概念"。两层通过 `MATCHES_KG` 匹配连接（TextbookKP → Concept，置信度 ≥0.5，方向固定不可逆）。
- **计算与存储分离**：关系处理在 Python 内存/CSV 完成，"离线构建 → 批量导入"，Neo4j 只是最后仓库；`neo4j-admin import` 对 CSV 批量导入性能是 TTL 导入 10 倍以上（方案选型选 **方案 C：CSV→Neo4j**）。
- **权威图谱零写入**：EduKG 静态权威库冻结只读；业务派生数据（掌握度/点亮/题型）存 MySQL，无限业务事实永远不写权威图（后续 kp-matching-lightup 模块复用此原则）。
- **三端分工**：Python（edukg 管道 + ai-edu-ai-service 桥）离线构建 + 在线 API；Java（Spring Boot + MyBatis-Plus，双数据源）页面化接口 + 掌握度派生；前端（React SPA）三栏布局（树+图谱+详情）只读消费。
