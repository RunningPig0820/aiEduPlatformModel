### 11. 页面化与同步

- **方案 B（已拍板）**：Neo4j 知识点数据同步到 MySQL，前端 SPA 读 MySQL；图谱关系（MATCHES_KG/PART_OF/RELATED_TO 等）**不同步**，后续 Neo4j 直查（Redis 缓存 TTL 300s + 降级 `neo4jAvailable:false`）。
- **MySQL 表（8 张）**：4 张节点主表（`t_kg_textbook/chapter/section/knowledge_point`，**URI 主键** + status + merged_to_uri）+ 3 张层级关联表（含 order_index）+ 1 张同步记录表（edition/subject/stage/grade 维度 + reconciliation_status）。
- **同步策略**：手动按需触发（非实时/CDC）+ UPSERT（按 URI）+ 状态机 active/deleted/merged + 大事务（按年级拆分子任务 + 细粒度锁 `...:{edition}:{subject}:{stage}:{grade}`，失败仅影响该年级）+ 对账校验；URI 校验（以 `http://edukg.org/knowledge/` 开头）；6,757 节点预计 <10s。
- **双数据源**：`dynamic-datasource-spring-boot3-starter` 4.x + `@DS("kg")` 注解 + Mapper 包路径隔离；`/api/kg/**` → `ai_edu_kg`，其余业务 → `ai_edu_user` 物理隔离；HikariCP 每源 5-20 连接。
- **API 面**：教材列表/章节树/小节知识点/知识点详情（2 层父级）/年级知识体系/年级统计/Neo4j 健康检查/批量概念关联（Redis TTL 300s + 降级）。
- **前端**：React SPA 三栏布局（树+图谱+详情），React Flow 关系图谱（力导向；节点 >50 提供"简化视图"Top 10），树形导航逐级懒加载（6,757 节点不宜一次渲染），同步管理页面 + 系统统计面板。
