**场景1 数据源缺失/不可读**
> 检索摘要：图谱数据源读不到怎么办？某来源不可读如实标注不可读，不硬连；多来源（TTL/main.ttl/爬虫/课标）互补兜底。

| 属性 | 内容 |
|---|---|
| 触发条件 | TTL/教材 JSON/entities 某来源缺失或解析失败 |
| 当前处理 | 来源不可读标注，跳过该来源信息，不编造 |
| 兜底 | 四类数据源互补；爬虫断点续爬（--no-resume 重爬） |
| 风险 | 覆盖不全（小学初中 main.ttl 缺失靠爬虫补） |
| 证据 | 证据：语雀-产品中心-问题记录.md / design-textbook-crawler |

**场景3 双模型投票不一致**
> 检索摘要：DeepSeek 和 GLM 判断不一致怎么办？加权投票 DS=0.6/GLM=0.4，仅 DeepSeek=True 才可能过阈值（DS 否决），不一致时置信 ×0.7。

| 属性 | 内容 |
|---|---|
| 触发条件 | 匹配/前置推断时两模型结论不一致 |
| 当前处理 | 两模型一致 → 平均置信采纳；不一致 → 加权投票，DS 否决权，置信 ×0.7 |
| 兜底 | 前置投票不一致 → 不采纳；匹配不一致 → 走候选/人工 |
| 风险 | 系统性偏见双模型同向错 |
| 证据 | 证据：edukg/core/llm_inference/dual_model_voter.py:354-396 |

**场景4 维度不一致 v0.1 vs v3.0**
> 检索摘要：EduKG 版本数据不一致怎么办？TTL v0.1 与 main.ttl v3.0 数据不匹配，靠标签匹配容忍缺失，URI 版本前缀区分。

| 属性 | 内容 |
|---|---|
| 触发条件 | ttl v0.1 与 main.ttl v3.0 数据口径不一（同名实体属性缺失） |
| 当前处理 | 标签匹配容忍缺失；URI 版本前缀（v0.1/v3.0/v3.1）区分来源 |
| 兜底 | 权威图零写入，不污染 |
| 风险 | 属性覆盖率低 |
| 证据 | 证据：语雀-方案设计1/2/3.md |

**场景5 本地 embedding 内存过大**
> 检索摘要：本地 embedding 内存不够怎么办？bge 懒加载 3.5GB → 预构建索引仅 10MB（--use-prebuilt-index），numpy 单次检索 <5ms。

| 属性 | 内容 |
|---|---|
| 触发条件 | 每次匹配重新加载模型+建索引约 60 秒、内存 3.5GB |
| 当前处理 | 预构建一次（kg_vectors.npy 等 4 文件）、多次复用；内存约 10MB |
| 兜底 | checksum 失配回退懒加载 |
| 风险 | 索引过期 |
| 证据 | 证据：语雀-产品中心-问题记录.md / edukg/core/textbook/vector_index_manager.py |

**场景10 属性增强覆盖率低（22%）**

| 兜底 | 纯规则推断（difficulty/importance/cognitive_level/topic） |
| 风险 | 无 |
| 证据 | 证据：语雀-产品中心-问题记录.md |

**场景11 topic 继承偏差**

| 兜底 | 属性规则修正 |
| 风险 | 剩余未识别 topic |
| 证据 | 证据：语雀-产品中心-问题记录.md |

**场景12 图谱节点数过大（前端渲染）**
> 检索摘要：前端图谱节点太多怎么办？6,757 节点树形懒加载、React Flow 图谱 >50 节点简化视图（Top 10）、后端限制 ≤50 节点。

| 属性 | 内容 |
|---|---|
| 触发条件 | 前端一次性渲染 6,757 节点 DOM 暴增 |
| 当前处理 | 树形逐级懒加载（daisyUI Tree 不支持动态懒加载 → 自定义递归组件）；图谱后端返回 ≤50 节点 + 简化视图 Top 10 |
| 兜底 | react-window 虚拟滚动（可选）；状态缓存切换根节点清空 |
| 风险 | 图谱关系 API 未实现时替代方案 |
| 证据 | 证据：design-frontend-ui-front Decision 3/5/9 |

**场景13 Neo4j 不可用（图谱关系降级）**
> 检索摘要：Neo4j 挂了对前端影响什么？图谱关系直查降级——Redis TTL 300s 缓存 + neo4jAvailable:false 隐藏模块，不抛异常。

| 属性 | 内容 |
|---|---|
| 触发条件 | Neo4j 服务不可用/网络故障 |
| 当前处理 | Redis key `kg:neo4j:{uri}:{query_type}` TTL 300s；降级返回空关联 + `neo4jAvailable:false` 前端隐藏图谱关系模块 |
| 兜底 | `/api/kg/neo4j/health` 健康检查；批量概念关联避免 N+1 |
| 风险 | 缓存与实时数据不一致（300s 窗口） |
| 证据 | 证据：design-backend-ui Decision 5 |
