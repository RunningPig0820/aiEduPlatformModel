## 对账结论与使用建议

1. **面试口径建议**:对外讲"匹配率 ~97%、匹配链路 精确+向量+LLM 投票"是准确的;但**前置依赖的"三来源融合/年级倒置惩罚"是设计构想,主链路只产 LLM 推断结果**(fuse_results 未接入)——面试被追问"前置依赖怎么融合"要如实讲当前是 LLM 单路径 + 0.8 阈值,融合是设计目标非落地现状。
2. **匹配评审系统未落地**:D16 是方案,代码只有 candidate_review 字段——审核闭环是规划,不是已上线功能。
3. **在线查询标签坑**:api/kg.py 用 :Entity 而导入用具体标签,可能导致在线查不到数据——这是真实运维坑,面试可讲(J-KG10 关联)。
4. **canonical 文档校准**:`语雀-决策记录.md` 的 D8-D10(前置依赖融合/年级倒置)标了 ✅,实际部分未落地——建议按本对账把相关决策改为 ⚠️,或在对账表引用本文件。
