每节固定结构：`## 为什么（语雀）` → `## 怎么设计（方案）` → `## 落地真相（代码）` → `## 追问与防御` → `## 证据引用`。代码真相写 `文件:行号` 证据，方案与代码口径不一致处用 `> ⚠️ **翻转**` 标注。**权威 1.0 前置校验**：必须同时具备方案素材 + 对应主题分析文档落地真值，缺失代码证据禁止 1.0 降为 0.8。

**文件头固定 5 行标准（与语雀/3.代码 统一，2026-08-27 定）**：
```
> summary: 解答「{业务问题}」——{一句话说明如何解决，关键词密集，不写实现细节}
> 权威度: 1.0
> 模块: knowledge-graph
> COS路径: rag-source/knowledge-graph/完善文档/0N-{标题}.md
> 类别：{从 9 视角集合选 1}
```
节号（0N）只在文件名与标题体现，元信息头不重复。

**完善文档 vs 1.语雀（防混淆）**：完善文档 = 权威正文层（1.0，**整篇进全量池不切片**，直接当答案）；语雀 = 产品意图/设计决策层（0.8，切块进切片池，回答"为什么/权衡"，不能直接当答案）。检索规则：先正文层，正文答不了的"为什么/演进"才落语雀层。9 视角全覆盖：业务视角并入 01、数据存储并入 02（补存储拓扑表：Neo4j 7 类节点 / MySQL 同步表 / COS 向量索引）、业务流程=09 独立成节。

### 第 ④ 步：切片（提示词 + 大模型语义分组）

> **切片方式 = 提示词 + 大模型语义分组**（脚本方案已废弃）。切片统一落各来源 `切片/`。

- `切片清单.md` 定进库边界（多层：完善文档/语雀 canonical/design/代码，proposal 与原始问答不进）
- 代码层双切片：开发切片（业务链路/代码事实/坑与对账）+ 面试向切片（业务与流程/架构与技术取舍/落地问题与复盘），全落 `切片数据/代码/切片/`
- 坑档案双切片：一坑一文件（开发向 6 段原文 + 面试向复盘）
- 引导问题问答切片：一问题一文件逐问作答
- 语雀层按条目切（决策/选型/场景/阶段各一条一文件，术语表整表一块）
- OpenSpec 层按 `###` 切（一个决策/背景/目标/风险/迁移/开放各一小节一块；data-research 90KB 拆子块）

**切片统一规范（语雀/OpenSpec 层）**：
1. **头部精简 5 行**：`summary`（源检索摘要**原样完整保留**）/ `权威度` / `模块` / `COS路径` / `类别`（9 视角闭集单值）；**无 `> 状态` 行**（未落地/待决语义靠 检索摘要【未实现建议】标注 + 类别(未来演进) 兜底；素材层靠 `authority=0.7 + source=OpenSpec` 层规则兜底）。
2. **正文 `> 检索摘要` 必带**：每块 `### 标题` 后第一行 `> 检索摘要：{源检索摘要原样}`。
3. **机器元信息摄入时推导，md 头不写**：`entry_id` ← 文件名段（`语雀-决策记录-D#-*`→D#、`design-{change}-D{n}-*`→{change}-D{n}、子块 `-2/-3` 后缀）；`source_doc` ← 文件名前缀；`source/authority/module` ← 层配置。
4. **OpenSpec 决策编号归一化** `Decision #/决策 # → D{#}`；**100% 保留 Migration/Risks/OpenQuestions**；顶层 `# ==== 分节 ====` 不作 chunk；**WARNING 不自动生成**（退人工对账）。
5. **证据指针仅真实关联**：`> 证据：详见 {源文档}（§小节）`，禁止模板式占位抄写。
6. 一次处理 1 份文档；超长块按 `####` 拆子块（`-2/-3`）。

### 第 ④-① 步：问题列表 → 代码 guide_pool 同步 + 引导功能开发（写代码必做）
