# 组织中心 — 面试问题整理

> 模块定位：DDD 组织域，SchoolAggregate 聚合根 + school_user 关联表，以学校为权限管控基础单元。（无权限中心，权限由组织中心承载）
> 所属大纲段：1 项目介绍 / 2 项目如何操作（权限门）/ 4 数据关联 / 5 难点

## 1. 项目介绍

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 组织中心做什么？ | 以学校为权限基础单元，控制用户可访问功能范围 | "用户和学校怎么绑定？" → school_user 关联表 |
| 为什么用 DDD？ | SchoolAggregate 聚合根把学校业务规则收拢在一处 | "DDD 四层怎么分？" → Domain/Application/Infra/Interface |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 为什么不做真角色体系？ | demo 简化；数据隔离/权限管控靠组织中心，角色体系是后续扩展点 |

## 2. 项目如何操作（权限门）

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 权限怎么做到全局统一？ | 统一权限拦截器接口 + 各域 SPI 扩展 | "拦截器拦截什么？" → 按 school_id 限定功能范围 |
| 用户登录后怎么定权限？ | Spring Security 注入学校 ID，按学校→角色确定可访问范围 | "一个用户多学校？" → school_user 多关联 |

## 4. 数据如何关联

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 学校数据模型怎么设计？ | school（含学段 JSON 值对象）+ school_user 关联表 | "学段为什么 JSON 存？" → 数量少查询简单，需聚合再拆 |

## 5. 项目开发中有什么难点

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 迁移旧学校表怎么办？ | Flyway 渐进式迁移 + 软开关回滚 | "回滚怎么保证？" → 保留旧表，软开关控制新逻辑 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 学校权限和其他域权限不一致怎么办？ | 统一拦截器接口 + SPI 扩展，各域按需接入 |

## ⚠️ 最危险的可能问题（防御）

| 可能问题 | 防御要点 |
|---------|---------|
| 这是 Java 后端的事，和你的 RAG 有什么关系？ | 权限门/租户隔离是 RAG 的数据边界；页面权限标签来自组织中心 |
| DDD 是空架子吗？ | 讲清聚合根收拢规则 + 实际落地（school_user 表 + 拦截器） |
| 为什么没有权限中心？ | 权限由组织中心承载，权限中心未单列 |
