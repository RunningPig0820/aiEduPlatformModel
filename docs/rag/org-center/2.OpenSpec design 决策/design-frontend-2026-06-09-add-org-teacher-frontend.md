## Context

当前组织架构页面（DepartmentManagement.jsx）已完成部门树管理，左侧展示部门树，右侧展示教职工列表（Mock 数据）。后端已完成教职工 API 设计：OrgTeacher 实体只存储关联关系（userId, departmentId, schoolId），用户基本信息存储在用户域。

前端需要配合后端 API 实现教职工的完整 CRUD 交互，包括：
- 添加教职工：通过手机号查询/创建用户 + 创建关联关系
- 查看教职工：聚合查询返回完整信息
- 编辑教职工：只修改所属部门
- 删除教职工：只删除关联关系

## Goals / Non-Goals

**Goals:**
- 实现教职工添加功能：右侧抽屉表单，支持姓名、手机号、部门选择
- 实现教职工查看功能：右侧抽屉展示详情
- 实现教职工编辑功能：修改所属部门
- 实现教职工删除功能：确认删除，移除关联关系
- 实现按部门筛选教职工：点击部门树节点筛选列表
- 教职工列表展示：姓名、联系电话、学科（默认"未分配"）、职务（默认"教师"）

**Non-Goals:**
- 姓名/手机号模糊搜索（需要用户域支持，后续开发）
- 学科、职务字段的真实数据（后续接入任职任课模块）
- 用户信息编辑（需跳转用户中心处理）

## Decisions

### D1: 抽屉组件设计

**选择**: 使用右侧抽屉（Drawer）组件，与现有 DepartmentDrawer 保持一致的交互风格。

**表单字段**:
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 姓名 | 文本输入 | 是 | 新用户姓名 |
| 手机号 | 文本输入 | 是 | 11位，用于查询/创建用户 |
| 所属部门 | 下拉选择 | 是 | 树形下拉选择部门 |

**交互细节**:
- 选中部门后添加：部门字段自动预设，可修改
- 未选中部门添加：部门字段为空，需手动选择
- 手机号实时校验 11 位数字格式

**备选方案**: 使用弹窗 Modal。
**选择理由**: 抽屉交互与现有部门管理保持一致，用户体验统一。

### D2: 默认值处理

**选择**: 学科、职务字段在前端显示默认值，不调用后端接口。

**默认值**:
- 学科/专业：显示"未分配"
- 职务：显示"教师"

**选择理由**: 学科、职务属于"任职任课"模块，不在本次范围，使用默认值保证列表展示完整。

### D3: 搜索功能设计

**选择**: 目前只支持部门筛选（点击左侧树节点），不支持姓名/手机号搜索。

**选择理由**: 用户信息存储在用户域，模糊搜索需要后端宽表或用户域搜索接口支持，后续开发。

## Risks / Trade-offs

### R1: 后端 API 未就绪
- **风险**: 后端 `/api/org/teachers` 接口可能未完全实现
- **缓解**: 前端先使用 Mock 数据开发，API 就绪后切换真实调用

### R2: 用户域接口依赖
- **风险**: 添加教职工依赖用户域的用户查询/创建接口
- **缓解**: 后端聚合处理，前端无需直接调用用户域接口

### R3: 默认值展示
- **风险**: 学科/职务使用默认值，可能与后续任职任课模块数据冲突
- **缓解**: 后续接入任职任课模块时替换默认值逻辑
