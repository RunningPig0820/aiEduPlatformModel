一、核心诉求

  题型分析必须自动关联出知识点，不得出现空白。 学生贴一道题 → 识别题型 → 关联出该题涉及的知识点。如果 LLM
  不能自动、精准地完成「题目 → 知识点」映射，个性化学习的地基就不成立。

  二、当前问题（前端真实联调发现）

1. 空候选频繁（最核心，流程死穴）
+ 实测同一道「鸡兔同笼」5 次调用，4 次返回 candidates=[]
+ 学生没得选 → 流程断在「待确认」，死胡同
2. 关联质量不稳定（非确定性）
+ 同一文本多次调用结果不同：RESOLVED → 对数方程求解 / PENDING 空候选 / 候选内容每次波动
+ 根因：无数据锚时 LLM 自由猜测，题型识别→知识点 两段传递误差叠加
3. 错误关联（离谱）
+ 小学「鸡兔同笼」曾被关联到高中「对数方程求解」
+ 根因：候选未按学生年级锚定过滤，跨学段混选
4. vote 链路
+ 曾对 analyze 候选报 10003 → 已修（candidates 镜像校验）✓
+ 但依赖候选生成质量，候选空时仍无解
5. resolveKp 候选生成弱
+ 待确认清单确认依赖它，冷启动题型常返回空候选
6. 题型库为空
+ question-types total=0，聚合任务未沉淀 → 数据驱动权威命中路径未生效，全靠 LLM 猜
7. 搜索兜底未落地
+ 前端 KpSearchSelector 已就绪、已正确发 {keyword} 请求
+ 后端 POST /api/kg/knowledge-points 未支持 keyword → 搜索返回空
8. 冷调用慢
+ analyze 冷调用 curl 实测 ~5s，浏览器端偶发超 30s（前端 30s 超时截断）


三、解决思路（已对齐）

  核心转变：从「开放域自由猜测」→「封闭域约束选择」

  现状：题目 → LLM 凭空猜关联 → 猜不中返回空
  目标：题目文本 + 该生年级的全部教材知识点（label 池）
                       ↓
       LLM 约束选择：只能从池里挑最相关的 1-3 个
                       ↓
       恒返回 top-N（置信低也返回池内最相近，绝不空）

  关键点：

+ 年级锚定（后端
  resolveGrade(studentId)）：用学生年级的知识点池作候选集，顺带消灭「小学→高中对数」类错误
+ 池 = 该年级教材知识点 label 集（/api/kg/knowledge-points 已有全量数据，仅需按年级过滤/传入 LLM）
+ 结果恒非空：LLM 是「从有限选项里选」，不是「凭空想」，必然命中池内知识点

  四、给后端的具体待办（按优先级）

  P0（本次必须，打通闭环）

1. analyze 改造为「年级知识点池约束选择」：题目 + 年级池 → LLM 返回 top-N
  关联，保证不空（置信低也返回池内最相近候选）
2. 年级锚定过滤候选（resolveGrade 锚定，候选只在对应学段池内）
3. POST /api/kg/knowledge-points 支持 keyword：空候选时学生手动搜教材知识点确认（前端已就绪）

  P1（提升稳定性）

4. 候选稳定性：同文本多次调用结果尽量一致（当前波动大）
5. 聚合手动触发：联调时即时验证题型库沉淀（现在凌晨定时跑，看不到效果）

  P2（可选后续）

6. 管理端审核页面（你提到的「后端页面」）：一边学生题型、一边年级知识点，LLM 批量分析关联 + 人工校准 →
  喂题型库
