## 硬性规则（强制全部遵守）

### 术语强制统一
固定术语：canonical标准题型 / 派生层 / obs观测层 / 掌握度 / 解析管线 / 动态涌现 / 两域解耦。禁止自行创造别名。

### 状态判定标准（严格区分，禁止混淆）
- ✅【已落地设计】：代码可观测到实现逻辑；语雀文档描述+代码同时存在。
- ⚠️【建议项(未实现)】：仅语雀方案文档描述，代码无对应实现。
- ❓【待决策 Open Question】：语雀和代码均无明确结论。

> 边界场景的状态判定依据「当前处理」：✅=已处理(有落地逻辑或兜底)；⚠️=未处理/待补强(当前处理填"未处理"或依赖建议项)；❓=待决。

### 证据标注规范
1. 语雀来源证据：`证据：语雀-原文件-xxx.md`；引用总揽：`[总揽§X.X]`
2. 代码来源证据：优先写 `文件:函数名/类名`；无法获取真实行号时禁止编造虚假行号，写`文件:逻辑片段`。
3. 某类来源不可读（如 Java 代码无法解析），证据字段写`来源不可读，无有效证据`，禁止编造逻辑。

### 格式与内容约束
1. 移除全部对话、问答、来回讨论口吻；输出正式技术综述，禁止提问者/回答者视角。
2. 重要流程使用有序列表或者文本流程图；规则、阈值全部使用表格承载。
3. 同主题信息归并，一处讲透；总揽已详述内容直接引用章节标记。
4. RAG切片友好：**禁止宽横向大表作文档主体**；段落简短，避免大段无分割文本。
5. **禁止业务臆造，所有内容必须来自来源材料，没有来源就如实标记信息缺失。**
6. 引用本库内部文档标记：决策记录条目标记`D#序号`，其他文档引用写`D#X`。

### 条目型文档强制 RAG 块级结构（本文档必须严格执行）
1. 文档开头增加【文档说明】：说明编号用途、阅读提示；正文分块小节用于 RAG 检索；末尾附录总索引仅人工查阅。
2. **每一个边界场景一条一个 `### 场景N：业务场景名称` 独立 H3 小节**，适配按标题切片，一个场景 = 一个 chunk。
3. 每个 H3 小节顶部固定两行（**两行都必须输出，缺一不可**）：
   ```
   > 状态：✅/⚠️/❓
   > 检索摘要：xxx（1-2 句话提炼该场景核心业务语义，作为向量召回锚点）
   ```
4. 单场景内部使用**竖向窄属性小表**，固定字段：业务场景、触发条件、当前处理、兜底降级策略、残余风险。
5. 全部场景输出完毕，文档最末尾追加【附录：原始边界场景总表】，放完整原始宽表格；必须增加警告注释：`⚠️注意：向量切片不要依赖本表，业务检索请使用上面分章节单场景小节。`

### 输出前强制自检（不输出自检文本，只保证结果符合）
1. 是否区分 ✅/⚠️/❓ 状态，没有把建议项标记为已落地。
2. 所有代码相关条目是否附带证据，没有编造行号。
3. 是否删除问答对话口吻。
4. 是否出现术语别名。
5. 是否有重复内容，同类场景已经合并。
6. 文档顶部元信息完整，summary、权威度、模块、COS路径、类别字段齐全。
7. 是否没有把宽大表作为文档主体；**每个场景独立 H3、且 `> 状态` 与 `> 检索摘要` 两行都在**；附录总表存在并且有警告提示。

### 失败降级
某类来源完全不可读，直接跳过该来源信息，如实在证据字段标记，不编造内容。

## 提取范围（逐项核对）

1. 冷启动类：零题库、无预置题型池、首题建锚、题库空question-types=0
2. 数据异常类：跨年级、低置信、空候选、alias miss、两层PENDING、未命中题型
3. 基础设施类：向量桶挂、embedding失败、写入延迟(~10s)、COS权限不足
4. 质量类：关联错误、掌握度假低(首题答错)、归一误并、搜索兜底未落地
5. 交互类：学生恶意乱点、学生跳过、低龄不耐烦、vote报错

## 校验规则

1. 当前处理无实现则填写"未处理"，不要脑补逻辑；
2. 兜底降级必须写具体可执行路径，不能写"做降级处理"这种空话；
3. 残余风险如实写明，不要弱化风险；
4. 同类场景合并，禁止重复条目；
5. 合理分配场景编号，从1开始顺序递增；
6. 可以引用决策记录`D#X`。
