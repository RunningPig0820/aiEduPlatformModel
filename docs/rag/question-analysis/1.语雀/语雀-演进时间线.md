### 阶段0：原始诉求（可行性论证阶段）
> 状态：✅ 历史基线
> 检索摘要：项目初始可行性论证，明确核心约束：禁止业务数据污染教育局权威知识图谱，确立「分层隔离」设计前置诉求。

- 阶段时间：2026-08-24 语雀方案定稿前
- 核心形态：基于教育局官方Neo4j知识图谱，评估题目-知识点自动关联可行性
- 迭代翻转：项目起点，无前置版本
- 阶段详述：初始基线具备权威知识图谱底座（Neo4j+kg-sync镜像），但真实业务题目存在大量**图谱无覆盖题型、跨年级考点、非标题型**，无法直接绑定权威节点。核心风险：AI自动关联、自动补全题型知识点会**篡改、污染官方权威图谱**，因此立项核心诉求为：实现自动关联的同时，严格保证权威图谱只读、零写入。
- 关联决策：无（可行性论证阶段）
- 落地证据：语雀-方案设计1（可行性结论：可落地，核心方案为「业务派生层隔离」）

### 阶段1：派生层解析期（方案设计1 成型阶段）

- 阶段时间：2026-08-24（方案设计1定稿）
- 核心形态：分层隔离架构、解析管线、题型库飞轮、别名匹配、挂起队列、多层纠错保障
- 迭代翻转（相对阶段0）：
  1. 落地权威图谱只读约束，所有业务数据下沉MySQL派生层（D1）
  2. 定型题目解析四步管线，解决非标题型关联问题
  3. 搭建题型库、别名表、挂起队列，实现脏数据隔离
- 阶段详述：解决「权威图谱有限、业务题型无限」的核心矛盾，**严格隔离权威层与派生层**：权威教育局图谱永久只读不写入，所有题型派生、观测、关联数据全部落MySQL派生层。完整落地解析管线：镜像精确匹配→模糊匹配→年级题型库匹配→LLM消歧+挂起兜底。配套建设观测数据表、年级题型库、别名映射、异常挂起队列、六层纠错机制，形成可自迭代的题型识别闭环。
- 关联决策：D1、D9、D11、D17（前身）
- 落地证据：语雀-方案设计1、语雀-问题1

### 阶段2：掌握度题型化重构（方案设计2 核心重构阶段）
> 状态：✅ 完整落地
> 检索摘要：完成**掌握度核心范式翻转**，统计主体从知识点改为题型，淘汰劣质算法，落地可解释的累计平均正确率模型，定型学生学情数据底盘。

- 阶段时间：2026-08-24（方案设计2 问题1~3定稿）
- 核心形态：题型为唯一掌握度锚点、题型自举、累计平均正确率、多场景信号打折机制
- 迭代翻转（相对阶段1）：
  1. 掌握度统计主体：知识点 → 题型（D2）
  2. 掌握度算法：离散四档/MAX/EWMA → 连续可解释累计平均正确率（D3）
  3. 确立AI答疑为唯一有效学情信号来源（D12）
  4. 拆分双层PENDING状态，解决状态语义混淆（D14）
- 阶段详述：基于「学生学习本质是掌握解题题型模式」的认知，推翻原有知识点锚点统计方案。建立完整数据链路：题目采集→向量化识别→题型归一自举→掌握度聚合打分。废弃虚高、不可回查、不可解释的MAX、EWMA算法，统一使用**累计平均正确率公式**，实现学情分数可审计、可回滚、真实可信。针对答对、求助答对、答错等不同场景做题型维度信号打折，精细化学情计算。
- 关联决策：D2、D3、D4、D12、D14
- 落地证据：语雀-方案设计2-问题1、问题2、问题3

### 阶段3：动态涌现架构收敛（后端架构定型阶段）
> 状态：✅ 完整落地
> 检索摘要：淘汰预置题型池方案，实现**零锚点动态题型涌现**，完成两域解耦，关停高风险自动关联，域B题型知识点关联改为人工可控维护。

- 阶段时间：2026-08 后端决策收敛
- 核心形态：零锚点动态涌现、题型名向量聚类、两域解耦、域B独立只读维护、手动聚合触发
- 迭代翻转（相对阶段2）：
  1. 废弃编辑距离匹配、废弃预置题型池，实现无锚点动态自举（D5/D6）
  2. 聚集信号收敛为「题型名向量」单一核心信号（D6）
  3. 两域彻底解耦：域A题目-题型、域B题型-知识点完全隔离（D8）
  4. 关停高污染自动关联链路，域B改为ADMIN手动查表维护（D8）
  5. 移除定时聚合任务，改为手动触发（D10）
- 阶段详述：解决预置池固化、题型别名泛滥、自动关联脏数据污染等问题。支持**学生做题动态生成canonical标准题型**，无需提前题库预埋，通过向量最近邻自动归并同类题型。彻底拆分两大业务域：题目识别域、知识点关联域，阻断业务数据反向污染权威映射，大幅提升架构可控性与稳定性。

### 阶段4：代码最终落地现状（线上稳定版本）
> 状态：✅ 线上落地
> 检索摘要：架构完全代码落地，Python无状态四端点提供AI能力，Java负责数据聚合与落库，定型向量多索引架构、0.2聚集阈值；掌握度数据底盘（题目表+掌握表）与题型分析端点落地，同时暴露待优化边界问题。

- 阶段时间：2026-08-18 起（代码全量落地）
- 核心形态：Python stateless四端点、Java业务编排、向量多索引路由、0.2归并阈值、掌握度两表底盘、analyze-question 独立端点、别名合并
- 迭代翻转（相对阶段3）：
  1. 向量架构升级为多索引vector_type路由，适配未来扩容（D13）
  2. 标定安全归并阈值distance≤0.2，区分同型/异型题型
  3. 掌握度数据底盘落地：题目表+掌握表两表分离、掌握信号跟题目走、累计平均正确率（D18/D19，承接 D2/D3）
  4. 题型分析端点落地：analyze-question 独立 REST（纯分析不写 obs）、题目理解端口抽象（Java LLM）、别名合并 kp 重叠 ≥70%、图片多模态直看（D20/D21/D22/D23）
  5. 掌握信号契约收敛：mastery_signals 题型化 + 字段改名 kp_label→topic_label + mastery_snapshot 脱钩 + 题型名 prompt 稳定规范（D25/D26）
- 阶段详述：最终线上架构拆分前后职责：Python侧提供**无状态AI能力接口**（学科分类、题型理解、掌握度决策、向量读写），Java侧负责**业务编排、聚合计算、数据库落库**。通过实测标定题型归并阈值0.2，可精准区分同题型（0.077左右）与异型题型（≥0.33）。掌握度按「题目表（事实源）+ 掌握表（聚合结果）」两表落地，可追溯每道题证据；题型分析 `analyze-question` 独立成 REST，纯分析不写观测、浏览不产生学习信号。当前架构稳定可用，但暴露**开放域候选猜测、跨学段错配、空候选**等边界问题，对应封闭域约束为待落地建议项（D15/D27）。
