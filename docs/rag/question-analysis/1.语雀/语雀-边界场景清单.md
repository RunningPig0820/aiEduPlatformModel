## 一、冷启动类场景

### 场景1：零题库、无预置题型池
> 状态：✅
> 检索摘要：模块冷启动无预置题型池，依靠首条题目创建 canonical 锚点，向量近邻归并做动态涌现；风险为初始 canonical 命名受 LLM 输出影响发生漂移。

| 属性 | 内容 |
|---|---|
| 业务场景 | 零题库、无预置题型池 |
| 触发条件 | 新模块上线，没有任何预置题型分类 |
| 当前处理 | 动态涌现：第一条题建锚（canonical 由首见名/最高频名创建），后续题型名向量查最近邻归并（D6） |
| 兜底降级策略 | 字符规则先拦确定性变体（解/求前缀 + 全半角/空白归一）；首题建锚不立查 |
| 残余风险 | 冷启动初期 canonical 命名靠 LLM，可能漂移；题型名稳定性仅靠 prompt 约束 |

### 场景2：题型库为空（question-types total=0）
> 状态：⚠️
> 检索摘要：聚合任务未沉淀导致题型库为空，命中不到先验题型，解析链路降级走向 LLM 消歧或挂起，质量完全依赖 LLM 输出。

| 属性 | 内容 |
|---|---|
| 业务场景 | 题型库为空（question-types total=0） |
| 触发条件 | 聚合任务未沉淀，数据驱动权威命中路径未生效 |
| 当前处理 | 未处理（Java 侧聚合任务待沉淀） |
| 兜底降级策略 | 解析管线第②步题型库未命中 → 落 LLM 消歧（③）或挂起（④）；前端联调建议聚合手动触发即时验证 |
| 残余风险 | 全靠 LLM 猜，关联质量依赖 LLM 稳定性 |

### 场景3：首题建锚后立查近邻
> 状态：✅
> 检索摘要：向量 put 之后索引存在约 10s 异步生效延迟，建锚后禁止立刻查询近邻，避免联调误判向量写入失败。

| 属性 | 内容 |
|---|---|
| 业务场景 | 首题建锚后立查近邻 |
| 触发条件 | put 题型名向量后立即 query |
| 当前处理 | 已处理：put 后索引异步生效 ~10s，建锚后不立查（本身无近邻），留重试 |
| 兜底降级策略 | vector_store.py 注释"put 后约 10s 生效"；聚集编排容忍延迟 |
| 残余风险 | 联调期容易误判"向量没写进去" |

## 二、数据异常类场景

### 场景4：跨年级薄弱
> 状态：✅
> 检索摘要：掌握度绑定 canonical 题型，不绑定学生当前学年；年级只是展示与先验约束，允许跨年级真实薄弱信号保留，不能直接过滤丢弃。

| 属性 | 内容 |
|---|---|
| 业务场景 | 跨年级薄弱 |
| 触发条件 | 学生卡在低年级知识点（七年级卡四年级假设法） |
| 当前处理 | 掌握度按题型名（canonical）记，不绑定当前学年；年级只是展示维度 |
| 兜底降级策略 | 年级是强先验非硬规则，LLM 上下文 + 置信度可覆盖年级锚 |
| 残余风险 | 若按当前年级过滤候选会丢掉最有价值的跨年级信号 |

### 场景5：低置信关联
> 状态：✅
> 检索摘要：LLM 消歧置信度低时执行挂起 PENDING，不落掌握度，前端展示疑似待确认；注意区分低置信挂起与高置信幻觉错误。

| 属性 | 内容 |
|---|---|
| 业务场景 | 低置信关联 |
| 触发条件 | LLM 消歧 confidence 低 |
| 当前处理 | 挂起 PENDING（不落掌握度），进待确认队列（D11） |
| 兜底降级策略 | 前端渲染"疑似待确认"虚线态；低置信直接挂起不点亮 |
| 残余风险 | 低置信与"高置信但错"（高置信幻觉）不同——后者绕过低置信挂起 |

### 场景6：空候选（candidates=[]）
> 状态：⚠️
> 检索摘要：识别无候选返回空列表，Java 侧降级 PENDING，不调用掌握度接口；该问题需要 D15 封闭域约束方案补强。

| 属性 | 内容 |
|---|---|
| 业务场景 | 空候选（candidates=[]） |
| 触发条件 | 题型识别低置信/冷启动猜不出，无候选给前端 |
| 当前处理 | 空 topic_labels = Java 降级 PENDING |
| 兜底降级策略 | 前端展示候选/空态，到此为止，不查掌握度 |
| 残余风险 | 5 次调用 4 次空候选是流程死穴，需封闭域约束选择（D15 建议项）补强 |

### 场景7：alias miss（题型名不匹配）
> 状态：⚠️
> 检索摘要：analyze 返回原始题型名和掌握表 canonical 不一致，需要后端输出 canonical 做等值匹配，匹配失败静默展示未开始，容易造成学生困惑。

| 属性 | 内容 |
|---|---|
| 业务场景 | alias miss（题型名不匹配） |

| 兜底降级策略 | 后端保证返回 canonical；等号匹配查掌握度 |
| 残余风险 | 匹配不上静默降级显示"未开始"，学生困惑 |

### 场景8：两层 PENDING 混用
> 状态：✅
> 检索摘要：analyze 识别 PENDING 与 getMastery 掌握度 PENDING 语义分离，禁止前端共用同一个 status 变量，否则全部状态展示错乱（D14）。

| 属性 | 内容 |
|---|---|
| 业务场景 | 两层 PENDING 混用 |
| 触发条件 | 前端共用一个 status 变量判断 analyze 与 getMastery 的 PENDING |
| 当前处理 | 已定稿：两层分开判（D14）——识别层 PENDING 展示候选，掌握度层 PENDING 才是待确认 |
| 兜底降级策略 | 绝不共用一个判断变量 |
| 残余风险 | 若前端不遵守契约，状态展示全错 |

### 场景9：未命中题型（学生没做过）
> 状态：✅
> 检索摘要：掌握表查无该学生题型记录，前端渲染"未开始"灰态，要区分真实未做题与 alias miss 导致的假未命中。

| 属性 | 内容 |
|---|---|
| 业务场景 | 未命中题型（学生没做过） |
| 触发条件 | 该题型在掌握表查不到 |
| 当前处理 | 已定稿：显示"未开始"灰态（not 待巩固） |
| 兜底降级策略 | 明确"这个题型你还没做过题" |
| 残余风险 | 与 alias miss（false miss）需区分，前端不能吞掉后端 bug |

## 三、基础设施类场景

### 场景10：向量桶挂/未配置
> 状态：✅
> 检索摘要：COS 向量桶异常或配置缺失，向量层抛出异常，Java 桥可降级到字符规则；向量是增强能力，不阻塞主业务链路。

| 属性 | 内容 |
|---|---|
| 业务场景 | 向量桶挂/未配置 |
| 触发条件 | COS_VECTORS_* 未配齐或 COS 不可用 |
| 当前处理 | 懒加载抛 RuntimeError → 端点 500 → Java 桥降级 |
| 兜底降级策略 | Java 回退字符规则 + 原样落库，主链路（题目落库/掌握表/接口）不依赖向量 |
| 残余风险 | 归一退化为字符规则，语义同型变体裂行 |

### 场景11：embedding 失败
> 状态：✅
> 检索摘要：大模型 embedding 接口超时不可用，向量层抛出 500，Java 桥降级，主链路不受影响。

| 属性 | 内容 |

| 兜底降级策略 | 同上，Java 桥降级 |
| 残余风险 | embedding 是增强层，失败不影响主链路 |

### 场景12：COS 写入延迟
> 状态：✅
> 检索摘要：COS 向量写入存在异步生效延迟约 10 秒，业务侧禁止 put 之后立刻查询向量，编排层面容忍延迟。

| 属性 | 内容 |

| 属性 | 内容 |

| 残余风险 | 联调前需确认参数清单 |

## 四、质量类场景

### 场景14：关联错误（归错知识点）
> 状态：✅
> 检索摘要：LLM 或人工确认造成题型关联错误，具备多层纠错保障；最大盲区为高置信幻觉，模型自信输出错误结果，矛盾检测无法识别。

| 属性 | 内容 |
|---|---|
| 业务场景 | 关联错误（归错知识点） |
| 触发条件 | LLM 消歧选错 / 人工 confirm 错 |
| 当前处理 | 纠错 6 层保障（D1/D11 等）：权威图零写入、观测打标重判、掌握度 MIGRATED 打标不删、UNIQUE 去重、source 溯源、先验回流 |
| 兜底降级策略 | 冲突信号 4 源自动检测（decide 诊断/掌握度矛盾/年级分布异常/低置信）；自动修正保守 |
| 残余风险 | 高置信幻觉 + 系统性偏见组合盲区——LLM 自信地错绕过低置信挂起，且大家一致错时矛盾信号不触发 |

### 场景15：掌握度假低（首题答错）
> 状态：✅
> 检索摘要：题型第一道题目答错造成掌握度假低，采用题型前 N 题打分打折策略缓解，打折系数为经验标定。

| 属性 | 内容 |
|---|---|
| 业务场景 | 掌握度假低（首题答错） |
| 触发条件 | 题型第 1 题就答错 |
| 当前处理 | per-题型前几题打折：第1题 0.7/第2题 0.8/第3题起 1.0，打折作用于 score 不作用于结果（D4） |
| 兜底降级策略 | 打折防"第一题答错→题型 0%"假低 |
| 残余风险 | 打折系数可配置，标定靠经验 |

### 场景16：归一误并/漏并
> 状态：✅
> 检索摘要：向量距离落在阈值边界，采用保守阈值 0.2，策略宁可拆分不要错误合并；漏并依靠人工别名表补充。

| 属性 | 内容 |
|---|---|
| 业务场景 | 归一误并/漏并 |
| 触发条件 | 题型名向量距离在阈值边界 |
| 当前处理 | 归并阈值 0.2 保守（D7），宁可拆不误并 |
| 兜底降级策略 | "相遇(0.332)/行程"默认拆分；漏并后续人工/别名表补 |
| 残余风险 | 误并的题权重互相污染（累计百分比可容忍） |

## 六、掌握度底盘 & 题型分析（OpenSpec design 增量）

> 检索摘要：题型名未识别的题照常采集对错信号落题目表，归属确定后再聚合进掌握表，不因题型待定丢数据。

### 场景22：掌握度历史语义迁移（置信度 → 正确率）

| 属性 | 内容 |
|---|---|

| 当前处理 | 历史数据量小：旧值作初始正确率 + train_count=1；掌握表加列非删列，回滚无损（D18） |
| 兜底降级策略 | 若历史迁移有风险可退化为新表并行 |
| 残余风险 | 迁移后旧语义数值与新题混算，早期数值参考意义有限 |

### 场景23：embedding 维度绑定（索引维度建好后不可改）

| 属性 | 内容 |
