# question-type-mastery 技术设计

## Context

- **现状**：掌握度 = 题型 已确立（`kp-matching-lightup` 翻转）。但数据底盘是零散观测——AI 答疑 `decide` 顺带输出 `mastery_signals`，题型分析页 `analyze-question` 纯分析不落观测。**没有统一的题目记录、没有题型名的规范收敛、掌握度算不出可追溯的百分比。**
- **诉求**：掌握度业务含义通透——学生掌握的是**题型**（解题模式），不是知识点（教材概念）。要让学生看到「某题型 64%，练了 10 题，来源 AI/题库，可跳转看题目」。
- **现有资产**（复用）：
  - `POST /api/tutoring/ocr`（图片题识别文本）、`POST /api/kp/analyze-question`（贴题识别题型）、`POST /api/kp/resolve`（题型 label 解析候选）。
  - 腾讯 COS 已在答疑链路使用（`uploadQuestionImage` → COS → 多模态），向量化存储可复用同一 COS 账号，新增向量索引/检索能力。
  - 知识图谱（Neo4j）含教材知识点（`kpUri`/`kpLabel`）——本期仅展示，不参与派生。

## Goals / Non-Goals

**Goals:**
- 建立「题目 → 题型掌握」的完整数据底盘：采集 → 向量 → 聚类 → 聚合。
- 掌握度可追溯：每道题都有记录，掌握度 = 累计平均（可解释）。
- 掌握度页列表化：题型 / 来源 / 掌握程度% / 训练数 / 跳转题目。

**Non-Goals（本期明确不做）：**
- **题型↔知识点关联不做**——知识点不从题型派生覆盖度，知识点总览页仅展示知识地图（不标熟练度）。
- 题库建设（当前题库无题）。
- 学生确认关联 / 待确认清单确认 / 候选搜索（沿用 `kp-question-analysis` 的范围降级，转后续独立功能）。
- 管理端全局审核题型↔知识点。

## Decisions

### 1. 掌握度主体 = 题型（承接已有翻转，不重新讨论）

**已定**：掌握的是题型（鸡兔同笼），不是知识点（二元一次方程）。本期只升级数据底盘，不翻主体。

### 2. 题目来源：全入口采集，且是唯一证据源

所有入口的题目统一落库：
- AI 答疑（学生提问时的题目）——**唯一产生掌握信号**的入口；
- 题型分析页（贴题/拍题/粘贴图片）——记录题目，但**不产生掌握信号**（学生只是贴了题，没做）；
- 未来扩展：练习、题库做题。

**为什么这样设计**：掌握度必须可追溯。零散观测无法回答「这个题型练了几道、答对几道、从哪来」；全量采集后，掌握表每一行都有题目证据可回查（跳转题目）。

### 3. 掌握信号唯一来源 = AI 答疑，且打折

- 信号只在 AI 答疑产生：学生做一道题 → `decide` 输出对/错信号。
- **前几次打折（递进 70/80/100）**：学生刚开始做题时置信度低——第一题答对不代表会，第一题答错也不代表不会。打折让早期题目权重低，后期稳定。
- **提示后答对 = 50%**：学生先看思路/答案再答对的，算半掌握。

> 信号分映射：直接答对=100%×打折系数；提示后答对=50%×打折系数；答错=0%。打折系数按该题型训练数递进（第1题70%、第2题80%、第3题起100%）。

**需后端确认**：`decide` 当前输出的 `mastery_signals` 是否区分「直接答对 / 提示后答对」？若无，前端从「学生是否请求过答案再答对」推断，或后端在信号里加 `hinted` 字段。

### 4. 信号跟题目走，不跟题型走（关键设计点）

PENDING 题型（识别不出的题）**照常采集掌握信号**，先落在题目表；题型归属由聚类后定，**归属确定后再聚合进掌握表**。

**为什么**：PENDING 是「题型暂时没认出来」，不代表「题没做」——答对/答错的信号是确定的，不能因为题型待定就丢。若反过来（信号等题型确定才记），PENDING 高频场景下掌握度会大面积漏采。

### 5. 题型名统一 = 定时向量聚类（per 学生）

学生各入口产生的题型名可能是 alias（"相遇问题"/"行程问题"）。**定时任务**用向量匹配把同一学生的题型收敛成一个 canonical 名。

**为什么用向量而不用规则**：题型名是 LLM 生成的自由文本，无规范枚举；向量匹配对 alias 鲁棒。**误差可容忍**——因为掌握度是百分比聚合，个别题归错题型只影响该题权重，不造成整体语义崩坏。

**粒度：per 学生**。每个学生自己的题型别名收敛为自己的题型行；不做跨学生全局题型库（那是聚合任务的后续独立功能）。

### 6. 掌握程度 = 累计平均（每道题加权）

```
题型掌握表: { topicLabel | source(ai/题库) | mastery% | trainCount }

更新：new = old × (n/n+1) + score × (1/n+1)   // n = 当前训练数
      trainCount += 1
```

- 累计平均 = 历史正确率，可解释、稳定、不抖动。
- **一次作答算一次**（不做题目去重）——同一道题做两次，两次都计入训练数，反映真实练习量。
- 打折作用于 `score`（前几次 70/80/100 递减权重），不作用于结果——避免「第一题答错 → 题型 0%」的假低 / 假高。

### 7. 掌握度展示 = 列表列（题型/来源/掌握%/训练数）+ 跳转题目

掌握度页题型明细改为列式：
```
题型        | 来源 | 掌握程度 | 训练数 | 操作
鸡兔同笼     | AI   | 64%     | 10     | [查看题目]
行程问题     | 题库 | 80%     | 5      | [查看题目]
```

**为什么列式**：题型 + 来源 + 百分比 + 训练数天然是表结构，比卡片直观；「查看题目」直接命中「掌握度可追溯」的诉求。

### 8. `getMastery` 契约变更（BREAKING，需联调）

现有 `getMastery` 返回离散四档 `{0,25,50,75}` + status。本期改为**连续百分比** + 来源 + 训练数：

```js
// 请求不变：GET /students/{id}/mastery
// 响应 items[].masteryLevel 语义变更：0-100 连续百分比（原 0/25/50/75）
// 新增字段：source('ai'|'bank')、trainCount、topicLabel
```

**前端分桶展示**：连续百分比 → 徽标（如 <25 待巩固 / 25-50 练习中 / 50-75 / ≥75 已掌握），保留现有四档视觉。**知识点总览页不再消费本接口做覆盖度。**

### 9. 两层 PENDING 拆枚举，不混用

| 枚举 | 语义 | 取值 |
|---|---|---|
| `analyze-status` | 题型识别态 | `RESOLVED` / `PENDING`（题型没认出来） |
| `mastery-status` | 掌握度态 | `MASTERED` / `PRACTICING` / `CONSOLIDATING` / `NOT_STARTED`（练过与否） |
| `kp-status` | 知识点关联态 | `CONFIRMED` / `UNCONFIRMED`（本期断联，预留） |

**为什么**：`analyze-question` 的 PENDING（题型没认出来）和 `getMastery` 的 PENDING（题型练了但知识点待确认）语义不同，混用会导致「识别失败被当成待确认」。拆开后：识别失败 → 走候选/空态，不查掌握度；识别成功 → 查掌握度四态。

### 10. 题型↔知识点本期断联（明确收窄）

知识点总览页**保留展示但不再标熟练度**——仅展示知识地图，供演示入口。不做题型→知识点映射。

**为什么**：本期聚焦「题型掌握」这一层，知识点关联需要单独的数据底盘（题型→知识点映射表 + 确认机制），是独立功能；硬塞进来会让掌握度语义再次混淆。断联后：掌握度锚题型，语义最通透。

## Risks / Trade-offs

- [掌握信号依赖 AI 答疑] → 唯一信号源是 `decide`；题型分析只记录不产生信号。缓解：掌握度页「未开始」态引导去 AI 答疑做题。
- [提示后答对 50% 的信号后端未确认] → 需后端拍板 `decide` 是否输出 `hinted`；无则前端从「请求答案后答对」推断（有误差，可接受）。
- [向量聚类误差] → 题型名 alias 收敛有误差。缓解：掌握度是累计百分比，单题归错只影响权重；且聚类是 per 学生，影响面小。
- [getMastery 契约破坏] → 离散四档改连续百分比。缓解：前端分桶保留四档视觉；知识点总览不再消费，隔离影响。
- [知识点总览页数据源断联] → 本期明确为「仅展示、不标熟练度」，避免悬空承诺。

## Migration Plan

1. 后端：题目表 + 向量存储 + 定时聚类 + 掌握表聚合 + `getMastery` 契约变更。
2. 前端：掌握度页列式化 + 分桶映射 + 跳转题目；知识点总览去掉覆盖度着色；题型分析页不动。
3. 联调：AI 答疑做题 → 题目落库 → 聚类 → 掌握度百分比更新 → 掌握度页展示 → 跳转题目。
4. 回滚：掌握度页可回退到四档卡片；`getMastery` 契约加新字段而非删旧字段（向后兼容）。

### A. 命名：掌握度 → 题型掌握（已决 2026-08-18）

- **反馈**：掌握度页命名是否更贴切（曾考虑「学习记录」）。
- **决策**：定名「**题型掌握**」——保留「掌握」语义、明确主体是题型（vs 知识点），不引入「学习记录」（那对应未来的题目级记录页，B 已定后端分页）。**已实施**：导航 label、页面标题/副标题、错误态文案（routes.jsx + Mastery.jsx）。
- **不含**题目级时间线（本期定位纯题型聚合视图，题目明细留未来「学习记录」页）。

### B. 掌握度列表加分页（后端分页）

- **反馈**：掌握度列表需要分页。
- **决策（2026-08-18）**：**后端分页**——题型会越来越多（聚类后的 canonical 题型持续增长），前端全量拿到后渲染/切页会撑不住，锁定后端分页。
- **契约**：`GET /students/{id}/mastery?page=&size=` → `{ studentId, page, size, total, items }`；`total` 完整计数（RESOLVED + PENDING 拼接后分页）。**转后端**（tasks 4.5）。
- **前端**：请求式分页（翻页带参调后端），移除本地 `slice` 全量切页（tasks 12.2）。

### C. 摘要卡点击筛选（已掌握 / 练习中 / 待巩固）

- **反馈**：点击摘要卡「已掌握 / 练习中 / 待巩固」时，列表按该档位筛选。
- **方案**：摘要卡可点击 → 选中档位 → 前端按 `masteryBucket(level)` 过滤本地 items 展示。**纯前端，后端不改**。
- **交互**：未选中 = 全部；选中某档 = 只显示该档；再次点击取消筛选。

### D. 掌握度加时间列

- **反馈**：掌握度列表加「时间」列（最近练习时间）。
- **现状**：`getMastery.items[]` **已返回 `updatedAt`**（该题型最近一次作答时间）——后端已实现，无需加字段。
- **前端**：列表加时间列，展示 `items[].updatedAt` + 可按时间排序（新→旧）；题型分析页 9.1 标注如需也可消费同字段。
