## 业务描述与业务场景

**业务描述**：一次答疑/题型分析是**三方协作**的业务——学生在前端操作，Java 后端决定"要不要处理、怎么落库"，Python AI 服务负责"判断学科、认题型、出掌握度信号"。本节讲清三方各管业务的哪一块。

**业务场景**：
1. 学生点「发送消息」→ 前端触达 Java → Java 先过学科门（决定收不收数学题）→ 再调 Python decide（决定这轮怎么引导）。
2. 图片题在 Java 上传 COS 后交给 Python question-understand 认题型；文本题由 Java 自己用 KpQuestionAnalyzer 识别——业务入口不同，分工不同。
3. 题型归并 canonical、掌握度落库全在 Java；Python 只管"出信号、存向量"，故障时 Java 桥侧降级——分工决定谁的故障影响谁。

## 职责

Python（ai-edu-ai-service）本模块 = **纯智能四端点桥**：学科门/图片题型识别/掌握度信号输出/向量原语，全部无状态、不落库。
Java（aiEduPlatform）= 编排 + 决策（canonical 归并/掌握度计算/落库/防作弊）+ 前端契约。
**Python 显式禁止做题型↔知识点映射**（`models/tutoring.py:73-76`）。

## 高层业务调用链（前端→Java 编排→Python 六端点）

## 代码事实

### 端点清单（Python 全部端点 = 6 个，全走 `x-internal-token` 鉴权）

| 端点 | 形态 | 职责 | 出处 |
|---|---|---|---|
| `POST /api/tutoring/decide` | SSE 流式 | 决策：动作闭集 + 掌握度信号 | `api/tutoring.py:41-81` |
| `POST /api/tutoring/generate` | SSE 流式 | 按已放行 type 生成正文 | `api/tutoring.py:84-118` |
| `POST /api/tutoring/question-understand` | 同步 JSON | 图片题题型识别（无会话一次性） | `api/tutoring.py:121-133` |
| `POST /api/tutoring/subject-classify` | 同步 JSON | 学科门（decide 前置） | `api/tutoring.py:136-149` |
| `POST /api/tutoring/vector/put` | 同步 JSON | 存向量（key 相同 upsert） | `api/vector.py:30-50` |
| `POST /api/tutoring/vector/query` | 同步 JSON | 查最近邻 Top-K | `api/vector.py:53-81` |

### 失败语义分两种（关键分工设计，务必区分）

| 端点 | 失败语义 | 原因 | 出处 |
|---|---|---|---|
| decide / generate | 流中段失败 → `event:error`，HTTP 状态码不返回 | SSE 已开流 | `api/tutoring.py:70-72,107-109` |
| question-understand / subject-classify | **吞异常降级空结果**（空 labels / None subject） | 业务判定失败 ≠ 错误 | `api/tutoring.py:128,143-144` + core |
| vector put/query | **错误冒泡** → HTTP 400(ValueError)/500 | 基础设施，让 Java 感知失败再降级 | `api/vector.py:45-50,76-81` |

> 注释原文：向量不同于 question-understand 的"吞异常降级空结果"——**向量是基础设施，让 Java 感知失败**（`api/vector.py:8-9`）。

### 掌握度信号契约（decide 输出三档）

- `mastery_signals[].topic_label` = **题型名**（「鸡兔同笼」），signal 三档；`question_kps` 顺带知识点（`models/tutoring.py:93-97,119`）。
- 落库/映射/聚合全部在 Java；Python 只输出信号，不反查图谱（`models/tutoring.py:70-76 KpSnapshot` 注释）。

### 向量桥

- embedding：text-embedding-v3 + 显式 768 维（模型默认 1024，必须与索引维度一致）（`core/tutoring/vector_store.py:26-28`）。
- 桶按 `vector_type` 路由：topic 走默认桶，rag* 走 RAG 独立桶（`vector_store.py:106-118`）。

## 隐性坑与注意事项

- **put 后 ~10s 异步生效**：建锚后不立查、留重试（`vector_store.py:13` spike 实测注释）。
- **subject-classify 闭集外 → None，不是 other**：other = "明确非学科内容"，None = "不知道"；Java 按 math 放行，宁漏不误（`models/tutoring.py:212-216`）。
- **decide/generate 中段失败 Java 不可重试**，提示重发（`api/tutoring.py:93` 注释）——别把 error 事件当可恢复。
- **embedding 维度一旦建索引就不可改**：768 维必须与索引一致，否则写失败（`vector_store.py:27-28`）。
- **未知 vector_type → 400**：Java 传错逻辑名直接 400，不是 500（`api/vector.py:45-47`）。
- **is_new_question 短路**：Java 换题信号 → Python 直接 `type=switch` 不调 LLM，别误当决策错误（`models/tutoring.py:143`）。

## 设计要点

- **python 纯智能、Java 平台决策**：Python 管 LLM/embedding（无状态），Java 管数据/落库/编排。
- **失败语义按类型分化**：业务判定（学科门/题型识别）吞异常降级、不阻塞；基础设施（向量）冒泡让 Java 感知后降级——不是一刀切。
- **索引路由对 Java 透明**：Java 只传 `vector_type` 逻辑名，Python `settings.COS_VECTORS_INDEXES` 路由物理索引（`settings.py:99-105`）。
