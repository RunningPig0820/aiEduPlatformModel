## 业务描述与业务场景

**业务描述**：学生掌握的是**题型**（解题模式，如鸡兔同笼）而不是抽象知识点。系统在答题过程中判断 Ta 对每类题型练得怎么样，累计成可解释的掌握度（连续百分比），让"这个学生哪里薄弱"看得见。

**业务场景**：
1. 学生在答疑里做「鸡兔同笼」题——直接答对/求助后答对/答错被折算成信号，落进该题型的掌握度（第 1 题打折更保守），报表上可看「64%·练了10题」。
2. 下一次决策时，系统把学生已有掌握度快照塞回给 AI（薄弱题型排在前面）——AI 优先照顾不会的题，快照只是上下文，不会反过来污染题型名。
3. 学生在掌握度页看到列式的题型清单 + 训练数 + 可跳转原题——掌握度可追溯，不是拍脑袋数字。

## 职责

Python 只**输出掌握度信号**（三档 `mastered/practicing/struggling`），`decide` 每轮产出 `mastery_signals[].topic_label + signal`。0-100 累计平均计算在 Java（`ScoreMapper` + 掌握表）。

## 高层业务调用链（掌握度信号计算与落库）

```mermaid

    JAVA[Java 答疑编排] -->|每轮 decide| DEC[decide 决策]
    DEC -->|eval.correct + exercise_complete| E[Eval 软信号]

    DEC -->|answer_request_count| AR[Java 判断是否引导过 hinted]
    E -->|带题累加| ON[onRoundSignal correct+hinted 累计到当前题]
    MS -->|topic_label 题型| MG[掌握表 canonical 累计平均]
    ON -->|结算 ScoreMapper| SC{映射}
    SC -->|直接答对| S1[score=1.0]
    SC -->|引导后答对| S2[score=0.5]
    SC -->|答错| S3[score=0.0]

```

## 代码事实

- **mastery_snapshot 结构**：`KpSnapshot(kp_key, label, mastery_level: int 0-100)`；**kp_key 现在是题型名(canonical)，不是 TextbookKP URI**；注释明确 Python 不要拿 kp_key 反查图谱/做题型↔知识点映射。（`models/tutoring.py:70-79`）
- **信号枚举**：`MasterySignal(mastered/practicing/struggling)` 三档——不是四档百分比。`MasterySignalItem(topic_label + signal)`。（`models/tutoring.py:38-42,93-97`）
- **信号来源**：`Eval.correct`（对错）+ `exercise_complete`（是否独立解出）+ 换题短路无作答。（`models/tutoring.py:85-90`）
- **decide 提示词**：强调"mastery_signals 记录学生对题型的掌握度，不是知识点，知识点由后端根据题型派生"。（`prompts.py:78-83`）
- **快照回流 decide**：`snapshot_top_n` 按 `mastery_level` **升序**取 top-10（薄弱题型在前），让模型优先关注薄弱项 + 防撑爆上下文。（`core/tutoring/context.py:26-43,15-16`）
- **快照仅作上下文**：提示词"仅作上下文提示，不照抄为 mastery_signals 的 topic_label"。（`prompts.py:88-89`）
- **换题信号**：Java 换题 → `is_new_question=true` → 短路 `type=switch`，此时无 `eval.correct` 有效信号。（`decider.py:67-74`）

## 隐性坑与注意事项

- **topic_label 是题型不是知识点**：Python 输出题型名，否则污染后端题型库 → 掌握度/派生覆盖度/图谱点亮全脏。（`prompts.py:78-83`）
- **快照不是候选池**：`mastery_snapshot` 已脱钩（题型无法从知识点快照接地），仅作上下文提示，不要从快照挑 topic_label。（`prompts.py:88-89`）
- **信号只在 AI 答疑产生**：题型分析页只记题目不产生信号；PENDING 题型照常采信号先落题目表。
- **打折作用于 score 不作用于结果**：防"第一题答错→题型 0%"假低；每题型自己的第 1 题打折（per-题型 scoping）。

## 设计要点

- **掌握度主体=题型**：学生掌握的是解题模式（鸡兔同笼），不是抽象知识点；知识点由后端根据题型派生。（`models/tutoring.py:70-76` + `prompts.py`）
- **累计平均可追溯**：`new = old×n/(n+1) + score×1/(n+1)`，历史正确率可解释、稳定、不抖动；一次作答算一次（不做去重）。
- **信号跟题目走**：PENDING 题型照常采信号落题目表，归属确定后再聚合，不因题型待定丢数据。
