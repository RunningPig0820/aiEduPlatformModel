## 职责

Python 侧**无任何题型↔知识点映射逻辑**，且被显式禁止（`models/tutoring.py:73-76`）。图谱点亮是独立变更（kp-matching-lightup）；题型↔知识点关联放 Java 派生层（查表只读 + ADMIN 手动维护，域 B 独立化）。

## 代码事实

- **显式禁止映射**：`models/tutoring.py:73-76` KpSnapshot 注释"Python 不要拿 kp_key 反查图谱/做题型↔知识点映射（桥已移到后端 ADMIN 维护接口）"。
- **decide 顺带输出题目知识点**：`ActionMeta.question_kps: Optional[List[str]]`，模型读题顺手列，"可选、不要求每次必填"。（`models/tutoring.py:119`、`prompts.py:32-33`）
- **question-understand 顺带知识点**：从图片识别，`question_kps` 可空。（`question_understand.py:60-64`、`models/tutoring.py:176`）
- **相关表全在 Java learning 库**：`t_kp_question_type` / `t_kp_question_type_kp` / `t_kp_question_type_alias` / `t_kp_derived_obs`——Python 不触碰。
- **Neo4j 权威图谱**：只被"借结构"持 URI 向外展开，不污染权威图（派生层 MySQL 放映射）。

## 隐性坑与注意事项

- **Python 收 question_kps 但不能反查图谱**：`question_kps` 只是模型顺带输出，不送去匹配；匹配/映射全在 Java 派生层。（`models/tutoring.py:70-76,119`）
- **PENDING 语义更新**：getMastery `status=PENDING` 不再来自 obs，改为"题目记录有但 canonical 未归属"（Java 侧）。（refer 对账）
- **停用自动涌现链路**：obs 共现→自动关联、upsertPendingIfAbsent 挂起、学生 vote、聚合批处理、KpCoverageAppService 派生——已停用，前端已不消费。

## 设计要点

- **两域解耦**：域 A「题目→题型」（本期，掌握度）与域 B「题型→知识点」（独立维护）完全解耦，一个环节故障不影响另一个。
- **查表只读 + ADMIN 维护**：识别题型 → 查题型库（findByTopicLabelOrAlias → 分布桶）→ 命中返回权威分布/未命中返回"仅题型+canonical+空知识点"——不挂起、不写 obs、不顺带 LLM kps。（design Decision 10，Java 侧）
- **权威图谱零写入**：Neo4j 只被"借结构"（持 URI 向外展开），题型↔知识点放派生层 MySQL，权威图不被污染。（refer 对账）
