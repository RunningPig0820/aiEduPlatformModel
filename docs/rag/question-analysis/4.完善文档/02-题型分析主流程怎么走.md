# 02 题型分析主流程怎么走
> COS路径: rag-source/question-analysis/完善文档/02-题型分析主流程怎么走.md

> 模块=question-analysis｜节=02｜问题表=操作｜权威度=高（正文）

## 为什么（语雀）

学生贴一道题进来，系统要回答的不只是"这题怎么解"，还有"**这是什么题型、你现在练得怎么样**"。核心诉求（语雀-方案设计2-问题1）：题目 → 题型（识别）→ 当场判该题型状态（已掌握/练习中/待巩固/待确认），**不绕道知识点**。

## 怎么设计（方案）

**主流程三段：题目进来 → 题型识别 → 掌握度挂接。**

```
题目(贴题/答疑/图片) ──▶ subject_classify(学科门, decide 之前)
        │                    K12 十值闭集, 学科无关分类
        ▼
question_understand(题型识别) ──▶ status:
        │                          RESOLVED(题型确定) / PENDING(低置信, 给候选/空态)
        ▼ RESOLVED
题型名 → 向量最近邻归并 canonical("鸡兔同笼"→canonical, 不裂行)
        ▼
掌握表累计平均更新(trainCount++, mastery=old×n/(n+1)+score×1/(n+1))
        ▼
展示: 题型 | 来源(ai/题库) | 掌握% | 跳转题目  (掌握度页列式化)
```

**关键设计（方案口径）**：
- **两层 PENDING 必须分开**（语雀-方案设计2-问题1 坑2）：`analyze-question` 的 PENDING = "题型没认出来"（展示候选，到此为止，不查掌握度）；`getMastery` 的 PENDING = "题型已练、知识点待确认"。绝不用同一个判断变量。
- **alias 匹配收敛**（坑1）：`analyze-question` 返回的 topicLabel 必须是 canonical（和掌握表 key 同构），前端直接等号匹配查掌握度，否则"相遇问题"vs"行程问题"静默 miss。
- **未命中题型**（坑3）：该题型在掌握表查不到 = 学生没做过 → 显示"未开始"灰态，不假"待巩固"。
- **掌握信号唯一来源 = AI 答疑**：题型分析页只记题目、不出对错；掌握表只会被答疑链路的 decide 信号更新。

## 落地真相（代码）

> ⚠️ 代码实现口径：`subject_classify` 是新加的**学科无关分类**（decide 之前，K12 十值闭集，模型统一），先判学科再进题型链路；`question_understand` 输出题型 + status + candidates。题型名落库前过向量归并（`vector_type="topic"` 查最近邻），canonical 在**落库前**动态锚定，掌握表从源头不裂行。

- **调用链**：贴题/答疑 → `subject_classify`（学科门）→ `question_understand`（题型识别）→ 题型名向量归并 → 落题目表 + 掌握表。
- **状态枚举**：RESOLVED（确定）/ PENDING（低置信，冷启动猜不出，给 candidates）。
- **归并阈值**：distance ≤ 0.2 直接归并（保守，只并同型），"相遇(0.332)/行程"默认拆分。

## 追问与防御

**预期追问：题型分析页和 AI 答疑什么关系？**
→ **回答要点**：两个入口，一个数据底盘。答疑产生题目 + 掌握信号（对错），题型分析页产生题目 + 题型识别（无对错）。题目都落 `t_student_question_record`，掌握度只被答疑信号更新——分析页"贴题"不产生掌握度（学生没做，哪来的对错）。

**预期追问：识别错了怎么办（把"一元二次方程"叫成"解一元二次方程"）？**
→ **回答要点**：两层兜底——① 字符规则先拦确定性变体（"解X/求X"），② 题型名向量查最近邻归并到 canonical（同型 distance 0.026~0.096 远低于归并阈值 0.2）。识别低置信 → PENDING + 候选，不硬猜。

**预期追问：为什么掌握信号只能来自答疑？**
→ **回答要点**：掌握度 = 累计正确率，信号 = 答题对错。只有答疑链路有真实的答题行为（decide 判 eval.correct + 是否被引导）；题型分析页是"贴题分析"，学生没做题，无法产生对错信号，所以只记录题目。
