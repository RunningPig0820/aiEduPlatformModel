## 为什么（语雀）

题型动态聚集要用**向量检索**（cosine 最近邻），但腾讯 COS 向量检索**只有 Python/Go SDK，无 Java SDK**——Java 后端没法直调。且 embedding 密钥不能散到 Java。所以向量能力必须放 Python 侧，Java 经桥调用。

## 怎么设计（方案）

**架构核心 = Python 桥 + vector_type 路由。**

```
             Java 后端(aiEduPlatform)              Python AI 服务(ai-edu-ai-service)
┌─────────────────────────────────────┐        ┌──────────────────────────────────┐
│ 题目/答题信号                        │  HTTP   │                                  │
│   │ subject_classify 调用  ─────────┼────────▶│ subject_classify.py (学科门)     │
│   │ question_understand 调用 ───────┼────────▶│ question_understand.py (题型识别) │
│   │                                  │        │                                  │
│   │ TopicVectorStore 端口 ──────────┼────────▶│ api/vector.py put/query          │
│   │   (向量桥, 不碰 SDK)             │        │   → embed(dashscope 768)         │
│   │                                  │        │   → CosVectorsClient put/query   │
│   │ 掌握度落库(t_student_topic_      │        │   → vector_type 路由 topic-index │
│   │  mastery / question_record)      │        │                                  │
│   └─────────────────────────────────┘        └──────────────────────────────────┘
```

**关键设计**：
- **vector_type 必填路由**：每次 put/query 后端显式声明写/查哪个索引，无缺省、无跨索引查询。本期唯一合法值 `"topic"`（题型名向量索引）；`question`（相似题）/`rag` 纯配置占位。Python 内部 `COS_VECTORS_INDEXES` 路由表，将来加索引 Java 契约零改动。
- **Python 不感知 Java，Java 不感知 COS 基础设施**：Java 只知 `vector_type` 逻辑名，不知物理索引名；Python 管索引映射。改名只动 Python 配置。
- **embedding 复用 dashscope**（text-embedding-v3，768 维，显式 dimensions），不引入新密钥，不进 LLMFactory（语义不同，独立封装 vector_store.py）。
- **两域解耦**：域 A「题目→题型」只消费题目记录，域 B「题型→知识点」独立维护，一个环节故障不影响另一个。
- **鉴权统一**：向量端点走 `x-internal-token`（与 decide/question-understand 一致），snake_case 契约。

## 落地真相（代码）

> ⚠️ 代码口径：`vector_store.py` 是唯一核心向量模块（embed/put/query/_resolve_index）；`models/vector.py` 定义契约（vector_type 必填）；`api/vector.py` 两个端点。已交付（ai-edu-ai-service，241 测试绿）。

- **embed 链路**：dashscope OpenAI 兼容端点 → `text-embedding-v3` `dimensions=768`（默认 1024，不显式指定维度对不上）。
- **CosVectorsClient 签名**（spike 实测）：`query_vectors` 返回 `(resp, data)` 元组，命中在 `data["vectors"]`（非契约里的 `hits`）；`put_vectors` 后**索引异步生效 ~10s**（立即 query 返回空）。
- **distance 语义**：cosine，越小越相似。self≈0、同型 ~0.077、异型 ≥0.33。
- **失败语义 = 错误冒泡**（与 question-understand 相反）：向量是内部基础设施，Java 桥侧有降级（回退字符规则 + 原样落库），Python 正常抛 HTTP 错误码。

## 追问与防御

**预期追问：为什么向量要走 Python 桥，不 Java 直调？**
→ **回答要点**：① COS 向量检索无 Java SDK，只有 Python/Go；② embedding 复用 Python 现成 dashscope 配置，密钥不散到 Java；③ 后续 RAG 复用同一套向量基础设施。Java 只持 `vector_type` 逻辑名，不碰 COS。

**预期追问：向量挂了会拖垮主链路吗？**
→ **回答要点**：不会。向量是**增强层**：Java 桥 HTTP 超时短，失败回退字符规则 + 原样落库。主链路（题目落库/掌握表/接口）不依赖向量——聚集是落库前的优化，不是必要条件。

**预期追问：怎么保证归并质量（误并/漏并）？**
→ **回答要点**：阈值 = 粒度旋钮（distance ≤ 0.2 保守只并同型，"相遇/行程" 0.332 默认拆分，宁可拆不误并）。误并只影响个别题权重（累计百分比可容忍），漏并后续人工/别名表补。spike 实测同型/异型在 0.08~0.33 有清晰间距。
