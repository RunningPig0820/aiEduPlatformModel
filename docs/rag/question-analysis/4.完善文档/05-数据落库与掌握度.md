## 为什么（语雀）

掌握度要**有题目证据、能算百分比、能追溯**。旧方案只存"三档信号 max 单调不减"（mastered/practicing/struggling，答错不降分，置信度视角），算不出"练了几道、答对几道"。学生和家长要的是**题型行 + 来源 + 掌握% + 训练数 + 跳转题目**——可解释、可追溯。

## 怎么设计（方案）

**（方案口径，已演进）** 早期：掌握度按知识点 URI，max 单调不减。**已不是最终形态**——落地演进为题型口径 + 累计平均（见下）。

### 两张表隔离：题目表（事实源）+ 掌握表（聚合结果）

```
t_student_question_record        t_student_topic_mastery（改造）
  id, student_id                   id, student_id
  content（题目文本）                topic_key（canonical，唯一）
  source（ai/bank）                 topic_label
  topic_label（原始/归一）           mastery（连续 0-100，累计平均）
  score（0.0/0.5/1.0 × 打折）       train_count
  hint_count, answer_request_count  source（ai/bank）
  session_id, created_at            updated_at
```

- 题目表 = 事实源（每道题一条，对错信号 + 引导轮数，可回查）；掌握表 = 聚合结果（canonical key + 累计平均）。
- 隔离红利：改信号映射/打折系数 → 重算聚合即可，题目证据不丢。

### 掌握度 = 累计平均正确率

```
new = old × n/(n+1) + score × 1/(n+1)     // n = train_count
train_count += 1
```

- 一次作答算一次（不做去重，同一题做两次计两次训练数，反映真实练习量）。
- 不用 max 单调不减（答错永不降、会虚高）；不用 EWMA（难解释、难回查）。累计平均语义 = "做了 n 道题的正确率"。

### 掌握信号映射 + per-题型打折

```
直接答对（answer_request_count=0）→ score = 1.0
求助后答对（answer_request_count≥1）→ score = 0.5
答错 / 未完成                        → score = 0.0
× per-题型前几题打折: 第1题 0.7 / 第2题 0.8 / 第3题起 1.0（可配置）
```

- **打折作用于 score，不作用于结果**——避免"第一题答错 → 题型 0%"的假低。
- **打分 scoping = per 题型**（对每个题型，它的第 1 题打折）——学习新题型都是从不会开始。
- 掌握信号**唯一来源 = AI 答疑**（decide 输出，题型分析页只记题目不出对错）。

## 落地真相（代码）

> ⚠️ 代码口径：掌握度主体 = 题型（`mastery_signals[].topic_label` 输出题型名），`mastery_snapshot` 脱钩。题型名落库前过向量归并 canonical，掌握表**从源头不裂行**。

### 存储拓扑（数据存哪全景，回答"存哪个表/存哪"）

```
Python(ai-edu-ai-service)          Java(aiEduPlatform)               外部
  纯智能无状态不落任何业务库  ──▶   自己管数据: MySQL + Redis          Neo4j 权威图谱(只读)
   仅写 COS 向量桶(题型名向量)  ──▶  也在 COS 普通桶写 transcript      派生层 MySQL(应本属 Java)
```

| 数据 | 存哪 | 形态 | 谁写 | 用途 |
|---|---|---|---|---|
| 题目记录 | MySQL `t_student_question_record` | 一行一题（内容/source/score/引导计数/session_id） | Java | 事实源：回查原题、对错证据、题目页展示 |
| 掌握度 | MySQL `t_student_topic_mastery` | canonical key 唯一 + 连续 0-100 累计平均 + train_count + source | Java | 掌握度页分桶展示 + 回流 decide（mastery_snapshot） |
| 会话状态 | Redis（Java 侧） | 会话 3 态（ACTIVE/ARCHIVED/TERMINATED）+ 护栏计数 | Java | 断线重连不丢、轮次/答案次数控制 |
| 题型名向量 | COS 向量桶 `topic-index` | 768 维 embedding（text-embedding-v3） | Python put | 归并 canonical（distance≤0.2） |
| 题型↔知识点 | 派生层 MySQL（`t_kp_question_type` 等，Java learning 库） | 查表只读 + ADMIN 维护 | ADMIN | 域名 B：权威分布 |
| 权威图谱 | Neo4j（只读） | 借 URI 钩子不写入 | — | 知识结构锚点（域名，不受污染） |
| 答疑记录 | COS 普通桶（Java 侧） | transcript 每轮整写 | Java | 历史回看、训练闭环 |

- **Python 唯一"存储" = COS 向量桶**：metadata 透传不落库，不碰 MySQL/Redis/Neo4j。（`3.代码/分析-07-数据流与存储.md`）
- **两表隔离红利**：改信号映射/打折系数 → 重算聚合即可，题目证据不丢。

- **信号映射**：Java 侧从会话实体取 `answerRequestCount`（要答案次数）推断——直接答对 1.0 / 求助后答对 0.5 / 答错 0.0，**Python 不新增字段**（复用现有 decide 契约）。
- **两表**：题目表 `t_student_question_record`（事实源）+ 掌握表 `t_student_topic_mastery` 改造（加 source/train_count，mastery_level 语义从"置信度"改"正确率累计"）。
- **PENDING 语义**：getMastery 的 `status=PENDING` = "题目记录有但 canonical 未归属"（不再是 obs 挂起），未开始 = 不在 items[]。
- **getMastery 契约 BREAKING**：masteryLevel 0-100 连续百分比（原离散四档 0/25/50/75），前端分桶保留四档视觉（<25 待巩固 / 25-50 练习中 / 50-75 偏稳 / ≥75 已掌握）。

## 追问与防御

**预期追问：掌握度数值是怎么算出来的，可靠吗？**
→ **回答要点**：完整链路可追溯——每道题落题目表（score 生效分值 + 引导轮数 + 会话链接）→ 题型名向量归并 canonical → 掌握表累计平均（trainCount 计数）。"某题型练 10 道对 6 道 = 64%"是可直接解释的数字，不是拍脑袋。

**预期追问：答错会不会导致掌握度被误导性拉低（第一题就错）？**
→ **回答要点**：per-题型前几题打折——第 1 题答错只记 70%×0 = 0，但它只占一次训练数；后续题正确会把累计拉回。打折作用于单题 score 不作用于结果，防"假低"。

**预期追问：为什么不用 max 单调不减（答错不降）？**
→ **回答要点**：max 是**置信度视角**（"这个信号出现过最强的一次"），答错永不降会虚高，算不出正确率；累计平均是**正确率视角**（"练了 N 道的真实水平"），可解释、可回查、稳定不抖动。

**预期追问：掌握度和答疑/图谱的完整闭环？**
→ **回答要点**：答疑产生信号 → 题目落库 + 掌握表更新 → 题型掌握页展示（分页/分桶/查看原题跳回答疑会话）→ 回流 decide（mastery_snapshot 作背景）。图谱点亮是独立变更（kp-matching-lightup），答疑链路不直接写 Neo4j。
