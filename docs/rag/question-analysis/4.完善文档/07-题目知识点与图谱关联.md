# 07 题目知识点与图谱关联
> summary: 解答「题型和知识点怎么关联、与知识图谱什么关系」——两域解耦（A题目→题型 / B题型→知识点）+ 查表只读+ADMIN 维护 + 权威图谱零写入 + 跨年级薄弱展示。
> COS路径: rag-source/question-analysis/完善文档/07-题目知识点与图谱关联.md

> 模块=question-analysis｜节=07｜问题表=数据关联｜权威度=高（正文）

## 为什么（语雀）

学生做的是题（题型可测），但知识点（二元一次方程组）才是图谱/课程的锚点。早期方案想"自动把题型关联到知识点 + 共现聚合 + 自动维护闭环"，但**题型↔知识点业务不成熟**，自动关联引入 obs 状态机/聚合批处理/LLM 归纳 5 个环节，分散本期核心（题目→题型→掌握度），且容易污染权威图谱。

## 怎么设计（方案）

**（方案口径，已演进）** 早期：派生层自动关联——个体派生 `t_kp_derived_obs` + 聚合题型库 `t_kp_question_type`（带年级分布）+ 挂起队列 + 自动维护闭环 + 数据飞轮。**已调整**——本期域 B 独立化：**查表只读 + ADMIN 手动维护**，不做自动关联。

### 两域解耦

```
域 A「题目→题型」（本期，掌握度）          域 B「题型→知识点」（独立维护）
  题目落库 → 向量聚集 → 掌握表累计平均       题型库(t_kp_question_type) / 分布桶
  只消费题目记录，不依赖域 B                (t_kp_question_type_kp) / 别名表
  ↑ 一个环节故障不影响另一个，反之亦然       ADMIN 维护接口，入口只读
```

- **入口流程（analyze-question / 答疑 decide）**：识别题型名 → 查题型库（`findByTopicLabelOrAlias`）→ **命中返回权威分布 / 未命中返回"仅题型 + canonical + 空知识点"**——不挂起、不写 obs、不顺带 LLM kps。
- **独立逻辑 = ADMIN 维护接口**：题型 CRUD + 题型↔知识点分布绑定——演示手动配几条数据，入口查表即命中。是下期"题型库管理后台"的雏形。
- **停用自动涌现链路**：obs 共现 → LLM 归纳 ratio 的自动关联、`upsertPendingIfAbsent` 挂起、学生 vote 澄清、聚合批处理、`KpCoverageAppService` 派生（前端已不消费）。
- **PENDING 语义更新**：getMastery 的 `status=PENDING` **不再来自 obs**，改为"题目记录有但 canonical 未归属"。

## 落地真相（代码）

> ⚠️ 代码口径：Python 侧**无任何题型↔知识点映射逻辑**，且被显式禁止——`models/tutoring.py` KpSnapshot 注释"Python 不要拿 kp_key 反查图谱/做题型↔知识点映射（桥已移到后端 ADMIN 维护接口）"。（`models/tutoring.py:70-76`）

**Python 侧只做三件与知识点相关的事：**
- `decide` 顺带输出题目知识点：`ActionMeta.question_kps`（读题顺手列，"可选、不要求每次必填"）。（`models/tutoring.py:119`、`prompts.py:32-33`）
- `question-understand` 图片题顺带知识点（可空）。（`question_understand.py:60-64`）
- `mastery_signals` 稳定输出**题型**（不输出知识点）——知识点由后端根据题型派生。（`prompts.py:78-83`）

**图谱点亮（不在本模块，独立变更）**：`kp-matching-lightup` 承担，答疑/题型链路不直接写 Neo4j。相关表（`t_kp_question_type` / `t_kp_question_type_kp` / `t_kp_question_type_alias` / `t_kp_derived_obs`）全在 Java learning 库。

**跨年级**：掌握度按题型名（canonical）记，和"当前学年"无关；图谱 URI 全局（年级只是 URI 一部分），跨年级薄弱天生可展示。

## 追问与防御

**预期追问：题型和知识点怎么关联？（面试高频）**
→ **回答要点**：本期**查表只读 + ADMIN 维护**，不做自动关联——业务不成熟，自动关联引入 5 个环节（obs 状态机/聚合批处理/LLM 归纳/vote 澄清/派生覆盖度）且易污染权威图谱。入口识别题型 → 查题型库分布桶 → 命中返回权威分布 / 未命中返回空知识点。演进路线是题型库管理后台。

**预期追问：为什么不让答疑链路直接关联知识点？**
→ **回答要点**：① 权威图谱零写入是红线——关联错了会污染教育局图谱；② 题型↔知识点是"业务隔离"的派生数据（鸡兔同笼 → 四年级假设法 或 七年级二元一次方程组，年级相关），需要独立维护/审核；③ 答疑链路只负责"题目→题型→掌握度"，图谱点亮是独立变更（kp-matching-lightup）。

**预期追问：跨年级薄弱怎么处理？**
→ **回答要点**：掌握度按题型名（canonical）记，不绑定当前学年——学生七年级二元一次方程卡壳，落库的题型掌握度在低年级图谱也能展示那个薄弱节点。年级只是展示维度，不是数据边界。
