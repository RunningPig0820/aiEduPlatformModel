## 为什么（语雀）

MVP 只做"题目 → 题型 → 掌握度"最小闭环，把复杂度后置。但语雀方案勾画了一个**数据飞轮**愿景：答疑产生个体派生 → 共现沉淀题型库 → 题型库反过来喂变式题/错题分组/薄弱诊断 → 更多答疑。演进要有清晰边界——哪些现在不做、为什么，哪些将来做、怎么做。

## 怎么设计（方案）

**（方案口径，已演进）** 早期方案规划了"派生层自动关联 + 定时批量聚类 + LLM 归纳规范名 + 大数据语义聚类"。**已收敛**——本期明确三项 Non-Goal（自动关联/相似题/定时任务），其余按需演进。

### 本期边界（Non-Goal，刻意不做）

| 不做 | 为什么 | 将来要做的前置条件/风险 |
|---|---|---|
| 题型↔知识点自动关联 | 业务不成熟，改查表只读 + ADMIN 维护（域 B 独立化） | 需题型库数据积累 + 人工审核流程 + 年级锚准确；风险=错误关联经先验放大污染全体学生，故零写入红线不破 |
| 相似题检索 | 题目向量不落库（`question` 索引仅配置占位），是独立功能 | 需启用 `question` 索引（向量维度 768 与 topic 同款）+ 题目文本落库；零架构改动 |
| 定时批量聚类 | 面试项目不引入定时复杂度，改按钮手动触发（`@Scheduled` 已移除） | 需调度基础设施 + 幂等/断点续传；风险=批量误并与当前手动确认链路冲突 |
| 题库建设 | `t_question` 题库域与"学生作答记录"是两回事，无题库数据 | 需教材/题库数据源（企业级对接）+ `source=bank` 字段已预留；风险=题库题带固定题型可显著减少 LLM 猜名漂移 |

### 演进路径（将来做）

```
阶段 0（本期）  题目→题型→掌握度 + 动态聚集 + 两域解耦
阶段 1          题库引入(bank) + 相似题检索(启用 question 索引)
阶段 2          题型库管理后台(域 B ADMIN 维护界面化) + 题型↔知识点分布
阶段 3          学情分析/多维能力画像(概念理解/计算/逻辑/审题) + 家长/教师视图
阶段 4          大数据手段: 语义聚类(embedding 把近义题型名归成同一簇) + 派生层物化(扩展命名空间)
```

- **数据飞轮**：答疑产生个体派生 → 共现沉淀题型库 → 题型库喂变式题/错题分组/薄弱诊断 → 更多答疑。"题型库不是我们造的，是从答疑数据里长出来的"。（完整业务闭环 + 两域解耦见 `09-业务闭环与两域解耦.md`）
- **相似题检索**：题目向量不落库是本期收敛（非能力边界）——`question` 索引已配置占位，后续启用零架构改动。
- **题库引入**：`source=bank` 已入掌握表字段，题库题目带固定题型/知识点，减少 LLM 猜名漂移。

## 追问与防御

**预期追问：没有题库，掌握度靠什么兜底？**
→ **回答要点**：无题库正是**动态涌现**的用武之地——canonical 由学生第一条题建锚，后续题目向量最近邻自动靠拢。题型是长出来的，不是靠题库预置的。数据飞轮：答疑越多 → 题型库越准 → 变式/诊断越好 → 更多答疑。

**预期追问：什么时候引入题库？**
→ **回答要点**：掌握表 `source` 已预留 `bank` 口径，题库题目带固定题型/知识点，能显著降低 LLM 猜名漂移。但题库建设是独立工程（`t_question` 题库域），本期无题库数据，先从答疑/题型分析入口采集。

**预期追问：掌握度将来怎么更准（多维能力）？**
→ **回答要点**：阶段 3 演进——概念理解/计算/逻辑/审题多维能力画像，事件累计 + 多信号（`answer_request_count`/`hint_count` 引导量可做 `0.6^hint_count` 衰减）。量小先有趋势，量大后聚合更准。
