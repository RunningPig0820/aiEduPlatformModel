# 09 业务闭环与两域解耦
> COS路径: rag-source/question-analysis/完善文档/09-业务闭环与两域解耦.md

> 模块=question-analysis｜节=09｜问题表=业务流程｜权威度=高（正文）

## 为什么（语雀）

单看"题目→题型→掌握度"某一环是不够的——面试/业务方真正关心的是**整个业务闭环怎么转**：学生的一道题经历了什么，信号从哪来、落到哪、怎么回流成下一次的决策依据。更要紧的是**知识链路别被杂事污染**：题目可以无限多、题型可以动态长出来，但教材知识点是有限权威结构——一个故障必须不能影响另一个，这就是"无限业务事实与有限权威结构彻底分离"的核心哲学。

## 怎么设计（方案）

**端到端闭环全景（三入口汇入 → 识别两条线 → 落三处 → 回流一源）**：

```
题目入口(答疑对话 / 题型分析页贴题 / 图片题)
        │
        ▼
① 学科门(subject-classify, decide 之前) → 非 math 直接不放行
        ▼
② 题型识别：文本题 Java KpQuestionAnalyzer / 图片题 Python question-understand
        ▼
③ 题型名 → 字符规则 + 题型名向量最近邻归并 canonical（零锚点动态涌现）
        ▼
④ 落库：题目表(事实源) + 掌握表(累计平均) + 向量桶(题型名向量)
        ▼
⑤ 展示：掌握度页（题型 | 来源 | 掌握% | 训练数 | 跳转原题）
        ▼
⑥ 回流：mastery_snapshot 组装 → 下一次 decide 作背景（薄弱题型优先讲解）
```

**两域解耦（A 题目→题型 / B 题型→知识点，分工表）**：

| | 域 A「题目→题型」（本期核心） | 域 B「题型→知识点」（独立维护） |
|---|---|---|
| 职责 | 题目落库 → 向量聚集 → 掌握表累计平均，产出题型掌握度 | 题型库（`t_kp_question_type`）+ 分布桶 + 别名表，产出题型↔知识点权威分布 |
| 数据依赖 | 只消费题目记录，**不依赖域 B** | 入口查表只读 + ADMIN 手动维护，**不依赖域 A 对错信号** |
| 故障隔离 | 域 B 挂了，掌握度链路照跑 | 域 A 挂了，知识点展示分支不受影响 |

设计要点：
- **canonical 名是两域的对接缝**：域 A 产出的 canonical 题型名进别名表查域 B 映射，域 A 不碰图谱、域 B 不碰答题信号。
- **数据飞轮**：答疑越多 → 题型库越准 → 变式题/错题分组/薄弱诊断越好 → 更多答疑。"题型库不是我们造的，是从答疑数据里长出来的"。（`1.语雀/语雀-方案总揽.md（§1 两域解耦 / §3 业务流程）`）

## 落地真相（代码）

> ⚠️ **最大事实**：掌握度主体是**题型**不是知识点（`mastery_signals[].topic_label` 输出题型名），且 **Python 不落任何业务库**——落库/映射/决策全在 Java，Python 是纯智能无状态桥。域 A 是本期已落地的主链路，域 B 是查表只读 + ADMIN 维护的独立分支。

- **信号唯一来源 = AI 答疑 decide**：题型分析页只记题目、不出对错，掌握表只会被答疑链路的 decide 信号更新。（`3.代码/分析-01-题型分析完整流程.md`、`4.完善文档/05-数据落库与掌握度.md`）
- **链路各段分工**：学科门/图片识别/decide 信号/向量原语在 Python（`api/tutoring.py` 四端点 + `api/vector.py` put/query，全 `x-internal-token`）；编排/canonical 归并/掌握表累计平均/落库在 Java；mastery_snapshot 由 Java 从掌握表组装回传 decide。（`3.代码/分析-02-微服务分工.md` 端点表）
- **向量归并在落库前**：题型名过 `vector_type="topic"` 查最近邻（distance ≤ 0.2 归并），canonical 在落库前动态锚定，掌握表从源头不裂行。（`3.代码/分析-06-向量动态聚类.md`）
- **回流闭环**：`DecideRequest.mastery_snapshot: List[KpSnapshot]`（Java 从掌握表组装），Python 只排序取 top-10 薄弱在前作上下文。（`4.完善文档/05` 追问、`3.代码/分析-07-数据流与存储.md`）
- **域 B 独立化**：Python 侧**无任何题型↔知识点映射逻辑且被显式禁止**（`models/tutoring.py:73-76` KpSnapshot 注释）；入口 `findByTopicLabelOrAlias` 查表只读，命中返权威分布/未命中返空知识点，不挂起、不写 obs、不顺带 LLM kps。（`3.代码/分析-08-图谱与知识点关联.md`）
- **两线识别**：文本题 Java KpQuestionAnalyzer 识别；图片题 Python `question-understand`（失败降级空 labels → Java PENDING 走澄清卡）。（`3.代码/分析-04-题型识别与题目理解.md`）

## 追问与防御

**预期追问：整个业务闭环怎么走（一句话盘面）？**
→ **回答要点**：题目从答疑/贴题/图片进来 → 学科门筛掉非数学 → 识别题型 → 题型名向量归并 canonical → 落题目表（事实源）+ 掌握表（累计平均）+ 题型名向量桶 → 掌握度页展示可回看原题 → 掌握度快照回流下一次 decide——**讲题、记题、涨熟练、回看环环相扣**。

**预期追问：两域 A/B 怎么交互，故障真的互不影响吗？**
→ **回答要点**：靠 canonical 名对接——域 A 产出题型掌握度（只消费题目记录），域 B 查表只读 + ADMIN 维护（只消费题型库）。Python 被显式禁止做映射，所以域内故障只影响本段：域 B 挂，掌握度链路照跑；域 A 挂，知识点展示分支不受影响。**这是设计红线（两域解耦），不是口头承诺。**

**预期追问：数据飞轮是什么？为什么说题型库是长出来的？**
→ **回答要点**：答疑产生个体信号 → 落题目表/掌握表 → 共现沉淀题型库 → 题型库喂变式题/错题分组/薄弱诊断 → 更多答疑。canonical 由第一条相似题建锚（无题库、零锚点），后续向量最近邻自动靠拢——**不是靠教材预置，是从学生真实做题数据里动态涌现**。

**预期追问：两域为什么不合并成一个链路？**
→ **回答要点**：题型（无限、随 LLM 叫法漂移）与知识点（有限、教材权威）本质不同——合并会让"学生答错"污染权威图谱，且题型↔知识点有年级相关性（鸡兔同笼四年级=假设法 / 七年级=二元一次方程组），需独立维护/审核。拆开 = 权威数据零写入红线 + 故障隔离双保险。（`4.完善文档/07-题目知识点与图谱关联.md`）
