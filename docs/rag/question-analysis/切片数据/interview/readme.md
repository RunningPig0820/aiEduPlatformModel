# 切片数据 / interview（面试专项切片）

> 用途：**面试官提问 / 候选人介绍项目**专用 RAG 切片。与 `../代码/`（开发查问题用代码证据切片）分离，检索时按 `target: 面试项目问答` 过滤。
> 来源：`3.代码/分析-01~10.md`（权威 0.8），由 `处理方案/提示词/切片-面试分组-提示词.md` 生成。
> 状态：2026-08-27 建目录，分析-01 样例产出中，待批量。

## 与开发切片的区别

| 维度 | 开发切片（`../代码/`） | 面试切片（本目录） |
|---|---|---|
| 消费方 | 开发查问题/对账 | 面试官提问/候选人介绍 |
| 保留 | 文件:行号、API、枚举表（证据全） | 业务/流程/架构/踩坑/复盘（过滤代码噪声） |
| 对账 | 原始 markdown 对比表 | 提炼为自然语言复盘段落 |
| summary | 面向开发检索（接口/端点） | 面向面试检索（痛点/权衡/妥协） |
| 分组 | 业务链路/代码事实/坑与对账 | 业务与流程/架构与技术取舍/落地问题与复盘 |
| target 标签 | — | `target: 面试项目问答` |

## 与 完善文档（1.0 全量池）的分工（关键）

- **完善文档 1.0** = 面试主答案（整篇全量池，优先召回）——答"业务是什么/为什么"
- **面试切片 0.8** = 细节/踩坑/翻转事实补充——答"具体怎么做的/踩过什么坑/方案怎么翻转"
- **检索规则**：先 1.0 主答案，面试切片补深度；面试切片转述后必须带**证据指针**（详见 分析-0X / 完善文档 0X），追问可回源

## 生成方式

- 提示词：`../代码/处理方案/提示词/切片-面试分组-提示词.md`
- 每份文档 → 3 块（业务与流程 / 架构与技术取舍 / 落地问题与复盘）
- 批量：按提示词逐个处理 分析-01~10
