## 架构与技术取舍

### topic_hint 词表收敛（命名漂移的关键手段）
图片题型名是 LLM 看图输出的弱标注，会飘（鸡兔同笼/鸡兔同笼问题/假设法）。**topic_hint**（Java 传题型库 top-20 常用题型名）注入 system prompt 作为"参考题型名词表"，提示模型"优先从这些名字里选，词汇不足可自拟"——从源头压变体漂移。
- **有词表**（题型库有锚点）：用它收敛命名
- **冷启动**（题型库为空）：跳过词表，模型自拟题目名，后续动态涌现补

### 识别失败不是错误（空结果语义）
图片识别失败/解析失败/无法识别 → 返回**空 topic_labels**，Java 降级 PENDING 挂起走澄清卡（学生确认或跳过），**不编造题型名**。空结果 = 失败降级，不是错误——与学科门同理，业务判定失败 ≠ 故障。

### 两层 PENDING 语义分离（本模块最易踩的坑）
- **识别层 PENDING**："题型没认出来"（Python 空结果 → Java 挂起）——本模块只产生这一种
- **掌握度层 PENDING**："题型已练、知识点待确认"（在 Java）——别混
- 共用判断变量会导致前端状态展示全错

### 慢修复复用
视觉模型走"关思考 + 20s 超时 + 重试 0"——实测看图 1.2s 出答案，杜绝 32s+ 卡顿。与学科门同款慢修复护栏。

### 独立 stateless 一次性端点
图片识别是"贴题→结果"无状态请求，不从 decide 拆整个流程——单题分析独立端点，多入口（题型分析页/答疑）复用同一能力。

## 设计要点

- **topic_hint 词表收敛**：有锚点用词表压漂移；冷启动自拟动态涌现补。
- **识别失败不是错误**：空结果 → Java PENDING（低置信挂起走澄清卡），不编造题型名。
- **慢修复复用**：关思考 + 20s，看图 1.2s 出答案，杜绝卡顿。
- **独立 stateless 一次性端点**：单题分析无状态请求，多入口复用。
