## 架构与技术取舍

### 两类失败语义分治（本模块核心架构）
**业务判定（学科门/题型识别）= 吞异常降级空**：LLM 前置环节失败不是错误，快速返回空结果（宁返回空不阻塞）——Java 侧降级 PENDING / 按 math 放行。
**向量基础设施 = 错误冒泡**：embedding/COS 失败 → 错误，Java 桥侧降级（回退字符规则 + 原样落库）——向量是增强层，Python 正常报错便于定位。

### 慢修复护栏（性能防线）
学科判定/题型识别统一"慢修复"：**关思考 + 20s 超时 + 关 SDK 重试**——慢/失败快速返回空结果，不让调用方无限等。开思考实测 50~145s、关思考秒出——前置判定不能成为答疑链路新卡点。

### 确定性优先
关思考 + 重试 0 + 兜底，**宁可略降精度也要秒回 + 不阻塞**。结构化四段降级：function calling → JSON mode → 正则提取 → 兜底 type=hint degraded=true。

### decide/generate 降级链路
- **decide 流式失败** → 降级非流式 decide()（四段管线），该次无 thinking 展示
- **generate 空流兜底**：0 token 时输出固定引导话术，学生不收到空回复
- **非流式主路径**：关思考 mini 偶发不走 tool_call 直接吐 JSON 也有 content 兜底解析

### 向量增强层哲学
主链路（题目落库/掌握表/接口）**不依赖向量**——向量挂了只是归一退化为字符规则 + 原样落库，不阻塞。COS 未配置 ≠ 不可启动：懒加载保证 endpoints 可加载，调用时才失败。

## 设计要点

- **两类失败语义分治**：LLM 前置（学科门/题型识别）= 吞异常降级空；向量基础设施 = 错误冒泡。
- **慢修复是性能护栏**：题型识别/学科门不能成为答疑链路新卡点。
- **确定性优先**：关思考 + 重试 0 + 兜底，宁可略降精度也要秒回 + 不阻塞。
- **degraded 监控**：Java 依 degraded=true 监控 Python 降级频次，排查是降级不是 bug。
