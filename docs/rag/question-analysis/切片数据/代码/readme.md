## 二、切片（语义分组，LLM 切分）

> **切片方式 2026-08-27 改为提示词 + 大模型**：语义分组（判断哪些节该合并）是模型擅长的事，硬编码脚本前缀规则易踩坑（h3/同组合并边界）——改用提示词让模型按语义切，更准、可复现。提示词：`处理方案/提示词/切片-分组-提示词.md`。

**同一份源文档产出两套切片（双输出，服务两个目标）**：

| 切片 | 分组（每份 3 块） | 输出位置 | 消费方 |
|---|---|---|---|
| **开发切片** | 业务链路 / 代码事实 / 坑与对账（原文拼接） | 本目录 `代码/` | 开发查问题/对账 |
| **切片（面试向）** | 业务与流程 / 架构与技术取舍 / 落地问题与复盘（过滤代码噪声+转述） | `切片/`（与开发切片并列） | 面试官提问/候选人介绍 |

**开发切片**（本目录 30 块）：每份按语义合并 3 块（业务描述+职责+调用链 → 业务链路；代码事实+设计要点 → 代码事实；隐性坑+对账 → 坑与对账），丢弃标题行/文件头/已读清单；只合并不改写正文，块内保留子标题层级，表格/mermaid 不切破。保留文件:行号/API/枚举表等全部证据。

**切片（面试向）**（`切片/`，30 块）：面向面试提问重分组，过滤文件路径/行号/API/枚举表，对账表转自然语言复盘（每条 ⚠️翻转/✅落地 结论句保留），mermaid 完整保留，summary 短标题式（`{主题}{块名}`），头部去 权威度/模块（保留 summary/来源/锚点/节/COS路径/类别/target），每块带证据指针（可回源分析-0X/完善文档）。详见 `切片/readme.md`。
