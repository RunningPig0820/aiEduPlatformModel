## 业务描述与业务场景

**业务描述**：题型（解题模式）与教材知识点（课程概念）是两个不同实体：**掌握度锚题型**，题型↔知识点的关联映射独立维护，两者互不污染——这样「我会鸡兔同笼」和「鸡兔同笼对应教材哪个知识点」是两条干净的业务线。

**业务场景**：
1. 学生在知识点总览页看知识地图、题目命中题型后想关联到教材概念——映射来自运营后台手动维护（域 B 独立），AI 服务不碰图谱，不脏化权威数据。
2. 语法调用只"顺带"输出题目知识点（question_kps）作展示；真正的题型↔知识点映射在 Java 派生层查表只读，使命中则给权威分布、未命中则空知识点待补。
3. 答题信息不出现在 Neo4j 权威图谱上——图谱只被"借结构"展开，衍生关系全在 MySQL 派生层，坏了不波及时权威数据。
