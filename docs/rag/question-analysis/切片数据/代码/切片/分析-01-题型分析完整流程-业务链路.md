## 业务描述与业务场景

**业务描述**：学生把一道题发到 AI 答疑/题型分析页，系统要认出是什么题型、判定学科、记录掌握度——「题目→题型→掌握度」就是本节代码支撑的完整业务闭环。

**业务场景**：
1. 学生在答疑页拍一张数学题图片或贴文本，期望先被判定是不是数学题（非数学直接拒），再被认出题型（鸡兔同笼/相遇问题），答题过程中记录 Ta 对这类型题的掌握程度。
2. 学生在题型分析页贴题/拍题，期望直接得到「题型 + 关联知识点」清单，识别不出时进入待确认（PENDING）而非死胡同。
3. AI 答疑每轮答题后，期望系统把「这次答对/答错/求助后答对」折算进该题型掌握度，下一次决策时优先关注薄弱题型。

## 职责

一道题从学生发起 → 题型识别 → 掌握度信号的**端到端链路**。Python 侧是 stateless 四端点（信号源 + 向量原语），由 Java 编排；掌握度/canonical/落库在 Java。

## 高层业务调用链（题目→题型→掌握度信号）

```mermaid
flowchart TD
    FE[前端 AiQa.jsx / 题型分析页] -->|贴题/拍题| JAVA[Java 编排]
    JAVA -->|① decide 前置| SC[subject-classify 学科门]
    SC -->|非 math/subject 空| MATHGATE[跳过: 仅支持数学 不建会不落库]
    SC -->|math 文本题| ANALYZER[Java KpQuestionAnalyzer 自研识别题型]
    JAVA -->|图片题| QU[question-understand 看图 → topic_labels+question_kps]
    QU -->|空 labels| QUFAIL[失败/识别不出 → Java 降级 PENDING 挂起]
    ANALYZER -->|题型名| VEC[vector query 最近邻归并 canonical]
    QU -->|题型名| VEC
    VEC -->|distance≤0.2 归并| MERGE[落 canonical 归并]
    VEC -->|无近邻| NEWANCH[首题建锚 动态涌现]
    JAVA -->|答疑每轮| DECIDE[decide SSE → meta ActionMeta]
    DECIDE -->|mastery_signals 题型三档| APPLY[Java 落题目表 + 掌握表累计平均]
    DECIDE -.原始流失败.-> DECIDEFALLBACK[降级非流式四段管线]
    DECIDE -.换题信号.-> SWITCH[type=switch 短路 不调LLM]
```

**文字复述链路**：前端贴题/拍题 → Java 编排 → ① decide 前置先过 subject-classify 学科门（非 math 或 subject 空直接跳过，仅支持数学，不建会不落库）→ 文本题走 Java `KpQuestionAnalyzer` 自研识别题型、图片题走 Python `question-understand` 看图得到 topic_labels+question_kps（空 labels 即失败/识别不出 → Java 降级 PENDING 挂起）→ 题型名进入 vector query 最近邻归并 canonical（distance≤0.2 归并落 canonical / 无近邻首题建锚动态涌现）→ 答疑每轮 decide SSE 输出 meta ActionMeta，mastery_signals 题型三档由 Java 落题目表 + 掌握表累计平均；decide 原始流失败降级非流式四段管线、换题信号 type=switch 短路不调 LLM。
