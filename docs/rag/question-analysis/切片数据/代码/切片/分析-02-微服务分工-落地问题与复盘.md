## 隐性坑与注意事项

1. **题型名向量写入有 ~10s 异步延迟**：建锚后不立查、留重试——COS 向量索引异步构建。
2. **学科判定闭集外 → 空，不是 other**：other = "明确非学科内容"，空 = "不知道"；Java 按 math 放行，宁漏不误。
3. **流式接口中途失败不可重试**：decide/generate 流中段失败 → 错误事件，提示重发——别把错误事件当可恢复。
4. **embedding 维度一旦建索引不可改**：768 维必须与索引一致，否则写入失败。
5. **换题短路不是决策错误**：Java 换题信号 → 直接返回 switch 不调 LLM，别误当故障。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**掌握度主体翻转：知识点 URI → 题型**
原始方案掌握度基于知识点 URI；落地改为**题型（canonical 题型名）**。影响：学生掌握的是解题模式，题目可聚可打分可观测，落库不裂行。

**掌握度数值翻转：离散四档 max 单调不减 → 连续 0-100 累计平均**
原始方案三档 max 单调不减（答错不降）；落地改为**连续累计平均**。影响：可算"练了几道、对了几道"，答错真实反映，不虚高。

**canonical 来源翻转：预置题型池 → 动态涌现**
原始方案预置题型池；落地改为**首题建锚、向量最近邻靠拢**。影响：无题库也能跑，题型从做题数据里长出来。

**字符归一翻转：编辑距离 ≤1 近字归并 → 移除**
原始方案用编辑距离近字归并；落地**移除**（"一元一次/一元二次"一字之差与错别字同为距离 1，无法区分会误并），全交向量层。影响：语义最近邻正确区分"一次/二次"、归并"方成/方程"。

**题型↔知识点映射职责：Python 桥 → Java（✅落地）**
原始方案 Python 做映射；落地 Python 显式禁止（代码注释明确"Python 不要反查图谱/做映射"），映射移到 Java ADMIN 维护接口。影响：权威图谱零写入红线，域名 B 独立化。

**decide 契约 BREAKING：非流式 JSON → SSE 流式**
原始契约是非流式 JSON；落地改 SSE 流式。影响：前端逐步收 token，体验更好但属 BREAKING 变更。
