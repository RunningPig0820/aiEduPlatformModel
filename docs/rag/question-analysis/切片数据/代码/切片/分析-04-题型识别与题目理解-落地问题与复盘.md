## 隐性坑与注意事项

1. **识别失败不是错误**：空结果 → Java PENDING（低置信挂起走澄清卡），不编造题型名。
2. **两层 PENDING 分开**：识别层 = "题型没认出来"；掌握度层 = "题型已练、知识点待确认"。Python 只产生前者（空结果），后者在 Java。
3. **"知识点："行要单独拆**：识别输出里混进 topic_labels 会把知识点当题型——解析时单独拆行。
4. **topic_hint 冷启动跳过**：题型库为空时不注入词表，模型自拟题目名动态涌现。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**文本题识别职责确认（✅Java 承担）**
原始方案未明确文本题由谁识别；落地 Python 无此端点，Java 自研识别器承担。影响：跨端边界清晰——Python 只管图片题 + LLM 决策，文本题识别归 Java。

**WEAK 状态翻转：曾返回 RESOLVED conf=70 → 空 labels=Java PENDING**
原始设计曾有"WEAK 置信返回 RESOLVED conf=70"的口径；落地 Python 不判置信度，识别不出直接返回空，Java 降级 PENDING。影响：低置信不再冒充已解决，走澄清卡更诚实。

**题型名上限对齐（✅落地）**
Python 题型名上限 5（`_MAX_TOPIC_LABELS=5`）与 Java 自研识别器 1~5 一致。影响：两端契约一致，不出现一 5 一 3 的错位。

**topic_hint 词表落地（✅落地）**
设计建议 topic_hint 词表；落地为 system prompt"参考题型名词表"注入。影响：命名收敛从源头做起，变体漂移被压低。
