## 业务描述与业务场景

**业务描述**：学生掌握的是**题型**（解题模式，如鸡兔同笼）而不是抽象知识点。系统在答题过程中判断 Ta 对每类题型练得怎么样，累计成可解释的掌握度（连续百分比），让"这个学生哪里薄弱"看得见。

**业务场景**：
1. 学生在答疑里做「鸡兔同笼」题——直接答对/求助后答对/答错被折算成信号，落进该题型的掌握度（第 1 题打折更保守），报表上可看「64%·练了10题」。
2. 下一次决策时，系统把学生已有掌握度快照塞回给 AI（薄弱题型排在前面）——AI 优先照顾不会的题，快照只是上下文，不会反过来污染题型名。
3. 学生在掌握度页看到列式的题型清单 + 训练数 + 可跳转原题——掌握度可追溯，不是拍脑袋数字。

## 职责

Python 只**输出掌握度信号**（三档 `mastered/practicing/struggling`），`decide` 每轮产出 `mastery_signals[].topic_label + signal`。0-100 累计平均计算在 Java（`ScoreMapper` + 掌握表）。

## 高层业务调用链（掌握度信号计算与落库）

```mermaid
flowchart TD
    JAVA[Java 答疑编排] -->|每轮 decide| DEC[decide 决策]
    DEC -->|eval.correct + exercise_complete| E[Eval 软信号]
    DEC -->|mastery_signals[topic_label+signal]| MS[掌握度信号 三档]
    DEC -->|answer_request_count| AR[Java 判断是否引导过 hinted]
    E -->|带题累加| ON[onRoundSignal correct+hinted 累计到当前题]
    MS -->|topic_label 题型| MG[掌握表 canonical 累计平均]
    ON -->|结算 ScoreMapper| SC{映射}
    SC -->|直接答对| S1[score=1.0]
    SC -->|引导后答对| S2[score=0.5]
    SC -->|答错| S3[score=0.0]
    S1 -->|× 打折 per 题型第1题0.7/第2题0.8/第3题起1.0| DISCOUNT[new = old×n/(n+1) + score×1/(n+1)]
    DISCOUNT -->|落库| TMT[t_student_topic_mastery]
    TMT -->|汇编请求| SNAP[mastery_snapshot 回流 decide 按薄弱升序 top10]
```

**文字复述**：Java 答疑编排每轮调用 decide 决策 → Python 输出两类结果：Eval 软信号（`eval.correct` 对错 + `exercise_complete` 是否独立解出，经 onRoundSignal 把 correct+hinted 带题累加到当前题）与掌握度题型三档信号（`mastery_signals[topic_label+signal]`，topic_label 为题型名）；同时输出 `answer_request_count` 供 Java 判断是否引导过 hinted。Java 侧用 ScoreMapper 结算映射：直接答对 score=1.0、引导后答对 score=0.5、答错 score=0.0，再按 per 题型打折系数（第 1 题 0.7 / 第 2 题 0.8 / 第 3 题起 1.0）代入累计平均公式 `new = old×n/(n+1) + score×1/(n+1)`，落库掌握表 `t_student_topic_mastery`；汇编请求时按薄弱升序 top10 生成 `mastery_snapshot` 回流 decide，作为上下文让 AI 优先照顾薄弱题型。
