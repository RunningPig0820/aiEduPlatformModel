## 代码事实

- **mastery_snapshot 结构**：`KpSnapshot(kp_key, label, mastery_level: int 0-100)`；**kp_key 现在是题型名(canonical)，不是 TextbookKP URI**；注释明确 Python 不要拿 kp_key 反查图谱/做题型↔知识点映射。（`models/tutoring.py:70-79`）
- **信号枚举**：`MasterySignal(mastered/practicing/struggling)` 三档——不是四档百分比。`MasterySignalItem(topic_label + signal)`。（`models/tutoring.py:38-42,93-97`）
- **信号来源**：`Eval.correct`（对错）+ `exercise_complete`（是否独立解出）+ 换题短路无作答。（`models/tutoring.py:85-90`）
- **decide 提示词**：强调"mastery_signals 记录学生对题型的掌握度，不是知识点，知识点由后端根据题型派生"。（`prompts.py:78-83`）
- **快照回流 decide**：`snapshot_top_n` 按 `mastery_level` **升序**取 top-10（薄弱题型在前），让模型优先关注薄弱项 + 防撑爆上下文。（`core/tutoring/context.py:26-43,15-16`）
- **快照仅作上下文**：提示词"仅作上下文提示，不照抄为 mastery_signals 的 topic_label"。（`prompts.py:88-89`）
- **换题信号**：Java 换题 → `is_new_question=true` → 短路 `type=switch`，此时无 `eval.correct` 有效信号。（`decider.py:67-74`）

## 设计要点

- **掌握度主体=题型**：学生掌握的是解题模式（鸡兔同笼），不是抽象知识点；知识点由后端根据题型派生。（`models/tutoring.py:70-76` + `prompts.py`）
- **累计平均可追溯**：`new = old×n/(n+1) + score×1/(n+1)`，历史正确率可解释、稳定、不抖动；一次作答算一次（不做去重）。
- **信号跟题目走**：PENDING 题型照常采信号落题目表，归属确定后再聚合，不因题型待定丢数据。
