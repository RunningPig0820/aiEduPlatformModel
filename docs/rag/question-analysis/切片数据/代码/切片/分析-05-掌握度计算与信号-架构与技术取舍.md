## 架构与技术取舍

### 掌握度主体 = 题型（本模块最大设计决策）
学生掌握的是**解题模式**（鸡兔同笼类题做得怎么样），不是抽象知识点（二元一次方程组）。掌握度按题型（canonical 题型名）记——题目天然可聚到题型、可打分可观测、落库不裂行；知识点由后端根据题型派生（后置）。

### 掌握度 = 累计平均正确率（可解释、不虚高）
```
new = old×n/(n+1) + score×1/(n+1)     // n = 已训练题数
```
- **不用 max 单调不减**（答错永不降 → 会虚高）
- **不用 EWMA**（难解释、难回查）
- 累计平均语义 = "练了 N 道题的正确率"，可解释、可追溯、稳定不抖动
- 一次作答算一次（不做去重，反映真实练习量）

### per-题型打折（防"第一题答错 → 题型 0%"假低）
- 直接答对 1.0 / 求助后答对 0.5 / 答错 0.0
- × per 题型：第 1 题 0.7 / 第 2 题 0.8 / 第 3 题起 1.0
- **打折作用于单题 score，不作用于结果**——避免首题答错把题型拉成 0% 的假低
- **scoping = per 题型**：每个题型自己的第 1 题打折——学习新题型都是从不会开始

### 掌握信号唯一来源 = AI 答疑
decide 输出掌握度题型三档信号；题型分析页只记题目、不出对错——只有答疑有真实答题行为。PENDING 题型照常采信号先落题目表（信号跟题目走，不跟题型走）。

### 快照回流设计（防污染）
掌握度快照（薄弱升序 top10）回流 decide 作**上下文提示**，但明确"仅作上下文，不照抄为输出题型名"——快照已脱钩，不会反过来污染题型名。

## 设计要点

- **掌握度主体=题型**：学生掌握的是解题模式，知识点由后端根据题型派生。
- **累计平均可追溯**：历史正确率可解释、稳定、不抖动；一次作答算一次。
- **信号跟题目走**：PENDING 题型照常采信号落题目表，归属确定后再聚合，不因题型待定丢数据。
- **topic_label 是题型不是知识点**：Python 输出题型名，否则污染后端题型库 → 掌握度/派生覆盖度/图谱点亮全脏。
