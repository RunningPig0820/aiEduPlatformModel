## 隐性坑与注意事项

- **编辑距离 ≤1 近字归并已移除**："一元一次/一元二次"一字之差与错别字"方成/方程"同为距离 1，字符级无法区分会误并——近字/错别字全交给向量层。（`vector_store.py` 无此逻辑，refer 对账）
- **聚集依据 = 题型名向量单信号**：题目向量本期不落库（`models/vector.py:23` "题目文本不落库"），别以为题目向量参与归一。
- **put 后 ~10s 异步生效**：建锚后不立查、留重试（`vector_store.py:13,126-127`）。
- **COS 未配置时**：put/query → 500，Java 桥降级（回退字符规则 + 原样落库），不阻塞主链路。

## 对账要点

对账复盘（原始方案 → 实际落地 → 业务影响）：

1. **聚集依据 ⚠️翻转**：语雀/design 口径是"题目向量为主 + 题型名向量为辅"，代码实际只用了**题型名向量单信号**（题目向量本期不落库）——归一精度由题型名单信号承担，别误以为题目向量参与归一。
2. **canonical 来源 ⚠️翻转**：语雀/design 口径是"预置题型池"，代码实际是**动态涌现**（首题建锚）——题型是"长出来"的不是"规定出来的"，零预置。
3. **字符归一 ⚠️翻转**：语雀/design 建议"编辑距离 ≤1 近字归并"，代码已**移除**——因为"一元一次/一元二次"一字之差与错别字"方成/方程"同为距离 1，字符级无法区分会误并，近字/错别字全交给向量层。
4. **定时批量聚类 ⚠️翻转**：design 建议定时批量聚类，代码 **Python 无批处理**，Java `@Scheduled` 已移除改手动触发——只是即时 put/query 原语。
5. **vector_type ✅落地**：接口契约口径"多索引哈希"，代码现状**本期唯一 "topic"，其余占位**（question/rag 配置占位）——路由行为与接口契约一致。
6. **失败语义 ⚠️翻转**：早期注释口径"吞异常"，代码实际**错误冒泡**——向量是基础设施，让 Java 感知失败再降级，与 question-understand 吞异常相反。
