## 隐性坑与注意事项

- **Python 无状态**：会话历史在 Java Redis，掌握度快照在 Java 掌握表，Python 只接收 snapshot 作上下文提示。（`context.py` + `models/tutoring.py:138,141`）
- **"唯一存储"是 COS 向量桶**——别误以为 Python 把题目/掌握度存了库。
- **题目表跳答疑会话**：`session_id` 关联原题，掌握度页"查看原题"靠它；无会话链接显示题目原文（Java 侧）。

## 对账要点（方案 vs 代码现状复盘）

**⚠️翻转：掌握度主体——知识点 URI → 题型（canonical key）**
原始方案掌握度主体是知识点 URI；代码现状是题型（canonical key）。业务影响：掌握度落到解题模式（题型）而非抽象知识点，可聚可打分可追溯，知识点由题型派生。

**⚠️翻转：Python 落库职责——早期方案 → Python 不落业务库，Java 全落**
原始方案 Python 参与落库；代码现状 Python 不落任何业务库、只出信号，落库/存储全在 Java（题目表 + 掌握表 + Redis 会话 + 向量桶）。业务影响：Python 可水平扩展，状态与数据分离，任何一轮可被新机器接管。

**⚠️翻转：题目文本落向量——题目向量为主 + 题型名向量 → 只题型名向量，题目不落库**
原始方案题目向量为主 + 题型名向量为辅；代码现状只题型名向量进 COS 向量桶，题目文本不落库（落 MySQL 题目表作事实源）。业务影响：相似题检索本期不做，聚集用题型名向量足够；题目仍可经题目表回查原题。

**✅落地：会话存储——Java Redis，Python 无状态**
会话状态存 Java Redis、Python 无状态这一项与预期一致，已落地。业务影响：多轮答疑断开重连会话不丢。
