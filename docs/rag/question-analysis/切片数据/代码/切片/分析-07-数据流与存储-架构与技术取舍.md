## 架构与技术取舍

### Python 无状态不落库（核心架构决策）
Python 不落任何业务库（无 ORM/MySQL/Redis 依赖），当前题目完全由 history 推断（Java 零题目状态）。Python 唯一"存储" = COS 向量桶（题型名向量）。
- **红利**：Python 可水平扩展，任何一轮都可被新机器接管
- **代价**：每次调用由 Java 传全量上下文（历史截断 12 条 + 掌握度快照 top10）

### 两表隔离（事实源 + 聚合结果）
- **题目表 = 事实源**：每道题一条（内容/source/score/引导计数/session_id），可回查原题
- **掌握表 = 聚合结果**：canonical key + 连续 0-100 累计平均 + trainCount
- **隔离红利**：改信号映射/打折系数 → 重算聚合即可，题目证据不丢

### 状态与数据分离
- Python stateless（纯智能），Java 管状态（Redis 会话）与数据（两表）
- 会话状态存 Java Redis：多轮答疑断开重连不丢；会话 3 态（ACTIVE/ARCHIVED/TERMINATED）

### 信号源唯一
AI 答疑 decide 是唯一产出掌握信号的入口；题型分析页只记题目不产生信号——只有答疑有真实答题行为。

### 存储拓扑全景
| 数据 | 存哪 | 谁写 |
|---|---|---|
| 题目记录 | 题目表（MySQL） | Java |
| 掌握度 | 掌握表（MySQL） | Java |
| 会话状态 | Redis | Java |
| 题型名向量 | COS 向量桶 | Python put |
| 权威图谱 | Neo4j（只读） | — |

## 设计要点

- **事件驱动 → 信号 → 落库**：答疑事件 → 信号（掌握度题型三档 + 对错）→ 题目落库 + 掌握表累计平均，数据可追溯。
- **信号源唯一**：AI 答疑 decide 是唯一产出掌握信号的入口；题型分析页只记题不产生信号。
- **状态与数据分离**：Python stateless（纯智能），Java 管状态（Redis/session）与数据（两表）。
