## 隐性坑与注意事项

1. **Python 无状态**：会话历史在 Java Redis，掌握度快照在 Java 掌握表，Python 只接收快照作上下文提示——别误以为 Python 存了数据。
2. **"唯一存储"是 COS 向量桶**——别误以为 Python 把题目/掌握度存了库。
3. **题目表跳答疑会话**：session_id 关联原题，掌握度页"查看原题"靠它；无会话链接显示题目原文。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**掌握度主体翻转：知识点 URI → 题型**
原始方案掌握度基于知识点 URI；落地改题型（canonical key）。影响：学生掌握的是解题模式，可聚可打分可追溯；知识点由题型派生。

**Python 落库职责翻转：早期方案 → Python 不落业务库，Java 全落**
原始方案 Python 参与落库；落地 Python stateless 只出信号，Java 全权落库。影响：Python 可水平扩展，状态与数据分离。

**题目向量策略翻转：题目向量为主 → 只题型名向量，题目不落库**
原始方案题目向量为主 + 题型名向量为辅；落地只题型名向量进向量桶，题目文本落 MySQL 作事实源。影响：相似题检索本期不做，聚集用题型名向量足够。

**会话存储确认（✅落地）**
会话存 Java Redis，Python 无状态——多轮答疑断开重连不丢。
