## 隐性坑与注意事项

- **Python 收 question_kps 但不能反查图谱**：`question_kps` 只是模型顺带输出，不送去匹配；匹配/映射全在 Java 派生层。（`models/tutoring.py:70-76,119`）
- **PENDING 语义更新**：getMastery `status=PENDING` 不再来自 obs，改为"题目记录有但 canonical 未归属"（Java 侧）。（refer 对账）
- **停用自动涌现链路**：obs 共现→自动关联、upsertPendingIfAbsent 挂起、学生 vote、聚合批处理、KpCoverageAppService 派生——已停用，前端已不消费。

## 对账要点

原始对账表（保留证据）：

| 对账分类 | 项 | 语雀/design 口径 | 代码现状 | 结论 |
|---|---|---|---|---|
| 方案vs实现 | Python 映射职责 | 早方案 Python 桥 | Python 显式禁止，Java ADMIN 维护 | ⚠️翻转 |
| 方案vs实现 | 自动涌现链路 | obs 共现自动关联 | 已停用，改手动/只读 | ⚠️翻转 |
| 方案vs实现 | PENDING 语义 | obs 挂起（知识点待确认） | 题目记录有但 canonical 未归属 | ⚠️翻转 |
| 接口契约 | 题型库查询 | 聚合展示 | 查表只读 + ADMIN 维护 | ✅落地 |
| 注释vs运行行为 | Neo4j 写入 | 权威图可写 | 只借结构不写 | ✅落地 |

自然语言复盘（原始方案 → 实际落地 → 业务影响）：

1. **Python 映射职责 ⚠️翻转**：早方案由 Python 桥做题型↔知识点映射；实际落地 Python 显式禁止（`models/tutoring.py:73-76`），改由 Java 派生层 ADMIN 手动维护。业务影响：映射入口收敛到运营后台，Python 侧不脏化权威数据。
2. **自动涌现链路 ⚠️翻转**：原方案 obs 共现自动关联题型↔知识点（含 upsertPendingIfAbsent 挂起、学生 vote、聚合批处理、KpCoverageAppService 派生）；实际全部停用、改手动维护 + 只读查询，前端已不消费覆盖度。业务影响：消灭不可控的自动写库，映射稳定可审计。
3. **PENDING 语义 ⚠️翻转**：原方案 getMastery `status=PENDING` 由 obs 挂起（知识点待确认）；实际改为"题目记录有但 canonical 未归属"（Java 侧判定）。业务影响：PENDING 从"待 LLM 确认"变为"待归属归并"，不再依赖 obs 链路。
4. **题型库查询 ✅落地**：语雀/design 口径为聚合展示；实际落地为查表只读 + ADMIN 维护（findByTopicLabelOrAlias → 分布桶）。业务影响：查询路径清晰只读，映射由后台维护。
5. **Neo4j 写入 ✅落地**：注释/口径疑"权威图可写"；实际落地 Neo4j 只被借结构（持 URI 向外展开）不写入，题型↔知识点映射放派生层 MySQL。业务影响：权威图谱零污染，坏了不波及时权威数据。
