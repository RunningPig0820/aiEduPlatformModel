## 架构与技术取舍

### 两域解耦（本模块最核心架构）
```
域 A「题目→题型」（本期核心）          域 B「题型→知识点」（独立维护）
  题目落库 → 向量聚集 → 掌握表累计平均    题型库 / 分布桶 / 别名表
  只消费题目记录，不依赖域 B             入口查表只读 + ADMIN 维护
  一个环节故障不影响另一个，反之亦然
```
- **canonical 名是两域对接缝**：域 A 产出题型掌握度 → canonical 名进域 B 查映射
- **域 B 独立化**：查表只读 + ADMIN 手动维护，不做自动关联（业务不成熟，防污染权威图谱）

### 权威图谱零写入（红线）
- Neo4j 只被"借结构"（持 URI 向外展开），**永不写入**
- 题型↔知识点关联放派生层 MySQL，权威图不被污染
- **关联错了也只在派生层可纠错**，不会破坏教育局权威数据

### Python 显式禁止映射
`models/tutoring.py` KpSnapshot 注释明确"Python 不要拿 kp_key 反查图谱/做题型↔知识点映射（桥已移到后端 ADMIN 维护接口）"——Python 只做三件事：decide 顺带输出题目知识点（可选）、图片识别顺带知识点（可空）、掌握度信号稳定输出题型（不输出知识点）。

### 为什么本期不做自动关联（面试高频）
自动关联引入 5 个环节（obs 状态机/聚合批处理/LLM 归纳/vote 澄清/派生覆盖度），分散本期核心（题目→题型→掌握度），且容易污染权威图谱。题型↔知识点是"业务隔离"的派生数据，需要独立维护/审核。

### 跨年级薄弱
掌握度按题型名（canonical）记，不绑定"当前学年"；图谱 URI 全局（年级只是 URI 一部分）——跨年级薄弱天生可展示（七年级卡在四年级假设法，是重要信号）。

## 设计要点

- **两域解耦**：域 A「题目→题型」与域 B「题型→知识点」完全解耦，一个环节故障不影响另一个。
- **查表只读 + ADMIN 维护**：识别题型 → 查题型库 → 命中返权威分布 / 未命中返空知识点——不挂起、不写 obs、不顺带 LLM kps。
- **权威图谱零写入**：Neo4j 只被"借结构"，题型↔知识点放派生层 MySQL，权威图不被污染。
