## 业务描述与业务场景

**业务描述**：AI 答疑直接面对学生，学生可能乱答、抄答案、发非数学闲聊、或者换题——系统需要一层护栏保证「答错了不会恭喜、不直接给答案、识别不出不硬猜、闲聊不乱收尾」，这是答疑体验和防作弊（成绩可信度）的底线。

**业务场景**：
1. 学生答错但 AI 却断言"做对了"还收尾道歉恭喜——不允许：end 联动校验兜住，降级为继续引导（type=concept），保持会话。
2. 学生直接说「把答案给我」——reveal 有门禁（请求答案计数），第一次只给思路不给完整解答，防止抄答案当熟练度。
3. 学生发「帮我写作文/今天心情不好」——不是答题内容，AI 引导回题、绝不乱端会话；识别不出题型的图片题走 PENDING 挂起，待学生确认，不留死胡同。

## 职责

题型识别链路 + decide 决策的**护栏与异常防护**：低置信挂起、闭集外放行、答非所问引导、end 一致性护栏、结构化输出兜底。Python 侧护栏集中在"别让 LLM 乱答/别泄答案/别拖慢"。

## 高层业务调用链（防作弊护栏与异常路径）

```mermaid
flowchart TD
    J[Java 编排] -->|①学科门| SC[subject-classify 闭集外→None]
    SC -->|None| PASS1[Java 按 math 放行 宁漏不误]
    J -->|②识别| QU[question-understand 空labels→PENDING]
    QU -->|空| JPEND[Java 降级 PENDING 挂起 走澄清卡]
    J -->|③decide| DEC[decide 决策]
    DEC -->|答非所问/非数学| CON[type=concept 引导回题 绝不end]
    DEC -->|负面硬规则| NG[在答题内容绝不end/绝不reveal]
    DEC -->|type=end 但联动不一致| SAN[_sanitize_end_consistency 降级concept]
    DEC -->|结构化全失败| FB[兜底 type=hint degraded=true]
    DEC -->|高危内容| SAFE[safety_flag=true Java 拦截]
    DEC -->|is_new_question 换题| SW[短路 type=switch 确定性]
```

**文字链路复述**：Java 编排作为入口，先后过三道关卡——① 学科门 subject-classify，模型返回闭集外 → None，Java 按 math 放行（宁漏不误拦）；② 题型识别 question-understand，识别结果为空 labels → Java 降级 PENDING 挂起，走澄清卡待学生确认；③ decide 决策分六条护栏分支：答非所问/非数学 → `type=concept` 引导回题绝不 end；负面硬规则下在答题内容绝不 end/绝不 reveal；`type=end` 但联动不一致 → `_sanitize_end_consistency` 降级 concept；结构化输出全失败 → 兜底 `type=hint degraded=true`；高危内容 → `safety_flag=true` 由 Java 拦截；`is_new_question` 换题 → 短路 `type=switch` 确定性收尾（不调 LLM）。
