## 隐性坑与注意事项

- **end 联动收紧**：答错的学生禁止被"恭喜"、summary 禁止泄出完整解答——`type=end` 但联动不一致会降级 concept。（`decider.py:24-53`）
- **负面硬规则**：在答题内容绝不 end / 绝不 reveal——答错 ≠ 要答案。（`prompts.py:66`）
- **PENDING 不是错误**：识别失败 → PENDING → 澄清卡，不是 Python 抛异常。
- **结构化兜底与降级监控**：兜底 `degraded=true` 让 Java 监控 Python 降级频次。

## 对账要点

对账结论逐条复盘（原始方案 → 实际落地 → 结论）：

- **答非所问处理**：原始方案走澄清卡，实际落地为 decide 提示词 `type=concept` 引导回题。✅落地——答非所问由 decide 提示词 type=concept 引导回题落地，与澄清卡方案等价。
- **end 收尾**：原始方案模型自判完成，实际落地为 end 联动护栏 + 降级 concept。✅落地——end 收尾由 end 联动护栏（COMPLETED 必须 correct=true 且 exercise_complete=true）+ 降级 concept 兜底落地。
- **换题**：接口契约未明示，实际落地 `is_new_question=true` 短路 `type=switch`。✅落地——换题通过 is_new_question=true 短路 type=switch 落地为确定性行为。
- **WEAK 冒充 RESOLVED**：注释/旧行为曾返回 RESOLVED conf=70，实际落地识别失败→PENDING，不冒充题型。⚠️翻转——识别失败从冒充 RESOLVED 翻转为走 PENDING 挂起、不编造题型名。
- **失败语义**：曾统一降级空，实际落地业务判定吞异常、向量基础设施错误冒泡。⚠️翻转——失败语义从统一降级空翻转为业务判定吞异常 vs 向量冒泡分治。
