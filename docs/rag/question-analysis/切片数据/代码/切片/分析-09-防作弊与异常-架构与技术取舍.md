## 架构与技术取舍

### 确定性护栏不信任模型格式（核心设计）
**LLM 只是候选输出，不是最终裁决**——关键护栏都是代码层面的硬校验：
- **end 联动护栏**：type=end 但 end_reason 缺失 / COMPLETED 但 correct/exercise_complete 不满足 → 降级 type=concept——防"答错被恭喜/泄答案"
- **换题短路护栏**：Java 检测新题 → is_new_question=true → 直接 type=switch 不调 LLM——确定性 100% 准，省调用
- **负面硬规则**：任何在答题内容（无论对错/跑偏）绝不 type=end、绝不 type=reveal——答错 ≠ 要答案

### 低置信不硬猜（识别护栏）
Python 侧不判置信度——"识别失败 = 空 topic_labels = Java 降级 PENDING"（走澄清卡 resolve/vote），不编造题型名进掌握表。识别对的信号才落库，错的不会污染。

### 闭集外放行（学科门护栏）
学科判定闭集外 → 空 → Java 按 math 放行（宁漏拦不误拦）。代价是"垃圾学科题"可能进答疑，但数学题永远不会被拦在门外——误拦是更糟的产品事故。

### 结构化输出四段降级（防畸形）
function calling → JSON mode → 正则提取 → 兜底 type=hint degraded=true——保证决策元数据绝不畸形、绝不抛异常。
- 情绪值宽容归一：模型关思考后偶发填中文/小写情绪值 → 映射为大写枚举，避免整条校验失败丢信号
- corrective_retries=1：只修 schema 不整段重生成

### 两类失败语义分治
业务判定（学科门/题型识别）= 吞异常降级空（宁返回空不阻塞）；向量基础设施 = 错误冒泡（Java 有降级，Python 正常报错便于定位）。

## 设计要点

- **确定性护栏不信任模型格式**：end 联动、换题短路都是代码层面的硬校验，LLM 只被当候选输出。
- **两类失败语义分治**：业务判定吞异常降级空；向量基础设施错误冒泡。
- **识别失败不是错误**：空结果 → Java PENDING（低置信挂起走澄清卡），不编造题型名。
