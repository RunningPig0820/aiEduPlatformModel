## 隐性坑与注意事项

1. **end 联动收紧**：答错的学生禁止被"恭喜"、summary 禁止泄出完整解答——type=end 但联动不一致会降级 concept。
2. **负面硬规则**：在答题内容绝不 end / 绝不 reveal——答错 ≠ 要答案。
3. **PENDING 不是错误**：识别失败 → PENDING → 澄清卡，不是 Python 抛异常。
4. **结构化兜底与降级监控**：兜底 degraded=true 让 Java 监控 Python 降级频次。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**答非所问处理（✅落地）**
原始方案澄清卡；落地 decide 提示词 type=concept 引导回题。影响：不在答题（闲聊/非数学）不硬端会话，引导回题。

**end 收尾（✅落地）**
原始方案模型自判完成；落地 end 联动护栏 + 降级 concept。影响：答错绝不会被"恭喜"，防泄答案。

**换题信号翻转：模型自判 → is_new_question=true 确定性短路**
原始方案模型判断换题；落地 Java 检测新题信号 → 直接 type=switch 不调 LLM。影响：确定性 100% 准，省一次 LLM 调用。

**WEAK 冒充 RESOLVED 翻转：曾返回 RESOLVED conf=70 → 识别失败→PENDING**
原始设计曾有 WEAK 置信返回 RESOLVED conf=70；落地识别失败直接 PENDING，不冒充。影响：低置信不再假装已解决，走澄清卡更诚实。

**失败语义翻转：统一降级空 → 业务判定吞异常 vs 向量冒泡**
原始方案统一降级空；落地业务判定吞异常、向量冒泡。影响：基础设施失败让 Java 感知后降级，业务判定失败快速空结果不阻塞。
