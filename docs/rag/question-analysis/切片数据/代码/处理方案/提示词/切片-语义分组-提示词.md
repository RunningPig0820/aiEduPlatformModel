# 任务：代码分析文档 → 语义分组切片（LLM 切分，替代硬编码脚本）

## 文件元信息
> 用途: 读取 `3.代码/分析-*.md`（10 份权威 0.8 代码证据文档），按**语义关联**分组合并成大块，输出切片文件到 `切片数据/代码/`。解决机械 h2 切太碎的问题（职责 110 字/设计 239 字各自成块无意义）。
> 权威度: 0.8
> 模块: question-analysis
> 类别：开发难点

## 角色
你是RAG语料切片助手。输入：代码分析文档全文。任务：把每份文档按**语义分组**切成 3 个大块（块自包含、可独立回答一类问题），输出为独立 md 文件。

## 为什么用语义分组而非机械 h2 切
机械按 `##` 切会把关联的小节拆碎（`职责` 110 字一块、`设计要点` 239 字一块），检索时语义断裂、召回即碎。正确做法：**读文档判断哪些节在回答同一类问题，合并成一个大块**。

## 输入
- 源文档：`docs/rag/question-analysis/3.代码/分析-01~10.md`（10 份）
- 每份结构固定 8 节：`业务描述与业务场景` / `职责` / `高层业务调用链（xx）` / `代码事实`（含 `### 端点` `### 机制` `### 枚举表` 子节）/ `隐性坑与注意事项` / `设计要点` / `对账要点` / `已读代码清单`

## 分组规则（每份文档 → 3 块）

| 输出块名 | 合并哪些节 | 回答什么 | 说明 |
|---|---|---|---|
| **业务链路** | `业务描述与业务场景` + `职责` + `高层业务调用链（xx）` | "这个业务做什么 / 怎么走的" | 完整叙事穿起来，别拆 |
| **代码事实** | `代码事实`（含全部 `###` 子节）+ `设计要点` | "接口/参数/降级/实现取舍" | 主体是端点/机制/枚举表，设计要点并入 |
| **坑与对账** | `隐性坑与注意事项` + `对账要点` | "踩过什么坑 / 方案和代码差在哪" | 防御向合并 |

**明确丢弃（不输出）**：
- `# 文档标题行` + 文件头元信息（`> summary`/`> 权威度` 等）——与切片内容重复
- `已读代码清单`——纯文件路径索引，无回答价值

## 硬性规则
1. **只做合并，不改写正文**：各节原文保留（含 `文件:行号` 证据、表格、mermaid、列表），只是把同组的节拼接在一起；禁止增删改任何内容。
2. **表格/代码块/mermaid 不切破**：完整搬进所在块。
3. **保留块内小节标题**：合并后块内保留原来的 `## 业务描述与业务场景` `## 职责` 等子标题层级（正文结构可读、人可复核）。
4. **每块自包含**：单独看这一块能回答问题，不依赖其它块（块内可补一句"本文档见 X 节"的衔接说明，但不得改变原意）。
5. **无内容可丢弃时明确标注**：某节不存在/内容为空 → 跳过即可，不臆造。

## 输出格式（每份文档 → 3 个 md 文件，保存到 `docs/rag/question-analysis/切片数据/代码/`）

```
文件 1: 分析-{0X}-{主题}-业务链路.md
文件 2: 分析-{0X}-{主题}-代码事实.md
文件 3: 分析-{0X}-{主题}-坑与对账.md
```

每文件内容：
```markdown
# 分析-{0X}-{主题}-{块名}

> summary: 解答「{本块回答的问题}」——{一句话，关键词密集}
> 权威度: 0.8 ｜ 来源: 代码 ｜ 锚点: {块名}
> 模块: question-analysis ｜ 节: {分析-0X-主题}
> COS路径: rag-slices/question-analysis/代码/分析-{0X}-{主题}-{块名}.md
> 类别：{本块类别}

---

## {块内第一个子节标题}
{合并的原文...}

## {块内第二个子节标题}
{合并的原文...}
```

> 类别取值：业务链路=操作流程/业务流程，代码事实=架构设计/数据关联，坑与对账=开发难点——按块内容最贴合的取。

## 输出前自检
1. ✅ 每份文档只输出 3 个块文件（业务链路/代码事实/坑与对账），已删除的节没有遗漏或错放。
2. ✅ 各节原文未改动（文件:行号/表格/mermaid/列表原样保留），只是同组合并。
3. ✅ 块内子标题层级保留，人可读可复核。
4. ✅ 每个块自包含、能独立回答问题。
5. ✅ summary 一句话说明本块解决什么、关键词密集。

## 使用提示
1. 本提示词替代 `slice_corpus.py` 的 CODE_GROUP 硬编码方案——语义分组由模型判断更准（能处理标题带括号后缀、子节归属等边界）。
2. 产出后：`export_slices_md.py` 不用跑了（已是视图）；后续入桶用 `md_to_jsonl.py` 或直接由 jsonl 生成流程接手。
3. 幂等：先清空 `切片数据/代码/` 下旧切片块（保留 readme.md / 处理方案/ / 脚本/），再写新块。
4. 一次处理 1 份文档，分 10 次执行（避免上下文过长漏节）；或一次 10 份（若文档都短）。
5. 新模块复用：改模块 id / 源文档路径 / 输出目录 / 块名表（如该模块分析文档结构不同，按需调整分组映射）。
