## 业务描述与业务场景

一次题型分析/答疑是**三方协作**：学生在前端操作，Java 后端决定"要不要处理、怎么落库"，Python AI 服务负责"判断学科、认题型、出掌握度信号"。

典型场景：
1. 学生点「发送消息」→ 前端触达 Java → Java 先过学科门（决定收不收数学题）→ 再调 Python 决策（决定这轮怎么引导）。
2. 图片题在 Java 上传后交给 Python 看图认题型；文本题由 Java 自研识别——业务入口不同，分工不同。
3. 题型归并 canonical、掌握度落库全在 Java；Python 只管"出信号、存向量"——分工决定谁的故障影响谁。

## 职责

Python（AI 服务）在本模块 = **纯智能桥**：学科门/图片题型识别/掌握度信号/向量原语，全部无状态、不落库。Java = 编排 + 决策（canonical 归并/掌握度计算/落库/防作弊）。Python 显式禁止做题型↔知识点映射。

## 高层业务调用链（前端→Java 编排→Python 六端点）

```mermaid
flowchart TD
    FE[前端 AiQa.jsx] -->|start/send/requestAnswer| JAVA[Java TutoringAppService 编排]
    JAVA -->|① 学科门 decide 前| SC[学科判定 同步JSON]
    SC -->|空 subject / 非 math| SKIP[跳过: 不建/不续会话 不落库]
    SC -->|math| ENSURE[频率限制]
    JAVA -->|图片题| QU[图片题型识别 同步JSON]
    QU -->|空 topic_labels| PENDING[Java 降级 PENDING 挂起]
    ENSURE -->|每轮| DECIDE[decide 流式SSE]
    DECIDE -->|meta ActionMeta| GUARD[Java 护栏审批 type]
    GUARD -->|放行| GEN[generate 流式SSE]
    JAVA -->|题型名归一| V[向量 put|query 同步JSON]
    V -.失败 HTTP 400/500.-> FALLBACK[Java 桥降级: 回退字符规则 + 原样落库]
```

**文字复述**：前端自动路由（start/send/requestAnswer）→ Java 编排（TutoringAppService 总控）→ ①学科门判定（非 math 跳过不落库，math 过频率限制）→ 图片题走 Python 图片识别（失败降级 PENDING）→ 每轮 decide 流式出 ActionMeta → Java 护栏审批 type → 放行 generate 流式正文 → 题型名走向量归并 canonical（失败桥降级字符规则+原样落库）。
