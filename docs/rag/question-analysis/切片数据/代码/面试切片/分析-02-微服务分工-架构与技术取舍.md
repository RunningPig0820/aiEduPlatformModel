## 架构分工（关键设计）

| 端 | 职责 | 关键边界 |
|---|---|---|
| **前端** | 交互/渲染/会话状态/SSE 消费 | 不碰智能逻辑 |
| **Java** | 认证/护栏/编排/掌握度/落库 | 不暴露 Python 内部端点；护栏只读 type+计数 |
| **Python** | 决策/生成/学科判定/图片识别/向量原语 | **无状态**，不碰 MySQL/Redis/图谱 |

**三个核心边界**：
1. **Python 无状态可水平扩展**：每次调用由 Java 传全量上下文（历史截断 + 掌握度快照），单次调用可重试。
2. **掌握信号在 Python 出、落库在 Java**：Python 只输出信号，不反查图谱、不做映射。
3. **失败语义按类型分化**（本架构最值得讲的设计）：
   - **业务判定**（学科门/题型识别）：吞异常降级空结果——识别失败 ≠ 错误，快速返回空让 Java 降级，不阻塞主链路
   - **基础设施**（向量）：错误冒泡——向量挂了要 Java 感知，再降级（回退字符规则 + 原样落库）
   - 两类刻意不对称，是"业务判定和基础设施的失败语义分治"

## 关键机制

### 失败语义分两种（务必区分）
- decide/generate 流式：中途失败发错误事件，HTTP 状态码不返回（SSE 已开流）
- 学科判定/图片识别：**吞异常降级空结果**（业务判定失败 ≠ 错误）
- 向量存查：**错误冒泡** HTTP 400/500（基础设施，让 Java 感知失败再降级）

### 向量桥设计
- embedding 复用 dashscope（text-embedding-v3 768 维），不进 LLMFactory（语义不同，独立封装）
- 索引按 `vector_type` 路由：Java 只传逻辑名，Python 映射物理索引——改名只动 Python 配置，Java 零改动
- 桶按 vector_type 路由：topic 走默认桶，rag 系走 RAG 独立桶

## 设计要点

- **python 纯智能、Java 平台决策**：Python 管 LLM/embedding（无状态），Java 管数据/落库/编排。
- **失败语义按类型分化**：业务判定（学科门/题型识别）吞异常降级、不阻塞；基础设施（向量）冒泡让 Java 感知后降级——不是一刀切。
- **索引路由对 Java 透明**：Java 只传 vector_type 逻辑名，Python 路由物理索引。
- **掌握信号题型化**：mastery_signals 输出题型名（canonical），不输出知识点名——否则后端题型库混入知识点名，整条链路脏。
