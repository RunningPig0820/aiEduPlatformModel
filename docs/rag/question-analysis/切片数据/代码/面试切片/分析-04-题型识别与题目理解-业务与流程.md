## 业务描述与业务场景

图片题（拍照/截图题目）由 AI 看图直接识别出题型名和顺带知识点——让"拍下题目"就能知道"这是什么题"，不用手打题目文本。

典型场景：
1. 题型分析页学生拍一张题图 → 期望直接看到「鸡兔同笼」「相遇问题」这类题型名（1~5 个），并顺带知道涉及的知识点。
2. 识别不出/图片模糊/不是数学题时，不硬猜——返回空结果，Java 侧降级为待确认（PENDING），事后通过澄清卡让学生确认，不留死胡同。
3. 答疑链路多入口复用同一能力；题型名有现成词表时优先从词表选，冷启动没词表时允许 AI 自拟题型名（后续动态涌现收敛）。

## 职责

**图片题**的题型识别（视觉多模态），Java 传图片 URL → Python 看图 → 题型名 1~5 个 + 顺带知识点。文本题在 Java（自研识别器），Python 无此端点。

## 高层业务调用链（图片题型识别）

```mermaid
flowchart TD
    FE[前端题型分析页/答疑] -->|上传图片| JAVA[Java 上传后传签名URL]
    JAVA -->|图片识别| QU[understand_question]
    QU -->|topic_hint 题型库 top-20 注入 system| DBG[参考题型名词表 压低漂移]
    QU -->|关思考 20s 重试0| LLM[写死 doubao 视觉模型<br/>text+image_url 多模态]
    LLM -->|解析 topic_labels 1~5| OK[返回 topic_labels + question_kps]
    LLM -->|失败/解析失败/无法识别| FAIL[空 topic_labels]
    QU -->|识别不出| JPEND[Java 降级 PENDING 挂起走澄清卡]
    OK -->|正常| JUSE[Java uses: 题型分析页/答疑]
```

**文字复述**：前端上传图片到 COS → Java 传签名 URL → Python 图片识别 → topic_hint（题型库 top-20）注入 system 压低命名漂移 → 写死视觉模型（关思考/20s/重试0）多模态看图 → 解析 1~5 个题型名 + 顺带知识点返回；失败/解析失败返回空 → Java 降级 PENDING 挂起走澄清卡。
