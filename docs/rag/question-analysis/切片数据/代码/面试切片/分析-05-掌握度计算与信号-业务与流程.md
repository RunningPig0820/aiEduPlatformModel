## 业务描述与业务场景

学生掌握的是**题型**（解题模式，如鸡兔同笼）而不是抽象知识点。系统在答题过程中判断他对每类题型练得怎么样，累计成可解释的掌握度（连续百分比），让"这个学生哪里薄弱"看得见。

典型场景：
1. 学生在答疑里做「鸡兔同笼」题——直接答对/求助后答对/答错被折算成信号，落进该题型掌握度（第 1 题打折更保守），报表上可看「64%·练了 10 题」。
2. 下一次决策时，系统把学生已有掌握度快照塞回给 AI（薄弱题型排在前面）——AI 优先照顾不会的题，快照只是上下文，不会反过来污染题型名。
3. 学生在掌握度页看到列式的题型清单 + 训练数 + 可跳转原题——掌握度可追溯，不是拍脑袋数字。

## 职责

Python 只**输出掌握度信号**（三档），decide 每轮产出题型三档信号。0-100 累计平均计算在 Java（打分映射 + 掌握表）。

## 高层业务调用链（掌握度信号计算与落库）

```mermaid
flowchart TD
    JAVA[Java 答疑编排] -->|每轮 decide| DEC[decide 决策]
    DEC -->|eval.correct + exercise_complete| E[Eval 软信号]
    DEC -->|mastery_signals[topic_label+signal]| MS[掌握度信号 三档]
    DEC -->|answer_request_count| AR[Java 判断是否引导过 hinted]
    E -->|带题累加| ON[onRoundSignal correct+hinted 累计到当前题]
    MS -->|topic_label 题型| MG[掌握表 canonical 累计平均]
    ON -->|结算映射| SC{映射}
    SC -->|直接答对| S1[score=1.0]
    SC -->|引导后答对| S2[score=0.5]
    SC -->|答错| S3[score=0.0]
    S1 -->|× 打折 per 题型第1题0.7/第2题0.8/第3题起1.0| DISCOUNT[new = old×n/(n+1) + score×1/(n+1)]
    DISCOUNT -->|落库| TMT[掌握表]
    TMT -->|汇编请求| SNAP[mastery_snapshot 回流 decide 按薄弱升序 top10]
```

**文字复述**：Java 每轮 decide → Python 输出 Eval 软信号（对错）+ 掌握度题型三档信号 + 请求答案计数 → Java 带题累加、结算映射（直接答对 1.0 / 引导后答对 0.5 / 答错 0.0，per 题型第 1 题打折 0.7/0.8/1.0）→ 累计平均公式落掌握表 → 汇编快照回流 decide（薄弱升序 top10）。
