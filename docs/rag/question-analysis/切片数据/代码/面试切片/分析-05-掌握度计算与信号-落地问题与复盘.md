## 隐性坑与注意事项

1. **topic_label 是题型不是知识点**：Python 输出题型名，否则污染后端题型库 → 掌握度/派生覆盖度/图谱点亮全脏。
2. **快照不是候选池**：掌握度快照已脱钩，仅作上下文提示，不要从快照挑题型名——会污染输出。
3. **信号只在 AI 答疑产生**：题型分析页只记题不产生信号；PENDING 题型照常采信号先落题目表。
4. **打折作用于 score 不作用于结果**：防"第一题答错→题型 0%"假低；per 题型自己的第 1 题打折。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**掌握度主体翻转：知识点 URI → 题型**
原始方案掌握度基于知识点 URI；落地改为题型（canonical 题型名）。影响：学生掌握的是解题模式，可打分可观测可追溯；知识点由题型派生。

**掌握度数值翻转：离散四档 max 单调不减 → 连续 0-100 累计平均**
原始方案离散四档（0/25/50/75）max 单调不减；落地改连续百分比累计平均。影响：能算"练了几道、对了几道"的可解释数字，答错真实反映，不虚高。

**掌握度信号字段翻转：kp_label → topic_label**
原始信号字段叫 kp_label（知识点标签）；落地改 topic_label（题型标签）。影响：整条链路题型口径统一，避免后端题型库混入知识点名。

**信号枚举翻转：离散四档 → 三档**
原始方案离散四档信号；落地三档 mastered/practicing/struggling。影响：Python 只出三档粗信号，0-100 细分计算在 Java。

**快照用途翻转：候选接地 → 仅上下文提示**
原始设计让掌握度快照给题型做候选接地；落地快照脱钩，仅作上下文提示，不照抄。影响：题型不会从知识点快照"接地"出错误题型名。

**getMastery 契约 BREAKING：离散四档+status → 0-100 连续+source/trainCount**
原始 getMastery 返回离散四档+status；落地 0-100 连续 + source/trainCount。影响：前端分桶保留四档视觉，后端语义从"置信度"改"正确率累计"。

**打折作用域确认（✅落地）**
打折作用于 score 不作用于结果，per 题型 scoping——防假低设计落地。
