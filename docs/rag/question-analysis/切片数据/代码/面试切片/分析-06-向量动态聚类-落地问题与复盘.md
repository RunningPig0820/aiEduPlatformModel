## 隐性坑与注意事项

1. **编辑距离 ≤1 近字归并已移除**："一元一次/一元二次"一字之差与错别字"方成/方程"同为距离 1，字符级无法区分会误并——近字/错别字全交给向量层。
2. **聚集依据 = 题型名向量单信号**：题目向量本期不落库，别以为题目向量参与归一。
3. **put 后 ~10s 异步生效**：建锚后不立查、留重试（COS 向量索引异步构建）。
4. **COS 未配置时**：存查 → 错误，Java 桥降级（回退字符规则 + 原样落库），不阻塞主链路。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**聚集依据翻转：题目向量为主 → 只题型名向量单信号**
原始方案题目向量为主 + 题型名向量为辅；落地只用题型名向量。影响：相似题检索本期不做，掌握度/动态聚集用题型名向量足够，题目向量不落库。

**canonical 来源翻转：预置题型池 → 动态涌现**
原始方案预置题型池、新名归进池；落地首题建锚动态涌现。影响：无题库也能跑，题型从学生做题数据里"长出来"。

**字符归一翻转：编辑距离 ≤1 近字归并 → 移除**
原始方案编辑距离近字归并；落地移除（"一元一次/一元二次"一字之差与错别字同为距离 1，无法区分会误并），全交向量层。影响：语义最近邻正确区分"一次/二次"、归并"方成/方程"。

**定时批量聚类翻转：design 建议 → Python 无 / Java 定时移除改手动**
原始方案有定时批量聚类；落地 Python 无、Java 定时任务移除改手动触发。影响：面试项目不引入定时复杂度，即时存查原语够用。

**失败语义翻转：早期"吞异常" → 错误冒泡**
原始方案向量失败吞异常；落地错误冒泡（基础设施感知失败）。影响：Java 桥侧有降级（回退字符规则+原样落库），Python 正常报错便于定位。

**vector_type 契约确认（✅落地）**
本期唯一合法值 topic，其余（question/rag）配置占位——多索引哈希方案收敛为单索引。
