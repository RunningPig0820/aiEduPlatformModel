## 业务描述与业务场景

学生作答时 AI 服务可能慢、可能挂、向量库可能不可用——系统必须让每个环节都有超时/降级兜底，保证学生**不干等、不收白屏**，主链路（答疑/掌握度记录）永远走得通。

典型场景：
1. AI 识别题型超时（>20s）→ 快速返回空结果让 Java 降级 PENDING，学生看到「待确认」而不是转圈卡死；开思考才慢，所以全链路关思考秒出。
2. 向量库挂了 → Python 报错让 Java 感知 → 桥侧退化成字符规则 + 原样落库，归一精度降一点但学生作答不受影响。
3. AI 生成时模型 0 token（网络抖动）→ 给固定引导话术（"说说你读到了哪些关键条件"），学生收到可继续对话，而不是空回复。

## 职责

Python 桥的**工程韧性**设计：超时/降级/重试/兜底，保证各端点在 LLM 或 COS 异常时不让主链路卡死。

## 高层业务调用链（降级与兜底全景）

```mermaid
flowchart TD
    subgraph 业务判定 吞异常降级空结果
    SC[学科判定] -->|关思考 20s 超时 重试0| SCHR{异常/闭集外}
    SCHR -->|空| J1[Java 按 math 放行]
    QU[题型识别] -->|同款慢修复| QHR{异常/解析失败}
    QHR -->|空 topic_labels| J2[Java 降级 PENDING]
    end
    subgraph 向量基础设施 错误冒泡
    PUT[向量存查] -->|embedding/COS 失败| VERR[错误]
    VERR -->|Java 桥侧降级| VF[回退字符规则 + 原样落库]
    end
    subgraph decide 决策链路
    DR[decide 流式] -->|原始流失败| DF[降级非流式 decide 四段管线]
    DF -->|再失败| DBD[兜底 type=hint degraded]
    GEN[generate] -->|0 token 空流| GFB[固定引导话术兜底]
    end
```

**文字复述**：业务判定（学科判定/题型识别）统一关思考+20s 超时+重试0，异常返回空 → Java 降级（按 math 放行 / PENDING）；向量基础设施错误冒泡 → Java 桥降级（回退字符规则+原样落库）；decide 原始流失败 → 降级非流式四段管线 → 再失败兜底 hint degraded；generate 0 token 空流 → 固定引导话术。
