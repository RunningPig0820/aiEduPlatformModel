# 坑档案 J-QT1 向量写入延迟：put 后立即 query 查不到

> summary: 向量写入延迟：put 后立即 query 查不到
> 权威度: 0.8 ｜ 来源: 坑档案 ｜ 锚点: J-QT1. 向量写入延迟
> 模块: question-analysis ｜ 节: 坑档案
> COS路径: rag-slices/question-analysis/坑档案/坑档案-J-QT1-向量写入延迟.md
> 类别：开发难点

---

**1. 问题现象**：首题建锚后立查最近邻，返回空 `vectors: []`，动态聚集没反应。

**2. 触发流程**：题型名向量入库（`put_vectors`）→ 立即 `query_vectors` 查近邻。

**3. 根因分析**：COS 向量索引 **put 后 ~10s 异步构建**，立即 query 命中不到刚写入的向量。

**4. 排查过程**：spike 反复 put→query，发现写入生效延迟稳定 ~10s（非网络/权限问题）。

**5. 解决方案 & 改动点**：① 首题建锚后不立查（本身无近邻）；② 聚集编排「put 后查」路径容忍延迟/留重试。（`core/tutoring/vector_store.py:126-127` 注释）

**6. 面试口述要点**：COS 向量桶写入是异步生效的，spike 实测要等 ~10 秒才能查到——所以"建锚后立刻查近邻"这个路径是有坑的，我们设计成首题建锚不立查，后续题目查询时近邻已经可见。
