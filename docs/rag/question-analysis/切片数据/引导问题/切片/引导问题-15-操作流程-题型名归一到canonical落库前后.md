# 题型名是怎么归一到 canonical 的？在落库前还是落库后？

## 回答

**核心结论**：题型名**在落库前**归一到 canonical——识别出的题型名先过 `vector/query` 查最近邻（distance ≤0.2 归并 / 首题建锚），canonical 动态锚定后掌握表从源头不裂行。

**分层展开**：
- **归并步骤**：识别题型名 → `POST /api/tutoring/vector/query` 查最近邻 → Java `TopicLabelAggregationService.aggregate`：distance ≤0.2 归并到命中 canonical（写别名表）/ 0.2~0.3 建新 / ≥0.3 异型建新 / 首题无近邻建锚。（依据：完善文档 06 / 分析-06）
- **落库前**：canonical 在落库前动态锚定——题目表和掌握表从源头就用 canonical key，不会先存原始名再归并导致裂行。（依据：完善文档 02 落地真相 / 分析-06）
- **前置字符规则**：归并前先过字符级归一（"解X/求X"前缀剥离 + 全半角/空白/标点归一），拦确定性变体省 embedding 调用。（依据：完善文档 06）
- **⚠️翻转**：编辑距离 ≤1 近字归并**已移除**（"一元一次/一元二次"与错别字同为距离 1 会误并），近字/错别字归并全交向量层。（依据：完善文档 06 / 坑档案 J-QT2）
