## 回答

**核心结论**：同一个词 PENDING 在两个接口里含义**完全相反**——识别层的 PENDING = "题型没认出来"（展示候选，到此为止，不查掌握度）；掌握度层的 PENDING = "题型已练、知识点待确认"（题目记录有但 canonical 未归属）。**绝不共用一个判断变量**。

**分层展开**：
- **识别层 PENDING（analyze-question）**："题型没敢确定"——低置信识别，返回 candidates 候选清单让学生确认，**到此为止不再查掌握度**；识别失败 = 空 topic_labels → Java 降级 PENDING。（依据：完善文档 02 / 分析-04）
- **掌握度层 PENDING（getMastery）**："题型已练但知识点待确认"——题目记录有但 canonical 未归属（新语义，不再来自 obs 挂起）。（依据：完善文档 02 / 分析-08）
- **为什么是坑**：前端若用一个 `status === 'PENDING'` 分支处理两类状态，会把"识别失败"和"待确认"混成一种展示，学生看到错误状态。（依据：坑档案 J-QT3）
- **解决**：两层分开判——识别结果 RESOLVED → 查掌握度 / PENDING → 展示候选到此为止；掌握度结果 RESOLVED+四档 / PENDING → 待确认。（依据：坑档案 J-QT3 / 完善文档 02）
