## 回答

**核心结论**：本期**查表只读 + ADMIN 手动维护**，不做自动关联——因为题型↔知识点业务不成熟，自动关联会引入 5 个环节（obs 状态机/聚合批处理/LLM 归纳/vote 澄清/派生覆盖度）分散核心，且易污染权威图谱。

**分层展开**：
- **现在怎么做**：识别题型 → `findByTopicLabelOrAlias` 查题型库 → 命中返回权威分布 / 未命中返回"仅题型 + canonical + 空知识点"——不挂起、不写 obs、不顺带 LLM kps。（依据：完善文档 07 / 分析-08）
- **为什么不做自动关联**：① 业务不成熟，自动关联引入 5 个环节分散本期核心（题目→题型→掌握度）；② 易污染权威图谱——关联错了经先验放大污染全体学生，**权威图零写入红线**。（依据：完善文档 07 / 08）
- **⚠️翻转事实**：早期方案是"派生层自动关联 + 共现聚合 + 自动维护闭环"——已调整为域 B 独立化：查表只读 + ADMIN 手动维护；停用 obs 共现→LLM 归纳自动关联、upsertPendingIfAbsent 挂起、学生 vote、聚合批处理、KpCoverageAppService 派生。（依据：完善文档 07 落地真相 / 分析-08 对账）
- **演进**：ADMIN 维护接口是下期"题型库管理后台"的雏形。（依据：完善文档 07 / 08）
