## 回答

**核心结论**：答疑产生信号 → 落题目表 + 掌握表 → 掌握度页展示 → 快照回流 decide；**答疑链路不直接写知识图谱**——图谱点亮是独立变更（kp-matching-lightup），权威图谱零写入。

**分层展开**：
- **答疑→掌握度**：答疑 decide 每轮输出 `mastery_signals`（题型三档）→ Java 落题目表 + 掌握表累计平均 → 掌握度页展示 → `mastery_snapshot` 回流下一次 decide（薄弱题型优先讲解）。（依据：完善文档 05 追问 / 分析-07）
- **答疑→图谱**：答疑/题型链路**不直接写 Neo4j**——图谱点亮由独立变更 `kp-matching-lightup` 承担；题型↔知识点关联放派生层 MySQL（查表只读 + ADMIN 维护）。（依据：完善文档 07 / 分析-08）
- **权威图谱零写入**：Neo4j 只被"借结构"（持 URI 向外展开），关联错了也不污染教育局图谱。（依据：完善文档 07 / 分析-08）
- **Python 边界**：Python 显式禁止做题型↔知识点映射（`models/tutoring.py:73-76`）——只输出信号，映射全在 Java。（依据：分析-08）
