## 回答

**核心结论**：开思考模式下学科门判定要 **50~145 秒**，完全不可接受。慢修复 = **关思考 + 20s 超时 + 关 SDK 重试**——慢或失败快速返回空结果让 Java 走降级，**宁可快速失败走降级，也不让主链路等**。

**分层展开**：
- **实测**：开思考 50~145s、关思考秒出（学科门/题型识别统一）。（依据：坑档案 J-QT6 / 完善文档 04）
- **慢修复三件套**：关思考（thinking disabled）+ `request_timeout=20` + `max_retries=0`——写死在 `subject_classify.py:66-73`、`question_understand.py:82-91`。（依据：坑档案 J-QT6 / 分析-03/10）
- **降级路径**：慢/失败快速返回空结果 → Java 降级（学科门闭集外按 math 放行 / 空 topic_labels 降级 PENDING）。（依据：坑档案 J-QT6 / 完善文档 04）
- **为什么**：前置判定环节最怕变卡点——学科门/题型识别不能成为答疑链路新卡点，用降级换可用性。（依据：坑档案 J-QT6 / 分析-10）
