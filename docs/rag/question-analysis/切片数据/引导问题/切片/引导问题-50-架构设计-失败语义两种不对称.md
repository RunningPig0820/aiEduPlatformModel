## 回答

**核心结论**：**业务判定失败 ≠ 错误，向量失败 = 基础设施故障**——学科门/题型识别吞异常降级空结果（宁返回空不阻塞，Java 走 PENDING/放行）；向量 put/query 错误冒泡（让 Java 感知失败再降级）。不对称是**刻意设计**，不是疏漏。

**分层展开**：
- **业务判定（吞异常降级空）**：question-understand / subject-classify 全部 try/except，失败返回空 topic_labels / 空 subject——"识别失败"是业务状态（走 PENDING/放行），不是系统错误。（依据：分析-02 / 分析-10）
- **向量（错误冒泡）**：向量 put/query 失败 → HTTP 500（未知 vector_type → 400），不吞异常——向量是基础设施，必须让 Java 感知失败才能正确降级（回退字符规则 + 原样落库）。（依据：分析-02 / 分析-10）
- **为什么不对称**：业务判定失败有明确的业务降级语义（PENDING/放行），吞掉是安全的；向量失败如果吞掉，Java 会误以为归并成功、落库错 canonical——必须冒泡让上游决策。（依据：分析-02 设计要点）
- **注释铁证**：`api/vector.py:8-9` "向量不同于 question-understand 的吞异常降级空结果——向量是基础设施，让 Java 感知失败"。（依据：分析-02）
