## 回答

**核心结论**：结构化输出（ActionMeta）走**四段降级管线**：① function calling → ② JSON mode → ③ 正则提取 → ④ 兜底 `type=hint, degraded=true`——保证 ActionMeta 绝不畸形、绝不抛异常，让 Java 靠 `degraded` 标记监控 Python 降级频次。

**分层展开**：
- **四段管线**：`structured.py:251-277`——function calling（Pydantic 绑定 schema）失败 → JSON mode → 正则提取 → 兜底（`type=hint, degraded=true`）。（依据：分析-09 / 分析-10）
- **为什么多段**：LLM 输出不稳定（模型关思考后偶发直接吐 JSON、字段名漂移），多段保证"只要模型给出任何可解析内容就能收敛"，绝不抛异常。（依据：分析-09 / 分析-10）
- **纠错重试**：corrective_retries=1（只修 schema 不整段重生成），情绪值宽容归一 `_normalize_emotion`（中文/小写→大写枚举），避免整条 ActionMeta 校验失败丢信号。（依据：分析-09）
- **degraded 监控**：兜底 `degraded=true` 让 Java 监控 Python 降级频次——排查是降级不是 bug。（依据：分析-10）
- **⚠️关联坑**：function calling schema 与纠错提示词字段名必须同步（`kp_label→topic_label` 改名脱节曾导致信号静默丢失）。（依据：坑档案 J-QT7）
