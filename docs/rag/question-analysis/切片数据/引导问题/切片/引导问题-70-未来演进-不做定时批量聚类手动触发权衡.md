## 回答

**核心结论**：不做定时批量聚类 = **面试项目不引入定时复杂度**——Python 侧无定时任务/批处理（`vector_store.py` 只有 put/query 原语），Java `@Scheduled` 已移除改**按钮手动触发**。权衡：用"人工确认链路"换"批量误并风险"——批量聚类若自动跑，误并会和当前手动确认链路冲突。

**分层展开**：
- **现状**：Python 侧无"批量聚类"（只有即时 put/query 原语）；Java `@Scheduled` 定时批量已移除改手动触发。（依据：完善文档 06 落地真相 / 分析-06 设计要点）
- **为什么不做定时**：① 面试项目不引入定时复杂度（调度基础设施 + 幂等/断点续传）；② 批量误并与当前手动确认链路冲突——自动批量聚类误并无法人工把关。（依据：完善文档 08 / 06）
- **手动触发是什么**：散名全量聚类 → 补归并 + LLM 归纳规范名 → 重算聚合，由按钮手动触发，人工确认后再生效。（依据：完善文档 06）
- **将来**：大数据语义聚类（阶段 4）再引入规模化手段，需调度基础设施 + 幂等/断点续传前置。（依据：完善文档 08）
