# 任务：引导问题列表 → 带答案的问答切片

## 文件元信息
> 用途: 读取 `7. 引导问题/问题列表.md`（9 视角 70 问，纯问题不回答），**为每条问题产出带答案的问答切片**——一个问题一个 md，答案直接可用（引导问答 / 面试口述 / 评测答案）。输出到 `切片数据/引导问题/切片/`。
> 权威度: 1.0（**合成问答答案切片**——指"直接作答"，不是原始证据；原始证据文档权威度 0.8，勿混淆）｜ 模块: question-analysis ｜ 类别：9 视角闭集
> 定位：**问题列表 = 问题矿**（guide_pool + 评测集用）；**本切片 = 答案库**（RAG 直接召回作答）。两者配套构成问答闭环。

## 角色
你是 RAG 引导问答切片助手。输入：**单条问题 + 该问题所属视角对应的完整原始参考语料片段**（完善文档 / 分析 / 坑档案 / 语雀）。
> ⚠️ **禁止仅输入问题文本就生成答案**——必须附带该视角原始参考语料；缺少参考语料不得产出切片（否则模型靠内部记忆编造）。
任务：产出一个**自包含问答切片**——标题是问题、正文是可直接作答的答案，引导/面试被问到时能照讲。
> 回答兼顾两套场景：① RAG 前端引导问答；② 候选人面试口述。核心结论简洁、技术要点完整；避免过度学生向口语，也避免纯开发调试黑话。

## 硬性规则
1. **答案第一铁律：只答语料里有的，严禁编造**——语料未实现/未做的如实写"本期未实现 / 不做（Non-Goal）"，禁止臆造已实现。
   > **兜底**：若给定参考语料内找不到对应答案，**不编造**，直接写明 `> 当前参考语料未覆盖该问题，请补充对应源文档片段，暂不生成完整回答`，不产出完整切片。
2. **口径对齐 + 区分方案与落地现状**：答案与 完善文档/分析/坑档案 一致，术语统一（canonical/两域 A·B/PENDING/动态涌现/聚集/打折系数）。**design 设计方案 ≠ 线上代码现状**——遇到 ⚠️翻转（方案与实现不一致）必须在回答中体现差异；现状优先级：**代码分析文档、坑档案 > 语雀/OpenSpec 设计文档**。
3. **可直接照讲**：核心结论一句话直接回答；分层展开要点式，面试/引导可照读。
4. **证据标注精确到编号**：每个要点末尾标 `（依据：完善文档 01 / 分析-02-微服务分工 / 坑档案 J-QT3）`，**禁止只写大类**（如"完善文档"）。
5. **技术名词保留但要解释**：canonical/PENDING/聚集 等技术词直接用，但一句话解释清含义。
6. **涉及流程/链路的问题**：
   - mermaid **只复用原始参考语料中已存在的图，禁止凭空绘制语料没有的流程图**；
   - 完整保留 mermaid 不切破，并配套文字复述链路；
   - 原始语料没有 mermaid → 只用文字描述链路，**不新建流程图**。
7. **每问一文件，不合并问题**；问题编号、所属视角不变。
8. **类别 / 节 = 9 视角闭集**（项目介绍/操作流程/数据关联/开发难点/业务流程/架构设计/业务视角/数据存储/未来演进），禁止自造新类别。
9. **文件名短名规则**：问题去除全部中英文标点、过滤操作系统非法文件名字符 `/\?*"<>|`，只保留中文/字母/数字/下划线，截取前 20 字符。

## 输出格式（每个问题 1 个 md，输出 `切片数据/引导问题/切片/`）

文件：`引导问题-{编号}-{视角}-{问题短名}.md`

```markdown
# {问题原文}

> summary: {问题原文}
> 权威度: 1.0
> 模块: question-analysis
> COS路径: rag-slices/question-analysis/引导问题/引导问题-{编号}-{视角}-{问题短名}.md
> 类别：{视角}

---

## 回答

**核心结论**：{一句话直接回答，面试/引导可照讲}

**分层展开**：
- {要点 1}（依据：完善文档 01 / 分析-02-微服务分工）
- {要点 2}（依据：坑档案 J-QT3）

> 证据：详见 `7. 引导问题/问题列表.md`（第 {编号} 问）｜ `4.完善文档/0X-*.md` ｜ `3.代码/分析-0X-*.md` ｜ `5.难点/坑档案.md`
```

## summary 规则
- summary = 问题原文（引导问答按问题检索命中，问题即锚点，不做标题式压缩）。

## 输出前自检（必过）
1. ✅ 每问 1 文件，编号/视角/问题短名正确（短名已过滤非法字符）；问题原文完整作标题。
2. ✅ 答案全部来自**输入附带的参考语料**，无编造；Non-Goal 如实标注"未实现/不做"；参考语料未覆盖的问题已走兜底，不产出完整切片。
3. ✅ 核心结论一句话 + 分层展开要点，同时适配引导问答与面试口述。
4. ✅ 术语口径一致，区分设计方案与线上落地现状（⚠️翻转已体现）。
5. ✅ 每要点依据精确到文档编号；末尾带全局证据指针。
6. ✅ 类别/节 = 9 视角之一；权威度 1.0；COS 路径与磁盘输出一致。
7. ✅ mermaid 未凭空生成，全部复用原始语料已有；无参考图则只用文字描述链路。
8. ✅ 文件名短名已过滤操作系统非法字符。

## 使用提示
1. 一次处理 1 个视角（5~11 问），产出该视角全部问答切片；9 视角共 70 文件。
   > ⚠️ 单次执行**必须带入该视角完整原始参考语料片段**，不要只传入问题列表文本；缺少参考材料会导致编造答案。不建议单次超过 11 个问题，避免上下文过载丢失语料细节。
2. 产出前清空 `切片数据/引导问题/切片/` 旧切片（保留 readme.md / 处理方案）。
3. 新模块复用：改模块 id / 源路径 / 输出目录 / 视角映射表；若目标模块无「业务流程」视角对应语料，删除该分组（视角数随之减少）。
