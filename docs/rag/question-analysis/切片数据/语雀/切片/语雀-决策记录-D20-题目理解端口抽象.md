### D20 题目理解端口抽象，Java LLM 默认实现（prompt 注入题型库收词）

> 状态：✅
> 检索摘要：新增 QuestionUnderstandingPort 端口，Java KpQuestionAnalyzer 默认实现，prompt 注入题型库 top-N 已收词约束命名，降低题型名变体漂移。

| 属性 | 内容 |
|---|---|
| 背景 | 题目文本 → 题型名的题目理解只在 Python decide 会话内（SSE 绑定），无独立 REST |
| 演进 | 无独立题目理解 → domain 端口 + Java LLM 默认实现（端口预留可换 Python 独立端点） |
| 拍板理由 | Java 自包含不阻塞跨仓库；prompt 注入题型库已收词让命名偏向现有词汇（别名合并之外第一道防线，纯 prompt 零成本） |
| 系统影响 | 换实现只动 infra 装配，不动 domain/application；analyze-question 依赖该端口 |
| 证据 | design-backend-kp-question-analysis D1 |

> 证据：详见 `1.语雀/语雀-决策记录.md`（§D20）｜ 完善文档 03-架构与微服务分工.md
