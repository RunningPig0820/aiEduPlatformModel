### D24 设计原则：逻辑优先于数据准确，数据可后整理
> 检索摘要：先打通「题目→关联→确认→沉淀」逻辑闭环，不因数据残缺阻塞实现；各类数据错误由后续机制整理（vote 纠正/维护重判/别名合并/管理端审核）。

| 属性 | 内容 |
|---|---|
| 背景 | 镜像/题型库残缺是冷启动常态，数据不准易阻塞流程 |
| 演进 | 追求数据准确先行 → 逻辑优先，错误后整理 |
| 拍板理由 | 恒非空返回「池内最相近」允许出错，错误由 vote 纠正/维护重判/别名合并/管理端审核整理，而非阻止流程 |
| 系统影响 | 先跑通逻辑闭环，质量收敛依赖真实数据飞轮（学生确认参与），是产品积累曲线而非代码交付 |
| 证据 | design-backend-kp-question-analysis D11 |
