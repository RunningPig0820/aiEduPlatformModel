### 选型9：题目理解实现位置选型（Java 自研 LLM vs Python 独立端点）
> 检索摘要：题目文本→题型名的题目理解采用 Java 自研 LLM 实现 + 端口抽象，预留 Python 独立端点可替换；prompt 注入题型库已收词降低变体漂移。

- 选型场景：题目理解能力放哪一端、以什么形态暴露
- 候选方案A：Java 自研 LLM 实现（domain 端口 + infra KpQuestionAnalyzer）
  - 方案A优劣：自包含、不阻塞跨仓库；prompt 注入题型库 top-N 收词让命名偏向现有词汇（零成本第一道防线）
- 候选方案B：Python 独立题目理解端点（拆 decide）
  - 方案B优劣（致命短板）：跨仓库、需协调；命名变体靠别名合并 + prompt 词表兜底
- 最终拍板：Java 自研 + 端口抽象（QuestionUnderstandingPort），Python 端点作后续可替换实现
- 拍板理由：用户已拍板 Java 自研；端口抽象保证换实现只动 infra 装配，不动 domain/application（D20）
- 证据：design-backend-kp-question-analysis D1
