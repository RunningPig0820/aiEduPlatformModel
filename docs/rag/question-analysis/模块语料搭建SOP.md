## 三、完善文档 9 节（权威 1.0 正文标题）

| 节 | 标题 | 对应问题表 | 类别 |
|---|---|---|---|
| 01 | 模块定位与核心价值 | 项目介绍 | 项目介绍 |
| 02 | 题型分析主流程怎么走 | 操作 | 操作流程 |
| 03 | 架构与微服务分工 | 架构设计 | 架构设计 |
| 04 | 防作弊与异常防护 | 难点 | 开发难点 |
| 05 | 数据落库与掌握度 | 数据关联 ★ | 数据关联 |
| 06 | 题型动态聚集与向量 | 数据关联 ★ | 数据关联 |
| 07 | 题目知识点与图谱关联 | 数据关联 | 数据关联 |
| 08 | 演进路线 | 未来演进 | 未来演进 |
| 09 | 业务闭环与两域解耦 | 业务流程 ★（2026-08-27 评审补节，闭环全景+两域A/B） | 业务流程 |

每节固定结构：`## 为什么（语雀）` → `## 怎么设计（方案）` → `## 落地真相（代码）` → `## 追问与防御` → `## 证据引用`。代码真相写 `文件:行号` 证据，方案与代码口径不一致处用 `> ⚠️ **翻转**` 标注。**权威 1.0 前置校验**：必须同时具备方案素材 + 对应主题分析文档落地真值，缺失代码证据禁止 1.0 降为 0.8。

**文件头固定 5 行标准（与语雀/3.代码 统一，2026-08-27 定）**：
```
> summary: 解答「{业务问题}」——{一句话说明如何解决，关键词密集，不写实现细节}
> 权威度: 1.0
> 模块: question-analysis
> COS路径: rag-source/question-analysis/完善文档/0N-{标题}.md
> 类别：{从 9 视角集合选 1}
```
节号（0N）只在文件名与标题体现，元信息头不重复。

**完善文档 vs 1.语雀（防混淆）**：完善文档 = 权威正文层（1.0，**整篇进全量池不切片**，直接当答案）；语雀 = 产品意图/设计决策层（0.8，切块进切片池，回答"为什么/权衡"，不能直接当答案）。检索规则：先正文层，正文答不了的"为什么/演进"才落语雀层。9 视角全覆盖：业务视角并入 01、数据存储并入 05（补存储拓扑表）、业务流程=09 独立成节。

### 第 ② 步：文档对齐（方案 vs 代码）

产出 `方案-代码对账.md`，本模块核心口径翻转 6 处：

| # | 项 | 方案 → 代码现状 |
|---|---|---|
| 1 | 掌握度主体 | 知识点 URI → **题型**（canonical 题型名） |
| 2 | 掌握度数值 | 离散四档 max 单调不减 → **连续 0-100 累计平均** |
| 3 | canonical 来源 | 预置题型池 → **动态涌现**（首题建锚） |
| 4 | 聚集依据 | 题目向量为主 + 题型名向量为辅 → **只题型名向量单信号** |
| 5 | PENDING 语义 | obs 挂起（知识点待确认）→ **题目记录有但 canonical 未归属** |
| 6 | 字符归一 | 编辑距离 ≤1 近字归并 → **移除**（会误并"一元一次/一元二次"），全交向量层 |

### 第 ③ 步：完善文档 9 节

用 `4.完善文档/处理方案/提示词/完善文档-生成-提示词.md` 生成，权威 1.0 是主答案，质量最关键。写作时以 `语雀-方案总揽.md` 为动机源、`3.代码/分析-*.md` 为落地真值、design 为方案口径。**硬性规则**：①权威 1.0 前置校验（方案素材 + 代码真值缺一降 0.8）②五段结构（为什么/方案/落地真相/追问防御/证据）③Non-Goal 不冒充已实现 ④整篇禁切（进全量池不切片）⑤文件头 5 行标准（summary/权威度/模块/COS路径/类别）。详见 Phase 7。

### 第 ④ 步：切片（提示词 + 大模型语义分组，2026-08-27 改）

> **切片方式改为提示词 + 大模型**：语义分组（判断哪些节该合并）是模型擅长的事，硬编码脚本前缀规则易踩坑（h3/同组合并边界）——脚本方案（slice_corpus.py 等）已废弃，改用提示词让模型按语义切，更准、可复现。

- `切片清单.md` 定进库边界（四层：完善文档/语雀总揽/design/代码，proposal 与原始问答不进）
- 提示词：`切片数据/代码/处理方案/提示词/切片-分组-提示词.md`（语义分组合并，开发 + 面试向共用）

**代码层双切片（同一份源文档 → 两套切片）**：

| 切片 | 分组（每份 3 块） | 输出位置 | 消费方 |
|---|---|---|---|
| **开发切片** | 业务链路 / 代码事实 / 坑与对账（原文拼接，保留代码证据） | `切片数据/代码/切片/` | 开发查问题/对账 |
| **切片（面试向）** | 业务与流程 / 架构与技术取舍 / 落地问题与复盘（过滤代码噪声+转述） | `切片数据/代码/切片/` | 面试官提问/候选人介绍 |

> **切片统一放 `切片/`**（2026-08-27 定）：开发向/面试向同目录，靠文件名（面试向带块名/`-复盘`）+ `target: 面试项目问答` 区分；坑档案双切片同理（一坑一文件，见 Phase 8 ㊱）。

**切片注意事项（代码真相层 3.代码 专属，2026-08-27 评审沉淀）**：

1. **语义分组，不机械 h2 切**：把关联小节合并成大块（业务描述+职责+调用链→业务链路；代码事实+设计要点→代码事实；隐性坑+对账→坑与对账），避免碎片化（职责 110 字/设计 239 字各自成块无意义）。
2. **面试向切片过滤代码噪声**：过滤文件路径/行号/原始 API/枚举表；对账表转自然语言复盘（每条 ⚠️翻转/✅落地 结论句保留）；mermaid 完整保留；summary 短标题式（`{主题}{块名}`）；头部去 权威度/模块（保留 summary/来源/锚点/节/COS路径/类别/target）；每块带**证据指针**（可回源 分析-0X / 完善文档 0X）。
3. **表格/代码块/mermaid 不切破**：整块搬进所在分组；mermaid 向量不可读——**关键链路信息必须同时存在于正文文本段落**。
4. **chunk 上限**：≤6000 字符，超限按段落拆多块、不丢尾部。
5. **块元数据**：`doc_type=code_analysis` + `authority=0.8` + `source=代码` + `module=question-analysis`；`file_path` 指向源文档（`3.代码/分析-XX-*.md`），前端"查看原文"可回源。
6. **检索侧来源区分（入桶前的规则，非切片操作）**：code_analysis 只答**接口/参数/降级/对账翻转/代码真实行为**；**不答"为什么这么设计/选型权衡"**（那是 canonical 决策记录/选型对比职责，代码层缺设计背景）——RAG 系统 prompt 必须按 `doc_type` 做来源过滤/优先序，禁止用代码真相文档裸答业务设计权衡类问题。
7. **切片统一落 `切片/`，类别钉死 9 视角闭集（2026-08-27 定）**：同一来源开发向/面试向切片都放 `切片/`，靠文件名（面试向带块名/`-复盘`）+ `target: 面试项目问答` 区分，入桶按 `target` 路由；**类别字段只取 9 视角之一**（项目介绍/操作流程/数据关联/开发难点/业务流程/架构设计/业务视角/数据存储/未来演进），坑档案/落地问题复盘固定 `开发难点`，禁止 `项目难点复盘` 等游离值。

**语料整理方法论（本模块沉淀的关键经验）：**

1. **语雀问答材料先汇总成总揽再进语料**——问答口吻（来回质疑/提问者视角）不适合 RAG，先整理成正式综述，切片质量才高。
2. **问题列表先于完善文档**——把语雀里待解决/待决策的事项先提炼成问题列表，让"已定/建议项/待决"在写正文前浮出，正文不臆造未决事项。
3. **决策/选型迁出为独立文档**——决策记录/方案选型对比这类表格化条目，独立成文 + 切片后每块就是"一条决策/一组选型"，RAG 命中粒度最好；总揽保持叙述性综合，只留指针，不双维护。
4. **提示词库单任务独立**——每个文档一个独立提示词（决策/选型/演进/边界/联调 + 辅助A增量/B校验/C术语），各自自包含通用底座（术语统一/状态判定/证据规范/自检），放一起生成容易格式漂移，剥离独立后单任务生成质量更好。
5. **RAG 块级结构（语料梳理核心）**——条目型文档每条一个 `### H3` 独立块 + 顶部 `> 状态` + `> 检索摘要`（1-2 句作向量锚点）+ 内部窄表/分级列表 + 文档末尾附录标注"仅供人工查阅，不参与 RAG"——**一个 chunk = 一条决策/选型/场景/问题/阶段**，适配标题切片，命中粒度最好。禁止宽横向大表作主体（切片行被切断、语义断裂）。
6. **双池入桶**——完善文档（权威 1.0）直接整篇进全量池（一个问题=一节完整答案）；语雀/OpenSpec/坑/引导/代码（0.7~0.8）切片进切片池（细粒度块）。代码证据层=`doc_type=code_analysis`，`###` 切块但**不强制检索摘要**，专答「代码真实行为」类精确问题（与业务层区分：业务块强制检索摘要）。

### 顺序方法论总结

1. **先汇总再提炼**：语雀问答 → 总揽(综述) → 问题列表(待决浮出)，顺序不可反。
2. **落地真相先行**：代码深读 → 对账 → 才写权威正文，防止正文臆造。
3. **提示词先合并后剥离**：初版合并生成发现格式漂移 → 剥离独立 → 删总索引，迭代方向是"越独立越好"。
4. **RAG 块级结构是后补的认知**：宽表不行 → 豆包格式(###+状态+检索摘要+附录)，这是语料质量的转折点。
5. **spec 先价值评估再处置**：找问题地图 → 评估删 → 用户纠正恢复 → 归档 → 建增量桥，顺序是"先理解价值再动手删"。
6. **spec 双轨：补充语雀方案 + 自身成文进池**：OpenSpec design 的 Context/Decisions = 语雀方案"为什么"的增量来源，也是自身 RAG 文档的信息主体——① 跑 `spec信息补充提示词` 把收敛事实折入语雀 canonical（决策/选型/场景/问题/演进，递增编号+证据）回答"为什么"；② 跑 `spec文件整理提示词` 把每份 design 各自成文 `2.OpenSpec design 决策/design-*.md`（**权威度 0.7 素材溯源库**，100% 保留 Migration/Risks/OpenQuestions，summary 一句话高层概括，文档说明带 ⚠️ 警告）进池补细节。**检索规则：优先 0.8 canonical 真相源，主库无答案才引用 0.7 素材库并提示「请核对代码确认落地」，禁止 ⚠️/❓ 当已上线**。原始 design 归档 `原来的文件/` 仅人肉溯源。
7. **检索摘要=路标、summary=高层（豆包标准）**：检索摘要 1-2句≤120字符、模拟用户真实提问、埋核心实体，禁罗列枚举/堆实现细节（参数/备选/风险明细留正文）；summary 一句话高层概括，禁①-⑧长列点枚举。两者都是向量锚点决定检索命中质量——写完后自问「用户口头会不会这么说」，是则合格，只是把段落缩一遍则需精简。
8. **代码证据层四要（真读代码 / 三端核对 / 业务场景先行 / 元数据锚点）**：3.代码 是"代码真实行为"层的真值源——① **真读代码第一铁律**：只写代码可观测事实，禁止凭记忆/从语雀/design/对账转述当代码事实、禁止画"纸上流程图"（分支必须有代码出处）；② **三端必须一起读**：判定主题跨哪几端、每端真实打开文件，跨端契约两端对照核对，缺一端不准写全链路，已读清单按前端/Java/Python 分组可复核；③ **业务描述与业务场景先行**：每份文档 `## 职责` 前必须有纯业务语言（不出现代码名词）的业务描述 + 2-3 条具体场景（谁/何时触发/期望结果），让业务视角提问能命中（参照 ai-tutoring `业务情况` 模式）；④ **元数据块**统一 `summary/权威度/模块/COS路径/类别`，summary 说明**解决什么问题**作检索锚点，调用链标题写明业务名。
9. **权威正文层四要（视角全覆盖 / 1.0 前置校验 / 整篇禁切 / 文件头统一）**：4.完善文档 是"业务是什么/为什么"的权威正文层——① **9 视角全覆盖**：按问题表视角组织（项目介绍/操作流程/数据关联/开发难点/业务流程/架构设计/业务视角/数据存储/未来演进），补节标准=检索命中率（有高频问题召回被切碎才独立成节），业务视角并入 01、数据存储并入 05 补存储拓扑表；② **1.0 前置校验**：必须同时具备方案素材 + 代码分析真值，缺失代码证据禁止 1.0 降 0.8；③ **整篇禁切**：正文整篇一个 chunk 进全量池，禁止内部 ##/### 切（与代码层 ### 切、素材层 ### 切区分）；④ **文件头 5 行标准**统一 `summary/权威度1.0/模块/COS路径/类别`，与语雀/代码层同格式。与 1.语雀 的区别：正文层答"业务是什么/为什么"直接当答案（1.0 全量池优先召回），语雀层答"设计决策的为什么/权衡"（0.8 切片池补充，正文答不了才落）。
10. **旁支层也要"readme + 提示词 + 文档头标准"三件套，且提示词必须模块专属**：5.难点/7.引导问题 是语料库的旁支层（不是主链），但同样要配 `处理方案/readme.md` + `处理方案/提示词/*.md` + 文档头 5 行标准。**教训：从其它模块拷贝提示词必须适配**——`坑-提示词.md`/`ai-tutoring-提示词.md` 曾是 ai-tutoring 拷贝未改路径/业务/编号，生成会全错。坑档案防编造第一铁律 = **真挖三端 git log + 双证据**；引导问题 = **可回答性第一**（每条问题能在语料中找到答案）且**问题列表须同步进代码 GUIDE_POOL**（只放问题不写答案，前端"开始引导"才生效）。切片数据目录先立骨架（对齐 ai-tutoring 5 来源 + 每来源 readme/处理方案），切片 md 文件由 QT⑥ 导出填充。
