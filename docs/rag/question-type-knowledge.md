# 题型知识点 — 面试问题整理

> 模块定位：题型动态聚集（向量归一 canonical）+ 掌握度分析（主体是题型，不是知识点），多维能力画像。
> 所属大纲段：1 项目介绍 / 3 数据入库 / 4 数据关联 / 5 难点

## 1. 项目介绍

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 题型知识点模块做什么？ | 把学生散乱的答题记录聚成 canonical 题型，算掌握度、出能力画像 | "掌握度给谁看？" → 学生雷达图 / 教师视图 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 这和知识图谱什么区别？ | 知识图谱是知识结构，这是学生个人能力画像，靠题型可测 |

## 3. 数据入库

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 掌握度数据从哪来？ | 答疑/答题事件落库 mastery_snapshot | "怎么保证准？" → 事件驱动，题→题型→掌握度 |
| 题型怎么归一？ | 向量语义聚集（dashscope embedding → COS 向量桶）成 canonical | "向量桶挂了？" → 降级字符规则 + 原样落库 |

## 4. 数据如何关联

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 题型和知识点怎么关联？ | 题型↔知识点多对多映射，交叉分析综合能力 | "映射哪来的？" → 题目标签 + 图谱匹配 |
| 掌握度为什么挂在题型不是知识点？ | 学生做的是题，**题对应题型可测**；知识点是间接推断 | "那知识点掌握度呢？" → 由题型聚合推导 |

## 5. 项目开发中有什么难点

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 题型归一为什么用向量不用字符规则？ | "一元二次方程" vs "解一元二次方程" 语义变体，规则匹配不了 | "向量方案怎么验证？" → 聚集后人工抽查 |
| 掌握度怎么算/怎么衰减？ | 多维能力（概念理解/计算/逻辑/审题），按答题事件更新 | "连续错怎么办？" → 判定薄弱点，推针对性练习 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 学生乱答/只抄答案怎么办？ | 数据源来自答疑链路（防作弊前置），异常行为已拦截 |
| 数据量小掌握度不准？ | 事件累计 + 能力维度多信号，量小也先有趋势 |

## ⚠️ 最危险的可能问题（防御）

| 可能问题 | 防御要点 |
|---------|---------|
| 掌握度数值是怎么算出来的，可靠吗？ | 讲清事件→题型→能力维度→更新的完整链路，非拍脑袋 |
| 归一结果错了怎么办？ | 向量聚集 + 人工抽查 + 字符规则兜底双保险 |
| 这模块是不是只是统计报表？ | 强调题型归一用向量（真实检索能力）+ 联动答疑/图谱 |
