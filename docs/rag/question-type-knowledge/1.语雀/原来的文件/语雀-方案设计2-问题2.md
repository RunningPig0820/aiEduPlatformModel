  核心问题（你的第 6 点）：真的需要题型吗？

  我把这个问题的本质挖出来——它取决于向量匹配在哪个粒度可靠：

  题目实体（“鸡兔同笼”）—— 题型粒度
      ↓ 向量匹配
      ├─ 匹配其他题目（同粒度）→ 聚类成题型簇 ── 可靠 ✓
      └─ 匹配知识点（跨粒度）→ “二元一次方程组” ── 错位 ⚠️

  关键洞察：题型和知识点是不同粒度的语义。

+ 「鸡兔同笼」的语义 = 解题模式（假设法、应用题）
+ 「二元一次方程组」的语义 = 代数内容概念

  一道鸡兔同笼题的向量，离「假设法」「应用题」更近，离「二元一次方程组」并不近。向量匹配擅长同粒度相似（
  题目↔题目），不擅长跨粒度映射（题目↔知识点）。跨粒度必须靠 LLM 或映射表，不能靠向量硬匹配。

  所以——

  ▎ “直接定为到知识点”会撞回当初翻转的原因：会解鸡兔同笼 ≠
  ▎ 掌握二元一次方程组。你现在说“掌握度是百分比、误差可接受”，但那是容忍数值误差，不是容忍语义错位——如果
  ▎ 错位常态化，学生问“我鸡兔同笼练得咋样”时系统答的是“你二元一次方程 60%”，业务含义就又不通透了。

  但要题型的理由是“自举”，不是“预建题型库”

  建造方式。

  空题型库（现在）

  簇 → “鸡兔同笼”（题型名）

+ 现在 analyze-question 靠 LLM
  猜题型名（冷启动，不稳定）——向量库积累后，先用向量匹配收敛到已知题型簇，再用 LLM 兜底命名，这就是你坑 1
