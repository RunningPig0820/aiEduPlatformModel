回答你这一版把「题型掌握」的存储和更新算法定出来了，很好。我先把你的模型固化，然后给你补充清单——有几个前置
  问题不比“题型 vs 知识点”小。

  你的模型固化

  题目来源（记录所有入口）
    ├─ AI 答疑（产生题目 + 每题的掌握信号）
    ├─ 题型分析页（产生题目 + 题型识别，但无掌握信号）
    └─ 未来（练习/题库做题）
          ↓ 记录
  题目表（内容 + 来源 + 向量ID + 题型归属(暂) + 时间）
          ↓ 向量化存 COS
  定时任务：向量聚类 → 学生自己的题型 alias 统一成一行
          ↓ 聚合
  题型掌握表 { 题型 | 来源(ai/题库) | 掌握程度% | 训练题目数 }
    ├─ 更新算法（你给的）：new = old×(n/n+1) + score×(1/n+1)
    └─ 展示：题型 | 来源 | 掌握程度 | 跳转题目

  公式本身没问题——它就是“累计平均”（= 历史正确率）。n=9, old=60, score=100 → 64,
  n→10。语义直观。补一句：它永不衰减（早期错的题永远压着），如果想要“近期进步更明显”就用固定权重的
  EMA（new = old×0.9 + score×0.1）。v1 用你的累计版即可，语义是“做了 n 道题的正确率”。

  补充清单（按优先级）

  ① 掌握信号源只有一处：AI 答疑

+ AI 答疑 decide 已输出 mastery\_signals（答对/答错的信号）→ 这是唯一的掌握分来源。
+ 题型分析页只记录题目、不出掌握信号——学生只是贴了道题，没做，哪来的对错？
+ 所以：掌握表只会被 AI 答疑更新；题型分析/未来练习只是“积累题型库 + 记录题目”。
+ 需要定义：答对=100%、答错=0%、提示后答对=?（建议 50%）。

  ② 题目表的结构（跳转题目的前提）

  “COS 存向量 + 后端表存题目本体”：
  question: { id, studentId, content, source(AI/题库), vectorId, topicLabel(暂), createdAt }
  「跳转到题目」就是按题型查这张表。没有它，向量库只是无主的数据。

  ③ 未匹配/PENDING 题目的去向

  AI 题型不确定的题（PENDING）记入题目表，但不进掌握表——否则一个 PENDING 的 0%
  会把题型正确率拉下去。等定时任务向量聚类回收、或学生确认后再并入。

  ④ 计数规则：一次作答算一次

  同一道题被做 2 次：训练数 +2，公式跑两次（该题的 100 和 0
  都算）。这就是“训练题目数”的语义。别按去重后的唯一题数算，否则和公式对不上。

  ⑤ 一个必须拍板的后果：知识点总览页数据源断了

  题型↔知识点关联本期不做 → 老方案的「知识点总览」页（覆盖度着色）失去数据源（它原本靠 题型→知识点
  派生）。
  处置三选一：

+ (a) 本期明确它为空态展示入口（“暂未完善”），不承诺覆盖度；
+ (b) 保留 LLM 顺带判断的知识点（有则显示灰态）——跟题型分析页一致；
+ (c) 临时下线入口。

  ⑥ 契约冲突：现有掌握度是四档离散 {0,25,50,75}

  新模型的掌握程度是连续百分比（60%→64%）。现有 getMastery 返回离散四档 + status。要定：

+ 后端改返回 { 题型, 来源, 掌握程度%, 训练数 }，前端分桶成 已掌握/练习中/待巩固/待确认 徽标（如 <33
  待巩固 / 33-66 练习中 / ≥66 已掌握）；
+ 还是保留四档、只把分母换成累计。

  ⑦ 坑3 的最终落位（你还没完全定）

+ 锚题型：掌握表按题型，没记录 = “未开始”（灰态 + 跳转引导去练习）。
+ 知识点只做派生覆盖度（本期不做关联 → 也就不用处理）。
+ 我建议就按这个：掌握度锚题型 + 知识点本期断联，语义最通透。

  放一起的完整链路

  AI答疑 ──产生──→ 题目 + 掌握分(100/50/0)
  题型分析 ──产生──→ 题目 + 题型(可能PENDING)
          │
          ▼
     题目表 ──→ COS向量 ──→ 定时聚类统一题型(per学生)
          │
          ▼
     题型掌握表(题型/来源/掌握%/训练数) ←── 累计平均更新
          │
          ▼
     掌握度页: 题型行 + 来源 + 掌握%徽标 + 跳转该题型题目列表
