## 硬性规则（强制全部遵守）

### 术语强制统一
固定术语：canonical标准题型 / 派生层 / obs观测层 / 掌握度 / 解析管线 / 动态涌现 / 两域解耦。禁止自创别名。

### 状态判定标准
- ✅【已落地设计】：代码可观测到实现逻辑；语雀文档描述+代码同时存在。
- ⚠️【建议项(未实现)】：仅语雀方案文档描述，代码无对应实现。
- ❓【待决策 Open Question】：语雀和代码均无明确结论。

### 证据标注规范
1. 语雀来源证据：`证据：语雀-原文件-xxx.md`；引用总揽：`[总揽§X.X]`
2. 代码来源证据：优先写 `文件:函数名/类名`；无法获取真实行号时禁止编造虚假行号，写`文件:逻辑片段`。
3. 某类来源不可读，证据字段写`来源不可读，无有效证据`，禁止编造逻辑。
4. **每一个独立阶段小节，必须附带来源证据，禁止无证据条目。**

### 格式与内容约束
1. 移除全部对话、问答、来回讨论口吻；输出正式技术综述。
2. 重要流程使用有序列表或者文本流程图；规则、阈值全部使用表格承载。

4. RAG切片友好：段落简短，避免大段无分割文本。
5. **禁止业务臆造，所有内容必须来自来源材料。**
6. 引用本库内部文档标记：决策记录条目标记`D#序号`。

1. 文档开头增加【文档说明】：说明阅读提示——正文分块阶段用于 RAG 检索，阶段总览/附录仅供人工速读。
2. **文档开头放阶段总览（人工速读索引）**，标注"不参与向量检索"；正文再逐阶段 H3 小节。
3. **每一个阶段一条 `### 阶段N：名称` 独立 H3 小节**，适配标题切片，一个阶段 = 一个 chunk。
4. 每个 H3 小节顶部固定两行（缺一不可）：
   ```
   > 状态：✅/⚠️/❓
   > 检索摘要：xxx（1-2 句话提炼该阶段核心演进语义，作向量召回锚点）
   ```

5. 阶段内部用结构化条目（阶段时间/核心形态/迭代翻转/阶段详述/关联决策/落地证据）——阶段是叙述性内容，用分级列表/段落，**不用竖表**（候选对比/条目型才用竖表）。
6. **迭代翻转必须写"相对阶段N"**，明确前后版本差异。
7. 全部阶段输出完毕，文档最末尾追加【附录：原始阶段总览表】，标注仅供人工查阅、不参与 RAG 切片。
