## 硬性规则（强制全部遵守）
### 术语强制统一
固定术语：canonical标准题型 / 派生层 / obs观测层 / 掌握度 / 解析管线 / 动态涌现 / 两域解耦
> 禁止自行创造别名，出现陌生概念优先参考总揽文档。

### 状态判定标准（严格区分，禁止混淆）
- ✅【已落地设计】：**代码可观测到实现逻辑**；语雀文档描述+代码同时存在。
- ⚠️【建议项(未实现)】：仅语雀方案文档描述，**代码无对应实现**，属于设计构想、备选方案。
- ❓【待决策 Open Question】：语雀和代码均无明确结论，待后续评审拍板。

### 证据标注规范
1. 语雀来源证据：`证据：语雀‑原文件‑xxx.md`；引用总揽：`[总揽§X.X]`
2. 代码来源证据：优先写 `文件:函数名/类名`；**无法获取真实行号时禁止编造虚假行号**，写`文件:逻辑片段`；只有明确可见行号才写`文件:行号`。
3. 如果某类来源不可读（例如Java代码无法解析），证据字段写`来源不可读，无有效证据`，禁止编造逻辑。

### 格式与内容约束
1. 移除全部对话、问答、来回讨论口吻；输出正式技术综述，禁止提问者/回答者视角。
2. 重要流程使用有序列表或者文本流程图；规则、阈值全部使用表格承载。
3. 同主题信息归并，一处讲透，禁止碎片化重复；总揽已经详细阐述的内容不再复述，直接引用章节标记。
4. RAG切片友好：单表格不要超过20行，超长表格进行拆分；段落简短，避免大段无分割文本。
5. **禁止业务臆造，所有内容必须来自来源材料，没有来源就如实标记信息缺失，不能脑补设计。**
6. 引用本库内部文档标记：决策记录条目标记`D#序号`，其他文档引用写`D#X`。
7. **RAG切片块级结构（条目型文档强制）**：决策/选型/场景/问题等条目型内容，一律 **每条一个 `###` 独立小节** + 小节顶部 `> 状态：xxx` + `> 检索摘要：xxx`（1-2 句提炼核心语义，作向量召回锚点） + 内部用**窄属性竖向小表**（字段固定）。文档开头加【文档说明】（编号用途 + 阅读提示），末尾加【附录】总索引并标注 `⚠️仅供人工查阅，不用于 RAG 检索`。**禁止宽横向大表作文档主体**（切片时行被切断、语义单元断裂）。

### 输出前强制自检（输出文档结束前，逐条自检，不输出自检文本，只保证结果符合）
1. 是否区分 ✅/⚠️/❓状态，没有把建议项标记为已落地。
2. 所有代码相关条目是否附带证据，没有编造行号。
3. 是否删除问答对话口吻。
4. 是否出现术语别名，没有使用非标准命名。
5. 是否有重复内容，同类场景/问题已经合并。
6. 文档顶部元信息完整，summary、权威度、模块、COS路径、类别字段齐全。

### 失败降级
> 如果某一类来源完全不可读，直接跳过该来源信息，如实在证据字段标记，不编造内容。

## 使用说明
1. **顺序**：先跑 ①决策记录（**用独立提示词 `语雀-决策记录-提示词.md`**，单任务生成质量更好）→ ②方案选型对比(引用 D#) → ③演进时间线(引用 D#) → ④边界场景 → ⑤联调问题单。前三个互为参照，后两个相对独立。另跑 辅助C 术语对照表作全库词汇基准。
2. **产出位置**：`docs/rag/question-type-knowledge/1.语雀/语雀-{文档名}.md`（切片进池，**权威度 0.8**，与各 prompt 元信息一致）。文件头 COS路径 写 `rag-source/question-type-knowledge/语雀/语雀-{文档名}.md`。
3. **质量门**：每个文档生成后，对照"通用底座"硬性规则自检一遍。也可以调用辅助B校验器独立执行校验。
4. **与总揽关系**：总揽是主方案（叙述性综合），决策记录/方案选型对比等为**独立文档（canonical）**——总揽已删除 §13/§14 大表，决策/选型以独立文档为准；总揽已详述的内容引用章节号 `[总揽§X.X]`。
5. **迭代模式**：代码/语雀变更优先调用辅助A增量更新，不进行全量重生成。
6. **权威度口径**：语雀整合类文档（含本库 5 份 + 总揽）统一 **0.8**（代码接地，高于纯语雀原稿 0.7）；`模块` 统一填闭集 id `question-analysis`。
