## 一、架构层决策

### D1 权威图谱零写入，派生层（MySQL）承载
> 状态：✅
> 检索摘要：选择 MySQL 派生层，不写入修改权威 Neo4j 图谱，避免权威图谱被无限题型空间污染，复用原有图谱 URI 结构。

| 属性 | 内容 |
|---|---|
| 背景 | 题型空间无限（鸡兔同笼/相遇/浓度），知识点有限；把无限挂有限会图爆炸、污染权威图 |
| 演进 | 早期考虑物化进 Neo4j 扩展层 → 拍板 MySQL 派生层 |
| 拍板理由 | 权威图物理上不可能被污染；派生层可写可改可回滚 |
| 系统影响 | 图逻辑靠"持 URI 借结构"（expandNode 复用），不建图 |
| 证据 | 语雀-方案设计1-问题1；[总揽§1] |

### D8 两域解耦 + 域 B 独立化（查表只读 + ADMIN 维护）
> 状态：✅
> 检索摘要：关闭 obs 自动关联涌现链路，域 B 改为管理员手动维护查表模式，隔离题目解析链路与题型关联逻辑，降低系统复杂度。

| 属性 | 内容 |
|---|---|
| 背景 | 早期 obs 共现自动关联 + 挂起 + LLM 归纳 ratio |
| 演进 | obs 自动关联涌现链路 → 业务不成熟收敛，切换域 B 只读管理员维护 |
| 拍板理由 | 自动关联引入 5 环节分散本期核心（题目→题型→掌握度）；防污染权威图谱 |
| 系统影响 | 停用自动涌现链路；getMastery PENDING 语义改为"canonical 未归属" |
| 证据 | design-backend Decision 9/10；[总揽§7] |

### D13 Python 桥向量 + vector_type 多索引路由
> 状态：✅
> 检索摘要：Java 不直接调用 COS 与 Embedding，通过 HTTP 桥调用 Python 服务；vector_type 参数做多索引路由，支持后续扩展 question、rag 索引。

| 属性 | 内容 |
|---|---|
| 背景 | COS 向量检索无 Java SDK；Java 不碰 embedding API / COS SDK |
| 演进 | 定稿方案，Python 侧统一接管向量操作 |
| 拍板理由 | Java 经 TopicVectorStore 桥 HTTP 调 Python；vector_type 必填路由（本期 topic，question/rag 占位） |
| 系统影响 | 向量操作全在 Python 侧；多索引加索引零代码改动 |
| 证据 | api/vector.py；design-python Decision 1/5 |

## 二、掌握度口径决策

### D2 掌握度主体 = 题型（非知识点）
> 状态：✅
> 检索摘要：掌握度统计主体从知识点切换为题型，学生掌握对象是解题模式，mastery 信号输出题型 label，知识点由后端派生计算。

| 属性 | 内容 |
|---|---|
| 背景 | 早期方案掌握度按知识点 URI；学生掌握的是解题模式 |
| 演进 | 2026-08 翻转，主体从知识点改为题型 |
| 拍板理由 | 题目天然可聚到题型、可打分可观测、落库不裂行；直接输出知识点名会污染后端题型库 |
| 系统影响 | mastery_signals.topic_label 输出题型；知识点由后端派生 |
| 证据 | models/tutoring.py:KpSnapshot 注释；prompts.py:78-83 |

### D3 掌握度 = 累计平均正确率（替代 max 单调不减）
> 状态：✅
> 检索摘要：掌握度算法替换 max 单调不减，改为累计平均正确率，得到 0-100 连续分值，解决答错无法降分、掌握度虚高问题。

| 属性 | 内容 |
|---|---|
| 背景 | 现状 max 单调不减 = 置信度视角，答错永不降、虚高，算不出正确率 |
| 演进 | 早期 max 单调不减 → 累计平均 |
| 拍板理由 | 正确率视角可解释、可回查、稳定不抖动；"练 10 道对 6 道=60%" |
| 系统影响 | 掌握度从离散四档变连续 0-100，getMastery BREAKING |
| 证据 | 语雀-方案设计2-问题3；[总揽§3.3] |

### D4 掌握度信号映射 + per-题型打折
> 状态：✅
> 检索摘要：定义答疑行为得分权重，答对 1.0、求助答对 0.5、答错 0；前 N 题做分数打折，缓解首题答错带来掌握度假低。

| 属性 | 内容 |
|---|---|
| 背景 | 掌握信号需定义（答对/求助/答错）；首题答错会造成假低 |
| 演进 | 定稿 |
| 拍板理由 | 区分不同答题行为质量；首题打折降低单次作答对掌握度的冲击 |
| 系统影响 | 掌握表只被 AI 答疑信号更新；题型分析页无对错信号 |
| 证据 | 语雀-方案设计2-问题3；design-backend Decision 3 |

### D12 掌握信号唯一来源 = AI 答疑
> 状态：✅
> 检索摘要：掌握度更新信号仅来自 AI 答疑链路；题型分析页面只采集题目，不产生答题对错信号，不会更新掌握度。

| 属性 | 内容 |
|---|---|
| 背景 | 掌握信号需明确来源 |
| 演进 | 定稿 |
| 拍板理由 | 只有答疑有真实答题行为（对错）；题型分析页只记题目无对错 |
| 系统影响 | 掌握表只被答疑链路信号更新 |
| 证据 | 语雀-方案设计2-问题3；[总揽§3.3] |

### D14 两层 PENDING 语义分离
> 状态：✅
> 检索摘要：区分 analyze-question 与 getMastery 的 PENDING 语义，不再复用同一个状态字段；识别失败与掌握度未归属是两类业务状态。

| 属性 | 内容 |
|---|---|
| 背景 | analyze-question 与 getMastery 都用 PENDING 但含义相反 |
| 演进 | 定稿，两套 PENDING 语义完全解耦 |
| 拍板理由 | analyze PENDING=题型没认出（展示候选/空态）；getMastery PENDING=题型已练、知识点待确认；绝不共用一个判断变量 |
| 系统影响 | 前端状态展示分层判断，识别失败不查掌握度 |
| 证据 | 语雀-方案设计2-问题1 坑2 |

## 三、向量&聚集归并算法决策

### D5 编辑距离 ≤1 近字归并移除
> 状态：✅
> 检索摘要：移除编辑距离<=1 字符归并逻辑；形近字、错别字、近似题型的归并全部交给题型名字向量层处理，避免"一元一次/一元二次"误合并。

| 属性 | 内容 |
|---|---|
| 背景 | 早期字符规则按编辑距离 ≤1 归并近字变体 |
| 演进 | 联调发现误并 → 移除字符归并逻辑 |
| 拍板理由 | "一元一次/一元二次"一字之差与错别字"方成/方程"同为距离 1，字符级无法区分 |
| 系统影响 | 近字/错别字归并全交给题型名向量层 |
| 证据 | design-backend Decision 4；[总揽§3.4] |

### D6 聚集依据 = 题型名向量单信号（题目向量不落库）
> 状态：✅
> 检索摘要：动态聚集只使用题型名向量，题目向量本期不作为聚集依据；相似题检索属于非本期目标，question 索引仅做占位预留。

| 属性 | 内容 |
|---|---|
| 背景 | 语雀早期建议题目向量为主 + 题型名向量为辅 |
| 演进 | 收敛为题型名向量单信号 |
| 拍板理由 | 相似题检索本期 Non-Goal；动态聚集只需要题型名向量 |
| 系统影响 | question 索引仅配置占位，后续启用零架构改动 |
| 证据 | models/vector.py:22；design-backend Non-Goals |

### D7 归并阈值 distance ≤ 0.2 保守
> 状态：✅
> 检索摘要：向量归并阈值设定 0.2；宁可拆分也不误合并，防止不同题型样本互相权重污染；相遇、行程这类距离 0.332 直接拆分。

| 属性 | 内容 |
|---|---|
| 背景 | 归并粒度需要旋钮 |
| 演进 | spike 标定后定稿 0.2 保守阈值 |
| 拍板理由 | 同型 ~0.077 / 异型 ≥0.33 有清晰间距；误并的题权重互相污染，宁可拆不误并 |
| 系统影响 | "相遇(0.332)/行程"默认拆分 |
| 证据 | vector_store.py；design-backend Decision 6 |

### D9 聚合触发阈值（CANDIDATE/STABLE 两级）
> 状态：✅
> 检索摘要：题型库两级状态；CANDIDATE 靠学生样本数量触发；STABLE 需要人工审核门禁，STABLE 题型进入解析管线先验池。

| 属性 | 内容 |
|---|---|
| 背景 | 个体观测如何沉淀为精选题型 |
| 演进 | 定稿两级状态机制 |
| 拍板理由 | CANDIDATE = 去重学生 ≥3 且总命中 ≥5（单生偶然不算）；STABLE = 审核通过 + 学生 ≥10 + 近30天仍增长（人工门禁） |
| 系统影响 | 题型库两级状态，STABLE 进入解析先验 |
| 证据 | 语雀-方案设计1-问题1；[总揽§5.2] |
