## 一、空数据类

### 问题1：空候选频繁（流程死穴）
> 状态：⚠️ 待办
> 检索摘要：同一道「鸡兔同笼」5 次调用 4 次返回 candidates=[]，学生没得选流程断在"待确认"，根因是无数据锚时 LLM 自由猜测。

| 属性 | 内容 |
|---|---|
| 现象 | 5 次调用 4 次 candidates=[]，学生没得选，流程断在"待确认" |
| 触发流程 | 题型分析贴题 → analyze-question → 候选生成 |
| 根因 | 无数据锚时 LLM 自由猜测，题型识别→知识点两段传递误差叠加 |
| 修复方案 | 封闭域约束选择（D15）：题目+年级知识点池 → LLM 从池里选 → 恒返回 top-N 绝不空 |
| 状态 | ⚠️ 待办（方案已对齐） |
| 证据 | 语雀-方案设计1-问题6 |

## 二、契约类

### 问题4：两层 PENDING 语义混用
> 状态：✅ 已修复（方案定稿）
> 检索摘要：analyze 识别 PENDING 与 getMastery 掌握度 PENDING 语义相反，前端共用 status 变量导致状态展示全错，需分层判断（D14）。

| 属性 | 内容 |
|---|---|
| 现象 | 前端用一个 status 变量处理两类 PENDING，状态展示全错 |
| 触发流程 | analyze 返回 PENDING（题型没认出）与 getMastery 返回 PENDING（知识点待确认）都被当"待确认" |
| 根因 | 两个接口 PENDING 含义相反，共用一个判断变量必然混 |
| 修复方案 | 分层判断（D14）：识别层 PENDING → 展示候选/空态到此为止；掌握度层 PENDING → 待确认 |
| 状态 | ✅ 已修复（方案定稿）`前端需适配` |
| 证据 | 语雀-方案设计2-问题1 坑2 |

### 问题5：analyze.topicLabel 非 canonical（alias miss）
> 状态：⚠️ 待办
> 检索摘要：analyze 返回原始题型名与掌握表 canonical 名不一致，前端等号匹配 miss 静默显示"未开始"，学生困惑；需后端返回前过聚集 post-process。

| 属性 | 内容 |
|---|---|
| 现象 | 学生鸡兔同笼练很多，掌握度页显示"未开始" |
| 触发流程 | analyze 返回原始名"解一元二次方程" → 前端拿它查 getMastery（key="一元二次方程"）→ 等号 miss |
| 根因 | analyze 返回前未过聚集 post-process，非 canonical；掌握表 key 是 canonical |
| 修复方案 | 后端保证 analyze 返回 topicLabel = canonical（返回前过聚集） |
| 状态 | ⚠️ 待办（P0）`后端需修` |
| 证据 | 语雀-方案设计2-问题1 坑1 |

### 问题6：掌握度信号字段改名脱节
> 状态：✅ 已修复
> 检索摘要：kp_label→topic_label 改名后纠错提示词仍硬编码旧名，Pydantic 校验失败反复纠错掉兜底，掌握度信号静默丢失；纠错提示词需同步。

| 属性 | 内容 |
|---|---|
| 现象 | 掌握度信号静默丢失（mastery_signals 为空） |
| 触发流程 | kp_label→topic_label 改名 → 纠错提示词仍硬编码 kp_label → 模型输出旧名 → Pydantic 校验失败 → 反复纠错 → 掉兜底 |
| 根因 | function calling schema（自动变 topic_label）与纠错提示词字段名脱节 |
| 修复方案 | `_schema_instructions` 纠错提示词同步改 topic_label；测试断言纠错提示词含 topic_label |
| 状态 | ✅ 已修复（Python 侧） |
| 证据 | design-python-ai-tutoring-topic-mastery-signal Decision 2 |
