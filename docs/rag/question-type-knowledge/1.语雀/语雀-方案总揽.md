# 题型知识点模块 技术方案总揽

> 来源：docs/rag/question-type-knowledge/1.语雀/原来的文件/（方案设计1 主文 + 问题1~6、方案设计2 问题1~4，2026-08-24 下载整理）
> 口径：本总揽汇总两期方案——**派生层解析期**（题型↔知识点关联，方案设计1）与**题型掌握度期**（题型动态聚集 + 累计平均，方案设计2）。后者为演进形态。凡属【可选补强建议】章节内容均为建议项，非已落地实现。

## 1. 整体架构与分层模型

系统由三层组成，核心哲学为"**无限的业务事实**与**有限的权威结构**彻底分离"：

```
┌─────────────────────────────────────────────┐
│ 权威图谱（只读，永不写）                        │
│   Neo4j 教育局数据 + kg-sync MySQL 镜像         │
│   节点 key = TextbookKP URI                    │
└─────────────────────▲────────────────────────┘
         只「借」kp_uri 做钩子（不写入）
┌─────────────────────┴────────────────────────┐
│ 派生层（MySQL ai_edu_learning，可写可改）       │
│   ① t_kp_derived_obs        个体观测（无限）    │
│   ② t_kp_question_type      题型库主表（有限）  │
│   ③ t_kp_question_type_kp   题型↔知识点分布     │
│   ④ t_kp_question_type_alias 题型别名表        │
└─────────────────────▲────────────────────────┘
         解析管线命中后落库
┌─────────────────────┴────────────────────────┐
│ 掌握度（题型口径，累计平均正确率）               │
│   前端图谱按 URI 匹配 → 点亮                    │
└──────────────────────────────────────────────┘
```

- **权威图谱**：教育局教材知识点（有限、可枚举、权威），Neo4j + kg-sync 镜像，节点带 URI，关系含 IN_UNIT/CONTAINS（层级）、MATCHES_KG/DEVELOPS/RELATED_TO（语义关联）。**无前置边**（PREREQ 不存在），根因溯源不能靠图遍历。
- **派生层**：自建 MySQL，承载所有可变业务事实。题型空间无限（鸡兔同笼、相遇、浓度…），教材知识点有限——无限的东西永远不写进权威图，只在派生层"借用"权威图的 URI。
- **掌握度**：以 URI 为键、按题型聚合。前端图谱按 `mastery.kpKey == node.uri` 匹配点亮。

**两域解耦**（演进形态）：域 A「题目→题型」（掌握度链路，本期）与域 B「题型→知识点」（独立维护）完全解耦——一个环节故障不影响另一个。

## 2. 核心概念与术语

| 术语 | 定义 |
|---|---|
| 题型（canonical） | 学生题目的解题模式，如「鸡兔同笼」「相遇问题」；canonical 为动态涌现的规范名 |
| 知识点 URI | 教材知识点（TextbookKP）的唯一锚点，如 `...#renjiao-g1s-2-2-xxx`；跨年级，年级只是 URI 的一部分 |
| 个体观测 obs | `t_kp_derived_obs` 一行，记录某学生某题型绑定到某知识点的观测 |
| 题型库 | `t_kp_question_type`，从个体观测共现聚合出的精选题型（带年级分布） |
| 解析管线 | 题型名 → 知识点 URI 的 4 步按序命中流程 |
| 动态涌现 | canonical 由学生第一条题创建，非预置题型池 |
| 掌握度 | 学生某题型的正确率累计（0-100），主体是题型不是知识点 |

## 3. 完整业务流程

### 3.1 解析管线：题目 → 知识点关联（4 步按序命中）

```
AI 答疑 decide 输出题型 label（如"鸡兔同笼"）+ 学生年级
        │
        ▼
① kg 镜像 精确/LIKE 匹配        ──命中──▶ 绑定完成（0 成本，确定性规则）
        │ 未命中
        ▼
② 题型库 年级匹配（查分布桶，按该生年级取占比最高 kp）──命中──▶ 绑定完成（查表，不调 LLM）
        │ 未命中
        ▼
③ LLM 消歧（label + 候选知识点列表 → 选最匹配 + 置信度）──高置信──▶ 绑定完成
        │ 低置信
        ▼
④ PENDING 挂起                 ──▶ 不绑定，进入待确认队列（不落掌握度）
```

- **年级锚是绑定的灵魂**：同一个「鸡兔同笼」，四年级绑「假设法」，七年级绑「二元一次方程组」。年级是强先验但非硬规则——跨年级薄弱被当成 feature（七年级学生卡在四年级的假设法，本身是重要信号）。
- **LLM 消歧是选择题不是填空题**：给它镜像里取的候选知识点列表，从候选里选最匹配，比凭空生成可靠，但未消除选错可能。
- **演进形态（动态涌现）**：无题库零锚点，canonical 由第一条相似题创建，后续题型名向量查最近邻归并。

### 3.2 题型名 → 知识点关联的桥接（两跳）

题型名与知识点名永远可以不一样，关联靠"观测终点 + 翻译"，不靠名字相等：

```
题型名 "鸡兔同笼问题"           ← 题型空间（无限，叫法随 LLM 漂移）
  │ ① LLM 翻译：题型名 → 候选知识点名（教材叫法）
  ▼
知识点名 "鸡兔同笼"             ← 知识点空间（教材叫法，有限）
  │ ② 镜像校验：findByLabel / findByLabelLike → 教材知识点
  ▼
TextbookKP URI  math#textbook-…  ← 锚点（唯一、可图链接、可聚合）
  │ ③ 观测共现：obs(topic_label, kp_uri) 累积 → 题型库 kp 分布
```

- 在线路径：resolve 第③步的 LLM 两段式即此桥。
- 离线路径：聚合把同 topic_label 的 obs 按 kp_uri 聚类出 `t_kp_question_type_kp(question_type_id, kp_uri, ratio, grade_range)`。
- **硬前提**：LLM 只能挂到镜像里已有的 URI——镜像（kg-sync 教材知识点）是封闭宇宙，教材同步不全则翻译校验失败 → PENDING → 人工兜底。补镜像为外部依赖。

### 3.3 掌握度计算链路（题型口径，演进形态）

```
学生做题 → decide 判 eval.correct + 是否被引导（hinted = answer_request_count>0）
  → 掌握度信号（mastered/practicing/struggling 三档）
  → 结算时：题型名 → 聚集 canonical（向量最近邻，防裂行）
  → 生效分值 = baseScore × per-题型打折
       直接答对 1.0 / 引导后答对 0.5 / 答错 0.0
       × 第1题 0.7 / 第2题 0.8 / 第3题起 1.0（打折作用于 score，不作用于结果）
  → 落题目表（事实源，一道题一条）+ 掌握表累计平均（trainCount 已训练数）
```

掌握度公式：`new = old × n/(n+1) + score × 1/(n+1)`，n = train_count。一次作答算一次（不做去重，反映真实练习量）。掌握信号**唯一来源 = AI 答疑**（题型分析页只记题目不出对错）。

### 3.4 动态题型聚集（零锚点，演进形态）

```
第 1 条题：向量桶无近邻 → 建 canonical（锚点诞生）
第 N 条题：题型名向量查最近邻 → 命中归并 / 未命中建新
批量（手动触发）：散名全量聚类 → 补归并 + LLM 归纳规范名 → 重算聚合
```

- 聚集依据 = 字符规则 + 题型名向量最近邻（单信号）；题目向量本期不落库。
- 向量存储：dashscope `text-embedding-v3`（显式 768 维），COS 向量桶 `topic-index`（float32/cosine），`vector_type="topic"` 必填路由。
- 归并阈值（distance，越小越相似）：self≈0、同型 ~0.077、异型 ≥0.33。

| 距离区间 | 动作 |
|---|---|
| ≤ 0.2 | 归并到命中 canonical（写别名表）——只并同型，不并异型 |
| 0.2 ~ 0.3 | 建新，不误并 |
| ≥ 0.3 | 异型建新（宁可拆不误并） |

## 4. 数据模型与表结构

### 4.1 个体观测 `t_kp_derived_obs`（无限增长）

| 字段 | 含义 |
|---|---|
| id | 主键 |
| student_id | 谁 |
| topic_label | 什么题型（如"鸡兔同笼"） |
| kp_uri | 绑到了哪个知识点（如假设法 URI） |
| student_grade | 解析时学生年级（快照） |
| confidence | 置信度 |
| source | 来源（llm/mirror/catalog/curated/student_vote） |
| status | 状态（NEW/RESOLVED/CONFLICTED/READJUDICATED/HUMAN_REVIEW） |
| occurrence_count | 同生同题型同 URI 累计命中数 |
| first_seen_at / updated_at | 时间线 |

约束：`UNIQUE(student_id, topic_label, kp_uri)`——同生同题型同 URI 再次命中只 `occurrence_count+1`，不建新行。

### 4.2 题型库 `t_kp_question_type`（有限精选）

| 字段 | 含义 |
|---|---|
| id | 主键 |
| topic_label | canonical 题型名 |
| kp_uri | 关联知识点（可多，见分布表） |
| hit_students / hit_count | 去重学生数 / 总命中 |
| status | CANDIDATE / STABLE |
| definition | LLM/人工补的定义 |
| promoted_by | 首个触发学生（溯源） |
| created_at / updated_at | 时间线 |

### 4.3 题型↔知识点分布 `t_kp_question_type_kp`

题型↔知识点为 **1:N**，用年级分布桶存：

```
「鸡兔同笼」题型
  ├─ 假设法         (年级 4-6, 38人)  ratio=64%
  └─ 二元一次方程组 (年级 7-8, 21人)  ratio=36%
```

字段：`question_type_id, kp_uri, ratio, grade_range`。解析管线第②步查此表，按学生年级取占比最高的 kp。

### 4.4 题型别名表 `t_kp_question_type_alias`

`alias_label UNIQUE, question_type_id FK`。用于相似题型名（鸡兔同笼/鸡兔同笼问题）合并到同一 canonical。查询改 `findByTopicLabelOrAlias(label)`。

### 4.5 掌握度表（演进形态）

| 表 | 结构 |
|---|---|
| `t_student_topic_mastery`（改造） | id, student_id, topic_key(canonical 唯一), topic_label, mastery(连续 0-100 累计平均), train_count, source(ai/bank), updated_at |
| `t_student_question_record`（新建） | id, student_id, content(题目文本), source(ai/bank), topic_label(原始/归一), score(0.0/0.5/1.0×打折), hint_count, answer_request_count, session_id, created_at |

两表隔离：题目表 = 事实源（可回查），掌握表 = 聚合结果（可重算）。

### 4.6 题目采集模型（演进形态）

`t_student_question_record` 的题目来源：① AI 答疑（产生题目 + 掌握信号）② 题型分析页贴题（产生题目 + 题型识别，无对错信号）③ 未来题库。题目文本落 MySQL，向量 ID 存 COS（`question` 索引占位）。

## 5. 派生聚合逻辑

### 5.1 个体观测 → 题型库两层收敛

```
个体观测（无限，每个学生每道题一条）
   │ 按 topic_label 跨学生「共现聚合」
   ▼
题型库（有限精选，一个题型一条）
   │ 审核
   ▼
STABLE 稳定题型（进入解析先验，服务全体学生）
```

### 5.2 聚合触发阈值

| 阶段 | 触发条件 | 说明 |
|---|---|---|
| CANDIDATE | 同一题型去重学生数 ≥ 3 且总命中 ≥ 5 | 自动，阈值可配置；单生偶然不算题型 |
| STABLE | 审核通过 + 去重学生数 ≥ 10 且近 30 天仍增长 | 人工门禁 |

聚合桶为 `(topic, kp_uri)`，非只按 topic——「鸡兔同笼→假设法」与「鸡兔同笼→二元一次方程组」是两个桶，各算各的命中数。

### 5.3 别名合并（确定性机制，建议项）

聚合建新 CANDIDATE 前：`findByTopicLabel(label)` 逐字命中则更新现有条目；未命中则与现有题型比 kp_uri 集合重叠 ≥ 70% → 不新建，label 记为现有题型别名 + 桶观测折叠进现有分布；否则新建。覆盖场景：「鸡兔同笼问题」与「鸡兔同笼」两个变体桶，单独都达不到 CANDIDATE 阈值，合并后信号集中。

### 5.4 跨学生消歧 + 年级先验（演进形态）

同一题型不同年级本就不同知识点：`最终 kp = f(年级锚, LLM 方法判定, 统计先验)`。冷启动 = 年级锚 + LLM 上下文；成熟后 = 三信号加权。统计先验来自题型库该 topic 按年级的历史分布。年级是强先验非硬规则，LLM 上下文 + 置信度可覆盖年级锚。

### 5.5 自动维护闭环（建议项，自校正）

```
错误信号 ──▶ ① 扫描冲突/低置信/分布异常行
            ② 用「年级锚+先验+LLM」重判
            ③ 变化 → 更新派生行 + 迁移/回退掌握度(打标) + 更新题型库统计(先验漂移)
            ④ 仍歧义 → 人工「待确认」队列
            修正结果回流 = 共享维护 → 下次解析直接用更新后的先验
```

自动错误信号来源（不用人盯）：① decide 诊断冲突（LLM 说卡在假设法、观测记了二元一次方程组）② 掌握度矛盾（该生二元一次方程组已 mastered 却还在鸡兔同笼 struggling 且归到它）③ 年级分布异常（某题型在某年级段出现非预期尖峰）④ 低置信（confidence < 阈值直接重判）。维护原则：保守——只有高置信重判才自动改；LLM 摇摆、无年级锚的进人工。

## 6. 纠错机制（6 层保障）

关联错误可纠正，且设计上专门为"可纠错 + 不脏数据"提供保障：

| # | 保障 | 机制 |
|---|---|---|
| ① | 权威图零写入（最硬防线） | 错误永远只发生在 MySQL 派生层；Neo4j 和镜像只读，物理上不可能污染权威数据 |
| ② | 观测打标重判，非覆盖删除 | 状态机 NEW→RESOLVED→CONFLICTED→READJUDICATED（重判改对）/ HUMAN_REVIEW（转人工）；更新 kp_uri + status，保留 first_seen_at 时间线，改错留痕可回溯 |
| ③ | 掌握度回退打标 MIGRATED + 人工复核，不自动删 | 错判后不自动删（自动删可能丢真实信号），只打标 + 记迁移日志 + 挂人工复核；宁可暂存可疑，不误删真实 |
| ④ | UNIQUE 去重 | 同生同题型同 URI 再次命中只 occurrence_count+1，不建新行；"命中频繁" ≠ "数据频繁改" |
| ⑤ | source 溯源 + 保守原则 | 每条记录有 source（llm/mirror/catalog/curated/student_vote）；自动修正只在高置信时执行，LLM 摇摆、无年级锚一律转人工 |
| ⑥ | 修正回流先验 | 一批观测修正 → 题型库分布更新 → 先验漂移 → 后续所有学生解析跟着修正；一次纠错全局受益 |

**诚实边界**：人工 confirm 本身也可能错——错误确认会通过题型库先验放大给所有学生；但仍在派生层、仍可被冲突检测 + 重判纠正、仍不碰权威图，错误影响被限制在派生层内且可再次纠错，不会造成不可逆损伤。

## 7. 信任模型（分层）

各角色各归其位，信任度不是模糊的"LLM 最可信"，而是一套有客观校准锚的信任分工：

| 角色 | 职责 | 校准机制 |
|---|---|---|
| LLM = 主裁判 / 默认引擎 | 日常解析 + 批量重判（可规模化、可复现、可交叉验证、可升级） | 每次判断被客观信号校准 |
| 学生 = 意图信号源 | 只问"你想学哪个"（主观意图），量最大、最贴近真实 | 只当软信号进统计，一票 |
| 人工 = 边界仲裁 | 只处理"LLM 和学生都摇摆"的极少数边界，找懂学科的人 | 不做日常打标 |

**学生澄清交互**（建议项）：解析走到 LLM 消歧低置信（或镜像/题型库都未命中）→ 不直接 PENDING，给学生澄清选择："这道题你想学哪一块？A. 假设法 B. 二元一次方程组 C. 我不确定/跳过"。选 A/B 落一条 obs（source=student_vote，confidence 固定中等 60，不给 100）；跳过维持"疑似待确认"态。

**防恶意设计**：① 只碰自己这条 obs，改不了全局映射 ② 票数稀释（1 个捣乱 vs 30 个认真选，恶意票被多数一致稀释）③ 不暴露底层（选项是"假设法/方程"概念，不是内部 URI）④ 跳过即弃权（乱点产生不了坏信号）。聚合仍须 ≥3 名学生一致才进 CANDIDATE。

## 8. 已知风险与漏洞

### 8.1 LLM 自证循环（冷启动命门）

- **风险 A：冷启动种子依赖 LLM**。第一次关联错了，后续 obs、题型库聚合、先验、掌握度全建立在这个错种子上。
- **风险 B：LLM 自证循环**。维护闭环的"重判"也是 LLM——"用 LLM 纠正 LLM"，若对某类题型有系统性偏见，重判是自我强化，越纠越偏。

**4 层非 LLM 锚**（已设计，打断自证循环）：

| 锚 | 来源 | 作用 |
|---|---|---|
| ① 镜像精确匹配 | 确定性字符串规则 | 题型名 = 教材知识点名时，0 依赖 LLM |
| ② 题型库统计先验 | 多学生共现客观事实 | 命中走查表按年级取占比，不调 LLM |
| ③ 掌握度矛盾信号 | 数据本身（已 mastered 却 struggling） | 客观矛盾，不是 LLM 猜的 |
| ④ 人工门禁 | 人 | 低置信/摇摆/无年级锚一律转人工 |

**盲区（未显式暴露）**：① 高置信幻觉——LLM 自信地错（给 90 分但选错），绕过"低置信挂起"和"人工门禁"直接高置信结晶 ② 系统性偏见 + 统计自证——种子错且 LLM 稳定错同一方向，题型库先验 = 错误方向，掌握度矛盾信号不触发（大家一致地错），维护重判 = 同一偏见确认错误。

### 8.2 人工兜底的两头死穴

- **开发者打标脱离解题**：开发/教研不一定懂具体学科，判断"鸡兔同笼归假设法还是方程"本身可能错，等于用不专业人工替代不专业 LLM。
- **学生端不能完全信任**：真把系统交给学生，恶意乱点/捣乱会污染数据，"众包"在此信任模型下不成立。

### 8.3 关联质量不稳定（前端联调实测）

1. **空候选频繁（流程死穴）**：实测同一道「鸡兔同笼」5 次调用 4 次返回 candidates=[]，学生没得选 → 流程断在"待确认"。
2. **关联质量不稳定**：同一文本多次调用结果不同（RESOLVED→对数方程求解 / PENDING 空候选 / 候选波动），根因 = 无数据锚时 LLM 自由猜测，题型识别→知识点两段传递误差叠加。
3. **错误关联**：小学「鸡兔同笼」曾被关联到高中「对数方程求解」，根因 = 候选未按学生年级锚定过滤，跨学段混选。
4. **题型库为空**：question-types total=0，聚合任务未沉淀，数据驱动权威命中路径未生效，全靠 LLM 猜。
5. **搜索兜底未落地**：后端 `POST /api/kg/knowledge-points` 未支持 keyword，前端 KpSearchSelector 已就绪但返回空。
6. **冷调用慢**：analyze 冷调用 curl ~5s，浏览器端偶发超 30s（前端 30s 超时截断）。

### 8.4 相似题型名聚合稀释

obs 分桶用 `groupingBy(getTopicLabel)` 逐字聚类，`TopicKeyNormalizer` 故意不剥离「问题」后缀（design Decision 17：同义词聚类留大数据阶段）。「鸡兔同笼问题」与「鸡兔同笼」成两个变体桶，各自达不到 CANDIDATE 阈值，信号被稀释；即使都够阈值也建两个并行 CANDIDATE，前端展示重复题型。

### 8.5 两层 PENDING 语义冲突

`analyze-question` 的 PENDING = "题型没认出来"（低置信/冷启动猜不出）；`getMastery` 的 PENDING = "题型认出来了但知识点待确认"。两层 PENDING 若共用一个判断变量，前端状态展示全错——识别层 PENDING 应展示候选/空态并到此为止，掌握度层 PENDING 才是待确认。

## 9. 可选补强建议

> 本节全部为建议项，非已落地实现。区分：已确定设计见第 3~7 章。

1. **冷启动弱化**：第一次 LLM 消歧（无题型库先验支撑）不直接点亮，先落"弱确定"态，等第二个独立信号（同生后续答对/答错、或第二个学生同题型同结论）才升级为可复用先验。
2. **候选列表接地**：LLM 只做"从镜像候选里选"，候选列表必须保证"正确答案在其中"——冷启动候选列表质量是真正的命门。
3. **掌握度结果做后验裁判**：关联"对"的唯一客观判据是能否解释学生对错——归到假设法但学生用二元一次方程做对了 → 关联可疑。让客观做题结果而非 LLM 当最终裁判。
4. **STABLE 前强制人工抽检**：现有审核门禁为可选项，建议做成 STABLE 的硬前提。
5. **重判交叉**：维护重判用不同 prompt/温度/模型交叉，打断"同一偏见"。
6. **别名表合并（确定性机制）**：聚合时按 kp_uri 集合重叠 ≥ 70% 合并变体桶 + 别名表（见 5.3），把 Decision 17 的 LLM 同义词聚类中确定性的廉价部分提前。
7. **封闭域约束选择**：题型分析从"开放域自由猜测"转"封闭域约束选择"——题目 + 该生年级全部教材知识点 label 池 → LLM 只能从池里挑最相关的 1-3 个 → 恒返回 top-N（置信低也返回池内最相近，绝不空）。年级锚定 `resolveGrade(studentId)` 顺带消灭跨学段错误。
8. **reactive + proactive 补题型**：reactive（已有）学生真实做到 → obs → 聚合 → CANDIDATE → STABLE；proactive（缺口）批量扫题库未标注题 → LLM 题型识别 → 批量写 obs → 聚合 = 把前端贴题链路离线化、批量化，同时补全题库标注。
9. **学生澄清交互**：低置信给"你想学哪个"可选澄清（source=student_vote，confidence 60，≥3 人一致才进候选），见第 7 章信任模型。

## 11. 技术债务

| 项 | 现状 | 影响 |
|---|---|---|
| obs 长期尾膨胀 | 个体观测无限尾，方案用"同生去重 + 聚合后归档"控制，分表/清理本期未做 | 数据量上来后需分表/归档 |
| 消费方未实现 | 题型库的未来消费方（变式题生成、错题本分组、薄弱点溯源）全是 Non-Goal | 本期只沉淀数据，建题型库是"存数据"非"用数据"，LangGraph 阶段 2 才复用 |
| 掌握度"只升不降"策略不变 | 现有单调策略（只升、显式纠正才降）本期保持不动 | 与累计平均正确率的语义过渡需平滑迁移（旧值作初始正确率 + train_count=1） |
| 镜像补全为外部依赖 | 题型翻译出知识点名校验失败 → PENDING → 人工兜底，补镜像不在本 change | 教材同步不全时命中率受限 |
| 搜索 keyword 未支持 | 后端 `/api/kg/knowledge-points` 未支持 keyword | 前端 KpSearchSelector 兜底悬空 |
| 题型名稳定性仅靠 prompt | 纯一句"别换说法"不够，需 few-shot 锚定 + 最常见最短命名 + 后端字面归一化兜底 | 冷启动无约束，同名变异可能裂行 |

## 12. 上线灰度策略

**迁移顺序**：先上线解析 + 落 obs（**不接点亮**）→ 验证解析质量 → 再接点亮 → 维护闭环最后上。

**回滚**：停维护任务 + 关学生图谱路由，很干净。

**灰度对齐演进形态的并行过渡**：旧数据知识点粒度、新数据题型粒度——后端并行过渡（旧表保留），Python 无需处理；掌握表加列非删列，回滚无损。
