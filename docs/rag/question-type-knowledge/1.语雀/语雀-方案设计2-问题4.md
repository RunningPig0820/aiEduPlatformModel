llm 梳理了 五条题型

  但是学生提问的本身 会提问十几二十条 如何把相同的题型聚集起来

  Thought for 22s (ctrl+o to expand)

⏺ 这是关键场景——20 条题、5 条「鸡兔同笼」类、8 种叫法，怎么自动并成一行。先拆清一个前提，再给聚集方案。

  前提：聚集改的是「映射」，不是直接动掌握表

  题目表（事实源）        映射层（别名表）         掌握表（可重算）
  20 条记录               raw → canonical           5 行掌握度
    「鸡兔同笼」   ──▶     鸡兔同笼      →「鸡兔同笼」
    「鸡兔同笼问题」──▶     鸡兔同笼问题 →「鸡兔同笼」    ← 并成 1 行
    「假设法」    ──▶     假设法        →「鸡兔同笼」

  聚集 = 完善「题型名 → canonical」映射（写别名表），然后重算掌握表聚合。题目证据不丢，聚集错了改回映射重
  算即可——这是「两张表隔离」设计的红利。

  三层聚集信号（由强到弱）

  20 条题 · 题型名自由文本

  ① 字符级规则（免费，秒级）：
     「鸡兔同笼」vs「鸡兔同笼问题」   → 编辑距离/后缀剥离 → 同组 ✅
     覆盖：加字/减字/「问题」后缀类变体

  ② 向量相似度（批量召回，聚类）：
     20 条题型名 embedding → 相似度矩阵 → 高相似组
     「假设法」「笼中鸡兔」「鸡兔同笼」向量相近 → 同组候选 ✅
     覆盖：叫法完全不同但语义同类的变体
     ★ 这就是你要的「用向量聚集」——向量负责把近义名召回成组

  ③ 仲裁（向量召回是「候选」，不是「终判」）：
     组内相似度 ≥ 高阈值（如 0.98）→ 直接合并
     组内相似度中等（0.85~0.98）→ LLM 判断「这是不是同一解题模式」+ 给 canonical 名
     组内相似度 < 下限 → 不强并（散题型保护）

  向量聚集怎么落地（批量，定时跑）

  定时任务（夜里跑）：
    扫描题目表全部原始题型名 → 取 embedding
         │
         ▼
    相似度聚类（连通分量 / 层次聚类）：
       「鸡兔同笼」──0.99──「鸡兔同笼问题」
            └──0.93──「假设法」     → 一组
       「相遇问题」──0.82──「行程问题」 → 阈值判：合并 or 不合并（粒度旋钮）
       「工程问题」   0.7 以下无连接     → 独立
         │
         ▼
    每组归并 → canonical 名（LLM 命名 or 组内最频繁名）
         │
         ▼
    写别名表 raw→canonical → 重算掌握表聚合 → 5 条「鸡兔同笼」并成 1 行 64%

  三个必须想清楚的边界

1. canonical 名谁定——向量聚类只能分组，不能命名。组内 8 个成员谁当 canonical？建议：LLM
  给规范名（「鸡兔同笼」），或组内出现频次最高的名兜底。这是向量方案自己给不了、需要 LLM 补的一环。
2. 语义粒度旋钮——「相遇问题 vs 行程问题」相似度 0.82，是同一题型还是两个？阈值就是粒度。但注意：数学应
  用题里「相遇/行程/追及」其实都属「行程问题」大类，granularity 是产品定义，向量不知道你要多细。高阈值 =
  细粒度（只并近字变体），低阈值 = 粗粒度（并语义同型）。这个旋钮必须 spike
  标定，且建议默认偏保守（宁可拆，不误并——误并的题权重会互相污染）。
3. 强并保护——20 条题可能属 5 个真实题型，聚类不能把不相关的硬并。下限（相似度 < 0.8
  不进任何组）保留散题型，它们维持各自 canonical，等后续更多证据再并。

  和你之前「归一」的关系

  在线归一（落库时，单条）：20 条题每落一条，就查一次向量库归到已有 canonical
  批量聚集（定时，全部）：  对历史积累的散名做一遍归并、回写别名表、重算聚合
                          ↑ 是「在线归一的兜底 + 历史数据清洗」

  如果在线归一做得好，20 条题落库时就已收敛，「5
  条鸡兔同笼」在源头就不裂行，批量聚集的压力很小。你问的场景（LLM 梳理出 8
  种叫法）恰恰说明在线归一早期没接或阈值偏保守——所以批量聚集是必要的兜底层，两者都要有。

第一步：每条题目入库时，把 LLM 猜的题型一起存进去

# 把“题型描述”转成向量（用 Embedding 模型）

  type_vector = embedding_model.encode(question_type)  # 比如 [0.12, 0.34, ...]

# 存入向量存储桶

  client.put_vectors(
Bucket='student-questions-bucket-xxxx',
Index='question-type-index',
Vectors=[{
'key': 'q_001',
'data': {“float32”: type_vector.tolist()},
'metadata': {
'question': question,
'type_label': question_type,    # LLM 猜的题型
'student_id': 'S001',
'timestamp': '2026-08-17 22:50'
}
}]
)

  new_type_vector = embedding_model.encode(new_type)

  result = client.query_vectors(

Vector=new_type_vector.tolist(),

IncludeMetadata=True
)

⏺ 你这个场景梳理得非常清楚，而且戳中了我之前方案的一个隐含前提——我确实「预设了有题型」：canonical
  池（知识点池/题型库）。但你的场景是零题库、零锚点，题型要动态长出来。这是对的，方案必须适配。先回应你的
  疑问，再给完整业务实现。

  回应：「你预先知道题型」——是，但可以改成「锚点动态涌现」

  我之前的假设：                       你的场景：
    有 canonical 池（知识点/题型库）      无题库、无预先分类
    → 新题题型名「归进」已有池            → 每条都是 LLM 猜的新名字
                                          → 锚点 = 第一条相似题出现时才建立

  解法：canonical 不是预定义的，是「第一条题长出来的」。聚集依据也不依赖预定义分类，而是用题目本身 + LLM
  猜的题型名做最近邻查询。

  核心洞察：聚集依据用「题目向量」为主

  LLM 猜的题型名是弱标注（会飘：鸡兔同笼/假设法/笼中鸡兔），而题目文本是事实（「笼子里有鸡和兔共 35 个头
  94 只脚」——稳定）。所以：

  强信号：题目文本向量相近 → 大概率同题型（同题/变体，连发几条鸡兔变体）
  中信号：题目不相似但题型名近义 → 可能同题型（汽车轮子版鸡兔同笼）
  双命中 = 高置信直接并；单命中 = 进候选 LLM 仲裁

  你贴的外部方案只用「LLM 猜的题型描述」做向量——可以，但如果 LLM
  猜名本身不一致，聚集质量就受限于名字的一致性。题目向量兜底，名字向量补充，两个都要。

  完整业务实现（逐条题目，锚点从零涌现）

  题目表加「原题链接」字段（你的第 1 点）：

  t_student_question_record:
    id, student_id, content(题目文本)
    source('ai'), session_id ──▶ 跳回 AI 答疑会话（原题链接）
    topic_label     LLM 猜的原始题型名
    canonical_label 聚集后归属（初始=null）
    score, hint_count, answer_request_count, created_at

  时序：

   T1  学生问第1题「鸡兔同笼…」
      ① 落题目表#1（含 session_id 链接）
      ② LLM 猜题型「鸡兔同笼」
      ③ 向量桶入库：题目向量 + 题型名向量（key=题目id）
      ④ 查最近邻 → 桶空，无近邻 → 建 canonical「鸡兔同笼」
         掌握表建行：鸡兔同笼 n=1，score=…         ← 锚点诞生

   T2  学生问第2题「鸡兔…变体」
      ① 落题目表#2
      ② LLM 猜题型「假设法」
      ③ 向量桶查最近邻：
         → 题目向量命中 T1 那题（同题变体，相似度高）
         → 归到 canonical「鸡兔同笼」
      ④ canonical_label=鸡兔同笼，写别名表「假设法→鸡兔同笼」
      ⑤ 掌握表累计平均：n=2                            ← 聚集发生

   T3~T20  陆续问（鸡兔 5 条 + 相遇 + 工程…）
      「鸡兔同笼」「鸡兔同笼问题」「假设法」都并进 canonical「鸡兔同笼」
      其他题型各自成 canonical → 掌握表 5 行

   夜里  定时批量聚集（兜底）：
      扫描 canonical_label 为空 / 低置信的题 → 全量向量聚类 → 补归并
      → LLM 归纳规范题型名 → 重算掌握表聚合

  关键：这就是「动态题型聚类」的全部实现

  每条题目落库时（在线）：
    题目向量查桶 → 命中归并 / 未命中建新   ← 第二题起自动聚集
    题型名向量也入库，参与后续查询          ← 「假设法」也能被召回

  批量（定时）：
    桶里所有向量聚类 → 归纳大类 → 回写
    ← 你贴的方案里的「定期批量聚类」，作为在线归并的兜底

  收口：这跟之前方案的关系

  之前「在线归一 + canonical」  现在「动态涌现」＝ 去掉「预置池」这一步
    ┌─────────────────┐
    │ 池：预置 canonical │   → 池 = 向量桶里的已聚集题目（第一条开始长）
    │ 新名归进池        │   → 新名查最近邻：命中已有题→归并 / 未命中→建新
    └─────────────────┘

  你的场景下不需要预先知道任何题型——第一条题建锚，后续题目靠「题目向量最近邻」自动靠拢，类型是长出来的，
  不是规定出来的。canonical 名由 LLM 定（首见名/最高频名兜底）。
