## 二、阶段详解

### 阶段0 原始诉求（可行性论证）

**描述**：起点是"用 AI 估计出的题目可以匹配系统知识点"。教育局知识图谱（Neo4j + kg-sync 镜像）已就绪，但鸡兔同笼这类题目考点不在图谱里、用户问题跨年级、题目知识点与图谱关联方式未定。核心担忧：自动补充知识点会不会污染权威图谱。

**决策引入**：无（可行性论证阶段）。
**证据**：语雀-方案设计1（可行性结论：可完成，关键在"匹配放在派生层，永远不写权威图"）。

### 阶段1 派生层解析期（方案设计1）

**描述**：确立"无限的业务事实"与"有限的权威结构"分离——题型空间无限，知识点有限，无限永远不写权威图，只在 MySQL 派生层"借用"权威图 URI。设计了解析管线（镜像精确/LIKE → 题型库年级匹配 → LLM 消歧 → PENDING 挂起）、个体观测 t_kp_derived_obs、题型库 t_kp_question_type（带年级分布）、别名表、挂起队列、自动维护闭环、纠错 6 层保障。

**决策引入**：D1（权威图零写入）、D9（聚合阈值两级）、D11（挂起不落掌握度）、D17 前身（纠错打标重判/掌握度 MIGRATED）。
**证据**：语雀-方案设计1 + 问题1（方案梳理/纠错保障）。

### 阶段2 掌握度题型化（方案设计2-问题1~3）

**描述**：核心转变——掌握度主体从知识点翻转为题型。学生掌握的是"解题模式"，题目 → 题型识别 → 当场判该题型状态（已掌握/练习中/待巩固/待确认）。确立掌握信号唯一来源=AI 答疑、题目采集 → 向量化 → 题型自举 → 掌握度聚合的完整数据底盘。掌握度改为累计平均正确率（new=old×n/(n+1)+score×1/(n+1)），信号映射（直接答对/求助后答对/答错 × per-题型打折）。

**决策引入**：D2（掌握度主体=题型）、D3（累计平均）、D4（信号映射+打折）、D12（信号唯一来源）、D14（两层 PENDING 分离）。
**证据**：语雀-方案设计2-问题1（三坑）、问题2（题型自举）、问题3（累计平均/两表）。

### 阶段3 动态涌现（后端决策收敛）

**描述**：确立零锚点动态聚集——无题库、无预置题型池，canonical 由学生第一条题创建，后续题型名向量查最近邻归并。聚集依据收敛为题型名向量单信号（题目向量不落库）。两域解耦（域A题目→题型 / 域B题型→知识点），域B 独立化为查表只读 + ADMIN 手动维护，停用 obs 共现自动关联。去定时（聚合手动触发）。

**决策引入**：D5（编辑距离移除）、D6（动态涌现/单信号）、D7（阈值0.2）、D8（两域解耦+域B独立化）、D10（去定时）。
**证据**：语雀-方案设计2-问题4（20条题8叫法聚集）+ design-backend-question-type-mastery-backend（Decision 4/6/9/10）。

### 阶段4 当前现状（代码真相）

**描述**：落地为 Python 侧纯 stateless 四端点（subject-classify 学科门、question-understand 图片题型识别、decide 掌握度信号、vector put/query 题型名向量）+ Java 编排。掌握度计算/canonical 归并/落库全在 Java。spike 实测归并阈值 distance ≤0.2 保守（同型 ~0.077 / 异型 ≥0.33）。前端联调暴露封闭域约束选择等补强需求（空候选/跨学段错配）。

**决策引入**：D13（Python 桥 + vector_type 多索引）、D7 落地（阈值0.2）、D15/D16 建议项待评估。
**证据**：api/tutoring.py、api/vector.py、core/tutoring/（subject_classify/question_understand/decider/vector_store）；语雀-方案设计1-问题6（前端联调 8 问题）。
