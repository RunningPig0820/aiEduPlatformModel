## 二、数据异常类

| 类别 | 业务场景 | 触发条件 | 当前处理(已落地逻辑) | 兜底降级策略 | 残余风险 |
|---|---|---|---|---|---|
| 数据异常 | 跨年级薄弱 | 学生卡在低年级知识点（七年级卡四年级假设法） | 掌握度按题型名（canonical）记，不绑定当前学年；年级只是展示维度 | 年级是强先验非硬规则，LLM 上下文 + 置信度可覆盖年级锚 | 若按当前年级过滤候选会丢掉最有价值的跨年级信号 |
| 数据异常 | 低置信关联 | LLM 消歧 confidence 低 | 挂起 PENDING（不落掌握度），进待确认队列（D11） | 前端渲染"疑似待确认"虚线态；低置信直接挂起不点亮 | 低置信与"高置信但错"（高置信幻觉）不同——后者绕过低置信挂起 |
| 数据异常 | 空候选（candidates=[]） | 题型识别低置信/冷启动猜不出，无候选给前端 | 空 topic_labels = Java 降级 PENDING | 前端展示候选/空态，到此为止，不查掌握度 | 5 次调用 4 次空候选是流程死穴，需封闭域约束选择（D15 建议项）补强 |
| 数据异常 | alias miss（题型名不匹配） | analyze 返回原始名 vs 掌握表 canonical 名不同 | 未处理（前端联调契约：analyze.topicLabel 需过聚集 post-process 出 canonical） | 后端保证返回 canonical；等号匹配查掌握度 | 匹配不上静默降级显示"未开始"，学生困惑 |
| 数据异常 | 两层 PENDING 混用 | 前端共用一个 status 变量判断 analyze 与 getMastery 的 PENDING | 已定稿：两层分开判（D14）——识别层 PENDING 展示候选，掌握度层 PENDING 才是待确认 | 绝不共用一个判断变量 | 若前端不遵守契约，状态展示全错 |
| 数据异常 | 未命中题型（学生没做过） | 该题型在掌握表查不到 | 已定稿：显示"未开始"灰态（not 待巩固） | 明确"这个题型你还没做过题" | 与 alias miss（false miss）需区分，前端不能吞掉后端 bug |

| 类别 | 业务场景 | 触发条件 | 当前处理(已落地逻辑) | 兜底降级策略 | 残余风险 |
|---|---|---|---|---|---|
| 基础设施 | 向量桶挂/未配置 | COS_VECTORS_* 未配齐或 COS 不可用 | 懒加载抛 RuntimeError → 端点 500 → Java 桥降级 | Java 回退字符规则 + 原样落库，主链路（题目落库/掌握表/接口）不依赖向量 | 归一退化为字符规则，语义同型变体裂行 |
| 基础设施 | embedding 失败 | dashscope 不可用/超时 | 向量端点错误冒泡（HTTP 500）→ Java 桥降级（与 subject-classify 相反：不吞异常） | 同上，Java 桥降级 | embedding 是增强层，失败不影响主链路 |
| 基础设施 | COS 写入延迟 | put_vectors 后立即 query | 已处理：容忍 ~10s 异步生效 | 建锚不立查 + 留重试 | 联调预期要含延迟 |
