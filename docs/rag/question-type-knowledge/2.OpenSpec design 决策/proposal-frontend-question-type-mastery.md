# 题型掌握（题目采集 → 向量聚类 → 掌握度聚合）

## Why

现有掌握度链路（`kp-matching-lightup` 翻转 + `kp-question-analysis` 贴题识别）已经确立了**「掌握度 = 题型」**的核心业务关系，但掌握度的**数据底盘是零散观测**——只有 AI 答疑的 `decide` 顺带输出，题型掌握度算不清、来源不明、没有可回溯的题目证据。

需要把掌握度升级为**以题目为单位的完整采集链路**：所有入口的题目被记录 → 向量化入腾讯 COS → 定时聚类统一题型 → 每道题累计出掌握程度。这样「我掌握了哪些题型」才有数据支撑，业务含义通透：**掌握的是题型（解题模式），不是知识点（教材概念）**。

## What Changes

- **题目采集（全入口）**：AI 答疑、题型分析页等入口的题目**全部落库**，成为掌握度的唯一证据源。题目分「用户自己的题目」与「题库题目」——当前题库无题，只有用户自己的。
- **向量存储**：题目存入腾讯向量 COS，作为定时聚类统一题型名的依据（坑1：alias 题型名用向量匹配收敛，有误差可容忍，因为掌握度本身是百分比）。
- **题型掌握表**：新增 `{ 题型 | 来源(ai/题库) | 掌握程度% | 训练题目数量 }`。掌握程度按**每道题累计平均**计算：`new = old × (n/n+1) + score × (1/n+1)`；前几次作答打折（score × 70/80/100 递进）；提示后答对按 50% 计。
- **掌握度展示（前端）**：掌握度页题型明细改为**列表列展示**——题型 / 来源 / 掌握程度 / 跳转该题型的题目列表。
- **题型↔知识点关联本期不做**（**BREAKING 相对旧预期**）：知识点不再从题型派生覆盖度。知识点总览页**保留展示但不标熟练度**（仅知识地图，供演示入口）。
- **承接**：题型分析页（贴题→识别题型）保留，降级为本采集链路的入口之一；`getMastery` 契约变更（见 Impact）。

## Capabilities

### New Capabilities

- `question-mastery-pipeline`: 题目全量采集 → 向量存储 → 定时聚类统一题型 → 题型掌握表（累计平均聚合），掌握度数据底盘。
- `question-type-mastery-view`: 掌握度页列表化展示——题型/来源/掌握程度%/训练数 + 跳转该题型题目列表。

### Modified Capabilities

- `student-mastery-lightup`: 掌握度主体仍是题型，但数据源从「零散观测聚合」升级为「题目采集 + 累计平均」；`getMastery` 返回结构变更（加 来源/训练数/连续百分比）。
- `kp-question-analysis`: 题型分析页保留为入口，但其「掌握度标注预留」的锚点从 `kp-coverage`（知识点）改为 `getMastery`（题型）；知识点总览不再标覆盖度。

## Impact

- **后端（主）**：
  - 题目表 + 腾讯向量 COS 存储（题目内容 + embedding）；
  - 定时任务：向量聚类把学生各入口的题型 alias 统一成一个题型（per 学生）；
  - 题型掌握表（累计平均聚合，含打折 / 提示 50%）；
  - `getMastery` 契约变更：返回 `{ 题型, 来源, 掌握程度%, 训练数 }`（连续百分比）或配套字段，**需前端联调**；
  - `decide` 信号增强：确认「提示后答对」信号是否存在（无则前端从"请求答案后答对"推断）。
- **前端**：掌握度页加「来源/训练数」列 + 「跳转题目」链接（按题型查题目列表）；知识点总览页去掉覆盖度着色；题型分析页不动。
- **数据契约**：`getMastery` 增加连续百分比字段；新增「按题型查题目列表」接口。
- **风险**：知识点总览页数据源断联（本期明确：只展示知识地图、不标熟练度）。
