# 分析-01 题型分析完整流程（代码真相）

> 来源：ai-edu-ai-service 深读（2026-08-26）｜权威度 0.8 ｜ 模块=question-analysis
> 口径：Python 侧纯 stateless 四端点，由 Java 编排。掌握度/canonical/落库在 Java。

## 调用链（一道题 → 题型 → 掌握度信号）

```
① 学科门（decide 之前）  Java → POST /api/tutoring/subject-classify
                          非 math → 跳过不建/不续会话
② 题目理解（图片题）     Java 传 COS 签名 URL → POST /api/tutoring/question-understand
                          看图 → topic_labels + question_kps
                          （文本题 → Java 自研 KpQuestionAnalyzer，Python 无此端点）
③ 掌握度信号（答疑过程） Java 每轮 → POST /api/tutoring/decide
                          → ActionMeta（mastery_signals 题型三档 + question_kps 顺带知识点）
④ 题型名归一（canonical） Java → POST /api/tutoring/vector/put|query
                          → Python 只做 embedding + COS 向量桶存取
```

## 关键实现细节

- **Python 无状态、不落库**：会话历史（含题目）在 Java Redis，掌握度快照在 Java 掌握表；Python 只接收 `mastery_snapshot` 作上下文提示。（`models/tutoring.py:138,141`）
- **换题短路径**：`is_new_question=true`（Java 检测新图/新题）→ Python 直接短路 `type=switch`，不调 LLM。（`core/tutoring/decider.py:68-74,105-113`）
- **端点清单**：subject-classify（`api/tutoring.py:136-149`）、question-understand（`api/tutoring.py:121-133`）、decide（`api/tutoring.py:41-81`）、vector put/query（`api/vector.py:30-81`）。

## 对账要点

- Python 侧**没有** analyze-question / mastery 端点——Java 实现，Python 只留 question-understand 图片入口。
- "题目 → 题型 → 掌握度"的数据流完整性在 Java（两表 + ScoreMapper），Python 是信号源 + 向量原语。
