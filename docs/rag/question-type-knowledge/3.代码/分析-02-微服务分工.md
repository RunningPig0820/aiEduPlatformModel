# 分析-02 微服务分工（代码真相）

> 来源：ai-edu-ai-service 深读（2026-08-26）｜权威度 0.8 ｜ 模块=question-analysis

## 分工边界

| 能力 | Python (ai-edu-ai-service) | Java (aiEduPlatform) |
|---|---|---|
| 学科门 | ✅ subject-classify 端点 | 编排（decide 前调） |
| 图片题型识别 | ✅ question-understand 端点 | 文本题 KpQuestionAnalyzer 自研 |
| 掌握度信号输出 | ✅ decide 产 mastery_signals + question_kps | 消费信号 |
| 向量存查 | ✅ vector put/query（embedding + COS） | 经 TopicVectorStore 桥调用，不碰 SDK |
| canonical 决策 | ❌（只提供向量原语） | ✅ TopicLabelAggregationService.aggregate |
| 掌握度计算/落库 | ❌ | ✅ ScoreMapper + 两表 |
| analyze-question / mastery 端点 | ❌ | ✅ |
| 题型↔知识点映射 | ❌（显式禁止） | ✅ ADMIN 维护接口 |

## 关键设计

- **Python 不感知 Java，Java 不感知 COS 基础设施**：Java 只知 `vector_type` 逻辑名，Python 内部 `COS_VECTORS_INDEXES` 路由到物理索引。（`settings.py:99-105`）
- **embedding 复用 dashscope**：text-embedding-v3，显式 `dimensions=768`，不进 LLMFactory，独立封装 `vector_store.py`。（`core/tutoring/vector_store.py:26-28,87-103`）
- **鉴权统一**：四端点都走 `x-internal-token` + snake_case 契约。
- **Python 显式禁止做题型↔知识点映射**：KpSnapshot 注释"桥已移到后端 ADMIN 维护接口"。（`models/tutoring.py:73-76`）

## 对账要点

- 向量是 Python 桥（COS 无 Java SDK）；canonical/掌握度/落库是 Java 职责——分工清晰，Python 纯 stateless。
- "Python 纯智能、Java 平台决策"的架构原则在本模块体现：Python 管 LLM/embedding，Java 管数据/编排。
