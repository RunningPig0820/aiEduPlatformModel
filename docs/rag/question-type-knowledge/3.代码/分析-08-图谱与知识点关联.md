# 分析-08 图谱与知识点关联（代码真相）

> 来源：ai-edu-ai-service 深读（2026-08-26）｜权威度 0.8 ｜ 模块=question-analysis

## 职责

Python 侧**无任何题型↔知识点映射逻辑**，且被显式禁止。图谱点亮是独立变更（kp-matching-lightup）。

## 代码事实

- **显式禁止映射**：`models/tutoring.py:73-76` KpSnapshot 注释"Python 不要拿 kp_key 反查图谱/做题型↔知识点映射（桥已移到后端 ADMIN 维护接口）"。
- **decide 顺带输出题目知识点**：`ActionMeta.question_kps: Optional[List[str]]`，模型读题顺手列，"可选、不要求每次必填"。（`models/tutoring.py:119`、`prompts.py:32-33`）
- **question-understand 顺带知识点**：从图片识别，`question_kps` 可空。（`question_understand.py:60-64`、`models/tutoring.py:176`）
- **相关表全在 Java learning 库**：`t_kp_question_type` / `t_kp_question_type_kp` / `t_kp_question_type_alias` / `t_kp_derived_obs`——Python 不触碰。

## 对账要点（Java 侧，域 B 独立化）

- **查表只读 + ADMIN 维护**：入口识别题型 → 查题型库（`findByTopicLabelOrAlias` → 分布桶）→ 命中返回权威分布 / 未命中返回"仅题型 + canonical + 空知识点"——不挂起、不写 obs、不顺带 LLM kps。（design Decision 10）
- **停用自动涌现链路**：obs 共现 → LLM 归纳 ratio 自动关联、`upsertPendingIfAbsent` 挂起、学生 vote 澄清、聚合批处理、`KpCoverageAppService` 派生（前端已不消费）。
- **PENDING 语义更新**：getMastery `status=PENDING` 不再来自 obs，改为"题目记录有但 canonical 未归属"。
- **图谱点亮**：`kp-matching-lightup` 独立变更承担，答疑/题型链路不直接写 Neo4j。

## 关键设计

- 两域解耦：域 A「题目→题型」（本期，掌握度）与域 B「题型→知识点」（独立维护）完全解耦，一个环节故障不影响另一个。
- 跨年级：掌握度按题型名（canonical）记，不绑定学年；图谱 URI 全局（年级只是 URI 一部分）。
