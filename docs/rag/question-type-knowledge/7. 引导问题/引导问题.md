# 题型知识点 — 面试问题整理

> 模块定位：题型动态聚集（向量归一 canonical）+ 掌握度分析（主体是题型，不是知识点），多维能力画像。
> 所属大纲段：1 项目介绍 / 2 项目如何操作 / 4 数据关联 / 5 难点

## 1. 项目介绍

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 题型知识点模块在项目里做什么？ | 把学生散乱的答题记录聚成 canonical 题型，算掌握度、出能力画像 | "掌握度给谁看？" → 学生雷达图 / 教师视图 |
| 为什么掌握度主体是题型，不是知识点？ | 学生做的是题，题对应题型可测；知识点是间接推断 | "那知识点掌握度呢？" → 由题型聚合推导 |
| 题型分析和 AI 答疑是什么关系？ | 两个入口一个底盘：答疑产信号，分析页记题目 | "掌握信号从哪来？" → 只有答疑有对错 |
| 没有题库，题型库是怎么来的？ | 动态涌现：第一条题建锚，后续向量近邻自动靠拢 | "冷启动怎么办？" → 首题建锚 + 字符规则兜底 |
| 这个模块和知识图谱有什么区别？ | 图谱是知识结构，这是学生个人能力画像 | "怎么联动？" → 派生层 + kp-matching-lightup 点亮 |
| 掌握度怎么算出来的，可靠吗？ | 事件驱动：题→题型→掌握度累计平均，可追溯 | "第一题答错怎么办？" → per-题型打折防假低 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 这和知识图谱什么区别？ | 知识图谱是知识结构，这是学生个人能力画像，靠题型可测 |
| 这模块是不是只是统计报表？ | 强调题型归一用向量（真实检索能力）+ 联动答疑/图谱 |

## 2. 项目如何操作

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 描述一次完整的题型分析流程？ | 学科门 → 题型识别 → 向量归并 canonical → 掌握表累计平均 | "识别错了呢？" → 空结果降级 PENDING + 澄清卡 |
| 学科门 subject-classify 是干什么的？ | decide 之前判学科，K12 十值闭集，宁放过不误拦 | "判错了会怎样？" → 拿不准放行 math |
| 题目是怎么识别成题型的？ | 图片题视觉模型 + topic_hint 词表收敛 | "文本题呢？" → Java KpQuestionAnalyzer |
| 掌握度是怎么更新的？ | 一道题→score(1.0/0.5/0.0×打折)→累计平均 | "一次作答算几次？" → 一次算一次，不做去重 |
| 题型名是怎么归一到 canonical 的？ | 字符规则先拦 + 题型名向量最近邻(阈值0.2) | "阈值怎么定？" → 同型0.08/异型0.33间距标定 |
| 掌握度页展示什么？ | 题型行+来源+掌握%+训练数+跳转原题 | "跳转去哪？" → session_id 回答疑会话 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 向量桶挂了怎么办？ | 降级字符规则 + 原样落库，主链路不依赖向量 |
| 图片识别不出来？ | 空 topic_labels → Java PENDING，不编造题型名 |

## 4. 数据如何关联

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 题目、题型、知识点三者怎么关联？ | 题目→题型(本期)，题型→知识点(域B独立维护) | "为什么两域解耦？" → 一个故障不影响另一个 |
| 题型↔知识点映射怎么做？ | 查表只读 + ADMIN 维护，不做自动关联 | "为什么不做自动？" → 业务不成熟防污染权威图谱 |
| 掌握度和答疑、知识图谱怎么联动？ | 答疑产信号→掌握表→回流decide；图谱点亮独立变更 | "答疑直接写图谱吗？" → 不，kp-matching-lightup 承担 |
| 动态聚集用什么向量？ | dashscope text-embedding-v3 768维 cosine，topic索引 | "为什么不用题目向量？" → 相似题检索本期不做 |
| 跨年级薄弱怎么处理？ | 掌握度按题型名记，不绑定学年 | "年级只是展示维度？" → URI全局，跨年级天生可展示 |
| 两层 PENDING 是什么？ | analyze的PENDING=题型没认出；getMastery的=知识点待确认 | "混用会怎样？" → 状态展示全错，必须分层判 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 题型和知识点边界这么模糊？ | 题型可测的解题模式，知识点课程锚点；canonical 经别名表收敛 |
| 掌握信号源单一？ | 只有答疑有真实答题行为，分析页无对错是设计 |

## 5. 项目开发中有什么难点

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 题型归一为什么用向量不用字符规则？ | 语义变体规则匹配不了，向量同型0.08/异型0.33清晰 | "向量方案怎么验证？" → 聚集后人工抽查 |
| 动态聚集没有题库锚点，怎么冷启动？ | 首题建锚，后续向量近邻靠拢，题型长出来 | "名字漂移怎么办？" → 字符规则+向量+阈值旋钮 |
| 向量写入有延迟，怎么处理？ | 首题建锚不立查 + 留重试容忍~10s异步 | "为什么有延迟？" → COS索引异步构建 |
| 两层 PENDING 混用会出什么 bug？ | 前端共用一个变量，状态展示全错 | "怎么解决？" → 分层判断，识别失败不查掌握度 |
| 掌握度第一题答错怎么办？ | per-题型前几题打折(0.7/0.8/1.0)防假低 | "打折作用于什么？" → score 不作用于结果 |
| alias 匹配 miss 怎么解决？ | analyze 返回前过聚集 post-process 出 canonical | "为什么静默？" → 等号 miss 不报错，显示未开始 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 学生乱答/只抄答案怎么办？ | 数据源来自答疑链路（防作弊前置），异常行为已拦截 |
| 数据量小掌握度不准？ | 事件累计 + 能力维度多信号，量小也先有趋势 |

## ⚠️ 最危险的可能问题（防御）

| 可能问题 | 防御要点 |
|---------|---------|
| 掌握度数值是怎么算出来的，可靠吗？ | 讲清事件→题型→能力维度→更新的完整链路，非拍脑袋 |
| 归一结果错了怎么办？ | 向量聚集 + 人工抽查 + 字符规则兜底双保险 |
| 这模块是不是只是统计报表？ | 强调题型归一用向量（真实检索能力）+ 联动答疑/图谱 |
| 为什么题型↔知识点不做自动关联？ | 业务不成熟 + 防污染权威图谱，查表只读 + ADMIN 维护 |
