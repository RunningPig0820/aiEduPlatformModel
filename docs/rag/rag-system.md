# RAG问答系统（本项目）— 面试问题整理

> 模块定位：项目介绍 RAG 问答系统自身。不是纯 RAG，产品 = 讲清每个页面，RAG = 证明能力的引擎。
> 所属大纲段：全部 5 段（问题最多，面试主场）
> 配套设计：`docs/project-intro-rag-notes-2026-08-21.md` + `openspec/changes/project-intro-rag`

## 1. 项目介绍

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 为什么做这个 RAG 系统？ | 面试/汇报用：RAG 证明能力，同时把项目页面讲清楚（一鱼两吃） | "为什么不用现成 RAG 框架？" → 链路掌控 |
| 你的 RAG 和普通 RAG 有什么不同？ | 双池 / 范围门=检索置信度 / 预写答案兜底 / token 成本展示 | "双池怎么判断走哪个？" → doc_type 区分 |
| 怎么证明它有效？ | 评测 agent：hit@3 + 答案质量分 + 版本对比 | "指标怎么算？" → 纯函数可验证 |

## 2. 项目如何操作

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 面试官怎么操作这个系统？ | 点页面 → 概览卡 → 引导问题/自由输入 → 答案+召回文档+mermaid+token | "自由输入也能答？" → 源文档池纯 RAG |
| 页面锚定怎么工作？ | 前端传 page → 锁页检索；不传/跨页 → 全局模式 | "怎么知道我传哪页？" → 前端主动带 page |
| 双池怎么配合？ | 引导走索引层(可控)，自由走源文档池(纯RAG) | "索引层答不了怎么办？" → 降级到源文档池 |
| 两道门怎么设计？ | 权限门（前置校验）+ 范围门（检索置信度→边界回答） | "超范围会怎样？" → 预写边界话术不硬编 |
| 打分和阈值？ | 相似度×问题类型×锚定；索引层 0.75 / 源文档池 0.5 | "为什么两个阈值？" → 索引层要精，源文档池要宽 |
| 生成怎么带引用？ | 强制引用、无引用不输出、跨页按页标注 | "跨页怎么标？" → 知识图谱页§x … AI答疑页§y |
| 追问限制？ | 5 轮/会话，防上下文膨胀 | "到了怎么办？" → 提示开新会话 |

**可能（防御）**

| 可能问题 | 防御要点 |
|---------|---------|
| 挂了怎么办？ | 降级矩阵 + 预写答案兜底（最坏也能答） |
| 引导问题=预定答案？ | 变体文案强制检索 + 自由问题纯 RAG + 现场随意问 |

## 3. 数据入库

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 语料从哪来？ | 语雀 + 代码注释 + OpenSpec | "语雀空模板怎么办？" → 自己完善成 8 节 |
| 完善文档 8 节结构？ | 定位/功能/为什么/数据流(mermaid)/技术/坑/规模/权限 | "为什么是这 8 节？" → 对应面试问法 |
| 切片 + metadata？ | 按节切，带 page/doc_type/section/source_doc | "为什么带 source_doc？" → 召回原文面板 |
| embedding 用什么？ | dashscope 768 维；本地 bge 备选 | "维度怎么定？" → 索引维度固定不可改 |
| 向量桶怎么建？ | COS rag-index；10s 异步 → demo 预建 | "写后即查会怎样？" → 异步生效可能 miss |
| 索引层 QA 条目怎么来？ | 从完善文档提炼，每模块 5~8 条 | "和引导问题啥关系？" → 同一份，视角不同 |
| 评测集怎么设计？ | 每模块 5 条，覆盖 5 类问题（概览/为什么/数据流/难点/指标） | "预期答案哪来？" → 完善文档回查 |

## 4. 数据如何关联

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 双池怎么关联？ | 索引层 QA ↔ 源文档池，doc_type 区分，共用一个 COS 索引 | "引用怎么回源？" → QA 条目带 references |
| 跨模块数据流？ | 答疑 → 掌握度 → 图谱点亮 → 薄弱点分析（闭环） | "RAG 怎么讲这个？" → 跨页检索多页引用 |

## 5. 项目开发中有什么难点

| 引导（扬长） | 亮点 | 预期追问 |
|-------------|------|---------|
| 流式 usage 只在结尾怎么拿？ | include_usage + 解析结尾 usage chunk，流结束更新 | "拿不到呢？" → tokenizer 估算标注"估算" |
| COS 10s 异步生效？ | demo 预建索引 / 写后校验 | "生产怎么处理？" → 延迟确认 |
| embedding 维度不可改？ | 换模型 = 全量重建 | "怎么发现过期？" → checksum 校验 |
| 语料空模板/多版本矛盾？ | 完善文档向代码对齐，冲突以代码为准 | "未发布草稿？" → 靠代码/其他文档补 |
| 降级矩阵怎么设计？ | 多路召回本身就是降级备份；生成失败 → 预写答案兜底 | "全挂了？" → 边界话术 |
| 判分模型偏差？ | 固定判分标准 + 人工复核 | "怎么发现偏差？" → 抽样复核 |

## ⚠️ 最危险的可能问题（防御）

| 可能问题 | 防御要点 |
|---------|---------|
| 这是预写答案吧？检索是假的？ | 变体文案强制走检索 + 自由问题纯 RAG + 现场随意问一个没准备的 |
| 评测集是你自己写的，不是自证？ | expected 引用回查完善文档 + hit@k 客观命中率 |
| 语料才几十条，能说明什么？ | 链路真实完整；可解释检索才是重点 |
| 为什么不接 Neo4j 做 GraphRAG？ | 语料是文档不是图谱；图谱能力在知识图谱页讲 |
| 这套东西值多少钱？ | 成本叙事：token 展示 + 本地 embedding + 追问限制，成本可控 |
