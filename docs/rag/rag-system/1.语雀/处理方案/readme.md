# rag-system 语雀处理方案

> 模块：RAG问答系统（项目介绍 RAG，双池检索系统）｜ 语料根目录：`docs/rag/rag-system/`
> 方法同源：question-analysis / knowledge-graph，本流程为 rag-system 专属口径。

## 处理流程

1. **转移原文件**：将语雀原始文档转移到 `原来的文件/` 下（已归档 **11 篇**：语雀-问题1~9、11、12，记录 RAG 系统的方案与问题讨论，原始语雀链接保留在每篇头部）
2. **语料盘点**：11 篇原始问答 → 汇总提炼 **6 份 canonical 文档**（权威度 0.8，doc_type=canonical）：
   - 方案总揽（叙述性综合主文档）/ 决策记录（D#）/ 方案选型对比（选型#）/ 演进时间线（阶段#）/ 边界场景清单（场景#）/ 术语对照表
3. **通过提示词处理语雀文档数据**：使用 `提示词/` 下 **9 份独立提示词**（一次产出一份 canonical，独立生成避免格式漂移），配合增量更新与文档校验器做迭代维护
4. **保留语雀文档给其他环节使用**：
   - 切片进**双池**：索引层 QA 池（doc_type=qa，引导问题/答案要点）+ 源文档池（doc_type=source，完善文档 chunk），module 标签 `rag-system`
   - 供 `4.完善文档/`（权威 1.0）与 `3.代码/`（代码真相）交叉引用证据
   - 供 `7. 引导问题/问题列表.md` 与 `GUIDE_POOL["rag-system"]`（intro/operation/data_relation/difficulty/rag 5 组）同步

## 双池方案事实（本模块口径，提示词统一引用）

- **双池检索** = 索引层预写 QA 池（引导问题 + 答案要点 + 引用）+ 源文档池（全项目各模块完善文档，纯 RAG 检索证据）
- **页面锚定** = 页面模式（前端传 page，锁页检索）+ 全局模式（跨页检索）
- **两道门** = 权限门（前置角色校验，非学生 403）+ 范围门（检索置信度阈值 0.75/0.5，低于即边界拒答）
- **token 真算** = usage 真实采集（流式结尾更新，`stream_options.include_usage`，丢 usage 是已踩坑）
- **评测 agent** = hit@k + answer_quality（编造封顶 3 分，HIT_K=5）
- **引导问题** = 索引层入口（UI 展示"你可能想问"，命中预置 QA 条目取答案）
- **语料** = 全项目各模块完善文档（策展非全量倾倒，版本一致性优先）

完善文档 1.0 / 代码 0.8 / 坑档案 0.8 / 语雀 canonical 0.8 / OpenSpec 0.7。
