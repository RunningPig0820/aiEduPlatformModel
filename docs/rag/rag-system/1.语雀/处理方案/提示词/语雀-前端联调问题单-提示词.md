## 硬性规则（强制全部遵守）

### 术语强制统一
固定术语：双池检索 / 页面锚定（页面模式/全局模式）/ 两道门（权限门/范围门，阈值0.75/0.5）/ token真算 / 白盒化 / SSE事件透传 / 引导问题 / 评测agent / is_quoted / 禁区拒答。禁止自创别名。

### 状态判定标准（联调问题单口径）
- ✅【已修复】：代码/契约已改，问题闭环。
- ⚠️【待办】：已定位根因但未修（含方案已对齐待实现）。
- ❓【待决策】：根因未明或方案未定。

### 证据标注规范
1. 语雀来源证据：`证据：语雀-原文件-问题X.md`；引用总揽：`[总揽§X.X]`
2. 代码来源证据：优先写 `文件:函数名/类名`；无法获取真实行号时禁止编造虚假行号，写`文件:逻辑片段`。
3. 某类来源不可读，证据字段写`来源不可读，无有效证据`，禁止编造逻辑。
4. **每一个独立问题小节，必须附带来源证据，禁止无证据条目。**

### 格式与内容约束
1. 移除全部对话、问答、来回讨论口吻；输出正式技术综述。
2. 重要流程使用有序列表或者文本流程图；规则、阈值全部使用表格承载。
3. 同主题信息归并，一处讲透；总揽已详述内容直接引用章节标记。
4. RAG切片友好：段落简短，避免大段无分割文本。
5. **禁止业务臆造，所有内容必须来自来源材料。**
6. 引用本库内部文档标记：决策记录条目标记`D#序号`。

### RAG 切片块级结构（本文档必须严格执行）
1. 文档开头增加【文档说明】：说明阅读提示——正文分块问题用于 RAG 检索，附录总表仅供人工查阅。
2. 按问题类别分组，**每一个问题一条 `### 问题N：标题` 独立 H3 小节**，一个 chunk = 一个问题。
3. 每个 H3 小节顶部固定两行（缺一不可）：
   ```
   > 状态：✅/⚠️/❓
   > 检索摘要：xxx（1-2 句话提炼该问题核心语义，作向量召回锚点）
   ```
4. 单问题内部使用**竖向窄属性小表**，固定字段：现象、触发流程、根因、修复方案、状态、证据。
5. 契约错位问题标注：`前端待适配` / `后端已修复`。
6. 全部问题输出完毕，文档最末尾追加【附录：原始问题总表】，标注仅供人工查阅、不参与 RAG 切片。

### 输出前强制自检
1. 是否区分 ✅/⚠️/❓ 状态。
2. 所有代码相关条目是否附带证据，没有编造行号。
3. 是否删除问答对话口吻。
4. 是否出现术语别名。
5. 是否有重复内容，同类问题已合并。
6. 文档顶部元信息完整，summary、权威度、模块、COS路径、类别字段齐全。
7. 宽表未作为主体；每个问题 H3 带 状态+检索摘要；附录已标注不参与 RAG 检索。

### 失败降级
某类来源完全不可读，直接跳过该来源信息，如实在证据字段标记，不编造内容。
