## 硬性规则（强制全部遵守）

### 术语强制统一
固定术语：双池检索（索引层QA池/源文档池）/ 页面锚定（页面模式/全局模式）/ 两道门（权限门/范围门，阈值0.75/0.5）/ token真算 / 白盒化 / 引导问题（索引层入口）/ 评测agent（hit@k/answer_quality）/ 多路召回（向量+BM25）/ RRF融合 / is_quoted（LCS硬匹配）。禁止自创别名。

### 状态判定标准
- ✅【已落地设计】：代码可观测到实现逻辑；语雀文档描述+代码同时存在。
- ⚠️【建议项(未实现)】：仅语雀方案文档描述，代码无对应实现。
- ❓【待决策 Open Question】：语雀和代码均无明确结论。

### 证据标注规范
1. 语雀来源证据：`证据：语雀-原文件-问题X.md`；引用总揽内部：`[总揽§X.X]`；引用决策：`D#X`。
2. 代码来源证据：优先写 `文件:函数名/类名`；无真实行号禁止编造，写`文件:逻辑片段`。
3. 某类来源不可读，证据字段写`来源不可读，无有效证据`，禁止编造逻辑。
4. 关键事实必须带证据；叙述性综合允许归并多来源，但不得臆造。

### 格式与内容约束
1. 移除全部对话、问答、来回讨论口吻；输出正式技术综述，禁止提问者/回答者视角。
2. 重要流程使用有序列表或者文本流程图；规则、阈值、表结构全部使用表格承载。
3. 同主题信息归并，一处讲透；**5 个 canonical 文档已详述的内容不再大表复述**，用引用标记 `D#X` / `[详见 语雀-决策记录.md]` 关联。
4. RAG切片友好：段落简短，避免大段无分割文本；单表格不超过 20 行。
5. **禁止业务臆造，所有内容必须来自来源材料。**
6. **方案总揽是叙述性综合文档**，不适用"每条 ### + 检索摘要"的条目型块结构（那是 canonical 条目文档的格式）；总揽按章节叙述 + 关键表。

### 输出前强制自检
1. 是否区分 ✅/⚠️/❓ 状态，没有把建议项标记为已落地。
2. 代码相关条目是否带证据，没有编造行号。
3. 是否删除问答对话口吻。
4. 是否出现术语别名。
5. 是否有重复内容；5 个 canonical 文档已详述的没有大表复述。
6. 文档顶部元信息完整，summary、权威度、模块、COS路径、类别字段齐全。
7. 章节结构与约定一致（见输出结构）。

### 失败降级
某类来源完全不可读，直接跳过该来源信息，如实在证据字段标记，不编造内容。
