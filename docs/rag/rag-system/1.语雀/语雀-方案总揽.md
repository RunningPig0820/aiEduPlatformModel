## 1. 整体架构与分层模型

系统定位为**项目介绍 RAG 问答系统**：**不是纯 RAG，产品 = 项目介绍问答，RAG = 证明能力的引擎**；RAG 本身也作为项目一个功能点被介绍（"一鱼两吃"——用系统介绍系统）。证据：语雀-原文件-问题1.md / 问题3.md。

```
┌─────────────────────────────────────────────┐
│ 离线语料建设（策展，非全量倾倒）              │
│  语雀+代码+OpenSpec → 完善文档(8节/模块)       │
│  → 切片(metadata: page/doc_type/section/      │
│     source_doc) → embedding(dashscope 768d/   │
│     bge本地) → COS 向量桶 rag-index            │
└────────────────────┬────────────────────────┘
┌────────────────────▼────────────────────────┐
│ 双池（同一 COS 索引，doc_type 区分）          │
│  索引层QA池(doc_type=qa) 预写可控 +           │
│  源文档池(doc_type=source) 纯RAG证据          │
└────────────────────┬────────────────────────┘
┌────────────────────▼────────────────────────┐
│ 在线白盒流水线（标准 RAG 6 步）               │
│  权限门→意图识别→Query改写→多路召回→          │
│  RRF重排→范围门→流式生成(强制引用)             │
│  全阶段 SSE 透传 + token真算 + 降级矩阵        │
└─────────────────────────────────────────────┘
```

### 1.1 分层职责（Java + Python 无状态引擎）

| 层 | 职责 | 说明 |
|---|---|---|
| 前端学生页 | 页面锚定传 `page`、召回文档面板、demo 页直连 `x-internal-token` | 页面模式/全局模式由前端触发 |
| Java 网关 | 角色门（403）、SSE 中继、可信 session 取角色 | 与 tutoring 网关同构，Python 不碰会话 |
| Python RAG 引擎 | 无状态：意图硬路由→Query改写→多路召回→RRF 重排→范围门→doubao 流式→is_quoted | `core/rag/`，含语料切片/索引/检索编排/引导/评测/降级 |

证据：语雀-原文件-问题8.md（08-25 架构映射到 tutoring gateway pattern）。

### 1.2 产品意图反转：08-21 vs 08-25

产品范围在两套设计之间发生**反转/收窄**，是本模块最关键的演进事实（详见 `语雀-演进时间线.md`）：

| 维度 | 08-21 已设计 | 08-25 今日 spec | 关系 |
|---|---|---|---|
| 介绍对象 | 4 业务模块 + RAG 自身 | 仅 RAG 项目；AI答疑/知识图谱/题型分析=禁区拒答 | 🔴 范围反转/收窄 |
| 鉴权 | role 由 body 传（demo） | 可信源(Token/网关Header)取角色，仅学生放行，否则固定 403 | 🔴 收严，禁 body |
| 白盒透传 | 无（只回结果 + retrieved_docs） | 权限→意图→改写→召回→重排→token 全阶段 SSE 透传 | 🟢 新增 |
| 意图识别 | 无独立分类器（范围门兜底） | 硬路由：架构/代码/部署/评测/接口→RAG项目；禁区→固定拒答 | 🟢 新增 |
| Query 改写 | 无 | 改写后问题透传前端 | 🟢 新增 |
| 重排 | "小语料不需要重排模型" | RRF 融合，Top-K=3 | 🟡 08-21 显式否决过 RRF |
| 引用 | citations(page/section/source_doc) | Top-K 块 + is_quoted（LCS 硬匹配，8中/12英） | 🟢 新增确定性引用 |
| 引导 | 每页 5~8 条索引层 QA + 变体 chips | suggestions_pool.json 静态池随机 2~3 条，4 方向 | 🟡 简化/静态化 |
| 超时 | 检索 <2s / 生成 <15s | 召回 2s / 生成 8s | 🟡 生成收紧 |
| 断连 | "保留已吐内容" | is_disconnected() 主动取消 LLM 流 | 🟢 新增 |
| Token | cost{prompt/completion/cumulative/cost_yuan/embedding} | tokens_usage{prompt/completion/cache_hit/total} + trace_id | 🟡 标准化+新增 |
| 会话 | 页面锚定 + 5 轮上限 | 未明确轮数；强调对话时长/断连健壮性 | ❓ 待确认 |

证据：语雀-原文件-问题8.md（对比表全文）。

### 1.3 9 类问题矩阵（RAG 功能清单）

面试官问题按 9 类分类，每类对应不同的检索目标与展示形态（问题 2 定义的功能矩阵）：

| # | 问题类型 | 例子 | RAG 检索什么 | 展示形态 |
|---|---|---|---|---|
| ① | 概览类 | "介绍一下这个模块" | 产品定位+核心功能 | 项目卡片+一句话定位 |
| ② | 设计意图类 | "为什么这么设计？关键点" | 设计决策/Rationale | 关键决策点卡片（带出处） |
| ③ | 数据流转类 | "数据怎么流转的？" | 数据流/架构章节 | 流程图（mermaid→前端渲染） |
| ④ | 技术实现类 | "用什么技术栈？有哪些接口/表？" | 技术选型/API spec | 技术栈清单+接口列表 |
| ⑤ | 难点踩坑类 | "遇到什么难点？怎么解决？" | 设计权衡/问题记录 | 难点→解法卡片 |
| ⑥ | 对比权衡类 | "为什么用 Neo4j 不用 MySQL？" | Trade-offs/Decisions | 对比表 |
| ⑦ | 指标规模类 | "多少节点？匹配率？性能？" | 数据规模/验收指标 | 数字卡片（带引用来源） |
| ⑧ | 权限范围类 | "这个页面谁能用？" | 权限/角色定义 | 角色说明 |
| ⑨ | 边界规划类 | "题库做了吗？下一步呢？" | 范围/里程碑 | 明确边界或规划 |

证据：语雀-原文件-问题2.md。数据流转类（③）为差异化亮点——RAG 生成 mermaid 描述、前端渲染成图。

## 2. 核心概念与术语

| 术语 | 定义 |
|---|---|
| 双池检索 | 索引层预写 QA 池 + 源文档池 两层语料结构，同一 COS 索引以 `doc_type` 区分 |
| 索引层QA池 | 预写"问题+答案要点+引用"条目（doc_type=qa），引导问题命中→答案可控、上下文小、便宜 |
| 源文档池 | 完善文档全文 chunk（doc_type=source），自由问题命中→纯 RAG 真发挥 |
| 页面锚定 | 前端传 `page`，检索限定页面范围；是"页面路由"搬到文档域 |
| 页面模式 / 全局模式 | 页面模式=锁页检索；全局模式=跨页检索（自由问题/对比类） |
| 权限门 / 范围门 | 两道门：权限门（前置校验"能不能看"）+ 范围门（后置检索置信度"有没有覆盖"） |
| 范围门 = 检索置信度 | 检索不到高置信度条目→说明没覆盖→边界回答；语料即边界，无需单独分类器 |
| token 真算 | usage 真实采集（流式结尾更新，`stream_options.include_usage`）；丢 usage 是已踩坑 |
| 白盒化 | 权限→意图→改写→召回→重排→token 全阶段中间状态 SSE 透传前端 |
| 引导问题 | 索引层入口（UI 展示"你可能想问"），命中预置 QA 条目取答案 |
| 意图硬路由 | 架构/代码/部署/评测/接口→RAG项目；禁区模块→固定拒答 |
| 多路召回 | 向量 + BM25 两路召回 |
| RRF 融合 | Reciprocal Rank Fusion，多路结果按排名倒数融合，Top-K=3 |
| is_quoted | 引用标记，LCS 最长公共子串硬匹配，连续 8 中/12 英字符命中即引用 |
| 评测 agent | hit@k + answer_quality（LLM 判分，编造封顶 3 分），离线质量把关工具；证据：`文件:core/rag/eval_agent.py:_score_from_covered` |

## 3. 完整业务流程

### 3.1 离线语料建设

**来源**：语雀（产品意图）+ 代码注释/实现（落地事实）+ OpenSpec design 决策（为什么）+ git 提交（坑）+ api 契约（接口摘要）。证据：语雀-原文件-问题7.md。

1. 每模块产出一份**完善文档（8 节）**：①产品定位 ②核心功能 ③为什么这么设计 ④数据流转(含预置 mermaid) ⑤技术实现 ⑥关键坑与解法 ⑦数据规模与指标 ⑧权限与边界。证据：语雀-原文件-问题6.md / 问题7.md。
2. **切片 + metadata**：按 markdown 标题切分，保留 页面+章节 层级，metadata 带 `page / doc_type / section / source_doc`。证据：语雀-原文件-问题1.md / 问题8.md。
3. **嵌入**：dashscope 768d / bge 本地备选；维度固定不可改（换模型=全量重建）。证据：语雀-原文件-问题1.md / rag-system.md。
4. **索引**：COS 向量桶 `rag-index`（生产）/ 本地 FAISS（demo）同一接口抽象。证据：语雀-原文件-问题1.md。

**语料策展规则**：每页精选一套权威文档（如每模块 = 1 产品规划 + 1 设计方案）；问题记录/草稿/内部讨论/未发布文档明确不收录；spec/api 原文全文不进；除 RAG智能客服"规划中功能点"外内部规划状态不进。语料白名单本身就是权限层。证据：语雀-原文件-问题1.md / 问题7.md。

### 3.2 在线标准 RAG 流程（/api/rag/ask）

白盒化问答体验遵循 RAG 标准流程 6 步，中间状态实时透传前端。证据：语雀-原文件-问题8.md。

```
query理解(页面锚定+问题类型) → 权限门(前置) → 双池多路召回(向量+BM25)
→ RRF重排 Top-3 → 打分(相似度×问题类型×锚定) → 范围门(阈值0.75/0.5)
→ doubao 流式生成(强制引用) → is_quoted 后置硬匹配
→ cost(token usage 流结束更新) + mermaid 预置 + 5轮追问上限 + 降级矩阵
```

### 3.3 SSE 事件序列（每轮）

| 事件 | 内容 | 条件 |
|---|---|---|
| intent | LLM 结构化：anchor/switch/ambiguous | 可含 reject |
| rewrite | 改写后 query | 可含 |
| switch | anchor 变了，上下文重置（仅下一 turn，不掐在途流） | 条件 |
| rerank | RRF top-3 块：标题/摘要/file_path | 先发，供引用面板 |
| token | 生成流 | |
| reject / boundary | 两道门任一道触发 → 无 token 流 | reject: reason=module_not_covered / boundary: reason=no_relevant_doc |
| done | answer + quoted_keys + tokens_usage + trace_id + suggestions | |

证据：语雀-原文件-问题9.md。

### 3.4 横切能力

**降级矩阵**（逐级降级，最差也是"把原文给面试官看"）：

| 故障环节 | 降级到 | 最差兜底 |
|---|---|---|
| embedding API 挂/超时 | 关键词/规则（jieba）| 提示换说法 |
| 向量桶/COS 挂 | 本地索引 | 该页文档大纲 |
| 全挂 | 页面文档大纲（"这一页讲什么"结构）| 边界话术 |
| LLM 生成挂/超时 | 展示召回原文（"我找到了以下相关资料…点击查看原文"）| 预写答案卡片 |

超时：召回 2s（单路超时自动降级为纯另一路）/ 生成 8s。断连：`is_disconnected()` 检测前端断开→立即中止底层 LLM 流式请求，防后端空转烧钱。证据：语雀-原文件-问题1.md / 问题8.md。

**其他横切**：引导问题静态池（§4）、token 成本展示（§7）、评测 agent（§4/§9）。

## 4. 数据模型与池结构

### 4.1 索引层 QA 条目（doc_type=qa）

每条 = **问题 + 答案要点 + 引用**，每模块 5~8 条；UI 引导问题为索引层规范问题的**变体写法**（例：UI"你们为什么拆成三段" vs 索引"为什么拆 decide/generate/question-understand"），强制检索真实发生、避免"点按钮=预定答案"。证据：语雀-原文件-问题3.md / 问题5.md；design-python-project-intro-rag.md D3。

### 4.2 源文档 chunk（doc_type=source）

完善文档全文切片，metadata 四元组：

| 字段 | 含义 |
|---|---|
| page | 所属页面/模块（知识图谱/AI答疑/组织中心/学生知识点分析/RAG问答系统） |
| doc_type | qa（索引层）/ source（源文档池） |
| section | 8 节之一（定位/功能/为什么/数据流/技术/坑/指标/权限） |
| source_doc | 来源文档，支撑"点击查看原文"+ 召回文档面板 |

切片时把源文档全文存进 metadata，答案生成后前端渲染**召回文档面板**（面试官能看到系统捞了哪几段原文）——把 RAG 检索从黑盒变成"能指给你看"。证据：语雀-原文件-问题5.md / 问题8.md。

### 4.3 suggestions_pool.json（引导静态池）

后端预置静态池（非 LLM 生成），每次问答完成后随机抽 2~3 条引导建议，强制引导学生围绕 4 方向追问（静态化降本）。证据：语雀-原文件-问题8.md。

```json
{
  "project_intro": ["想了解RAG的整体架构吗？", "想知道这个系统解决了什么痛点吗？"],
  "operation": ["如何部署这套RAG系统？", "接口调用流程是怎样的？"],
  "data_relation": ["知识库的数据是如何流转的？", "向量和BM25是怎么协同的？"],
  "difficulty": ["RRF融合算法有什么难点？", "评测体系是如何设计的？"]
}
```

### 4.4 会话与 token 数据结构

- `tokens_usage`：`prompt_tokens / completion_tokens / cache_hit_tokens / total_tokens`，随每轮返回。
- `trace_id`：供前端断线后补查。证据：语雀-原文件-问题8.md。
- 会话：页面锚定 + 追问上限 5 轮/会话（08-21），超限提示开新会话（文案预写）。

### 4.5 评测集

每条 = `{module, question, question_type, expected_references[], expected_points[]}`，每模块 ≥5 条（25 条基准，建议扩到 30~50 条）；`question_type` ∈ 概览/为什么/数据流/难点/指标，保证覆盖索引层 QA 各类型。预期引用/要点是 hit@k 与答案质量的 ground truth。证据：design-python-rag-eval-agent.md D2；语雀-原文件-问题12.md。

## 5. 检索与重排逻辑

检索链路：**页面锚定过滤 → 多路召回（向量 + BM25）→ RRF 融合 → 打分 → 范围门**。

1. **页面锚定过滤**：页面模式下检索限定该页（`page` 过滤）；全局模式不限。天然可解释——"这条问题命中了 AI答疑 页面，所以我在这个页面的文档里检索"。证据：语雀-原文件-问题1.md / 问题2.md。
2. **多路召回**：向量 + BM25 两路；单路超时自动降级为纯另一路。证据：语雀-原文件-问题8.md。
3. **RRF 融合**：多路结果按排名倒数融合，最终只展示喂给 LLM 的 Top-K 块（建议 K=3），严禁全量召回列表吐前端。证据：语雀-原文件-问题8.md。注：08-21 曾显式否决重排模型（"小语料不需要重排模型"，D5），08-25 反转采用 RRF。证据：问题8.md 对比表。
4. **打分公式**：`score = 相似度 × 问题类型匹配 × 页面锚定加权`；索引层池 top-K=1~3，源文档池 top-K=3~5。证据：design-python-project-intro-rag.md D5。
5. **范围门阈值**：索引层命中 > 0.75、源文档池 > 0.5，低于→边界回答。两阈值分工：索引层要精、源文档池要宽。证据：design-python-project-intro-rag.md D4/D5；rag-system.md。

每个展示块必须附：**块标题/摘要、文件路径（前端"点击查看原文"）、is_quoted 标签**。被引用块高亮，未引用灰显折叠。证据：语雀-原文件-问题8.md。

**is_quoted 判定规则**：不依赖 LLM 主观自述，采用确定性硬匹配——生成完成后遍历每个候选块的 `content_preview`，在最终答案字符串做最长公共子串（LCS）匹配，任意连续 **8 个中文字符（或 12 个英文字符）** 命中即标记 `is_quoted=True`，后端实现、无需 LLM 额外输出。证据：语雀-原文件-问题8.md。

## 6. 两道门与拒答机制

### 6.1 权限门（前置，硬性拦截）

后端从**可信源**（Token/网关 Header）取角色，**严禁信任前端 Body 传参**；仅当角色明确为"学生"时放行，非学生/角色缺失→直接返回固定 403 拒绝语，不进入任何 RAG 流程、**不消耗任何 Token**。证据：语雀-原文件-问题8.md。08-21 时期为页面权限标签 + demo 学生=最高权限（前置校验机制保留），08-25 收严为可信源取角色。证据：design-python-project-intro-rag.md Non-Goals / 问题8.md。

### 6.2 意图门（硬路由，禁区拒答）

- 凡问题涉及"系统架构 / 代码实现 / 部署流程 / 评测方案 / 接口设计"→ 强制路由至 **RAG项目** 知识库。
- 凡明确指向 **AI答疑 / 知识图谱 / 题型分析** 三个禁区模块 → 直接返回固定话术 **"该问题涉及其他业务模块，我尚未掌握"**，**严禁调用 LLM 生成拒答语**（节省成本，0 token）。
- 语义分析层透传 3 项：原始问题 / 改写后问题 / 意图分类标签（如 `#rag_project` 或 `#reject`）。证据：语雀-原文件-问题8.md。

### 6.3 范围门（后置，检索置信度即范围判断）

检索置信度低于阈值→说明语料未覆盖→边界回答，**不硬编**。语料本身就是范围，无需单独"是否覆盖"分类器。证据：语雀-原文件-问题4.md；design-python-project-intro-rag.md D4。

### 6.4 双门协作（"没有找到知识文档"两者都要）

| 门 | 触发时机 | 代价 | 事件 |
|---|---|---|---|
| 意图门 | turn 开头 intent 后立即判（最便宜）| 不 recall、不 generate、0 token | event: reject + reason: module_not_covered |
| 范围门 | recall 之后，检索置信度低于阈值 | 付了 recall、省 generate | event: boundary + reason: no_relevant_doc |

两道门共享同一固定拒答话术（不调 LLM）；前端据此展示"拒绝发生在哪一层"。证据：语雀-原文件-问题9.md。

### 6.5 生成中切换：不支持

**下一轮切换**符合业务（intent 每轮本来就跑，多一次"当前锚点 vs 已锚定"对比，switch 前零生成 token）；**生成中切换**是另一量级（中止上游 doubao HTTP 流不可靠、半截答案作废、半截 token 已计费不退款）。生成中只做一件事：`is_disconnected()` → 中止，防空转烧钱。`switch` 事件不掐断在途流，只作用于下一 turn 上下文（重置锚点/清上轮召回/重新 rewrite→recall）。证据：语雀-原文件-问题9.md。

## 7. 成本与 token 体系

### 7.1 token 真算（usage 流式结尾更新）

现有代码**丢 usage**的坑（已踩）：`ark_stream.py` 请求体没加 `stream_options: {"include_usage": true}`（OpenAI 兼容流式不加默认不返回 usage）；`_parse_sse_lines` 只解析 reasoning/content/tool_calls，流里带 usage 也被丢弃。修复 = 两处小改动：请求体加 `include_usage`、解析时抓最后一个 chunk（choices 为空但带顶层 usage）→ 流结束取 `usage.prompt_tokens / completion_tokens`。embedding 侧同理：`vector_store.embed()` 只返回向量，`resp.usage.total_tokens` 未抓。证据：语雀-原文件-问题4.md；design-python-project-intro-rag.md D7。面试可讲："流式下 usage 只在结尾返回，所以我是结束后更新"。

### 7.2 成本叙事

- **每轮明细**：输入(query + 检索到的 N 段上下文共 X tokens) + 输出(答案 Y tokens) = Z tokens；可视化检索成本（"本轮检索了 3 段上下文 450 tokens"）让面试官直观看到 RAG 为什么费 token。
- **累计 + 费用换算**：整场会话累计 token，按模型单价换算成 ¥。
- **成本控制故事**：本地 bge 免费 embedding / top-K 限制上下文膨胀 / 查询 LRU 缓存 / 降级到关键词检索便宜路径 / 追问上限。证据：语雀-原文件-问题3.md。

### 7.3 模型选择与边际成本

| 方案 | 成本叙事 | 代价 |
|---|---|---|
| 免费模型 glm-4-flash | "本地 bge embedding + 免费生成模型，边际成本趋近 0"（最强）| 质量弱于答疑链路 |
| doubao（答疑同款）| 复用 ark_stream（usage 改动只做一次）| token 单价付费，费用数字不好看 |

证据：语雀-原文件-问题5.md。08-21 生成选 doubao 流式；08-25 沿用 doubao 流式。

### 7.4 cache_hit_tokens 与估算口子

`cache_hit_tokens`（缓存命中）ark/doubao **不一定真返回**，取不到→ tokenizer 估算并标注"估算"（08-21 已留此口子）。证据：语雀-原文件-问题8.md（待验证项）/ 问题11.md。

## 8. 已知风险与漏洞

| 风险 | 说明 | 缓解 |
|---|---|---|
| 语料版本矛盾 | 语雀空模板/多版本方案/未发布草稿，同问题召回互相矛盾版本当场翻车 | 每页策展精选权威文档，完善文档向代码事实对齐、冲突以代码为准 |

| 答案一致性 | 跨页回答引用矛盾段落 | 完善文档第 3/6 节统一口径 + prompt 强制按页引用 |
| 生成超时露怯 | 8s 超时无答案 | 直接返回召回清单"我找到了以下相关资料…点击查看原文" |

证据：语雀-原文件-问题1/8/11.md；design-python-project-intro-rag.md Risks。

### 9.4 评测体系补强（问题12）

## 12. 上线灰度策略

1. **demo 兜底**：生产走 COS 向量桶（生产链路叙事），demo 默认本地 FAISS + 索引抽象层同接口；COS 10s 异步写后不可即查→demo 前预建索引。证据：design-python-project-intro-rag.md D11；语雀-原文件-问题1/5.md。
2. **迁移顺序**：先产出「知识图谱」完善文档作标本→确认格式→补其余模块（+ RAG 功能点文档）→离线脚本（完善文档→切片→embedding→COS 建 rag-index，`--clear` 幂等）→在线链路分阶段（召回→打分/范围门→生成/引用→权限门→降级→token 展示）。证据：design-python-project-intro-rag.md Migration。
3. **评测先于推广**：知识图谱模块先切片索引→写该模块评测集→跑评测 agent→出首份报告→迭代稳定后推广到其余模块（状态机 pending→organized→chunked→indexed→evaluated）。证据：design-python-rag-eval-agent.md Migration。
4. **回滚**：新增 `/api/rag/*` 独立路由，不影响既有 tutoring 路径；ark_stream 改动对既有调用透明（多返回 usage，不改变流式语义）；评测 agent 纯离线（`/api/rag/eval/*` 独立前缀），不触碰 `/api/rag/ask` 主链路。证据：design-python-project-intro-rag.md / design-python-rag-eval-agent.md Migration。
