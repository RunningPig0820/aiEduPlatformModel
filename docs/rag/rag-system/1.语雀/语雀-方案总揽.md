## 1. 整体架构与分层模型

系统定位为**项目介绍 RAG 问答系统**：**不是纯 RAG，产品 = 项目介绍问答，RAG = 证明能力的引擎**；RAG 本身也作为项目一个功能点被介绍（"一鱼两吃"——用系统介绍系统）。证据：语雀-原文件-问题1.md / 问题3.md。

```
┌─────────────────────────────────────────────┐
│ 离线语料建设（策展，非全量倾倒）              │
│  语雀+代码+OpenSpec → 完善文档(8节/模块)       │
│  → 切片(metadata: page/doc_type/section/      │
│     source_doc) → embedding(dashscope 768d/   │
│     bge本地) → COS 向量桶 rag-index            │
└────────────────────┬────────────────────────┘
┌────────────────────▼────────────────────────┐
│ 双池（同一 COS 索引，doc_type 区分）          │
│  索引层QA池(doc_type=qa) 预写可控 +           │
│  源文档池(doc_type=source) 纯RAG证据          │
└────────────────────┬────────────────────────┘
┌────────────────────▼────────────────────────┐
│ 在线白盒流水线（标准 RAG 6 步）               │
│  权限门→意图识别→Query改写→多路召回→          │
│  RRF重排→范围门→流式生成(强制引用)             │
│  全阶段 SSE 透传 + token真算 + 降级矩阵        │
└─────────────────────────────────────────────┘
```

## 2. 核心概念与术语

| 术语 | 定义 |
|---|---|
| 双池检索 | 索引层预写 QA 池 + 源文档池 两层语料结构，同一 COS 索引以 `doc_type` 区分 |
| 索引层QA池 | 预写"问题+答案要点+引用"条目（doc_type=qa），引导问题命中→答案可控、上下文小、便宜 |
| 源文档池 | 完善文档全文 chunk（doc_type=source），自由问题命中→纯 RAG 真发挥 |
| 页面锚定 | 前端传 `page`，检索限定页面范围；是"页面路由"搬到文档域 |
| 页面模式 / 全局模式 | 页面模式=锁页检索；全局模式=跨页检索（自由问题/对比类） |
| 权限门 / 范围门 | 两道门：权限门（前置校验"能不能看"）+ 范围门（后置检索置信度"有没有覆盖"） |
| 范围门 = 检索置信度 | 检索不到高置信度条目→说明没覆盖→边界回答；语料即边界，无需单独分类器 |
| token 真算 | usage 真实采集（流式结尾更新，`stream_options.include_usage`）；丢 usage 是已踩坑 |
| 白盒化 | 权限→意图→改写→召回→重排→token 全阶段中间状态 SSE 透传前端 |
| 引导问题 | 索引层入口（UI 展示"你可能想问"），命中预置 QA 条目取答案 |
| 意图硬路由 | 架构/代码/部署/评测/接口→RAG项目；禁区模块→固定拒答 |
| 多路召回 | 向量 + BM25 两路召回 |
| RRF 融合 | Reciprocal Rank Fusion，多路结果按排名倒数融合，Top-K=3 |
| is_quoted | 引用标记，LCS 最长公共子串硬匹配，连续 8 中/12 英字符命中即引用 |
| 评测 agent | hit@k + answer_quality（LLM 判分，编造封顶 3 分），离线质量把关工具；证据：`文件:core/rag/eval_agent.py:_score_from_covered` |
| 双池三路（代码落地） | 全量池向量(rag-full) + 切片池双向量(rag-slice `-c` 内容路/`-q` 问题路) + 本地 BM25，四路 RRF 融合；替代方案 doc_type=qa/source 双池 |
| 模块 id 闭集 | ai-tutoring/knowledge-graph/question-analysis/rag-system 四模块，语料按 metadata.module 过滤选池（D-A） |
| 范围门判定口径 | 用召回置信度（向量 = 1-平均余弦距离、BM25 = `min(1.0, top_score/10)`）与 0.75/0.5 比，非 RRF 相对分（0.01~0.05 量级永远够不到阈值，2026-08-25 校正） |

### 3.2 在线标准 RAG 流程（/api/rag/assistant/ask）

白盒化问答体验遵循 RAG 标准流程，中间状态实时透传前端。【落地】生产入口为白盒 SSE 端点 `POST /api/rag/assistant/ask`（`stream=true` 流式 / `stream=false` 非流式 done+stages）；旧 1.6C 同步端点 `POST /api/tutoring/rag/query` 仍保留（`{answer, references, intent, version}`）。证据：语雀-原文件-问题8.md；分析-01/04。

```
permission(Java, 含traceId) → intent(模块锚点+类别+问候/clarify/switch 判定)
→ rewrite(改写透传) → recall(双池三路: rag-full向量+rag-slice -c/-q 向量+BM25, 单路2s超时降级)
→ rerank(RRF×authority×锚定 Top-3 精排) → 范围门(check_boundary 0.75/0.5)
→ doubao 流式生成(强制引用, 8s) → is_quoted(LCS 后置硬匹配) → done
→ cost(token usage 流结束更新) + 引导建议(GUIDE_POOL 池内原题) + 降级矩阵
```

### 3.3 SSE 事件序列（每轮）

| 事件 | 内容 | 条件 |
|---|---|---|
| permission | `{role, allowed, traceId}`，trace_id 流开始即可取（D-B） | 仅 Java 网关产（角色门在 Java，Python 生产端点不产，从 intent 开始） |
| intent | LLM 结构化：anchor/category/switchDetected/ambiguous/candidates/lockedSections；问候→category="问候" | 可含 degraded（LLM 失败回退关键词锚定） |
| clarify | 固定话术 + candidates(字符串 id 数组) + default，0 token 不计答案轮次、写 history | ambiguous & candidates≥2；点选候选 = 重发原问 + currentProject=点选 id（intent 以 currentProject 为权威锚点） |
| switch | fromAnchor→toAnchor，上下文重置（仅下一 turn，不掐在途流） | 前端 current_project ≠ 会话已锚定 project |
| rewrite | 改写后 query `{originalQuestion, rewrittenQuery}` | 基于原问题+锚点+历史 |
| rerank | RRF top-3 精排块：blockId/title/summary/filePath/score（**严禁吐全量召回列表**） | 单路降级可带 degraded |
| boundary | reason=low_confidence，固定话术 0 token | 范围门触发（rerank 空 或 vec<0.75 且 bm<0.5），无 token 流，rerank 可为空 |
| token | 生成流 | |
| done | answer + quoted_keys + tokens_usage + trace_id + suggestions | **所有分支的终止点**（前端到 done 停止一切转圈） |

分支无流规则：`clarify`/`switch` 分支**无 rewrite/recall/generate**；`boundary` 分支**无 token 流**；时序冻结为 `permission → intent → (clarify|switch) → rewrite → rerank → (boundary|token) → done`，不得重排/丢失。

证据：语雀-原文件-问题9.md；design-java 契约 D-A~D-E + 事件时序（M2 冻结）；spec-java-gateway 事件字段契约。

### 3.4 横切能力

**降级矩阵**（逐级降级，最差也是"把原文给面试官看"）：

| 故障环节 | 降级到 | 最差兜底 |
|---|---|---|
| embedding API 挂/超时 | 关键词/规则（jieba）| 提示换说法 |
| 向量桶/COS 挂 | 本地索引 | 该页文档大纲 |
| 全挂 | 页面文档大纲（"这一页讲什么"结构）| 边界话术 |
| LLM 生成挂/超时 | 展示召回原文（"我找到了以下相关资料…点击查看原文"）| 预写答案卡片 |

超时：召回 2s（单路超时自动降级为纯另一路）/ 生成 8s。断连：`is_disconnected()` 检测前端断开→立即中止底层 LLM 流式请求，防后端空转烧钱。证据：语雀-原文件-问题1.md / 问题8.md。【落地】代码降级路径为"向量挂→纯 BM25 / doubao 挂→召回块清单当答案 / 无命中→拒答 / 全挂→边界话术"（1.6C 与白盒各自落地，**"返回页面大纲"一级未见**）；`DEGRADED_VECTOR/BM25` 标记定义了但未透传进 SSE 事件。证据：分析-01/07。

**其他横切**：引导问题静态池（§4）、token 成本展示（§7）、评测 agent（§4/§9）、显式关闭对话 + 会话累计 token（【定稿 D12】`POST /sessions/{sessionId}/close`：中止在途流 + 置 closed + 返回累计 token/轮数；断连未 close 时累计保留 Redis 续接）、Java 侧真实对话 LLM 质量打分旁路（done 后异步判分累计进评估报告，不阻塞 SSE）。证据：design-java D12；`RagAssistantAppService.close/scheduleGradeOnDone`。

## 4. 数据模型与池结构

### 4.1 索引层 QA 条目（doc_type=qa）

每条 = **问题 + 答案要点 + 引用**，每模块 5~8 条；UI 引导问题为索引层规范问题的**变体写法**（例：UI"你们为什么拆成三段" vs 索引"为什么拆 decide/generate/question-understand"），强制检索真实发生、避免"点按钮=预定答案"。证据：语雀-原文件-问题3.md / 问题5.md；design-python-project-intro-rag.md D3。

### 4.2 源文档 chunk（doc_type=source）

完善文档全文切片，metadata 四元组：

| 字段 | 含义 |
|---|---|
| page | 所属页面/模块（知识图谱/AI答疑/组织中心/学生知识点分析/RAG问答系统） |
| doc_type | qa（索引层）/ source（源文档池） |
| section | 8 节之一（定位/功能/为什么/数据流/技术/坑/指标/权限） |
| source_doc | 来源文档，支撑"点击查看原文"+ 召回文档面板 |

切片时把源文档全文存进 metadata，答案生成后前端渲染**召回文档面板**（面试官能看到系统捞了哪几段原文）——把 RAG 检索从黑盒变成"能指给你看"。证据：语雀-原文件-问题5.md / 问题8.md。

【落地】代码 metadata 实际 10 字段**无 doc_type**：`version/module/category/source/authority/section/file/file_path/anchor/summary`（`build_index.py:145-157`，注释"doc_type 与 module 同值冗余已去掉 2026-08-26"）；双池 = **rag-full(整篇 23 块) / rag-slice(切片 294 块) 两个物理 COS 索引**，靠 metadata.module + 查询侧 Filter($eq) 隔离；**page 参数未落地**，模块由 current_project/anchor 承载。切片全文不进 metadata（≤2048B 限制），命中后经 key 反查本地 jsonl。证据：分析-01/03。

### 4.3 引导静态池（方案 suggestions_pool.json → 代码 GUIDE_POOL dict）

后端预置静态池（非 LLM 生成），每次问答完成后随机抽 2~3 条引导建议，强制引导学生围绕方向追问（静态化降本）。证据：语雀-原文件-问题8.md。

【落地】代码实现为 **Python dict `GUIDE_POOL`**（`core/rag/guide_pool.py`，**非 json 文件**）；方向由方案的 4 组扩展为 **5 组**（`intro/operation/data_relation/difficulty` + **rag 桥接子集**，rag 组可与其他组重复、scope 去重）；已入池 ai-tutoring(75 去重)/question-analysis(70)/knowledge-graph(64)，**rag-system 未入池**（兜底 `FALLBACK_MODULE="ai-tutoring"`）。证据：分析-05。

【落地反转】方案"UI 引导问题 = 索引层规范问题**变体写法**、强制检索真实发生"在代码中被**反转**为**池内原题直出**（`assistant.py:326-331`，注释记录 2026-08-26 用户实测：LLM 改编引入池外概念致新问题匹配不到切片）；引导题纯池不切片，点击后走双向量 `-q` 问题路检索（命中 sim~0.99）。

### 4.4 会话与 token 数据结构

- `tokens_usage`：`prompt_tokens / completion_tokens / cache_hit_tokens / total_tokens`，随每轮返回。
- `trace_id`：供前端断线后补查。【定稿 D-B】由 Java 网关入口生成并随 `permission` 事件下发，**流开始即可取**，断线补查不依赖 done；每轮 done 快照存 Java Redis（`rag:assistant:trace:{traceId}`，TTL 24h），`GET /api/rag/assistant/turns/{traceId}` 读回（超窗 → 10002）。证据：语雀-原文件-问题8.md；design-java D-B/D8；`RagAssistantAppService.persistRound`。
- `sessionId`：【定稿 D-C】前端面板挂载生成 UUID 整场复用；Java 以 sessionId 为键累计会话 token + 轮数（`rag:assistant:session:{sessionId}:usage`，close 结算返回；断连未 close 时累计保留 Redis 续接）。Python 无状态不落会话。
- 会话：页面锚定 + 追问上限 5 轮/会话（08-21）；【定稿 08-25】**不设轮数上限**（用户确认轮数无意义），改为上下文窗口保留**最近 3 轮** history（`HISTORY_LIMIT=3`，history 由前端传、Java 透传 Python 只消费+截断；刷新后为空=新会话）。证据：design-java Open Questions；分析-01。

### 4.5 评测集

每条 = `{module, question, question_type, expected_references[], expected_points[]}`，每模块 ≥5 条（25 条基准，建议扩到 30~50 条）；`question_type` ∈ 项目介绍/操作/数据关联/难点/最危险/**边界拒答**（`VALID_TYPES` 闭集含 08-25 新增边界拒答类型，断言=触发固定话术且 0 token）。预期引用/要点是 hit@k 与答案质量的 ground truth。证据：design-python-rag-eval-agent.md D2；design-java D10；语雀-原文件-问题12.md。

【落地】`HIT_K=5`（2026-08-26 由 3 改 5，对齐生成 top-5，方案 hit@3 演进）；判分 LLM 只报事实 `{covered_count, fabricated, rationale}`、分数由 `_score_from_covered` 规则硬算（覆盖比例分档 5→0，**编造 ≥1 处封顶 3 分**，`eval_agent.py:164-183`）；**评测集仅 `ai-tutoring.jsonl` 6 条**（5 正常 + 1 边界拒答"帮我写一封辞职信"），`eval_dataset.py:76` 硬编码 `module=="ai-tutoring"`——**无 rag-system 评测集**，多模块评测需先改此处。评测走真实检索原语不降级（向量挂了就暴露）。证据：分析-06。

## 5. 检索与重排逻辑

检索链路：**页面锚定过滤 → 多路召回（向量 + BM25）→ RRF 融合 → 打分 → 范围门**。

1. **页面锚定过滤**：页面模式下检索限定该页（`page` 过滤）；全局模式不限。天然可解释——"这条问题命中了 AI答疑 页面，所以我在这个页面的文档里检索"。证据：语雀-原文件-问题1.md / 问题2.md。【落地】**无 page 参数**，演变为两层锚定：模块级 `current_project` + intent anchor（闭集 `MODULE_ANCHORS`，`select_corpus` 按 module 过滤选池）+ 节级 `locked_sections`（`ANCHOR_WEIGHT=1.5`，**只加权不过滤**）；**白盒链路 recall 写死 `locked_sections=[]`（assistant.py:118）节级锚定被旁路**，旧 1.6C 端点则完整传入（两入口召回排序可能不同）。证据：分析-01/04。
2. **多路召回**：向量 + BM25 两路；单路超时自动降级为纯另一路。证据：语雀-原文件-问题8.md。【落地】代码为**双池三路**：全量池向量(rag-full) + 切片池双向量(rag-slice `-c`/`-q`) + 本地 BM25（jieba+Okapi），**四路 RRF**；任一向量路 2s 超时 → 空路降级 + degraded 标记（`RAG_RECALL_TIMEOUT=2.0`）。证据：分析-01/04。
3. **RRF 融合**：多路结果按排名倒数融合，最终只展示喂给 LLM 的 Top-K 块（建议 K=3），严禁全量召回列表吐前端。证据：语雀-原文件-问题8.md。注：08-21 曾显式否决重排模型（"小语料不需要重排模型"，D5），08-25 反转采用 RRF。证据：问题8.md 对比表。【落地】`RRF_K=60`，`score = RRF × authority × anchor_w`（`query.py:667`）；白盒 `rerank` 事件只回传精排 `RERANK_K=3` 块（assistant.py:31）。证据：分析-04。
4. **打分公式**：方案 `score = 相似度 × 问题类型匹配 × 页面锚定加权`；索引层池 top-K=1~3，源文档池 top-K=3~5。证据：design-python-project-intro-rag.md D5。【落地演进】**"问题类型匹配"未单独成因子**（类别过滤已废弃，LLM 判类别不准误伤），相似度由 RRF rank 间接表达；权威度（1.0 完善文档/0.8 代码/0.7 语雀）连乘、节锚定命中 ×1.5；top-K 全局 5（生成用），白盒 rerank 回传 3。证据：分析-01/04。
5. **范围门阈值**：索引层命中 > 0.75、源文档池 > 0.5，低于→边界回答。两阈值分工：索引层要精、源文档池要宽。证据：design-python-project-intro-rag.md D4/D5；rag-system.md。【落地】**0.75/0.5 只在白盒 `check_boundary` 生效**（`assistant.py:388-408, 616-625`：rerank 空 → 拒答；或 `vec_conf<0.75 且 bm_conf<0.5` 双路都低才拒），**1.6C `/query` 端点无阈值门**只有空命中拒答；判定用召回置信度（向量=1-平均余弦距离、BM25=`min(1.0,top_score/10)`），非 RRF 相对分。证据：分析-04/07。

每个展示块必须附：**块标题/摘要、文件路径（前端"点击查看原文"）、is_quoted 标签**。被引用块高亮，未引用灰显折叠。证据：语雀-原文件-问题8.md。

**is_quoted 判定规则**：不依赖 LLM 主观自述，采用确定性硬匹配——生成完成后遍历每个候选块的 `content_preview`，在最终答案字符串做最长公共子串（LCS）匹配，任意连续 **8 个中文字符（或 12 个英文字符）** 命中即标记 `is_quoted=True`，后端实现、无需 LLM 额外输出。证据：语雀-原文件-问题8.md。

## 6. 两道门与拒答机制

### 6.1 权限门（前置，硬性拦截）

后端从**可信源**（Token/网关 Header）取角色，**严禁信任前端 Body 传参**；仅当角色明确为"学生"时放行，非学生/角色缺失→直接返回固定 403 拒绝语，不进入任何 RAG 流程、**不消耗任何 Token**。证据：语雀-原文件-问题8.md。08-21 时期为页面权限标签 + demo 学生=最高权限（前置校验机制保留），08-25 收严为可信源取角色。证据：design-python-project-intro-rag.md Non-Goals / 问题8.md。

【落地】**权限门在 Java 网关**（`RagAssistantController.requireStudent` → `TutoringAuth.isStudent(session)`），仅 STUDENT 放行、**body 传 role 一律忽略**、非学生/角色缺失固定 403（`ResponseStatusException(FORBIDDEN)`，不进入 RAG 流程、不产生 trace）；**Python 代码无权限门**——`api/rag.py`/`api/rag_assistant.py` 仅 `verify_internal_token`（内部服务鉴权），请求模型无 role/permission 字段（`api/rag_assistant.py:9` 明确"permission 由 Java 网关产"）。【定稿 D-B】`permission` 事件 = `{role, allowed, traceId}`，trace_id 由 Java 入口生成，流开始前端即可取（断线补查不依赖 done）。证据：分析-01/04；design-java D1/D-B。

### 6.2 意图门（硬路由 + 问候识别）

- 凡问题涉及"系统架构 / 代码实现 / 部署流程 / 评测方案 / 接口设计"→ 强制路由至 **RAG项目** 知识库。
- 凡明确指向 **AI答疑 / 知识图谱 / 题型分析** 三个禁区模块 → 直接返回固定话术 **"该问题涉及其他业务模块，我尚未掌握"**，**严禁调用 LLM 生成拒答语**（节省成本，0 token）。【落地反转】08-25 定稿改走"**模块全放行 + 范围门低置信过滤**"（D4/D9，用户确认"AI答疑、知识图谱、题型分析和 RAG 模块都放行，查不到关联文档直接返回可信度低过滤"），**意图层无禁区硬拒答**，唯一拒答路径 = `boundary`(reason=low_confidence)；未来模块入库切片即自动可答（数据驱动，无代码改动）。证据：design-java D4/D9；guardrails spec。
- 语义分析层透传 3 项：原始问题 / 改写后问题 / 意图分类标签（如 `#rag_project` 或 `#reject`）。证据：语雀-原文件-问题8.md。
- 【定稿 D-E】**问候识别**：intent 将"你好/Hi/在吗"识别为 `category="问候"`、`ambiguous=false`，**不触发 clarify**（clarify 仅用于功能指代不明：ambiguous+candidates≥2；实联调发现"你好"被误判 ambiguous 弹澄清很怪）；走**欢迎话术 + 引导池建议**（0 生成 token，不 recall 不 generate），指向 ①项目介绍②操作③数据关联④难点。代码实现 `is_greeting` 关键词预检（你好/您好/hello/hi/哈喽/嗨/hey/在吗，**短句 ≤8 字才命中防误杀**，assistant.py:361,366-372）+ `WELCOME_MSG` 直返 done（assistant.py:580-586）。证据：design-java D-E；分析-05。

### 6.3 范围门（后置，检索置信度即范围判断）

检索置信度低于阈值→说明语料未覆盖→边界回答，**不硬编**。语料本身就是范围，无需单独"是否覆盖"分类器。证据：语雀-原文件-问题4.md；design-python-project-intro-rag.md D4。

【落地】**0.75/0.5 只在白盒链路 `check_boundary` 生效**（`assistant.py:388-408, 616-625`：rerank 空 → 拒答；或 `vec_conf<0.75 且 bm_conf<0.5` 双路都低才拒，单路高即过；`vec_conf=max(全量置信, 切片置信)`），**1.6C `/query` 端点无阈值门**、只有"hits 为空"粗粒度拒答（`api/rag.py:120-126`，docstring 自称"置信度过低→拒答"与实际不符）。**阈值语义校正（2026-08-25）**：初版误用 rerank 的 RRF 融合分（量级 0.01~0.05）比对 0.75/0.5 → 所有命中都误判低置信拒答；改为**召回置信度**（向量 = 1-平均余弦距离 / BM25 = `min(1.0, top_score/10)`）。触发 → boundary 事件 + 固定话术"未找到关联文档，我尚未掌握。" + **短路不调 generate（0 token，防无谓成本）**。证据：分析-04/07；guardrails spec 阈值语义校正。

### 6.4 双门协作（"没有找到知识文档"两者都要）

| 门 | 触发时机 | 代价 | 事件 |
|---|---|---|---|
| 权限门 | Java 网关入口（最前置） | 非 STUDENT → 固定 403，0 token、不产生 trace | HTTP 403（非 SSE 事件）；STUDENT → `permission` 事件 |
| 意图门 | turn 开头 intent 后立即判 | 不 recall、不 generate、0 token | 08-21 为 `reject`(module_not_covered)；**08-25 改全放行，无 reject**（四模块均可路由） |
| 范围门 | recall 之后，检索置信度低于阈值 | 付了 recall、省 generate | `boundary` + reason=**low_confidence**（唯一拒答路径） |

【落地】08-25 定稿后**唯一拒答路径 = 范围门 `boundary`(low_confidence)**（D4/D9，模块全放行由语料驱动）；权限门在 Java 网关（HTTP 403 而非 SSE reject 事件）；两道门共享固定拒答话术（不调 LLM），前端据此展示"拒绝发生在哪一层"。证据：语雀-原文件-问题9.md；design-java D4/D9；guardrails spec。

### 6.5 生成中切换：不支持

**下一轮切换**符合业务（intent 每轮本来就跑，多一次"当前锚点 vs 已锚定"对比，switch 前零生成 token）；**生成中切换**是另一量级（中止上游 doubao HTTP 流不可靠、半截答案作废、半截 token 已计费不退款）。生成中只做一件事：`is_disconnected()` → 中止，防空转烧钱。`switch` 事件不掐断在途流，只作用于下一 turn 上下文（重置锚点/清上轮召回/重新 rewrite→recall）。证据：语雀-原文件-问题9.md。

## 7. 成本与 token 体系

### 7.1 token 真算（usage 流式结尾更新）

现有代码**丢 usage**的坑（已踩）：`ark_stream.py` 请求体没加 `stream_options: {"include_usage": true}`（OpenAI 兼容流式不加默认不返回 usage）；`_parse_sse_lines` 只解析 reasoning/content/tool_calls，流里带 usage 也被丢弃。修复 = 两处小改动：请求体加 `include_usage`、解析时抓最后一个 chunk（choices 为空但带顶层 usage）→ 流结束取 `usage.prompt_tokens / completion_tokens`。embedding 侧同理：`vector_store.embed()` 只返回向量，`resp.usage.total_tokens` 未抓。证据：语雀-原文件-问题4.md；design-python-project-intro-rag.md D7。面试可讲："流式下 usage 只在结尾返回，所以我是结束后更新"。

【落地对账】**白盒流式链路已修**：`stream_generate` 传 `include_usage=True`（`assistant.py:448`）+ 流末尾 usage chunk 经 `_parse_sse_lines` yield（`ark_stream.py:128-129`）+ `assemble_usage` 组装 `{prompt/completion/cache_hit/total}` 进 done.tokens_usage（`assistant.py:486-502, 514`，cache_hit 从 `prompt_tokens_details.cached_tokens` 取，取不到 → 0）；**评测侧真采**（`generate(return_usage=True)` → `eval_agent.calc_cost`）。**1.6C `/query` 端点仍不采**（`api/rag.py:130` 未传 `return_usage`，`RAGQueryResponse` 模型无 usage 字段）；**embedding 侧仍未抓**（`vector_store.embed()` 不返 usage，方案 D7"embedding 单列"未落地）。证据：分析-01/04/07。

### 7.2 成本叙事

- **每轮明细**：输入(query + 检索到的 N 段上下文共 X tokens) + 输出(答案 Y tokens) = Z tokens；可视化检索成本（"本轮检索了 3 段上下文 450 tokens"）让面试官直观看到 RAG 为什么费 token。
- **累计 + 费用换算**：整场会话累计 token，按模型单价换算成 ¥。
- **成本控制故事**：本地 bge 免费 embedding / top-K 限制上下文膨胀 / 查询 LRU 缓存 / 降级到关键词检索便宜路径 / history 截断（最近 3 轮）+ 0 token 兜底话术（问候/澄清/边界/超时均写死不调 LLM）。证据：语雀-原文件-问题3.md；分析-01/07。

### 7.3 模型选择与边际成本

| 方案 | 成本叙事 | 代价 |
|---|---|---|
| ~~免费模型 glm-4-flash~~ | ~~"本地 bge embedding + 免费生成模型，边际成本趋近 0"（最强）~~ | 08-25 已不采用 |
| **doubao（答疑同款）** | 复用 ark_stream（usage 改动只做一次）| token 单价付费，费用数字不好看 |

证据：语雀-原文件-问题5.md。08-21 生成选 doubao 流式；【已定 08-25】**生成/意图/改写/判分统一 doubao**（`doubao-seed-2-0-mini-260428`：意图/改写/判分 0 温度关思考 20s 超时、生成 0.2 温度 60s 超时，`settings.py:56,60`），**glm-4-flash 免费模型优先叙事已放弃**；成本叙事转为"本地 bge embedding 免费 + doubao 单价（¥0.003/0.009 千 token）+ top-K 控制上下文膨胀 + 0 token 兜底话术"。证据：分析-01/04/06。

`cache_hit_tokens`（缓存命中）ark/doubao **不一定真返回**，取不到→ tokenizer 估算并标注"估算"（08-21 已留此口子）。【落地】代码从 `prompt_tokens_details.cached_tokens` 取（`assistant.py:486-502`），取不到**置 0 而非"估算"标注**；需实现期实测 doubao 是否真返回缓存命中计数。证据：语雀-原文件-问题8.md（待验证项）/ 问题11.md；分析-01。

## 12. 上线灰度策略

1. **demo 兜底**：生产走 COS 向量桶（生产链路叙事），demo 默认本地 FAISS + 索引抽象层同接口；COS 10s 异步写后不可即查→demo 前预建索引。证据：design-python-project-intro-rag.md D11；语雀-原文件-问题1/5.md。
2. **迁移顺序**：先产出「知识图谱」完善文档作标本→确认格式→补其余模块（+ RAG 功能点文档）→离线脚本（完善文档→切片→embedding→COS 建 rag-index，`--clear` 幂等）→在线链路分阶段（召回→打分/范围门→生成/引用→权限门→降级→token 展示）。证据：design-python-project-intro-rag.md Migration。
3. **评测先于推广**：知识图谱模块先切片索引→写该模块评测集→跑评测 agent→出首份报告→迭代稳定后推广到其余模块（状态机 pending→organized→chunked→indexed→evaluated）。证据：design-python-rag-eval-agent.md Migration。
4. **回滚**：新增 `/api/rag/*` 独立路由，不影响既有 tutoring 路径；ark_stream 改动对既有调用透明（多返回 usage，不改变流式语义）；评测 agent 纯离线（`/api/rag/eval/*` 独立前缀），不触碰 `/api/rag/ask` 主链路。证据：design-python-project-intro-rag.md / design-python-rag-eval-agent.md Migration。
5. 【落地 08-25】白盒助手按 **M1-M8 里程碑纵向切片**交付（每里程碑 = 纵向切片 + 前后端+模型端三端对接测试，SSE 契约 M2 冻结下游只补字段）；Python 先行泛化 `query.py` 白盒链路 + 新增 `assistant.py`/`api/rag_assistant.py`，Java 网关新增 `RagAssistantController`（角色门 + SSE 中继 + trace_id），前端另立 `rag-assistant-frontend` 变更；**数据无迁移**（AI答疑语料现状，其它模块入库即自动可答）。证据：design-java 交付编排 M1-M8；design-python Migration；分析-01。
