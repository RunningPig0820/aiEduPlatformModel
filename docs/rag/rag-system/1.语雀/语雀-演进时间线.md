### 阶段2：关键决定落定（问题3/4/5）

> 状态：已落地设计（决定在 08-21/08-24 design D2/D3/D4/D6/D7 落定并代码落地）
> 检索摘要：落定全部关键决定：问题索引层=话术库（RAG=引擎，非纯 RAG）、权限=展示属性（demo 学生最高权限）、引导问题=索引层入口、答案 B 路线（要点+生成）、token 真算（丢 usage 坑）、双池检索、两道门（范围门=检索置信度）、跨页按页引用+召回原文面板、引导 chips 变体文案。

- 阶段时间：未注明（问题3/4/5 讨论阶段，早于 2026-08-21 纪要定稿）
- 核心形态：话术库定位、答案 B 路线、token 真算、双池检索、两道门、跨页按页引用、引导问题变体文案、召回原文面板
- 迭代翻转（相对阶段1）：
  1. **定位收口**：问题索引层 = 话术库，RAG = 引擎——不是纯 RAG 项目，是"用 RAG 引擎驱动项目介绍系统"；权限简化为**展示属性**（每页面挂权限标签，前端渲染，不做真角色体系）
  2. **引导问题变体**：UI 引导问题 = 索引层规范问题的变体写法（"你们为什么拆成三段" vs "为什么拆 decide/generate"），强制检索真实发生，避免"点按钮=预定答案"；每页需提前配对两套文案
  3. **答案形态落定 B 路线**：索引层存"答案要点 + 强制引用原文段落"，LLM 实时组织语言（A 全预写=查表露怯、C 纯检索=不可控翻车，弃）
  4. **token 真算**：发现现有代码丢 usage（ark_stream 不加 `stream_options: {"include_usage": true}`、`_parse_sse_lines` 丢弃 usage）→ 请求体加 include_usage + 流结束抓结尾 usage chunk；embedding 侧抓 `resp.usage.total_tokens`
  5. **双池检索确立**：索引层池（20~30 条 QA，引导问题可控）+ 源文档池（自由问题纯 RAG 真发挥）——"源文档池=真的检索"正是证明 RAG 能力的证据
  6. **两道门确立**：权限门（检索前过滤，限定搜索空间）+ 范围门（检索后判定，=检索置信度，语料即边界）；范围门阈值 0.75/0.5 于 08-24 design D4/D5 定稿
  7. **跨页按页引用 + 召回原文面板**：答案按页面分别引用（每句标来源页）；切片时每个 chunk 把源文档全文存进 metadata，答案生成后前端渲染"召回文档"面板，检索从黑盒变"能指给你看"
- 阶段详述：本轮把骨架件全部钉成可执行决定。引导问题=索引层入口（每条 QA 条目 = UI"你可能想问"按钮，安全路径直接取预置条目）；Token 展示做成完整成本叙事（每轮 prompt/completion 明细+会话累计+¥ 换算，本地 bge 免费 embedding / top-K 限制 / 降级便宜路径）；自由问题走两道门完整路径（自由输入→权限门过滤可检索页→向量检索→范围门置信度判定→命中取要点+引用合成/未命中边界回答→流式输出→结束更新 token 明细）；流程图预置为主（每页一张 mermaid，demo 可靠性优先）；演示走本地 FAISS 优先（零网络依赖）+ 索引抽象层（生产 COS 同接口）；边界话术预写 2~3 条固定"不在范围"回答。
- 关联决策：D2（双池）、D3（页面锚定+变体文案）、D4（两道门）、D6（生成强制引用+按页标注）、D7（token 真算）（design-python-project-intro-rag）
- 落地证据：语雀-原文件-问题3、问题4、问题5
