### 阶段2：关键决定落定（问题3/4/5）

> 状态：✅ 已落地设计（决定在 08-21/08-24 design D2/D3/D4/D6/D7 落定并代码落地）
> 检索摘要：落定全部关键决定：问题索引层=话术库（RAG=引擎，非纯 RAG）、权限=展示属性（demo 学生最高权限）、引导问题=索引层入口、答案 B 路线（要点+生成）、token 真算（丢 usage 坑）、双池检索、两道门（范围门=检索置信度）、跨页按页引用+召回原文面板、引导 chips 变体文案。

- 阶段时间：未注明（问题3/4/5 讨论阶段，早于 2026-08-21 纪要定稿）
- 核心形态：话术库定位、答案 B 路线、token 真算、双池检索、两道门、跨页按页引用、引导问题变体文案、召回原文面板
- 迭代翻转（相对阶段1）：
  1. **定位收口**：问题索引层 = 话术库，RAG = 引擎——不是纯 RAG 项目，是"用 RAG 引擎驱动项目介绍系统"；权限简化为**展示属性**（每页面挂权限标签，前端渲染，不做真角色体系）
  2. **引导问题变体**：UI 引导问题 = 索引层规范问题的变体写法（"你们为什么拆成三段" vs "为什么拆 decide/generate"），强制检索真实发生，避免"点按钮=预定答案"；每页需提前配对两套文案
  3. **答案形态落定 B 路线**：索引层存"答案要点 + 强制引用原文段落"，LLM 实时组织语言（A 全预写=查表露怯、C 纯检索=不可控翻车，弃）
  4. **token 真算**：发现现有代码丢 usage（ark_stream 不加 `stream_options: {"include_usage": true}`、`_parse_sse_lines` 丢弃 usage）→ 请求体加 include_usage + 流结束抓结尾 usage chunk；embedding 侧抓 `resp.usage.total_tokens`
  5. **双池检索确立**：索引层池（20~30 条 QA，引导问题可控）+ 源文档池（自由问题纯 RAG 真发挥）——"源文档池=真的检索"正是证明 RAG 能力的证据
  6. **两道门确立**：权限门（检索前过滤，限定搜索空间）+ 范围门（检索后判定，=检索置信度，语料即边界）；范围门阈值 0.75/0.5 于 08-24 design D4/D5 定稿
  7. **跨页按页引用 + 召回原文面板**：答案按页面分别引用（每句标来源页）；切片时每个 chunk 把源文档全文存进 metadata，答案生成后前端渲染"召回文档"面板，检索从黑盒变"能指给你看"
- 阶段详述：本轮把骨架件全部钉成可执行决定。引导问题=索引层入口（每条 QA 条目 = UI"你可能想问"按钮，安全路径直接取预置条目）；Token 展示做成完整成本叙事（每轮 prompt/completion 明细+会话累计+¥ 换算，本地 bge 免费 embedding / top-K 限制 / 降级便宜路径）；自由问题走两道门完整路径（自由输入→权限门过滤可检索页→向量检索→范围门置信度判定→命中取要点+引用合成/未命中边界回答→流式输出→结束更新 token 明细）；流程图预置为主（每页一张 mermaid，demo 可靠性优先）；演示走本地 FAISS 优先（零网络依赖）+ 索引抽象层（生产 COS 同接口）；边界话术预写 2~3 条固定"不在范围"回答。
- 关联决策：D2（双池）、D3（页面锚定+变体文案）、D4（两道门）、D6（生成强制引用+按页标注）、D7（token 真算）（design-python-project-intro-rag）
- 落地证据：语雀-原文件-问题3、问题4、问题5

  3. **🟢 白盒透传新增**：无（只回结果+retrieved_docs）→ 权限→意图→改写→召回→重排→生成全阶段 SSE 透传，语义处理三项（原始问题/改写后问题/意图分类标签）必须在流式元数据阶段透传
  4. **🟢 意图识别新增**：无独立分类器（范围门兜底）→ 硬路由：架构/代码/部署/评测/接口 → 强制路由 RAG 项目；指向禁区 → 直接固定拒答
  5. **🟢 Query 改写新增**：改写后问题透传前端
  6. **🟡 重排引入**："小语料不需要重排模型"（08-21 显式否决过 RRF）→ RRF 融合 Top-K=3，只展示喂给 LLM 的 Top-K 块，严禁全量召回列表吐前端
  7. **🟢 is_quoted 确定性引用**：citations → Top-K 块+块标题/摘要/文件路径+is_quoted（不依赖 LLM 自述，生成完成后对 content_preview 做最长公共子串匹配，任意连续 8 中文字符或 12 英文字符命中即 True）
  8. **🟡 引导静态化**：每页 5~8 条索引层 QA+变体 chips → suggestions_pool.json 静态池随机抽 2~3 条，4 方向（project_intro/operation/data_relation/difficulty），严禁动态生成省 token
  9. **🟡 超时收紧**：检索 <2s / 生成 <15s → 召回 2s（单路超时自动降级纯另一路）/ 生成 8s；生成超时直接返回召回清单话术
  10. **🟢 断连主动取消**："保留已吐内容" → `is_disconnected()` 检测前端断开即中止 LLM 流，防空转烧钱
  11. **🟡 token 标准化+新增 trace_id**：cost{prompt/completion/cumulative/¥/embedding} → tokens_usage{prompt/completion/cache_hit_tokens/total} + trace_id 供断线后补查
  12. **❓ 会话轮数待确认**：页面锚定+5 轮上限 → 未明确轮数，强调对话时长/断连健壮性

### 阶段5：健壮性与评测深化（问题9/11/12）

> 状态：⚠️ 评测 agent 已落地（承接 eval-agent D1~D7）；LLM 健壮性/白盒可观测/成本安全 16 项以建议项为主
> 检索摘要：深化拒答双门事件契约（reject/boundary）、确立"下一轮切换"模型；补齐 LLM 健壮性 8 项（提示注入/结构化兜底/无引用不输出/重试分层/429/上下文窗口/模型分层）、白盒可观测 4 项（阶段失败透传/is_quoted 时序/trace_id 补查/断线恢复）、成本安全 4 项（会话 token 预算/current_project 信任/渲染安全/契约容错）；评测分层框架 L1~L4 + RAGAS 参考。

- 阶段时间：未注明（问题9/11/12 讨论，晚于 08-25 spec）
- 核心形态：拒答双门事件契约、下一轮切换模型、LLM 健壮性 8 项、白盒可观测 4 项、成本安全 4 项、评测分层框架、RAGAS 参考
- 迭代翻转（相对阶段4）：
  1. **拒答双门语义化**：两道门都产同一固定拒答话术（不调 LLM），但事件区分——意图门拒答发 `reject`（reason=module_not_covered，零检索零生成）；范围门拒答发 `boundary`（reason=no_relevant_doc，付 recall 省 generate）；SSE 事件契约定型：intent→rewrite→switch(条件)→rerank→token→reject/boundary→done(answer+quoted_keys+tokens_usage+trace_id+suggestions)
  2. **切换模型定型**：选**下一轮切换**（intent 每轮跑，多一次"当前锚点 vs 已锚定"对比，switch 前零生成 token）；生成中切换需中止上游 doubao 流/半截答案作废/半截 token 已计费且上游取消不可靠，不建议做；生成中只做 `is_disconnected()` → 中止
  3. **LLM 健壮性 8 项补齐**（spec 最薄层）：提示注入/越权（复用 tutoring safety_flag：本地关键词+intent 兜底，命中→固定安全话术 0 token）、intent 结构化输出兜底（复用 200+degraded=true，LLM 失败→回退规则 `_fallback_anchor`）、"无引用不输出"执行细节（quoted_keys 为空→标注"引用未能精确匹配"或重召回一档，不假装有引用）、重试语义分层（intent/rewrite 0 重试走规则兜底；recall COS 短超时重试 1~2 次幂等；generate 0 重试超时→召回清单话术）、速率限制 429（服务端每学生每秒 N 次+429 降级召回清单）、上下文窗口管理（每会话轮次上限+history 截断保留最近 N 轮+首轮锚点）、cache_hit_tokens 拿不到→tokenizer 估算并标注"估算"、模型分层（intent/rewrite 快模型，generate 强模型）
  4. **白盒可观测 4 项补齐**：每阶段失败/超时也要透传（`stage_failed`+stage+reason，否则降级对面试官不可见=没降级）、is_quoted 时序（8 中文字符匹配须生成完才能算→rerank 块先发灰显、done 后补 quoted_keys 高亮，"先灰后亮"）、缺 `GET /api/rag/turns/{trace_id}` 断线补查接口、断线恢复需会话持久化（Redis/MySQL）+恢复接口（否则 trace_id 补查是死口）
  5. **成本与安全 4 项**：每会话累计 token 预算上限（如 50k，到顶提示开新会话）、current_project 信任边界（服务端校验 ∈ 有语料模块列表，防恶意传参空转）、语料渲染安全（markdown/mermaid/HTML 防注入，mermaid 白名单校验）、Java↔Python 契约容错（FAIL_ON_UNKNOWN_PROPERTIES=false、snake↔camel、degraded 走 200 不走 503）
  6. **评测体系深化**：分层评估 L1 知识库（覆盖率/重复率/过期版本）/ L2 检索（Context Recall/Precision，hit@3=0.80）/ L3 生成（Faithfulness/Answer Relevancy，质量分 3.6~4.6/5）/ L4 端到端（Answer Correctness/Latency&Cost，单条 ≈5.6s/≈¥0.016）；评估数据集三要素（问题+标准答案+证据文档 ID），建议 RAG 项目介绍助手单独建 30~50 条评测集覆盖 5 类（项目介绍/操作流程/数据关联/难点技术/边界拒答）；RAGAS 四指标参考（Faithfulness 两阶段 LLM 调用可复用 judge_quality）
- 阶段详述：优先级排序——提示注入、无引用不输出、轮次上限、trace_id 补查+断线恢复是"不做会翻车"级，其余是"做了更完整"。评测最终话术锚定为"专属评估数据集+检索/生成/端到端三维度持续追踪+每次改动跑回归评测并生成对比报告"，把"RAG 靠不靠谱"从主观问题变成每轮评测报告上的数字。
- 关联决策：无新 D#（建议项为主，问题9/11/12 讨论）；评测部分承接 design-python-rag-eval-agent D1~D7（hit@k/answer_quality/trace+报告）
- 落地证据：语雀-原文件-问题9、问题11、问题12
