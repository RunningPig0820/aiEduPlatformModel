> 阅读提示：正文分块小节为 RAG 检索主体；附录原始大表格仅供人工翻阅，不要依赖表格做召回。配套主文档 `语雀-方案总揽.md` 详述正常链路，本文专注"遇到 XX 异常如何处理"。

## 一、两道门拒答类场景

### 场景1：非学生角色访问学生助手（固定 403）

> 状态：✅【已落地】
> 检索摘要：权限门前置校验，Java 网关从可信 session 取角色，非 STUDENT 固定 403 拒绝语，不进入 RAG 流程、不调用 LLM、不消耗 token、不产生 trace。

| 属性 | 内容 |
|---|---|
| 业务场景 | 非学生角色（教师/管理员/其他）访问 RAG 项目介绍助手 |
| 触发条件 | 已登录用户角色为 TEACHER/ADMIN 或其它非 STUDENT 角色发起 `/api/rag/assistant/ask` |
| 当前处理 | Java 网关 `RagAssistantController.requireStudent` → `TutoringAuth.isStudent(session)`，仅 STUDENT 放行；**body 传 role 一律忽略**，非学生返回固定 403（`ResponseStatusException(FORBIDDEN)`） |
| 兜底降级策略 | 前端读角色非 STUDENT 展示"当前非学生无法使用"占位，不发起 ask；0 token、不产生 trace |
| 残余风险 | 若 Java 侧与 tutoring 网关角色判定逻辑不一致（`TutoringAuth.isStudent` 与 `requireStudent` 两处同构），存在判定口径漂移可能 |

证据：语雀-原文件-问题8.md；spec-java-rag-project-intro-assistant-gateway；3.代码/分析-01、04；[总揽§6.1]

### 场景4：范围门低置信拒答（0.75/0.5）

> 状态：✅【已落地·仅白盒链路】
> 检索摘要：召回后范围门判定，rerank 空或向量置信度<0.75 且 BM25 置信度<0.5 双路都低才拒答；判定用召回置信度非 RRF 融合分，触发 boundary 事件固定话术 0 token、短路不调 generate。

| 属性 | 内容 |
|---|---|
| 业务场景 | 问题超出语料覆盖，检索置信度不达标 |
| 触发条件 | rerank 空；或 `vec_conf < 0.75 且 bm_conf < 0.5`（双路都低，单路高即过）；`vec_conf = max(全量置信, 切片置信)` |
| 当前处理 | `check_boundary`（assistant.py:394-408，616-625）：触发 → `boundary` 事件（reason=low_confidence）+ 固定话术"未找到关联文档，我尚未掌握。"，**短路不调 generate（0 token，防无谓成本）**；阈值语义校正（2026-08-25）：初版误用 RRF 融合分（0.01~0.05 量级够不到阈值）→ 改为召回置信度（向量=1-平均余弦距离 / BM25=min(1.0, top_score/10)） |
| 兜底降级策略 | 全局模式跨页检索 + 引导问题把高频问题收纳进索引层，减少误拒 |
| 残余风险 | **范围门只在白盒链路生效**，1.6C `/query` 端点无阈值门（只有 `if not hits` 空命中拒答，docstring 自称"置信度过低→拒答"与实际不符）；低置信但非空命中在 1.6C 会直接进生成，可能硬编 |

证据：3.代码/分析-01、04、07；spec-python-rag-project-intro-assistant-guardrails；[总揽§6.3/§5#5]

### 场景5：无语料模块必然边界拒答（DEFAULT_MODULE=rag-system 悬空）

> 状态：⚠️【部分落地】
> 检索摘要：query 未传 module 时默认 Filter 指向 rag-system，但 MODULE_DATA 无 rag-system jsonl，anchor=rag-system 当前必然边界拒答；rag-system 完善文档头无 `> COS路径:` 被 upload_cos 跳过。

| 属性 | 内容 |
|---|---|
| 业务场景 | 学生提问被路由到尚无语料的模块（当前 rag-system 自身） |

### 场景6：指代词"这个功能"被误路由到 rag-system

## 二、检索异常类场景

### 场景7：向量桶 / COS 挂（降级纯 BM25）

> 状态：✅【已落地】
> 检索摘要：COS 向量桶异常或 query 失败时，1.6C 端点构造空向量结果降级纯 BM25，白盒链路单路降空路 + DEGRADED_VECTOR 标记，BM25 纯本地断电可用。

| 属性 | 内容 |
|---|---|
| 业务场景 | 现场演示/生产时 COS 向量桶网络抖动或 down |
| 触发条件 | `query_vector` 抛异常 / 超时（向量桶 rag-1318177119 不可达） |
| 当前处理 | 1.6C：`retrieve_dual` 内层 try 捕获 → 构造 `full/slice/slice_q` 空结果 + `bm25 = retrieve_bm25`（api/rag.py:100-106）；白盒：`_recall_vector` 捕获 → 空路 `{"hits":[], "confidence":0.0}` + `DEGRADED_VECTOR="vector_timeout"` |
| 兜底降级策略 | BM25 纯本地（jieba+Okapi，query.py:529-578）不依赖网络，断电断网可用；最差兜底=页面文档大纲/边界话术（"返回大纲"一级代码未见） |
| 残余风险 | 归一退化为关键词匹配，语义同型变体召回变差；`DEGRADED_VECTOR` 标记定义了但未透传进 SSE 事件（见场景31） |

证据：3.代码/分析-01、04、07；坑档案 K3（向量桶 role mode 拒普通对象）；[总揽§3.4/§8]

### 场景8：embedding 失败（dashscope 不可用）

> 状态：✅【已落地】
> 检索摘要：embedding 接口（dashscope）超时/不可用时，query_vector 内 embed 抛异常冒泡到 retrieve_dual，两入口都降级 BM25；embedding 是增强层，不影响主链路。

| 属性 | 内容 |
|---|---|
| 业务场景 | dashscope embedding 服务不可用/超时 |
| 触发条件 | `vector_store.embed()`（dashscope text-embedding-v3，vector_store.py:87-103）抛异常 |
| 当前处理 | `query_vector` 内 `embed(text)` 异常（vector_store.py:172-175）→ 冒泡到 retrieve_dual → 1.6C 降级纯 BM25 / 白盒 `_recall_vector` 捕获降空路 |
| 兜底降级策略 | 与向量桶挂共用 BM25 降级路径；embedding 是增强能力，主链路（语料落库/BM25 检索）不依赖 |
| 残余风险 | 降级后无语义泛化，仅关键词命中；评测走真实检索原语不降级，embedding 挂时评测会暴露失败（特性非 bug） |

证据：3.代码/分析-07；[总揽§3.4/§8]

### 场景9：检索超时（2s 单路降级）

> 状态：✅【已落地】
> 检索摘要：白盒向量召回每路独立 2s 硬超时，单路超时降空路 + degraded 标记，链路继续走另一路，绝不无限阻塞。

| 属性 | 内容 |
|---|---|
| 业务场景 | 向量召回超过预算时间 |
| 触发条件 | `RAG_RECALL_TIMEOUT=2.0s`（settings.py:119），`asyncio.wait_for` + `run_in_threadpool` 超时 |
| 当前处理 | `_recall_vector`（assistant.py:71-88）：单路 2s 超时 → 空路降级 + `DEGRADED_VECTOR="vector_timeout"` 标记，链路继续；BM25 本地路永远可用 |
| 兜底降级策略 | 一路挂只影响该路，另一路正常出结果；最差=rerank 空 → 范围门拒答 |
