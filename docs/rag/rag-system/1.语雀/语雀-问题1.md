跟之前教育版相比，简单了一个数量级：切分不用管公式、不用管题目完整性、不用指纹。但同时，有几个这个领域
专属的新坑，是你之前那版没有的：

这个领域你没考虑到的

① 语料治理 / 版本一致性（最大的坑）
你手上有 方案设计1/2/3/4、设计方案拆分1-5、知识图谱方案设计还没发布、产品中心的文档还是空模板。同一个问
题会召回互相矛盾的版本——面试官问“为什么这么设计”，RAG
可能把“方案1”和“方案2”的矛盾描述都搬出来，当场翻车。
对策：每页精选一套权威文档（比如每个模块 = 1 产品规划 + 1
设计方案），问题记录、草稿、内部讨论明确不收录。语料要“策展”而不是“全量倾倒”。

② 页面锚定（页面路由）
面试官的问题几乎都带页面：“知识图谱为什么用 Neo4j？”、“AI答疑怎么防作弊？”。所以 query
理解第一件事是识别提到哪个页面，然后检索只在该页面的文档内做。这比全局检索质量高得多，而且天然可解释——
你能对面试官说“这条问题命中了 AI答疑 页面，所以我在这个页面的文档里检索”。相当于把你们已有的
subject_classify 思路搬到文档域。

③ 超出范围的处理（比“答对”更要紧）
面试官一定会问不在你语料里的东西：“题库呢？” “权限中心呢？” “RAG智能客服做了吗？”。RAG
最大的翻车点就是没检索到还硬编答案。所以“该不该检索”的自适应判断在这个系统里是保命功能：超出范围 →
明确说“这个模块不在本次介绍范围内”并给出边界，而不是编。这比任何检索优化都重要。

④ Demo 可靠性
面试现场你不可能依赖 COS
和网络——万一超时/断网就是当着面试官的面演示降级失败。设计上应该索引抽象层：生产走 COS，demo 走本地
FAISS，同一个接口。“本地兜底”这件事本身就是你重试降级的最好故事，而且面试能真演示。

⑤ 评测集（便宜但救命）
因为你懂自己的文档，可以花半小时写 20 条“预期问答对”（每个模块 5
条），做命中率评估。面试官问“怎么证明有效”，你直接亮 hit@k 数据。这是小语料系统里最划算的投资。

三件横切能力，在这个领域重新定位

需要你拍板的

    - 一鱼两吃：它既是 RAG 项目本身，又是你的自我介绍——面试官问“这页为什么这么设计”，你直接让系统答，用你自
己的系统介绍自己的项目，闭环本身就是演示
    - 可验证：你比谁都懂这些文档，回答好不好你一眼能判断，不用等人评
    - 自适应判断 → 变成两级：页面路由（提到哪页锁哪页）+
检索必要性（超出介绍范围就拒绝检索、直接给边界提示）。这两个都是你既有
subject_classify/意图分类模式的自然延伸，好讲、有真实代码支撑。
    - 权限判断 → 简化成演示可见性：只收录“可以给面试官看”的文档；问题记录/未发布/内部规划（优先级、待启动状
态）不进语料。这个“语料白名单”就是权限层。
    - 重试降级 → 逐级：embedding
挂→BM25；向量桶挂→本地索引；全挂→返回该页面文档大纲（“这一页讲什么”的结构，至少面试官能接着问）；LLM
挂→直接展示检索到的原文。最差情况也是“把原文给面试官看”，不尴尬。
    1. 语料来源：只用 OpenSpec 技术文档？还是也收语雀的产品文档（产品规划/设计方案）？我建议两类都要——产品
文档讲“为什么这么设计”，技术文档讲“怎么落地”，正好对应你想讲的两个维度。
    2. 覆盖范围：只覆盖 4 个有内容的页面，还是也想把 RAG智能客服/AI知识库
这些“待启动”的收进去（作为“规划中”回答）？
    3. 展示形态：纯问答界面，还是带“召回过程可视化”（每路召回+打分过程）——后者面试演示更炸，但多一层工作量
。
