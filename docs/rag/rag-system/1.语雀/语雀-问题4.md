  ②有个精妙点：范围门 = 检索置信度

  你不需要单独做个“问题在不在方案里”的分类器——你的语料本身就是范围：

  问题检索不到高置信度条目 → 说明没覆盖 → 边界回答
  “这个问题不在本次介绍范围，我目前覆盖了 知识图谱/AI答疑/组织中心/学生知识点分析，
    你可以问我其中任何一个页面的设计、数据流转或难点。”

  “检索置信度即范围判断”——这是纯 RAG
  机制，面试官问“你怎么判断问题在不在范围内”，你答“检索不到就是不在，我的语料就是边界”，逻辑自洽且漂亮。

  自由问题的完整路径（两道门在中间）

  自由输入: “知识图谱怎么支撑AI答疑的防作弊?”(跨页)
    → 权限门: 当前角色(学生)能访问哪些页 → 过滤可检索页集合
    → 向量检索: 在权限内全局检索(命中AI答疑+知识图谱两页的条目)
    → 范围门: 置信度达标?
         ✓ → 取两页预写要点+引用 → 模型合成回答(双页引用)
         ✗ → 边界回答(上面那段)
    → 流式输出 → 结束时 usage 更新本轮 token 明细

  权限门是检索前过滤（限定搜索空间，也更快）；范围门是检索后判定（置信度兜底）。两道门职责不同，正好分层
  。

  还剩几个可以讨论的点

1. 跨页答案的形态——上面例子命中两页，模型怎么“合成”？我建议 prompt
里明确“回答时按页面分别引用”，输出长这样：
  ▎ 知识图谱提供图谱检索作为召回一路（引用：知识图谱页§5）…AI答疑的防作弊主要靠行为风控（引用：AI答疑页§
  五）…每句话标来源页，这是“多页 RAG”的规范做法。
2. 权限在 demo 里怎么演——前端放个“角色”切换（学生/教师/管理员）？切到学生，组织中心页的条目就从检索范围
里消失，现场演示权限门生效。
3. 引导问题要不要也“制造点难度”——如果 chips 点下去永远精确命中，面试官可能觉得“预定答案”。一个化解法：
引导问题文案和索引层问题故意不同写法（“你们为什么拆三段” vs 索引里的“为什么拆
decide/generate”），让检索真的匹配一下，而不是直接查 ID。
