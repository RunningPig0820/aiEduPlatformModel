## 回答

三个回应都收到，先锁一下（每个都带一个隐含的设计要求）：

  ① 跨页引用 + 召回原文 —— 落定为“检索可见”：切片时每个 chunk 把源文档全文存进
  metadata，答案生成后前端渲染一个“召回文档”面板，面试官能直接看到系统捞了哪几段原文。这一步把 RAG
  的检索从“黑盒”变成“能指给你看”。

  ② 权限 —— 落定为“前置校验”：进页面/会话时直接校验“当前页需要的权限点 vs 当前角色”，demo
  默认学生账号=最高权限（所以演示中权限门基本放行，但机制在那，可切换演示）。

  ③ 制造难度 —— 落定，但它带来一个隐藏的 curation 要求：每页要写两套文案——UI
  上给面试官看的“引导问题”（变体写法）+
  索引层里的“规范问题”（检索目标）。比如引导问题写“你们为什么拆成三段”，索引条目是“为什么拆
  decide/generate/question-understand”。这个要提前配对好。

---

  还有什么值得讨论：4 个实质性 + 几个小项

  A. 检索池到底几层？（最关键，决定 RAG 有多“真”）

+ 只有索引层（20~30 条 QA 条目）：引导问题全可控，但自由问题命中不了就直接边界拒绝。面试官问个没准备的
→ 当场只能答“不在范围”。
+ 索引层 + 源文档双池：引导问题走索引层（稳定），自由问题走源文档池（纯 RAG
真发挥，能答你没准备的问题）。代价是自由问题不可控一点。
+ 你要证明 RAG 能力，“源文档池 = 真的检索”正是证据。我倾向双池，但这是你要拍板的。

  B. 生成模型用谁？这决定你的成本故事。

+ 免费模型（glm-4-flash）：成本故事最强——“本地 bge embedding + 免费生成模型，我这套 RAG
的边际成本趋近于 0”。
+ doubao（答疑同款）：质量和答疑链路一致，能复用 ark_stream（usage 改动只做一次），但 token
单价是付费的，费用换算数字没那么好看。
+ 面试官看 token/cost 展示时，问的是“你这套跑起来多贵”，模型选谁直接决定答案。

  C. 数据流流程图：真生成还是预置？

+ 你点名要流程图。两条路：
    - 预置：每页存一张 mermaid 图，命中“数据流”类问题直接展示 → 稳定、快、面试不翻车
    - 动态生成：LLM 检索数据流要点 → 现场生成 mermaid → 前端渲染 → 炫但有格式/渲染风险
+ demo 可靠性优先的话，我建议预置为主、动态为进阶。

  D. 演示跑本地还是 COS？

+ 本地 FAISS：面试现场零网络依赖，绝不出错
+ COS 向量桶：生产链路、好讲，但有 10s 异步 + 网络风险（当着面试官的面断网就完了）
+ 建议索引抽象层 + demo 默认本地，UI 上标注“生产环境走 COS”；或者你坚持 COS 也行，但本地兜底必须备着。
