## Context

面试用的**项目介绍 RAG 问答系统**：用 RAG 引擎驱动，给面试官讲清每个项目页面（产品设计 / 为什么这么设计 / 数据流转 / 关注点）。

现状约束：
- 语料来源（语雀文档）大量是**空模板**，同模块**多版本矛盾**，部分**未发布草稿**读不到 —— 必须先完善文档再切片。
- 已有基础设施可直接复用：`vector_store.py`（dashscope embedding 768 维 + COS 向量桶，`rag` 索引已预留）、`ark_stream.py`（doubao 流式，但**当前不采 usage**）、`settings.py`（COS_VECTORS_INDEXES / INTERNAL_TOKEN）、jieba（关键词）、降级模式（错误冒泡 / 吞异常降级 / 20s 内部超时）。
- 定位：**不是纯 RAG**。产品 = 项目介绍问答，RAG = 证明能力的引擎。RAG 本身也作为项目一个功能点被介绍。

设计依据：`docs/project-intro-rag-notes-2026-08-21.md`（讨论纪要，本设计的来源）。

## Goals / Non-Goals

**Goals:**
- 覆盖 4 个有内容的模块：知识图谱 / AI答疑 / 组织中心 / 学生知识点分析（RAG 自身作为第 5 个介绍点）。
- 文档准备：语雀 + 代码 + OpenSpec → 完善成每模块「完善版设计文档」→ 切片 → 嵌入 → COS 索引。
- 双池检索：索引层池（预写 QA，可控）+ 源文档池（纯 RAG）。
- 页面锚定：前端传 `page`，页面模式锁页 / 全局模式跨页。
- 两道门：权限门（前置校验）+ 范围门（检索置信度 → 边界回答不硬编）。
- 生成带引用、按页标注；token 真算（usage 流结束更新）并展示成本。
- 追问上限 5 轮；逐环节降级矩阵。
- **每个关键阶段有测试**。

**Non-Goals:**
- 不做教育领域内容检索（知识点/题库/答疑）——语料是本项目的方案文档，不是教育数据。
- 不接真实角色体系——权限为页面权限标签 + demo 学生=最高权限，前置校验机制保留。
- 不做图谱检索召回——本系统召回对象是文档（向量+BM25），不接 Neo4j。
- 不做真 mermaid 动态生成——预置为主，动态生成仅兜底。
- 不做生产级部署与鉴权扩展——内部演示系统，Java 桥侧调用沿用 `x-internal-token`。

## Decisions

### D1. 文档准备 = 自己完善文档，再切片
语雀空模板/多版本矛盾/未发布草稿导致语料不可直接用。**处理**：每模块产出一份「完善版设计文档」，以代码注释/git/OpenSpec/语雀有内容的方案设计为事实源，人工补全。完善文档 8 节即切片单元：

```
## 1. 产品定位    ## 2. 核心功能    ## 3. 为什么这么设计
## 4. 数据流转(含预置mermaid)  ## 5. 技术实现    ## 6. 关键坑与解法
## 7. 数据规模与指标  ## 8. 权限与边界
```
- **为什么**：语料质量决定 RAG 上限；完善文档同时是切片单元、源文档池、索引层 QA 的来源。
- **备选**：直接全文抓语雀 → 质量不可控、答案互相矛盾，弃。

### D2. 双池检索（索引层池 + 源文档池）
- **索引层池**：每页 5~8 条 QA 条目（`问题 + 答案要点 + 引用`），doc_type=`qa`。引导问题命中它 → 答案可控、上下文小、便宜。
- **源文档池**：完善文档全文，doc_type=`source`。自由问题命中它 → 纯 RAG 真发挥。
- 两池同写一个 COS 索引，用 `doc_type` metadata 区分。
- **为什么**：引导问题要稳定可控，自由问题要证明 RAG——一池满足不了两个目标。
- **备选**：只有索引层 → 自由问题全变边界回答，RAG 能力没证据；只有源文档池 → 引导问题不可控易翻车。

### D3. 页面锚定 + 引导问题变体文案
- 前端主动传 `page`；页面模式下检索限定该页（`page` 过滤），全局模式不限。
- UI 引导问题 = 索引层规范问题的**变体写法**（例：UI"你们为什么拆成三段" vs 索引"为什么拆 decide/generate/question-understand"），强制检索真实发生，避免"点按钮=预定答案"。
- **为什么**：页面锚定提升检索确定性、可解释；变体文案让 RAG 检索被真实执行、可演示。

### D4. 两道门
- **权限门（前置）**：进会话时校验「当前页权限点 vs 角色」。demo 学生账号=最高权限，机制保留可切换演示。无权限 → 权限提示，不检索不生成。
- **范围门（后置）**：检索置信度阈值——索引层命中 > 0.75、源文档池 > 0.5；低于 → 边界回答（预写话术），不硬编。
- **为什么**：权限门过滤"能不能看"，范围门过滤"有没有覆盖"。**范围门 = 检索置信度**，语料即边界，无需单独分类器。
- **备选**：单独"是否覆盖"分类器 → 多一个易错组件，弃。

### D5. 打分
`score = similarity × 问题类型匹配 × 页面锚定加权`。
- 索引层池 top-K=1~3，源文档池 top-K=3~5。
- 阈值：索引层 0.75 / 源文档池 0.5。
- **为什么**：小语料不需要重排模型；多信号加权 + 阈值已足够区分命中与超范围。

### D6. 生成：doubao 流式 + 强制引用 + 按页标注
- 复用 `ark_stream.py` 直连方舟流式；**强制引用**：prompt 要求只基于检索上下文回答、每条引用标注来源页、无引用不输出正文。
- 跨页答案按页分段引用（`知识图谱页§3 … AI答疑页§5 …`）。
- **为什么**：强制引用同时堵死幻觉和跑题（"检索不到就边界拒绝，没引用就不输出正文"）。
- **备选**：预写完整答案直发 → RAG 沦为查表，弃。

### D7. token 真算（usage）+ 成本展示
- **改 `ark_stream.py`**：请求体加 `stream_options: {"include_usage": true}`，解析结尾 usage chunk（choices 空、顶层带 usage）→ 流结束更新本轮 prompt/completion。
- **改 `vector_store.py`**：`embed()` 抓 `resp.usage.total_tokens`，embedding tokens 单列。
- 展示：每轮 prompt/completion + 会话累计 + ¥ 换算（doubao 单价）；embedding 单列。
- **为什么**：成本是 RAG 最大实战痛点；真算 + 展示 = 成本控制叙事。流式 usage 只在结尾返回 → "结束后更新"。

### D8. 流程图：预置为主
- 每模块完善文档第 4 节含**预置 mermaid 数据流图**；命中"数据流"类问题 → 检索到该节 → 前端直接渲染 mermaid。
- 未预置才动态生成兜底（备选通道，演示不依赖）。
- **为什么**：demo 可靠性优先；预置零渲染风险。

### D9. 会话与追问限制
- 页面锚定会话：追问默认锁定当前页；跨页由全局模式处理。
- 追问上限 **5 轮/会话**，超限提示"信息较多，请开启新一轮对话"（文案预写）。
- **为什么**：上下文不无限膨胀 = 成本可控 + 节奏可控。

### D10. 降级矩阵 + 重试策略
| 环节 | 故障 | 重试 | 降级到 | 最差兜底 |
|------|------|------|--------|---------|
| query 理解 | embedding API 挂/超时 | 否 | 关键词/规则(jieba) | 提示换说法 |
| 检索(COS) | 查询失败/超时/索引缺失 | 是, 短超时重试1~2次 | 关键词检索兜底 | 边界话术 |
| 打分/范围门 | 全低于阈值 | — | 边界回答 | 同上 |
| 生成(doubao) | 失败/限流/流断 | 否(流已起) | 展示召回原文 | 预写答案卡片 |
| 展示 | mermaid 渲染失败 | 否 | 文本/预置图片 | 纯文字答案 |
- **为什么**：复用既有失败语义模式（错误冒泡 / 吞异常降级 / 关 SDK 重试 / 20s 超时）。**预写答案 = 天然兜底**：LLM 挂也能答。
- 超时：检索链 < 2s，生成流 < 15s，超时即降级。

### D11. demo 可靠性：COS + 预建索引 + 本地兜底
- 用 COS 向量桶（生产链路叙事），但**demo 前预建索引**（避开 10s 异步写后不可即查）。
- 保留本地索引兜底路径（同接口抽象），断网时降级到本地。

## Risks / Trade-offs

- [COS 网络依赖] demo 现场断网/超时 → 本地索引兜底 + 降级矩阵真跑通
- [语料完善工作量大] 每模块一份完善文档是主要成本 → 分模块推进，先用知识图谱做标本
- [引导问题预写=非纯RAG] 面试官可能质疑 → 定位明确"预写保证可控、检索证明能力"，自由问题走源文档池纯RAG
- [流式 usage 兼容性] 个别模型/接口不返回 usage → 降级为 tokenizer 估算 + 标注"估算"
- [多版本矛盾残留] 完善文档向代码事实对齐，冲突以代码为准
- [答案一致性] 跨页回答可能引用矛盾段落 → 完善文档第3/6节统一口径，prompt 强制按页引用

## Migration Plan

1. 先产出「知识图谱」完善文档作标本 → 确认格式 → 补其余 3 模块（+ RAG 功能点文档）。
2. 离线脚本：完善文档 → 切片 + metadata → embedding → COS 建 rag-index（`--clear` 幂等）。
3. 在线链路分阶段：召回 → 打分/范围门 → 生成/引用 → 权限门 → 降级 → token 展示。
4. 回滚：新增 `/api/rag/*` 独立路由，不影响既有 tutoring 路径；ark_stream 改动对既有调用透明（多返回 usage，不改变流式语义）。
