## 一、业务描述与业务场景

索引与向量库层是 RAG 语料「切片 → 可检索」的中间件: 把 `scripts/rag/data/*.jsonl` 的语料块做 embedding, 写入腾讯云 COS 向量索引; 查询时按模块过滤召回 Top-K 相似块, 供 RRF 融合 + 权威度加权 → doubao 生成。

场景边界:
- **双池**: 全量池 `rag-full`(整篇文档, 管整体问题) + 切片池 `rag-slice`(细节块, 管追问/细节)。两个池**共用同一向量桶 `rag-1318177119`, 各自独立索引**(settings.py:92 注释、settings.py:99-105 `COS_VECTORS_INDEXES`)。
- **多模块共用索引**: ai-tutoring/question-analysis(已入) 与 knowledge-graph/rag-system(锚点闭集已定但语料未建) 同写 rag-full/rag-slice 索引, **靠 metadata.module 标签 + query 侧 Filter 过滤隔离**(build_index.py:5、query.py:35-40、query.py:458-465)。
- **普通桶放原文**: 源语料 + 切片视图上传 COS 普通桶 `ai-edu-1318177119`(upload_cos.py:36-37、settings.py:114), 前端「查看原文」走 `/api/rag/source/{key}` 读该桶(api/rag.py:57-72)。

## 三、高层业务调用链

```
切片/整篇 .md
  → slice_corpus.py 生成 jsonl  (scripts/rag/data/rag_slices*.jsonl, 每行 {text, summary, tags})
  → build_index.py 阶段3: 逐块 embed → put_vectors(批20) → rag-1318177119/rag-full|rag-slice
      ├ 切片池每块写 2 key: {key}-c = embed(summary+"\n"+text) / {key}-q = embed(summary)   (build_index.py:166-175)
      └ 全量池写 1 key:  ≤5000 字符 embed(summary+全文), 超限只 embed(summary)               (build_index.py:176-183)
  → upload_cos.py 阶段2: 读 `> COS路径:` 头 → put_object → ai-edu-1318177119/rag-source|rag-slices/<模块>/...
  → 查询时 query.py:
      retrieve_vector(question, vector_type, module) → build_filter({"module": {"$eq": module}}) → query_vector(Filter=...)   (query.py:458-479)
      retrieve_dual = 全量池单向量 + 切片池双向量(-c/-q 按 key 后缀拆两路) + 本地 BM25       (query.py:507-526)
      orchestrate = RRF(四路) × authority × 节锚定加权 → top-K                                   (query.py:620-686)
  → generate(doubao)  +  text 反查: metadata 不含 text, 全文/全量摘要经 key 反查本地 jsonl  (build_index.py:14, query.py:584-606)
```

## 四、代码事实

### 4.1 索引构建 build_index.py(198 行)

1. **双池定义**: `POOLS = {"full": {vector_type: "rag-full", data: "rag_slices_full.jsonl"}, "slice": {vector_type: "rag-slice", data: "rag_slices.jsonl"}}`(build_index.py:42-45)。`vector_type` = 池前缀(rag-full/rag-slice), 决定桶+索引路由。
2. **模块→jsonl 映射**: `MODULE_DATA = {"ai-tutoring": {...}, "question-analysis": {...}}`(build_index.py:47-51)。**仅 2 个模块, 无 rag-system/knowledge-graph**。
3. **CLI**: `--pool full|slice`(必填)、`--module`(默认 ai-tutoring)、`--clear`(清空该池索引后重写)(build_index.py:101-107)。**支持 --module/--pool/--clear 三参数**。
4. **增量并入**: 不带 `--clear` 时, 直接读 jsonl 全部块 → put_vectors 覆盖写(同 key upsert); **没有按块增量插入的 diff 逻辑**——"增量"实际是"重读当前 jsonl 全量重写", 旧 key 若已不在 jsonl 中不会被删(除非 --clear 先清池)(build_index.py:128-131、185-190)。
5. **`--clear` 清的是整个池, 不分模块**: `list_all_keys` 用 list_vectors 分页枚举该索引**全部** key(仅 key)(build_index.py:76-86), `clear_index` 分批 delete 全删(build_index.py:89-97)。即 `--clear --module rag-system` 会连 ai-tutoring/question-analysis 在该池的向量一起删——多模块共池时须注意。
6. **key 规则**: `make_key = "{vector_type}/{module}/{file}/{anchor}#{idx}"`(build_index.py:59-65)。2026-08-27 加 module 段: 跨模块同名文件(如两模块完善文档 01-08)键含 module 才不冲突覆盖。
7. **version**: `YYYY-MM-DD-<全块text sha1[:6]>` 走 metadata 不走索引名(build_index.py:68-73)。
8. **索引预建**: 脚本不建索引, `get_index` 校验缺失则报错退出, 要求控制台先建 **768/float32/cosine**(build_index.py:117-123)。
9. **metadata 10 字段**: version/module/category/source/authority/section/file/file_path/anchor/summary(build_index.py:143-157)。doc_type 与 module 同值冗余已去掉(2026-08-26)。
10. **metadata.summary 截断但 embedding 用全量**: 按「非 summary 值字节 + 250B 安全量」预算 ≤2048B 截断 summary(build_index.py:158-165); embedding 仍用全量 b["summary"](data 侧), 全文/全量摘要经 key 反查 jsonl。
11. **切片池双向量**(task #78): 每块写 2 key, `-c`=embed(summary+"\n"+text) 内容路, `-q`=embed(summary) 问题路, 同索引 rag-slice, 不加 metadata(build_index.py:166-175)。
12. **全量池条件式 embed**(2026-08-27 改): `full_text = summary+"\n"+text`; `len≤5000(FULL_EMBED_MAX_CHARS)` → embed(full_text), 超限只 embed(summary)(build_index.py:176-183)。防大语雀(10~12K 字符)超 8192 token 被 dashscope 静默截断。
13. **写入批处理**: put_vectors 每批 20(BATCH_PUT), 写后 sleep 10s 等异步生效(build_index.py:185-190)。
14. **语料留本地**: 向量桶 role mode 不收普通对象, put_object 被拒(AccessDenied), jsonl 留本地供 BM25/反查(build_index.py:192-194)。

### 4.2 原文上传 upload_cos.py(151 行)

1. **普通桶**: `COS_OBJ_BUCKET` 默认 "ai-edu-1318177119", region ap-guangzhou(upload_cos.py:36-37)。**凭据复用 COS_VECTORS_SECRET_ID/KEY**(upload_cos.py:46-47)——向量桶子账号可写该普通桶。
2. **key 来源 = 文件头标注**: `HEADER_RE = ^\s*>\s*COS路径[:：]\s*(.+?)\s*$`, 扫文件头 20 行(upload_cos.py:38-39、51-57)。**无 `> COS路径:` 头的 .md 不上传, 自动跳过**。
3. **校验**: key 含 `\`/前导 `/`、超 850B、与已有 key 冲突 → 剔除并告警(upload_cos.py:79-93)。
4. **CLI**: `--root`(默认 settings.RAG_CORPUS_DIR)/`--dry-run`/`--skip-existing`(head_object 判断跳过)(upload_cos.py:96-147)。
5. **幂等**: 同 key put_object 覆盖; ContentType=text/markdown(upload_cos.py:41、141)。

### 4.3 查询侧 query.py(823 行, 索引/元数据相关)

1. **语料 jsonl 路径**: `DATA_DIR = scripts/rag/data`; `DATA = rag_slices.jsonl`(兼容旧引用=ai-tutoring 切片池)、`DATA_FULL = rag_slices_full.jsonl`(ai-tutoring 全量池)(query.py:30-34)。
2. **多模块 jsonl**: `MODULE_DATA = {"ai-tutoring": ("rag_slices.jsonl","rag_slices_full.jsonl"), "question-analysis": ("rag_slices-question-analysis.jsonl","rag_slices_full-question-analysis.jsonl")}`(query.py:37-40)。**仅 2 模块**。`_load_all_blocks` 全读 MODULE_DATA 全部模块(缺失文件跳过容错), 否则 qa 向量命中后 keymap/BM25 无 qa 块被丢弃(query.py:436-449)。
3. **模块锚点闭集**: `MODULE_ANCHORS = ("ai-tutoring", "knowledge-graph", "question-analysis", "rag-system")`(query.py:68)——rag-system **在锚点闭集内**但无语料。
4. **DEFAULT_MODULE**: `DEFAULT_MODULE = "rag-system"`(query.py:455)——**未传 module 时的默认 Filter 指向 rag-system(当前无数据 → 向量 0 命中)**。
5. **module 过滤实现**: `build_filter(module, categories) → {"module": {"$eq": module or DEFAULT_MODULE}}`(query.py:458-465)。2026-08-26 决策: **查询不再按 categories 过滤**(LLM 判类别不准误伤), categories 参数仅作签名兼容。
6. **向量召回单元**: `retrieve_vector` → `query_vector(question, top_k, vector_type, filter_)`(query.py:468-484)。confidence = 1 - 平均 cosine distance(COS distance 越小越相似)。
7. **双池召回**: `retrieve_dual` = 全量池向量(单向量) + 切片池向量(切片池双向量 top_k=VEC_K+2 补偿同块双记录占位) + BM25(本地 jsonl, corpus=模块 anchor 时 select_corpus 过滤)(query.py:507-526)。
8. **双向量拆分**: `_split_roles` 按 key 后缀拆 -c(内容路)/-q(问题路), 归一化 key 后两路各自贡献 RRF(query.py:487-504)。
9. **key 反查**: `_key_of = "rag-{tags.pool}/{module}/{file}/{anchor}#{_idx}"` 与 build_index 同规则(query.py:584-592); `_assign_idx` 为块补 _idx 建 keymap(query.py:595-606)。
10. **编排**: RRF(RRF_K=60) × authority × 节锚定加权(1.5)→ top-K(query.py:620-686)。不做类别过滤/提权(1.13.2)。
11. **BM25 纯本地**: jieba 分词 + Okapi BM25(k1=1.5, b=0.75), 不依赖向量, 断电断网可用(query.py:529-578)。

### 4.4 向量基座 vector_store.py

1. **embedding 模型/维度**: `_EMBEDDING_MODEL = "text-embedding-v3"`, `_EMBEDDING_DIMENSIONS = 768`(显式, 模型默认 1024, 必须与索引维度一致; 索引建好不可改)(vector_store.py:26-28)。base = dashscope OpenAI 兼容 `https://dashscope.aliyuncs.com/compatible-mode/v1`, 复用 DASHSCOPE_API_KEY(vector_store.py:29、93)。
2. **相似度度量**: cosine。索引控制台建 768/float32/cosine(build_index.py:121-122); vector_store 头注释 spike 实测 768 维对齐 / query 返回字段 vectors / cosine distance 越小越相似(vector_store.py:12-13)。
3. **路由**: `_resolve_bucket_index(vector_type)`: `rag*`(rag/rag-full/rag-slice) → `COS_VECTORS_RAG_BUCKET`(rag-1318177119), 其余(topic) → `COS_VECTORS_BUCKET`; 未知 vector_type → ValueError(vector_store.py:106-121)。
4. **query_vector**: embed → `query_vectors(QueryVector={"float32": vector}, TopK, ReturnMetaData=True, ReturnDistance=True, Filter=可选)`(vector_store.py:150-179)。
5. **客户端**: CosVectorsClient(向量桶) 与 CosS3Client(普通桶) 均单例懒加载, 凭据复用 COS_VECTORS_*(vector_store.py:38-84)。

4. `COS_OBJ_BUCKET = "ai-edu-1318177119"`、`COS_OBJ_REGION = "ap-guangzhou"`(settings.py:114-115)。
5. 超时: `RAG_RECALL_TIMEOUT=2.0`(向量路)、`RAG_GEN_TIMEOUT=8.0`(生成)(settings.py:119-120)。

## 六、隐性坑

1. **`--clear` 清整个池不分模块**: 多模块共池(rag-full/rag-slice)下, `--clear --module rag-system` 会把该池内 ai-tutoring/question-analysis 向量一起删光, 需重灌全部模块(build_index.py:76-97)。
2. **`DEFAULT_MODULE="rag-system"` 指向无数据模块**: query.py:455 未传 module 时 Filter 筛 rag-system, 但 rag-system 无语料 → 向量召回 0 命中。当前 API 路径 current_project 默认 "ai-tutoring" 兜底才不触发(intent 签名 query.py:294), 是潜在隐患。
3. **metadata.summary 截断 ≠ embedding 摘要**: 入索引的 metadata.summary 被 2048B 预算截断, 但向量仍 embed 全量 summary; 全文/全量摘要只能经 key 反查 jsonl——**反查失败(本地 jsonl 缺块)则全文丢失**(build_index.py:158-165、query.py:584-606)。
4. **COS 索引维度建好不可改**: 索引控制台建 768/float32/cosine, embedding 显式 768 强制一致, 维度不匹配抛异常(vector_store.py:28、100-102)。
5. **put 后 10s 才可查**: COS 向量索引异步生效, 写完立即 query 会 miss(build_index.py:55、vector_store.py:127)。
6. **脚本不建索引**: 索引须控制台预建, get_index 缺失直接 sys.exit(build_index.py:117-123)。
7. **向量桶 role mode 不收普通对象**: 语料 jsonl 不能传向量桶, 只能留本地/传普通桶(build_index.py:192-194)。
8. **增量写入不是真增量**: 不带 --clear 重跑 = 全量 jsonl upsert, 已删块的旧 key 残留(除非 --clear 清池)。
9. **key 跨模块冲突**: 若无 module 段(2026-08-27 前), 两模块同名文件(完善文档 01-08)会互相覆盖——现 key 含 module 段已防(build_index.py:60-64)。
10. **查询侧 categories 不再过滤**: 2026-08-26 决策去掉类别过滤(误伤), 若旧认知"按类别筛"会得到空结果(query.py:461-463)。

## 七、设计要点

1. **双池同桶异索引**: rag-full(整篇 23 块) 与 rag-slice(切片 294 块) 同一桶 rag-1318177119、两个物理索引, 与 topic(题型聚集) 桶隔离, 重建 rag-slice 不碰 topic 生产查询(vector_store.py:109-110、settings.py:92-105)。
2. **多模块靠 module 标签 + Filter 隔离**: 向量 key 带 module 段、metadata.module 打标、query 侧 build_filter `{"module": {"$eq": ...}}` 下推到 COS 向量层过滤, 防其他模块相似向量挤占 top-k(query.py:458-465、vector_store.py:154-155)。
3. **切片池双向量 = 语义双路召回**: -c 内容路 embed(summary+text)、-q 问题路 embed(summary)——query 是问题形态, 匹配"问题"侧更准; 同块两路命中各贡献 RRF 互补(task #78, build_index.py:166-175、query.py:487-504)。
4. **全量池条件式 embed**: 小文件(≤5000 字符)全文进向量可检索(完善文档 1.0 主答案/代码 0.8), 大语雀只 embed(summary) 摘要粗召回防 8192 token 静默截断(build_index.py:176-183)。
5. **version 走 metadata 支持回退**: `YYYY-MM-DD-sha1[:6]`, 语料变→版本变→可回退, 不走索引名(build_index.py:68-73)。
6. **BM25 本地兜底**: 纯本地 jsonl 全文打分, 断电/断网仍可用; 向量路失败 → API 降级纯 BM25(api/rag.py:96-106)。
7. **双池 + 多模块统一 key 规则**: build_index 的 make_key 与 query 的 _key_of 同规则({池}/{module}/{file}/{anchor}#{idx}), 保证向量命中后能反查本地 jsonl 拿全文。
