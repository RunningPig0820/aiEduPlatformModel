## 业务描述与业务场景

**业务描述**：RAG 项目介绍助手的"引导问题"机制——每个功能页进页面/每次问答完成后，前端展示可点击的候选问题，引导用户围绕项目介绍/操作流程/数据关联/开发难点四个主方向追问，并下沉 RAG 引擎/链路/契约的桥接题。核心约束：**引导不能自由发挥**——开始引导 guide / 结束建议 done.suggestions 都必须围绕底座池（GUIDE_POOL）取原题，保证池内问题都能被语料答出（guide_pool.py:8-9）。

**业务场景**：
- 学生/面试官进入某功能页（当前页锚点 current_project），第一屏展示 3 条入门级引导题（"能不能先介绍一下RAG项目？"级别），点击即发起问答
- 每次问答完成后，done 事件携带 2~3 条池内原题作为"结束建议"，引导继续追问（必含 ≥1 条 RAG 桥接题）
- 用户发"你好"问候时，0 token 返回固定欢迎语 + 入口池建议（不 recall 不 generate）
- 多模块切换（AI答疑/知识图谱/题型分析/RAG项目）时，引导语随 current_project 走各自模块池

## 职责

**职责**：把每模块"引导问题.md/问题列表.md"的编号问题沉淀成 Python 静态底座池（GUIDE_POOL），并向前端/白盒链路提供 0 token 的引导候选（开始引导 + 结束建议 + 问候分支）。
**不做什么**：不做 LLM 生成引导语（0 token，llm 参数保留签名兼容但不再调用）；引导问题纯问题不切片进全量池（切片清单"7. 引导问题/问题列表.md 问题进 guide_pool，纯问题不切片"）；不做入口引导问题的语料可答性自检（可答性由评测集验证，test_guide_pool.py:64 注释）。
**分工要点**：
- **guide_pool.py**：引导底座池唯一事实源——GUIDE_POOL 数据结构、pool_for 兜底、scope_questions 去重、entry_for 入口模板（guide_pool.py:27-370）
- **rag_assistant.py**：API 层——GET /guide 白盒透传 current_project（rag_assistant.py:144-152）
- **assistant.py**：编排层——guide() 入口池 3 条、gen_suggestions() 结束建议池内原题、问候分支 welcome（assistant.py:347-355, 528-540, 580-586）
- **query.py**：模块锚点闭集 MODULE_ANCHORS 四模块（含 rag-system），引导题点击后走正常检索链路（query.py:68）

## 代码事实

### GUIDE_POOL 结构（`core/rag/guide_pool.py`）

- 数据结构：`GUIDE_POOL: Dict[str, Dict[str, List[str]]] = {模块id: {direction: [问题]}}`（guide_pool.py:27）
- 每题只落一个主方向（intro/operation/data_relation/difficulty）；rag 组是 RAG 桥接子集，可与主方向重复，scope 去重（guide_pool.py:11-14）
- 方向 → 引导问题.md 节映射（guide_pool.py:17-22）：intro=项目介绍 / operation=操作流程+业务流程 / data_relation=数据关联+数据存储 / difficulty=开发难点+架构设计+业务视角+稳定性+未来演进 / rag=从以上挑桥接 RAG 引擎/链路/契约的（完整调用链路/SSE时序/和普通RAG本质区别/ActionMeta契约/不直接写Neo4j）
- 主方向闭集：`DIRECTIONS = ("intro", "operation", "data_relation", "difficulty")`（guide_pool.py:316）
- 兜底：`FALLBACK_MODULE = "ai-tutoring"`（guide_pool.py:313）；`pool_for(module)` 未知/缺省 → FALLBACK 池（guide_pool.py:319-321）

### scope 去重逻辑（`guide_pool.scope_questions`）

- `scope_questions(module, directions=())`：`directions` 非空时限定方向；空 → 主方向闭集。遍历 directions 的每个问题的 q 加入 `seen` set，**去重保序**（guide_pool.py:324-334）
- rag 组与其他组重复 → 去重后不新增数量（test_guide_pool.py:30-33 `test_rag_is_subset` 断言 rag ⊆ 主方向池）
- **注意**：scope_questions 是"全量去重视图"，**当前生产链路 guide()/gen_suggestions() 并不调用它**——guide() 只从入口池抽，gen_suggestions 靠 `_pool_suggestions` 内部 picks 去重（assistant.py:340-343）。scope_questions 仅用于测试断言（test_guide_pool.py）与 suggestions 测试的"不超池"校验（test_assistant_suggestions.py:39）。

### 引导问题 API（`api/rag_assistant.py` + `assistant.guide`）

| 方法 | 路径 | 说明 | 证据 |

- **GET /guide 白盒透传**：`current_project` 为可选 query 参数，后端 `?current_project=` 透传；"每功能引导问题不同，进页面/切换功能以当前功能为准；缺省/未知 → FALLBACK_MODULE(ai-tutoring)"（rag_assistant.py:144-152）。`verify_internal_token` 鉴权（rag_assistant.py:151）。
- **assistant.guide()** 返回 shape：`{"suggestions": [{"title", "direction"}]}`，direction 值随池方向：intro/operation/data_relation/difficulty/rag（assistant.py:524-525, 528-540）。

### 引导问题与查询链路衔接（索引层入口）

- **引导问题是"索引层入口"**：前端引导候选 → 点击变成普通问题 → `POST /ask` → `pipeline_events` 白盒链路（assistant.py:543-652）。事件时序（冻结）：`intent → (greeting|clarify|switch) → rewrite → rerank → (boundary|token*) → done`（assistant.py:549-560）。
- 引导题在链路中的落点：intent 模块锚定（MODULE_ANCHORS 四模块，query.py:68；rag-system 关键词 rag/检索/召回/重排/向量/bm25/rrf/多路/知识库，query.py:73）→ recall 双池三路（全量向量 rag-full + 切片向量 rag-slice 各 2s 超时降级 + BM25，anchor 选池，assistant.py:91-133）→ rerank 精排 Top-K=3（assistant.py:139-155）→ generate（assistant.py:411-477）。
- **池内原题直接返回，不做 LLM 改编**：assistant.py:326-331 注释明确"用户实测反馈：LLM 改编'换提问方法'会偏离池内范围——如把池内'题目记录/错误事件/掌握度三张表关系'编成'题目数据怎么和向量索引关联'（引入池外概念'向量索引'），新问题没对应切片 → 学生点了匹配不到答案（问题6 翻版）"。结论：结束引导直接返回池内原题（0 token，100% 可答），"双向量 -q 问题路对池内原题命中 sim~0.99"。
- **结束建议 gen_suggestions**（assistant.py:347-355）：`module = anchor if anchor in MODULE_ANCHORS else FALLBACK`；`_pool_suggestions(module)` 必含 ≥1 条 rag 组 + 其余主方向随机，返回 2~3 条去重（assistant.py:334-344）。`llm` 参数保留签名兼容但不再调用（test_assistant_suggestions.py:53-60）。
- **问候分支**（assistant.py:358-380, 580-586）：`is_greeting` 关键词预检（你好/您好/hello/hi/哈喽/嗨/hey/在吗，短句 ≤8 字才命中防误杀，assistant.py:361, 366-372）；命中 → 0 token 直接 done，answer=固定 WELCOME_MSG + `_spread_pool_suggestions(module)` 从入口池抽入门级题（assistant.py:375-380, 583-585）。
- **guide 与 ask 的 current_project 缺省不一致（）**：guide 接口缺省/未知 → FALLBACK_MODULE=**ai-tutoring**（rag_assistant.py:148-149）；ask 请求模型 `current_project` 默认值 = **rag-system**（"缺省=rag-system（对齐后端 api.md，会话入口默认聊 RAG 项目）"，models/rag_assistant.py:18-19）。

### rag-system 引导问题现状（对账重点）

- **GUIDE_POOL 无 rag-system 池**（guide_pool.py:309 注释待加）。current_project=rag-system 时的实际行为：
  - `pool_for("rag-system")` → `GUIDE_POOL.get("rag-system", GUIDE_POOL["ai-tutoring"])` → 取 **ai-tutoring 池**（guide_pool.py:321）
  - guide() 判定 module="rag-system"（在 MODULE_ANCHORS 内，assistant.py:535-536），`entry_for("rag-system")` → 用 ai-tutoring 池 + `_MODULE_ZH["rag-system"]="RAG项目"` 模板生成 4 条入口题（guide_pool.py:369-370, 354）
  - 结束建议 gen_suggestions(answer, anchor="rag-system") → `_pool_suggestions("rag-system")` → ai-tutoring 池（assistant.py:353-355）

## 隐性坑与注意事项

- **rag-system 引导题未入池（最大坑）**：rag-system 页面引导语实际是 ai-tutoring 池的题（只是入口模板名换成了"RAG项目"）。入口模板题（"RAG项目是干什么的？"）点击后 anchor 判定、检索走 rag-system 语料池，但池内没有 rag-system 专属引导题，结束建议也是 ai-tutoring 的题——在 rag-system 问题列表生成并同步 GUIDE_POOL 前，引导题与语料池存在错位风险（guide_pool.py:309 + 处理方案 readme.md:3）。
- **guide 缺省 vs ask 缺省不一致**：guide 缺省/未知 → ai-tutoring（rag_assistant.py:148-149）；ask 请求 current_project 默认 rag-system（models/rag_assistant.py:18-19）。前端不传 current_project 时，进页面引导给 ai-tutoring 题，点击却默认走 rag-system 锚点——两入口缺省不同，易造成"引导题与检索池不匹配"。
- **入口模板题的"可答性"依赖语料**：入口模板是通用句式 + 模块中文名，guide_pool.py:340-341 注释记录 2026-08-26 删了 rag 入口题"这个功能的底层是怎么实现的?"——太泛，"底层"同时匹配架构/ActionMeta/召回等一堆块，没有明确答案，检索答非所问；入口只保留可答的具体功能题。
- **LLM 改编引导语是已知翻车点**：曾用 LLM 改编"换提问方法"导致新问题引入池外概念、匹配不到答案（问题6 翻版），已改为池内原题直出（assistant.py:326-331）。
- **scope_questions 不是生产调用路径**：全量去重视图仅测试用，生产 guide()/gen_suggestions() 走入口池/抽样，不经过 scope_questions（assistant.py:334-344, 537-539）。
- **问候关键词短句门槛防误杀**：`is_greeting` 限定 0 < len ≤ 8，避免"你好，请介绍一下这个项目"（含问候词但语义是真实提问）被误判为问候而吞掉真实检索（assistant.py:366-372）。
- **guide() 的 direction 值已替换旧枚举**：旧 architecture/data_flow/evaluation 换成 intro/operation/data_relation/difficulty/rag，后端联调清单已记录——Java/前端如按旧值硬编码需适配（assistant.py:524-525）。

## 设计要点

- **引导静态池 0 token**：开始引导 guide / 结束建议 done.suggestions 都从底座池取原题，严禁 LLM 生成（降本 + 保证可答）。底座池存在的意义 = 对齐语料可答（guide_pool.py:8-15, assistant.py:348-351）。
- **入口引导 vs 结束引导分层**：入口给入门级简单题（用户还不知道怎么用，第一屏，如"能不能先介绍一下X？"）；难题留给结束建议（用户问过一轮有上下文）——"难题留给结束建议"，入口题短句式、无技术难点词（assistant.py:521-523, test_guide_pool.py:74-79）。
- **rag 组是 RAG 桥接子集**：与其他主方向可重复、scope 去重；但 gen_suggestions 强制必含 ≥1 条 rag 组，保证每次结束引导都留一条 RAG 引擎/链路/契约桥接题（assistant.py:334-344, C5 测试 test_assistant_suggestions.py:41-45）。
- **多模块通用不写死**：入口引导用通用模板 + 模块中文名动态替换，避免新模块复制"AI答疑"字样（驴唇不对马嘴）；每模块可加 entry 组定制入口重点（guide_pool.py:125-127, 342-347, 358-370）。
- **引导题可答性由"池内原题 + 双向量 -q 问题路"双保险**：池内原题 100% 有切片；点击后经 -q 问题路命中 sim~0.99（assistant.py:330-331）。
