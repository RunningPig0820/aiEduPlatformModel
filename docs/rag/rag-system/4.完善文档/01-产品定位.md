## 为什么（语雀/动机）

面试/汇报时要**把项目讲清楚 + 证明 RAG 能力**：项目模块多（AI答疑/知识图谱/题型分析/组织中心），人讲会乱会漏；"我会 RAG"的口头宣称又缺可演示证据。早期想过知识点/题型 RAG，但无题库做不了闭环，遂改做**项目介绍 RAG**——以自身方案/设计文档为自包含语料，demo 随时能跑。

**核心定位**：不是纯 RAG（丢一堆文档就能问），而是"**产品 = 讲清每个页面，RAG = 证明能力的引擎**"；RAG 本身也作为项目一个功能点被介绍——**一鱼两吃，用系统介绍系统**。

## 怎么设计（方案）

三层价值：

1. **语料层（产品 = 讲清每个页面）**：每模块产出完善文档 8 节（定位→功能→为什么→数据流→技术→坑→指标→权限），8 节即切片单元、即面试问法清单——语料质量决定 RAG 上限。
2. **检索层（RAG = 证明能力的引擎）**：双池检索（索引层预写 QA 可控 + 源文档池纯 RAG 证据）+ 页面锚定 + 两道门（权限门"能不能看" + 范围门"有没有覆盖"）+ 生成强制引用。
3. **证明层（评测 agent）**：hit@k + 答案质量判分 + 版本对比，走真实检索不降级，用数据证明有效。

答案形态走 **B 路线（要点 + 生成）**：索引层存要点 + 引用，LLM 实时组织语言——既证明 RAG 在动、又答案可控。

> 范围演进：08-21 曾覆盖 4 业务模块 + RAG 自身 → 08-25 spec 一度反转为"仅 RAG 项目、禁区拒答" → 最终定稿四模块全放行 + 范围门低置信唯一拒答。这一反转是理解本模块定位的关键。

## 落地真相（代码）

> **总翻转**：方案口径（doc_type 双池/前端传 page/权限门+范围门都在 Python 链）落地为：**双物理 COS 索引 rag-full+rag-slice + module 过滤、模块/节两级锚定（无 page）、权限门在 Java 网关（Python 无）**；范围门 0.75/0.5 只在白盒链路生效。

- **双池落地但形态演进**：rag-full（整篇 23 块）+ rag-slice（切片 294 块）两个物理索引，靠 metadata.module 隔离；metadata 无 doc_type（与 module 同值已删）。
- **页面锚定演进**：无 page 参数，改为模块级 current_project/anchor 过滤选池 + 节级 locked_sections 加权（×1.5）。
- **两道门落地**：权限门在 Java 网关（仅 STUDENT 放行、非学生 403、0 token）；范围门只在白盒 check_boundary 生效，旧 1.6C 端点只有空命中拒答。
- **证明层落地**：评测走真实检索不降级；hit@3 已演进为 HIT_K=5；判分 LLM 只报事实、分数规则硬算、编造封顶 3 分。当前基线（ai-tutoring 6 条）：hit@5=0.583 / 质量 3.833 / 成本 ¥0.018。
- **本模块现状**：rag-system 自身语料未入 MODULE_DATA → anchor=rag-system 的问题当前必然边界拒答（"语料整理中"的过渡态，语料就绪即自动可答）。
- **token 真算**：白盒流式已修（usage 结尾采集）；旧 1.6C / embedding 未采。

流水线现状（一鱼两吃闭环）：语料 → 对账 → 完善文档 → 切片 → 入 COS → 双池召回（rag-full + rag-slice 双向量 + BM25 RRF）→ 生成带引用 → 评测出报告。AI答疑 已全链路跑通，rag-system 整理中。

## 追问与防御

- **为什么不用现成 RAG 框架？** → 链路掌控：切片/索引/双池/打分/范围门/评测全自建，每一层为什么这么设计都讲得清；现成框架是黑盒，面试讲不出深度。RAGAS 全量明确 Non-Goal。
- **这系统给谁用？** → 面试/汇报人自己用；范围经反转定稿为四模块全放行 + 范围门（语料驱动、无禁区列表）。
- **评测集是你自己写的，凭什么算证明？** → 评测走真实检索原语不降级（向量挂了就暴露）；hit@k 是引用命中客观率（纯函数），判分只报事实、分数硬算、编造封顶 3 分，报告可版本对比。
- **"讲清每个页面"怎么落地？** → 每模块完善文档 8 节即切片单元、即问法清单；白盒 SSE 链路把"检索怎么工作"当场演示——一鱼两吃。
