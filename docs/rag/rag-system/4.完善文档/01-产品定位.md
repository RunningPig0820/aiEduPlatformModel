# 01 产品定位

> 模块=rag-system｜节=01｜问题表=项目介绍｜权威度=高（正文）

## 为什么（语雀/动机）

本项目要解决的问题：**面试/汇报时，把项目讲清楚 + 证明 RAG 能力**。项目有多个模块（AI答疑/知识图谱/题型知识点/组织中心），光靠人讲会乱、会漏、会答不上来。RAG 问答系统把每个模块整理成完善文档，面试官问什么，它答什么，还能展示"RAG 是怎么工作的"——**一鱼两吃**。

**核心定位**：不是纯 RAG（"丢一堆文档进去就能问"），而是"**产品 = 讲清每个页面，RAG = 证明能力的引擎**"。重点在语料整理（完善文档 8 节），RAG 是把它呈现出来的手段。

## 怎么设计（方案）

三层价值（对齐 project-intro-rag D1）：
1. **语料层**：逐个模块产出完善文档（8 节结构）→ 切片 → 索引。语料质量决定 RAG 上限。
2. **检索层**：双池（索引层 QA + 源文档池）+ 页面锚定 + 两道门。
3. **证明层**：评测 agent（hit@3 + 质量分 + 版本对比）——用数据证明有效。

## 落地真相（代码）

- 流水线：语料 → 对账 → 完善文档 8 节 → 切片(234 块 AI答疑) → 索引入 COS → 检索 → 生成 → 评测。
- 当前已跑通：AI答疑 模块全链路（切片/索引/检索/生成/评测），rag-system 模块语料整理中。
- 评测证据：hit@3=0.80、质量分 3.6/5、单次成本 ¥0.016、trace/报告可回溯可对比。

## 追问与防御

- **"为什么不用现成 RAG 框架？"** → 链路掌控：从切片、索引、双池、打分、到评测全自建，能讲清每一层为什么这么设计；现成框架(RAGAS 等)是黑盒，面试讲不出深度。
- **"这系统给谁用？"** → 面试/汇报人自己用：面试官点页面提问 → 系统答 + 展示证据（引用/指标）。
