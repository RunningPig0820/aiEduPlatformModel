## 为什么（语雀/动机）

面试/汇报要同时做到"把项目讲清楚 + 证明 RAG 能力"（D1）。纯 RAG 自由发挥不可控、面试现场易翻车；全预写答案又是查表，一问"检索体现在哪"就露怯。所以每个核心决策都是在**可控、可解释、可证明**三个目标间权衡，一条主线可贯穿全链路：

**答案要可控（不翻车）→ 但不能靠预写（否则检索是假的）→ 所以双池分层（引导走预写QA、自由问题走真RAG）→ 池多了要锚定（检索限定模块/节、可解释）→ 回答由"要点+LLM现组织"（提纲你定、措辞AI来）→ 引用用 LCS 硬匹配定真伪（纯函数可入评测）→ 两道门按最便宜顺序拦截（权限前置0token、范围门兜底）→ token 真算（成本叙事）→ 权限不在 Python 做（保无状态可扩展）→ 范围最终反转（语料即边界、数据驱动）**。面试官顺着这条线问，每一层都能讲出"为什么这么取舍"。

## 怎么设计（方案）

① **双池检索**：一池满足不了"引导可控+自由纯RAG"两个目标（D2/选型1）。只有索引层预写QA→自由问题全边界拒绝、RAG没证据；只有源文档全文→答案不可控、现场易翻车。定稿双池=索引层预写QA池（可控、便宜）+源文档池全文chunk（真发挥）。
② **页面锚定**：检索限定范围、确定性+可解释（D3/选型1）。"命中该页→在该页文档内检索"天然讲得清；引导问题用"变体文案"强制检索真实发生，防"点按钮=查表"质疑。
③ **两道门**：权限门前置"能不能看"+范围门后置"有没有覆盖"（D14/D16/选型6/7）。权限门从可信源取角色、非学生固定403、0token、严禁信body（前端可任意伪造role）；范围门=检索置信度（0.75/0.5）、语料即边界，不单独做覆盖分类器（多一易错组件、职责重叠）。
④ **答案B路线**：要点+生成，非全预写非纯检索（D6/选型2）。A全预写=查表露怯、C纯检索=不可控；B"提纲你定、措辞AI来"——要点/引用锁定范围、LLM现组织语言，检索→增强→生成全真实发生、看得见。
⑤ **is_quoted LCS 硬匹配**：引用判定不靠 LLM 自述（D12/选型5）。LLM自述与真实依据可能不一致、白盒露怯；LCS最长公共子串（8中/12英）纯函数硬匹配、可单测可入评测；8字窗口对单token不友好→生成完才匹配，故done后置补发。
⑥ **token 真算**：成本是 RAG 最大实战痛点（D19/选型9）。真算+展示=成本控制叙事，估算只能标"估算"；流式usage只在结尾返回（include_usage+结尾chunk）→"结束后更新"是踩过流式坑的加分细节。
⑦ **角色门在 Java**：Python 无状态、禁信 body（D14/选型16）。与tutoring gateway同构——Java是天然聚合点（token/trace/session每轮过手）；Python不自己认证、不碰会话，保住无状态边界、可水平扩展；body传role形同虚设，角色从可信session取。
⑧ **范围反转**：语料即边界、数据驱动（D7/选型8）。08-21四业务模块+RAG→08-25仅RAG项目（禁区拒答）→定稿四模块全放行+范围门低置信唯一拒答；学生场景只讲RAG自身，未来模块入库切片即自动可答，无禁区列表、无代码改动。

## 落地真相（代码）

> **总翻转**：方案 4 件事形态全部演进或反转——doc_type 双池→rag-full/rag-slice 双物理索引、page 参数→模块+节两层锚定、范围门 0.75/0.5 只在白盒 check_boundary 生效、引导"变体强制检索"→池内原题直出；权限门确在 Java。权威 1.0 以代码现状为准，面试按"演进后口径"讲。

- **双池**：形态演进——`rag-full`(23块)+`rag-slice`(294块)双物理COS索引、metadata无doc_type（build_index.py:145-157）、靠module Filter($eq)选池（query.py:458-465）。
- **页面锚定**：无page参数，模块级current_project/anchor过滤选池+节级locked_sections只加权×1.5；白盒链路写死locked_sections=[]节级被旁路（assistant.py:118）。
- **两道门**：权限门在Java（requireStudent→isStudent，非学生403、body role忽略、0trace），Python仅verify_internal_token；范围门只白盒check_boundary生效（0.75/0.5），1.6C端点仅空命中拒答（api/rag.py:120-126）。
- **答案B**：白盒stream_generate基于精排Top-K块现组织语言（assistant.py:411-477）；引导题=池内原题直出。
- **is_quoted**：lcs_quote_match连续≥8中/12英、done后补发、前端先灰后亮（assistant.py:189-238）。
- **token 真算**：白盒流式+评测真采；1.6C端点不采（api/rag.py:130）、embedding侧未抓。
- **角色门**：已在Java网关硬拦截，非STUDENT固定403、body传role忽略（RagAskCommand无role字段）。
- **范围反转**：代码走08-25定稿方向（四模块全放行、reject DTO保留不产出、唯一拒答=boundary low_confidence）；rag-system自身语料未入MODULE_DATA→anchor=rag-system当前必然边界拒答（语料整理中过渡态）。

## 追问与防御

- **为什么不用现成RAG框架（LangChain/LlamaIndex）？** → 链路全掌控+可解释——白盒要求意图/改写/召回/重排/token全阶段SSE透传，框架黑盒讲不出"为什么双池/两道门/阈值哪来"；小语料显式否决重排模型，自建轻量RRF即够（D9/D10/选型4）。
- **引导题池内原题直出，检索是假的吗？** → 自由问题走源文档池纯RAG真发挥；引导题点击仍走双向量-q问题路（sim~0.99），池内原题只为可答——LLM改编实测引入池外概念致新问题匹配不到切片，故反转（D23/选型12）。
- **范围门只在白盒生效，老1.6C会硬编吗？** → 会——1.6C无0.75/0.5阈值门，仅"hits空"粗粒度拒答（api/rag.py:120-126）；面试表述以"范围门仅白盒、白盒ask是生产主入口"为准。
- **为什么不接Neo4j做GraphRAG？** → 语料是项目方案文档不是图谱，召回对象是文档向量+BM25；图谱检索是本模块Non-Goal，知识图谱能力在知识图谱模块讲。
