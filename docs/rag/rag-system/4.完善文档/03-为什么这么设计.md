# 03 为什么这么设计

> 模块=rag-system｜节=03｜问题表=项目介绍/难点｜权威度=高（正文）

## 为什么（语雀/动机）

面试官会追问"你的 RAG 和普通 RAG 有什么不同？为什么这么设计？"——本节约回答"为什么做双池/两道门/页面锚定/评测"这些核心设计决策。

## 怎么设计（方案）——核心决策

**双池**（D2）：
- **为什么**：只有索引层 → 自由问题全变边界回答，RAG 能力没证据；只有源文档池 → 引导问题不可控易翻车。双池 = 可控 + 发挥兼得。
- **取舍**：引导问题走 QA 池（可控、便宜），自由问题走源文档池（真 RAG 发挥）。

**两道门**（D4）：
- **权限门**（前置）：过滤"能不能看"——未授权页直接拒。
- **范围门**（后置）：检索置信度阈值——索引层 0.75 / 源文档池 0.5；低于 → 边界回答（预写话术），不硬编。
- **为什么**：权限门管"能不能看"，范围门管"有没有覆盖"。**范围门 = 检索置信度**，语料即边界，无需单独分类器。

**页面锚定**（D3）：
- 前端传 `page` → 锁页检索；引导问题用**变体文案**（UI"你们为什么拆三段" vs 索引"为什么拆 decide/generate"），强制检索真实发生。
- **为什么**：提升检索确定性、可解释；避免"点按钮=预定答案"的质疑。

**打分**（D5）：`score = similarity × 问题类型匹配 × 页面锚定加权`，两池各自 top-K + 阈值。

## 落地真相（代码）

- AI答疑 实现的是"单池增强版"：双路召回(向量+BM25) + RRF × 权威度 × 锚定加权 + LLM 意图识别。
- 评测 agent 落地了 hit@3 + 质量分（确定性硬化：模型只报覆盖条数，代码硬算分数）。

## 追问与防御

- **"为什么不用现成 RAG 框架？"** → 链路掌控 + 可解释；框架黑盒讲不出"为什么双池/两道门"。
- **"打分阈值怎么定的？"** → 索引层要精(0.75，宁可少答别答错)，源文档池要宽(0.5，多捞再筛)——分别对应"引导可控"和"自由发挥"的定位。
- **"为什么不接 Neo4j 做 GraphRAG？"** → 语料是文档不是图谱；图谱能力在知识图谱页讲，RAG 专注文档问答。
