## 为什么（语雀/动机）

面试官会追问技术细节：语料怎么来、切片怎么切、embedding 用什么、向量桶怎么建、双池怎么隔离、打分怎么算、两道门在哪落地、token 怎么真算、评测怎么做。本节给每层的技术实现口径，作为技术向问答的标准答案。

## 怎么设计（方案）

**语料层（用什么切、怎么入池）**：语料 = 语雀 + 代码分析 + OpenSpec + 完善文档 8 节 + 引导问题；`slice_corpus.py` 按 LAYERS 表定切法（完善文档整篇一块、其余按 h2/h3 切，OpenSpec 的 Risks/Non-Goals 段过滤），产出双池 jsonl——切片池（细节块 + 引导问题）+ 全量池（整篇文档）；embedding 用 dashscope `text-embedding-v3` 显式 768 维，**维度固定不可改**（索引建好即锁死，换模型 = 全量重建）。

**检索层（怎么召回、怎么融合、怎么挡边界）**：双池三路召回——全量池向量（rag-full）+ 切片池双向量（rag-slice 每块 `-c` 内容路 / `-q` 问题路）+ 本地 BM25（jieba+Okapi），四路 RRF（`RRF_K=60`）融合成 `score = RRF × authority × anchor_w`（权威度 1.0/0.8/0.7 连乘、节锚定命中 ×1.5）；范围门 0.75/0.5 双路都低才拒答，触发即边界话术、短路不调生成（0 token）。

**编排层（怎么判意图、怎么兜底）**：intent 用 LLM 结构化输出（anchor/category/switch/ambiguous）→ schema 校验 → 失败回退关键词（模块 `_fallback_module` + 节 `_fallback_anchor`）+ 指代词兜底 `_deictic_anchor`；白盒链路事件时序 `intent → (clarify|switch) → rewrite → rerank → (boundary|token*) → done`，clarify/switch/问候均 0 token。

**生成层（怎么流式、怎么证明引用）**：doubao 流式生成（`include_usage=True` 流末 usage chunk 真采 token），强制只基于召回语料、末尾统一贴参考来源；引用校验用 LCS 最长公共子串硬匹配（连续 8 中/12 英字符命中即 `is_quoted`），纯函数不靠 LLM 自述。

**网关层（Java 做什么）**：Java 网关做角色硬门（仅 STUDENT 放行、非学生固定 403、body 传 role 忽略）、SSE 白盒中继（permission 前置含 traceId、snake→camel 逐事件重建）、Redis 会话聚合（每轮 done 落累计 token/trace 快照、close 结算、turns 断线补查，TTL 24h）；Python 无状态。

**前端层（怎么演示白盒）**：白盒阶段面板按事件点亮 5 阶段行（权限→意图→改写→召回·重排→生成）；引导 chips（guide 入口 + done 建议）点选即问；召回块"先灰后亮"——rerank 到达灰显折叠、done.quotedKeys 命中块高亮 + 已引用徽标；查看原文走 Java 代理。

**评测层（怎么证明有效）**：`run_eval.py` 跑评测集 → `eval_agent.py` 走真实检索原语（不降级）→ hit@5 纯函数 + LLM 判分只报事实（covered_count/fabricated）、分数规则硬算、编造封顶 3 分 → trace/报告落盘 + 版本对比。

## 落地真相（代码）

> ⚠️ **总翻转**：方案口径（doc_type 双池 / 前端传 page 锁页 / 打分 = similarity×问题类型×锚定 / 两道门都在 Python 链）落地为：**物理双池 rag-full + rag-slice（metadata 无 doc_type）、模块级 current_project/anchor 选池 + 节级 locked_sections 加权（无 page 参数）、打分 = RRF×authority×anchor_w、权限门在 Java 网关（Python 无）**；范围门 0.75/0.5 只在白盒链路生效，1.6C 端点只有空命中拒答。

- **语料层**：切片池 294 块 + 全量池 23 块（ai-tutoring），question-analysis 另 317+25；引导问题块混在切片池、双向量 `-q` 问题路对池内原题命中 sim~0.99；rag-system 自身语料未入 MODULE_DATA（当前 anchor=rag-system 必边界拒答，语料就绪即自动可答）。
- **检索层**：`RRF_K=60 / TOP_K=5 / VEC_K=12 / BM25_K=10 / ANCHOR_WEIGHT=1.5`；白盒链路 recall 写死 `locked_sections=[]`（节锚定被旁路，仅 1.6C 端点生效）；COS 向量索引 10s 异步生效（写后即查可能 miss）。
- **两道门**：权限门在 Java（`requireStudent`，仅 role=STUDENT、不查 userId）；范围门只在白盒 `check_boundary`（`vec<0.75 且 bm<0.5` 双路都低才拒），1.6C 端点无阈值门。
- **token 真算**：白盒流式已修（include_usage 流末 usage chunk 真采）；评测真采（`generate(return_usage=True)`）；1.6C 端点不采、embedding 未单列。
- **生成/引用**：生成超时/异常/边界降级全写死话术 0 token；is_quoted 用 LCS 硬匹配（非 LLM 自述）。
- **评测**：HIT_K=5（由 3 演进），判分 LLM 只报事实 + 规则硬算 + 编造封顶 3 分；评测集仅 ai-tutoring 6 条（含 1 边界拒答），当前基线 hit@5=0.583 / 质量 3.833 / 均 ¥0.018 / 17.4s。

## 追问与防御

- **"embedding 维度怎么定？"** → 索引维度建好不可改，所以显式 768 对齐 dashscope 默认输出并预建 768/float32/cosine 索引；换模型 = 全量重建，故维度决策是"一次锁死"。
- **"流式 usage 只在结尾怎么拿？"** → 请求体加 `stream_options.include_usage`，流末尾 choices 为空的 usage chunk 解析取 prompt/completion/cache_hit，白盒 done.tokens_usage 即真采值；cache_hit 取不到置 0。
- **"索引层 QA 和引导问题啥关系？"** → 方案设想"QA 规范问题 + 变体写法强制检索"在代码被反转：引导题纯池不切片、直接返池内原题（LLM 改编会引入池外概念匹配不到切片），点击走 `-q` 问题路检索切片池，0 token 且 100% 可答。
- **"范围门 0.75/0.5 全链路生效吗？"** → 不是：只白盒 `check_boundary` + 评测边界类型用；1.6C 旧端点只有空命中拒答，低置信非空命中仍进生成——答"两道门"要分清入口。
