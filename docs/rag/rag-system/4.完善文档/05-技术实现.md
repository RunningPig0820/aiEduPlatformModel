# 05 技术实现

> 模块=rag-system｜节=05｜问题表=操作/数据关联｜权威度=高（正文）

## 为什么（语雀/动机）

面试官会追问技术细节：语料怎么来、切片怎么切、embedding 用什么、向量桶怎么建、打分怎么算、评测怎么做。本节给技术实现口径。

## 怎么设计（方案）

**语料**（D1）：语雀 + 代码注释 + OpenSpec → 自己完善成 8 节（空模板自己补）。完善文档同时是切片单元、源文档池、索引层 QA 的来源。

**切片 + metadata**：按节切，带 `page/doc_type/section/source_doc`。`source_doc` 用于召回原文面板（前端展示来源）。

**embedding**：dashscope `text-embedding-v3` 768 维；本地 bge 备选。**维度固定不可改**（索引建好改维度 = 全量重建）。

**向量桶**：COS `rag-index`，**10s 异步生效** → demo 预建索引（写后即查可能 miss）。

**索引层 QA**：从完善文档提炼，每模块 5~8 条（`问题+答案要点+引用`）。

**打分**（D5）：`score = similarity × 问题类型匹配 × 页面锚定加权`；索引层 top-K=1~3/阈值 0.75，源文档池 top-K=3~5/阈值 0.5。

**评测集**：每模块 5 条，覆盖 5 类问题（概览/为什么/数据流/难点/指标）；预期答案 = 完善文档回查。

## 落地真相（代码）

- `core/tutoring/vector_store.py`：`embed`(dashscope 768d) + `put_vector`/`query_vector`(CosVectorsClient，按 vector_type 路由桶)。
- `scripts/rag/`：`slice_corpus.py`(234 块) → `build_index.py`(纯 COS 入桶) → `rag_query.py`(CLI) → `run_eval.py`(评测)。
- 判分：`eval_agent.py`——LLM 只报 `covered_count/fabricated`，`_score_from_covered` 按比例 + 编造封顶硬算。

## 追问与防御

- **"embedding 维度怎么定？"** → 索引维度固定不可改（建好就锁死），所以选 768 对齐模型默认输出；换模型 = 全量重建。
- **"写后即查会怎样？"** → COS 10s 异步生效，立即 query 可能 miss → demo 预建索引 / 写后校验。
- **"流式 usage 只在结尾怎么拿？"** → include_usage + 解析结尾 usage chunk，流结束更新；拿不到 → tokenizer 估算并标注"估算"。
- **"索引层 QA 和引导问题啥关系？"** → 同一份，视角不同：QA 是规范答案，UI 引导是它的变体写法（强制走检索）。
