# 06 关键坑与解法

> 模块=rag-system｜节=06｜问题表=难点｜权威度=高（正文）

## 为什么（语雀/动机）

面试官最爱问"项目开发中有什么难点"。RAG 系统自身踩过哪些坑、怎么解决的——既要讲业务坑（AI答疑），也要讲 RAG 技术坑（本模块）。

## 怎么设计（方案）——坑摘要

| 类 | 坑 | 根因 | 解法 |
|---|---|---|---|
| **意图分类** | 关键词锚定太粗，覆盖核对 6/10 | "怎么/如何"万能词锁错节 | LLM 语义判断 → 10/10 |
| **评测误判** | 首跑质量分 2.6，"覆盖4/4却给4分" | 判分 prompt 弱 + 评测集要点不适用 | 判分确定性硬化(模型报覆盖条数, 代码硬算) |
| **存储** | jsonl 副本传 COS 被拒 | 向量桶 role mode 拒普通对象 | 副本留本地 |
| **环境** | conda langchain 冲突 | 两套 langchain 版本不匹配 | 统一 venv |
| **异步** | COS 10s 异步生效 | 写后即查可能 miss | demo 预建索引 / 写后校验 |
| **维度** | embedding 维度不可改 | 索引维度建好锁死 | 换模型=全量重建 / checksum 校验 |
| **语料矛盾** | 空模板/多版本 | 语料不全或多版本冲突 | 完善文档向代码对齐，冲突以代码为准 |

**降级矩阵**（D10）：多路召回本身就是降级备份（向量挂→纯 BM25）；生成失败 → 预写答案兜底；全挂 → 边界话术。

## 落地真相（代码）

- 完整坑档案（含 git commit + 代码位置证据）：`5.难点/坑档案-开发与验证.md`（K1-K5 + V1-V3）。
- 评测定位问题方法论：hit@3 测检索、质量分测答案、trace 回溯定位"问题在哪一层"。

## 追问与防御

- **"降级矩阵怎么设计？"** → 多路召回本身是备份；生成失败降级预写答案；全挂了有边界话术，最坏也能答。
- **"判分模型偏差？"** → 固定判分标准 + 确定性硬化（分数可复现）+ 抽样人工复核。
- **"语料才几十条能说明什么？"** → 链路真实完整；可解释检索才是重点（不是比语料量）。
