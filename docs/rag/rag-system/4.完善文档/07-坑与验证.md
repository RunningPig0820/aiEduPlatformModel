# 07 坑与验证（RAG 系统自身）

> 模块=rag-system｜节=07｜问题表=难点/最危险｜权威度=高（正文）
> 说明：本节讲 **RAG 系统自身开发踩过的坑 + 怎么验证它有效**——面试官问"你的 RAG 怎么证明有效、遇到过什么问题"时的答案。

## 为什么（语雀/动机）

RAG 问答系统用于面试/汇报，核心是**用数据证明有效**——不能只说"感觉答得还行"。要能回答：
- 你怎么知道语料覆盖了面试官要问的问题？（覆盖核对）
- 你怎么知道检索捞得对、答案答得好？（评测 agent：hit@k + 质量分）
- 遇到什么问题、怎么解决的？（真实踩坑 = 可信度）

## 怎么设计（方案）

**分层验证，不混为一谈**（对齐 rag-eval-agent D3）：
1. **覆盖核对**（先验证语料完备）：问题表 5 类代表问题逐个跑 `classify + orchestrate`，看锁定节是否命中期望节——语料完备性是检索质量的前提。
2. **评测 agent**（再验证检索+生成质量）：评测集 5 条 → hit@k 测"检索捞得对不对"，LLM 质量分测"答案答得好不好"。**先测检索再测答案，分层定位**。
3. **测试 agent 三层**：纯函数单测（hit@k/聚合）、判分 mock 注入、外部边界 mock（不碰真实 COS/LLM）。

**评测走真实检索原语，不降级**——向量挂了就暴露，不让降级掩盖真实质量问题。

## 追问与防御

- **"评测集是你自己写的，不是自证吗？"** → expected_references 回查完善文档（节号真实存在），hit@k 是客观命中率；质量分是 LLM 独立判分（非自评）。
- **"质量分才 2.6，说明不行？"** → 恰恰说明评测有效——它准确指出了短板在生成层不在检索层，下一步改生成 prompt 就能拉高；而且 hit@3=0.8 证明检索是可靠的。
- **"为什么加 LLM 意图识别？"** → 覆盖核对发现关键词万能词稀释意图分类（6/10）→ 换 LLM 语义判断升到 10/10；接口不变，未来可换更强意图模型。
- **"质量分从 2.6 变 4.6，改了什么？"** → **没改生成代码，改的是"打分的人"和"考卷标准"**：
  ① 判分 prompt 强化——之前判分模型认不出同义表述（要点"ScoreMapper 累计"=答案"题型掌握度回流"）、误判语料有支撑的表述为"编造"、没有评分锚定。修复：同义表述覆盖即算覆盖、判分时传入检索到的语料块供"编造"判定（答案在语料有支撑即非编造）、明确 0~5 评分锚定。
  ② 评测集 expected_points 修正——数据关联那条混入了不适用该问题的要点（B3门控/澄清卡 是"掌握度怎么算"的细节，非"知识图谱怎么联动"的要点），答案没答到"无关要点"就被扣 0 分。修复：收窄为该问题真正的核心要点。
  → 操作类 2→5、数据关联 0→4、难点 3→5、最危险 4→5。**核心教训：评测分数低先查判分器和评测集，别急着怀疑检索/生成——分层定位要分层修。**（git: `b13220b`）
