# 08 数据规模与指标

> 模块=rag-system｜节=08｜问题表=数据关联/最危险｜权威度=高（正文）

## 为什么（语雀/动机）

面试官会问"这套系统多大、值多少钱、怎么证明有效"——需要**量化的规模和指标**。

## 数据规模（当前 AI答疑 模块实测）

| 维度 | 值 |
|---|---|
| 语料 | 语雀 5 篇 + OpenSpec 22 + 代码分析 10 + 坑档案 26 坑 |
| 完善文档 | 8 节（每节 27-63 行，共 372 行） |
| 切片 | **234 块**（完善文档 8 + 语雀 42 + OpenSpec 126 + 代码 30 + 坑档案 28） |
| 向量 | rag-1318177119/rag-index，768 维 float32 cosine |
| 评测集 | 5 条（5 类问题各 1） |

## 评测指标（2026-08-24 实测）

| 指标 | 值 | 含义 |
|---|---|---|
| hit@3 | **0.80** | 检索命中预期节的比例（5 条全命中） |
| 质量分 | **3.6~4.6/5** | 答案覆盖要点 + 无编造（判分确定性硬化，可复现） |
| 单条耗时 | **5.7s** | 检索 2s + 生成 3.3s + 判分 |
| 单条成本 | **¥0.016** | 均 4686 tokens，doubao mini 单价 |
| 覆盖核对 | **10/10** | 问题表 5 类全锁定期望节 |

## 成本叙事（面试"值多少钱"）

```
单次问答 ¥0.016（检索嵌入 + 生成 + 判分）
本地 embedding 备选（bge 免费）进一步降成本
追问限制 5 轮防上下文膨胀（防 token 飙升）
→ 全链路可控，个人项目成本可承担
```

## 追问与防御

- **"语料才几十条，能说明什么？"** → 链路真实完整（切片→索引→检索→生成→评测全通）；**可解释检索**才是重点——不是语料多，是每一层为什么这么设计能讲清。
- **"评测集是你自己写的，不是自证？"** → expected 引用回查完善文档（节号真实存在）+ hit@k 客观命中率 + 判分确定性硬化（模型只报事实，分数硬算可复现）。
- **"质量分波动（3.6~4.6）？"** → LLM 判断覆盖条数有正常波动，但**评分锚定表 + 确定性算分**让分数范围可控可复现；hit@3 客观指标稳定 0.80。
