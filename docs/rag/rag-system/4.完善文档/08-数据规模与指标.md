## 为什么（语雀/动机）

面试官必问"这套系统多大、值多少钱、怎么证明有效"——需要**量化的规模和指标**支撑：语料规模（多少文档/多少块）证明工程量，评测指标（hit@k/质量/成本/耗时）证明检索与生成质量，成本换算证明可负担。

## 怎么设计（方案）

规模与指标按五块设计，每块都可查证据：

1. **语料规模**：每模块产出完善文档 **9 节**（定位→功能→为什么→数据流→技术→坑→指标→数据规模→权限），9 节即切片单元；双池双层语料（全量池 rag-full 整篇管整体问题 + 切片池 rag-slice 细节块管追问），JSONL 双池落本地供 BM25/反查。
2. **索引**：dashscope text-embedding-v3 **768 维**（模型默认 1024，索引控制台预建 768/float32/cosine 不可改）；键规则 `{池}/{module}/{file}/{anchor}#{idx}`，含 module 段防跨模块同名文件覆盖。
3. **检索指标**：双池三路召回（全量池向量 + 切片池双向量 -c/-q + 本地 BM25）四路 RRF 融合，RRF_K=60、VEC_K=12、BM25_K=10、节锚定 ×1.5、TOP_K=5；范围门阈值 0.75/0.5。
4. **评测指标**：评测 agent 每模块 ≥5 条评测集（5 类各 1 + 边界拒答），hit@k + 质量分 + 成本/耗时，报告按语料版本（date-sha1[:6]）`--compare` 对比。
5. **成本**：token 真算（流式 usage 结尾采集），按 doubao 单价换算 ¥；0 token 兜底话术（问候/澄清/边界/超时写死不调 LLM）。

## 落地真相（代码）

> **总翻转**：方案口径（每模块 5~8 条 QA / 25 条评测 / 单条 ¥0.016 / hit@3）落地为：评测集仅 ai-tutoring 6 条、指标演进为 hit@5 + 判分硬算、多模块未全部入池。

- **语料规模实测**：ai-tutoring 双池 = rag-full 整篇 **23 块** + rag-slice 切片 **294 块**；question-analysis 另 317+25 块，**多模块合计 659 块**（头注释"294/23"只反映单模块）。**rag-system 无 jsonl**（未入 MODULE_DATA，anchor=rag-system 当前必然边界拒答——语料就绪即自动可答）。
- **索引实测**：双池共用向量桶 rag-1318177119、两个物理索引 rag-full/rag-slice；768 维 float32 cosine；键 `{池}/{module}/{file}/{anchor}#{idx}`，切片池每块写 2 key（-c 内容路 embed(summary+text) / -q 问题路 embed(summary)），全量池条件式 embed（≤5000 字符全文、超限只 summary）。
- **检索指标实测**：双池三路 → 四路 RRF（RRF_K=60）；范围门 0.75/0.5 **只在白盒 check_boundary 生效**，1.6C 端点无阈值门只有空命中拒答；VEC_K=12、BM25_K=10、TOP_K=5。
- **评测指标实测（最新报告 2026-08-26-259c06）**：**hit@5=0.583 / 质量分 3.833 / 单条成本 ¥0.0181 / 单条耗时 17.4s**；HIT_K 由 3 改 5（对齐生成 top-5）。两套口径：hit_cases 5/6（任一引用命中）vs hit_at_k_avg 0.583（引用命中比例）；4 份历史报告按语料版本对比（08-24-e966ac → 08-26-259c06）。
- **评测集现状**：仅 ai-tutoring.jsonl **6 条**（5 正常 + 1 边界拒答"帮我写一封辞职信"）；eval_dataset 硬编码 module=="ai-tutoring" → **rag-system 无评测集**，多模块评测需先改代码。
- **成本实测**：calc_cost 纯函数 = prompt/1000×0.003 + completion/1000×0.009（doubao 单价）；token 真算白盒流式已修 + 评测侧真采，1.6C/embedding 未采。K9 实测：引导题 summary 用 LLM 翻译版 → 语义错位（sim 0.65），BM25 第 7、向量不进 top；改 summary=问题标题后 BM25 第 7→第 1、向量不进 top→第 1（sim 0.8513）。

## 追问与防御

- **"语料才几百块，能说明什么？"** → 链路真实完整（切片→索引→双池召回→生成→评测全通）；重点不是语料多，是每一层为什么这么设计能讲清（双池/双向量/RRF/范围门/判分硬算）。
- **"hit@5=0.583 是不是很低？"** → 0.583 是引用命中比例，6 条中 5 条任一引用命中（hit_cases 5/6）；评测集仅 6 条样本量小，指标主要证明"评测体系能跑、能版本对比定位回归"，扩到 30~50 条才谈稳定基线。
- **"评测集是你自己写的，不是自证？"** → 评测走真实检索原语不降级（向量挂了就暴露）；hit@k 是引用命中客观率（纯函数），判分 LLM 只报事实、分数硬算、编造封顶 3 分，报告按语料版本可对比。
- **"成本/耗时数字怎么来的？"** → calc_cost 按 doubao 单价 × token 真采 usage（白盒流式 include_usage 已修）；17.4s 含检索+生成+判分三段 latency，报告里逐条可查。
