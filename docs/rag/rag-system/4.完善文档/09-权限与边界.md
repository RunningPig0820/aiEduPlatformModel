# 09 权限与边界

> summary: 解答「这系统有没有边界？会不会答错/乱答/越权？」——权限与边界分五层：①权限门=Java 角色门（可信 session 取 role、仅 STUDENT 放行、非学生固定 403 不耗 token、Python 无权限门只 verify_internal_token）②范围门=白盒 check_boundary 0.75/0.5（语料即边界，无单独分类器）③边界拒答=固定话术不硬编、唯一拒答路径 boundary(low_confidence)、双门事件各归其位 ④白盒降级=单路 2s 超时降空路/8s 生成超时召回清单/断连 is_disconnected 中止，降级矩阵结构不变 ⑤安全=提示注入/渲染注入 LCS 硬匹配/current_project 信任边界；落地真相总结：范围门仅白盒生效（1.6C 无阈值门、docstring 高于实际）、降级标记 DEGRADED_* 定义未透传 SSE。

## 为什么（语雀/动机）

面试官最危险的问题是"会不会答错/乱答/越权"——RAG 是生成系统，天然有编造与越界风险。设计目标：把"边界"做成**显式分层防御**（权限门能不能看 → 范围门有没有覆盖 → 边界拒答不硬编 → 降级不空答 → 安全不中注入），每一层都能对面试官讲清"为什么这么挡、挡在哪、代价是什么"。

## 怎么设计（方案）——权限与边界分五层

**① 权限门（前置硬拦截，能不能看）**：后端从**可信源**（HttpSession）取角色，严禁信任前端 body 传 role；仅"学生"放行，非学生/角色缺失 → 固定 403，不进入 RAG 流程、不消耗 token、不产生 trace。

**② 范围门（后置置信度，有没有覆盖）**：检索置信度 = 范围判断，**语料即边界**、无需单独"是否覆盖"分类器；索引层 0.75 / 源文档池 0.5，低于 → 边界回答不硬编。

**③ 边界拒答（固定话术不编造）**：语料没覆盖 → 预写话术（"该问题语料未覆盖…"/"未找到关联文档，我尚未掌握"）0 token 直返；生成失败 → 召回块清单当答案不空答；全挂 → 边界话术兜底（最坏也能答）。权限门与范围门各发各的事件（HTTP 403 vs boundary 事件），前端能展示"拒绝发生在哪一层"。

**④ 白盒降级（结构不变、不卡死）**：向量路挂 → 纯 BM25、单路 2s 超时降空路、doubao 生成挂 → 召回清单/降级话术、断连 `is_disconnected` 中止防空转烧钱；所有降级路径响应结构不变，前端只按同一结构渲染。

**⑤ 安全（防注入/防越权读取）**：提示注入 → 复用 tutoring safety_flag 本地关键词 + intent 兜底（⚠️建议项未落地）；渲染注入 → is_quoted 用 LCS 硬匹配标记引用（非 LLM 判断）；current_project/锚点来自调用方，靠模块闭集 + 语料白名单约束（语料白名单本身就是权限层）。

## 落地真相（代码）

- **权限门在 Java 网关、Python 无**：`RagAssistantController.requireStudent` → `TutoringAuth.isStudent`（可信 session 取 role、body 传 role 忽略、仅 STUDENT 放行、非学生固定 403、0 token 不产 trace）；Python 所有端点只有 `verify_internal_token` 服务鉴权，无角色/权限点——方案 D4"按角色过滤可检索页"在 Python 检索编排中不存在。
- **范围门 0.75/0.5 只在白盒 `check_boundary` 生效**：rerank 空 → 拒答；或 `vec_conf<0.75 且 bm_conf<0.5` 双路都低才拒、单路高即过，触发短路不调 generate（0 token）；**1.6C `/query` 端点无阈值门**，只有 `if not hits` 空命中拒答（docstring 自称"置信度过低→拒答"与实际不符）——面试表述以"范围门仅白盒链路"为准。
- **边界拒答 = 唯一拒答路径**：08-25 定稿"四模块全放行 + 范围门 low_confidence 过滤"，意图层无禁区硬拒答；`reject` 事件 DTO 保留定义但不产出；boundary 固定话术 0 token。
- **白盒降级落地，但标记未透传**：单路 2s 超时降空路、8s 生成超时 → `GEN_TIMEOUT_MSG`+召回清单、断连 `is_disconnected` 中止；`DEGRADED_VECTOR/DEGRADED_BM25` 定义了但未放进 rerank/done 事件，前端拿不到"本轮降级"显式信号。
- **安全落地/缺口**：is_quoted LCS 硬匹配已落地（8 中/12 英连续字符命中即引用）；提示注入 safety_flag 仅方案未落地（白盒系统易当靶子）；`current_project` 由 Java 透传 Python，guide 缺省=ai-tutoring vs ask 缺省=rag-system 不一致（前端不传时引导题与检索池错位）。

## 追问与防御

- **权限门在哪一层？Python 怎么防越权？** → 角色门收敛在 Java 网关（可信 session 仅 STUDENT 放行、403 不耗 token），Python 无状态不自己认证；Python 侧只有 `x-internal-token` 服务鉴权，source 查看原文还有前缀白名单 `rag-source/`/`rag-slices/` 防任意 COS key 读取。
- **边界怎么判？会不会误拒好问题？** → 范围门 = 召回置信度（向量 1-平均余弦距离 / BM25 `min(1.0, top_score/10)`），0.75/0.5 双路都低才拒、单路高即过；阈值语义 2026-08-25 校正过（初版误用 RRF 分 0.01~0.05 量级永远够不到阈值）；缓解误拒靠双池 + 引导问题把高频问题收纳进索引层。
- **答错了/超范围了怎么办？** → 三层兜底：语料没覆盖 → 边界话术不编造；生成失败 → 召回块清单当答案不空答；全挂 → 边界话术兜底。评测对"编造"封顶 3 分——答错会被数据压低，用数据证明。
- **会不会被提示注入/越权读取？** → 诚实分层：提示注入 safety_flag 是方案建议项未落地；已落地的是引用硬匹配（is_quoted LCS）、source 前缀白名单、模块闭集选池；current_project 信任边界靠前端恒传 + 语料白名单（语料白名单本身就是权限层）。
