```
问题列表.md（9 视角 57 问，纯问题）
   ├──▶ guide_pool（前端引导候选，intro/operation/data_relation/difficulty/rag 5 组）
   └──▶ 评测集（run_eval 用问题，检查 RAG 能否答对）
        ↑ 答案检索源
   └──▶ 完善文档 1.0（全量池）+ 分析/坑 0.8（切片池）
```

## 三、生成指引

1. 用 `提示词/问题列表-生成-提示词.md` 重生成（输入：主文档 + 完善文档 + 分析 + 坑档案）
2. **可回答性第一**：每条问题必须能在语料中找到答案（对照完善文档/分析文档）
3. **纯问题不回答**：只产问题清单，答案走检索链路
4. 生成后按 intro/operation/data_relation/difficulty/rag **5 组**映射进 `guide_pool.py` 的 `GUIDE_POOL["rag-system"]`（只放问题文本），随后引导单测回归

## 四、与 question-analysis 的区别

- question-analysis 引导问题 = 9 视角 70 问，映射进 `GUIDE_POOL["question-analysis"]`；
- rag-system = **9 视角 57 问**，9 视角来自本模块完善文档 9 份（01-产品定位 / 02-核心功能 / 03-为什么这么设计 / 04-数据流转 / 05-技术实现 / 06-关键坑与解法 / 07-坑与验证 / 08-数据规模与指标 / 09-权限与边界）；
- **guide_pool 只用 5 组**（intro/operation/data_relation/difficulty/rag）：与 question-analysis 组名相同，但 rag-system **不再扩张组数**——业务视角/数据存储/未来演进问题按语义归入既有 5 组，不新增组，保证 pool 组闭集稳定；
- 源 = `问题列表.md` 每条问题的 `<!--tag:{视角}-->` 标签，映射依据同 question-analysis。
