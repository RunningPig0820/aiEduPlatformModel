## 2. 操作流程（答案来源：完善文档 02 + 分析-04/05）

| # | 问题 | 答案要点（一句话核心结论） |
|---|---|---|
| 7 | 面试官第一次进来，怎么上手操作这个系统？ | 学生端右栏常驻面板，进页面点引导 chips 或自由输入 → 白盒 SSE 逐事件点亮 → 出带引用的流式答案 + 召回文档面板 + token 成本 → 可追问、可 close 结算。 |
| 8 | 描述一次完整问答：从提问到出答案，用户在界面上能看到哪些步骤？ | 前端带 sessionId+history 发 POST /ask → Java 角色门产 permission → Python 走 intent→(clarify\|switch)→rewrite→rerank→(boundary\|token)→done → 前端按序点亮 5 阶段行（权限→意图→改写→召回·重排→生成）。 |
| 9 | 白盒 SSE 链路的事件时序是什么样的？每个事件分别做什么？ | 冻结时序 `permission→intent→(clarify\|switch)→rewrite→rerank→(boundary\|token*)→done`，done 是所有分支唯一终止点；clarify/switch/boundary 分支无 generate、0 token 短路。 |
| 10 | 引导问题在哪些入口出现？和自由输入走的路一样吗？ | 两个入口：面板空态开始引导（GET /guide 取 3 条入口题）+ 每轮 done 后结束建议（池内原题 2~3 条）；点击后仍走 -q 问题路真检索，自由输入走源文档池纯 RAG，池内原题只为 100% 可答。 |
| 11 | 问题模糊/想切换模块时，系统会怎么处理？ | 模糊 → clarify 事件发候选 chips，点选=重发原问 + currentProject=点选模块 id；switch → switch 事件 + 按 to_anchor 继续，两条分支都不产 rewrite/recall/generate、0 token。 |
| 12 | 对话中途断线了怎么办？能补回来吗？ | 每轮 done 的 camel JSON 落 Java Redis trace 快照（TTL 24h）；SSE 中断前端凭 permission.traceId 调 GET turns/{traceId} 补回 answer/quotedKeys/usage，超窗提示重发。 |
| 13 | 会话状态、累计 token、结束结算这些归谁管？Python 有状态吗？ | 全归 Java Redis（rag:assistant:* 键，TTL 24h）：每轮 done 累计 token/轮数、close 结算、trace 补查；Python 显式无状态，只消费 history/trace_id，可水平扩展。 |

## 4. 开发难点（答案来源：完善文档 06/07 + 坑档案 K1~K10）

| # | 问题 | 答案要点（一句话核心结论） |
|---|---|---|
| 22 | 开发这个 RAG 系统，你遇到的最大坑是什么？ | 不是单点 bug，而是方案/代码漂移——V4 三端对账抓出范围门仅白盒生效、usage 半修、rag_query 死代码；坑档案 K1~K10 每条可核 git commit，证明真踩过真修了。 |
| 23 | 关键词锚定太粗，"怎么/如何"万能词把问题锁错节，怎么解决的？ | K1：ANCHOR_RULES 字面匹配读不懂语义，覆盖核对只有 6/10；classify 升级 LLM 语义判断（闭集 6 类映射锁节）+ 关键词降级保底 → 10/10，接口不变、API 零改动。 |
| 24 | 评测首跑检索全对但答案质量分只有 2.60，怎么定位修复的？ | K2：trace 回溯发现不是生成层——是判分 prompt 认不出同义表述+评测集 expected_points 混入无关细节；修判分+收窄评测集 → 质量 2.60→4.60，hit@3 不变；教训"分数低先查判分器和评测集"。 |
| 25 | 流式回答结束时 token 明细拿不到（usage 丢失），根因和修法是什么？ | K6：两层都丢——请求体没带 include_usage（服务端默认不回）+ 解析器不认结尾 usage chunk（choices 空带顶层 usage）；修法是 ark_stream 加 include_usage + 抓结尾 chunk 组装 done.tokens_usage。 |
| 26 | 引导问题用 LLM 改编后学生点了答非所问，为什么反转成池内原题直出？ | K7：LLM 改编"换提问方法"会引入池外概念（如"向量索引"）无对应切片 → 匹配不到答案；反转池内原题直出 0 token，牺牲引导多样性换 100% 可答 + 省 token。 |
| 27 | 学生问"这个功能的底层是怎么实现的"被路由到 RAG 项目必然拒答，怎么兜底？ | K8：intent 没解析指代词=current_project、D4 硬路由过激进；修复=指代词规则 + 优先级放宽（只有"无指代+明确问 RAG 整体"才选 rag-system）+ 确定性兜底 _deictic_anchor（LLM 不听话也能兜住）。 |
| 28 | 引导题自己检索不到自己的答案块，summary 错位怎么修？ | K9：引导题 summary 被 LLM 翻成"答案式描述"与用户 query（问题标题）语义错位（sim 0.65）；改 summary=问题标题 → BM25 第 7→第 1、向量第 1（sim 0.85）——离线切片元数据语义必须与线上 query 对齐。 |
| 29 | 多模块共用索引，后入库的覆盖先入库的块，怎么防？ | K10：块 key 原只有 `{池}/{file}/{anchor}#{idx}` 不含 module，跨模块同名文件后写覆盖先写；修法=make_key 加 module 段 `rag-{pool}/{module}/...`，query._key_of 同步，252 passed。 |

## 5. 架构设计（答案来源：完善文档 03 + 分析-01/04）

| # | 问题 | 答案要点（一句话核心结论） |
|---|---|---|
| 30 | 双池检索为什么这么设计？只留一个池不行吗？ | 一池满足不了"引导可控 + 自由纯 RAG"两个目标：只有预写 QA → 自由问题全拒答、RAG 没证据；只有源文档全文 → 答案不可控、现场易翻车；双池分层各管一目标。 |
| 31 | 页面锚定怎么落地？"锁页检索"和"全局模式"分别对应什么？ | 落地无 page 参数：模块级 current_project/anchor 过滤选池（锁模块）+ 节级 locked_sections 加权 ×1.5（锁节，只加权不过滤）；页面模式≈locked_sections 非空、全局模式≈空；白盒链路节级被旁路。 |
| 32 | 两道门分别挡什么？权限门为什么在 Java、范围门为什么只在白盒链路？ | 权限门挡"能不能看"（Java 角色门、非学生 403、0 token）；范围门挡"有没有覆盖"（0.75/0.5 双路都低才拒、短路不调 generate）；范围门 0.75/0.5 只在白盒 check_boundary 生效，1.6C 旧端点只有空命中拒答。 |
| 33 | 答案为什么走"要点+生成"的 B 路线？全预写和纯检索各有什么致命问题？ | A 全预写=查表露怯（一问"检索在哪"就穿帮）、C 纯检索=不可控翻车；B"提纲你定、措辞 AI 来"——要点/引用锁范围、LLM 现组织语言，检索→增强→生成全真实发生。 |
| 34 | is_quoted 引用判定为什么用 LCS 硬匹配，不用 LLM 自述？ | LLM 自述与真实依据可能不一致、白盒露怯；LCS 最长公共子串（连续 8 中/12 英字符命中）纯函数硬匹配、可单测可入评测，生成完才匹配故 done 后置补发（先灰后亮）。 |
| 35 | token 成本为什么强调"真算"？流式 usage 只在结尾返回怎么拿？ | 成本是 RAG 最大实战痛点，真算+展示=成本控制叙事，估算只能标"估算"；流式 usage 只在流末尾专用 chunk 返回（OpenAI 兼容默认不返回），要显式带 stream_options.include_usage + 解析结尾 usage chunk（schema 与中间不同）。 |
| 36 | Python 为什么保持无状态？角色门、会话聚合为什么都放 Java？ | Java 是天然聚合点（token/trace/session 每轮过手），角色从可信 session 取、body 传 role 忽略；Python 不自己认证、不碰会话、不落库，保住无状态边界可水平扩展。 |

## 6. 业务流程（答案来源：完善文档 02/09 + 分析-04/07/08）

| # | 问题 | 答案要点（一句话核心结论） |
|---|---|---|
| 37 | 整个业务闭环怎么走？前端/Java/Python 三端各自承担什么？ | 前端白盒面板（发起/点亮阶段/渲染引用/断线补查/close）；Java 角色门 + SSE 中继（snake→camel 重建）+ Redis 会话聚合；Python 检索问答编排（intent→召回→RRF→生成）无状态。 |
| 38 | 边界怎么判？会不会误拒好问题？ | 范围门 = 召回置信度（向量 1-平均余弦距离 / BM25 min(1.0,top_score/10)），0.75/0.5 双路都低才拒、单路高即过；缓解误拒靠双池 + 引导问题把高频问题收纳进索引层。 |
| 39 | 答不上来/超范围时会怎么处理？会不会硬编？ | 三层兜底不硬编：语料没覆盖 → 边界话术（"未找到关联文档，我尚未掌握"）0 token；生成失败 → 召回块清单当答案不空答；全挂 → 边界话术兜底；评测对编造封顶 3 分用数据压。 |
| 40 | 降级矩阵怎么设计？多路召回本身怎么当降级备份？ | 多路召回本身就是降级备份：向量路挂 → 纯 BM25；单路 2s 超时降空路；doubao 生成挂 → 召回清单/降级话术；全挂 → 边界话术；所有兜底写死 0 token 短路防无谓成本，响应结构不变。 |
| 41 | 权限门怎么实现？前端 body 传 role 有用吗？ | Java 网关 RagAssistantController.requireStudent → TutoringAuth.isStudent 从可信 HttpSession 取 role，仅 STUDENT 放行、非学生固定 403、0 token 不产 trace；body 传 role 一律忽略（RagAskCommand 无 role 字段）。 |
| 42 | 会不会被提示注入/越权读取？防了哪些、没防哪些？ | 诚实分层：提示注入 safety_flag 是方案建议项未落地；已落地 is_quoted 引用硬匹配、source 前缀白名单（rag-source//rag-slices/）、模块闭集选池——语料白名单本身就是权限层。 |

| 58 | embedding 向量维度为什么选 768？维度选大/选小各有什么影响？ | 768 是 dashscope text-embedding-v3 显式对齐的维度（模型默认 1024），COS 索引控制台预建 768/float32/cosine、维度建好不可改（换模型=全量重建）——维度越大语义表达力越强但存储/成本越高、越小越省资源但召回变糙，本项目选 768 是"一次锁死"的折中（出处：分析-03 vector_store.py:26-28/build_index.py:121-122、完善文档 05 追问段）。 |
