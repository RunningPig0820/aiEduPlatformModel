## 双切片分工

| 维度 | 开发向（本目录） | 面试向（本目录） |
|---|---|---|
| 消费方 | 开发查问题/对账 | 面试官提问/候选人介绍 |
| 块名 | 业务链路 / 代码事实 / 坑与对账 | 业务与流程 / 架构与技术取舍 / 落地问题与复盘 |
| 保留 | 文件:行号、API、枚举表（证据全） | 业务/流程/架构/踩坑/复盘（过滤代码噪声） |
| 对账 | 原始 markdown 对比表 | 提炼为自然语言复盘段落 |
| COS路径 | `rag-slices/rag-system/代码/...` | `rag-slices/interview/rag-system/...` |
| target | `target: 开发对账` | `target: 面试项目问答` |

## 与 完善文档（1.0 全量池）的分工（关键）

- **完善文档 1.0** = 面试主答案（整篇全量池，优先召回）——答"业务是什么/为什么"
- **代码切片 0.8** = 细节/踩坑/翻转事实补充——答"具体怎么做的/踩过什么坑/方案怎么翻转"
- **检索规则**：先 1.0 主答案，切片补深度；切片带**证据指针**（详见 分析-0X / 完善文档 0X），追问可回源；`code_analysis` 只答接口/参数/降级/对账翻转/代码真实行为，不答"为什么这么设计"（canonical 职责）

## 生成方式

- 开发向提示词：`../处理方案/提示词/切片-开发向-提示词.md`（语义合并不改写，保留代码证据）
- 面试向提示词：`../处理方案/提示词/切片-分组-提示词.md`（过滤代码噪声转述）
- 每份文档 → 开发 3 块 + 面试 3 块 = 6 块；7 份 × 6 = **待生成**（以实际产出为准）
