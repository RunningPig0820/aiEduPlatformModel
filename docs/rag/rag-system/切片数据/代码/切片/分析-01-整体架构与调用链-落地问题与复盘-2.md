## 方案 vs 落地的复盘（续）

**评测走真实检索原语、不降级**
原始方案 D3 就说评测走 rag-retrieval；实际评测直接调真实检索原语、不经过带降级语义的 API，向量挂了就暴露——设计意图是"评测要看真实质量，不让降级掩盖问题"。落地——设计意图如此，代码明确。

**降级矩阵大体落地，缺"返回页面大纲"一级**
原始方案 D10 设计逐级降级矩阵（embedding挂→BM25/本地索引/大纲/原文）；实际旧 query 端点三级降级（向量挂→纯 BM25、doubao 挂→references 当答案、无命中→拒答），白盒链路向量超时→空路、生成超时→写死话术 + 召回清单、范围门→固定话术；但**"返回页面大纲"这一级未见**。大体落地——"返回大纲"级未做，其余落地。

**引导池部分建成：rag-system 无独立池**
原始设计是"引导问题源=每模块自己的底座池"；实际 GUIDE_POOL 有 ai-tutoring / question-analysis / knowledge-graph 三模块池，rag-system 无独立池（注释"语料就绪再加"），`pool_for("rag-system")` 兜底到 ai-tutoring。部分——rag-system 池未建，语料整理中。

**生成强制引用落地，"跨页按页标注"未落实**
原始方案 D6 要求"强制引用、无引用不输出、跨页按页标注"；实际生成系统提示词硬性约束只基于召回语料、末尾统一贴参考来源、正文不插标记，引用来源格式"引用/锚点"两行；但**"跨页按页标注"在提示词里没有显式分段指令**。部分落地——强制引用落地；按页标注未见。

**追问上限不做在 Python**
原始方案 D9 设计"追问限制 5 轮/会话"；实际 Python 无状态、不产出 turns/close/轮次上限，归 Java Redis，Python 侧代码未见 5 轮上限实现。🚫 Python 不做（Java 承接）。

**打分公式演进：similarity 连乘 → RRF × 权威 × 锚定**
原始方案 D5 是 score = similarity × 问题类型匹配 × 页面锚定加权；实际是 `rrf × authority × anchor_w`，"问题类型匹配"未单独成因子（类别过滤已废弃），相似度由 RRF rank 间接表达。演进——公式重构，RRF 取代 similarity。

**语料来源落地**
原始方案 D1 设计"语雀+代码+OpenSpec → 完善文档 8 节"；实际切片池 tags.source 实测含引导问题/语雀-*/设计/坑档案/完善文档 1-8，全量池 23 块含语雀 0.7/代码 0.8/完善文档 1.0。落地。
