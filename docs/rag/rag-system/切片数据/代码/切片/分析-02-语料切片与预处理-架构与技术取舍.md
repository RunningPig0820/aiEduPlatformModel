## 架构与技术取舍

### 切片边界：标题正则 + LAYERS 切分等级双控
语料怎么切由两个机制共同决定：标题正则认 `#`~`####` 四级标题；再按来源在 LAYERS 配置表里指定切分等级与模式——mode="file" 整文件一块、mode="split" 时低于等于 split_level 的标题作块起点、`###`/`####` 作为块内内容。各来源切法刻意不同：完善文档（1.0）整篇一块（一节=一个问题答案，不细切）；语雀（0.7）按 h2 切；OpenSpec design 决策（0.7）按 h3 决策切，并过滤 Risks/Migration/OpenQuestions/Non-Goals 等决策副作用段；代码分析（0.8）按 h2 切；坑档案（0.8）按 h3 每坑一块；引导问题（1.0）整文件一块并解析文件头结构化块。设计用意：完整答案块不细切保上下文，决策/坑这类粒度小的内容按更细标题切，保证每块语义自洽。

### 双池设计：切片池管细节、全量池管整体
双池互补——全量池整篇一块回答"整体/全局"问题（不丢上下文），切片池细块管细节；一池满足不了"引导可控 + 自由 RAG"两个目标。切片池由切片脚本直接从原始语料切出（summary 空占位），再经审查视图 md 逆解析补全标签；全量池由专用脚本把源文档整篇做成一块（去标题/头块、保留正文引用），summary 复用旧 jsonl——完善文档整篇块直接用、语雀/代码各切片块 summary 拼接、category 取多数。字段结构统一 `{text, summary, tags}`，tags 带 module/section/source/authority/file/file_path/anchor + 可选 category/pool。

### 摘要生成两路：切片级一句话 vs 全量池文档级
切片池的摘要脚本按批次（BATCH=5）批量给每块生成 ≤30 字一句话；全量池的摘要脚本逐篇生成 40~80 字文档级摘要——刻意逐篇而非批量，因为批量把大数组喂给模型会被合并成一份摘要。两路失败都能重跑：切片池该批留空，全量池留旧摘要。用途不同：切片池索引时对每块做双向量 embed(summary+text)；全量池大文件（>5000 字符）只 embed(summary) 作文档级粗召回，防止超 8192 token 截断。

### 切片头部与标签：精简头 + 检索摘要 + 类别闭集
切片导出脚本写固定精简头（标题 + summary + 权威度|来源|锚点 + 模块|节），逆解析脚本读的正是这套头；但实际模块 md 头比 5 行多（人工补齐 COS路径/类别）。"检索摘要"不参与切边界——它是正文里的块引用行，split 模式作为普通正文保留进块首行；代码证据层不强制每个子块写检索摘要。类别闭集 9 类（项目介绍/操作流程/数据关联/开发难点/业务流程/架构设计/业务视角/数据存储/未来演进），从 md 头读入 tags.category，最终写进 COS metadata。

### 多模块来源组织：通用脚本 vs per-module 子目录
ai-tutoring 用通用脚本 + LAYERS 表统一驱动 5 来源；question-analysis 是第一个 per-module 子目录，因为该模块切片 md 是双切片 + 格式A/B 头，与通用脚本的 LAYERS/头格式不兼容；rag-system/knowledge-graph 按规划大概率走 per-module 模式或复用切片脚本后调整 LAYERS。

## 设计要点

- **"切归切、改归改"**：切片源头 = 审查视图 md（已定稿、带 summary/类别/COS路径 头），逆解析脚本从 md 读，不再重跑原始切片——避免"改了 md 头要重切 jsonl"的耦合。
- **双池互补**：全量池管整体不丢上下文、切片池管细节。
- **超长不截尾**：split 超长块按段落贪心合并到上限再拆，单段超限硬切但保尾部进索引（替代旧方案会截掉尾段的做法）。
- **引导问题 summary 用标题不用翻译版**：LLM 翻译版 summary 语义错位导致 embedding/BM25 召不回（实测 sim 0.65），标题即"这段回答解决什么问题"。
- **块 key 带 module 段**：多模块共用同一索引，跨模块同名文件若键不含 module 会冲突覆盖，module 段保证键跨模块唯一。
- **双向量设计**：切片池每块写两个 key——内容路 embed(summary+text)、问题路 embed(summary)，同索引、key 后缀 role 区分，兼顾语义检索与短 query 召回。
- **分库独立脚本**：切片 md 格式因模块而异（头行数/格式A-B/target 双切片），故 per-module 子目录脚本而非继续堆参数。
