## 隐性坑与注意事项

1. **切片脚本不产 category/pool 标签**：split/file 模式的 tags 只有 8 字段、无 category；实际 jsonl 里的 category 是"从切片文件头 `> 类别：` 手动反写"补的（明确标注 ⚠️）。直接用切片脚本产出的 jsonl 缺 category，需逆解析脚本或补写。
2. **恢复脚本只认 3 行头**：它期望 summary/权威度|来源|锚点/模块|节 后紧跟空行+分隔线；实际切片 md 头在"模块|节"后还有 COS路径 与 类别 两行，正则落空 → 摘要恢复全失败（头格式敏感）。
3. **导出脚本与逆解析脚本头字段不对称**：导出只写 3 meta 行（summary/权威度|来源|锚点/模块|节），不写 COS路径/类别；但逆解析期望 COS路径/类别（缺了只告警）。两个脚本对"头应含哪些字段"定义不一致。
4. **摘要脚本硬编码 ai-tutoring 路径**：只读写默认模块的 jsonl，不支持 --module 参数；多模块摘要靠 md 头 `> summary:` 直读，不走这两个脚本。
5. **全量池脚本硬编码默认模块**：语料根路径写死，summary 复用旧 jsonl 备份；跨模块全量池要另写脚本。
6. **file_path 双口径**：切片脚本产出的 file_path = 相对语料根路径（前端定位源文件）；逆解析/分库脚本的 file_path = 头 COS路径（COS key）。两条流水线产出同一字段、语义不同。
7. **COS metadata 硬限制**：metadata 单条 ≤10 entries、单条 ≤2048B，summary 按"非 summary 值字节 + 250B 安全量"截断；text 全文不进 metadata，命中后按 key 反查 jsonl。
8. **切块 key 冲突**：同 (file, anchor) 内段落拆多块靠 chunk_idx 区分；导出 md 时同名文件加 -2/-3 后缀防覆盖。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**⚠️翻转：代码分析切分等级——方案按 `###` 语义分组双切片 vs 实际 split_level=2（h2）且无 target/双切片字段**
切片清单规划代码分析"按 `###` 语义分组双切片（开发向+面试向）"；通用切片器 LAYERS 里代码层 split_level=2（h2），且无 target/双切片字段。影响：当前通用脚本切不出"双切片"效果，需 per-module 脚本或改 LAYERS 才对齐。

**⚠️翻转：语雀权威度——方案 canonical 0.8 vs 实际硬编码 0.7**
rag-system 切片清单把语雀 canonical 定为 0.8；通用切片器 LAYERS 语雀硬编码 0.7。影响：rag-system 语雀块权威度会按 0.7 进库，与清单口径不一致，需改 LAYERS 才对齐。

**⚠️翻转：头部 5 行标准——方案 summary/权威度/模块/COS路径/类别 vs 导出脚本只写 3 meta 行**
标准头定义 5 字段；导出脚本只写 3 meta 行（无 COS路径/类别），实际 ai-tutoring md 头有 5 行是人工补齐的。影响：脚本未产 COS路径/类别，依赖人工补，是漏标签隐患。

**⚠️翻转：恢复脚本预期块数过期——注释"应=234 块" vs 实际 294 块**
恢复脚本注释期望 234 块，当前 jsonl 实为 294 块；且 HEAD_RE 对含 COS路径/类别的实际 md 头不匹配。影响：数字过期 + 头格式敏感，恢复结果不可靠。

**⚠️翻转：file_path 双口径——方案相对语料根路径 vs 实际 COS key**
原始切片注释说 file_path 是相对语料根路径（前端定位源文件）；逆解析/分库脚本的 file_path 是 COS key（rag-slices/... 或 rag-source/...）。影响：同一字段两种语义，消费侧需分清谁写的。

**⚠️翻转：doc_type 字段折叠——方案要求 doc_type=code_analysis vs 实际索引已去掉**
代码深读提示词要求 doc_type=code_analysis；索引器已去掉该字段（与 module 同值冗余），COS metadata 用 module 字段承载。影响：概念仍在，字段已折叠进 module，对账时别按旧字段查。

**✅落地：全量池块数——注释"23 块" vs 实际 23 块**
实际 23 块（语雀 5 + 完善文档 8 + 代码 10），与注释对齐。

**✅落地：检索摘要——方案每个子块带 `> 检索摘要：` vs 实际切片脚本不生成、仅作正文保留**
切片脚本不生成检索摘要，仅作为正文保留进块；代码证据层不强制写。设计如此，非缺陷。
