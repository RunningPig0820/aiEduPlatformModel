## 业务描述与业务场景

索引与向量库层是 RAG 语料「切片 → 可检索」的中间件: 把语料 jsonl 的每个块做 embedding, 写入腾讯云 COS 向量索引; 查询时按模块过滤召回 Top-K 相似块, 供 RRF 融合 + 权威度加权, 最后交给大模型生成答案。

场景边界:
- **双池**: 全量池 rag-full 存整篇文档（管整体问题）, 切片池 rag-slice 存细节块（管追问/细节）。两个池共用同一向量桶、各自独立物理索引, 重建切片池不会碰全量池和题型池的生产查询。
- **多模块共用索引**: ai-tutoring / question-analysis（已入桶）与 knowledge-graph / rag-system（锚点闭集已定但语料未建）同写 rag-full / rag-slice 索引, 靠 metadata.module 标签 + 查询侧 Filter 下推过滤隔离, 防止其他模块的相似向量挤占 top-K。
- **普通桶放原文**: 源语料 + 切片视图上传 COS 普通桶, 前端「查看原文」通过接口按 key 读该桶。

## 职责

- **索引构建脚本（build_index.py）**: 阶段3 索引构建——jsonl → embedding → COS 向量桶批量写入（双池双向量/条件式, 支持幂等 --clear）。
- **原文上传脚本（upload_cos.py）**: 阶段2 原文上传——读 md 文件头标注的 COS 路径, 把源语料/切片视图写到普通桶。
- **向量基座（vector_store.py）**: 底层向量封装——dashscope 768 维 embedding、写向量、查相似、桶/索引路由、客户端单例。
- **查询侧（query.py）**: 语料加载、按模块构造过滤条件、全量池/切片池双路召回 + 本地 BM25、key 反查。
- **配置（settings.py + .env.example）**: 向量桶/普通桶名、索引路由表、embedding 说明。

## 高层业务调用链

```
切片/整篇 .md
  → slice_corpus.py 生成 jsonl  (scripts/rag/data/rag_slices*.jsonl, 每行 {text, summary, tags})
  → build_index.py 阶段3: 逐块 embed → put_vectors(批20) → rag-1318177119/rag-full|rag-slice
      ├ 切片池每块写 2 key: {key}-c = embed(summary+"\n"+text) / {key}-q = embed(summary)
      └ 全量池写 1 key:  ≤5000 字符 embed(summary+全文), 超限只 embed(summary)
  → upload_cos.py 阶段2: 读 `> COS路径:` 头 → put_object → ai-edu-1318177119/rag-source|rag-slices/<模块>/...
  → 查询时 query.py:
      retrieve_vector → build_filter({"module": {"$eq": module}}) → query_vector(Filter=...)
      retrieve_dual = 全量池单向量 + 切片池双向量(-c/-q 按 key 后缀拆两路) + 本地 BM25
      orchestrate = RRF(四路) × authority × 节锚定加权 → top-K
  → generate(doubao)  +  text 反查: metadata 不含 text, 全文/全量摘要经 key 反查本地 jsonl
```

**文字链路复述**: 切片/整篇 .md 先由 slice_corpus.py 生成 jsonl（每行含 text/summary/tags）；build_index.py 阶段3 逐块 embedding、批量写入向量桶的 rag-full 或 rag-slice 物理索引——切片池每块写 2 个 key（-c 内容路 embed 摘要+正文、-q 问题路 embed 摘要）, 全量池写 1 个 key（小文件摘要+全文一起 embed, 超长只 embed 摘要）。upload_cos.py 阶段2 读 md 文件头标注的 COS 路径, 把原文/切片视图上传普通桶。查询时 query.py 按模块构造 Filter（module 精确匹配）下推到 COS 向量层召回, retrieve_dual 融合全量池单向量 + 切片池双向量（-c/-q 拆两路）+ 本地 BM25 四路, 最后用 RRF × 权威度 × 节锚定加权取 top-K 交给大模型生成；由于向量 metadata 不含 text, 全文/全量摘要通过 key 反查本地 jsonl 拿回。
