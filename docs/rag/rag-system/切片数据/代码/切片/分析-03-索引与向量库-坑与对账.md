## 隐性坑与注意事项

1. **`--clear` 清整个池不分模块**: 多模块共池(rag-full/rag-slice)下, `--clear --module rag-system` 会把该池内 ai-tutoring/question-analysis 向量一起删光, 需重灌全部模块(build_index.py:76-97)。
2. **`DEFAULT_MODULE="rag-system"` 指向无数据模块**: query.py:455 未传 module 时 Filter 筛 rag-system, 但 rag-system 无语料 → 向量召回 0 命中。当前 API 路径 current_project 默认 "ai-tutoring" 兜底才不触发(intent 签名 query.py:294), 是潜在隐患。
3. **metadata.summary 截断 ≠ embedding 摘要**: 入索引的 metadata.summary 被 2048B 预算截断, 但向量仍 embed 全量 summary; 全文/全量摘要只能经 key 反查 jsonl——**反查失败(本地 jsonl 缺块)则全文丢失**(build_index.py:158-165、query.py:584-606)。
4. **COS 索引维度建好不可改**: 索引控制台建 768/float32/cosine, embedding 显式 768 强制一致, 维度不匹配抛异常(vector_store.py:28、100-102)。
5. **put 后 10s 才可查**: COS 向量索引异步生效, 写完立即 query 会 miss(build_index.py:55、vector_store.py:127)。
6. **脚本不建索引**: 索引须控制台预建, get_index 缺失直接 sys.exit(build_index.py:117-123)。
7. **向量桶 role mode 不收普通对象**: 语料 jsonl 不能传向量桶, 只能留本地/传普通桶(build_index.py:192-194)。
8. **增量写入不是真增量**: 不带 --clear 重跑 = 全量 jsonl upsert, 已删块的旧 key 残留(除非 --clear 清池)。
9. **key 跨模块冲突**: 若无 module 段(2026-08-27 前), 两模块同名文件(完善文档 01-08)会互相覆盖——现 key 含 module 段已防(build_index.py:60-64)。
10. **查询侧 categories 不再过滤**: 2026-08-26 决策去掉类别过滤(误伤), 若旧认知"按类别筛"会得到空结果(query.py:461-463)。

## 对账要点（方案 vs 代码现状复盘）

**翻转：双池从 doc_type 区分 → 两个物理索引 + module 区分**
原始方案(design D2)称"两池同写一个 COS 索引, 用 doc_type metadata 区分"；代码落地改为 **rag-full / rag-slice 两个物理索引**, metadata 用 module 区分（不写 doc_type; doc_type 与 module 同值冗余已去掉 build_index.py:143-144）。结论 方案 vs 代码口径翻转, 以代码为准。

**方案有/代码无：rag-system 模块语料应可索引入桶**
模块 SOP 称向量桶 module 标签 rag-system、共用 rag-full/rag-slice；代码现状 **rag-system 未入 MODULE_DATA**(build_index.py:47-51、query.py:37-40), `scripts/rag/data/` 无 `rag_slices-rag-system.jsonl`/`rag_slices_full-rag-system.jsonl`（实际数据: 仅 ai-tutoring 294+23、question-analysis 317+25）；rag-system 只在 MODULE_ANCHORS 锚点闭集 + guide_pool 中文名映射 + DEFAULT_MODULE 里出现。结论 方案有/代码无: rag-system 语料尚未切片/入 MODULE_DATA/入桶。

**悬空默认值：DEFAULT_MODULE 应为 rag-system**
query.py:455 注释"未传 module 时的默认(项目介绍 RAG 上下文)"；当前实际有数据的模块是 ai-tutoring/question-analysis, 默认 Filter 指向无数据的 rag-system, 若触发则向量 0 命中。结论 悬空默认值, 需在 rag-system 语料就绪后填实或改默认。

**方案有/代码无：rag-system 完善文档应可上传普通桶**
upload_cos 靠 `> COS路径:` 头上传；rag-system `4.完善文档/*.md` 现为旧单行头 `> 模块=rag-system｜节=01｜...`(实测 01-产品定位.md 头 4 行), **无 `> COS路径:` 头 → upload_cos.py parse_cos_key 返回 None → 会被跳过不上传**(upload_cos.py:51-57)。结论 方案有/代码无: 待规范化 5 行标准头(含 COS路径)。

**设计已调整：语料 jsonl 应传 COS 作普通对象（旧设计）**
旧设计语料 jsonl 传 COS 作普通对象；代码现状向量桶 role mode 不收普通对象, 语料 jsonl 留本地(build_index.py:192-194), 原文/切片视图走普通桶 ai-edu-1318177119。结论 设计已调整, 以代码为准。

**翻转：query 侧按 categories 过滤 → 移除**
原始方案(1.13 Q5)按 categories 过滤；2026-08-26 决策**移除类别过滤**(LLM 判类别不准误伤), categories 仅签名兼容(query.py:461-463、666)。结论 方案 vs 代码口径翻转。

**注释过时：query.py 头注释双池块数**
query.py:31 注释"294 块/23 块"只反映 ai-tutoring 单模块；question-analysis 另 317+25 块, 多模块合计 294+23+317+25=659 块(实测数据)。结论 注释过时, 以实际数据为准。
