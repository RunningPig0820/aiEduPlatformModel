## 架构分工（双池 + 多模块 + 双桶）

- **双池同桶异索引**: 全量池 rag-full（整篇文档, 管整体问题）与切片池 rag-slice（细节块, 管追问）共用同一向量桶, 但各自独立物理索引; 与题型池（topic）分桶隔离——重建切片池不影响题型生产查询。
- **多模块靠 module 标签 + Filter 隔离**: 向量 key 带 module 段、metadata.module 打标, 查询侧把 module 精确匹配过滤下推到 COS 向量层, 防止其他模块的相似向量挤占 top-K。已入模块 ai-tutoring / question-analysis, knowledge-graph / rag-system 锚点已定但语料未建。
- **双桶分工**: 向量桶存向量（role mode 不收普通对象）, 普通桶存源语料 + 切片视图原文, 供前端「查看原文」。

## 关键机制

### 切片池双向量 = 语义双路召回
每块写两个向量: -c 内容路 embed(摘要+正文)、-q 问题路 embed(摘要)。因为用户查询是"问题"形态, 匹配问题侧的 -q 更准; 同块两路命中各贡献 RRF 互补。查询时按 key 后缀拆两路、归一化 key 后各自参与融合。

### 全量池条件式 embed
小文件（≤5000 字符）把摘要+全文一起 embedding, 全文进向量可被精确检索; 大语雀（上万字符）只 embed 摘要做粗召回, 防止超长文本被 embedding 模型静默截断。这是"完整可检索 vs 防截断"的取舍。

### 多路召回 + RRF 融合
全量池单向量 + 切片池双向量 + 本地 BM25 共四路召回, 用 RRF 融合, 再乘权威度、做节锚定加权取 top-K。BM25 纯本地（jieba 分词 + Okapi BM25）, 断电断网仍可用, 是向量路失败时 API 降级为纯 BM25 的兜底。

### 版本走 metadata 支持回退
version = 日期 + 全文 sha1 前缀, 语料一变版本就变, 可回退, 不占索引名（索引建好不可改, 换维度必须重建）。

### 关键取舍汇总
- **embedding 维度显式固定 768**（模型默认 1024）, 必须与已建索引一致, 维度不匹配直接抛异常——索引建好不可改。
- **索引控制台预建**: 脚本不建索引, 缺失直接报错退出, 要求控制台先建 768/float32/cosine。
- **查询不再按类别过滤**: LLM 判类别不准会误伤, 已去掉类别过滤, 只按 module 过滤。
- **写后异步生效**: 向量写入后约 10 秒才能查到, 是最终一致语义。
- **统一 key 规则**: 构建侧与查询侧同规则（{池}/{module}/{file}/{anchor}#{idx}）, 保证向量命中后能反查本地 jsonl 拿全文——因为 metadata 不含 text。
