## 隐性坑与注意事项

1. **清池不分模块**: 多模块共用一个物理索引（rag-full / rag-slice）, 对某个模块执行清池重建时, 会把该池内所有模块的向量一起删光, 需要全部重灌——多模块共池下的高危操作。
2. **默认查询模块指向无数据模块**: 未传模块时查询默认 Filter 指向 rag-system, 但 rag-system 当前没有语料, 一旦触发就是向量 0 命中。目前靠 API 层默认传 ai-tutoring 才不暴露, 是潜在隐患, 需等 rag-system 语料就绪后填实。
3. **metadata 摘要被截断但向量用全量摘要**: 入索引的 metadata.summary 有 2048 字节预算截断, 但向量仍 embed 全量摘要; 全文/全量摘要只能通过 key 反查本地 jsonl——本地缺块时全文就丢了。
4. **COS 索引维度建好不可改**: 索引在控制台预建 768/float32/cosine, embedding 必须显式 768 强制一致, 换模型/换维度必须重建索引。
5. **写后异步生效**: 向量写完要等约 10 秒才能查到, 刚写完立刻查询会 miss, 是最终一致语义。
6. **脚本不建索引**: 索引必须在控制台预建, 脚本只校验, 缺失直接退出。
7. **向量桶不收普通对象**: 语料 jsonl 无法上传向量桶, 只能留本地或传普通桶。
8. **增量写入不是真增量**: 不带清池参数重跑 = 读当前 jsonl 全量覆盖写, 已删块的旧 key 会残留。
9. **key 跨模块冲突已修**: 早期 key 无 module 段时, 两个模块同名文件会互相覆盖; 后 key 含 module 段已防住。
10. **查询侧类别过滤已废弃**: 已不再按类别过滤（LLM 判类别不准会误伤）, 若还按"按类别筛"的旧认知排查会得到空结果。

## 方案 vs 落地的复盘（原始设计 → 实际实现 → 影响）

**翻转：双池从 doc_type 区分改为两个物理索引**
原始设计（design D2）称"两池同写一个 COS 索引, 用 doc_type metadata 区分"; 实际落地改为 rag-full / rag-slice 两个物理索引, metadata 用 module 区分（doc_type 与 module 同值的冗余字段已去掉）。影响: 双池物理隔离更彻底, 但方案口径翻转, 对账以代码为准。

**方案有/代码无：rag-system 语料尚未建**
模块 SOP 要求 rag-system 打 module 标签、共用 rag-full/rag-slice 可索引入桶; 实际 rag-system 未进入模块数据表, 语料目录也没有 rag-system 的 jsonl（实际只有 ai-tutoring 294+23、question-analysis 317+25 块）。rag-system 只出现在锚点闭集、中文名映射和默认模块里。影响: rag-system 目前向量 0 命中, 需补切片/入表/入桶。

**悬空默认值：默认查询模块指向空模块**
设计注释声称默认模块应为 rag-system（项目介绍 RAG 上下文）; 实际有数据的模块是 ai-tutoring / question-analysis, 默认 Filter 指向无数据的 rag-system, 触发即 0 命中。影响: 依赖上层兜底才正常, 属潜在隐患, 需填实或改默认。

**方案有/代码无：rag-system 完善文档头未规范化**
upload_cos 靠 md 文件头 `> COS路径:` 标注来决定上传; rag-system 完善文档现在还是旧单行头（模块/节/...）, 没有 COS路径 头, 会被上传脚本自动跳过。影响: rag-system 原文还没进普通桶, 前端「查看原文」无数据, 待规范化 5 行标准头。

**设计已调整：语料 jsonl 不再传 COS 作普通对象**
旧设计把语料 jsonl 传 COS 作普通对象; 实际向量桶 role mode 不收普通对象, 语料 jsonl 留本地（供 BM25 和反查）, 原文/切片视图改走普通桶。影响: 设计调整后以代码为准, 语料本地化让 BM25 断电断网可用。

**翻转：查询侧类别过滤被移除**
原始方案按 categories 过滤召回; 后决策移除类别过滤（LLM 判类别不准会误伤）, categories 参数只作签名兼容。影响: 旧认知"按类别筛"会得到空结果, 查询只按 module 过滤。

**注释过时：双池块数口径只含单模块**
query.py 头注释写"294 块/23 块"只反映 ai-tutoring 单模块; question-analysis 另 317+25 块, 多模块合计 659 块（实测数据）。影响: 注释口径过时, 统计以实际数据为准。
