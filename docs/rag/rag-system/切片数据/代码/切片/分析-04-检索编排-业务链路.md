## 业务描述与业务场景

检索编排是 RAG 问答系统的中枢环节。面试官提问进入后, 系统先做**意图钩子**(判模块锚点 + 语义类别 + 是否需要澄清/切换模块), 再走**双池检索**(索引层切片池 + 源文档全量池, 向量 + BM25 三路召回), 经 **RRF 融合 × 权威度分层 × 页面锚定加权** 得到 top-K 命中块, 最后 doubao 生成面试口述风格答案并附引用来源。

双线并行:
- **1.6C 简洁契约线**: `POST /api/tutoring/rag/query`, 返回 `{answer, references, intent, version}` 固定结构, 面向后端/前端渲染 (api/rag.py:75-142)。
- **白盒 SSE 线**: `POST /api/rag/assistant/ask`, 逐事件 `intent → (clarify|switch) → rewrite → rerank → (boundary|token*) → done` 流式输出, 面向"可解释"演示 (api/rag_assistant.py:105-141, assistant.py:543-652)。

## 高层业务调用链(问题 → 双池检索 → RRF → 两道门 → topK → 生成)

**1.6C 端点链** (api/rag.py:75-142):
```
POST /api/tutoring/rag/query
→ verify_internal_token(x-internal-token)                       [鉴权, 非权限门]  api/rag.py:81
→ rag_core._load_all_blocks()                                    [全模块 jsonl 合并] api/rag.py:85 / query.py:436-449
→ rag_core.intent(question, current_project, history)            [LLM 意图: anchor/category/categories] api/rag.py:86
→ rag_core.rewrite_query(question, anchor, history)              [口语→检索式改写] api/rag.py:93
→ rag_core.retrieve_dual(rewritten, corpus, locked_categories)   [双池三路召回] api/rag.py:98
     ├─ retrieve_vector("rag-full")                              全量池单向量           query.py:518
     ├─ retrieve_vector("rag-slice", top_k=VEC_K+2) → _split_roles  切片池双向量 -c/-q   query.py:520-522
     └─ retrieve_bm25(question, select_corpus(blocks, corpus))   本地 BM25             query.py:523-525
     (异常 → 降级纯 BM25, 空向量结果)                            api/rag.py:100-106
→ rag_core.orchestrate(rewritten, blocks, full, bm25, it,
                        top_k=request.top_k, vec2=slice, vec3=slice_q, corpus)   [RRF×权威×锚定] api/rag.py:108-110
→ 无命中 → 拒答"语料未覆盖"                                       [非置信度范围门] api/rag.py:120-126
→ rag_core.generate(hits, rewritten)                              [doubao 生成, 不采 usage] api/rag.py:130
     (异常 → 召回清单当答案, 不空答)                              api/rag.py:131-135
→ RAGQueryResponse(answer, references, intent, version)          api/rag.py:137-142
```

**白盒 SSE 链** (assistant.py:543-652):
```
POST /api/rag/assistant/ask → pipeline_events
→ is_greeting(question) [问候 0 token 短路]          assistant.py:563-586
→ rag_core.intent(question, history, current_project) assistant.py:571
→ resolve_clarify (ambiguous & 候选≥2 & 未澄清过)    assistant.py:589-595
→ resolve_switch (switch_detected → to_anchor)        assistant.py:599-603
→ rag_core.rewrite_query                               assistant.py:606
→ recall (双池三路, 单路 2s 超时降级)                  assistant.py:611-613
→ check_boundary (范围门 0.75/0.5, 短路不调 generate)  assistant.py:616-625
→ stream_generate (ark_stream 流式, usage 结尾)       assistant.py:634-644
→ lcs_quote_match + gen_suggestions + assemble_done   assistant.py:646-652
```

**端到端文字复述**: 问题进来 → 意图钩子(判锚点/类别/澄清需求) → 查询改写(口语→检索式) → 双池三路召回(全量池单向量 / 切片池 -c/-q 双向量 / BM25 本地全文) → RRF×权威×锚定 融合排序取 top-K → 两道门(范围门仅白盒, 权限门在 Java 网关) → doubao 生成附引用。1.6C 线返回 `{answer, references, intent, version}` 固定结构; 白盒线 SSE 逐事件流式输出, boundary 短路时 0 token 拒答。
