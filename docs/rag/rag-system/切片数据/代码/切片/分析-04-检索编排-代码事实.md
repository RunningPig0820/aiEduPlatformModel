## 检索走哪几个来源(双池三路, 均带行号证据)

四路 RRF 输入 (query.py:637-641 注释 + orchestrate 参数):
1. **全量池向量路** `rag-full`: `retrieve_vector(question, vector_type="rag-full", module=corpus)` (query.py:518), 走 COS 桶 `rag-1318177119` + index `rag-full` (vector_store.py:106-121, settings.py:99-105)。语料 = 整篇文档, 实测 23 块 (rag_slices_full.jsonl)。
2. **切片池内容路** `rag-slice` (-c): `retrieve_vector(..., top_k=VEC_K+2)` 后 `_split_roles` 拆 key 后缀 `-c` (query.py:520-522, 487-504)。语料 = 细节切片块, 实测 294 块 (rag_slices.jsonl)。
3. **切片池问题路** (-q): 同一次向量召回拆出 key 后缀 `-q` 的记录 (query.py:498-500)。同块 -c/-q 双向量分别贡献 RRF (互补)。
4. **BM25 本地全文路**: `retrieve_bm25(question, select_corpus(blocks, corpus))` — jieba 分词 + 本地 jsonl 全文打分 (query.py:523-525, 565-578), 纯本地无外部依赖, 断电可用。

语料来源: `MODULE_DATA` 全模块 jsonl (ai-tutoring + question-analysis), 模块靠 `tags.module` 区分 (query.py:37-40, 436-449)。`_load_all_blocks` 合并所有池、缺失文件跳过 (query.py:442-449)。

向量层过滤: `build_filter` 仅按 `module` 做 COS `$eq` 过滤 (query.py:458-465), 防其他模块相似向量挤占 top-k; `categories` 参数保留兼容但**不再过滤** (query.py:461-463, 475)。

## RRF 融合公式/参数 (RRF_K=60)

- `RRF_K = 60` (query.py:43)。
- orchestrate 内对四个 rank 字典(全量向量/切片内容/切片问题/BM25)做并集, 每路贡献 `1.0 / (RRF_K + rank)` (query.py:650-659)。rank 为 `enumerate` 序号, 从 0 起 (query.py:643-646)。
- 最终得分 = `rrf * authority * anchor_w` (query.py:667), 按得分降序取 top_k (query.py:669-671)。
- BM25 的 key 由 `_key_of` 生成与向量 key 同规则 (`rag-{pool}/{module}/{file}/{anchor}#{idx}`) (query.py:584-592, 575), 保证两路可并集融合。

## 权威分层怎么参与排序

- 权威度来自语料块 `tags.authority`, 缺省 `0.7` (query.py:664)。
- 排序乘法因子: `score = rrf × authority × anchor_w` (query.py:667)。
- 命中项带 `authority` 字段回传 (query.py:677, 113), 供前端/生成标注。
- 实测语料 authority 取值 `{1.0(完善文档/引导问题), 0.8, 0.7(语雀等原始语料)}` (rag_slices.jsonl 首块 tags: 引导问题 authority=1.0, rag_slices_full.jsonl 首块语雀 authority=0.7)。
- 语义: 权威度作为 RRF 分数的乘性权重, 高权威块(完善文档 1.0)即使 RRF 略低也能排前。

## 两道门在哪个函数生效(重点核实)

**权限门: 代码无实现。**
- 全 rag 模块 grep `权限/角色/permission` 仅命中注释: assistant.py:549 "无 permission——Python 生产端点不产, Java 网关从 intent 转发"; api/rag_assistant.py:9 "permission 由 Java 网关产(角色门在 Java)"。
- 1.6C 端点只有 `verify_internal_token`(服务级 x-internal-token 鉴权, 非页面权限点) (api/rag.py:64, 81)。
- 结论: 方案 D4 "权限门(前置校验 当前页权限点 vs 角色)" 是 Java 网关职责, Python 检索编排侧**未落地**。

**范围门(0.75/0.5): 只在白盒 `assistant.check_boundary` 生效, 1.6C 端点没有。**
- 常量: `BOUNDARY_VEC_CONF = 0.75` / `BOUNDARY_BM_CONF = 0.5` (assistant.py:388-389)。
- 判定函数 `check_boundary`: 空 rerank → 拒答; 或 `vec_conf < 0.75 且 bm_conf < 0.5` → 拒答; 单路高即过 (assistant.py:394-408)。
- 白盒链路内调用: `vec_conf = max(vec.confidence, vec2.confidence)`, `check_boundary(rec["rerank"], vec_conf, bm_conf)` → boundary 事件 + 立即 done, 不调 generate (assistant.py:616-625)。
- 1.6C 端点**未调用** check_boundary: 只有 `if not hits: 拒答"语料未覆盖"` (api/rag.py:119-126), 无任何置信度阈值判断。
- 置信度来源: 向量 = `1 - 平均余弦距离` (query.py:481-484); BM25 = `min(1.0, top_score/10)` (query.py:577)。
