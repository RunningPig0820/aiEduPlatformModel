## 双池三路召回机制

四路 RRF 输入:
1. **全量池向量路**(rag-full): 语料 = 整篇文档, 管整体问题, 实测 23 块。
2. **切片池内容路**(rag-slice, 后缀 -c): 语料 = 细节切片块, 管细节, 实测 294 块。
3. **切片池问题路**(-q): 同一次向量召回拆出的问题向量; 同块 -c/-q 双向量分别贡献 RRF, 互补。
4. **BM25 本地全文路**: jieba 分词 + 本地 jsonl 全文打分, 纯本地无外部依赖, 断电可用。

语料 = 全模块 jsonl 合并, 模块靠 tags.module 区分。向量层过滤仅按 module 做 COS $eq 过滤(防其他模块相似向量挤占 top-k); categories 参数保留兼容但不再过滤。

## RRF 融合 × 权威分层 × 页面锚定打分

- **打分公式**: score = RRF(四路) × authority × anchor_w, 三信号相乘后按降序取 top-k。
  - **RRF**: 对四路 rank 并集, 每路贡献 1/(RRF_K + rank), RRF_K=60 —— 管多路互补, 不依赖各路分数绝对值可比。
  - **authority**: 语料块权威度(完善文档/引导问题=1.0, 切片=0.8, 语雀等原始语料=0.7, 缺省 0.7), 作为乘性权重 —— 高权威块即使 RRF 略低也能排前, 管语料可信度分层。
  - **anchor_w**: 页面锚定加权, 命中节 ×1.5 —— 管页面锚定。
- 与方案 D5 的"similarity × 问题类型 × 页面锚定"对应, 但实现用 **RRF 替代纯相似度、authority 替代问题类型匹配** —— 多路召回互补更稳, 不依赖单一相似度分数。

## 页面锚定两层 + 多模块隔离

- **页面锚定两层**: 节级(关键词 → 完善文档节 01-08) + 模块级(关键词 → 模块锚点); 白盒/1.6C 优先 LLM 结构化 intent 判定锚点, 失败回退关键词两层。
- **多模块隔离**: 四模块闭集; 向量层 module Filter 下推 + 本地选池 + intent LLM 判 anchor 三方一致, 保证跨模块相似向量不互相污染。

## 两道门设计(权限门 / 范围门)

- **权限门: Python 检索编排侧无实现**, 角色门归 Java 网关(从 intent 转发)。1.6C 端点只有服务级 x-internal-token 鉴权, 非页面级权限点。
- **范围门(0.75/0.5): 只在白盒生效** — 空 rerank 拒答; 或向量置信度 <0.75 且 BM25 置信度 <0.5 拒答; 单路高即过。命中 → boundary 事件 + 立即 done, 不调生成(0 token)。1.6C 端点没有范围门, 仅凭 hits 是否为空拒答。
- **置信度口径**: 向量 = 1 - 平均余弦距离; BM25 = min(1.0, top_score/10)。RRF 分数量级小(约 0.01~0.05)不能直接当置信度与 0.75/0.5 比, 所以范围门必须另用召回 confidence。

## top-K 与 token 真算

- **top-K 分层**: 生成用块数 5; BM25 召回 10; 向量召回 12; 白盒 rerank 回传 3; 评测 hit@k 5。
- **token 真算三处结论不同**:
  - 白盒 SSE 线**真采**: 流式 include_usage + usage chunk 解析, 流末尾 yield usage, 组装 prompt/completion/cache_hit/total —— 语雀"现有代码在丢 usage"的坑**已修**。
  - 评测线**真采**: 生成时读 usage_metadata → 算 cost。
  - **1.6C 端点不采**: 非流式且不传 return_usage, 响应模型无 usage 字段 → 这条线 token 成本不可见。
  - **embedding 侧不抓**: 只返回向量, 未读 usage.total_tokens, 方案 D7 计划的 embedding token 统计落空。

## 死代码与类别过滤(两个决策)

- **rag_query() 是死代码且调用即崩**: 定义完整顶层问答入口但全仓库无调用(两个端点各自内联重排链路), 函数体引用未定义变量 strategy, 一旦调用立即 NameError。
- **类别过滤已禁用(1.13.2 决策)**: intent 仍产出 locked_categories(9 类闭集), 但检索层不再按类别过滤 —— 根因是 LLM 判类别不准会误伤相关块, 参数保留兼容。

## 白盒事件时序冻结 + 降级不破结构

- **白盒事件时序冻结**: intent → (clarify|switch) → rewrite → rerank → (boundary|token*) → done; boundary 短路纪律(不调 generate, 0 token)。
- **降级机制**: 向量路异常/超时 → 1.6C 降级纯 BM25(空向量结果)、白盒单路 2s 超时空路降级 + degraded 标记; 无命中 → 1.6C 拒答"语料未覆盖"、白盒 boundary 话术; 生成异常 → 1.6C 召回清单当答案(不空答)、白盒 error 事件 + 写死话术 + 召回清单。
- **降级不破结构**: 四条降级路径响应结构不变, 前端只按同一结构渲染。
