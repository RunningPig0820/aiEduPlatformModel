## 踩过的坑(隐性坑 10 条)

1. **rag_query() 是 NameError 死代码**: 定义完整问答入口但函数体引用未定义变量 strategy, 调用即崩; 全仓库无调用, 1.6C 端点与评测都明确绕开。
2. **1.6C 端点没有范围门**: 置信度阈值 0.75/0.5 只存在于白盒 check_boundary; 1.6C 端点仅凭 "hits 是否为空" 拒答 —— 低置信但非空命中会直接进生成, 可能硬编。
3. **权限门是 Java 的事**: Python 侧没有页面权限点过滤, 只有 x-internal-token 服务鉴权; 方案 D4 的"按角色过滤可检索页"在 Python 检索编排中不存在。
4. **1.6C 端点不采 usage**: 虽然 ark_stream 已修好流式 usage(白盒真采), 但 1.6C 走 generate 非流式且不传 return_usage, 响应模型无 usage 字段 → 这条线上的 token 成本不可见。
5. **embedding token 未统计**: embed() 不抓 usage.total_tokens, 方案 D7 计划的 embedding 单列成本落空。
6. **categories 过滤语义脱节**: intent 仍花 LLM 成本产出 locked_categories, 但检索层已禁用类别过滤(1.13.2), 产了不用。
7. **双向量 -c/-q 占 top-k**: 切片池每块双向量, 向量 top-k 需 VEC_K+2 补偿; orchestrate 同块两路各自贡献 RRF, 逻辑对但检索成本翻倍。
8. **RRF 分数量级小**: RRF 得分约 0.01~0.05(1/(60+rank)), 不能直接当置信度与 0.75/0.5 阈值比 —— 所以范围门必须另用召回 confidence。
9. **BM25 置信度粗糙**: min(1.0, top_score/10) 是经验标定, 与向量置信度(1-平均距离)不同量纲, 双阈值并比有口径差异。
10. **权威度缺省 0.7**: 语料块缺 authority 标签时按最低档 0.7 参与乘性排序, 会系统性压低无标签块的最终分。

## 对账复盘(方案/文档 有, 代码无 6 条)

**1. 双池结构翻转(方案 D2)**
- 原始方案: 索引层 QA(doc_type=qa) + 源文档池(source) 双池; 语雀问题4"预写答案 + 索引层 QA"。
- 实际落地: 切片池(pool=slice) + 全量池(pool=full), 无 doc_type 概念; 引导问题块(authority 1.0)作为"QA 层"混入切片池, 用 tags.pool + tags.module 区分。
- 差异影响: "预写答案 + 索引层 QA" 演化为 双池 + 双向量, 检索语义与方案命名不同。
- ⚠️翻转: 双池结构与 D2 不对应, doc_type 不存在, QA 层并入切片池。

**2. 权限门未落地(方案 D4)**
- 原始方案: 权限门(前置校验 当前页权限点 vs 角色)。
- 实际落地: Python 检索编排无实现, 角色门归 Java 网关; 1.6C 端点只有服务级 x-internal-token 鉴权。
- 差异影响: Python 侧无法按角色过滤可检索页, 页面级权限依赖 Java 网关。
- ⚠️翻转: D4 权限门在 Python 侧没有对应代码。

**3. 范围门只落白盒(方案 D4/D5)**
- 原始方案: 范围门阈值 0.75/0.5; 05-技术实现.md 写"索引层 top-K=1~3/阈值0.75, 源文档池 top-K=3~5/阈值0.5"。
- 实际落地: 只在白盒 check_boundary 生效; 1.6C 端点没有, 仅 hits 为空拒答; top-K 全局 5。
- 差异影响: 1.6C 线低置信非空命中直接进生成, 可能硬编; 文档写的分池阈值/top-K 与代码不对应。
- ⚠️翻转: 范围门仅白盒落地, 1.6C 缺失。

**4. token 真算部分落地(方案 D7)**
- 原始方案: token 真算, 修"现有代码在丢 usage"。
- 实际落地: ark_stream 已修(include_usage + usage chunk 解析), 白盒/评测真采; 但 1.6C 端点不采、embedding 侧 embed() 不抓 usage.total_tokens。
- 差异影响: "丢 usage"坑在白盒/评测修好, 1.6C 线 token 成本仍不可见, embedding 单列成本落空。
- ✅落地: 白盒 SSE 线与评测线 usage 真采已修复。
- ⚠️翻转: 1.6C 端点不采、embedding 不抓, D7 未全量落地。

**5. 打分公式替换(方案 D5)**
- 原始方案: score = similarity × 问题类型 × 页面锚定。
- 实际落地: 用 RRF 替代 similarity(四路融合), authority 替代"问题类型匹配", 页面锚定保留为乘性权重。
- 差异影响: 排序信号变为 多路 RRF 互补 × 语料权威分层 × 页面锚定, 更稳但公式与方案字面不同。
- ⚠️翻转: 打分公式实现替换。

**6. 类别过滤回退(1.13 决策)**
- 原始方案: 1.13 决策切片池按类别过滤。
- 实际落地: 已回退禁用, 参数保留、代码不筛, 与 intent 仍在产出的 locked_categories 字段脱节。
- 差异影响: LLM 判类别不准时不再误伤相关块, 但 intent 仍为产出 locked_categories 花 LLM 成本(产了不用)。
- ⚠️翻转: 类别过滤决策回退。
