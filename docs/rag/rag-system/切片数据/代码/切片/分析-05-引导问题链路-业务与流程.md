## 业务描述与业务场景

**业务描述**：RAG 项目介绍助手的"引导问题"机制——每个功能页进页面/每次问答完成后，前端展示可点击的候选问题，引导用户围绕项目介绍/操作流程/数据关联/开发难点四个主方向追问，并下沉 RAG 引擎/链路/契约的桥接题。核心约束：**引导不能自由发挥**——开始引导 guide / 结束建议 done.suggestions 都必须围绕底座池（GUIDE_POOL）取原题，保证池内问题都能被语料答出。

**业务场景**：
- 学生/面试官进入某功能页（当前页锚点 current_project），第一屏展示 3 条入门级引导题（"能不能先介绍一下RAG项目？"级别），点击即发起问答
- 每次问答完成后，done 事件携带 2~3 条池内原题作为"结束建议"，引导继续追问（必含 ≥1 条 RAG 桥接题）
- 用户发"你好"问候时，0 token 返回固定欢迎语 + 入口池建议（不 recall 不 generate）
- 多模块切换（AI答疑/知识图谱/题型分析/RAG项目）时，引导语随 current_project 走各自模块池

## 职责

**职责**：把每模块"引导问题.md/问题列表.md"的编号问题沉淀成 Python 静态底座池（GUIDE_POOL），并向前端/白盒链路提供 0 token 的引导候选（开始引导 + 结束建议 + 问候分支）。
**不做什么**：不做 LLM 生成引导语（0 token，llm 参数保留签名兼容但不再调用）；引导问题纯问题不切片进全量池；不做入口引导问题的语料可答性自检（可答性由评测集验证）。
**分工要点**：
- **guide_pool.py**：引导底座池唯一事实源——GUIDE_POOL 数据结构、pool_for 兜底、scope_questions 去重、entry_for 入口模板
- **rag_assistant.py**：API 层——GET /guide 白盒透传 current_project
- **assistant.py**：编排层——guide() 入口池 3 条、gen_suggestions() 结束建议池内原题、问候分支 welcome
- **query.py**：模块锚点闭集 MODULE_ANCHORS 四模块（含 rag-system），引导题点击后走正常检索链路

## 高层业务调用链（前端引导候选 → guide_pool → 查询入口）

```mermaid
flowchart LR
    A[前端功能页<br/>current_project 锚点] --> B[GET /api/rag/assistant/guide<br/>白盒透传 current_project]
    B --> C[assistant.guide<br/>entry_for 入口池]
    C --> D[guide_pool.entry_for<br/>_ENTRY_TEMPLATES 模板+模块中文名]
    D --> E[返回 3 条 {title,direction}<br/>0 token 非 SSE]
    A -- 点击引导问题 --> F[POST /api/rag/assistant/ask]
    F --> G[pipeline_events<br/>intent→greeting/clarify/switch→rewrite→rerank→boundary/token*→done]
    G --> H[done.suggestions<br/>gen_suggestions 池内原题 2~3 条]
    H --> I[guide_pool.pool_for<br/>rag 组≥1 + 主方向随机]
    G -.问候分支.-> J[is_greeting→固定 WELCOME_MSG<br/>+ _spread_pool_suggestions 入口池]
    J -.0 token 直接 done.-> K[不 recall 不 generate]
```

文字链路复述：前端功能页按 current_project 锚点请求开始引导（GET /guide，白盒透传模块 id）；编排层 guide() 经入口池 entry_for（通用模板 + 模块中文名）随机抽 3 条返回 {title,direction}，0 token 非 SSE。用户点击引导问题走 POST /ask 进入 pipeline_events 正常检索链路（intent→greeting/clarify/switch→rewrite→rerank→boundary/token*→done）；每次问答 done 事件携带 gen_suggestions 生成的池内原题 2~3 条（必含 ≥1 条 rag 组）。问候分支 is_greeting 命中 → 0 token 直接 done，返回固定欢迎语 + 入口池建议，不 recall 不 generate。
