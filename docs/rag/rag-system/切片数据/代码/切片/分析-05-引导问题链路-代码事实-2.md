### 引导问题与查询链路衔接（索引层入口）

- **引导问题是"索引层入口"**：前端引导候选 → 点击变成普通问题 → `POST /ask` → `pipeline_events` 白盒链路（assistant.py:543-652）。事件时序（冻结）：`intent → (greeting|clarify|switch) → rewrite → rerank → (boundary|token*) → done`（assistant.py:549-560）。
- 引导题在链路中的落点：intent 模块锚定（MODULE_ANCHORS 四模块，query.py:68；rag-system 关键词 rag/检索/召回/重排/向量/bm25/rrf/多路/知识库，query.py:73）→ recall 双池三路（全量向量 rag-full + 切片向量 rag-slice 各 2s 超时降级 + BM25，anchor 选池，assistant.py:91-133）→ rerank 精排 Top-K=3（assistant.py:139-155）→ generate（assistant.py:411-477）。
- **池内原题直接返回，不做 LLM 改编**：assistant.py:326-331 注释明确"用户实测反馈：LLM 改编'换提问方法'会偏离池内范围——如把池内'题目记录/错误事件/掌握度三张表关系'编成'题目数据怎么和向量索引关联'（引入池外概念'向量索引'），新问题没对应切片 → 学生点了匹配不到答案（问题6 翻版）"。结论：结束引导直接返回池内原题（0 token，100% 可答），"双向量 -q 问题路对池内原题命中 sim~0.99"。
- **结束建议 gen_suggestions**（assistant.py:347-355）：`module = anchor if anchor in MODULE_ANCHORS else FALLBACK`；`_pool_suggestions(module)` 必含 ≥1 条 rag 组 + 其余主方向随机，返回 2~3 条去重（assistant.py:334-344）。`llm` 参数保留签名兼容但不再调用（test_assistant_suggestions.py:53-60）。
- **问候分支**（assistant.py:358-380, 580-586）：`is_greeting` 关键词预检（你好/您好/hello/hi/哈喽/嗨/hey/在吗，短句 ≤8 字才命中防误杀，assistant.py:361, 366-372）；命中 → 0 token 直接 done，answer=固定 WELCOME_MSG + `_spread_pool_suggestions(module)` 从入口池抽入门级题（assistant.py:375-380, 583-585）。
- **guide 与 ask 的 current_project 缺省不一致（）**：guide 接口缺省/未知 → FALLBACK_MODULE=**ai-tutoring**（rag_assistant.py:148-149）；ask 请求模型 `current_project` 默认值 = **rag-system**（"缺省=rag-system（对齐后端 api.md，会话入口默认聊 RAG 项目）"，models/rag_assistant.py:18-19）。

### rag-system 引导问题现状（对账重点）

- **GUIDE_POOL 无 rag-system 池**（guide_pool.py:309 注释待加）。current_project=rag-system 时的实际行为：
  - `pool_for("rag-system")` → `GUIDE_POOL.get("rag-system", GUIDE_POOL["ai-tutoring"])` → 取 **ai-tutoring 池**（guide_pool.py:321）
  - guide() 判定 module="rag-system"（在 MODULE_ANCHORS 内，assistant.py:535-536），`entry_for("rag-system")` → 用 ai-tutoring 池 + `_MODULE_ZH["rag-system"]="RAG项目"` 模板生成 4 条入口题（guide_pool.py:369-370, 354）
  - 结束建议 gen_suggestions(answer, anchor="rag-system") → `_pool_suggestions("rag-system")` → ai-tutoring 池（assistant.py:353-355）
  - 测试确认：`scope_questions("rag-system") == scope_questions(FALLBACK_MODULE)`（test_guide_pool.py:54-55）；`_pool_suggestions("rag-system")` 返回全在 ai-tutoring 池（test_assistant_suggestions.py:86-88）
- **结论**：当前 rag-system 页面的引导题/结束建议实际是 **ai-tutoring 的池 + "RAG项目" 入口模板**；rag-system 自己的 9 视角 57 问问题列表尚未生成，生成后需同步 `GUIDE_POOL["rag-system"]` 5 组（7. 引导问题/处理方案/readme.md:3,36）。

### 设计要点

- **引导静态池 0 token**：开始引导 guide / 结束建议 done.suggestions 都从底座池取原题，严禁 LLM 生成（降本 + 保证可答）。底座池存在的意义 = 对齐语料可答（guide_pool.py:8-15, assistant.py:348-351）。
- **入口引导 vs 结束引导分层**：入口给入门级简单题（用户还不知道怎么用，第一屏，如"能不能先介绍一下X？"）；难题留给结束建议（用户问过一轮有上下文）——"难题留给结束建议"，入口题短句式、无技术难点词（assistant.py:521-523, test_guide_pool.py:74-79）。
- **rag 组是 RAG 桥接子集**：与其他主方向可重复、scope 去重；但 gen_suggestions 强制必含 ≥1 条 rag 组，保证每次结束引导都留一条 RAG 引擎/链路/契约桥接题（assistant.py:334-344, C5 测试 test_assistant_suggestions.py:41-45）。
- **多模块通用不写死**：入口引导用通用模板 + 模块中文名动态替换，避免新模块复制"AI答疑"字样（驴唇不对马嘴）；每模块可加 entry 组定制入口重点（guide_pool.py:125-127, 342-347, 358-370）。
- **引导题可答性由"池内原题 + 双向量 -q 问题路"双保险**：池内原题 100% 有切片；点击后经 -q 问题路命中 sim~0.99（assistant.py:330-331）。
