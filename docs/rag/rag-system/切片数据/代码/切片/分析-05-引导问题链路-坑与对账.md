## 隐性坑与注意事项

- **⚠️ rag-system 引导题未入池（最大坑）**：rag-system 页面引导语实际是 ai-tutoring 池的题（只是入口模板名换成了"RAG项目"）。入口模板题（"RAG项目是干什么的？"）点击后 anchor 判定、检索走 rag-system 语料池，但池内没有 rag-system 专属引导题，结束建议也是 ai-tutoring 的题——在 rag-system 问题列表生成并同步 GUIDE_POOL 前，引导题与语料池存在错位风险（guide_pool.py:309 + 处理方案 readme.md:3）。
- **guide 缺省 vs ask 缺省不一致**：guide 缺省/未知 → ai-tutoring（rag_assistant.py:148-149）；ask 请求 current_project 默认 rag-system（models/rag_assistant.py:18-19）。前端不传 current_project 时，进页面引导给 ai-tutoring 题，点击却默认走 rag-system 锚点——两入口缺省不同，易造成"引导题与检索池不匹配"。
- **入口模板题的"可答性"依赖语料**：入口模板是通用句式 + 模块中文名，guide_pool.py:340-341 注释记录 2026-08-26 删了 rag 入口题"这个功能的底层是怎么实现的?"——太泛，"底层"同时匹配架构/ActionMeta/召回等一堆块，没有明确答案，检索答非所问；入口只保留可答的具体功能题。
- **LLM 改编引导语是已知翻车点**：曾用 LLM 改编"换提问方法"导致新问题引入池外概念、匹配不到答案（问题6 翻版），已改为池内原题直出（assistant.py:326-331）。
- **scope_questions 不是生产调用路径**：全量去重视图仅测试用，生产 guide()/gen_suggestions() 走入口池/抽样，不经过 scope_questions（assistant.py:334-344, 537-539）。
- **问候关键词短句门槛防误杀**：`is_greeting` 限定 0 < len ≤ 8，避免"你好，请介绍一下这个项目"（含问候词但语义是真实提问）被误判为问候而吞掉真实检索（assistant.py:366-372）。
- **guide() 的 direction 值已替换旧枚举**：旧 architecture/data_flow/evaluation 换成 intro/operation/data_relation/difficulty/rag，后端联调清单已记录——Java/前端如按旧值硬编码需适配（assistant.py:524-525）。

## 对账要点

对账表转自然语言复盘（原始方案 → 实际落地 → 业务影响），逐条保留 ⚠️翻转/✅落地 结论句：

1. **引导静态池随机 2~3 条、严禁动态生成** — 语雀-问题8:66-67 口径"由后端从预设静态池随机抽取2~3条引导建议…严禁动态生成引导语"。实际落地：gen_suggestions 池内原题 2~3 条（必含 ≥1 rag），llm 参数保留不调用。**✅ 落地**。
2. **suggestions_pool.json** — 语雀-问题8:69-85 口径"提前让后端准备一个 suggestions_pool.json"。实际落地：用 Python dict `GUIDE_POOL` 硬编码，无 json 文件。**⚠️ 形式不同（dict 替代 json）**。
3. **引导方向组** — 语雀-问题8:76-84 4 组（project_intro/operation/data_relation/difficulty）。实际落地：5 组（intro/operation/data_relation/difficulty + **rag** 桥接子集）。**⚠️ 新增 rag 组**。
4. **禁区拒答** — 语雀-问题8（08-25 spec）"仅 RAG 项目；AI答疑/知识图谱/题型分析=禁区拒答"（问题8:30-32, 127-128）。实际落地：GUIDE_POOL 明确为 ai-tutoring/question-analysis/knowledge-graph 三个业务模块各建池 + rag-system 待加，走"每模块可答"路线。**⚠️ 范围反转未落地（代码走 08-21 多模块可答方向）**。
5. **引导问题=索引层 QA 变体** — design-python-project-intro-rag.md D3"UI 引导问题 = 索引层规范问题的变体写法…强制检索真实发生"；05-技术实现.md:37"索引层 QA 和引导问题…同一份，视角不同"。实际落地：guide()/gen_suggestions() 直接返回池内原题，无"变体写法"转换（assistant.py:326-331）。**⚠️ 变体文案未落地，改为池内原题直出**。
6. **引导问题与索引层** — 05-技术实现.md:37"引导问题命中索引层 → 答案可控"。实际落地：引导问题纯池不切片，点击后走双向量 -q 问题路检索切片池（assistant.py:330-331）。**⚠️ 命中路径变化（-q 问题路替代索引层 QA 池）**。
7. **接口契约 guide 缺省模块** — 无明确口径。实际落地：guide 缺省/未知 → FALLBACK=**ai-tutoring**；ask 缺省=**rag-system**。**⚠️ 两入口缺省不一致**。
8. **rag-system 引导题** — 切片清单"7. 引导问题/问题列表.md ✅ 问题进 guide_pool"；处理方案 readme"生成后同步 GUIDE_POOL['rag-system'] 5 组"。实际落地：GUIDE_POOL 无 rag-system 池（guide_pool.py:309 注释待加）；现走 ai-tutoring 池兜底。**⚠️ 方案规划有/代码暂无，待落地**。
