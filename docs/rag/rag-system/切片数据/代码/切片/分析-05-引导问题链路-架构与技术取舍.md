## 引导静态底座池 GUIDE_POOL（核心机制）

- **数据结构**：GUIDE_POOL 以 Python dict 硬编码，键=模块id，值={direction: [问题]}。每题只落一个主方向（intro/operation/data_relation/difficulty）；rag 组是 RAG 桥接子集，可与主方向重复，scope 去重。
- **方向 → 引导问题.md 节映射**：intro=项目介绍；operation=操作流程+业务流程；data_relation=数据关联+数据存储；difficulty=开发难点+架构设计+业务视角+稳定性+未来演进；rag=从以上挑桥接 RAG 引擎/链路/契约的题（完整调用链路/SSE时序/和普通RAG本质区别/ActionMeta契约/不直接写Neo4j）。
- **兜底**：FALLBACK_MODULE=ai-tutoring；pool_for(module) 未知/缺省 → FALLBACK 池。
- **已入池模块**：ai-tutoring（75 去重）/ question-analysis（70 去重）/ knowledge-graph（64 去重）三个业务模块各建池；**rag-system 未入池**（代码注释待加），当前 rag-system 页面实际走 ai-tutoring 池 + "RAG项目" 入口模板兜底。
- **scope_questions 去重机制**：directions 非空限定方向、空则主方向闭集，去重保序；rag 组与其他组重复不新增数量（断言 rag ⊆ 主方向池）。**注意：这是"全量去重视图"，生产链路 guide()/gen_suggestions() 并不调用它**（guide 只从入口池抽，gen_suggestions 靠内部 picks 去重）——仅测试断言用。

## 引导问题三入口（开始引导 / 结束建议 / 问候分支）

- **开始引导 guide**：GET 接口白盒透传 current_project；module=current_project（在模块锚点闭集内）否则 FALLBACK；从入口池 entry_for 随机抽 3 条（min(3, len(entry))）返回 {"suggestions":[{title,direction}]}，0 token 非 SSE，不占冻结时序。
- **结束建议 done.suggestions（gen_suggestions）**：每次问答 done 事件携带池内原题 2~3 条，必含 ≥1 条 rag 组 + 其余主方向随机，去重；llm 参数保留签名兼容但不再调用。
- **问候分支**：is_greeting 关键词预检（你好/您好/hello/hi/哈喽/嗨/hey/在吗，短句 ≤8 字才命中防误杀）→ 0 token 直接 done，answer=固定欢迎语 + 从入口池抽入门级题；不 recall 不 generate。
- **入口池 entry_for**：所有模块共用 4 条通用模板（intro×3 + operation×1，含 {模块} 占位）+ 模块中文名动态替换；避免新模块复制"AI答疑"字样。每模块可加 entry 组覆盖定制入口重点。

## 引导问题与查询链路衔接（索引层入口）

- **引导问题是"索引层入口"**：前端引导候选 → 点击变成普通问题 → 白盒链路 pipeline_events。事件时序（冻结）：intent → (greeting|clarify|switch) → rewrite → rerank → (boundary|token*) → done。
- **链路落点**：intent 模块锚定（MODULE_ANCHORS 四模块，rag-system 关键词 rag/检索/召回/重排/向量/bm25/rrf/多路/知识库）→ recall 双池三路（全量向量 + 切片向量各 2s 超时降级 + BM25，anchor 选池）→ rerank 精排 Top-K=3 → generate。
- **池内原题直接返回，不做 LLM 改编**：曾用 LLM 改编"换提问方法"会偏离池内范围——如把池内"题目记录/错误事件/掌握度三张表关系"编成"题目数据怎么和向量索引关联"（引入池外概念"向量索引"），新问题没对应切片 → 学生点了匹配不到答案。结论：结束引导直接返回池内原题（0 token，100% 可答），"双向量 -q 问题路对池内原题命中 sim~0.99"。

## rag-system 引导问题现状（对账重点）

- GUIDE_POOL 无 rag-system 池。current_project=rag-system 时的实际行为：pool_for("rag-system") → 取 ai-tutoring 池；guide() 判定 module="rag-system" 在锚点内，entry_for 用 ai-tutoring 池 + 模块中文名"RAG项目" 模板生成 4 条入口题；结束建议 gen_suggestions(anchor="rag-system") 走 _pool_suggestions("rag-system") → ai-tutoring 池。测试确认 scope_questions("rag-system") == scope_questions(FALLBACK)。
- **结论**：当前 rag-system 页面的引导题/结束建议实际是 **ai-tutoring 的池 + "RAG项目" 入口模板**；rag-system 自己的 9 视角 57 问问题列表尚未生成，生成后需同步 GUIDE_POOL["rag-system"] 5 组。

## 设计要点

- **引导静态池 0 token**：开始引导 guide / 结束建议 done.suggestions 都从底座池取原题，严禁 LLM 生成（降本 + 保证可答）。底座池存在的意义 = 对齐语料可答。
- **入口引导 vs 结束引导分层**：入口给入门级简单题（用户还不知道怎么用，第一屏，如"能不能先介绍一下X？"）；难题留给结束建议（用户问过一轮有上下文）——"难题留给结束建议"，入口题短句式、无技术难点词。
- **rag 组是 RAG 桥接子集**：与其他主方向可重复、scope 去重；但 gen_suggestions 强制必含 ≥1 条 rag 组，保证每次结束引导都留一条 RAG 引擎/链路/契约桥接题。
- **多模块通用不写死**：入口引导用通用模板 + 模块中文名动态替换，避免新模块复制"AI答疑"字样（驴唇不对马嘴）；每模块可加 entry 组定制入口重点。
- **引导题可答性由"池内原题 + 双向量 -q 问题路"双保险**：池内原题 100% 有切片；点击后经 -q 问题路命中 sim~0.99。
