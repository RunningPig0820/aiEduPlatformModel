## 业务描述与业务场景

**业务描述**：评测 agent 是 rag-system 的"质量把关工具"——预写评测集（Q&A + 预期引用 + 预期要点），对每条问题走一遍真实检索→生成→判分，产出 hit@k（检索是否捞得对）、answer_quality 质量分（答案是否答得好）、cost（贵不贵）、latency（快不快），trace 逐条落盘 + 聚合报告 + 跨语料版本对比，用数据证明"这套 RAG 系统靠谱"。

**业务场景**：
- 面试官问"怎么证明 RAG 有效"，亮出评测集 + hit@k + 质量分 + 成本/耗时报告（语雀-问题12 的"证明方案"）
- 改切片策略/检索参数/提示词后，`run_eval.py --compare` 对比前后 hit@k/质量分变化（回归验证）
- 定位问题：先测 hit@k 看"检索捞得对不对"，再测质量分看"答案答得好不好"，分层定位（design D3）

**定位**：内部评测工具（design Non-Goals），离线/手动触发，不碰 `/api/rag/ask` 主链路（design Migration Plan 第 4 条）。

## 职责

**职责**：评测集加载与格式校验 → 单条评测（真实检索 + hit@k + 生成 + LLM 判分 + 引用校验 + cost/latency）→ 逐条 trace 落盘 → 聚合指标 → 报告对比。
**不做什么**：不做线上/生产评测服务；不引入 RAGAS 全量框架（design Non-Goals，聚焦 hit@k + LLM 判分两个信号）；不自动改语料；不采集真实用户反馈。
**分工要点**：判分核心 `core/rag/eval_agent.py`（纯函数 hit_at_k / precision_at_k / calc_cost / _score_from_covered + LLM 判分 + 单条执行 + 聚合）；评测执行入口 `scripts/rag/run_eval.py`（CLI --compare + trace/报告落盘）；评测集校验 `scripts/rag/eval_dataset.py`（闭集/字段/最小条数）；评测集数据 `scripts/rag/data/eval/ai-tutoring.jsonl`。

## 高层业务调用链（eval集→真实检索→生成→判分→报告）

```mermaid
flowchart TD
    A[ai-tutoring.jsonl 6条评测集] --> B[eval_dataset.load_dataset 格式校验]
    B --> C[run_eval.run_evaluation 逐条]
    C --> D[eval_agent.run_eval_case]
    D --> E[rag_core.intent 意图钩子 anchor/locked_categories]
    E --> F[rag_core.retrieve_dual 双池三路召回: 全量向量 + 切片-c + 切片-q + BM25]
    F --> G[rag_core.orchestrate RRF×authority×节锚定 → top-5]
    G --> H{question_type 边界拒答?}
    H -- 是 --> I[_boundary_trace: check_boundary 低置信断言 → 固定话术 + 0 token, score=5/0]
    H -- 否 --> J[hit_at_k + precision_at_k 纯函数]
    J --> K[rag_core.generate doubao 生成答案 + usage]
    K --> L[judge_quality: LLM 只报 covered_count/fabricated/rationale]
    L --> M[_score_from_covered 确定性硬算 score 0~5, 编造封顶3]
    M --> N[_quoted_check: lcs_quote_match 引用 ⊆ 召回块]
    N --> O[trace dict: recall/hit/score/quoted/cost/latency]
    O --> P[trace_latest.jsonl 逐条落盘]
    P --> Q[aggregate 聚合: hit@k/质量分/cost/latency/precision/quoted]
    Q --> R[reports/&lt;version&gt;.json]
    R --> S{--compare?}
    S -- 是 --> T[_compare 与上一份报告对比 4 指标变化]
```

**文字链路复述**：评测集 `ai-tutoring.jsonl`（6 条）→ `eval_dataset.load_dataset` 做格式校验 → `run_eval.run_evaluation` 逐条评测 → `eval_agent.run_eval_case` 执行单条 → 先 `rag_core.intent` 拿意图锚点（anchor/locked_categories）→ `rag_core.retrieve_dual` 双池召回（全量向量 + 切片-c + 切片-q + BM25）→ `rag_core.orchestrate` 做 RRF×authority×节锚定出 top-5 → 判断 question_type 是否边界拒答：是则走 `_boundary_trace`（check_boundary 低置信断言 → 固定话术 + 0 token，score=5/0）；否则纯函数算 hit_at_k/precision_at_k → `rag_core.generate` 用 doubao 生成答案（带回 usage）→ `judge_quality` LLM 只报 covered_count/fabricated/rationale → `_score_from_covered` 确定性硬算 score 0~5（编造封顶 3）→ `_quoted_check` 用 lcs_quote_match 校验引用 ⊆ 召回块 → 组装 trace dict（recall/hit/score/quoted/cost/latency）→ `trace_latest.jsonl` 逐条落盘 → `aggregate` 聚合（hit@k/质量分/cost/latency/precision/quoted）→ `reports/<version>.json` → 若带 `--compare` 与上一份报告对比 4 指标变化。
