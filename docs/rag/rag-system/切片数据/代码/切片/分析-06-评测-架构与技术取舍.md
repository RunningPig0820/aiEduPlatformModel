## 判分机制：answer_quality 怎么评

1. **LLM 判分只报事实、不报分数**：判分 prompt 要求模型只输出 `{"covered_count": 覆盖了几条预期要点, "fabricated": 是否有编造, "rationale": 理由}`，并明确"分数由外部按规则计算"。这消除了 LLM 直接出分时的百分比计算波动。
2. **编造判定依据**：答案表述"在任意一块语料中有直接原文或合理推断支撑即不算编造"；语料含多源（完善文档/代码/坑档案/语雀/OpenSpec）有出处就不算；"语料块因 600 字截断导致无法验证的部分，不算编造"。判分 prompt 实际拼接前 4 块语料 × 每块 600 字。
3. **分数确定性硬算**：按覆盖比例分档 100%→5、≥80%→4、≥60%→3、≥40%→2、>0%→1、0%→0；fabricated 为真时 min(base, 3) 封顶 3 分——"编造权重高于遗漏"。注意 covered<=0 时直接 0 分，编造封顶只在覆盖>0 时生效。
4. **判分重试**：解析失败重试 1 次，仍失败返回 score=0 + judged=False（判分失败记 0 分而非剔除）。
5. **判分模型**：与生成同模型（doubao），temperature 0.0 + 关 thinking + 超时 30s + 不重试；生成则 temperature 0.2、超时 60s、重试 1 次——能力对齐，避免"自己人评自己"的模型偏差。

## 检索质量指标：hit@k 与 precision@k 互补

1. **命中判定**：expected 引用与召回块 file 做双向子串匹配；新格式 expected = 承载答案的源文件标识（全量池/切片池文件名），旧格式兼容含节号。
2. **hit_at_k**：expected_references 中命中召回 top-k 的比例（0~1，可多条引用部分命中）；k 默认 5（由 3 改 5，对齐生成上下文 top-5）。
3. **precision_at_k**：召回 top-k 中相关块占比（分母=k）。与 hit@k 互补——一个看"该捞的捞到没"，一个看"捞上来的干不干净"，分层定位检索问题。
4. **trace 双口径**：同时存 hit（bool，至少一条引用命中）与 hit_score（比例）。

## 单条评测执行机制

1. **真实检索原语、不降级**：加载双池语料 → 意图钩子拿 anchor/locked_categories → 双池召回 → 四路 RRF 出 top-K。**刻意不走带降级语义的线上问答入口，向量挂了就暴露，不让降级掩盖问题**——这是"评测集自证"可信度的关键。
2. **边界拒答类型短路**：question_type 为"边界拒答"直接走边界 trace，不进生成/判分。
3. **正常路径**：hit@k + precision@k → 生成答案（带回 usage）→ LLM 判分。
4. **引用校验**：空答案（拒答/降级）直接 valid；否则 LCS 硬匹配（连续 ≥8 中文字符/12 英文字符窗口命中即 is_quoted）算 quoted_keys，断言引用 ⊆ 召回块——纯函数、无 LLM，可单测可入评估。
5. **cost/latency**：cost 按 doubao 单价纯函数计算（prompt/1000×0.003 + completion/1000×0.009）；latency 拆 retrieve/generate/total 三段；version 是全语料内容指纹（sha1 前 6 位 + 日期），跨版本可比。

## 边界拒答评测机制

- 复用 check_boundary：rerank 空 → 拒答；或向量置信 < 0.75 且 BM25 置信 < 0.5 → 拒答（双路都低于才拒答）。
- 向量置信取全量/切片最大值（1.13 双池后：任一池置信够即不算低）；拒答正确 score=5、失败 score=0；0 token（不进生成/判分）；引用为空。

## 评测执行与报告机制

- **执行流程**：加载评测集 → 逐条评测 → 聚合 → 逐条 trace 落盘 + 报告落盘（按语料版本命名）。
- **报告对比**：与最后一份历史报告对比 hit@k 平均 / 质量分平均 / 总成本 / 平均耗时 4 指标，标 ↑/↓/=。
- **报告内容**：条数、hit@k 平均 + 命中条数、precision@k 平均、引用合法率、质量分平均 + 判分率、平均耗时、总成本。
- **评测集校验**：question_type 闭集（项目介绍/操作/数据关联/难点/最危险/边界拒答）；每模块最少 5 条；逐条校验必填字段；curation 错误当场抛错不静默。
- **评测集数据**：当前 6 条 = 5 类正常各 1 + 边界拒答 1（"帮我写一封辞职信。"）；引用混用全量池与切片池文件名；无 rag-system 评测集。

## 设计要点

- **评测走真实检索原语、不降级**：评测要看真实质量，向量挂了就暴露，不让 API 降级语义掩盖问题——这是"评测集自证"可信度的关键。
- **判分确定性硬化**：LLM 只报事实（covered_count/fabricated/rationale），分数由硬算函数得出 → 可复现、范围可控。
- **编造封顶 3 分**：编造权重高于遗漏——宁可漏要点也不许编，符合面试防御场景。
- **hit@k 与 precision@k 互补**：一个看"该捞的捞到没"，一个看"捞上来的干不干净"，分层定位检索问题。
- **引用校验纯函数化**：quoted 用 LCS 硬匹配（无 LLM），可单测可入评估。
- **cost/latency 可观测**：cost 纯函数 + latency 三段时间 + usage 汇总，报告同时给"贵不贵/快不快"。
- **聚合单一入口**：聚合输出 10+ 指标，报告/对比/CLI 全复用同一份数据。
