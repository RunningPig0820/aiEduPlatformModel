## 隐性坑与注意事项

- **hit_cases 与 hit_score 是两套口径**：hit_cases 按"任一引用命中即算"（bool 化），hit_at_k_avg 按引用命中比例平均。最新报告 hit_at_k_avg 0.583 但 hit_cases 5/6——"5 条有命中"不等于"引用命中比例高"，看报告两个数要一起看。
- **判分失败被记 0 分、不是剔除**：判分解析两次失败会记 score=0 + judged=False，拉低质量分平均；聚合里的判分率 < 1 就是有判分失败的信号。
- **编造封顶只在覆盖>0 时生效**：covered=0 直接 0 分，编造分支不参与；若预期"0 覆盖 + 有编造"应更重罚，但代码没有。
- **判编造的语料看不全**：只拼前 4 块 × 600 字，第 5 块以后及超 600 字部分模型看不到，可能漏判支撑/误判编造（prompt 里已写"600 字截断无法验证的部分不算编造"缓解）。
- **评测集只能建 ai-tutoring**：校验逻辑硬编码 module 必须等于 ai-tutoring，即使按 rag-system 加载也会因 module 不匹配抛错——这是"没有 rag-system 评测集"的代码根因，多模块评测需要先改这里。
- **报告对比只和最后一份比，不是固定基线**：取排序后最后一份历史报告对比；报告按语料版本（日期 + sha 前 6 位）命名，同一语料重跑会覆盖同名报告，可能丢历史。
- **version 是语料内容指纹、不是运行时间**：版本号 = 全语料文本哈希前 6 位 + 日期，同一天多次改语料会产生不同 sha 报告。
- **边界拒答的 precision 恒为 0** 且计进 precision 平均；hit 恒为 False，但正确拒答 score=5 计入质量分平均——边界条在检索指标上是"拖后腿"的，看指标要理解口径。
- **判分与生成共享同模型**：判分成本与生成成本同源计算（按 doubao 单价硬编码），若换模型需同步改单价，否则成本数字失真。

## 对账复盘（方案 vs 落地）

**hit@k 的 k**：方案口径（design D4、完善文档 08）都是"k 取 3"、报告 hit@3 0.80；实际落地 k=5（对齐生成上下文 top-5）。⚠️翻转：k 由 3 改 5，指标口径变化，历史 hit@3 数字不可直接对比。

**判分输出**：design D5 原设计"输出 {score, rationale}"；实际落地 LLM 只报事实（covered_count/fabricated/rationale），分数由外部硬算。⚠️翻转：判分改为确定性硬算，LLM 不再直接出分，消除百分比计算波动。

**判分维度**：design D4 原定"准确性/引用正确性/覆盖要点"三维；代码只按覆盖 + 编造两维，引用正确性改由独立的纯函数校验补位。⚠️部分落地：维度拆分，引用校验独立。

**编造封顶 3 分**：design 未提"封顶"；代码新增编造时分数封顶 3。➕代码新增硬约束：编造权重高于遗漏。

**question_type 分类体系**：design D2 原定"概览/为什么/数据流/难点/指标"；实际闭集为"项目介绍/操作/数据关联/难点/最危险/边界拒答"。⚠️翻转：分类改名并新增边界拒答类型。

**评测集规模**：design D2 原定"每模块 5 条 × 5 模块 = 25 条"；实际仅 ai-tutoring 6 条（5 正常 + 1 边界），无其他模块评测集。⚠️未覆盖：评测覆盖仅 1 个模块，与 25 条方案差距大。

**边界拒答评测**：原 25 条方案未含；代码新增边界拒答类型 + 边界 trace。➕超方案：1.13 双池后新增。

**真实检索原语**：design D3 要求"走真实检索"；实际走双池召回/编排原语不降级。✅落地：评测自证可信。

**cost/latency**：design D4 要求成本按单价 + 耗时分段；实际成本纯函数 + 耗时三段时间。✅落地。

**trace + 报告对比**：design D6 要求"逐条 trace + 报告对比"；实际逐条 trace 落盘 + 报告 + 版本对比。✅落地。

**每阶段可测试**：design D7 要求"纯函数可单测"；实际检索/判分指标均纯函数，判分 LLM 可注入。✅落地。

**完善文档 08 过时项**：完善文档 08 写"评测集 5 条"实际 6 条（含边界）⚠️过时；指标数值从"hit@3 0.80 / 质量 3.6~4.6 / 单条 ¥0.016 / 5.7s"变为"hit@5 0.583 / 质量 3.833 / 均 ¥0.0181 / 17.4s"⚠️过时——双向量 + 6 条 + 判分硬算后指标变化。
