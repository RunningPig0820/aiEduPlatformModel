## 隐性坑（踩过的坑）

- **范围门 0.75/0.5 只在白盒链路生效，1.6C 检索端点没有置信度门**：1.6C 端点只有 `if not hits` 空命中拒答，模块 docstring 却自称「置信度过低 → 拒答」——面试若说「所有端点都有 0.75/0.5 范围门」会被 1.6C 端点反证。真实是：白盒链路有阈值门，1.6C 端点只有空命中门，低置信但非空的命中仍会进生成。
- **降级标记定义了但未透传**：召回侧定义了「vector_timeout / bm25_empty」降级标记并声明要透传给 done/boundary 事件，但实际事件流里 rerank 事件只发块列表、done 事件组装时没有降级参数——降级标记最终没进任何 SSE 事件，前端拿不到「这轮是降级回答」的显式信号。这是「想做但没接上」的半成品设计。
- **1.6C 端点生成失败降级不区分超时/异常**：doubao 挂只有一种话术「生成服务不可用」，而白盒链路区分超时与异常两套话术——两条链路的降级粒度不一致，1.6C 端对根因不可观测。
- **意图/分类关重试 + 20s 超时**：意图判断失败就降级关键词，不会重试拖慢查询；代价是网络抖动时意图质量不稳——评测里「6/10→10/10」的提升正是靠 LLM 而非关键词，重试关掉后抖动场景可能退化。
- **查看原文的 404 语义有歧义**：读 COS 失败与「文件不存在」都返回 404，前端无法区分「真的没有」vs「COS 挂了」——这是刻意取舍，用可诊断性的损失换不暴露内部错误。
- **评测边界拒答走独立路径**：边界拒答类型 0 token、quoted 空、score 二值（满分/0 分），聚合时这类用例 judged=True 但 hit=False/precision=0——评测报告里边界用例与普通用例的指标不可混读，否则会误解精度数据。
- **流式生成断连检测有窗口**：断连只在生成前和每轮取队列前检测，注释明确「不掐 httpx 流，在途流由前端取消」——断开后到下一次检测之间会有残留 token 继续产出。

## 对账复盘（原始方案 → 实际落地 → 业务影响）

1. **范围门 0.75/0.5**：方案口径把「检索置信度阈值 0.75/0.5」描述成全局机制；实际只在白盒链路生效并作用于评测边界类型，1.6C 检索端点没有这道门、只有空命中拒答。**⚠️ 结论：范围门仅部分落地——白盒有、1.6C 端点无**，1.6C 端低置信但非空的命中会照常进生成，前端在该端拿不到置信度拦截。
2. **1.6C「置信度过低 → 拒答」注释**：模块 docstring 自称降级语义含「置信度过低 → 拒答」；实际代码只判空命中、不读置信度。**⚠️ 结论：注释高于实际**——按注释理解会高估 1.6C 端点的拦截能力，面试提到降级语义时要区分「注释口径」与「代码真值」。
3. **token usage 真算**：评审指出原代码在丢 usage，建议加流式 include_usage + 抓结尾 usage chunk；现状为流式白盒链路已修、评测侧已抓并算出 avg_tokens/cost_yuan，但 1.6C /query 端点与 embedding 侧仍丢（响应契约无 usage 字段）。**⚠️ 结论：半落地**——流式与评测真算，1.6C 端与向量侧拿不到真实 token 数与成本。
4. **降级标记透传**：代码注释声明降级标记要透传给 done/boundary 事件；实际 recall 返回了 degraded 列表但事件流没接上。**⚠️ 结论：方案有/代码无**——降级标记定义了但没进 SSE 事件，前端无法识别「本轮是降级回答」。
5. **降级矩阵**：方案是「多路召回本身就是降级备份（向量挂→纯 BM25）；生成失败→预写答案兜底；全挂→边界话术」；代码中向量挂→纯 BM25、生成挂→召回清单、全挂→拒答话术均落地。**✅ 结论：降级矩阵按设计落地**，三类外部依赖故障都有稳定兜底。
6. **边界原则三则**：方案是「语料没覆盖→拒答不编造 / 生成失败→references 当答案不空答 / 全挂→边界话术兜底」；1.6C 三则全落地，白盒链路用边界话术 + 生成超时/异常话术各自落地。**✅ 结论：边界三则全部落地**，两条链路各自实现同一套边界原则。
7. **两道门**：方案是「权限门(前置)+范围门(后置)」；权限门=内部 token 鉴权真实生效（Java 网关产 permission，Python 从 intent 开始），范围门只在白盒链路生效。**✅ 权限门落地 / ⚠️ 范围门仅白盒**——两道门只有前置权限门是全链路生效的。
8. **评测边界拒答 0 token**：方案是「断言=触发固定话术+0 token」；实际边界追踪 0 token、不进生成、score 满分/0 分二值。**✅ 结论：评测边界拒答 0 token 按设计落地**，边界用例不产生 LLM 成本。
