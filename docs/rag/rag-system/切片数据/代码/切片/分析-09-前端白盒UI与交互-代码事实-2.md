## sessionId 生成与按页会话

- **生成**：`useState(() => llmApi.generateSessionId())`（RagAssistantPanel.jsx:35）；`generateSessionId()` 返回 **`sess_${Date.now()}_${Math.random().toString(36).substr(2,9)}`**（api/modules/llm.js:191-193）——⚠️ **非 UUID**（见对账要点）
- **整场复用**：每轮 ask 都带同一 `sessionId`（RagAssistantPanel.jsx:135）；Java 以 sessionId 为键累计 token/轮数（语雀 1.4 D-C）
- **按页独立会话**：DashboardLayout 挂 `<RagAssistantPanel key={pageCode} ... mode="inline" />`——`key={pageCode}` 换页重挂载，消息/sessionId/token/流水线/history 全重置，在途 SSE 随卸载 cleanup 取消（DashboardLayout.jsx:79-81; RagAssistantPanel.jsx:88-93）
- **pageCode 推导**：`getPageCode()` 把路由路径转大写下划线（`/student/ai-qa` → `STUDENT_AI_QA`），菜单项 pageCode 优先（DashboardLayout.jsx:26-34）；`getModuleByPage` 映射不到 → `rag-system`（全局模式兜底，pageModuleMap.js:48-50）

## 断线补查 + 超时自关闭

- **断线判定**：`readRagSse` 流 EOF 后 `if (!sawDone && !cancelled) throw new Error('SSE 流中断:未收到完成事件')`（ragSse.js:68-72）——否则会静默挂到 45s 超时
- **error 分支**：`recoverTraceId = stagesRef.current.permission?.traceId || null`（RagAssistantPanel.jsx:217）；有 recoverTraceId 才渲染"补查本轮"按钮（data-testid rag-recover-btn，RagAssistantPanel.jsx:432-441）
- **补查**：`handleRecover` → `ragApi.getTurn(trc)` → `request.get('/rag/assistant/turns/{traceId}')`（RagAssistantPanel.jsx:248; ragAssistant.js:68）；成功渲染 `{answer, traceId, tokensUsage, quotedKeys, suggestions, recovered:true}`，"已补查"徽标（RagAssistantPanel.jsx:249-257,462-466）
- **trace 过期**：错误 `err?.code === '10002'` → "该轮记录已过期，请重新发送问题"（RagAssistantPanel.jsx:261）；request 拦截器把业务错误 code 附在 Error 上（request.js:29-35）
- **单轮超时**：`ROUND_TIMEOUT_MS = 45000`（后端桥 60s 超时的前端兜底）；超时 `cancelRef.current?.()` + 追加 error 消息"响应超时，已结束本轮，请重试" + 清 loading（RagAssistantPanel.jsx:18,120-130）；卸载 cleanup 取消在途流+清超时（RagAssistantPanel.jsx:88-93）
- **force 重开**：澄清点选/断线重试传 `force=true` 时先取消在途流+清超时再重开（RagAssistantPanel.jsx:101-106）

## 成本面板（`CostBar.jsx` + 头部累计）

- **每轮成本**：done.tokensUsage 四字段累加进 `turnTokens`（RagAssistantPanel.jsx:171-178）；回答气泡后 `<CostBar usage={message.tokensUsage} />`（data-testid rag-turn-cost，RagAssistantPanel.jsx:454-458）
- **头部本场累计**：`<CostBar usage={turnTokens} label="本场成本" />` 独立第二行（data-testid rag-header-cost，RagAssistantPanel.jsx:350-352）
- **展示规则**：prompt/completion/cacheHit/total 四字段；`cacheHitTokens > 0` 才显示并标注"(估算)"——后端拿不到（doubao 不报 cached_tokens）固定发 0 → 0 直接隐藏，不显示"缓存命中0"误导（CostBar.jsx:30-37）；`totalTokens` 兜底 `promptTokens + completionTokens`（CostBar.jsx:16）；数字 `toLocaleString()`（CostBar.jsx:10）

## close 结算 + 非学生占位 + 追问展开

- **结束对话**：头部"结束对话"按钮（isStudent 才显示）→ `handleClose` → `ragApi.close(sessionId)` → `request.post('/rag/assistant/sessions/{sessionId}/close')`（RagAssistantPanel.jsx:361-371,236-243; ragAssistant.js:65）；返回 `{sessionId, closed, rounds, sessionUsage}` 弹窗展示"本次对话总消耗"（rounds + sessionUsage CostBar；失败显示 error）（RagAssistantPanel.jsx:572-598）
- **角色门**：`isStudent = role === 'STUDENT'`；`handleSend` 首行 `if (!question || !isStudent) return`——非学生不发 ask；非学生渲染"当前非学生无法使用"占位（Lock 图标，RagAssistantPanel.jsx:62,99,375-383）。后端 403 兜底
- **追问展开（M6）**：`historyRef` 每轮 done 后追加 `{question: lastQuestionRef.current, answer: data.answer||'', anchor: stagesRef.current.intent?.anchor || currentProject}` 并 `.slice(-5)`；下轮 ask 带 `history: historyRef.current.slice(-5)`（RagAssistantPanel.jsx:136-137,199-204）——刷新/换页重挂载 → history 空 = 新会话（RagAssistantPanel.jsx:137 注释）。TC-6e 断言第 2 问 history=[{question,answer,anchor}]（rag-assistant-f1.spec.mjs:810-816）

## 渲染细节与建议 chips

- **流式正文**：token 期间纯文本 `whitespace-pre-wrap` 逐字展示（不解析 Markdown——流式中途语法不完整），done 后气泡整块 ReactMarkdown（remarkGfm+remarkBreaks）（RagAssistantPanel.jsx:444-445,512-521,515-516 注释）
- **done 建议 chips**：`done.suggestions` 纵向一行一条、填满行宽、浅色 pill，点击 `handleSend(s)` 作为新问题再问（RagAssistantPanel.jsx:481-495）
- **元信息行**：已补查徽标 + 引用命中 N 徽标 + `#traceId` 灰小字（RagAssistantPanel.jsx:460-478）
- **收起气泡建议池**：guideTitles + done.suggestions 去重进 `bubblePool`，`bubbleText` 随 `bubbleIndex` 轮换；inline 收起为右上角悬浮气泡（"点击展开"按钮 + 轮换按钮），fixed 模式为右侧居中细条（"建议问问: {bubbleText}"）（RagAssistantPanel.jsx:67-80,268-324）
- **EvalPanel**：折叠一屏放输入区上方（RagAssistantPanel.jsx:534-537）；离线 benchmark（hit@3/质量分/平均耗时/引用有效/上次评测/命中/avgTokens/总成本/语料版本）+ 真实对话质量区段（realConversation 非 null 才渲染）+ 重新评测（POST /eval/run 幂等 → 5s 轮询 running=false）（EvalPanel.jsx:102-114,147-222,48-60,84-97）

## 设计要点

- **白盒化 = 事件即状态**：SSE 事件名 ↔ stages state 键一一对应，阶段行按事件到达顺序点亮（✓/脉动/灰），`done` 是所有分支（正常/clarify/boundary/switch）的终止点，到达即停转圈并定稿（PipelineStages.jsx:87,93; 语雀 1.4 时序）
- **stagesRef 双写**：setStage 先写 ref 再 setState，保证 done 回调组装快照时能读到完整阶段，快照内联在回答气泡前（RagAssistantPanel.jsx:48-52,166-194）——解决"done 到达时阶段 state 未 flush"的时序问题
- **先灰后亮的数据流**：rerank 事件（无 quotedKeys）→ 引用面板灰显折叠；done 携带 quotedKeys（LCS 硬匹配，非 LLM 自述）→ 命中块高亮。quotedKeys 为空 → 全部保持灰显（ReferencePanel.jsx:11-14）
- **澄清点选契约冻结**：点选候选 = 重发原问 + currentProject=点选模块 id（不是发裸功能名），后端以 currentProject 权威锚定；点选模块与会话锚点不同 → switch 事件照常处理（ClarifyCard.jsx:8-11; TC-4.2）
- **按页会话 = key 重挂载**：`key={pageCode}` 使每页独立会话，规避 LLM 上下文猜错模块 vs 用户所在页的矛盾；换页自动清空，无需手动 close 旧会话（DashboardLayout.jsx:79-81 注释）
- **前端兜底分层**：/guide 静态池、clarify 文案重写、45s 超时自关闭、source 弹窗失败提示——每个后端未就绪/异常点前端都有不阻塞主链路的降级
- **渲染性能/正确性细节**：流式纯文本 vs done Markdown 分离；引用分数只显示 Top-N 排名不显示百分比（避免误导）；cacheHitTokens 0 隐藏（避免"实测命中0"误导）；建议 chips 纵向满宽（与引导 chips 一致）
