## 隐性坑与注意事项

- **quotedKeys 高亮≠展开**：设计文字写"高亮展开"，代码实现是"高亮 + 已引用徽标但**默认折叠**，点击才展开摘要/原文"（ReferencePanel.jsx:11-12,20; TC-10 断言折叠）。依赖"先灰后亮"演示效果的人需注意：命中块只是视觉高亮，不会自动展开内容
- **sessionId 非 UUID**：`llmApi.generateSessionId()` 返回 `sess_<时间戳>_<随机串>`，与语雀 D-C"前端生成 UUID"描述不符；Java 若按 UUID 校验 sessionId 格式会踩坑（TC-REAL 只校验了 traceId 的 UUID 格式，未校验 sessionId 格式）
- **mode="fixed" 默认分支生产不可达**：`mode = 'fixed'` 是组件默认值（RagAssistantPanel.jsx:28），但 DashboardLayout 恒传 `mode="inline"`（DashboardLayout.jsx:81），fixed 的右侧居中细条收起态是死代码（除非未来别处调用不带 mode）
- **RAG_EVENTS 常量未使用**：事件名实际以字面量走 `onEvent(type, data)` 分发；改事件名需同时改 RagAssistantPanel 的 if-else 链，无类型/枚举约束，易漏改
- **`ragApi.ask` 非流式接口 UI 未使用**：面板只用 askStream；非流式 ask 是 API 层备胎，测试也走流式
- **引导兜底会静默切换**：/guide 404 → 静态池，UI 只在标题旁标注"(静态建议)"（GuideChips.jsx:62-66），不弹错；演示时可能误以为后端 guide 已建（TC-REAL 特意断言无"(静态建议)"来确认真实 guide 生效，rag-assistant-real.spec.mjs:30）
- **流式正文不中途解析 Markdown**：token 期间纯文本，done 才切 Markdown（RagAssistantPanel.jsx:515-516 注释）——若 done 迟到，用户看到的是未格式化的裸文本
- **clarify 文案依赖后端 message**：后端 message 含英文 id 时靠 `localizeModuleIds` 替换（pageModuleMap.js:60-71）；若后端 message 结构变化（无 default/candidates）会落到 `buildClarifyMessage` 前端重写（RagAssistantPanel.jsx:151-154）
- **断线补查只覆盖"permission 已到"**：`recoverTraceId` 仅取 `stages.permission?.traceId`（RagAssistantPanel.jsx:217）；若在 permission 事件到达前就断连，无 traceId 可补，只能重试
- **close 未做在途流取消**：`handleClose` 只调 close 接口 + 弹窗，**没有**先 `cancelRef.current?.()` 中止在途 SSE（RagAssistantPanel.jsx:236-243）——设计 D12"中止在途流"由 Java 侧 close 负责，前端不主动取消
- **45s 超时与后端 60s 桥超时的错位**：前端 45s 先于后端 60s 触发，超时后前端已取消 reader，但后端/Java 桥仍在跑（可能继续消费 token）——属设计确认过的兜底行为
- **非学生页不发 ask 但面板仍在**：TEACHER/未登录也挂面板并显示占位（RagAssistantPanel.jsx:375-383），`handleSend` 直接 return，不会误发起请求

## 对账要点（方案 vs 代码复盘）

> 原始对比表转自然语言复盘；每条 翻转 / 落地 结论句显式保留。

- **对账1（AI答疑页排除 vs 全局挂载）**：设计 D2 表述"排除 AI答疑页（避免双聊天混淆）"，Non-Goal 也写"AI答疑页不挂 RAG 助手"。实际落地：DashboardLayout **全局挂载不排除任何页**，TC-5/TC-REAL 均进 `/student/ai-qa` 验证 RAG 面板 + 左引导 + 中内容三栏，`PAGE_TO_MODULE.STUDENT_AI_QA→ai-tutoring` 保留。**方案有/代码无**：最终定稿改为包含 AI答疑页（inline 三栏），设计早期 Non-Goal 已过时。
- **对账2（quotedKeys 高亮展开 vs 高亮折叠）**：设计 D5 / spec 表述"done.quotedKeys 命中块**高亮展开**"。实际落地：命中块**高亮 + 默认折叠**（点击才展开摘要/原文），未命中灰显折叠。**表述差异**：代码是"高亮折叠"，TC-10 已明确定稿该行为。
- **对账3（sessionId UUID vs 自定义格式）**：语雀 1.4 D-C 表述"sessionId 前端 **UUID** 生成"。实际落地：`generateSessionId()` 返回 `sess_<时间戳>_<随机串>`，**非 UUID**（llm.js:191-193）。**方案有/代码无**：sessionId 是自定义格式，Java 侧需按字符串处理而非 UUID。
- **对账4（收起态可发送 vs 只展开）**：设计 D2 表述"收起细条『建议问问』**可点发送**、可点展开"。实际落地：收起气泡/细条是单个 button `onClick={() => setOpen(true)}`，**只展开不直接发送**（RagAssistantPanel.jsx:272-321）。**方案有/代码无**：收起态无独立发送动作。
- **对账5（阶段行 6 vs 5）**：设计 D2 ASCII 图示 6 阶段行（④多路召回/⑤重排分开）；D4 表格"rerank→多路召回+重排"。实际落地：代码合并为 **4 行"召回·重排"**，共 5 阶段行（PipelineStages.jsx:89-95）。**设计内部不一致**：代码与 D4 表格一致，与 D2 图 6 行不同。
- **对账6（RAG 方向校验职责）**：spec 表述"开始引导必含 ≥1 条 RAG 方向"。实际落地：前端只取 `s.title` **丢弃 direction**，不校验 RAG 方向（GuideChips.jsx:35-38）；兜底池天然全 RAG。**职责分工**：RAG 方向由后端 guide 契约保证，前端不承担校验。
- **对账7（后端端点未建风险）**：设计 Risks 表述"后端端点未建（source/guide/eval/close/turns 待后端建）"。实际落地：前端五端点封装齐备 + 每端点兜底（guide 静态池、source 弹窗错误、eval 空值兜底）；后端是否全建属后端侧对账。前端侧**已按契约实现**，等待后端。
- **对账8（done.traceId 一致性校验缺失）**：设计 D9 表述"permission 事件携带 traceId，done 回显做一致性校验"。实际落地：前端存 permission.traceId 供补查（RagAssistantPanel.jsx:144,217）；**done.traceId 一致性校验代码不存在**（done 只 `if (data.traceId) setTraceId`，无比对/告警，RagAssistantPanel.jsx:170）。**方案有/代码无**：done 回显未做一致性比对。
- **对账9（close 中止在途流分工）**：spec Requirement 表述"关闭对话调 POST /sessions/{sessionId}/close **中止在途流**"。实际落地：前端 `handleClose` **只调接口 + 弹窗，不主动 cancelRef**（RagAssistantPanel.jsx:236-243）。**分工差异**：在途流中止由后端 close 承担，前端不实现。
- **对账10（模块 id 闭集落地）**：三端定稿模块 id 闭集。实际落地：`MODULE_LABELS` 四模块闭集（pageModuleMap.js:10-15）；clarify candidates 字符串 id、点选传 id 不传 label。**已落地**，与语雀 D-A 一致。
- **对账11（查看原文 Java 代理落地）**：语雀 D-D 表述"查看原文走 Java 代理"。实际落地：`source: request.get('/rag/assistant/source', {params:{path}})`，query 传参（ragAssistant.js:80; ReferencePanel.jsx:86）。**已落地**，与语雀 D-D 一致。
