## 踩过的坑与注意点

- **quotedKeys 高亮≠展开**：设计文字写"高亮展开"，代码实现是"高亮 + 已引用徽标但**默认折叠**，点击才展开摘要/原文"。依赖"先灰后亮"演示效果的人需注意：命中块只是视觉高亮，不会自动展开内容。
- **sessionId 非 UUID**：前端生成的 sessionId 是 `sess_<时间戳>_<随机串>`，与设计文档"前端生成 UUID"描述不符；Java 若按 UUID 校验 sessionId 格式会踩坑（测试只校验了 traceId 的 UUID 格式，未校验 sessionId 格式）。
- **mode="fixed" 默认分支生产不可达**：组件默认值是 fixed，但布局恒传 inline，fixed 的右侧居中细条收起态是死代码（除非未来别处调用不带 mode）。
- **RAG_EVENTS 常量未使用**：事件名实际以字面量字符串走分发；改事件名需同时改面板的 if-else 链，无类型/枚举约束，易漏改。
- **非流式 ask 接口 UI 未使用**：面板只用流式 askStream，非流式 ask 是 API 层备胎，测试也走流式。
- **引导兜底会静默切换**：/guide 404 → 静态池，UI 只在标题旁标注"(静态建议)"，不弹错；演示时可能误以为后端 guide 已建（真实联调测试特意断言无"(静态建议)"来确认真实 guide 生效）。
- **流式正文不中途解析 Markdown**：token 期间纯文本，done 才切 Markdown——若 done 迟到，用户看到的是未格式化的裸文本。
- **clarify 文案依赖后端 message**：后端 message 含英文 id 时靠本地化替换；若后端 message 结构变化（无 default/candidates）会落到前端重写补充语境。
- **断线补查只覆盖"permission 已到"**：补查 traceId 仅取 permission 阶段；若在 permission 事件到达前就断连，无 traceId 可补，只能重试。
- **close 未做在途流取消**：结束对话只调 close 接口 + 弹窗，**没有**先中止在途 SSE——设计"中止在途流"由 Java 侧 close 负责，前端不主动取消。
- **45s 超时与后端 60s 桥超时的错位**：前端 45s 先于后端 60s 触发，超时后前端已取消 reader，但后端/Java 桥仍在跑（可能继续消费 token）——属设计确认过的兜底行为。
- **非学生页不发 ask 但面板仍在**：TEACHER/未登录也挂面板并显示占位，`handleSend` 直接 return，不会误发起请求。

## 方案 vs 落地复盘（对账要点转述）

> 原始对比表已转自然语言复盘；每条 ⚠️翻转 / ✅落地 结论以一句话事实句保留。

- **对账1（AI答疑页排除 vs 全局挂载）**：原始设计 D2 明确"排除 AI答疑页（避免双聊天混淆）"，Non-Goal 也写"AI答疑页不挂 RAG 助手"。实际落地：布局**全局挂载不排除任何页**，测试均进 `/student/ai-qa` 验证 RAG 面板 + 左引导 + 中内容三栏。⚠️ 翻转：**方案有/代码无**——最终定稿改为包含 AI答疑页（inline 三栏），设计早期 Non-Goal 已过时。
- **对账2（quotedKeys 高亮展开 vs 高亮折叠）**：原始设计/spec 表述"命中块**高亮展开**"。实际落地：命中块**高亮 + 默认折叠**（点击才展开摘要/原文），未命中灰显折叠。⚠️ 表述差异：代码是"高亮折叠"，测试用例已明确定稿该行为。
- **对账3（sessionId UUID vs 自定义格式）**：语雀定稿契约表述"sessionId 前端 **UUID** 生成"。实际落地：返回 `sess_<时间戳>_<随机串>`，**非 UUID**。⚠️ 翻转：**方案有/代码无**——sessionId 是自定义格式，Java 侧需按字符串处理而非 UUID。
- **对账4（收起态可发送 vs 只展开）**：原始设计描述"收起细条『建议问问』**可点发送**、可点展开"。实际落地：收起气泡/细条是单个按钮，**只展开不直接发送**。⚠️ 翻转：**方案有/代码无**——收起态无独立发送动作。
- **对账5（阶段行 6 vs 5）**：设计内部自相矛盾——D2 图示画 6 阶段行（④多路召回/⑤重排分开），D4 表格写"rerank→多路召回+重排"。实际落地：代码合并为 **4 行"召回·重排"**，共 5 阶段行。⚠️ **设计内部不一致**：代码与 D4 表格一致，与 D2 图 6 行不同。
- **对账6（RAG 方向校验职责）**：原始 spec 要求"开始引导必含 ≥1 条 RAG 方向"。实际落地：前端只取标题**丢弃 direction**，不校验 RAG 方向；兜底池天然全 RAG。✅ 落地（职责分工）：RAG 方向由后端 guide 契约保证，前端不承担校验。
- **对账7（后端端点未建风险）**：设计 Risks 列了"后端端点未建（source/guide/eval/close/turns 待后端建）"。实际落地：前端五端点封装齐备 + 每端点兜底（引导静态池、查看原文弹窗错误、评测空值兜底）；后端是否全建属后端侧对账。✅ 前端侧**已按契约实现**，等待后端。
- **对账8（done.traceId 一致性校验缺失）**：设计 D9 要求"permission 携带 traceId，done 回显做一致性校验"。实际落地：前端存 permission.traceId 供补查，但 **done.traceId 一致性校验代码不存在**（done 只回填 traceId，无比对/告警）。⚠️ 翻转：**方案有/代码无**——done 回显未做一致性比对。
- **对账9（close 中止在途流分工）**：spec Requirement 要求"关闭对话调 close **中止在途流**"。实际落地：前端 `handleClose` **只调接口 + 弹窗，不主动取消在途流**。⚠️ 分工差异：在途流中止由后端 close 承担，前端不实现。
- **对账10（模块 id 闭集落地）**：三端定稿模块 id 闭集。实际落地：`MODULE_LABELS` 四模块闭集（AI答疑/知识图谱/题型分析/RAG 项目）；clarify 候选传模块 id 不传 label。✅ **已落地**，与语雀契约一致。
- **对账11（查看原文 Java 代理落地）**：语雀契约要求"查看原文走 Java 代理"。实际落地：前端以 query 传参调 source 接口（file_path 含 http:// 前缀走 path 会被容器拒）。✅ **已落地**，与契约一致。
