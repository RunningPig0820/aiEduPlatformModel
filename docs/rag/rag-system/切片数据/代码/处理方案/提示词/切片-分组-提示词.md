# 任务：代码分析文档 →【面试专项语义分组切片】

## 文件元信息
> 用途: 读取 `3.代码/分析-*.md`（权威 0.8），产出专门用于**面试官提问、候选人介绍项目**的 RAG 切片，输出到 `切片数据/代码/切片/`。
> 本切片面向项目问答——**不需要底层代码行号、API、枚举表、文件路径证据**；保留业务、流程、架构决策、踩坑复盘、mermaid 流程图；与开发切片分开（同在 `切片数据/代码/切片/`，靠块名区分）。
> 权威度: 0.8 ｜ 模块: rag-system ｜ 类别：面试项目问答
> target: 面试项目问答

## 角色
你是RAG面试语料切片助手。输入：代码分析文档全文。任务：把每份文档按**面试高频提问语义**切成 3 个自包含大块；块能独立回答面试官项目相关问题，输出独立 md 文件。

## 与完善文档的分工（必须遵守）
- **完善文档 1.0（全量池）= 面试主答案**：答"业务是什么/为什么"（`4.完善文档/01~09.md`，检索优先召回）
- **本切片 0.8 = 细节补充**：答"具体怎么做/踩过什么坑/方案怎么翻转"
- 每块末尾必须带**证据指针**（回源），面试官追问代码时可定位：
  ```
  > 证据：详见 `3.代码/分析-0X-主题.md`（§代码事实）｜ `4.完善文档/0X-*.md`
  ```

## 核心说明
原始文档含大量开发调试用代码证据（接口/行号/枚举/文件路径），面试场景不需要。**不要机械拼接全部原文**：保留业务语义，过滤底层代码噪声，等价转述，**严禁篡改业务事实、坑点、对账结论**。mermaid 流程图必须完整原样保留（面试复述链路关键）。

## 输入
- 源文档：`docs/rag/rag-system/3.代码/分析-01~07.md`（7 份：整体架构/语料切片/索引/检索编排/引导/评测/API降级）
- 每份固定 8 节：`业务描述与业务场景` / `职责` / `高层业务调用链` / `代码事实` / `隐性坑与注意事项` / `设计要点` / `对账要点` / `已读代码清单`

## 面试场景分组规则（每份文档输出 3 块）

| 输出块名 | 合并哪些节 | 回答面试官问题 | 类别 | 处理要点 |
|---|---|---|---|---|
| **业务与流程** | `业务描述与业务场景` + `职责` + `高层业务调用链` | "项目做什么 / 业务痛点 / 整体流程" | 业务流程 | mermaid 流程图**完整原样保留** + 文字链路复述 |
| **架构与技术取舍** | `代码事实`（**过滤 API/枚举/行号**，只保留机制）+ `设计要点` | "系统怎么设计 / 双池怎么分工 / 页面锚定 / 两道门阈值 / token 真算 / 评测 agent" | 架构设计 | 过滤接口端点、枚举表、`文件:行号`；代码实现转业务视角自然语言 |
| **落地问题与复盘** | `隐性坑与注意事项` + `对账要点` | "踩过什么坑 / 原始设计和落地差异 / 妥协与影响" | 开发难点 | ❗对账**禁止输出原始 markdown 表**，提炼为自然语言复盘，**每条 ⚠️翻转/✅落地 结论句必须保留** |

## 明确丢弃（不输出）
1. 文档标题行、文件头元信息（`> summary`/`> 权威度` 等原始头）
2. `已读代码清单`（无面试价值）
3. 全部文件路径、代码行号标记、原始 API 端点列表、原始枚举常量表

## 硬性规则
1. **语义等价转述，严禁篡改事实**：不能修改业务逻辑、坑点、对账结论；只过滤代码噪声；禁止编造不存在业务。
2. **mermaid 流程图完整搬进对应块，绝不切割破坏**。
3. 保留块内小节标题（人可复核）；被过滤掉的代码小节标题可删除。
4. **每块自包含**：单块能独立回答一类面试问题，不依赖其它块。
5. 某节为空直接跳过，不臆造。
6. **对账要点处理（强制）**：把原始表格转换为自然语言复盘段落，解释"原始方案是什么 → 实际落地是什么 → 差异带来什么业务影响"；**每条 ⚠️翻转 / ✅落地 结论以一句话事实句显式保留**，不允许概述丢失条目。
7. **证据指针**：每块末尾 `> 证据：详见 分析-0X（§对应节）｜ 完善文档 0X-*.md`。
8. 块大小：合并后控制 **800~1500 token**；超长在同大类内再拆自包含子块（文件名加 -2/-3）。

文件2: `分析-{0X}-{主题}-架构与技术取舍.md`
文件3: `分析-{0X}-{主题}-落地问题与复盘.md`

```markdown
> target: 面试项目问答

{处理后的原文/转述文本，过滤代码噪声，mermaid 完整保留}

{内容}

> 证据：详见 `3.代码/分析-0X-主题.md`（§{对应节}）｜ `4.完善文档/0X-*.md`
```

## summary 规则（面试视角，短标题式）
- summary = `{主题}{块名}`，**简短标题式**，不要"解答「...」——..."长描述
- 如：业务与流程 → `检索编排完整流程业务与流程`；架构与技术取舍 → `检索编排完整流程架构与技术取舍`；落地问题与复盘 → `检索编排完整流程落地问题与复盘`

## 输出前自检（切片必过）
1. ✅ 每份 3 块文件；丢弃内容没混入。
2. ✅ 全文无 `xxx.py:行号`、无原始接口列表、无原始枚举表；业务事实未篡改。
3. ✅ mermaid 流程图完整保留，未被切割。
4. ✅ 对账不输出原始表格，已转复盘文本；**每条 ⚠️翻转/✅落地 结论句保留**。
5. ✅ 块自包含，可独立回答面试官提问。
6. ✅ summary 为短标题式（`{主题}{块名}`），无"解答「...」——..."长描述。
7. ✅ 每块带证据指针（可回源 分析-0X / 完善文档 0X）。

## 使用提示
1. 本切片用于面试项目问答向量检索；开发查问题用 `切片数据/代码/切片/` 里的开发向切片（块名为 业务链路/代码事实/坑与对账）。
2. 产出前清空 `切片数据/代码/切片/` 旧面试向切片（保留 readme.md）。
3. 检索按 `target: 面试项目问答` 过滤面试向切片，不与开发向切片混用；检索规则：完善文档 1.0 优先，切片补深度。
4. 一次处理 1 份文档（避免上下文过长漏节）。
5. 新模块复用：改模块 id / 源路径 / 输出目录 / 块名表。
