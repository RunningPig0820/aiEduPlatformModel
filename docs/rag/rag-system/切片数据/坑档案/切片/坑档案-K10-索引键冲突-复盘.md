## 坑点复盘
**现象**：ai-tutoring 与 question-analysis 两个模块共用同一套索引，各自都有"完善文档 01-08"这类同名文件——后入库的覆盖先入库的，检索命中后键反查只剩后写的块，跨模块的块悄悄丢失。

**触发链路**：多模块各自把切片写入共享索引 → 生成块唯一键 → 检索命中返回键 → 按键反查映射回块。键里不含模块段时，两模块同名文件生成相同键 → 后写覆盖先写 → 命中后只能拿到后写的块。

**根因**：块唯一键规则只有"池/文件/锚点+序号"，不含业务命名空间——多模块共用同一物理索引时，跨模块同名文件（每个模块都有完善文档 01-08）生成相同键，后写覆盖先写，检索命中后键映射只指向后写块。这是共享索引多模块场景下典型的隐性丢数据。

**解决思路与权衡**：键规则加模块段 `rag-{池}/{模块}/{文件}/{锚点}#{序号}`，建索引生成键与检索反查键两侧同步改，测试命中的 mock 键也补上模块。验证：不同模块同名文件的键不再相等，全量测试通过。权衡：键变长、包含业务命名空间，换来多模块共存互不覆盖。

## 面试口述要点
多模块共索引的键设计——共享物理索引时，块唯一键必须含业务命名空间（module），否则同名文件互相覆盖。踩坑收获：共享资源（索引/缓存/表）引入多租户/多模块时，key 设计先想清命名空间，这类"后写覆盖先写"是典型隐性丢数据。
