# 坑档案 K10 多模块共用索引同名文件键冲突被覆盖

**1. 问题现象**：ai-tutoring 与 question-analysis 两模块共用 `rag-full`/`rag-slice` 索引，各自都有"完善文档 01-08"这类同名文件——后入库的覆盖先入库的，检索命中后 keymap 只剩后写的块，跨模块块丢失。

**2. 触发流程**：`build_index` 把各模块 jsonl 入 `rag-full`/`rag-slice` → `make_key` 生成块唯一 key → query 检索命中返回 key → `_key_of`/keymap 反查块。键不含 module 段时，两模块同名文件生成相同 key。

**3. 根因分析**：块 key 规则只有 `{池}/{file}/{anchor}#{idx}`，不含 module 段——多模块共用同一物理索引时，跨模块同名文件（每个模块都有完善文档 01-08）生成相同 key，后写覆盖先写（COS 向量桶按 key upsert），检索命中后 keymap 只映射到后写块。

**4. 排查过程**：多模块入库后，qa 向量命中后 keymap/BM25 无块被丢弃（此前 `85941ac` 修过"模块化 jsonl 加载"），继续追到键冲突：跨模块同名文件 key 相同。

**5. 解决方案 & 改动点**：`802d275`——键规则加 module 段 `rag-{pool}/{module}/{file}/{anchor}#{idx}`：`build_index.py:59-65` `make_key` 加 module 参数、`query.py` `_key_of` 同步；测试 mock 命中键补 module。验证：`_key_of(ai-tutoring/01-模块)` ≠ `_key_of(question-analysis/01-模块)`，252 passed。

**6. 面试口述要点**：讲"多模块共索引的键设计"——共享物理索引时，块唯一键必须含业务命名空间（module），否则同名文件互相覆盖。踩坑收获：共享资源（索引/缓存/表）引入多租户/多模块时，key 设计先想清命名空间，这类"后写覆盖先写"是典型隐性丢数据。

- **证据**：`802d275`（键规则加 module 段）+ `build_index.py:59-65`
