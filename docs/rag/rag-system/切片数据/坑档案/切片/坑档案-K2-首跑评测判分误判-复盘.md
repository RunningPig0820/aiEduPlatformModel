## 坑点复盘
**现象**：评测 agent 首跑 5 条，检索命中率 hit@3=0.80，但答案质量分只有均 2.60/5。其中 2 条是"检索全对但答案质量差"——比如"一次完整答疑怎么走"检索到了正确内容，却被判分"漏了类型先行流式/Java 护栏，还编造 Java 编排"。

**触发链路**：评测集 5 条（每类 1 条）→ 评测 agent 走真实检索 → 每条算检索命中率 + LLM 判分 → 聚合报告。低分集中在"检索对、答案被打差"这一组信号上。

**根因**：trace 回溯后确认不是生成层问题，而是判分侧 + 评测集——① 判分模型认不出同义表述（如要点"ScoreMapper 累计"对应答案里的"题型掌握度回流"）、把语料里有支撑的表述误判成"编造"、没有评分锚定，好答案被打低分；② 评测集的期望要点混入了不适用于该问题的细节（如把"掌握度怎么算"的门控/澄清卡要点放进了"怎么联动"的问题里）。

**解决思路与权衡**：分层定位、分层修——先修判分器：判分时同义覆盖即算覆盖、传语料块供"编造"判定、加 0~5 评分锚定；再收窄评测集期望要点到真正适用于该问题的点。效果：质量分 2.60→4.60/5（操作 2→5、数据关联 0→4、难点 3→5、最危险 4→5），检索命中率保持 0.80 不变。

## 面试口述要点
评测分数低，先查判分器和评测集，别急着怀疑检索/生成。trace 回溯定位到"检索全对但答案被打低分"后，发现真问题在判分侧——判分模型认不出同义表述、误判语料有支撑的内容为编造；同时评测集期望要点混入不适用细节。分层定位要分层修：修判分器（同义覆盖即算覆盖、传语料块供"编造"判定、加评分锚定）+ 收窄评测集期望要点，质量分从 2.60 提到 4.60/5。否则会错误地跑去改生成代码。
