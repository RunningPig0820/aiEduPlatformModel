# 坑档案 K2 首跑评测判分误判

> summary: 首跑评测判分误判：检索全对但答案被打低分，真问题在判分侧非生成侧（修复后质量分 2.60→4.60/5）

**坑**：评测 agent 首跑 5 条 → hit@3=0.80、质量分均 2.60。
**关键信号**：2 条是"检索全对（hit@3=1.0）但答案质量差"——如"一次完整答疑怎么走"检索到正确块，但被判分"漏了类型先行流式/Java 护栏，还编造 Java 编排"。
**根因（trace 回溯后修正）**：**不是生成层问题，是判分侧 + 评测集**——
  ① 判分 prompt 认不出同义表述（要点"ScoreMapper 累计"=答案"题型掌握度回流"）、误判语料有支撑的表述为"编造"、无评分锚定 → 好答案被打低分。
  ② 评测集 expected_points 混入不适用该问题的细节（B3门控/澄清卡 是"掌握度怎么算"的要点，非"怎么联动"）。
**解决（`b13220b`）**：判分 prompt 强化（同义覆盖即算覆盖 + 传语料块供"编造"判定 + 0~5 评分锚定）+ 评测集 expected_points 收窄 → **质量分 2.60→4.60/5**（操作 2→5、数据关联 0→4、难点 3→5、最危险 4→5），hit@3 保持 0.80。
**价值/教训**：评测 agent 的 trace 回溯——**分数低先查判分器和评测集，别急着怀疑检索/生成；分层定位要分层修**。否则会错误地去改生成代码。
**证据**：`21e3000`（首跑 + trace）+ `b13220b`（判分/评测集修复）
