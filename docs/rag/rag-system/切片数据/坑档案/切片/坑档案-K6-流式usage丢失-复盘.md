## 坑点复盘
**现象**：RAG 助手流式回答结束后，前端成本面板拿不到本轮 token 明细（0 或空）——"token 真算"成了摆设，无法向用户/运营证明成本可观测。

**触发链路**：学生提问 → 流式引擎拉取大模型 → 回答结束 → 结束事件 → 前端成本面板。丢失发生在流式这一层：流式请求没要求返回用量，且流末尾携带用量的专用数据块没被解析。

**根因**：两层同时丢——① 请求体没有显式要求流式返回用量（OpenAI 兼容的流式协议默认不返回，服务端一般不会主动给）；② 解析器只认内容/推理/工具调用类字段，就算流里带了用量也被丢弃。两层都丢，所以"真算 + 结束后更新"无从落地。

**排查定位思路**：代码评审直接核流式链路——先查请求体有没有要求返回用量，再查解析器抓没抓结尾用量块，两步都缺；靠的是"OpenAI 兼容流式默认不返回用量"的协议知识判断，不是线上日志。

**解决思路与权衡**：两个小改动——请求体显式要求返回用量 + 解析器识别流末尾的用量数据块并透传，结束事件携带"输入/输出/缓存命中/合计"四段 token 明细给前端展示。注意这是**半修**：白盒流式链路已修复，另一条非流式接口与 embedding 侧仍未采集用量，属已知不完善，讲时要如实说明。

## 面试口述要点
流式输出的用量统计是 RAG 成本展示的隐性坑——用量只在流末尾的专用数据块返回、默认不带，要做"结束后更新"必须显式请求并解析结尾数据块（其结构与中间增量块不同）。踩坑收获是流式协议层"你不主动要、服务端就不给"的默认值，以及"结尾块与中间块 schema 不同"这两点。
