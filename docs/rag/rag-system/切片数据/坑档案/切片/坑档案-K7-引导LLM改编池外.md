# 坑档案 K7 结束建议 LLM 改编引导语 → 池外概念匹配不到答案

> summary: 结束建议 LLM 改编引入池外概念：引导题反转回池内原题直出，100% 可答 + 0 token

**1. 问题现象**：每轮回答结束前端展示"结束建议"候选题；学生点其中一题，问出去后答非所问/拒答——引导价值断裂，引导题本应带学生到高频方向。

**2. 触发流程**：回答完成 → `gen_suggestions` 用 LLM"换提问方法"把池内原题改编 → 前端 chips → 学生点击 → `POST /ask` 检索。改编后的新问题引入了池外概念，切片池没有对应块 → 低置信 → 拒答。

**3. 根因分析**：修前 `gen_suggestions` 依赖 LLM 改编，如把池内"题目记录/错误事件/掌握度三张表关系"编成"题目数据怎么和向量索引关联"（引入池外概念"向量索引"）→ 新问题没对应切片 → 检索不到。本质：引导语"自由发挥"破坏了"引导问题=索引层入口"的可答性闭环——只有池内原题才保证 100% 有切片（双向量 `-q` 问题路命中 sim~0.99）。

**4. 排查过程**：用户实测（2026-08-26）点"结束建议"改编题复现匹配不到答案，对照 known-issues 问题6"引导建议太随机、很多不可答"翻版；定位到 `gen_suggestions` 的 LLM 改编逻辑。

**5. 解决方案 & 改动点**：`ee4f8d6` 反转——结束建议直接返回池内原题（0 token，不做 LLM 改编）：`assistant.py:334-344` `_pool_suggestions` 池内抽样（必含 ≥1 条 rag 组）、`347-355` `gen_suggestions` 池内原题直出、`326-331` 注释记录反转原因；删 `_SUGGEST_SYSTEM`/`_suggest_scope`。

**6. 面试口述要点**：讲"引导系统的可答性闭环"——引导问题必须从"语料可答的底座池"取原题，LLM 自由改编会引入池外概念破坏检索。技术权衡：牺牲"引导语多样性"换"100% 可答 + 0 token"，代价是引导题固定。

- **证据**：`ee4f8d6`（引导可答性修复）+ `assistant.py:326-331`
