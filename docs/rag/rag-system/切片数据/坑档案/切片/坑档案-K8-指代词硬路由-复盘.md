## 坑点复盘
**现象**：学生在"AI答疑"功能页问"这个功能的底层是怎么实现的？"，助手答"未找到关联文档，我尚未掌握。"——在当前功能页问本功能的架构/底层必然拒答，而这恰是架构/难点的高频方向，体验断裂。

**触发链路**：当前项目标识为 ai-tutoring + 用户问"这个功能的底层是怎么实现的？" → 意图层把锚点判成 rag-system → 改写被带偏成问 RAG 系统整体 → rag-system 没有对应切片 → 重排为空 → 边界置信度低 → 拒答。

**根因**：三处叠加——① 意图层把"底层实现/架构"这类词按硬路由规则一律导向 rag-system，没解析指代词"这个功能"指的就是当前项目；② 硬路由规则过激进，当前项目明确时"XXX 功能的底层"本应在当前模块的架构语料里，而非一律跨模块；③ 意图判到无语料模块 → 重排为空 → 必然拒答。

**排查定位思路**：三端联调自测复现——先确认当前项目标识在前端/后端正确透传无误，再看意图层输出发现锚点被判到 rag-system、改写被带偏，问题收敛在 Python 意图层。

**解决思路与权衡**：四处改——① 意图系统加指代词规则（"这个功能/它/本功能/当前功能/这个项目"→ 当前项目）；② 放宽优先级，只有"无指代 + 明确问 RAG 系统整体实现"才选 rag-system；③ 上下文约束明确"这个功能=当前项目，不要因底层/实现/架构跳模块"；④ 加确定性兜底——问题含指代词且未点名其他模块名时，强制锚定当前模块，LLM 不听话也能兜住。验证："这个功能的底层"→当前模块；"RAG 系统整体架构是什么？"→rag-system（跨模块硬路由保留）。

## 面试口述要点
指代词消解 + 硬路由边界的权衡——意图路由要区分"点名词"（如 RAG 系统整体 → 跨模块硬路由）与"指代词"（如这个功能 → 锚定当前模块）；光靠 LLM 不可靠，要加确定性兜底（指代词词表 + 模块闭集判断），"LLM 不听话也能兜住"是工程可靠性的关键。
