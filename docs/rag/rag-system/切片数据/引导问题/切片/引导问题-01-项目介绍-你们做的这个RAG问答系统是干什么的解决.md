## 回答

**核心结论**：面试/汇报要把项目讲清楚 + 证明 RAG 能力——项目模块多人讲会乱会漏，口头宣称"我会 RAG"又缺可演示证据，所以做**自包含的项目介绍 RAG**，demo 随时能跑。

**分层展开**：
- **痛点**：项目模块多（AI答疑/知识图谱/题型分析/组织中心），靠人讲会乱会漏；"我会 RAG"的口头宣称缺可演示证据。早期想过知识点/题型 RAG，但没有题库做不了闭环，遂改做项目介绍 RAG——以自身方案/设计文档为自包含语料（依据：完善文档 01）。
- **核心定位**：不是纯 RAG（丢一堆文档就能问），而是"**产品 = 讲清每个页面，RAG = 证明能力的引擎**"；RAG 本身也作为项目一个功能点被介绍——一鱼两吃、用系统介绍系统（依据：完善文档 01）。
- **三层价值**：语料层（每模块完善文档 8 节=切片单元=面试问法清单）、检索层（双池检索 + 页面锚定 + 两道门 + 生成强制引用）、证明层（评测 agent：hit@k + 答案质量判分 + 版本对比，走真实检索不降级）（依据：完善文档 01）。
- **范围演进（理解本模块定位的关键）**：08-21 曾覆盖 4 业务模块 + RAG 自身 → 08-25 spec 一度反转为"仅 RAG 项目、禁区拒答" → 最终定稿**四模块全放行 + 范围门低置信唯一拒答**（依据：完善文档 01）。
- **落地真相（方案 vs 代码）**：方案口径"doc_type 双池 / 前端传 page / 两道门都在 Python 链"落地为——双物理 COS 索引 `rag-full`+`rag-slice` + `module` 过滤、模块/节两级锚定（无 page）、权限门在 Java 网关（Python 无）、范围门 0.75/0.5 只在白盒链路生效（依据：完善文档 01 / 分析-01）。
- **当前过渡态**：rag-system 自身语料未入 `MODULE_DATA`，`anchor=rag-system` 的问题当前必然边界拒答（"语料整理中"，语料就绪即自动可答）；AI答疑 模块已全链路跑通，实测基线 hit@5=0.583 / 质量 3.833（依据：完善文档 01 / 分析-01）。
