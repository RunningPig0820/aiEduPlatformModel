## 回答

**核心结论**：早期想过知识点/题型 RAG，但**没有题库数据做不了闭环**，遂改用自身方案/设计文档当自包含语料，不依赖题库数据、随时能演示。

**分层展开**：
- **动机**：面试/汇报时要把项目讲清楚 + 证明 RAG 能力（依据：完善文档 01）。
- **早期设想**：知识点/题型 RAG——把知识点讲解、题型解析做成 RAG 问答；但手上**没有题库数据**，闭环（切片→索引→召回→生成→评测）跑不起来，demo 不可用（依据：完善文档 01）。
- **方向反转**：改用**自身方案/设计文档当自包含语料**——五来源（语雀/OpenSpec design/代码分析/坑档案/引导问题）整理成完善文档 9 节，不依赖外部题库，demo 随时能跑（依据：完善文档 01 / 引导问题.md 第 2 问）。
- **附带收益**：语料讲的是自己项目，正好把"项目讲清楚 + 证明 RAG 能力"两件事合并成一件事——一鱼两吃（依据：完善文档 01）。
