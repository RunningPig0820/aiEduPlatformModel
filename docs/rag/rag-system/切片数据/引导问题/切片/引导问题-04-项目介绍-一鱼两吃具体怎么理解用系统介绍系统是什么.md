## 回答

**核心结论**：一份语料两个用途——一面把项目页面讲清楚（产品侧），一面把 RAG 链路当作项目一个功能点被介绍（能力侧），用系统介绍系统。

**分层展开**：
- **产品侧**：语料层把每个页面/模块讲清楚——每模块产出完善文档 8~9 节（定位→功能→为什么→数据流→技术→坑→指标→规模→权限），8 节即切片单元、即面试问法清单（依据：完善文档 01）。
- **能力侧**：RAG 链路本身作为项目一个功能点被介绍——双池检索、页面锚定、两道门、白盒 SSE、引用硬匹配、token 真算，都是"项目做了什么"的一部分（依据：完善文档 01）。
- **用系统介绍系统**：白盒 SSE 链路把"检索怎么一步步工作"当场演示出来——回答一次提问，就等于把 RAG 引擎的能力演了一遍；引导问题 + 召回面板 + 成本面板 + 评测报告把"可上手、可演示、可量化"一次做齐（依据：完善文档 02）。
- **体验闭环**：面试官既能问"这个页面怎么用"（产品侧），又能问"你的 RAG 和普通 RAG 有什么不同"（能力侧），同一套语料都能答——一鱼两吃（依据：完善文档 01）。
