## 回答

**核心结论**：前端带 sessionId+history 发 POST /ask → Java 角色门产 permission → Python 走 intent→(clarify|switch)→rewrite→rerank→(boundary|token)→done → 前端按序点亮 5 阶段行（权限→意图→改写→召回·重排→生成）。

**分层展开**：
- **前端发起**：面板带 `sessionId`（整场复用）+ `history`（最近 5 轮）+ `currentProject` 发 `POST /api/rag/assistant/ask`（stream=true）（依据：分析-09）。
- **Java 角色门**：`requireStudent`→`TutoringAuth.isStudent`（可信 HttpSession 取 role，仅 STUDENT 放行），前置 permission 事件（含 traceId，流开始即存供断线补查）（依据：分析-08）。
- **Python 编排**：`intent`（模块锚点+类别，问候/clarify/switch 判断）→ 分支（clarify 候选/switch 切换）→ `rewrite` 追问改写 → `recall` 双池三路召回 → `rerank` 精排 Top-3 → `check_boundary` 范围门 → `stream_generate` 流式生成 → LCS 引用校验 → `done`（依据：分析-01 / 分析-04）。
- **前端可见步骤**：5 阶段行按事件顺序点亮（权限→意图→改写→召回·重排→生成）；召回块 rerank 到达即灰显折叠、done 带 quotedKeys 命中块高亮；token 逐字流式展示；done 后整块 Markdown + 本轮成本 + 建议 chips（依据：分析-09）。
- **⚠️ 分支差异**：clarify/switch/boundary 分支无 generate、0 token 短路，前端展示对应横幅/澄清卡（依据：完善文档 02 / 分析-09）。
