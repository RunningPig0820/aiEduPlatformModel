## 回答

**核心结论**：两个入口：面板空态开始引导（GET /guide 取 3 条入口题）+ 每轮 done 后结束建议（池内原题 2~3 条）；点击后仍走 `-q` 问题路真检索，自由输入走源文档池纯 RAG，池内原题只为 100% 可答。

**分层展开**：
- **两个入口**：① 面板空态引导 chips——`GET /api/rag/assistant/guide`（0 token 非 SSE）从入口池（`_ENTRY_TEMPLATES` 通用模板 + 模块中文名动态替换）取 3 条入门题；② 每轮 done 后结束建议——`gen_suggestions` 从池内原题抽 2~3 条（必含 ≥1 条 rag 桥接组）（依据：分析-05 / 分析-09）。
- **路一样吗（关键）**：不完全一样——引导题点击后**仍走正常检索链路**（`POST /ask` → intent→rewrite→rerank→generate），且走切片池 `-q` 问题路对池内原题命中 sim~0.99；自由输入走源文档池纯 RAG 真发挥（依据：完善文档 02 / 分析-05）。
- **池内原题只为可答**：结束建议不做 LLM 改编（K7 实测：LLM 改编"换提问方法"会引入池外概念，如"向量索引"，无对应切片 → 点了匹配不到答案）；反转成池内原题直出 0 token——牺牲引导多样性换 100% 可答（依据：坑档案 K7 / 分析-05）。
- **⚠️ rag-system 现状**：`GUIDE_POOL` 尚无 rag-system 独立池，`current_project=rag-system` 时兜底 ai-tutoring 池 + "RAG项目"入口模板；rag-system 问题列表生成后需同步 `GUIDE_POOL["rag-system"]` 5 组（依据：分析-05）。
