## 回答

**核心结论**：模糊 → clarify 事件发候选 chips，点选=重发原问 + currentProject=点选模块 id；switch → switch 事件 + 按 to_anchor 继续，两条分支都不产 rewrite/recall/generate、0 token。

**分层展开**：
- **模糊问题（ambiguous）**：`intent` 判定 ambiguous 且候选 ≥2 且未澄清过 → 发 `clarify` 事件，前端 ClarifyCard 渲染候选 chips；点选 = **重发原问 + currentProject=点选模块 id**（不是发裸功能名）（依据：分析-09 / 分析-01）。
- **切换模块（switch_detected）**：`intent` 检测到 switch → 发 `switch` 事件（fromAnchor→toAnchor），前端"已切换至 X"横幅，后续按 to_anchor 继续检索（依据：分析-01 / 分析-09）。
- **0 token 短路**：两条分支都不产 rewrite/recall/generate，0 token 不调 LLM（依据：完善文档 02 / 分析-01）。
- **落地细节**：点选模块与会话锚点不同 → 后端 switch 事件照常触发；clarify 文案后端 message 缺失时前端 `buildClarifyMessage` 重写补"当前在「X」功能页"语境（依据：分析-09）。
