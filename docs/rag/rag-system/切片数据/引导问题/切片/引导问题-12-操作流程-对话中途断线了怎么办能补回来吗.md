## 回答

**核心结论**：每轮 done 的 camel JSON 落 Java Redis trace 快照（TTL 24h）；SSE 中断前端凭 permission.traceId 调 GET turns/{traceId} 补回 answer/quotedKeys/usage，超窗提示重发。

**分层展开**：
- **落库**：Java 每轮 done 的 camel JSON 写 `rag:assistant:trace:{traceId}`，TTL 24h（`persistRound`，落库失败仅告警不阻断回答）（依据：分析-08）。
- **断线补查**：`readRagSse` 流 EOF 且未收到 done → 前端 error 分支，凭 `permission.traceId`（流开始即存）调 `GET /api/rag/assistant/turns/{traceId}` 补回完整结果（answer/quotedKeys/tokensUsage/suggestions），带"已补查"徽标（依据：分析-09 / 分析-08）。
- **超窗提示**：trace 过期 → 业务码 10002 →"该轮记录已过期，请重新发送问题"（依据：分析-09）。
- **超时/前置兜底**：前端单轮 45s 超时自关闭提示重试（后端桥 60s 超时的前端兜底）；若在 permission 事件到达前就断连，无 traceId 可补，只能重试（依据：分析-09）。
