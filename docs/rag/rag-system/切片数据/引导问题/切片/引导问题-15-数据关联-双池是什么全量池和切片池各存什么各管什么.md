## 回答

**核心结论**：`rag-full` 全量池（整篇一块，实测 23 块）管整体/全局问题；`rag-slice` 切片池（细节块 + 引导问题，实测 294 块，每块 `-c`/`-q` 双向量）管追问/细节——两池互补，一池满足不了"引导可控 + 自由纯 RAG"。

**分层展开**：
- **全量池 `rag-full`**：整篇文档一块（语雀/完善文档/代码源文档），管整体/全局问题；ai-tutoring 实测 23 块；大文件（>5000 字符）只 embed(summary) 作摘要级粗召回（依据：分析-01 / 分析-03）。
- **切片池 `rag-slice`**：细节切片块 + 引导问题块（authority 1.0 混入），管追问/细节；ai-tutoring 实测 294 块；每块写两个 key——`-c` 内容路 embed(summary+text)、`-q` 问题路 embed(summary)（依据：分析-01 / 分析-03）。
- **为什么两池**：只有预写 QA（索引层）→ 自由问题全拒答、RAG 没证据；只有源文档全文 → 答案不可控、现场易翻车；双池分层各管一个目标，互补（依据：完善文档 03 / 引导问题.md 第 30 问）。
- **落地翻转**：方案"同一 COS 索引 + doc_type=qa/source 区分"落地为**两个物理 COS 索引** `rag-full`/`rag-slice`（metadata 无 doc_type，被 module + pool 取代）（依据：分析-01 / 分析-03）。
