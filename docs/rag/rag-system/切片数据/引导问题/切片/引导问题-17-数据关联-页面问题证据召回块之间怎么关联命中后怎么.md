## 回答

**核心结论**：切片块 tags 带 module/category/source/authority/anchor 建立关联；向量命中后按 key（`rag-{pool}/{module}/{file}/{anchor}#{idx}`）反查本地 jsonl 拿全文喂生成，BM25 直读同批 jsonl。

**分层展开**：
- **关联建立**：切片块 metadata 10 字段（version/module/category/source/authority/section/file/file_path/anchor/summary）——module 关联页面/模块、anchor 关联节、file 关联源文档，形成"页面（模块/节）→问题 → 证据块"的可追溯链（依据：分析-03）。
- **回源拿全文**：向量命中返回 key → `_key_of`/keymap 按 key 反查**本地 jsonl** 拿全文/摘要喂生成；BM25 直读同批 jsonl——两路 key 规则统一（`rag-{pool}/{module}/{file}/{anchor}#{idx}`）保证可并集融合（依据：分析-03 / 分析-04）。
- **查看原文**：前端引用块"查看原文"走 Java 代理 → Python `GET /api/rag/source/{file_path}` 从 COS 普通桶读源文件，前缀白名单 `rag-source/`、`rag-slices/` 防任意 COS key 读取（依据：分析-08 / 分析-09）。
- **⚠️ 反查依赖本地 jsonl**：COS metadata 不含 text（上限 10 字段/单条 ≤2048B），全文只能靠 key 反查本地 jsonl——反查失败（缺块）则全文丢失（依据：分析-03）。
