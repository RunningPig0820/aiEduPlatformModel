## 回答

**核心结论**：引导问题块（authority 1.0）混在切片池、纯问题不切片进全量池；点击后走切片池 `-q` 问题路对池内原题命中 sim~0.99——可答性由池保证、检索真实发生，所以叫"索引层入口"。

**分层展开**：
- **切片池里的引导问题**：引导问题块混在切片池（`rag_slices.jsonl` 首块 source="引导问题"），authority 1.0，每块带 `-q` 问题路向量；纯问题（问题列表）不切片进全量池，而是进 `guide_pool` 底座池（依据：分析-01 / 分析-05）。
- **点击后检索真实发生**：引导题点击 → `POST /ask` → 走切片池 `-q` 问题路检索，对池内原题命中 sim~0.99——**可答性由池保证，检索真实发生**，两件事不冲突（依据：完善文档 02 / 分析-05）。
- **summary 必须语义对齐（K9）**：引导题 summary 曾用 LLM 翻译版导致语义错位（sim 0.65）、BM25 排第 7 召不回；改 summary=问题标题后 BM25 第 1、向量第 1（sim 0.8513）——离线切片元数据语义必须与线上 query 对齐（依据：坑档案 K9 / 分析-02）。
- **⚠️ rag-system 现状**：`GUIDE_POOL` 无 rag-system 独立池，current_project=rag-system 时兜底 ai-tutoring 池 + "RAG项目"入口模板；问题列表生成后需同步 `GUIDE_POOL["rag-system"]` 5 组（依据：分析-05）。
