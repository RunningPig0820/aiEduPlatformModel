## 回答

**核心结论**：靠 `metadata.module` 标签 + query 侧 COS Filter($eq) 过滤隔离；key 带 module 段（K10 修复）保证跨模块同名文件（如两模块完善文档 01-08）不互相覆盖。

**分层展开**：
- **隔离机制**：多模块共用 `rag-full`/`rag-slice` 物理索引，靠 `metadata.module` 打标 + query 侧 `build_filter({"module":{"$eq": module}})` 下推 COS 向量层过滤，防其他模块相似向量挤占 top-k（依据：分析-03 / 分析-04）。
- **曾经会串（K10）**：块 key 原只有 `{池}/{file}/{anchor}#{idx}` 不含 module——ai-tutoring 与 question-analysis 各自都有"完善文档 01-08"同名文件，生成相同 key，**后写覆盖先写**，keymap 只剩后写块，跨模块块丢失（依据：坑档案 K10）。
- **修复**：`make_key` 加 module 段 → `rag-{pool}/{module}/{file}/{anchor}#{idx}`（`build_index.py:59-65`），`query._key_of` 同步；验证 `_key_of(ai-tutoring/01-模块)` ≠ `_key_of(question-analysis/01-模块)`，252 passed（依据：坑档案 K10）。
- **关联注意**：`--clear` 清的是整个池不分模块——多模块共池下 `--clear --module rag-system` 会连该池其他模块向量一起删，需重灌全部模块（依据：分析-03）。
