# 评测首跑检索全对但答案质量分只有 2.60，怎么定位修复的？

## 回答

**核心结论**：K2：trace 回溯发现**不是生成层**——是判分 prompt 认不出同义表述 + 评测集 expected_points 混入无关细节；修判分 + 收窄评测集 → 质量 2.60→4.60，hit@3 不变；教训"分数低先查判分器和评测集"。

**分层展开**：
- **现象**：评测 agent 首跑 5 条 → hit@3=0.80 但质量分均 2.60；其中 2 条是"检索全对（hit@3=1.0）但答案质量差"（依据：坑档案 K2）。
- **根因（trace 回溯后修正）**：不是生成层问题——①判分 prompt 认不出同义表述（要点"ScoreMapper 累计"=答案"题型掌握度回流"）、误判语料有支撑的表述为"编造"、无评分锚定；②评测集 expected_points 混入不适用该问题的细节（依据：坑档案 K2）。
- **修复**：判分 prompt 强化（同义覆盖即算覆盖 + 传语料块供"编造"判定 + 0~5 评分锚定）+ 评测集 expected_points 收窄 → **质量分 2.60→4.60**，hit@3 保持 0.80（依据：坑档案 K2 / 完善文档 07）。
- **教训**：评测 agent 的 trace 回溯——**分数低先查判分器和评测集，别急着怀疑检索/生成；分层定位要分层修**，否则会错误地去改生成代码（依据：坑档案 K2）。
