## 回答

**核心结论**：K8：`intent` 没解析指代词=current_project、D4 硬路由过激进；修复=指代词规则 + 优先级放宽（只有"无指代 + 明确问 RAG 整体"才选 rag-system）+ 确定性兜底 `_deictic_anchor`（LLM 不听话也能兜住）。

**分层展开**：
- **现象**：学生在"AI答疑"功能页问"这个功能的底层是怎么实现的？"，助手答"未找到关联文档，我尚未掌握。"——当前功能页问本功能架构必然拒答，且是架构/难点高频方向，体验断裂（依据：坑档案 K8）。
- **根因（三处叠加）**：①intent 把"底层实现/架构"按 D4 硬路由到 rag-system，没解析指代词"这个功能"=current_project；②D4 硬路由规则过激进——current_project 明确时，"XXX 功能的底层"应在当前模块架构语料（ai-tutoring 有 03 等），而非一律 rag-system；③意图判到无语料模块 → rerank 空 → 必然拒答（依据：坑档案 K8）。
- **修复（4 改法）**：①`_INTENT_SYSTEM` 加指代词规则（"这个功能/它/本功能/当前功能/这个项目"→current_project）；②优先级放宽：只有"无指代 + 明确问 RAG 系统整体"才选 rag-system；③ctx_line 强约束"这个功能=current_project，不要因底层/实现/架构跳 rag-system"；④**确定性兜底** `_deictic_anchor`（`query.py:275-290`）——问题含指代词且未点名其他模块名 → 强制 anchor=current_project，LLM 不听话也能兜住（依据：坑档案 K8）。
- **验证**："这个功能的底层"→ai-tutoring；"RAG 系统整体架构是什么？"→rag-system（硬路由保留）（依据：坑档案 K8）。
