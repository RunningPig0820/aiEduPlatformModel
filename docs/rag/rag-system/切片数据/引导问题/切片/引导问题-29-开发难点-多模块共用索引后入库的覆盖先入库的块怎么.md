## 回答

**核心结论**：K10：块 key 原只有 `{池}/{file}/{anchor}#{idx}` 不含 module，跨模块同名文件后写覆盖先写；修法=`make_key` 加 module 段 `rag-{pool}/{module}/...`，`query._key_of` 同步，252 passed。

**分层展开**：
- **现象**：ai-tutoring 与 question-analysis 共用 `rag-full`/`rag-slice` 索引，各自都有"完善文档 01-08"这类同名文件——后入库的覆盖先入库的，检索命中后 keymap 只剩后写块，跨模块块丢失（依据：坑档案 K10）。
- **根因**：块 key 规则只有 `{池}/{file}/{anchor}#{idx}`，**不含 module 段**——多模块共用同一物理索引时，跨模块同名文件生成相同 key，COS 向量桶按 key upsert，后写覆盖先写（依据：坑档案 K10）。
- **修复**：键规则加 module 段 `rag-{pool}/{module}/{file}/{anchor}#{idx}`——`build_index.py:59-65` `make_key` 加 module 参数、`query.py` `_key_of` 同步；测试 mock 命中键补 module；验证 `_key_of(ai-tutoring/01-模块)` ≠ `_key_of(question-analysis/01-模块)`，252 passed（依据：坑档案 K10）。
- **面试口径**：共享物理索引 = 多租户，块唯一键必须含业务命名空间（module），否则同名文件互相覆盖；这类"后写覆盖先写"是典型隐性丢数据，key 设计先想清命名空间（依据：坑档案 K10）。
