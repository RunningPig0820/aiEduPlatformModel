## 回答

**核心结论**：落地无 page 参数：模块级 `current_project`/`anchor` 过滤选池（锁模块）+ 节级 `locked_sections` 加权 ×1.5（锁节，只加权不过滤）；页面模式≈locked_sections 非空、全局模式≈空；白盒链路节级被旁路。

**分层展开**：
- **方案 vs 落地**：方案 D3"前端传 page，页面模式锁页检索 / 全局模式跨页"在代码中**无 page 参数**，演变为两层锚定（依据：分析-01）。
- **模块级锚定（锁模块）**：`current_project`（请求字段）+ intent LLM 输出 `anchor`（闭集 `MODULE_ANCHORS`）→ `select_corpus` 按 module 过滤选池（依据：分析-01 / 分析-04）。
- **节级锚定（锁节，只加权不过滤）**：`locked_sections`（01~08 完善文档节）来自 ANCHOR_RULES 关键词表或 LLM category 映射；orchestrate 中 `anchor_w = ANCHOR_WEIGHT(1.5) if section in locked else 1.0`——节级只加权不过滤（依据：分析-01 / 分析-04）。
- **页面/全局模式**：页面模式 ≈ `locked_sections` 非空、全局模式 ≈ 空，无显式模式布尔（依据：分析-01）。
- **⚠️ 白盒旁路**：assistant 链路 `recall` 写死 `locked_sections=[]`（`assistant.py:118`），节级锚定加权 ×1.5 在白盒被旁路，只走模块级 corpus 过滤；旧 1.6C 端点则把完整 `it` 传入 orchestrate，节级锚定生效（依据：分析-01 / 完善文档 03）。
