## 回答

**核心结论**：多路召回本身就是降级备份：向量路挂 → 纯 BM25；单路 2s 超时降空路；doubao 生成挂 → 召回清单/降级话术；全挂 → 边界话术；所有兜底写死 0 token 短路防无谓成本，响应结构不变。

**分层展开**：
- **降级矩阵**：向量路挂/超时 → 纯 BM25（1.6C 捕获异常构造空向量结果）或空路 + `DEGRADED_VECTOR` 标记（白盒单路 2s 超时 `RAG_RECALL_TIMEOUT`）；生成挂 → 召回块清单当答案；无命中 → 拒答；全挂 → 边界话术兜底（依据：完善文档 06 / 分析-07）。
- **多路召回当降级备份**：BM25 纯本地（jieba 分词 + Okapi）不依赖外部、断电断网可用——向量路挂时兜底，这正是双池三路（全量向量 + 切片 -c/-q 双向量 + BM25）多路设计的目的（依据：分析-04 / 分析-07）。
- **短路纪律（防无谓成本）**：所有兜底话术写死 0 token（boundary/gen timeout/gen fail/问候/澄清/关闭），触发边界**绝不调 generate**（注释：rerank 空时 doubao 会自生成"未覆盖"话术 32 token，编排器必须拦）（依据：分析-07 / 完善文档 09）。
- **结构不变 + 评测不降级**：所有降级路径响应结构不变，前端只按同一结构渲染；评测走真实检索原语不降级，向量挂了就暴露，不让降级掩盖真实质量（依据：完善文档 09 / 分析-06）。
