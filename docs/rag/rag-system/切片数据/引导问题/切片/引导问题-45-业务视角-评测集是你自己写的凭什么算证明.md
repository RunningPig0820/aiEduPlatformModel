## 回答

**核心结论**：评测走**真实检索原语不降级**（向量挂了就暴露）；hit@k 是引用命中客观率（纯函数）；判分 LLM 只报事实、分数硬算、编造封顶 3 分，报告按语料版本可 `--compare` 对比。

**分层展开**：
- **真实检索不降级**：`eval_agent` 走 `retrieve_dual`/`orchestrate` 真实原语，**不走带降级语义的 API**——向量挂了评测就暴露，不让降级掩盖真实质量问题，这是"自证"可信度的关键（依据：分析-06）。
- **hit@k 客观率**：`hit_at_k` 是纯函数——expected 引用与召回块 file 做**双向子串匹配**，任一引用命中比例客观可复算（依据：分析-06）。
- **判分硬算**：判分 LLM **只报事实**（covered_count/fabricated/rationale，不报分数），分数由 `_score_from_covered` 规则硬算（覆盖比例分档 + **编造封顶 3 分**）——分数可复现、编造权重高于遗漏（依据：分析-06）。
- **版本对比**：报告按语料版本（date-sha1[:6]）命名，`run_eval --compare` 对比 hit@k/质量/成本/耗时四指标——语料变了指标变了，可定位回归（依据：分析-06）。
- **⚠️ 局限（诚实）**：评测集仅 ai-tutoring 6 条（含 1 条边界拒答）；`eval_dataset` 硬编码 `module=="ai-tutoring"`，rag-system 无评测集——扩到 30~50 条才谈稳定基线（依据：分析-06 / 完善文档 07）。
