## 回答

**核心结论**：方案目标每模块 30~50 条评测集，现状仅 ai-tutoring 6 条；`eval_dataset` 硬编码 `module=="ai-tutoring"` → rag-system 无评测集，多模块评测需先改代码；hit@k/质量/成本/版本对比已具备，扩样本量才谈稳定基线。

**分层展开**：
- **方案目标**：评测 agent 每模块 ≥5 条（5 类各 1 + 边界拒答），方案设计每模块 30~50 条评测集（依据：分析-06 / 完善文档 08）。
- **现状局限**：仅 `ai-tutoring.jsonl` 6 条（5 正常 + 1 边界拒答"帮我写一封辞职信"）；`eval_dataset._validate` 硬编码 `module=="ai-tutoring"`（`eval_dataset.py:76`）→ rag-system/其他模块评测集无法过校验——多模块评测需先改代码（依据：分析-06）。
- **已具备的能力**：hit@5（引用命中客观率，纯函数）+ 质量分（判分 LLM 只报事实、分数硬算、编造封顶 3 分）+ 成本/耗时 + 报告按语料版本 `--compare` 对比（依据：分析-06）。
- **增强方向**：扩样本量到每模块 30~50 条才谈稳定基线；修 `eval_dataset` 模块硬编码支持多模块评测；判分只拼前 4 块 ×600 字、判分失败记 0 等已知瑕疵待补（依据：分析-06 / 完善文档 07）。
