## 回答

**核心结论**：三次关键反转：范围（4 业务模块 → 仅 RAG 禁区拒答 → 定稿四模块全放行 + 范围门唯一拒答）、引导（变体文案强制检索 → 池内原题直出）、鉴权（body 传 role → 可信源 403）；每次反转都是"现场实测否定方案"驱动的数据驱动收敛。

**分层展开**：
- **范围反转**：08-21 覆盖 4 业务模块 + RAG 自身 → 08-25 spec 一度反转为"仅 RAG 项目、禁区拒答" → 最终定稿**四模块全放行 + 范围门低置信唯一拒答**——语料驱动、无禁区列表（依据：完善文档 01）。
- **引导反转**：方案"UI 引导问题 = 索引层规范问题的**变体写法**强制检索真实发生"→ 实测 LLM 改编"换提问方法"引入池外概念（如"向量索引"）无对应切片 → 学生点了匹配不到答案 → 反转**池内原题直出**（0 token，100% 可答）（依据：坑档案 K7 / 完善文档 03）。
- **鉴权反转**：方案"前端 body 传 role"→ 反转**从可信 HttpSession 取 role**、body 传 role 一律忽略、非学生固定 403、0 token 不产 trace（依据：完善文档 09 / 分析-08）。
- **为什么反转**：每次都是"现场实测否定方案"驱动的数据驱动收敛——用户实测（点引导题复现答非所问）、三端联调自测（"这个功能的底层"复现必然拒答）、V4 三端对账（方案有/代码无漂移）暴露了方案与现实的差距，用数据收敛到更可靠的实现（依据：完善文档 01 / 坑档案 V4）。
