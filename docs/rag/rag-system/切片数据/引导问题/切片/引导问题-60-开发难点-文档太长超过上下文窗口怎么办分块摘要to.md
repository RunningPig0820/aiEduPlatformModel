## 回答

**核心结论**：四招齐用——切片分块（split 块 ≤6000 字符）+ 摘要粗召回（全量池 >5000 字符只 embed summary，防 8192 token 静默截断）+ top-K 限制上下文膨胀（TOP_K=5、单块 MAX_GEN_TEXT=1200 截断）+ history 截断（HISTORY_LIMIT=3 轮），另有 0 token 兜底话术。

**分层展开**：
- **切片分块**：超长 split 块按段落贪心拆到 ≤6000 字符，单段超限按 6000 硬切**保尾部进索引**，替代早期会截掉尾段的做法（依据：分析-02 chunk_paragraphs）。
- **摘要粗召回**：全量池条件式 embed——`FULL_EMBED_MAX_CHARS=5000` 字符以内 `embed(summary+全文)`，超限只 `embed(summary)`，防大语雀（10~12K 字符）超 dashscope 8192 token 被静默截断（依据：分析-03 build_index.py:176-183）。
- **top-K 限制上下文膨胀**：TOP_K=5 生成块数、VEC_K=12 向量召回、BM25_K=10；单块生成截断 `MAX_GEN_TEXT=1200` 丢尾——top-K 限制本身是成本叙事的一环（依据：分析-04 常量表 / 语雀总揽 §7.2）。
- **history 截断**：`HISTORY_LIMIT=3` 只喂最近 3 轮给 intent/rewrite，会话状态/累计 token/trace 快照归 Java Redis（TTL 24h），Python 无状态（依据：分析-04 / 分析-08）。
