## 回答

**核心结论**：build_index.py 读本地 jsonl → embed → put_vectors（批 20、写后 sleep 10s 等异步生效）入 COS 向量桶 rag-1318177119；所谓"增量"实际是重读当前 jsonl 全量 upsert（同 key 覆盖），旧 key 残留需 --clear 清池，且 --clear 清的是整个池不分模块。

**分层展开**：
- **构建流程**：POOLS 定义 full/slice 两池（rag-full/rag-slice）→ MODULE_DATA 模块 jsonl → 逐块 embed（dashscope text-embedding-v3 768d）→ put_vectors 每批 20、写后 sleep 10s 等异步生效（依据：分析-03 build_index.py:42-55、185-190）。
- **增量真相**：不带 `--clear` 重跑 = 重读当前 jsonl 全量 upsert（同 key 覆盖），**没有按块 diff 的增量逻辑**；旧 key 若已不在 jsonl 中不会被删，除非先 --clear 清池（依据：分析-03 隐性坑8）。
- **--clear 语义**：清的是整个池、不分模块——`--clear --module rag-system` 会把该池内 ai-tutoring/question-analysis 的向量一起删光，多模块共池时须注意（依据：分析-03 隐性坑1）。
- **索引预建与异步生效**：脚本不建索引，需控制台预建 768/float32/cosine，get_index 缺失即报错退出；COS 向量写入 10s 异步生效、写完立即 query 会 miss（demo 前需预建索引/等待生效）（依据：分析-03 隐性坑5/6）。
