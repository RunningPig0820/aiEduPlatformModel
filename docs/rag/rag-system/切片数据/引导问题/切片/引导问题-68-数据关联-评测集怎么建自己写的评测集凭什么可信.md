## 回答

**核心结论**：评测集={module, question, question_type, expected_references, expected_points}、每模块≥5 条（5 类各 1 + 边界拒答），校验失败当场抛错；可信四理由：走真实检索原语不降级、hit@k 是引用命中客观率纯函数、判分 LLM 只报事实+分数硬算+编造封顶 3、报告按语料版本可 --compare 对比。

**分层展开**：
- **结构与校验**：`eval_dataset` 校验 question 必填、question_type ∈ 闭集（项目介绍/操作/数据关联/难点/最危险/边界拒答）、expected_references/expected_points 必填、MIN_PER_MODULE=5，失败即抛不静默（依据：分析-06 eval_dataset.py）。
- **可信四理由**：①评测走真实检索原语 `retrieve_dual`/`orchestrate` **不降级**，向量挂了就暴露，不让降级掩盖质量问题；②hit@k 是引用命中客观率、纯函数可单测；③判分 LLM 只报 covered_count/fabricated 事实、分数由 `_score_from_covered` 硬算、编造封顶 3 分；④报告按语料版本 date-sha1[:6] 命名、`--compare` 对比 4 指标（依据：分析-06 设计要点 / 完善文档 08）。
- **局限（如实说）**：评测集 module 硬编码 `ai-tutoring`、仅 6 条（5 正常 + 1 边界拒答），无 rag-system 评测集——多模块评测需先改 `eval_dataset.py:76`；样本小，指标主要证明"评测体系能跑、能版本对比定位回归"，扩到 30~50 条才谈稳定基线（依据：分析-06 / 坑档案 A4 / 完善文档 08 追问）。
