## 回答

**核心结论**：前端带 sessionId+history 发请求、Python 消费 history 做 intent/rewrite；HISTORY_LIMIT=3 截断最近 3 轮；会话状态/累计 token/trace 快照归 Java Redis（rag:assistant:* 键 TTL 24h），Python 无状态可水平扩展。

**分层展开**：
- **上下文窗口控制**：`HISTORY_LIMIT=3` 只喂最近 3 轮给 intent/rewrite，防上下文膨胀；单块 `MAX_GEN_TEXT=1200` 截断 + TOP_K=5 限制上下文——top-K 限制是成本叙事一环（依据：分析-04 / 语雀总揽 §7.2）。
- **状态归属（Java Redis）**：`rag:assistant:session:{sessionId}:usage`（累计 token+轮数）、`:closed`（关闭标志）、`rag:assistant:trace:{traceId}`（每轮 done camel 快照）、`rag:assistant:eval:recent`，全部 TTL 24h（依据：分析-08）。
- **Python 无状态**：只消费 history/trace_id，不自己认证、不碰会话、不落库，可水平扩展；SSE 中断可凭 permission.traceId 调 GET turns/{traceId} 补回 answer/quotedKeys/usage（依据：分析-08 / 引导问题 12）。
