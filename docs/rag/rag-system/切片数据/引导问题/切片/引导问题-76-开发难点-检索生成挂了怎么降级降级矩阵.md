## 回答

**核心结论**：降级矩阵——向量路异常/超时→降级纯 BM25（白盒单路 2s 超时降空路）、BM25 纯本地兜底；doubao 生成挂→召回块清单当答案（1.6C）/流式降级话术（白盒 reason=timeout）；全挂→边界话术；所有兜底写死 0 token 短路不调 generate，响应结构不变对前端透明。

**分层展开**：
- **向量路降级**：1.6C 端点 `retrieve_dual` 异常 → 捕获构造空向量结果、降级纯 BM25（references 仍返回）；白盒 `_recall_vector` 单路 2s 超时（RAG_RECALL_TIMEOUT）→ 空路降级 DEGRADED_VECTOR，BM25 本地路永远可用（依据：分析-07 api/rag.py:97-106 / assistant.py:71-88）。
- **生成降级**：1.6C doubao 挂 → 召回块清单当答案（"生成服务不可用，以下为检索到的语料…"，不空答）；白盒流式 8s 超时（RAG_GEN_TIMEOUT）→ GEN_TIMEOUT_MSG + 召回清单 reason=timeout（依据：分析-07）。
- **全挂兜底**：1.6C 无命中 → 拒答"语料未覆盖"；白盒 rerank 空 → BOUNDARY_MSG"未找到关联文档，我尚未掌握"；全部降级写死 0 token 短路、不调 generate 防无谓成本（依据：完善文档 09 / 分析-07）。
- **诚实标注**：`DEGRADED_VECTOR`/`DEGRADED_BM25` 标记定义了但未透传 SSE 事件（rerank/done 不带 degraded），前端拿不到"本轮降级"显式信号；评测走真实检索原语不降级（向量挂了就暴露，不让降级掩盖质量）（依据：坑档案 A3 / 分析-06）。
