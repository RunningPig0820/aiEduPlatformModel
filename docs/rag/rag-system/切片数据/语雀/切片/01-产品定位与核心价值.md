> 检索摘要：这个系统到底是做什么的？为什么说"不是纯 RAG、RAG=证明能力的引擎"？"一鱼两吃"是什么意思？产品范围从 08-21 到 08-25 怎么反转收窄的？它面向面试官能回答哪 9 类问题？

系统定位为**项目介绍 RAG 问答系统**：**不是纯 RAG，产品 = 项目介绍问答，RAG = 证明能力的引擎**；RAG 本身也作为项目一个功能点被介绍（"一鱼两吃"——用系统介绍系统）。证据：语雀-原文件-问题1.md / 问题3.md。

### 产品意图反转：08-21 vs 08-25

产品范围在两套设计之间发生**反转/收窄**，是本模块最关键的演进事实（详见 `语雀-演进时间线.md`）：

| 维度 | 08-21 已设计 | 08-25 今日 spec | 关系 |
|---|---|---|---|
| 介绍对象 | 4 业务模块 + RAG 自身 | 仅 RAG 项目；AI答疑/知识图谱/题型分析=禁区拒答 | 🔴 范围反转/收窄 |
| 鉴权 | role 由 body 传（demo） | 可信源(Token/网关Header)取角色，仅学生放行，否则固定 403 | 🔴 收严，禁 body |
| 白盒透传 | 无（只回结果 + retrieved_docs） | 权限→意图→改写→召回→重排→token 全阶段 SSE 透传 | 🟢 新增 |
| 意图识别 | 无独立分类器（范围门兜底） | 硬路由：架构/代码/部署/评测/接口→RAG项目；禁区→固定拒答 | 🟢 新增 |
| Query 改写 | 无 | 改写后问题透传前端 | 🟢 新增 |
| 重排 | "小语料不需要重排模型" | RRF 融合，Top-K=3 | 🟡 08-21 显式否决过 RRF |
| 引用 | citations(page/section/source_doc) | Top-K 块 + is_quoted（LCS 硬匹配，8中/12英） | 🟢 新增确定性引用 |
| 引导 | 每页 5~8 条索引层 QA + 变体 chips | suggestions_pool.json 静态池随机 2~3 条，4 方向 | 🟡 简化/静态化 |
| 超时 | 检索 <2s / 生成 <15s | 召回 2s / 生成 8s | 🟡 生成收紧 |
| 断连 | "保留已吐内容" | is_disconnected() 主动取消 LLM 流 | 🟢 新增 |
| Token | cost{prompt/completion/cumulative/cost_yuan/embedding} | tokens_usage{prompt/completion/cache_hit/total} + trace_id | 🟡 标准化+新增 |
| 会话 | 页面锚定 + 5 轮上限 | 不设轮数上限（用户确认轮数无意义）；上下文窗口保留最近 3 轮 history | 🟢 08-25 已定 |

证据：语雀-原文件-问题8.md（对比表全文）。

### 9 类问题矩阵（RAG 功能清单）

面试官问题按 9 类分类，每类对应不同的检索目标与展示形态（问题 2 定义的功能矩阵）：

| # | 问题类型 | 例子 | RAG 检索什么 | 展示形态 |
|---|---|---|---|---|
| ① | 概览类 | "介绍一下这个模块" | 产品定位+核心功能 | 项目卡片+一句话定位 |
| ② | 设计意图类 | "为什么这么设计？关键点" | 设计决策/Rationale | 关键决策点卡片（带出处） |
| ③ | 数据流转类 | "数据怎么流转的？" | 数据流/架构章节 | 流程图（mermaid→前端渲染） |
| ④ | 技术实现类 | "用什么技术栈？有哪些接口/表？" | 技术选型/API spec | 技术栈清单+接口列表 |
| ⑤ | 难点踩坑类 | "遇到什么难点？怎么解决？" | 设计权衡/问题记录 | 难点→解法卡片 |
| ⑥ | 对比权衡类 | "为什么用 Neo4j 不用 MySQL？" | Trade-offs/Decisions | 对比表 |
| ⑦ | 指标规模类 | "多少节点？匹配率？性能？" | 数据规模/验收指标 | 数字卡片（带引用来源） |
| ⑧ | 权限范围类 | "这个页面谁能用？" | 权限/角色定义 | 角色说明 |
| ⑨ | 边界规划类 | "题库做了吗？下一步呢？" | 范围/里程碑 | 明确边界或规划 |

证据：语雀-原文件-问题2.md。数据流转类（③）为差异化亮点——RAG 生成 mermaid 描述、前端渲染成图。

### D1 产品定位：不是纯 RAG，RAG=证明能力引擎，一鱼两吃
> 检索摘要：系统定位为项目介绍问答而非纯RAG：产品=把项目讲清楚，RAG=证明能力的引擎；RAG 本身也作为项目功能点被介绍，一鱼两吃。

| 属性 | 内容 |
|---|---|
| 背景 | 面试/汇报要"把项目讲清楚 + 证明 RAG 能力"；初期曾考虑知识点题型 RAG，但无题库做不了闭环 |
| 演进 | 知识点题型 RAG（否决）→ 项目介绍 RAG：基于自身方案/设计文档自包含语料，demo 随时能跑 |
| 拍板理由 | 纯 RAG 自由发挥不可控、全预写答案=查表露怯；双目标需要"分层语料 + 引擎"组合，用系统介绍系统（一鱼两吃） |
| 系统影响 | 语料=自身方案/设计文档（OpenSpec+语雀+CLAUDE.md），自包含不依赖题库；9 类问题矩阵成为 RAG 功能清单 |
| 证据 | 语雀-原文件-问题1/问题3；[总揽§1]；rag-system.md |
