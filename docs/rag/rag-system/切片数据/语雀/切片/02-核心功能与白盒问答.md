| 属性 | 内容 |
|---|---|
| 业务场景 | 白盒引用面板展示引用状态 |
| 触发条件 | rerank 事件先到达（此时 is_quoted 未知），done 后才算出 quoted_keys |

### 选型10：流程图选型
> 检索摘要：数据流流程图预置 mermaid（完善文档第 4 节内）为主，命中"数据流"类问题直接渲染，零渲染风险；动态生成仅兜底（08-25 spec Non-Goals 明确"不实现 mermaid 动态生成"）。

- 选型场景：数据流图怎么给——预置还是动态生成
- 候选方案A：预置 mermaid
  - 方案A优劣：每模块完善文档第 4 节存一张 mermaid 数据流图，命中"数据流"类问题直接渲染；稳定、快、面试不翻车。
- 候选方案B：动态生成（LLM 现场生成 mermaid）
  - 方案B优劣（致命短板）：炫、有差异化；但 LLM 现场生成的 mermaid 有语法/渲染风险，格式不可控，面试现场容易翻车。
- 最终拍板：预置 mermaid 为主（每模块第 4 节），动态生成仅兜底
- 拍板理由：demo 可靠性优先，预置零渲染风险（D8）；动态生成仅作未预置时的备选通道，演示不依赖（问题5 C）。
- 落地对账：✅ 落地——每模块完善文档第 4 节预置 mermaid 数据流图，数据流转类问题直接渲染；08-25 前端/后端 spec Non-Goals 均明确"本期不做 mermaid 动态生成/流程图渲染"（design-frontend Non-Goals、design-java Non-Goals）。结论=落地。

### 选型13：会话切换选型
> 检索摘要：功能点切换只在下一轮发生（intent 每轮判锚点变化→发 switch 事件→重置上下文），放弃生成中切换——后者需中止上游流、作废半截答案、白烧 token，复杂度高且无业务价值；08-25 会话不设轮数上限，改最近 3 轮 history 截断。

- 选型场景：切换功能点发生在哪一轮
- 候选方案A：下一轮切换
  - 方案A优劣：intent 每轮本来就跑，多一次"当前锚点 vs 已锚定"对比；switch 前零生成 token，成本极低。
- 候选方案B：生成中切换
  - 方案B优劣（致命短板）：①中止上游 doubao HTTP 流 ②半截答案作废 ③半截 token 已计费不退款 ④再起新一轮；Python 服务端取消上游流不可靠，复杂度与成本全面新增。
- 最终拍板：下一轮切换（switch 事件只作用于下一轮上下文：重置锚点、清上轮召回、重走 rewrite→recall）
- 拍板理由：业务上"生成中切换"其实不存在——学生只会等流完再问下一轮，或不想等就前端取消 fetch（is_disconnected 中止）；生成中切换复杂度高且无业务价值（问题9）。
- 落地对账：✅ 落地——`switch_detected = (前端 current_project ≠ 会话已锚定 project) 或问题明确指向另一有语料模块`，检测到发 switch 事件 + 重置上下文，不掐在途流（D3）；生成中只做 `is_disconnected()` 中止上游流防空转（`assistant.py:460-462, 628-630`）。⚠️ 会话轮数：08-21"追问上限 5 轮/会话"→ 08-25 定稿**不设轮数上限**（用户确认轮数无意义），改上下文窗口保留**最近 3 轮** history（`HISTORY_LIMIT=3`，`query.py:79`，history 前端传、Java 透传 Python 只消费+截断；刷新后为空=新会话）。结论=方案落地 + 轮数口径变化。

### D5 SSE 事件契约：事件序列与分支无流规则
> 检索摘要：SSE 事件时序冻结为 permission→intent→(clarify|switch)→rewrite→rerank→(boundary|token)→done；clarify/switch 分支无 rewrite/recall/generate，boundary 分支无 token 流；done 为所有分支终止点。

| 属性 | 内容 |
|---|---|
| 背景 | 白盒需要中间状态逐阶段透传，前端依赖事件顺序渲染链路阶段 |
| 演进 | 定稿时序 + 分支无流规则（clarify/switch 分支无 rewrite/recall/generate；boundary 分支无 token 流、rerank 可为空）；permission 事件由 Java 网关产，Python 生产端点从 intent 开始（无角色信息） |
| 拍板理由 | 前端按事件顺序点亮阶段行；时序不得重排/丢失（沿用 tutoring 阶段二契约冻结纪律） |
| 系统影响 | done 携带 answer/quoted_keys/tokens_usage/trace_id/suggestions，前端到 done 停止一切转圈；M2 冻结契约，下游只补字段不重排 |
