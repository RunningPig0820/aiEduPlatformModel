> 检索摘要：为什么检索要设计成"双池"？索引层QA池和源文档池怎么分工、为什么一个可控一个纯RAG？doc_type 怎么区分？代码落地为什么变成了 rag-full/rag-slice 两个物理索引？模块怎么隔离？

系统在线检索建立在**双池**之上（同一 COS 索引，`doc_type` 区分）：

```
┌────────────────────┬────────────────────────┐
│ 双池（同一 COS 索引，doc_type 区分）          │
│  索引层QA池(doc_type=qa) 预写可控 +           │
│  源文档池(doc_type=source) 纯RAG证据          │
└────────────────────┬────────────────────────┘
```

### 核心术语

| 术语 | 定义 |
|---|---|
| 双池检索 | 索引层预写 QA 池 + 源文档池 两层语料结构，同一 COS 索引以 `doc_type` 区分 |
| 索引层QA池 | 预写"问题+答案要点+引用"条目（doc_type=qa），引导问题命中→答案可控、上下文小、便宜 |
| 源文档池 | 完善文档全文 chunk（doc_type=source），自由问题命中→纯 RAG 真发挥 |
| 双池三路（代码落地） | 全量池向量(rag-full) + 切片池双向量(rag-slice `-c` 内容路/`-q` 问题路) + 本地 BM25，四路 RRF 融合；替代方案 doc_type=qa/source 双池 |
| 模块 id 闭集 | ai-tutoring/knowledge-graph/question-analysis/rag-system 四模块，语料按 metadata.module 过滤选池（D-A） |

### 索引层 QA 条目（doc_type=qa）

每条 = **问题 + 答案要点 + 引用**，每模块 5~8 条；UI 引导问题为索引层规范问题的**变体写法**（例：UI"你们为什么拆成三段" vs 索引"为什么拆 decide/generate/question-understand"），强制检索真实发生、避免"点按钮=预定答案"。证据：语雀-原文件-问题3.md / 问题5.md；design-python-project-intro-rag.md D3。

### 源文档 chunk（doc_type=source）

完善文档全文切片，metadata 四元组：

| 字段 | 含义 |
|---|---|
| page | 所属页面/模块（知识图谱/AI答疑/组织中心/学生知识点分析/RAG问答系统） |
| doc_type | qa（索引层）/ source（源文档池） |
| section | 8 节之一（定位/功能/为什么/数据流/技术/坑/指标/权限） |
| source_doc | 来源文档，支撑"点击查看原文"+ 召回文档面板 |

切片时把源文档全文存进 metadata，答案生成后前端渲染**召回文档面板**（面试官能看到系统捞了哪几段原文）——把 RAG 检索从黑盒变成"能指给你看"。证据：语雀-原文件-问题5.md / 问题8.md。

【落地】代码 metadata 实际 10 字段**无 doc_type**：`version/module/category/source/authority/section/file/file_path/anchor/summary`（`build_index.py:145-157`，注释"doc_type 与 module 同值冗余已去掉 2026-08-26"）；双池 = **rag-full(整篇 23 块) / rag-slice(切片 294 块) 两个物理 COS 索引**，靠 metadata.module + 查询侧 Filter($eq) 隔离；**page 参数未落地**，模块由 current_project/anchor 承载。切片全文不进 metadata（≤2048B 限制），命中后经 key 反查本地 jsonl。证据：分析-01/03。

### 双池在多路召回中的落地（双池三路）

【落地】代码为**双池三路**：全量池向量(rag-full) + 切片池双向量(rag-slice `-c`/`-q`) + 本地 BM25（jieba+Okapi），**四路 RRF**；任一向量路 2s 超时 → 空路降级 + degraded 标记（`RAG_RECALL_TIMEOUT=2.0`）。证据：分析-01/04。

> 检索摘要（选型合并）："检索池为什么分两层？为什么这么选？"——选型拍板：索引层预写 QA 池（doc_type=qa，引导问题稳定可控）+ 源文档池（doc_type=source，自由问题纯 RAG 真发挥），一池满足不了"稳定可控+证明 RAG"两个目标；否决单索引层（自由问题全边界拒绝、RAG 无证据）与纯全文检索（答案不可控易翻车）；落地形态演进 doc_type=qa/source → rag-full/rag-slice 双物理索引 + metadata.module 过滤。

### 选型1：检索池层数选型
> 检索摘要：最终采用索引层预写QA池+源文档池双池检索，引导问题走索引层稳定可控，自由问题走源文档池纯RAG真发挥；方案"同一COS索引用 doc_type 区分"落地为两个物理索引 rag-full/rag-slice + metadata.module 过滤。

- 选型场景：检索池到底几层，决定 RAG 有多"真"、能否证明检索能力
- 候选方案A：单索引层（20~30 条 QA 条目）
  - 方案A优劣（致命短板）：引导问题全可控；但自由问题命中不了就直接边界拒绝，面试官问个没准备的只能答"不在范围"，RAG 能力没有证据。
- 候选方案B：索引层 + 源文档双池
  - 方案B优劣：引导问题走索引层稳定可控，自由问题走源文档池纯 RAG 真发挥（能答没准备的问题）；代价是自由问题不可控一点。方案设计为两池同写一个 COS 索引，用 doc_type metadata 区分。
- 候选方案C：纯全文检索（无索引层）
  - 方案C优劣（致命短板）：最"纯 RAG"；但答案不可控、无法预演，面试现场最容易翻车。
- 最终拍板：双池检索（索引层 QA 池 doc_type=qa + 源文档池 doc_type=source）
- 拍板理由：引导问题要稳定可控、自由问题要证明 RAG，一池满足不了两个目标；"源文档池 = 真的检索"正是 RAG 能力证据（D2）。
- 落地对账：演进——代码落地为两个物理 COS 索引 `rag-full`（整篇 23 块）+ `rag-slice`（切片 294 块），metadata 10 字段无 doc_type（`build_index.py:145-157`，注释"doc_type 与 module 同值冗余已去掉 2026-08-26"）；双池隔离靠 metadata.module + 查询侧 Filter($eq) 下推（`query.py:458-465`）+ 池前缀 key；"预写 QA/引导可答"由切片池引导问题块 + 双向量 -q 问题路承接（`query.py:487-504`）。结论=方案双池拍板成立，形态 doc_type→pool+module。
- 落地对账（页面锚定反转）：反转/演进——方案"前端传 `page` + 页面模式锁页/全局模式跨页"（D3）在代码中**无 page 参数**，演变为两层锚定：模块级 `current_project`/intent `anchor`（决定选哪个语料池，`select_corpus` 按 module 过滤）+ 节级 `locked_sections`（`ANCHOR_WEIGHT=1.5`，`query.py:665`）——**节级锁页从"过滤"退化为"加权 ×1.5"**（只加权不过滤，过滤发生在模块级）；页面模式/全局模式 ≈ locked_sections 非空/空，无显式模式布尔；白盒链路 `recall` 写死 `locked_sections=[]`（`assistant.py:118`），节级锚定加权被旁路，仅 1.6C 端点完整传入。结论=page 参数未落地，模块锚定+节加权落地。

### D2 双池检索：索引层预写 QA 池 + 源文档池
> 检索摘要：采用索引层预写QA池+源文档池双池结构：引导问题走索引层稳定可控、上下文小、便宜，自由问题走源文档池纯RAG真发挥；一池满足不了两个目标。

| 属性 | 内容 |
|---|---|
| 背景 | 引导问题要稳定可控，自由问题要证明 RAG——单一语料池无法同时满足两个目标 |
| 演进 | 早期"两层语料"反向整理散落代码/git 的答案新造索引层 → 定稿双池：索引层 QA 池（doc_type=qa，每模块 5~8 条"问题+答案要点+引用"）+ 源文档池（doc_type=source，完善文档全文 chunk），同写一个 COS 索引用 doc_type 区分 |
| 拍板理由 | 只有索引层→自由问题全变边界回答，RAG 能力没证据；只有源文档池→引导问题不可控易翻车 |
| 系统影响 | 【落地对账】代码无 doc_type（metadata 10 字段 2026-08-26 去掉 doc_type），双池=rag-full(23块)/rag-slice(294块) 两个物理 COS 索引，靠 metadata.module + 查询侧 Filter($eq) 隔离；索引层 QA 条目=引导问题直取预置答案的入口 |
| 证据 | 语雀-原文件-问题1/3/5；design-python-project-intro-rag D2；[总揽§2/§4.1]；分析-01/03 |
