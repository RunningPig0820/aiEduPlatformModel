### 核心术语

| 术语 | 定义 |
|---|---|
| 页面锚定 | 前端传 `page`，检索限定页面范围；是"页面路由"搬到文档域 |
| 页面模式 / 全局模式 | 页面模式=锁页检索；全局模式=跨页检索（自由问题/对比类） |

前端学生页以 `current_project` 做模块锚定：页面 pageCode→模块 id 闭集（缺省 rag-system）；页面模式/全局模式由前端触发。

### 页面锚定过滤

页面模式下检索限定该页（`page` 过滤）；全局模式不限。天然可解释——"这条问题命中了 AI答疑 页面，所以我在这个页面的文档里检索"。证据：语雀-原文件-问题1.md / 问题2.md。

⚠️【落地】**无 page 参数**，演变为两层锚定：模块级 `current_project` + intent anchor（闭集 `MODULE_ANCHORS`，`select_corpus` 按 module 过滤选池）+ 节级 `locked_sections`（`ANCHOR_WEIGHT=1.5`，**只加权不过滤**）；**白盒链路 recall 写死 `locked_sections=[]`（assistant.py:118）节级锚定被旁路**，旧 1.6C 端点则完整传入（两入口召回排序可能不同）。证据：分析-01/04。

### 打分中的锚定加权

方案打分公式 = 相似度 × 问题类型匹配 × 页面锚定加权。⚠️【落地演进】"问题类型匹配"未单独成因子（类别过滤已废弃，LLM 判类别不准误伤），相似度由 RRF rank 间接表达；权威度（1.0 完善文档/0.8 代码/0.7 语雀）连乘、**节锚定命中 ×1.5**；top-K 全局 5（生成用），白盒 rerank 回传 3。证据：分析-01/04。

### 选型15：模块 id 闭集命名选型
> 检索摘要：模块 id 三端统一闭集 ai-tutoring/knowledge-graph/question-analysis/rag-system，弃用 rag-project/question-type；语料选池按块级 metadata.module == anchor 过滤（不依赖目录同名），slice_corpus 的 module 参数化。

- 选型场景：模块标识用什么 id、语料怎么按模块选池（跨前端/Java/Python 三端契约）
- 候选方案A：语义别名 rag-project / question-type
  - 方案A优劣（致命短板）：与页面 pageCode/契约/语料 metadata 三端各叫各的，对不齐；语料选池只能靠目录同名，脆弱易串池。
- 候选方案B：模块 id 闭集（ai-tutoring/knowledge-graph/question-analysis/rag-system）
  - 方案B优劣：三端统一；clarify candidates 传字符串 id 数组，中文 label 由前端 pageModuleMap 维护（Python 不产 label、契约零改动）；语料按块级 metadata.module 过滤，不依赖目录。
- 最终拍板：模块 id 闭集四 id（D-A）
- 拍板理由：语料选池按块级 metadata `tags.module == anchor` 过滤（design-java D-A）；弃 rag-project/question-type；前端 `pageModuleMap.js` 注释"弃 rag-project/question-type"。
- 落地对账：✅ 落地——`MODULE_ANCHORS` 闭集四 id（`query.py:68`），向量层 `build_filter` 按 module Filter($eq) 下推（`query.py:458-465`）+ `select_corpus` 本地按 module 选池（`query.py:609-617`）；⚠️ 遗留：`MODULE_DATA` 仅 ai-tutoring + question-analysis（`query.py:37-40`），**rag-system 无 jsonl**（`DEFAULT_MODULE="rag-system"` 悬空，anchor=rag-system 当前必然边界拒答，分析-01/03）。结论=契约统一落地 + rag-system 语料待入库。
