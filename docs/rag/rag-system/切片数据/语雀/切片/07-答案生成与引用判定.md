### 核心术语

| 术语 | 定义 |
|---|---|
| is_quoted | 引用标记，LCS 最长公共子串硬匹配，连续 8 中/12 英字符命中即引用 |

### 生成链路

`doubao 流式生成(强制引用, 8s) → is_quoted(LCS 后置硬匹配) → done`。证据：语雀-原文件-问题8.md；分析-01/04。

### 每个展示块必须附

每个展示块必须附：**块标题/摘要、文件路径（前端"点击查看原文"）、is_quoted 标签**。被引用块高亮，未引用灰显折叠。证据：语雀-原文件-问题8.md。

### is_quoted 判定规则

不依赖 LLM 主观自述，采用确定性硬匹配——生成完成后遍历每个候选块的 `content_preview`，在最终答案字符串做最长公共子串（LCS）匹配，任意连续 **8 个中文字符（或 12 个英文字符）** 命中即标记 `is_quoted=True`，后端实现、无需 LLM 额外输出。证据：语雀-原文件-问题8.md。

### 白盒时序：先灰后亮

is_quoted 需生成完才能 LCS 匹配，所以 rerank 先发（灰显）、done 后补 quoted_keys（高亮），前端"先灰后亮"，引用面板不闪跳。【落地】`ReferencePanel.jsx`：quotedKeys 命中块高亮+默认展开，其余灰显折叠。证据：语雀-原文件-问题8.md；分析-03。

### 生成模型选择

生成/意图/改写/判分统一 doubao（`doubao-seed-2-0-mini-260428`：生成 0.2 温度 60s 超时、意图/改写/判分 0 温度关思考 20s 超时，`settings.py:56,60`）；glm-4-flash 免费模型优先叙事已放弃。证据：分析-01/04/06。

### SSE 事件：token / done

| 事件 | 内容 | 条件 |
|---|---|---|
| token | 生成流 | |
| done | answer + quoted_keys + tokens_usage + trace_id + suggestions | **所有分支的终止点**（前端到 done 停止一切转圈） |

### 生成中切换：不支持

**下一轮切换**符合业务（intent 每轮本来就跑，多一次"当前锚点 vs 已锚定"对比，switch 前零生成 token）；**生成中切换**是另一量级（中止上游 doubao HTTP 流不可靠、半截答案作废、半截 token 已计费不退款）。生成中只做一件事：`is_disconnected()` → 中止，防空转烧钱。`switch` 事件不掐断在途流，只作用于下一 turn 上下文（重置锚点/清上轮召回/重新 rewrite→recall）。证据：语雀-原文件-问题9.md。

### 选型2：索引层答案形态选型
> 检索摘要：索引层存"问题+答案要点+引用"而非完整答案，检索仍走向量，命中后 LLM 按要点现组织语言并强制引用，避免 RAG 沦为查表、又避免纯检索不可控；代码白盒 generate 已按精排 Top-K 块现组织语言。

- 选型场景：索引层存完整答案还是答案要点，决定 RAG 是"真"还是"虚"（整个系统的十字路口）
- 候选方案A：完整答案全预写
  - 方案A优劣（致命短板）：绝对可控、永不翻车；但 RAG 沦为一个 fancy 查表，面试官一问"检索体现在哪"就露怯。
- 候选方案B：答案要点 + LLM 生成
  - 方案B优劣：索引层存答案要点和强制引用原文段落，LLM 每次从检索到的上下文现组织语言；检索/增强/生成都真实发生，RAG 能力看得见摸得着；需要控制 prompt 让它按要点答否则会跑偏。
- 候选方案C：纯检索生成（不预写）
  - 方案C优劣（致命短板）：最"纯 RAG"；但答案不可控，面试现场最容易翻车。
- 最终拍板：答案要点 + LLM 生成（索引层存"问题+答案要点+引用"，检索仍走向量，命中后要点+引用传给模型生成）
- 拍板理由：面试官能看见 RAG 在动，是"能力证明"；要点提前写仍可控，等于"提纲你定，措辞 AI 来"；若只做查表，检索和打分就全是假的（D6 否决"预写完整答案直发→RAG 沦为查表"）。
- 落地对账：白盒链路 `stream_generate` 基于精排 Top-K 块 + 改写 query 调 doubao 流式现组织语言（`assistant.py:411-477, 634`）；`_GEN_SYSTEM` 硬性约束"只基于召回语料、末尾统一贴参考来源、正文不插标记"（`query.py:692-748`）；引导题=池内原题直出（不预写完整答案，见选型12 反转）。结论=落地。

### 选型5：引用判定选型
> 检索摘要：放弃 LLM 自述引用，采用 is_quoted LCS 确定性硬匹配（连续 8 个中文字符或 12 个英文字符命中即标记引用），rerank 块先发灰显、done 后补发 quoted_keys 高亮；全部未命中时标注"引用未能精确匹配"不假装。

- 选型场景：怎么判定召回块是否被最终答案引用，维护白盒引用严谨性
- 候选方案A：is_quoted LCS 确定性硬匹配
  - 方案A优劣：生成完成后遍历候选块 content_preview 在答案字符串中做最长公共子串匹配，任意连续 8 个中文字符或 12 个英文字符命中即 is_quoted=True；确定性、不依赖 LLM 主观自述、后端实现零额外 LLM 输出。
- 候选方案B：LLM 自述引用
  - 方案B优劣（致命短板）：让模型自己说引用了哪个块；不可靠，自述与真实依据可能不一致，白盒露怯。
- 候选方案C：无引用
  - 方案C优劣（致命短板）：答案不带任何依据；quoted_keys 为空时答案照常显示但没有支撑，白盒反而露怯。
- 最终拍板：is_quoted LCS 硬匹配（8 中/12 英），rerank 块先发（灰显），done 后补发 quoted_keys（高亮）
- 拍板理由：8 中文字符匹配必须生成完才能算，所以 rerank 先发灰显、done 后补 quoted_keys 高亮，"先灰后亮"避免引用面板闪跳；quoted_keys 为空→答案标注"引用未能精确匹配"，不假装有引用（问题8 §5、问题11 #3/#10）。
- 落地对账：落地——`lcs_quote_match`（`assistant.py:193-238`）连续 ≥8 中/12 英字符命中即 is_quoted，纯函数可入评测；前端 `ReferencePanel.jsx` quotedKeys 命中块高亮+默认展开、其余灰显折叠；`QUOTE_LEN_CN/EN=8/12`（`assistant.py:189-190`）；全部未命中→答案标注"基于现有知识库，引用未能精确匹配"（guardrails spec）。结论=落地。

### 选型8：生成模型选型
> 检索摘要：生成链路落地 doubao 流式（复用 ark_stream + usage 真算），质量与答疑链路一致且 usage 改动只做一次；免费 glm-4-flash 是"边际成本趋近 0"的成本叙事备选，08-25 已放弃。

- 选型场景：生成模型用谁，直接决定成本故事与链路复用
- 候选方案A：免费 glm-4-flash
  - 方案A优劣：成本故事最强——"本地 bge embedding + 免费生成模型，这套 RAG 的边际成本趋近于 0"；但与答疑链路模型不一致，无法复用 ark_stream 的 usage 改造。08-25 已不采用。
- 候选方案B：doubao（答疑同款）
  - 方案B优劣：质量和答疑链路一致，可复用 ark_stream（usage 改动只做一次）；token 单价付费，费用换算数字没那么好看。
- 候选方案C：待定（未定模型）
  - 方案C优劣（致命短板）：无确定性，影响成本展示与链路复用，不采纳。
- 最终拍板：doubao 流式生成（复用 ark_stream + 强制引用 + usage 真算）；免费 glm-4-flash 作为成本叙事备选
- 拍板理由：D6 生成链路落地 doubao 流式+强制引用+按页标注，D7 token 真算按 doubao 单价换算（实测 ¥0.016/条）；复用 ark_stream 让 usage 改造只做一次（问题5 B）；面试成本叙事若要"边际成本趋近 0"，可切免费模型但需另起链路。
- 落地对账：落地——08-25 **意图/改写/判分/生成统一 doubao**（`doubao-seed-2-0-mini-260428`：意图/改写/判分 0 温度关思考 20s 超时、生成 0.2 温度 60s 超时，`settings.py:56,60`），**glm-4-flash 免费优先叙事已放弃**；成本叙事转为"本地 bge embedding 免费 + doubao 单价（¥0.003/0.009 千 token）+ top-K 控制上下文膨胀 + 0 token 兜底话术"（分析-01/04/06）。结论=落地。
