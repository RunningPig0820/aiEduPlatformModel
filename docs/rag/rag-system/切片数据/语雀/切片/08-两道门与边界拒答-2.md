| 属性 | 内容 |

### 场景38：问候识别（不触发 clarify）
> 检索摘要【已落地】：intent 将"你好/Hi/在吗"识别为 category="问候"、ambiguous=false，不触发 clarify；is_greeting 关键词预检短句 ≤8 字才命中防误杀，WELCOME_MSG 直返 done 0 token 不 recall 不 generate。

| 属性 | 内容 |
|---|---|
| 业务场景 | 学生发问候语（你好/Hi/在吗） |
| 触发条件 | 短句命中问候关键词（你好/您好/hello/hi/哈喽/嗨/hey/在吗，`0 < len ≤ 8` 才命中防误杀，assistant.py:361,366-372） |
| 当前处理 | `is_greeting` 预检 → category="问候"、ambiguous=false → 固定 WELCOME_MSG + 引导池入口建议，直返 done（assistant.py:580-586），0 生成 token、不 recall 不 generate |
| 兜底降级策略 | 长句含问候词（"你好，请介绍一下这个项目"）不命中，走正常链路；clarify 仅用于功能指代不明（ambiguous&candidates≥2） |
| 残余风险 | 短句问候被误判为真实问题（≤8 字边界需调优）；WELCOME_MSG 文案固定，模块名不随 current_project 变化 |

> 证据：详见 `1.语雀/语雀-边界场景清单.md`（§场景38）｜ spec-java-rag-project-intro-assistant-gateway（D-E）；3.代码/分析-05；[总揽§1.4/§6.2]

### 场景39：clarify 澄清轮（只澄清一次）
> 检索摘要【已落地】：intent ambiguous=true 且 candidates≥2 时触发 clarify（固定话术+candidates+default），不 recall/generate 0 token、不计答案轮次、写 history；点选候选=重发原问题+currentProject=点选 id 权威锚定；仍模糊不二次澄清直接按 default。

| 属性 | 内容 |
|---|---|
| 业务场景 | 问题指代不明、多模块候选时引导用户明确 |
| 触发条件 | intent `ambiguous=true` 且 candidates≥2；candidates 主源=LLM（2~4 个模块闭集），LLM 未给/给<2 → 会话最近 N 轮锚过模块去重兜底，仍 <2 → 不触发 |
| 当前处理 | 发 `clarify` 事件（固定话术+candidates+default），不 recall/generate、0 token、不计答案轮次、写 history；下一条重跑 intent；仍模糊不二次澄清直接按 default（default=current_project > 会话最后锚定）；点选候选=重发原问题+`currentProject=点选 id`，intent 以 currentProject 为权威消歧锚点 |
| 兜底降级策略 | 前端候选 chip 用 pageModuleMap id→label 映射，未知 id 显示原文兜底；点选模块与会话锚点不同 → switch 事件照常 |
| 残余风险 | 澄清只一次，学生答"就那个嘛"直接按 default 可能答非所问；candidates 生成质量依赖 LLM 稳定性 |
