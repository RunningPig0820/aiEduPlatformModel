> 检索摘要：两道门是什么？权限门/意图门/范围门分别在什么时候触发？范围门阈值 0.75/0.5 怎么判定、为什么用召回置信度而不是 RRF 相对分？边界话术是什么？禁区模块怎么拒答？唯一拒答路径为什么是 boundary(low_confidence)？

### 核心术语

| 术语 | 定义 |
|---|---|
| 权限门 / 范围门 | 两道门：权限门（前置校验"能不能看"）+ 范围门（后置检索置信度"有没有覆盖"） |
| 范围门 = 检索置信度 | 检索不到高置信度条目→说明没覆盖→边界回答；语料即边界，无需单独分类器 |
| 范围门判定口径 | 用召回置信度（向量 = 1-平均余弦距离、BM25 = `min(1.0, top_score/10)`）与 0.75/0.5 比，非 RRF 相对分（0.01~0.05 量级永远够不到阈值，2026-08-25 校正） |

### 权限门（前置，硬性拦截）

后端从**可信源**（Token/网关 Header）取角色，**严禁信任前端 Body 传参**；仅当角色明确为"学生"时放行，非学生/角色缺失→直接返回固定 403 拒绝语，不进入任何 RAG 流程、**不消耗任何 Token**。证据：语雀-原文件-问题8.md。08-21 时期为页面权限标签 + demo 学生=最高权限（前置校验机制保留），08-25 收严为可信源取角色。证据：design-python-project-intro-rag.md Non-Goals / 问题8.md。

⚠️【落地】**权限门在 Java 网关**（`RagAssistantController.requireStudent` → `TutoringAuth.isStudent(session)`），仅 STUDENT 放行、**body 传 role 一律忽略**、非学生/角色缺失固定 403（`ResponseStatusException(FORBIDDEN)`，不进入 RAG 流程、不产生 trace）；**Python 代码无权限门**。⚠️【定稿 D-B】`permission` 事件 = `{role, allowed, traceId}`。证据：分析-01/04；design-java D1/D-B。

### 意图门（硬路由 + 问候识别）

- 凡问题涉及"系统架构 / 代码实现 / 部署流程 / 评测方案 / 接口设计"→ 强制路由至 **RAG项目** 知识库。
- 凡明确指向 **AI答疑 / 知识图谱 / 题型分析** 三个禁区模块 → 直接返回固定话术 **"该问题涉及其他业务模块，我尚未掌握"**，**严禁调用 LLM 生成拒答语**（节省成本，0 token）。⚠️【落地反转】08-25 定稿改走"**模块全放行 + 范围门低置信过滤**"（D4/D9，用户确认"AI答疑、知识图谱、题型分析和 RAG 模块都放行，查不到关联文档直接返回可信度低过滤"），**意图层无禁区硬拒答**，唯一拒答路径 = `boundary`(reason=low_confidence)；未来模块入库切片即自动可答（数据驱动，无代码改动）。证据：design-java D4/D9；guardrails spec。
- 语义分析层透传 3 项：原始问题 / 改写后问题 / 意图分类标签（如 `#rag_project` 或 `#reject`）。证据：语雀-原文件-问题8.md。
- ⚠️【定稿 D-E】**问候识别**：intent 将"你好/Hi/在吗"识别为 `category="问候"`、`ambiguous=false`，**不触发 clarify**；走**欢迎话术 + 引导池建议**（0 生成 token，不 recall 不 generate），指向 ①项目介绍②操作③数据关联④难点。代码实现 `is_greeting` 关键词预检（短句 ≤8 字才命中防误杀，assistant.py:361,366-372）+ `WELCOME_MSG` 直返 done（assistant.py:580-586）。证据：design-java D-E；分析-05。

### 范围门（后置，检索置信度即范围判断）

检索置信度低于阈值→说明语料未覆盖→边界回答，**不硬编**。语料本身就是范围，无需单独"是否覆盖"分类器。证据：语雀-原文件-问题4.md；design-python-project-intro-rag.md D4。

⚠️【落地】**0.75/0.5 只在白盒链路 `check_boundary` 生效**（`assistant.py:388-408, 616-625`：rerank 空 → 拒答；或 `vec_conf<0.75 且 bm_conf<0.5` 双路都低才拒，单路高即过；`vec_conf=max(全量置信, 切片置信)`），**1.6C `/query` 端点无阈值门**、只有"hits 为空"粗粒度拒答（`api/rag.py:120-126`，docstring 自称"置信度过低→拒答"与实际不符）。**阈值语义校正（2026-08-25）**：初版误用 rerank 的 RRF 融合分（量级 0.01~0.05）比对 0.75/0.5 → 所有命中都误判低置信拒答；改为**召回置信度**（向量 = 1-平均余弦距离 / BM25 = `min(1.0, top_score/10)`）。触发 → boundary 事件 + 固定话术"未找到关联文档，我尚未掌握。" + **短路不调 generate（0 token，防无谓成本）**。证据：分析-04/07；guardrails spec 阈值语义校正。

### 双门协作（"没有找到知识文档"两者都要）

| 门 | 触发时机 | 代价 | 事件 |
|---|---|---|---|
| 权限门 | Java 网关入口（最前置） | 非 STUDENT → 固定 403，0 token、不产生 trace | HTTP 403（非 SSE 事件）；STUDENT → `permission` 事件 |
| 意图门 | turn 开头 intent 后立即判 | 不 recall、不 generate、0 token | 08-21 为 `reject`(module_not_covered)；⚠️ **08-25 改全放行，无 reject**（四模块均可路由） |
| 范围门 | recall 之后，检索置信度低于阈值 | 付了 recall、省 generate | `boundary` + reason=**low_confidence**（唯一拒答路径） |

⚠️【落地】08-25 定稿后**唯一拒答路径 = 范围门 `boundary`(low_confidence)**（D4/D9，模块全放行由语料驱动）；权限门在 Java 网关（HTTP 403 而非 SSE reject 事件）；两道门共享固定拒答话术（不调 LLM），前端据此展示"拒绝发生在哪一层"。证据：语雀-原文件-问题9.md；design-java D4/D9；guardrails spec。

### 范围门阈值（方案口径）

范围门阈值：索引层命中 > 0.75、源文档池 > 0.5，低于→边界回答。两阈值分工：索引层要精、源文档池要宽。证据：design-python-project-intro-rag.md D4/D5；rag-system.md。

### 相关风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 范围门误拒 | 语料未覆盖的好问题被边界拒绝 | 双池 + 全局模式；引导问题把高频问题收纳进索引层 |
| 范围门误拒（rag-system 语料空） | `DEFAULT_MODULE="rag-system"` 指向无数据模块，anchor=rag-system 当前必然边界拒答（MODULE_DATA 无 rag-system jsonl） | 语料入库切片后自动可答（数据驱动）；过渡期引导/提问注意错位 |
| 1.6C docstring 高于实际 | `api/rag.py` docstring 自称"置信度过低→拒答"，实际只判 `if not hits` 空命中、无阈值门 | 面试表述以"范围门仅白盒链路"为准 |

### 生成中切换（两道门边界）

**下一轮切换**符合业务（intent 每轮本来就跑，switch 前零生成 token）；**生成中切换**不支持（中止上游 doubao HTTP 流不可靠、半截 token 已计费不退款）。生成中只做一件事：`is_disconnected()` → 中止，防空转烧钱。`switch` 事件不掐断在途流，只作用于下一 turn 上下文。证据：语雀-原文件-问题9.md。

### 选型7：范围判定选型
> 检索摘要：范围门=检索置信度即范围判断（索引层阈值 0.75 / 源文档池 0.5），语料即边界，不单独做"是否覆盖"分类器；08-25 意图门改四模块全放行、唯一拒答路径=范围门 boundary(low_confidence)；阈值语义校正为召回置信度。

- 选型场景：怎么判断问题是否在语料覆盖范围内，避免没检索到还硬编答案
- 候选方案A：单独"是否覆盖"分类器
  - 方案A优劣（致命短板）：意图分类正规；但多一个易错组件，与范围门职责重叠，弃。
- 候选方案B：检索置信度即范围（范围门 0.75/0.5）
  - 方案B优劣：检索不到高置信条目→说明没覆盖→边界回答；纯 RAG 机制，"我的语料就是边界"逻辑自洽且可讲。
- 候选方案C：意图门硬路由（08-25 补充）
  - 方案C优劣：意图层硬路由——架构/代码/部署/评测/接口→强制路由 RAG 项目；AI答疑/知识图谱/题型分析→固定拒答；零检索零生成 0 token。⚠️ 08-25 定稿改走"模块全放行 + 范围门低置信过滤"（D4/D9），意图层无禁区硬拒答。
- 最终拍板：范围门=检索置信度（0.75/0.5）✅ + 意图门硬路由（08-25）双门互补，共用固定拒答话术，事件 reject vs boundary 可区分
- 拍板理由：范围门用检索置信度，语料即边界，无需单独分类器（D4 备选否决"单独覆盖分类器"）；意图门拦截明确指向禁区/无语料模块的问题，零成本（问题8 §3）；两道门职责不同——意图门前置拦截最便宜，范围门后置兜底语料未覆盖边角（问题9）。
- 落地对账：⚠️ 部分落地——`BOUNDARY_VEC_CONF=0.75 / BOUNDARY_BM_CONF=0.5`（`assistant.py:388-389`），`check_boundary` **只白盒链路生效**（`assistant.py:394-408, 616-625`：rerank 空→拒答；或 `vec_conf<0.75 且 bm_conf<0.5` 双路都低才拒，单路高即过；`vec_conf=max(全量置信,切片置信)`），触发→boundary 事件 + 固定话术 + **短路不调 generate**（0 token）；**1.6C `/query` 端点无阈值门**，只有 `if not hits` 空命中拒答（`api/rag.py:120-126`，docstring 自称"置信度过低→拒答"与实际不符）；⚠️ 阈值语义 2026-08-25 校正：初版误用 RRF 融合分（0.01~0.05）比对阈值→全部误拒，改为召回置信度（向量=1-平均余弦距离、BM25=`min(1.0,top_score/10)`）；⚠️ 08-25 意图门**无禁区硬拒答**（四模块全放行，唯一拒答路径=boundary low_confidence，D4/D9）。
