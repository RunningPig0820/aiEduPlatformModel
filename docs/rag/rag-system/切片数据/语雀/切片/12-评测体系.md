### 评测集

每条 = `{module, question, question_type, expected_references[], expected_points[]}`，每模块 ≥5 条（25 条基准，建议扩到 30~50 条）；`question_type` ∈ 项目介绍/操作/数据关联/难点/最危险/**边界拒答**（`VALID_TYPES` 闭集含 08-25 新增边界拒答类型，断言=触发固定话术且 0 token）。预期引用/要点是 hit@k 与答案质量的 ground truth。证据：design-python-rag-eval-agent.md D2；design-java D10；语雀-原文件-问题12.md。

⚠️【落地】`HIT_K=5`（2026-08-26 由 3 改 5，对齐生成 top-5，方案 hit@3 演进）；判分 LLM 只报事实 `{covered_count, fabricated, rationale}`、分数由 `_score_from_covered` 规则硬算（覆盖比例分档 5→0，**编造 ≥1 处封顶 3 分**，`eval_agent.py:164-183`）；**评测集仅 `ai-tutoring.jsonl` 6 条**（5 正常 + 1 边界拒答"帮我写一封辞职信"），`eval_dataset.py:76` 硬编码 `module=="ai-tutoring"`——**无 rag-system 评测集**，多模块评测需先改此处。评测走真实检索原语不降级（向量挂了就暴露）。证据：分析-06。

### 评测体系补强（分层评估框架）

分层评估框架：L1 知识库层（覆盖率/重复率/过期版本占比）、L2 检索层（Context Recall / Context Precision）、L3 生成层（Faithfulness / Answer Relevancy）、L4 端到端层（Answer Correctness / Latency / Cost）。行动清单：🔴 必须扩充评估集（30~50 条，覆盖项目介绍/操作流程/数据关联/难点技术/边界拒答 5 类）；🔴 必须跑一轮完整 baseline；🟡 补分层指标 + 回归测试；🟢 加分引入 RAGAS（行业标准对比分数）。现状基准（来自评测工具）：`hit@3 = 0.80`、`质量分 = 3.6~4.6/5`、`单条耗时 ≈ 5.6s`、`单条成本 ≈ ¥0.016`、语料 234 块。证据：语雀-原文件-问题12.md。

⚠️【落地】指标已演进：`HIT_K=5`、双向量 + 判分硬算后最新报告（`data/eval/reports/2026-08-26-259c06.json`）为 `hit@5=0.583 / quality=3.833 / avg_latency≈17.4s / avg_cost≈¥0.0181`、评测集 6 条（ai-tutoring）；`hit_cases 5/6` 与 `hit_at_k_avg 0.583` 是两套口径（任一引用命中 vs 引用命中比例）。证据：分析-06。

### 选型14：评测框架选型
> 检索摘要：评测聚焦 hit@k + LLM 判分（answer_quality）两个核心信号，分层先测检索后测答案；明确不做 RAGAS 全量框架；代码落地 HIT_K=5（2026-08-26 由 3 改 5）、判分 LLM 只报事实分数硬算、编造 ≥1 处封顶 3 分。

- 选型场景：怎么证明 RAG 系统靠谱——可量化、可复现、可追溯
- 候选方案A：RAGAS 全量框架
  - 方案A优劣（致命短板）：行业标准、可对比分数；但框架重，与"聚焦核心信号"目标不符，明确不做全量引入。
- 候选方案B：hit@k + LLM 判分（评测 agent）
  - 方案B优劣：先测"检索是否捞得对"（hit@k），再测"答案是否答得好"（answer_quality LLM 判分），分层定位问题；判分确定性硬化（模型只报 covered_count/fabricated，分数硬算可复现）。
- 最终拍板：评测 agent——hit@3 + answer_quality + cost/latency（离线工具，服务面试质量把关）
- 拍板理由：不做 RAGAS 全量框架，聚焦 hit@k + LLM 判分两个核心信号（eval agent Non-Goals）；分层评估先测检索后测答案，问题可定位到具体一条评测（问题12、eval D3/D4）；评估集每模块 ≥5 条、覆盖 5 类场景，扩充到 30~50 条（问题12）。实测 baseline：hit@3=0.80、质量分 3.6~4.6/5、单条成本 ¥0.016、耗时 5.7s（完善文档08）。
- 落地对账：⚠️ 指标演进——`HIT_K=5`（`eval_agent.py:31` 注释"2026-08-26: 3→5"，对齐生成 top-5，方案 hit@3 演进）；判分 LLM 只报 `{covered_count, fabricated, rationale}`（`_JUDGE_SYSTEM`），分数由 `_score_from_covered` **规则硬算**（覆盖比例分档 5→0，**编造 ≥1 处封顶 3 分**，`eval_agent.py:164-183`）；评测走真实检索原语**不降级**（向量挂了就暴露，`eval_agent.py:13-14`）；⚠️ 评测集**仅 ai-tutoring 6 条**（5 正常 + 1 边界拒答"帮我写一封辞职信"），`eval_dataset.py:76` 硬编码 `module=="ai-tutoring"`——无 rag-system 评测集；最新报告（2026-08-26-259c06）`hit@5=0.583 / quality=3.833 / avg_latency≈17.4s / avg_cost≈¥0.0181`。结论=落地 + 指标演进。
