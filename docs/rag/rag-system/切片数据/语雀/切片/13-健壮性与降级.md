### 降级矩阵

逐级降级，最差也是"把原文给面试官看"：

| 故障环节 | 降级到 | 最差兜底 |
|---|---|---|
| embedding API 挂/超时 | 关键词/规则（jieba）| 提示换说法 |
| 向量桶/COS 挂 | 本地索引 | 该页文档大纲 |
| 全挂 | 页面文档大纲（"这一页讲什么"结构）| 边界话术 |
| LLM 生成挂/超时 | 展示召回原文（"我找到了以下相关资料…点击查看原文"）| 预写答案卡片 |

超时：召回 2s（单路超时自动降级为纯另一路）/ 生成 8s。断连：`is_disconnected()` 检测前端断开→立即中止底层 LLM 流式请求，防后端空转烧钱。证据：语雀-原文件-问题1.md / 问题8.md。

【落地】代码降级路径为"向量挂→纯 BM25 / doubao 挂→召回块清单当答案 / 无命中→拒答 / 全挂→边界话术"（1.6C 与白盒各自落地，**"返回页面大纲"一级未见**）；`DEGRADED_VECTOR/BM25` 标记定义了但未透传进 SSE 事件。证据：分析-01/07。

### 其他横切：会话累计 token + close 结算

显式关闭对话 + 会话累计 token（【定稿 D12】`POST /sessions/{sessionId}/close`：中止在途流 + 置 closed + 返回累计 token/轮数；断连未 close 时累计保留 Redis 续接）、Java 侧真实对话 LLM 质量打分旁路（done 后异步判分累计进评估报告，不阻塞 SSE）。证据：design-java D12；`RagAssistantAppService.close/scheduleGradeOnDone`。

### 重试语义分层（建议 #4）

intent/rewrite 0 重试（非幂等，失败走规则兜底）；recall(COS) 短超时重试 1~2 次（幂等）；generate 0 重试，超时→召回清单话术。速率限制/429（建议 #5）：服务端轻量限流（每学生每秒 N 次）+ 429 降级到召回清单话术。

### 上下文窗口管理（建议 #6 / 已定）

已定 08-25：**不设轮数上限**、history 截断保留最近 3 轮（`HISTORY_LIMIT=3`，Java 组装 Python 截断）；建议仍是兜底"每会话 token 预算上限"（见建议 #13）。

### D26 分层超时：召回 2s / 生成 8s
> 检索摘要：分层超时：召回层向量/BM25 单路各 2s 硬超时降级为纯另一路，生成层 8s 硬超时→不走 LLM 直接返回召回清单+固定话术，任何阶段超时不无限阻塞。

| 属性 | 内容 |
|---|---|
| 背景 | 统一超时学生等待过久；生成超时也调 LLM 重试会重复花钱 |
| 演进 | 08-21 检索 <2s / 生成 <15s → 08-25 召回 2s（单路超时自动降级纯另一路）/ 生成 8s（超时→"我找到了以下相关资料，但生成完整答案超时了，您可以直接点击查看原文：块1、块2、块3"） |
| 拍板理由 | 分层超时是工程底线（spec 第 7 条）；超时降级话术写死成本 0，用户拿到原始资料体验正向（非报错） |
| 系统影响 | 【落地】RAG_RECALL_TIMEOUT=2.0（asyncio.wait_for + run_in_threadpool 包裹向量路）；生成 8s 由 httpx timeout 控制 + 外层捕获写死降级话术 |
| 证据 | 语雀-原文件-问题1/8；design-java D7；spec-python-rag-project-intro-assistant-resilience；[总揽§3.4] |

### D27 is_disconnected 断连取消 + trace_id 断线补查
> 检索摘要：SSE 生成循环监听 request.is_disconnected()，前端断开立即中止上游 doubao 流防空转烧钱；trace_id 由 Java 入口生成随 permission 事件下发（流开始即可取），每轮 done 快照存 Java Redis，GET turns/{traceId} 断线补查。

| 属性 | 内容 |
|---|---|
| 背景 | 前端断开不中止流=后端空转烧钱；断线后结果需可补查 |
| 演进 | 08-21"保留已吐内容" → 08-25 is_disconnected() 主动取消 LLM 流 + trace_id 断线补查 |
| 拍板理由 | 断连立即中止流防空转；spec 要求 trace_id"供断线后补查"，不依赖 done（permission 事件携带） |
| 系统影响 | 【落地】白盒路径已闭环：Java Redis 每轮 done 快照（rag:assistant:trace:{traceId} TTL 24h）+ GET /api/rag/assistant/turns/{traceId} 补查（超窗 10002）；1.6C 路径无 trace；Python 不落会话 trace |
| 证据 | 语雀-原文件-问题8/9；design-java D8/D-B；spec-java resilience；[总揽§8/§9.2] |

### D29 重试语义分层：intent/rewrite 0 重试、recall 幂等短重试、generate 0 重试
> 检索摘要：重试语义分层：intent/rewrite 非幂等 0 重试（失败走规则兜底）；recall(COS) 幂等短超时指数退避重试最多 2 次；generate/embedding 计费 0 重试，超时→召回清单话术。

| 属性 | 内容 |
|---|---|
| 背景 | 自动重试会重复计费（生成/embedding 是计费调用）；COS 查询便宜幂等可自愈 |
| 演进 | 08-21 design D10 只列"短超时重试 1~2 次" → 08-25 明确分层：仅 COS 查询重试（指数退避最多 2 次），LLM 生成与 embedding 均不重试 |
| 拍板理由 | 生成/embedding 计费调用自动重试重复计费；COS 查询便宜幂等短超时重试可自愈 |
| 系统影响 | 【建议为主】重试分层细则属建议项，白盒落地以各阶段降级话术写死（0 token）为准 |
| 证据 | 语雀-原文件-问题11；spec-python-project-intro-rag-rag-resilience；[总揽§9.1] |
