### 在线标准 RAG 流程（/api/rag/assistant/ask）

白盒化问答体验遵循 RAG 标准流程，中间状态实时透传前端。⚠️【落地】生产入口为白盒 SSE 端点 `POST /api/rag/assistant/ask`（`stream=true` 流式 / `stream=false` 非流式 done+stages）；旧 1.6C 同步端点 `POST /api/tutoring/rag/query` 仍保留（`{answer, references, intent, version}`）。证据：语雀-原文件-问题8.md；分析-01/04。

```
permission(Java, 含traceId) → intent(模块锚点+类别+问候/clarify/switch 判定)

```

### 会话与 token 数据结构

- `tokens_usage`：`prompt_tokens / completion_tokens / cache_hit_tokens / total_tokens`，随每轮返回。
- `trace_id`：供前端断线后补查。⚠️【定稿 D-B】由 Java 网关入口生成并随 `permission` 事件下发，**流开始即可取**，断线补查不依赖 done；每轮 done 快照存 Java Redis（`rag:assistant:trace:{traceId}`，TTL 24h），`GET /api/rag/assistant/turns/{traceId}` 读回（超窗 → 10002）。证据：语雀-原文件-问题8.md；design-java D-B/D8；`RagAssistantAppService.persistRound`。
- `sessionId`：⚠️【定稿 D-C】前端面板挂载生成 UUID 整场复用；Java 以 sessionId 为键累计会话 token + 轮数（`rag:assistant:session:{sessionId}:usage`，close 结算返回；断连未 close 时累计保留 Redis 续接）。Python 无状态不落会话。
- 会话：页面锚定 + 追问上限 5 轮/会话（08-21）；⚠️【定稿 08-25】**不设轮数上限**（用户确认轮数无意义），改为上下文窗口保留**最近 3 轮** history（`HISTORY_LIMIT=3`，history 由前端传、Java 透传 Python 只消费+截断；刷新后为空=新会话）。证据：design-java Open Questions；分析-01。

### 选型11：演示部署选型
> 检索摘要：索引抽象层双轨部署——demo 默认本地 FAISS 兜底、生产走 COS 向量桶，COS 预建索引避开 10s 异步生效，面试现场零网络风险；代码落地为 rag-full/rag-slice 双 COS 索引 + demo 本地兜底。

- 选型场景：demo 演示跑本地还是 COS，兼顾生产叙事与现场可靠性
- 候选方案A：本地 FAISS
  - 方案A优劣：面试现场零网络依赖绝不出错；但不是生产链路叙事。
- 候选方案B：COS 向量桶
  - 方案B优劣（致命短板）：生产链路好讲；但有 10s 异步生效 + 网络风险，当着面试官的面断网就完了。
- 候选方案C：索引抽象层双轨（demo 本地 + 生产 COS，COS 预建索引）
  - 方案C优劣：同一接口抽象，demo 默认本地 FAISS、UI 标注"生产环境走 COS"；COS 用预建索引避开 10s 异步写后不可即查。
- 最终拍板：索引抽象层双轨——demo 本地 FAISS 兜底 + 生产 COS 向量桶（预建索引）
- 拍板理由：demo 可靠性优先，本地兜底本身就是重试降级的最好故事且能真演示（问题1 ④）；COS 保留生产链路叙事，预建索引避开 10s 异步（D11、完善文档05）。
- 落地对账：✅ 落地——代码落地为 `rag-full`（整篇）+ `rag-slice`（切片）双 COS 向量索引（`settings.py:99-105`，COS 桶 `rag-1318177119`）+ demo 本地 FAISS 兜底（索引抽象层同接口）；COS 写后 10s 异步生效→demo 前预建索引（D11）。结论=落地。
