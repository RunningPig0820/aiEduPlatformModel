### 选型18：sessionId 归属选型
> 检索摘要：sessionId 由前端面板挂载生成 UUID 整场复用（llmApi.generateSessionId()），Java 以 sessionId 为键累计 token 与轮数，ask 未知 session 按新会话、close 未知 → 10002；否决后端生成（创建时序纠缠、跨端难对齐）。

- 选型场景：sessionId 谁生成（会话累计 token 的键归属）
- 候选方案A：后端生成
  - 方案A优劣（致命短板）：会话键与创建时序纠缠，前端断线重连难对齐；与"Python 无状态、Java 聚合"边界难协调，跨端难保一致。
- 候选方案B：前端生成 UUID 整场复用
  - 方案B优劣：前端面板挂载即生成 UUID 整场复用；Java 以 sessionId 为键累计会话 token + 轮数（Redis `rag:assistant:session:{sessionId}:usage`，close 结算返回）；ask 未知 session 按新会话（累计从 0），close 未知 → 10002。
- 最终拍板：前端生成（D-C）
- 拍板理由：design-java D-C；前端 `RagAssistantPanel.jsx` `useState(() => llmApi.generateSessionId())`；累计 token 放 Java（每轮 done 经过它，天然聚合点），Python 保持无状态。
- 落地对账：落地——前端挂载生成 UUID 整场复用（design-java D-C）；Java `RagAssistantAppService` 以 sessionId 为键累计 token/轮数 + close 结算；Python 无状态不落会话（`api/rag_assistant.py:9-12`）。结论=落地。

### 选型19：查看原文代理选型
> 检索摘要：查看原文走 Java 代理 GET /api/rag/assistant/source?path= 转发 Python /api/rag/source/{file_path}，前端不直连 Python；file_path 走 query 传参（不走 path 避免容器拒）；否决前端直连（绕过 Java 角色门）。

- 选型场景：前端点"查看原文"直连 Python 还是经 Java 代理
- 候选方案A：前端直连 Python /api/rag/source
  - 方案A优劣（致命短板）：绕过 Java 角色门、暴露 Python 内网地址，权限与网络边界双破坏；前端拿不到"仅学生可看原文"的强制。
- 候选方案B：Java 代理（STUDENT 角色门 + 转发）
  - 方案B优劣：新增 `GET /api/rag/assistant/source?path=<urlencoded>`（STUDENT 角色门）转发 Python `/api/rag/source/{file_path}`；Python 保留挂载作转发目标，前端不直连；file_path 走 query 传参（不走 path，避免特殊字符被容器拒）。
- 最终拍板：Java 代理（D-D）
- 拍板理由：复用角色门，前端不直连 Python（design-java D-D）；file_path 走 query 传参规避容器 URL 特殊字符拒绝；Python 保留挂载作转发目标，契约零破坏。
- 落地对账：落地——`RagAssistantController.source` 转发 + 前端 `ReferencePanel.jsx` 用 query 传参（design-java D-D）；Python `GET /api/rag/source/{file_path}` 前缀白名单 `rag-source/`、`rag-slices/`（`api/rag.py:65-66`），读 COS 失败 → 404。结论=落地。
