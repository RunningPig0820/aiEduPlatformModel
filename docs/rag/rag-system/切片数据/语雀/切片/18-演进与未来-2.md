### 阶段5：健壮性与评测深化（问题9/11/12）
> 检索摘要：深化拒答双门事件契约（reject/boundary）、确立"下一轮切换"模型；补齐 LLM 健壮性 8 项（提示注入/结构化兜底/无引用不输出/重试分层/429/上下文窗口/模型分层）、白盒可观测 4 项（阶段失败透传/is_quoted 时序/trace_id 补查/断线恢复）、成本安全 4 项（会话 token 预算/current_project 信任/渲染安全/契约容错）；评测分层框架 L1~L4 + RAGAS 参考。落地状态（代码对账）：评测 HIT_K 3→5、判分改 LLM 只报事实+规则硬算编造封顶 3 分、边界拒答评测类型新增；白盒可观测 #10 is_quoted 时序/#11 trace_id 补查 API 已落地（Java Redis 快照 TTL 24h + `GET /api/rag/assistant/turns/{traceId}` 超窗 10002）、#9 阶段失败透传与 #12 整场断线恢复未落地；拒答路径收敛为范围门 `boundary(low_confidence)` 唯一路径。

- 阶段时间：未注明（问题9/11/12 讨论，晚于 08-25 spec）
- 核心形态：拒答双门事件契约、下一轮切换模型、LLM 健壮性 8 项、白盒可观测 4 项、成本安全 4 项、评测分层框架、RAGAS 参考
- 迭代翻转（相对阶段4）：
  1. **拒答双门语义化**：两道门都产同一固定拒答话术（不调 LLM），但事件区分——意图门拒答发 `reject`（reason=module_not_covered，零检索零生成）；范围门拒答发 `boundary`（reason=no_relevant_doc，付 recall 省 generate）；SSE 事件契约定型：intent→rewrite→switch(条件)→rerank→token→reject/boundary→done(answer+quoted_keys+tokens_usage+trace_id+suggestions)。⚠️【落地反转】08-25 定稿 D4/D9 后 **reject 事件未实现**——四模块全放行、无意图门硬拒答，**唯一拒答路径 = 范围门 `boundary`(reason=low_confidence)**（付 recall 省 generate、0 token 短路不调 generate）
  2. **切换模型定型**：选**下一轮切换**（intent 每轮跑，多一次"当前锚点 vs 已锚定"对比，switch 前零生成 token）；生成中切换需中止上游 doubao 流/半截答案作废/半截 token 已计费且上游取消不可靠，不建议做；生成中只做 `is_disconnected()` → 中止
  3. **LLM 健壮性 8 项补齐**（spec 最薄层）：提示注入/越权（复用 tutoring safety_flag：本地关键词+intent 兜底，命中→固定安全话术 0 token）、intent 结构化输出兜底（复用 200+degraded=true，LLM 失败→回退规则 `_fallback_anchor`）、"无引用不输出"执行细节（quoted_keys 为空→标注"引用未能精确匹配"或重召回一档，不假装有引用）、重试语义分层（intent/rewrite 0 重试走规则兜底；recall COS 短超时重试 1~2 次幂等；generate 0 重试超时→召回清单话术）、速率限制 429（服务端每学生每秒 N 次+429 降级召回清单）、上下文窗口管理（每会话轮次上限+history 截断保留最近 N 轮+首轮锚点）、cache_hit_tokens 拿不到→tokenizer 估算并标注"估算"、模型分层（intent/rewrite 快模型，generate 强模型）
  4. **白盒可观测 4 项补齐**：每阶段失败/超时也要透传（`stage_failed`+stage+reason，否则降级对面试官不可见=没降级）、is_quoted 时序（8 中文字符匹配须生成完才能算→rerank 块先发灰显、done 后补 quoted_keys 高亮，"先灰后亮"）、缺 `GET /api/rag/turns/{trace_id}` 断线补查接口、断线恢复需会话持久化（Redis/MySQL）+恢复接口（否则 trace_id 补查是死口）
  5. **成本与安全 4 项**：每会话累计 token 预算上限（如 50k，到顶提示开新会话）、current_project 信任边界（服务端校验 ∈ 有语料模块列表，防恶意传参空转）、语料渲染安全（markdown/mermaid/HTML 防注入，mermaid 白名单校验）、Java↔Python 契约容错（FAIL_ON_UNKNOWN_PROPERTIES=false、snake↔camel、degraded 走 200 不走 503）
  6. **评测体系深化**：分层评估 L1 知识库（覆盖率/重复率/过期版本）/ L2 检索（Context Recall/Precision，hit@3=0.80）/ L3 生成（Faithfulness/Answer Relevancy，质量分 3.6~4.6/5）/ L4 端到端（Answer Correctness/Latency&Cost，单条 ≈5.6s/≈¥0.016）；评估数据集三要素（问题+标准答案+证据文档 ID），建议 RAG 项目介绍助手单独建 30~50 条评测集覆盖 5 类（项目介绍/操作流程/数据关联/难点技术/边界拒答）；RAGAS 四指标参考（Faithfulness 两阶段 LLM 调用可复用 judge_quality）
- 落地状态（代码对账，相对阶段4 建议项）：
  1. **评测代码演进**：HIT_K 由 3 改 **5**（2026-08-26，对齐生成上下文 top-5，`eval_agent.py` 注释）；判分重构为"LLM 只报事实 `{covered_count, fabricated, rationale}` + `_score_from_covered` 规则硬算"（覆盖比例分档 100%→5、…、0%→0，**编造 ≥1 处封顶 3 分**，`eval_agent.py` 硬算函数）；评测集仅 `ai-tutoring.jsonl` 6 条（5 正常 + 1 边界拒答"帮我写一封辞职信"），`eval_dataset.py` 硬编码 `module=="ai-tutoring"`——**无 rag-system 评测集**；评测走真实检索原语不降级（向量挂了就暴露）。⚠️【已落地】
