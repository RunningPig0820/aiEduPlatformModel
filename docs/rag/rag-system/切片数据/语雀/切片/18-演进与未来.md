### 阶段1：骨架确立（问题1/2）
> 检索摘要：确立系统骨架：语料策展（每页权威版本、问题记录/草稿不收录）、9 类面试官问题矩阵、页面锚定（页面/全局模式）、"反向整理"新造面试 Q&A 索引层形成两层语料设计。

- 阶段时间：未注明（问题1/2 讨论阶段，早于 2026-08-21 纪要定稿）
- 核心形态：语料策展、9 类问题矩阵（RAG 功能清单）、页面锚定（页面模式/全局模式）、面试 Q&A 索引层（两层语料）
- 迭代翻转（相对阶段0）：
  1. 从"识别坑与横切考虑"推进为**完整系统骨架**：语料策展策略、问题分类矩阵、页面锚定模式、反向整理机制
  2. 确立**两层语料设计**：现有文档（按设计结构组织）答不了"为什么/难点/指标"→ 反向整理散落在代码/git/语雀/排查记录里的答案 → 新造"面试 Q&A 索引层"（每页 5~8 条高频问题条目 = 问题+答案要点+引用原始文档段落），RAG 检索索引层命中即答，原始文档作证据层提供溯源
- 阶段详述：四个骨架件全部成形。**语料策展**：同模块多版本矛盾是最大坑，对策=每页精选一套权威文档（每模块=1 产品规划+1 设计方案），问题记录、草稿、内部讨论明确不收录，语料要"策展"而非"全量倾倒"。**9 类问题矩阵**：概览/设计意图/数据流转/技术实现/难点踩坑/对比权衡/指标规模/权限范围/边界规划，每一类对应 RAG 检索什么、展示成什么（卡片/表格/流程图/数字），流程图（数据流转类）为差异化亮点。**页面锚定**：前端主动传 page → 页面模式（锁页，检索只在该页文档内，天然可解释）/ 全局模式（跨页检索）。**反向整理**：每个模块列出面试官高频致命问题（如"为什么拆 decide/generate"答在代码注释、"掌握度为什么挂题型"答在 mastery_snapshot 变更记录），"两层语料"是整件事的灵魂——答案可控、可预演，RAG 只是现场组织语言。
- 关联决策：D1（文档准备=自己完善文档再切片）、D2（双池：索引层池落定"两层语料"）、D3（页面锚定+引导问题变体文案，design-python-project-intro-rag）
- 落地证据：语雀-原文件-问题1、问题2

### 阶段2：关键决定落定（问题3/4/5）
> 检索摘要：落定全部关键决定：问题索引层=话术库（RAG=引擎，非纯 RAG）、权限=展示属性（demo 学生最高权限）、引导问题=索引层入口、答案 B 路线（要点+生成）、token 真算（丢 usage 坑）、双池检索、两道门（范围门=检索置信度）、跨页按页引用+召回原文面板、引导 chips 变体文案。

- 阶段时间：未注明（问题3/4/5 讨论阶段，早于 2026-08-21 纪要定稿）
- 核心形态：话术库定位、答案 B 路线、token 真算、双池检索、两道门、跨页按页引用、引导问题变体文案、召回原文面板
- 迭代翻转（相对阶段1）：
  1. **定位收口**：问题索引层 = 话术库，RAG = 引擎——不是纯 RAG 项目，是"用 RAG 引擎驱动项目介绍系统"；权限简化为**展示属性**（每页面挂权限标签，前端渲染，不做真角色体系）
  2. **引导问题变体**：UI 引导问题 = 索引层规范问题的变体写法（"你们为什么拆成三段" vs "为什么拆 decide/generate"），强制检索真实发生，避免"点按钮=预定答案"；每页需提前配对两套文案
  3. **答案形态落定 B 路线**：索引层存"答案要点 + 强制引用原文段落"，LLM 实时组织语言（A 全预写=查表露怯、C 纯检索=不可控翻车，弃）
  4. **token 真算**：发现现有代码丢 usage（ark_stream 不加 `stream_options: {"include_usage": true}`、`_parse_sse_lines` 丢弃 usage）→ 请求体加 include_usage + 流结束抓结尾 usage chunk；embedding 侧抓 `resp.usage.total_tokens`
  5. **双池检索确立**：索引层池（20~30 条 QA，引导问题可控）+ 源文档池（自由问题纯 RAG 真发挥）——"源文档池=真的检索"正是证明 RAG 能力的证据
  6. **两道门确立**：权限门（检索前过滤，限定搜索空间）+ 范围门（检索后判定，=检索置信度，语料即边界）；范围门阈值 0.75/0.5 于 08-24 design D4/D5 定稿
  7. **跨页按页引用 + 召回原文面板**：答案按页面分别引用（每句标来源页）；切片时每个 chunk 把源文档全文存进 metadata，答案生成后前端渲染"召回文档"面板，检索从黑盒变"能指给你看"
- 阶段详述：本轮把骨架件全部钉成可执行决定。引导问题=索引层入口（每条 QA 条目 = UI"你可能想问"按钮，安全路径直接取预置条目）；Token 展示做成完整成本叙事（每轮 prompt/completion 明细+会话累计+¥ 换算，本地 bge 免费 embedding / top-K 限制 / 降级便宜路径）；自由问题走两道门完整路径（自由输入→权限门过滤可检索页→向量检索→范围门置信度判定→命中取要点+引用合成/未命中边界回答→流式输出→结束更新 token 明细）；流程图预置为主（每页一张 mermaid，demo 可靠性优先）；演示走本地 FAISS 优先（零网络依赖）+ 索引抽象层（生产 COS 同接口）；边界话术预写 2~3 条固定"不在范围"回答。
- 关联决策：D2（双池）、D3（页面锚定+变体文案）、D4（两道门）、D6（生成强制引用+按页标注）、D7（token 真算）（design-python-project-intro-rag）
- 落地证据：语雀-原文件-问题3、问题4、问题5

### 阶段3：08-21 design 成文（设计基线落稿）
> 检索摘要：讨论纪要成文为两份 design：design-python-project-intro-rag D1~D11（完善文档 8 节/双池/页面锚定/两道门 0.75/0.5/打分/token 真算/降级矩阵/demo 兜底）+ design-python-rag-eval-agent D1~D7（知识库状态机/评测集/hit@k+answer_quality/trace+报告），确立"不是纯 RAG、每阶段可测试"的工程基线。

- 阶段时间：2026-08-24（design 文档落稿，设计依据为 2026-08-21 讨论纪要）
- 核心形态：完善文档 8 节（切片单元/源文档池/索引层 QA 来源三合一）、双池、页面锚定、两道门、打分公式、token 真算、降级矩阵、评测 agent
- 迭代翻转（相对阶段2）：
  1. **从问答讨论 → 正式 design 决策**：把 11 项关键设计固化为 D1~D11 决策记录，含明确 Goals/Non-Goals/Risks/迁移计划
  2. **Non-Goals 显式化**：不做教育领域内容检索、不接真实角色体系、不做图谱检索召回、不做真 mermaid 动态生成、不做生产级部署鉴权
  3. **文档准备落定 D1**：语雀空模板/多版本矛盾/未发布草稿不可直接用 → 每模块产出"完善文档 8 节"（产品定位/核心功能/为什么这么设计/数据流转(含预置 mermaid)/技术实现/关键坑与解法/数据规模与指标/权限与边界），完善文档同时是切片单元、源文档池、索引层 QA 的来源
  4. **打分与阈值 D5**：`score = similarity × 问题类型匹配 × 页面锚定加权`，索引层 top-K=1~3、源文档池 top-K=3~5，阈值 0.75/0.5——小语料不需要重排模型
  5. **降级矩阵 D10 成表**：query 理解/检索/打分/生成/展示五环节逐级降级 + 重试策略（检索短超时重试 1~2 次，生成流已起不重试），超时检索 <2s / 生成 <15s
  6. **评测体系成文 D1~D7**：知识库状态机（pending→organized→chunked→indexed→evaluated）、评测集每模块 5 条共 25 条、评测 agent 流程（先测 hit@k 再测质量分）、指标四元组（hit@k=3/answer_quality 0~5/cost/latency）、trace+报告可对比、每阶段可测试
- 阶段详述：阶段2 的讨论成果在此固化为可执行、可测试的工程基线。project-intro-rag design 覆盖"语料→切片→索引→检索→打分→生成→token→降级→demo"全链路，D11 明确 demo 可靠性（COS+预建索引避开 10s 异步写后不可即查+本地兜底）；rag-eval-agent design 把"怎么证明有效"落为可观测评测工具，纯离线、不触碰 `/api/rag/ask` 主链路。两份 design 共同定义了"**不是纯 RAG，产品=讲清每个页面，RAG=证明能力的引擎**"这一最终定位。注：本阶段为 08-21 设计基线，08-25 spec 在其上反转/收窄并追加定稿契约 D-A~D-E（见阶段4）。
