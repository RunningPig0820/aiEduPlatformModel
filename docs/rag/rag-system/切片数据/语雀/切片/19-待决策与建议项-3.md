> 检索摘要：当前有哪些技术债务？rag-system 语料未入 MODULE_DATA 为什么必然边界拒答？两道门为什么只落地白盒？token 成本为什么半透明？节级锚定怎么被旁路？`rag_query()` 为什么是死代码？

| 债务 | 说明 |
|---|---|
| rag-system 语料未入 MODULE_DATA | `build_index.py`/`query.py` 的 MODULE_DATA 仅 ai-tutoring + question-analysis；无 `rag_slices-rag-system.jsonl`/`rag_slices_full-rag-system.jsonl`；`DEFAULT_MODULE="rag-system"` **悬空**（未传 module 时 Filter 指向无数据模块→向量 0 命中→必然边界拒答）；rag-system 完善文档头无 `> COS路径:` 会被 upload_cos 跳过。证据：分析-03 |
| 索引层依赖完善文档 | 语料空模板/多版本矛盾→必须先完善文档才能切片；完善文档是主要成本（分模块推进） |
| 两道门只落地白盒 | 范围门 0.75/0.5 仅 `check_boundary`（白盒链路）；1.6C `/query` 端点无阈值门只有空命中拒答（docstring 高于实际）；权限门 Python 无（归 Java 网关）。证据：分析-04/07 |
| token 成本半透明 | 白盒流式/评测真采 usage；**1.6C `/query` 响应无 usage 字段**（`RAGQueryResponse` 四字段）；embedding token 未抓（`vector_store.embed()`）。证据：分析-04/07 |
| 节级锚定被白盒旁路 | 白盒 `recall` 写死 `locked_sections=[]`（assistant.py:118），节级 ×1.5 加权只在 1.6C 端点生效——同一问题两入口召回排序可能不同。证据：分析-01 |
| 引导池与语料池错位 | rag-system 引导题未入 `GUIDE_POOL`（兜底 ai-tutoring 池 + "RAG项目"入口模板）；guide 缺省=ai-tutoring vs ask 缺省=rag-system 不一致。证据：分析-05 |
| 评测集仅 1 模块 | `eval_dataset.py:76` 硬编码 `module=="ai-tutoring"`（6 条）；无 rag-system 评测集；多模块评测需先改代码。证据：分析-06 |
| `rag_query()` 死代码 | `query.py:789-814` 全仓库无调用且函数体引用未定义变量 `strategy`，**调用即 NameError**；现状由 1.6C 端点与 assistant.py 各自内联替代。证据：分析-04 |
| 评测集不足 | 现状需扩充到 30~50 条才够覆盖 5 类场景；预期引用需人工核对 |
| 断线恢复未闭环 | ⚠️ **白盒路径已闭环**（Java Redis trace 快照 + turns 补查 + close 结算，TTL 24h）；1.6C 路径无 trace；Python 侧无会话态（有意的无状态边界） |
| 生成中切换未支持 | 有意不做（复杂度高/业务价值低），但产品若坚持需重做 |
| 流式 usage 未修 | ⚠️ **白盒已修**（assistant.py:448 include_usage）；1.6C 端点与 embedding 仍未抓（见 token 成本半透明行） |
| 会话轮数未明确 | 08-25 已定不设上限、改最近 3 轮 history；"5 轮上限"仅 08-21 叙事 |
| 索引依赖 COS 10s 异步 | demo 需预建索引规避写后即查 miss |
| embedding 维度不可改 | 换模型 = 全量重建；需 checksum 校验发现过期 |

证据：design-python-project-intro-rag.md Risks/Migration；语雀-原文件-问题11.md；rag-system.md §5；分析-01~09。
