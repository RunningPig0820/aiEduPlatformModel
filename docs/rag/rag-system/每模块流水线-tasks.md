## 4. 切片（✅ 2026-08-28 完成，共 256 块）

> **切片方式（核心）**：不是脚本切，而是**提示词 + 大模型语义分组**——把每份语料交给切片提示词，让 LLM 按"符合 RAG 检索"切成自包含块（一块一文件，单块能独立回答一个"为什么/权衡/演进/怎么走"类问题）。各来源提示词已在 `切片数据/{来源}/处理方案/提示词/`（代码 切片-开发向+分组 / 坑档案 / 引导问题 / 语雀 / OpenSpec）。
> **summary 不能长**：代码/坑/引导切片的 summary = **短标题式**（如 `{主题}{块名}`、`{坑名}{复盘}`、`{视角}引导问题回答：{一句话结论}`），**禁止**"解答「...」——..."长描述；语雀/OpenSpec 的 summary = 源 `> 检索摘要` 原样（源摘要本身 ≤120 字符）。检索摘要信息全、但 summary 要短——召回锚点靠检索摘要，头部 summary 只是短标签。
> **向量桶能放下**：整体块数/单块大小受向量桶约束——单块正文别塞过多（超长子块拆 `-2/-3`），头部精简 5 行（summary/权威度/模块/COS路径/类别），机器元信息（entry_id/source_doc/status）由摄入时从文件名+状态+层配置推导，不在 md 头冗余；全量切完按 `切片清单.md` 核对块数、类别闭集。
> **业务匹配不是框架结构**（2026-08-28 用户口径）：语雀/OpenSpec 切片**按业务主题合并**（`切片数据/业务主题清单.md` 20 主题，一块=一业务问题完整答案），**不按文档结构 D#/###/阶段 拆**。同主题跨文档块靠 source_doc/源文档前缀区分。
